[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（dsh）のデスクトップアプリと Web UI に、Codex 風の便利な機能を追加します。追加される機能は、変更パネル、スワイプで選ぶ機能のアイデアカード、メッセージ本文も探せるサイドバー検索、ファイルの復元付きのターンのロールバック、ゴミ箱へのチャットの削除、入力欄の下のプロジェクト名、サイドバーのプロジェクトの状態、入力履歴、計画モードのショートカット、ワンクリックで続行、再起動後の実行中チャットの再開、キューのドラッグ＆ドロップ、セッションのディープリンク、Markdown へのチャットの書き出し、チャットごとの自動レビュー（Auto Review）の許可、バックグラウンド通知、Tether アプリによる iPhone からのアクセス、自動アップデートです。

**ひとことで言うと：** DeepSeek Harness 用の 1 つのプラグインです（npm `dsh-composer-plus`。設定 → プラグインでは **Composer Plus** と表示されます）。このプラグインは、git の変更パネル、Tinder 風の機能のアイデアカード、メッセージ内の単語も探せるサイドバー検索、↶ ターンのロールバック（チャットのみ、またはチャットとファイル）、チャットを削除、入力欄の下のプロジェクト名、↑/↓ の入力履歴、Shift+Tab による `/plan` の切り替え、ワンクリックの ▶ 続行、再起動後に再開、ドラッグ＆ドロップによるキューの並べ替え、セッションリンクをコピー、Markdown として書き出し、自動レビューの「このチャットで許可」、バックグラウンド通知、iPhone からのアクセス（モバイル接続、Tether アプリ）、11 の追加 UI 言語、自動アップデートを追加します。

<p align="center"><img src="docs/images/hero.webp" width="820" alt="Composer Plus を入れた DeepSeek Harness：実行中のプロジェクトはサイドバーにスピナーを表示し、変更パネルは git の差分を表示しています"></p>

非公式のコミュニティプラグインです。ネットワーク通信は、アップデートの確認（GitHub のリリースと npm レジストリ）だけです。起動時のこの通信を止めるには、**自動アップデート** をオフにしてください。**機能のアイデア** は、**機能を提案** をクリックしたときだけ、チャットで使っているモデルを呼び出します。**次のメッセージの予測**（既定ではオン）は、ターンが終わるたびに、設定で選んだモデル（別のモデルを選ばない限り dsh の既定のモデル）を、クリックなしで 1 回呼び出します。この呼び出しを止めるには、**設定 → Composer Plus** でオフにしてください。**入力中に補完**（既定ではオフ）は、オンにした後、入力が止まるたびに、この機能で選んだモデル（既定では予測のモデル）を呼び出します。**プロンプトを改善** は、魔法の杖をクリックしたときだけモデルを呼び出します。**目標チェック**（既定ではオン）は、自動ラウンドでエージェントが `/goal` を完了にするたびに、モデルを 1 回呼び出します。**モバイル接続**（既定ではオフ）は、オンにした後だけ、ローカルネットワークまたは tailnet からの iPhone の接続を受け付けます。

## インストール

**デスクトップアプリ：** 設定 → プラグイン → **プラグインを追加** → `dsh-composer-plus` を入力 → **今すぐ有効にする**。
npm の名前の代わりに `https://github.com/furkancak1r/dsh-composer-plus` を貼り付けることもできます。

**Web / CLI プロファイル：**

```sh
dsh plugin --profile web add dsh-composer-plus
```

その後、dsh を再起動してください。（CLI はデスクトップのプロファイルにはインストールできません。デスクトップのプロファイルはアプリが管理します。）

> dsh の pnpm は、公開から 24 時間たっていないバージョンをスキップします。リリース直後は、バージョンを指定してください：`dsh-composer-plus@1.16.0`。

## 設定

すべての機能は、個別にオン／オフできます。場所は dsh の **設定 → Composer Plus** です。各行には小さなスクリーンショットがあります。ポインターを合わせると大きなプレビューが表示され、クリックすると原寸で開きます（`Esc` で閉じます）。上部の **機能を検索** ボックスは、名前または説明でページを絞り込みます（どの言語でも使えます。大文字と小文字、アクセント記号は区別しません）。`Esc` で入力を消去します。各行にはスイッチと短い説明があります。行名の後ろにある小さな **?** は、その機能を説明する README の箇所を、dsh のインターフェース言語の README で開きます。変更は再起動なしですぐに適用され、そのデバイスに保存されます。**モバイル接続**、**再起動後に再開**、**入力中に補完** を除き、すべての機能が既定でオンです。この 3 つと **内容検索**、**ターンのロールバック**、**次のメッセージの予測**、**目標チェック** のスイッチは、dsh のホストが保持します。そのため、これらのスイッチはすべてのウィンドウに適用され、再起動後も有効です。**次のメッセージの予測** で選んだ **モデル** も、ホストが保持します。**入力中に補完** のモデルの選択（既定は **次のメッセージの予測と同じ**）も、ホストが保持します。**プロンプトを改善** と **目標チェック** のモデルの選択（どちらも既定は **チャットのモデルと同じ**）も、ホストが保持します。**このチャットで許可** の **時間制限**（既定は 1 時間）も、ホストが保持します。**内容検索** の変更は、dsh の再起動後にだけ反映されます（dsh は起動時にこの設定を読み込みます）。それまでは、その行に **この変更を反映するには dsh を再起動してください。** と表示されます。

### アプリケーションの言語

**設定 → Composer Plus → アプリケーションの言語** を開き、**システムの言語** または 13 の言語のいずれかを選びます：

English · 中文 · Türkçe · Español · Português (Brasil) · Français · Deutsch · Русский · 日本語 · 한국어 · Bahasa Indonesia · Tiếng Việt · हिन्दी

<p align="center"><img src="docs/images/language-tr.webp" width="720" alt="Türkçe に切り替えた DeepSeek Harness のインターフェース"></p>

アプリ全体がすぐに切り替わります。この選択は dsh 標準の保存済みの設定 `locale.preference`（一般 → 言語と同じもの）なので、再起動後も維持されます。**システムの言語** は、この選択を消去します。その場合、デスクトップアプリは OS の言語に、Web UI はブラウザーの言語に従います。対応していない言語の場合は英語になります。プラグインをインストールしても、すでに選んだ言語が上書きされることはありません。

各言語パックには 3,280 件のテキストがあります。対象は、dsh `0.2.0-rc.2` と `0.2.1-rc.2` のすべての UI テキスト（チャット、サイドバー、設定、承認、スケジュール、ファイルのプレビュー、プラグインマネージャー、プラグインマーケット）、このプラグイン自体のコントロール、人気の [dsh-rewind](https://github.com/SiriLee/dsh-rewind) プラグインです。次のものは翻訳されません：あなたのメッセージ、モデルの出力、コード、スラッシュコマンドの名前（`/plan`、`/compact`）、推論の強度 `High` のようなプロバイダー側のラベル、ほかのプラグインのテキスト、デスクトップアプリのネイティブメニューとアップデートのダイアログ（dsh はこれらを英語と中国語でしか提供していません）。新しい dsh で追加された文字列は、言語パックが更新されるまで英語で表示されます。ほかのプラグインがすでにある言語を提供している場合、その言語にはそのプラグインのものが使われます。

| `Enter` | 新しいチャットのプロジェクトメニュー、検索ボックス | 最初に一致したプロジェクトを選ぶ |
| `↑` / `↓` | 新しいチャットのプロジェクトメニュー | 表示中のプロジェクトを移動 |
| `Esc` | 新しいチャットのプロジェクトメニュー、検索ボックス | 検索を消去（もう一度押すとメニューを閉じる） |
| `Tab` | 予測が表示された空の入力欄 | 予測を入力欄に入れる |
| `Tab` | カーソルの後ろのグレーの補完 | 補完をメッセージに追加する |
| `Esc` | 予測が表示された空の入力欄 | 予測を非表示にする |
| `Cmd/Ctrl+Z` | **プロンプトを改善** を使った後の入力欄 | 入力したテキストを戻す |
| `Esc` | **プロンプトを改善** の実行中の入力欄 | 改善をキャンセル |
| `Enter` / `Esc` | キュー内のメッセージのエディター | 編集を保存／キャンセル |
| Mac では `Cmd+F`、Windows と Linux では `Ctrl+F` | 開いているチャット | **チャット内を検索** を開く |
| `Enter` / `Shift+Enter`、`↓` / `↑` | **チャット内を検索** のボックス | 次 / 前の一致 |
| `Esc` | **チャット内を検索** のボックス | ボックスを閉じる |

`/` または `@` のメニューが開いているときは、これらのキーはメニューが使います。

## 互換性

dsh `0.2.0-rc.2`（デスクトップと Web）と `0.2.1-rc.2`（Web）でテストしています。CI は、プッシュのたびにテストを実行します。

## プライバシーとセキュリティ

- **続行：** 認証済みのローカルエンドポイントは、最後に中断されたターンだけを再開します。古いリクエストや重複したリクエストは拒否し、既存の承認フックはそのまま維持します。新しいユーザーメッセージは送信しません。
- **再起動後に再開：** オンにするまではオフです。ホスト側は、チャットの ID と開始時刻だけを `$DSH_HOME/storages/dsh-composer-plus/resume.json`（所有者のみのアクセス権）に保存します。データがマシンの外に出ることはありません。チャットを続行するのは、最後のターンを止めたのが（あなたではなく）dsh であることが、dsh 自身のログからわかる場合だけです。続行したターンにも、承認と自動レビューが通常どおり適用されます。

- **変更パネル：** git は、あなたのマシン上のチャットのフォルダーで、dsh の認証済みの `/api` チャネルを通じて、読み取り専用で実行されます。コミット、ステージ、フェッチは一切行いません。表示するのは、git 自体が一覧にしたパスだけです。ツリーには、ローカルとリモートのブランチを最大 1000 件表示し、1 つのブランチの最新 300 件のコミットを表示します。表示するのは最初の親をたどる線だけなので、マージコミットはそれが取り込んだコミットを代表します。ブランチの切り替え（checkout）は一切行いません。**このチャット** は、チャット自身のログから、そのファイルツールが書き込んだファイルを読み取り、チャットのターンのロールバックのスナップショットと比較します。比較は、すぐに削除される一時フォルダーで行います。リポジトリやスナップショットのストアには何も書き込みません。
- **機能のアイデア：** **機能を提案** をクリックするまで、何も実行されません。クリックすると、ホスト側はチャットのフォルダーだけを読み取ります（ブラウザーがパスを送ることはありません）。読み取るのは、最上位の項目の名前、README・AGENTS.md・マニフェスト（`package.json`、`pyproject.toml`、`Cargo.toml`、`go.mod` など）の先頭 6 kB、README の残りの部分のアウトライン（見出し、表の行、リスト項目。最大 6 kB）、最近のコミットのタイトル（`git log --format=%s`、最大 6 kB）で、合計 28 kB までです。`.env*`、鍵ファイル、`node_modules` などのフォルダーはスキップします。また、フォルダーの中にある通常のファイルだけを読み取ります。フォルダーの外を指すシンボリックリンク、FIFO、デバイスはスキップします。この概要は、dsh 標準のプロバイダー設定を通じて、チャットが使うモデルに 1 回のリクエストとして送られます。どのチャットにも追加されません。プロジェクトには何も書き込みません。右にスワイプしたアイデアは計画モードの新しいチャットを開始するため、承認と計画のレビューが通常どおり適用されます。**すぐに実装** は、計画モードなしでチャットを開始します。モデルはすぐにファイルを変更でき、チャットの通常の承認と自動レビューが適用されます。あとで使うために保存したアイデア（タイトル、概要、理由、規模）は、プロジェクトのフォルダーパスとともに、dsh のホームの `storages/dsh-composer-plus/later.json`（所有者のみのファイル）に保存されます。プロジェクトには何も入りません。提案されたアイデアの履歴（タイトル、概要、理由、規模、日付、開始済みかどうか）も同じ方法で `storages/dsh-composer-plus/idea-history.json` に保存されます。保存できるのはプロジェクトごとに最大 200 件で、古いものから削除されます。そのタイトルは、そのプロジェクトで次に **機能を提案** を実行したときにモデルに送られます。
- **内容検索：** チャットを検索する新しいコードはありません。プラグインは、dsh 標準のメッセージインデックス（SQLite FTS5、`dsh-session-query-sqlite`）をオンにし、そのためのファイル `$DSH_HOME/cache/composer-plus/session-search.db`（所有者のみのファイルとフォルダー）を割り当てるだけです。このファイルにはあなたのメッセージとアシスタントのメッセージのテキストが入るため、`$DSH_HOME/sessions` にあるチャットのログと同じように扱う必要がある個人的なデータです。データがマシンの外に出ることはありません。このファイルは、dsh が作り直せるコピーです。dsh を閉じている間なら削除できます。スイッチは `$DSH_HOME/storages/dsh-composer-plus/content-search.json` にあります。
- **ターンのロールバック：** あなたがメッセージを送るたびに、その前にホストがチャットのフォルダーの git スナップショットを作成し、専用のストア `$DSH_HOME/cache/composer-plus/rollback/<chat>.git`（所有者のみのフォルダー）に保存します。ストアには、そのフォルダーの中で git が認識するファイル（無視されたファイルを除く）のコピーが入ります。そのため、ストアはプロジェクトと同じように扱う必要がある個人的なデータです。ストアはリポジトリのオブジェクトを読み取ります（git がすでに持っているものはコピーしません）。リポジトリのインデックス、`HEAD`、ブランチ、タグ、stash、config には一切書き込みません。git がリポジトリに加える唯一の変更は、再利用するオブジェクトファイルのタイムスタンプの更新です（このため、`git gc` によるそれらのファイルの削除が遅れます）。ファイルを含むロールバックは、チャットのフォルダーの中の通常のファイルだけに書き込みます。シンボリックリンク、パイプ、フォルダーの外にあるものはスキップします。データがマシンの外に出ることはありません。dsh を閉じている間なら、ストアを削除できます（その後は、新しいメッセージを送るまで、ロールバックはチャットのみで動作します）。**チャットを削除** は、そのチャットのストアも削除します。スイッチは `$DSH_HOME/storages/dsh-composer-plus/rollback.json` にあります。ファイルを含むロールバックは、**やり直す** のために、ロールバック直前のファイルも保持します（同じストアの `refs/r/…`）。やり直したロールバックは、`$DSH_HOME/storages/dsh-composer-plus/redone.json`（所有者のみのファイル）に記録されます。
- **GitHub issue を作成**（機能のアイデア → **あとで** リスト）：クリックしたときだけ実行されます。ホスト側は、チャットのフォルダーで、あなた自身の GitHub CLI（`gh issue create`）を、アイデアの保存済みのタイトルと概要（とその重要性）で実行します。`gh` は自身のログインとフォルダーの GitHub リモートを使うため、issue はあなたのアカウントでそのリポジトリに作成され、GitHub はそのリポジトリを見られるすべての人にそれを表示します。dsh は、起動するコマンドから、トークンのような名前の変数を取り除きます。`GH_TOKEN` または `GITHUB_TOKEN` で `gh` にトークンを渡している場合、プラグインはこの 2 つだけを `gh` に渡します。issue のリンクは、アイデアとともに `later.json` に保存されます。
- **このファイルを変更したチャット**（変更、ファイルの「…」メニュー）：ホスト側は、フォルダーが同じリポジトリにあるチャットのログを、dsh が保存しているとおりに読み取り、各チャットのタイトル、時刻、依頼の最初の行を返します。ファイル自体を開くことはありません。
- **チャット行の Git ブランチ：** ホスト側は、ターンの開始時と終了時に、チャットのフォルダーで `git branch --show-current`（読み取り専用）を実行し、チャット ID、ブランチ名、時刻だけを `$DSH_HOME/storages/dsh-composer-plus/session-branches.json`（所有者のみのファイル、最新 2000 件のチャット）に保存します。スイッチは、その隣の `branches.json` にあります。
- **チャット内を検索** はページの中だけで動作します。ページが表示しているテキストを読み取るだけで、何も送信しません。
- **チャットを Markdown として書き出し：** ホスト側はチャット自身のログ（dsh が表示するのと同じメッセージ）だけを読み取り、ページに渡します。プロジェクトのファイルは読み取らず、ネットワークには何も送りません。Markdown が入るのは、クリップボードか、あなたが保存するファイルだけです。
- **チャットを削除：** チャット自身のログフォルダー（`$DSH_HOME/sessions/<project>/<chat>`）をゴミ箱に移動します。プロジェクトのフォルダーには触れません。
- **このチャットで許可：** 許可は、許可した時刻とともに `$DSH_HOME/storages/dsh-composer-plus/chat-grants.json`（所有者のみのアクセス権）に保存されます。1 つの許可の対象は、1 つのチャットの 1 つの特定のツールで、時間制限が終わるまで有効です（既定は 1 時間）。そのツールが書き込みできる場合は、あらゆる書き込みも許可の対象になります。許可は、ヘッダーのチップから取り消します。
- 自動レビューは、引き続きすべての呼び出しで実行されます。レビューの失敗が自動で許可されることはありません。
- **モバイル接続：** オンにするまではオフです。オンの間、ホスト側は Tether ゲートウェイを実行します。ゲートウェイは、ポート 19390 の HTTPS（Wi-Fi のサブネットと tailnet（100.64.0.0/10）からの接続だけを受け付けます）と、`127.0.0.1:19391` のペアリングページ（この Mac からのみ）で構成されます。スマートフォンを接続するには、QR コードに含まれる 1 回限りのコード（5 分間有効）と、Mac での **Approve** が必要です。スマートフォンは、ゲートウェイの証明書を固定（ピン留め）します。Mac が保存するのは、各スマートフォンのトークンのハッシュだけです（30 日間有効で、使用中は更新されます）。**Remove** をクリックすると、そのスマートフォンの接続をすぐに切断します。スマートフォンから呼び出せるのは、許可リストにある dsh のメソッド（チャット、プロンプト、添付ファイル、スラッシュコマンド、承認、質問、モデル、エージェント、目標）だけです。設定、認証情報、ファイルブラウザー、ターミナルは呼び出せません。「Tailscale only」は、ローカルネットワークからのすべての接続を拒否し、すでに開いている接続も切断します。アクセスログは、最新 200 件の接続の試み（時刻、IP アドレス、デバイス名、許可か拒否か、その理由）を `access.json` に保存します。トークンやペアリングコードは保存しません。データ：`$DSH_HOME/storages/dsh-composer-plus/mobile/`（所有者のみのファイル）。詳細：[tether/README.md](tether/README.md)。
- **アップデート：** ホスト側は、`api.github.com` に最新のリリースを問い合わせ、`registry.npmjs.org` にそのバージョンを問い合わせます。あなたやあなたのチャットに関する情報は送信しません。インストールには dsh のプラグインマネージャー（`pnpm add dsh-composer-plus@<version>`。インストール済みのプラグインに対して dsh 0.2.1 がこれを拒否する場合は `pnpm add https://registry.npmjs.org/dsh-composer-plus/-/dsh-composer-plus-<version>.tgz`。その場合、プロファイルにはその URL がプラグインのソースとして記載されます）を使うため、dsh 標準のレジストリ、スクリプト、バージョン互換性のチェックが適用されます。プレリリースのタグや古いバージョンがインストールされることはありません。
- **次のメッセージの予測：** 既定ではオンです。このモデル呼び出しを止めるには、**設定 → Composer Plus** でオフにしてください。ターンが終わるたびに、ホスト側は、そのチャットでのあなた自身のメッセージと、エージェントのテキストの返信（ツールの出力、隠れたコンテキスト、推論は含みません）を、最大で約 6,000 文字（最新の部分）、選んだモデル（別のモデルを選ばない限り dsh の既定のモデル）に送ります。送信は、dsh 標準のプロバイダー設定を通じた 1 回のリクエストです。チャットには何も保存しません。予測がチャットの履歴に追加されることはありません。スイッチと選んだモデルは `$DSH_HOME/storages/dsh-composer-plus/predict.json`（所有者のみのファイル）に保存されます。
- **入力中に補完：** オンにするまではオフです。オンの間は、入力が止まるたびに、ホスト側が、それまでに入力したテキストと、そのチャットでのあなた自身のメッセージ、エージェントのテキストの返信（ツールの出力、隠れたコンテキスト、推論は含みません）を、**入力中に補完** で選んだモデル（既定では **次のメッセージの予測** のモデル）に送ります。チャットの部分は最大で約 3,000 文字です。次に入力が止まると、前のリクエストは止まります。チャットには何も保存しません。スイッチは `$DSH_HOME/storages/dsh-composer-plus/complete.json`（所有者のみのファイル）に保存されます。
- **プロンプトを改善：** 魔法の杖をクリックするまで、何も実行されません。クリックすると、ホスト側は次の内容を、**プロンプトを改善** で選んだモデル（既定ではチャット自身のモデル）に 1 回のリクエストとして送ります。下書き、そのチャットでのあなた自身のメッセージとエージェントのテキストの返信（ツールの出力、隠れたコンテキスト、推論、ロールバックで取り消したメッセージは含みません。最大で約 6,000 文字、最新の部分）、**機能のアイデア** と同じプロジェクトの概要（ファイルのルールも同じです。`.env*` や鍵ファイルは読まず、フォルダーの外を指すシンボリックリンクや FIFO はスキップします）、`git status` が変更ありとして示すパス、名前に下書きと共通の言葉を含む、追跡済みまたは未追跡（無視されていない）のパス最大 30 件です。この概要以外のファイルの内容は送りません。チャットにもプロジェクトにも何も書き込みません。回答は入力欄の下書きを置き換えるだけで、送信するかどうかはあなたが決めます。モデルの選択は `$DSH_HOME/storages/dsh-composer-plus/improve.json`（所有者のみのファイル）に保存されます。
- **目標チェック：** 自動ラウンドでエージェントが `/goal` を完了にしたとき（または **今すぐ実行** をクリックしたとき）だけ実行されます。ホスト側は、テストコマンドをチャットのフォルダーで、チャットのサンドボックスモードのもとで実行します（dsh 自身の `bash` ツールと同じで、ファイルアクセスのポリシーも同じです。そのサンドボックスを開始できないときは、テストを実行せず、チェックは失敗します）。コマンドを見つけるために読むのは `package.json`、`Makefile`、`Cargo.toml`、`go.mod`、`pyproject.toml`、`pytest.ini` だけで、フォルダー内の通常のファイルとしてだけ読みます（フォルダーの外を指すシンボリックリンクや FIFO は読みません）。次に、ツールなしの 1 回のリクエストとして、**目標チェック** で選んだモデル（既定ではチャット自身のモデル）に次の内容を送ります。目標、目標の開始以降のチャット（あなたのメッセージ、エージェントの返信、1,000 文字に切り詰めたツール呼び出し、各ツール結果の最後の 2,000 文字。推論とロールバックで取り消したステップは含みません。最大で約 60,000 文字、最新の部分）、`git status --short`、テスト出力の末尾です。ツールの出力にはエージェントが読んだ内容が含まれることがあるため、このリクエストには、チャットそのものと同じように、あなたのファイルの一部が含まれることがあります。チャットにもプロジェクトにも何も書き込みません。テストコマンド、制限、最後の結果（出力の末尾を含む）、モデルの選択は `$DSH_HOME/storages/dsh-composer-plus/goal-check.json`（所有者のみのファイル、最新の 500 チャット）に保存されます。
- **プロジェクトメモリー：** オンにするまではオフです。オンの間は、最上位のチャットのターンが終わるたびに、Host 側が、前回の確認以降のそのチャット自身の新しいメッセージ（あなたのメッセージとエージェントのテキスト返信。ツールの出力、推論、隠しコンテキスト、ロールバックしたメッセージは含みません。分岐したチャットでは、親チャットからのコピーは除きます。最大約 16,000 文字）と保存済みのメモを、ツールなしの 1 回のリクエストとしてチャット自身のモデルに送ります。メモは `$DSH_HOME/storages/dsh-composer-plus/memory/` にある Markdown ファイル（所有者だけが読み書きできます）です。プロジェクトのフォルダーごとの `projects/<id>/`（`<id>` はフォルダーの実際のパスのハッシュで、`project.json` にフォルダーを記録します）、`global/`、`journal.jsonl`（各変更と、変更前後の行）、`reviewed.json`（各チャットをどこまで読んだか）があります。プロジェクトのフォルダーには何も書き込みません。キー、トークン、パスワード、ID 番号のように見えるメモは拒否します。プロジェクトのメモはそのフォルダーの新しいチャットのシステムプロンプトに入るので、そのチャットのリクエストごとにモデルに送られます。スイッチは同じ場所の `memory.json` にあります。
- **バックアップ：** データがマシンの外に出ることはありません。アーカイブは `~/Desktop/dsh-backups` に保存されます（所有者のみのファイル）。シークレットはアーカイブに含まれません。認証情報ファイル（`.credentials.yaml`、`.env`）、鍵ファイル（`.pem`、`.key`、`.p12`、`.pfx`）、yml ファイル内の token、secret、password、API キーの設定の値はマスクされます。それらの実際のコピーは、同じフォルダーの `composer-plus-vault/<archive>/`（所有者のみ）に、このコンピュータ上にだけ残ります。**別のコンピュータ用** は vault をコピーしません。それらのシークレットは、移行先でもう一度入力してください。チャットのログ、設定、dsh のホームのその他の内容は、そのままアーカイブに入ります。`$DSH_HOME` そのものと同じように、フォルダーを非公開にしておいてください。バックアップは `O_NOFOLLOW | O_NONBLOCK` でファイルを読み取ります。シンボリックリンクはリンクとして保存し（リンク先はたどりません）、FIFO やデバイスはスキップします。自動バックアップのスイッチと設定は `$DSH_HOME/storages/dsh-composer-plus/auto-backup.json` に、レスキューコンソールのスイッチは `rescue-console.json` に保存されます。dsh の実行中は、`running/host-<pid>.json` が各 dsh プロセスを示します（レスキューコンソールはこれらを読み取り、復元を拒否します）。
- **レスキューコンソール：** ターミナルのメニューです。ネットワークポートは開きません。復元は、dsh のホームの隣にある新しいフォルダーにだけ書き込みます（ファイルは `O_EXCL | O_NOFOLLOW` で書き込み、シンボリックリンクは最後に作成し、たどりません）。安全でない名前（`..`、絶対パス）、デバイスや FIFO、複数の最上位フォルダー、リンクの下のエントリーを含むアーカイブは拒否します。

## トラブルシューティング

- **macOS で通知が届かない：** システム設定 → 通知 → DeepSeek Harness で通知を許可します。通知を画面に残すには、「通知パネル」を選びます。
- **dsh のアップデート後に、▶、キューのハンドル、プロジェクトの状態、最近のプロジェクトのオプション、すべてのプロジェクトを折りたたむ、パスをコピー、プロジェクトの検索ボックス、次のメッセージの予測、入力中の補完、このチャットで許可、または右クリックが表示されない：** これらの機能は、dsh の現在の HTML に取り付けています。dsh にはまだ、これらを置く場所（スロット）がないためです。dsh がそのマークアップを変更すると、これらの機能は自動で非表示になります。ほかの部分が壊れることはありません。[issue](https://github.com/furkancak1r/dsh-composer-plus/issues) を作成してください。
- **「アップデートに失敗しました」または「npm からインストールされていない」と表示される：** ローカルフォルダーからリンクしたコピーや、名前を変更したコピーは、自分自身をアップデートできません。設定 → プラグインから `dsh-composer-plus` を再インストールしてください。それ以外の場合、メッセージには pnpm のエラーの 1 行目が表示されます。**アップデートを確認** で再試行できます。
- **モバイル接続で、ゲートウェイが動作していないと表示される：** 「no IPv4 address on en0」は、この Mac に Wi-Fi／Ethernet のアドレスがないことを意味します。「EADDRINUSE」は、別の dsh（または別のアプリ）がポート 19390 または 19391 を使っていることを意味します。モバイル接続を実行できる dsh は、一度に 1 つだけです。
- **モバイル接続、再起動後に再開、または内容検索に「dsh を再起動してください」と表示される：** dsh の実行中にプラグインがアップデートされました（内容検索の場合は、スイッチを変更したときにも表示されます）。新しい状態は、再起動後に読み込まれます。
- **検索でタイトルしか見つからない：** 原因は次のいずれかです。内容検索がオフになっている。内容検索をオンにした後、またはプラグインをインストールした後に、dsh を再起動していない。その単語がツールの出力にしかない（「制限事項」を参照）。
- **自分のメッセージに ↶ ボタンがない：** 原因は次のいずれかです。ターンのロールバックがオフになっている。そのチャットがサブエージェントのチャットである。dsh-rewind-plugin がインストールされている（そのプラグインの ↶ ボタンを使ってください）。アップデートの後は、dsh を再起動してください。
- **チャットとファイルがグレー表示になっている：** 原因は次のいずれかです。プロジェクトが git リポジトリではない。そのメッセージより前のスナップショットがない（メッセージがプラグインより古い、または最新 50 件のスナップショットに置き換えられた）。変更されたファイルがない。
- **削除すると、別の dsh がこのチャットを開いていると表示される：** 同じ dsh のホームを使う 2 つ目の dsh が、チャットのロックを持っています。そのウィンドウまたは dsh を閉じてから、もう一度削除してください。それまで、チャットはアーカイブされたままです。
- **「Tailscale only」をオンにした後、iPhone が接続できない：** Tailscale は Mac と iPhone の両方でオンにする必要があります。Mac でオフの場合は、モバイル接続のパネルに警告が表示されます。アクセスログには、拒否された各試行がその理由とともに表示されます。
- **再起動後にチャットが続行しなかった：** 原因は次のいずれかです。dsh の終了時に、再起動後に再開がオフだった。そのターンを自分で停止した。ターンがすでに終わっていた（完了または失敗）。チャットがアーカイブされていた。20 件を超えるチャットが実行中だった（最新の 20 件が続行します）。
- **再起動後にキューが空になっている：** キューを空にするのは dsh 自身の終了処理です。再起動後に再開は、続行するチャットでだけキューを元に戻します。ほかのチャットでは、メッセージをもう一度送信してください。終了の直前に削除したメッセージが戻ることがあります。その場合はもう一度削除してください。
- **GitHub issue を作成 で「gh could not open the issue」と表示される：** このメッセージは、`gh` 自身の出力の最初の行です。ターミナルで `gh auth status` を実行し、`gh auth login` でログインしてください。チャットのフォルダーには GitHub リモートが必要です（`git remote -v`）。「not installed or not on the PATH of dsh」は、dsh が `gh` を見つけられなかったという意味です。インストールするか、`gh` が動作するターミナルから dsh を起動してください。
- **チャット行にブランチのラベルがない：** 原因は次のいずれかです。このバージョンをインストールしてから、そのチャットにターンがない。フォルダーが git リポジトリではない。**チャット行の Git ブランチ** がオフになっている。アップデートの後は、dsh を再起動してください（ブランチはホスト側が記録します）。
- **目標チェックで、テストが終了コード 127 または「not found」で終了したと表示される：** Finder や Dock から起動した dsh は、ターミナルより PATH が短いことがあるため、`npm`、`pnpm`、`cargo` が見つかりません。ターミナルから dsh を起動するか、**目標チェック** → **編集** で、フルパスを使った独自のテストコマンドを設定してください。**今すぐ実行** を使うと、すぐに結果が表示されます。
- **目標が閉じず、エージェントが作業を続ける：** **目標チェック** が、失敗したテストまたは足りない作業を見つけました。目標の下の行に理由が表示されます（詳細は、結果にポインターを合わせると表示されます）。原因またはテストコマンドを直すか、`/goal` または目標バーで目標を自分で完了してください（その完了はチェックされません）。
- **リリース直後にインストールが失敗する：** バージョンを指定してください（`dsh-composer-plus@1.16.0`）。上のインストールの注記を参照してください。
- **今すぐバックアップ で「別のバックアップ操作を実行中です」と表示される：** 別の dsh のウィンドウ、またはレスキューコンソールで操作が実行中です（どちらも、バックアップフォルダーのロックファイル `.composer-plus.lock` を共有します）。完了するまで待ってください。実行中の操作がない場合は、次のクリックで、終了したプロセスのロックを引き継ぎます。
- **レスキューコンソールで「dsh is running」と表示される：** まず dsh を終了してください。dsh が本当に閉じている場合、メッセージに示されたファイルはクラッシュで残ったものです。そのファイルを削除して、もう一度試してください。
- **復元の後に dsh が起動しない、またはプラグインが見つからない：** プロファイルのプラグインパッケージを、もう一度インストールする必要があります。レスキューコンソールが、復元の後にこれを提案します。または、コンソールが一覧表示する `$DSH_HOME/profiles/` の下の各フォルダーで `pnpm install` を実行してください。vault に入っていなかったシークレット（別のコンピュータ）は、もう一度入力する必要があります。コンソールがそれらを一覧表示します。

## 制限事項

- メッセージを送らずに続行する機能は、dsh の `agent/pre-step` → `agent/request` のライフサイクルに依存しています。dsh をアップグレードするときは、互換性を再確認してください。
- **機能のアイデア** は、dsh またはページを再読み込みするまで、チャットごとにカードをメモリに保持します。再読み込みの後は、**機能を提案** でモデルにもう一度問い合わせます。カードは、クリックしたときの dsh の UI 言語で作成されます。言語を変更しても、すでに束にあるカードは元の言語のままで、**アイデアをさらに提案** は新しい言語を使います。モデルが見るのはプロジェクトの短い概要だけで、コードは見ません。そのため、プロジェクトにすでにある機能が提案されることがあります。その場合はスキップしてください。新しいチャットが計画モードで実行されるのは、プロファイルに dsh の `/plan` コマンドがある場合だけです。ない場合、アイデアは通常の最初のメッセージとして送られます。**あとで** リストは、チャットのフォルダーパスに属します。シンボリックリンク経由で開いた同じフォルダーには、別のリストがあります。リストに保存できるアイデアは、プロジェクトごとに最大 50 件です（さらに追加するには、1 件削除してください）。同じタイトルは 1 回だけ保存できます。カードのドラッグで決められるのは、左か右かだけです。保存するには **↓** を、すぐに実装するには **▶** を使ってください。重複はタイトルだけで判定されます。そのため、モデルが以前のアイデアを新しい名前で提案することもあります。その場合はスキップしてください。モデルが以前のアイデアだけを返した場合、新しいカードは表示されません。もう一度クリックしてください。重点テーマが狭いと、この状況が起こりやすくなります。より広いテーマにするか、テーマを解除してください。重点テーマは、dsh またはページを再読み込みするまで、チャットごとに欄に残ります。
- **チャットを Markdown として書き出し** に含まれるのは、あなたのメッセージとアシスタントのテキストの返信だけです。ツール呼び出しとその出力、思考、画像（`[image]` の行で示されます）、非表示のコンテキスト、ターンのロールバックまたは dsh-rewind-plugin で取り消したメッセージは含まれません。1 つのターンの返信は、1 つのセクションにまとめられます。1 回の書き出しに入るのは、約 400 万文字までです。それより長いチャットでは、最初の部分と注記が書き出されます。
- **再起動後に再開** はターンを続行するもので、ターンをやり直すものではありません。終了時に実行中だったツール呼び出しは、dsh の「結果不明」という結果で終わります。モデルには完了済みの作業を繰り返さないよう伝えます。それでも、2 回実行すると安全でないコマンドが、もう一度実行される可能性があります。開いていたサブエージェント、承認、質問は復元されません。親のチャットが続行し、もう一度尋ねます。1 回の起動で続行するチャットは、最大 20 件です。
- **再起動後に再開** とキュー：dsh は終了時にチャットのキューを空にします。プラグインは、キューにあったメッセージをチャットのログから元に戻します。順序、編集、画像、ファイルもそのままです。戻ったメッセージは、続行したターンの後に実行されます。キューが戻るのは、続行するチャットだけです（スイッチがオンで、ターンの実行中に終了した場合）。キューの最後のメッセージを自分で削除した操作も、dsh は同じ形でログに残します。削除した後、次のステップが始まる前に dsh が終了すると、そのメッセージは戻ります。

- **内容検索** は dsh 標準の検索なので、dsh の制限がそのまま当てはまります。検索対象は、ユーザーとアシスタントのメッセージだけです。ツールの出力（コマンド、ファイルの内容、結果）や推論は検索しません。ユーザー、アシスタント、ツールのメッセージで絞り込む機能もありません。単語単位で一致し、単語の一部には一致しません（`deploy` で `deployment` は見つかりません）。アクセント付きの文字は、アクセントなしでも一致します（`seker` で `şeker` が見つかります）。結果は 1 つのチャットにつき 1 行で、dsh の 240 文字の抜粋を表示し、最大 20 行です。
- **内容検索** のコスト（247 件の実際のチャットログのコピーで測定。159 MB、dsh 0.2.1-rc.2、Apple Silicon、32 GB）：起動後の最初の検索で、約 15 秒かけてインデックスを作成します。その間の約 7 秒は dsh のホストが何も応答しないため、ほかのチャットのストリーミングが一時的に止まります（ページ自体は固まりません）。ホストのメモリは、ピーク時に約 1.1 GB 増えます。1 分後も起動時より約 0.5–0.6 GB 多いままで、この状態は dsh を終了するまで続きます。インデックスファイルは約 165 MB です。2 回目以降の検索は約 0.5 秒です。再起動後の最初の検索は約 1 秒で（新しいチャットと変更されたチャットだけを追加します）、メモリが約 70 MB 増えます。コンピューターのメモリが少ない場合は、オフにしてください。
- **内容検索** は、dsh の再起動後にだけ反映されます。また、インデックスファイルは、同じ dsh のホームを使うすべての dsh で共有されます。そのような dsh は、一度に 1 つだけ実行してください（dsh は、1 つのインデックスファイルにつき所有者を 1 つだけ許可します）。
- **ターンのロールバック** がファイルを戻すのは、git リポジトリの中だけで、さらにチャットのフォルダーの中だけです。スナップショットは、チャットごとに最新の 50 件を保持します。無視されたファイル（`.gitignore`、`info/exclude`、グローバルの ignore ファイル）、空のフォルダー、シンボリックリンク、サブモジュールは戻しません。スナップショットの作成時に無視されていたファイルは、ターンで ignore のルールが変わっても削除しません。git が読み取れないファイルは、スナップショットから除外されます。メッセージを送るたびに、チャットのフォルダーに対して `git add --all` を 1 回実行し、専用のストアに記録します。追跡されていないファイルが多い非常に大きなフォルダーでは、数秒かかることがあります。次のツール呼び出しは、それが終わるのを待ちます（最大 10 秒。その後、スナップショットはバックグラウンドで完了します）。リポジトリの `git gc` が、古いスナップショットに必要なオブジェクトを削除した場合、そのファイルは戻せなかったファイルとして一覧に表示されます。入力欄に戻るのは、メッセージのテキストだけです。画像やファイルは、もう一度追加してください。サブエージェントのチャットには ↶ がありません（サブエージェントによるファイルの変更は、それを開始したチャットの変更として扱われます）。書き出したチャット（`/export`）には、取り除いたメッセージが残ります。1 つの隠しマーカーでチャットの一部を取り除くというアイデアは、SiriLee による [dsh-rewind-plugin](https://github.com/SiriLee/dsh-rewind)（MIT）から来ています。Composer Plus は、そのコードを一切使っていません。
- **チャットを削除** には、dsh のアーカイブ機能が必要です（dsh 0.2.0 以降）。15 秒以内に停止しないチャット（またはそのサブエージェントのチャット）や、別の dsh が保持しているチャットは、アーカイブされたままになり、何も移動しません。macOS 以外のシステムでは、ゴミ箱のフォルダーがチャットの履歴と同じディスク上にある必要があります。開いているチャットを削除すると、dsh を再起動するまで、そのチャットはアーカイブされた非表示の状態で dsh のメモリに残ります。ゴミ箱は自分で空にしてください。dsh は空にしません。
- dsh のキューには `move` 操作がないため、プラグインのホスト側が、dsh のキューの中でメッセージそのものを移動します（1 回の変更で、同じメッセージのままです）。画像やファイルを含むメッセージも移動できます。移動できるのは自分のメッセージだけです。キュー内の目標のラウンドや質問への回答は、その位置から動きません。ドラッグ中にメッセージの送信が始まった場合は、何も移動せず、そのことを知らせる通知が表示されます。
- 新しいバージョンが dsh の設定を何も変更しない場合、dsh 0.2.1 はアップデートをすぐに読み込みます。それ以外の場合と dsh 0.2.0 では、読み込むには dsh を再起動してください。プラグインが dsh を自動で再起動することはありません。dsh のプラグインマネージャーがない Web／CLI プロファイルでは、新しいバージョンがあることを知らせるだけです。
- **このチャットで許可** は、許可した時点から時間制限を数えます。新しい時間制限は、有効な許可にすぐに適用されます。そのため、短い時間制限にすると、許可がすぐに終わることがあります。バージョン 1.12 以前の許可には時刻がありません。更新後、エージェントはそのツールについてもう一度だけ確認します。
- **入力欄のフォーカスを維持** がフォーカスを戻すのは、`/` コマンドまたはスキルの後だけです。dsh がコマンドを処理する間、入力欄は数ミリ秒だけ読み取り専用になります。そのため、その間に押したキーは失われます。dsh の `/` メニューがまだ開いている場合、`Enter` は強調表示された行を選び、送信はしません。
- **質問カードをウィンドウに合わせる**は dsh の質問カードだけを変更し、計画レビューのカードは変更しません。カードは dsh のマークアップ（`data-question-key`、`data-question-scroll`）で見つけます。dsh の更新でこのマークアップが変わると、カードは dsh が描くとおりに表示されます。カードの高さはチャットではなくウィンドウに従います。狭いサイドパネル内のチャットでは、高いカードがチャットの上にはみ出すことがあります。
- **モバイル接続** は macOS でのみ動作します（`en0`、`openssl`、`swift`、`dns-sd` を使います）。固定のポート 19390 と 19391 を使うため、各 Mac でこれを実行できる dsh は、一度に 1 つだけです（スマートフォンの Mac の一覧では、各 Mac が 1 項目になります）。スマートフォンが通知を受け取るのは、Tether が開いているとき、またはバックグラウンドに移った直後だけです（プッシュサービスはありません）。Tether で「Settings → Notifications → Send notifications」をオンにするまで、Tether は通知を送りません。この設定は初期状態でオフで、オンにしたときに iOS が許可を求めます。iOS アプリは、まだ App Store にありません。Xcode で `tether/ios` からビルドしてください。「Tailscale only」でも、Mac に Wi-Fi または Ethernet のアドレスが必要です（ゲートウェイは、そのアドレスがある場合だけ起動します）。アクセスログは Mac ごとに保存され、最新 200 件の試行だけを残します。1 分以内に繰り返された試行は、新しい行を作らず、同じ行の回数を 1 つ増やします。Tether のアプリのロックは、iPhone のロック画面に表示される通知のプレビューを隠しません。iOS の設定でオフにしてください。Tether の緑の点は Mac に従います。dsh で開いたチャットは、スマートフォンでも点が消えます。Tether で開いたチャットは、スマートフォンでだけ点が消えます。Mac 上の dsh 自身の点は、Mac でそのチャットを開くまで残ります。
- セッションリンクは、チャットの中で機能します。クリックしても、そのチャットは開きません。**メッセージリンクをコピー** で作ったリンクでメッセージを開けるのは、dsh 0.2.1 以降で、チャットの中のメッセージから開いた場合だけです（dsh 0.2.0 にはユーザーテキストのルールがないため、リンクはコピーされますが、プレーンテキストとして表示されます）。ロールバックで取り除かれたメッセージや、圧縮によって dsh が読み込む履歴から削除されたメッセージは表示できません。その場合、リンクがそのことを表示します。🔗 ボタンは、dsh のメッセージ行に取り付けています。dsh のアップデートでそのマークアップが変わった場合、ボタンは表示されません。
- **すべて既読にする** は、公開 API ではない dsh の一部（dsh のセッション状態の `completionUnread` 一覧）を通じて、dsh 自身の未読の点を変更します。dsh のアップデートでこの名前が変わった場合、この項目は表示されません。この項目は dsh のプロジェクトの「…」メニューに入りますが、このメニューにはプラグイン用のスロットがありません。dsh がこのメニューを変更した場合も、この項目は表示されません。
- **キュー内のメッセージをその場で編集** は、その間に送信が始まったメッセージを変更せず、その間に変更されたメッセージ（たとえば iPhone の Tether で変更したもの）も上書きせず、そのことを通知で知らせます。新しい画像には画像を受け付けるモデルが必要で（dsh 標準の画像の制限も適用されます）、新しいファイルはアップロードが終わるまで保存できません。編集できるのは自分のキュー内のメッセージだけで、キュー内の目標のラウンドや質問への回答は編集できません。プラグインの更新後すぐに使えるのはテキストだけの編集で、画像やファイルを含むメッセージを保存する前には dsh を再起動してください（ホスト側は起動時に読み込まれます）。
- **やり直す** は、ロールバックしたチャットを変更しません。ロールバックの直前から新しいチャットを開始します（dsh 標準のフォークで、モデルのコンテキストも同じです）。そのため、新しいチャットには新しい ID とタイトルが付きます。やり直せるのは、チャットの最新のロールバックだけで、1 回だけです。また、その後に何もない間だけです（新しいメッセージを送ると、やり直しはできなくなります）。ロールバックの後に変更したファイルは保持されます。ただし、上書きするチェックボックスをオンにした場合は上書きします。やり直しには、ロールバックが保持したスナップショットが必要です（同じく最新 50 件の範囲）。このバージョンより前のロールバックや、**チャットのみ** のロールバックでは、メッセージだけが戻ります。
- **ツリー** のブランチマップは、各矢印の行き先を推測しています。git は、ブランチがどのブランチにマージされたかを保存しないためです。マージ済みのブランチは、マージコミットで最初にそのブランチを取り込んだブランチを指します。待機中のブランチは、分岐元のうち最も近いブランチ（メインブランチを優先）を指します。2 つのブランチが同じコミットから分岐した場合、マップが誤ったほうを選ぶことがあります。fast-forward で進んだブランチにはマージコミットがないため、その **マージ済み** ラベルをクリックしても何も開きません。メインブランチは `origin` のデフォルトブランチです。それがない場合は `main` または `master`、それもない場合は開いているブランチです。マップは最新の 20,000 件のコミットを読み取り、ブランチを最大 60 個表示します。履歴がそれより長い場合は、一部の矢印が正しくない可能性があることを表示します。squash や rebase でマージしたブランチ（たとえば GitHub 上で）は **待機中** と表示されます。git はそのコミットとのつながりを保存しないためです。
- **このチャット** が数えるのは、dsh のファイルツール（`write`、`edit`、`str_replace_editor`）が書き込んだファイルだけです。コマンド（`bash`）が変更したファイルは、この表示には含まれず、**未コミット** に表示されます。チャットのターンのロールバックのスナップショットがない場合（ターンのロールバックがオフ、dsh-rewind-plugin がインストール済み、またはチャットがプラグインより古い場合）、表示は最後のコミットと比較し、そのことを示します。ターンのロールバックはチャットごとに最新の 50 個のスナップショットを保持します。長いチャットでは、表示は保持されている最も古いものと比較し、どのメッセージからかを示し、それより前の変更は数えません。**空白の変更を非表示** は `git diff -w` です。行の中のスペースだけが変わった行も非表示になります。
- **GitHub issue を作成** には、dsh の PATH にある GitHub CLI（`gh`）と、チャットのフォルダーの GitHub リモートが必要です。実行時間は最大 60 秒です。`gh` がそれより長くかかると、issue は GitHub に作成されていても、そのリンクがリストに表示されないことがあります（もう一度クリックする前に、GitHub を確認してください。リストは完了した実行からしかリンクを読み取らないため、もう一度クリックすると 2 つ目の issue が作成されることがあります）。GitHub リモートが複数あるフォルダーでは、`gh` 自身のデフォルト（`gh repo set-default`）を使います。
- **このファイルを変更したチャット** は、**このチャット** と同じく、dsh のファイルツール（`write`、`edit`、`str_replace_editor`）だけを認識します。コマンド（`bash`）による変更は表示されません。リポジトリの最新 300 件のチャット（作成日時の順）を読み取り、それより多い場合はそのことを表示します。表示するのは最大 100 行です。名前を変更したファイルは、ツールが書き込んだ名前で表示されます。フォルダーがリポジトリの外にあるチャット（同じファイルへの別のパスを通る場合も含みます）は数えません。dsh の起動後に最初に開くときは、リポジトリのすべてのチャットのログを読み取ります（275 件のチャットで約 4 秒）。2 回目以降は、それ以降に変更されたチャットだけを読み取ります。
- **チャット行の Git ブランチ** が表示するのは、最後のターンの開始時または終了時に、チャットのフォルダーがあったブランチです。現在のブランチではありません。ターンの外でブランチを切り替えた場合は、次のターンの後に表示されます。このバージョンより前のチャットには、次のターンまでラベルが表示されません。ラベルは dsh のチャット行のマークアップの中に置かれます（dsh にはそこにスロットがありません）。dsh のアップデートでそのマークアップが変わった場合、ラベルは表示されません。チャットの上のプロジェクト行の名前がブランチと同じ場合（「チャットごとのブランチ」のフォルダーなど）、チャット行にラベルは表示されませんが、「1つのリスト」では表示されます。
- **チャットごとのブランチ** を計画モードで使う場合：dsh は `/plan <メッセージ>` をメッセージではなくコマンドとして送信します。そのため Composer Plus は、dsh の入力欄でコマンドの送信を横取りします（公開 API ではありません）。dsh のアップデートでこれが変わった場合、**新しいブランチ** を選んだ状態の `/plan <メッセージ>` は、開いている新しいチャットで dsh 自体のコマンドとして実行されます。ホストが新しいチャットで計画モードをオンにできない場合、ブランチのフォルダーは残り、メッセージは送信されません。そのため、新しいチャットが既定のモードでファイルを変更することはありません。
- **チャットごとのブランチ**：チャットのブランチフォルダー（`<project>/.worktrees/<name>`）が削除されると（たとえばチャット自身のエージェントが worktree を取り除いてブランチを削除したとき）、チャットの次のステップでチャットはそのフォルダーから移ります。ブランチフォルダーのプロジェクトはサイドバーから消え、チャットは「グループなし」の下に表示され、開いたままです。dsh 0.2.1 以降では、チャットはプロジェクトのメインフォルダーで続き、モデルには新しいフォルダーについての通知が届きます。dsh 0.2.0 では、チャットは削除されたフォルダーのままです。そこでのコマンドは、新しいチャットを始めるまで失敗します。どのチャットも使っていない削除済みブランチのプロジェクトもサイドバーから消えます。Composer Plus は起動時と 30 秒ごとにブランチフォルダーを確認します。サイドバーのフィルターは必要ありません。チャットの移動中は、同じリポジトリの **新しいブランチ** が「もう一度試してください」と答えます。スイッチをオフにすると、dsh 自身のエラー（「working-directory: directory does not exist」）が再び表示されます。
- **ワークスペースのツリー内のブランチ** はクリックなしで git に書き込みます。チャットを移すとき、プロジェクトフォルダーを元のブランチに戻し（`git switch`）、worktree を追加します（`git worktree add`）。ブランチ、worktree、ファイルを削除することはありません。dsh はチャットのフォルダーを変更できないため、移されたチャットはコピー（新しい id を持つ dsh 自身のフォーク）で、元のチャットはアーカイブされます。コピーは止まった作業を続けます。ブランチが現れたときに実行中だったツール呼び出しは拒否で終わり、エージェントは新しいフォルダーで再実行します。元のチャットの目標は移りません。移るのは、フォルダーがリポジトリのメインフォルダーであるチャットだけで、そのターンで作成して切り替えたブランチ（`git switch -c`、`git checkout -b`）の場合だけです。`git branch` だけで作ったブランチ、未コミットの変更があるフォルダー、リンクされた worktree、サブフォルダーでは何も移りません。ツリーに表示されるのは、`<project>/.worktrees/` の直下にありブランチを持つ worktree だけです。デタッチされた worktree や別の場所の worktree は表示されません。コピーが自動で開くのは、元のチャットが開いていたチャットだった場合だけです（プラグインは dsh のサイドバーの行からそれを読み取ります）。それ以外の場合、コピーはブランチのプロジェクトにあります。
- **チャット内を検索** が検索するのは、ページに表示されている内容だけです。対象は読み込まれたメッセージと返信です（古いものは、上にスクロールするか、**以前の履歴を読み込む** をクリックします）。閉じているツールのステップや、ツールの出力の中で折りたたまれているテキストは対象外です。数える一致は最大 2,000 件です（それを超えると「2000+」）。ブラウザーのハイライト API を使います（Chromium 105 以降。デスクトップアプリには搭載されています）。古いブラウザーでは、件数と移動は動作しますが、色は付きません。Mac では `Cmd+F`（Windows と Linux では `Ctrl+F`）でこれが開くのは、画面にチャットがあるときだけです。それ以外の場所では、ブラウザー自体の検索がこれまでどおり動作します。Mac の `Ctrl+F` は、テキスト欄での macOS の動作（カーソルを 1 文字進める）のままです。
- **操作がないときに待機中のチャットを開く** が分かるのは、dsh のウィンドウで見える操作だけです。ほかのアプリでの作業は数えないため、dsh がバックグラウンドにあると、30 秒後に待機中のチャットを開くことがあります。dsh は前面に出ません。キー入力、クリック、マウスの移動をせずに読んでいるだけの状態は、操作なしと見なします。対象は dsh のオレンジ色の点が付いたチャット（質問、承認、計画のレビュー）だけです。サブエージェントのリクエストは親のチャットに表示されます。待機中のチャットが画面にある間は、ほかのチャットを開きません。回答せずに離れたチャットは、次に 30 秒間操作がないときに再び開くことがあります。30 秒は変更できません。
- 再起動の前に送られた通知をクリックしても、dsh が前面に表示されるだけです。
- アクティブなプロジェクトは、dsh に保存されたプロジェクトの順序を使って移動します。そのため、新しい順序は再起動後も維持されます。どのプロジェクトにも属さないチャット（「グループなし」）は移動できません。dsh は、これらのチャットを常に最後に表示します。
- dsh には、サイドバーの表示オプションのメニューに拡張ポイントがありません。そのため、最近のプロジェクトのオプションは、dsh 標準のメニューに追加しています。dsh のアップデートでこのメニューが変わった場合、オプションは表示されず、すべてのプロジェクトが表示されたままになります。フィルターはプロジェクトの行に対して動作するため、**1つのリスト** は絞り込まれません。**ワークスペースのツリー** では、中のプロジェクトがアクティブな間は親フォルダーも表示されたままになり、過去 2 時間にアクティブでなかったチャットの行も非表示になります。**ワークスペース** では、プロジェクトの行だけを絞り込みます。フィルターは、dsh が保存している表示設定（公開 API ではありません）から、dsh が今どの表示かを読み取ります。dsh の更新でその名前が変わった場合、**ワークスペースのツリー** は **ワークスペース** と同じように絞り込まれます。プロジェクトの状態も同じ設定を読み取ります。**ワークスペースのツリー** では、親フォルダーの行は、中にあるプロジェクトのチャットも数に入れます。dsh がこの設定の名前を変えた場合、各行には自分のチャットだけが表示されます。**状態別** にも、同じ種類の制限があります。dsh には並べ替えのスロットがないため、この項目と行の並び順は、dsh のメニューとリストのマークアップに取り付けています。
- dsh には、プロジェクトの行のメニューも、ワークスペースのヘッダーのスロットもありません。**パスをコピー** は、dsh の行のマークアップからプロジェクトの行を見つけます。**すべてのプロジェクトを折りたたむ** は dsh のヘッダーに入り、プロジェクトの行をクリックするのと同じ方法で、開いている各プロジェクトを閉じます。dsh のアップデートでこのマークアップが変わった場合、右クリックではブラウザーのメニューが表示され、ボタンは表示されません。
- dsh には、新しいチャットのプロジェクトメニューにも拡張ポイントがありません。そのため、**プロジェクトを検索** ボックスと A–Z 順は、dsh のメニューのマークアップに取り付けています。dsh のアップデートでこのマークアップが変わった場合、メニューは dsh が描くとおりに表示されます（保存済みの順序で、ボックスはありません）。A–Z 順は表示だけのもので、dsh に保存されたプロジェクトの順序は変わりません。
- dsh には **新しいセッション** を開く場所を選ぶ拡張ポイントもありません。**新しいセッションの既定のワークスペース** は、公開 API ではない dsh のメソッド（dsh のワークスペースサービスの `startSession`）をラップします。dsh の更新でこの名前が変わると、**新しいセッション** は dsh が選ぶ場所（開いているプロジェクトまたは最新のプロジェクト）で開きます。プロジェクトを指定しない呼び出しはすべて既定を使います：サイドバーのボタン、そのショートカット、ロゴ、そして **自動化タスク** ページの **新規** も同じです。dsh は起動時に引き続き最後のチャットを開きます。汎用フォルダーは初回使用時に作成され、プロジェクトに追加されます。Windows や Linux で Documents フォルダーを移動している場合、dsh 自身のフォルダーと異なることがあります。
- dsh には、入力欄のヒントのための拡張ポイントもありません。そのため、**次のメッセージの予測** のテキストは、dsh 標準のプレースホルダー（`[data-composer-placeholder]`）の上に重ねて表示します。dsh のアップデートでこのマークアップが変わった場合、予測は表示されません。オンの間は、ターンが終わるたびに短いモデル呼び出しが 1 回行われます。
- **入力中に補完** は、dsh 標準の入力欄のヒント（dsh がスラッシュコマンドの引数のヒントに使う `--dsh-composer-hint` スタイル）を通じてテキストを表示します。スラッシュコマンド、ファイルやシンボルのチップを含むメッセージ、カーソルがメッセージの末尾にないときは動作しません。dsh のアップデートでこのスタイルが変わった場合、補完は表示されません。入力が止まるたびに、モデル呼び出しが 1 回行われます。
- **プロンプトを改善** が見るのは、短いプロジェクトの概要、変更されたパス、名前があなたの言葉と一致するパスだけで、コードそのものは見ません。そのため、正しいファイルを見落とすことがあり、渡されたパスしか挙げません。送信する前に新しいテキストを読んでください。スラッシュコマンドや、ファイルやシンボルのチップを含むメッセージには使えません（新しいテキストはプレーンテキストなので、チップが失われるためです）。メッセージは最大 8,000 文字です。画像は添付されたままで、変わるのはテキストだけです。クリックするたびに、モデル呼び出しが 1 回行われます。性能の高いモデルでは 1 分ほどかかることがあります（`Esc` でキャンセルします）。
- **目標チェック** がチェックするのは、自動の目標ラウンドでエージェントが行った完了だけです。チャットであなたが頼んだ完了、`/goal`、目標バーはチェックされません。エージェントは、テストやテストコマンドのファイルを自分で変更できます。検証用のモデルはチャットを読むのでそれに気づけますが、どちらの方向にも誤ることがあります（誤った「未完了」はラウンドを 1 回余分に使い、誤った「完了」は目標を閉じます）。検証用のモデルが見るのはチャットと `git status` で、コードそのものは見ません。テストの実行結果を再利用するのは、ファイルを変更できるエージェントの最新のステップが、同じフォルダーで完全に同じコマンドを実行して成功した、エージェント自身の `bash` 実行だった場合だけです。パイプ（`| tail`）や `&&` を含むコマンドは再利用しません。予算はターンの終わりに計測されるため、1 回のターンで予算を超えることがあります。数えるのはチャット自身のモデル呼び出しだけです（サブエージェントの呼び出しは数えません）。チェックの実行中、`update_goal` は待機します（テストは最大 15 分、検証は最大 3 分）。フォークしたチャットには新しいチャット ID が付くため、親チャット独自のテストコマンドと制限なしで始まります。検証まで進んだ完了 1 回ごとに、モデル呼び出しが 1 回行われます。
- **停止後の新規メッセージ優先** は、チャットを停止した後（または失敗したターンの後、まだキューがあるチャットを開いたとき）にだけ働きます。ターンの実行中に送信したメッセージは、これまでどおりキューの末尾で待ちます。追い越すのは自分がキューに入れたメッセージだけです。キューに目標のラウンドや質問への回答が待っている場合は、dsh 自身の順序のままです。公開 API ではない dsh の一部（停止したターンがまだ終了処理中かどうか）を読み取ります。dsh の更新でその名前が変わった場合、メッセージはそのターンが終わった後にだけ先頭に移ります。サブエージェントのチャットは dsh 自身の順序のままです。
- **プロジェクトメモリー** はチャットの最初のフォルダー（dsh のプロジェクトのフォルダー）に属します。`cd` でフォルダーを変えたチャットは最初のプロジェクトのメモリーを使い続けます。同じファイルへの別のパスで開いた同じフォルダーは、同じメモリーを共有します。チャットは開始時にメモリーのセクションを固定するため、後で保存したメモは次のチャットから表示されます（`memory_recall` ならすぐに見つかります）。確認では、モデルが残すと決めたものだけを残します。事実を見落としたり、誤った内容を残したりすることがあります。ファイルを開いて確認し、dsh を閉じている間に手で編集または削除してください。あなたのメッセージを含むターンが終わるたびに、モデルを 1 回呼び出します。呼び出しが失敗すると、次のターンの後に同じメッセージをもう一度読みます。サブエージェントのチャットは確認しません。考え方とファイル形式は [DS Bot](https://github.com/Fei2411/DS-Bot)（Apache-2.0）から来ています。Composer Plus はそのコードを使っておらず、DS Bot 自身のメモリーを読み書きすることもありません。
- **バックアップ** が使うのは、固定の 1 つのフォルダー `~/Desktop/dsh-backups` だけです（dsh-backup の既定のフォルダーなので、dsh-backup のアーカイブも引き続き使えます）。別のフォルダーを選ぶ設定はありません。アーカイブの大きさは、`cache/` と `dsh-runtimes/` を除いた dsh のホームとほぼ同じです（測定：Apple Silicon で、1.6 GB のファイルから約 30 秒で 830 MB のアーカイブができました。その間も dsh は応答し続けました）。読み取り中に変わったファイルは、バックアップがそのファイルを開いた時点の状態で保存されます。そのため、開いているチャットのログが、途切れたレコードで終わることがあります。これは、dsh が次の書き込みで修復します。マスクでは、yml ファイル内のシークレットを、1 行にあるキーの名前（`token:`、`apiKey:`、…）で見つけます。フローマップ内（`{token: x}`）、そのようなキーの下のリスト内、JSON ファイル内（たとえば、`.json` ファイル内にある MCP サーバーの `apiKey`）、または別の名前のシークレットは、アーカイブに残ります。dsh-backup の種類別アーカイブ（`dsh-t-…`）は一覧に表示されません。**別のコンピュータ用** はアーカイブをコピーします（APFS ではクローンなので、追加の容量は使いません）。vault は一緒にコピーされません。**今すぐバックアップ** はバックアップを削除しません。自動バックアップは、Composer Plus が作成したバックアップのうち最新のものを保持し（**自動バックアップ** の **保持** の設定）、それより古い自身のバックアップを削除します。アップグレード前のスナップショットは別に数えます（最新の 2 件が残ります）。dsh-backup のアーカイブが削除されることはありません。**削除** で取り除いてください。dsh-backup がまだインストールされている間は、dsh-backup が自身の保持件数に Composer Plus のアーカイブを数え、それらを削除することがあります。
- **復元** は、dsh を閉じている間に、レスキューコンソールでだけ実行できます。復元は dsh のホーム全体を置き換えます。古いホームは、あなたが削除するまで、隣に `.dsh.pre-restore-<time>` として残ります。そのため、ディスクには両方の分の空きが必要です。チャットはプロジェクトのパスを保ちます。別のコンピュータでは、別のパスにあるプロジェクトは、もう一度追加するまで見つからないものとして表示されます。dsh のホームの外を指すシンボリックリンク（たとえば、別のフォルダーからリンクしたスキル）は、リンクとして戻ります。リンク先は、そのコンピュータ上に存在する必要があります。
- **セッションログのチェック** は、各チャットの最新のログを、何が開けるかについての dsh 自身のルールで読み取ります。JSON ではない行や順序の乱れた行は、その後にターンの終わりがある場合にだけ損傷と数えます（そうでなければ、dsh はその行以降を除いてチャットを開くため、一覧には表示されません）。ログのイベントを、dsh 自身のイベントのルールと照らし合わせることはしません。そのため、正常と判定されたログでも、dsh のアップグレード後に開けないことがあります。修復では、バックアップからコピーを取り出します。そのバックアップ以降のメッセージは、そのチャットから失われます（損傷したファイルは隣に残ります）。この dsh で開いているチャットは、設定では修復されません。dsh がそのチャットを保持しているためです。
- **自動バックアップ** は、dsh の実行中にだけ実行されます。dsh を閉じている間に予定時刻になったバックアップは、次の起動の約 45 秒後に実行されます。新しいバージョンのスナップショットは、アップデートの前ではなく、その起動の後に作成されます。
- 標準機能としてのサポートを、上流に要望しています：キューの `move` は [#773](https://github.com/deepseek-ai/deepseek-harness/discussions/773)、続行の状態は [#9269](https://github.com/deepseek-ai/deepseek-harness/discussions/9269) です。

## よくある質問

**DeepSeek Harness に変更／git diff のパネルを追加するには？** `dsh-composer-plus` をインストールし、右サイドバー → `+` → **変更** を開きます。

**Tinder のカードをスワイプするように、dsh にプロジェクトの機能を提案してもらえますか？** はい。右サイドバー → `+` → **機能のアイデア** → **機能を提案** を開きます。右にスワイプすると、その機能を計画する新しいチャットを開始します。**▶ すぐに実装** をクリックすると、計画なしでその機能をすぐに実装するチャットを開始します。左にスワイプすると、スキップします。

**dsh のサイドバー検索で、タイトルだけでなく、メッセージ内の単語からチャットを探せますか？** はい、**内容検索**（既定でオン）で探せます。プラグインをインストールした後に dsh を 1 回再起動し、**ワークスペース** の横の虫眼鏡を使ってください。一致したチャットには、その単語の前後のテキストが表示されます。

**OpenCode や Claude Code のように、ターンを取り消してプロンプトを編集できますか？** はい、**ターンのロールバック** でできます。メッセージの **↶** をクリックし、**チャットとファイル** を選びます。入力欄に戻ったテキストを編集して、送信してください。

**チャットをアーカイブではなく、削除できますか？** はい、**チャットを削除** でできます。**…** → **削除…** を選びます。履歴はゴミ箱に移動するため、間違えても元に戻せます。

**チャットがどのプロジェクトのものかを確認するには？** 入力欄の下の行を見てください。**入力欄にプロジェクト名**（既定でオン）が有効なら、行の先頭にプロジェクト名が表示されます。ポインターを合わせると、フォルダーのパスが表示されます。

**dsh の入力欄で ↑/↓ のメッセージ履歴を使うには？** このプラグインをインストールしてください。空の入力欄で `↑` / `↓` を押すと、送信済みのメッセージを順に呼び出せます。

**「continue」と入力せずに、停止または失敗した dsh のターンを続行するには？** このプラグインを入れると、停止、失敗、または途中で切れたターンの後に、送信ボタンが **▶** に変わります。1 回クリックすると、ターンを再開します。

**dsh を終了して再び開いたとき、実行中だったチャットは続行しますか？** 自動では続行しません。dsh はそのようなターンを中断済みとして記録し、待機します（目標も `/goal resume` を待ちます）。**設定 → Composer Plus → 再起動後に再開** をオンにしてください。dsh の終了時に作業中だったチャットが、次の起動時に自動で続行します。

**予測はどのモデルが書きますか？** **設定 → Composer Plus → 次のメッセージの予測 → モデル** で選んだモデルです。一覧は dsh 自身のモデルの一覧です。**dsh の既定** は、dsh の既定のモデルに従います。選んだモデルが dsh の一覧からなくなった場合、予測には既定のモデルを使います。**入力中に補完** には専用の **モデル** メニューがあります。**次のメッセージの予測と同じ**（既定）は予測のモデルに従います。ほかのモデルを選ぶと、そのモデルは補完だけに使われます。そのモデルが dsh の一覧からなくなった場合、補完には予測のモデルを使います。

**Roo Code や Augment の Enhance prompt ボタンのように、送信前に dsh でプロンプトを改善できますか？** はい、**プロンプトを改善**（既定ではオン）でできます。大まかな依頼を入力し、モデルメニューの横にある魔法の杖をクリックします。このチャットとプロジェクトをコンテキストとして、あなたの言語でテキストを書き直します。送信はしません。`Cmd/Ctrl+Z` または **改善を元に戻す** で元のテキストに戻ります。モデルは **設定 → Composer Plus → プロンプトを改善 → モデル** で選びます。

**ループエンジニアリングの検証ループのように、エージェントが自分の作業を自分で完了扱いにしないようにできますか？** はい、**目標チェック**（既定ではオン）でできます。`/goal` で目標を開始します。エージェントが目標を完了したと言うと、プロジェクトのテストが実行され、独立したモデル呼び出しがチャットと照らし合わせて目標をチェックします。どちらかが失敗すると、目標は開いたままになり、エージェントが理由を読みます。目標の下の **目標チェック** の行にある **編集** で、独自のテストコマンド、時間制限、トークン制限を設定できます。

**DS Bot のメモリーのように、エージェントがチャットをまたいで好みを覚えておけますか？** はい、**プロジェクトメモリー**（既定ではオフ）で可能です。**設定 → Composer Plus** でオンにしてください。ターンが終わるたびに、長く続く好みや決定がチャットのプロジェクトの短いメモとして保存され、そのプロジェクトの新しいチャットがそれを読みます。エージェントに何かを覚えるように頼むと、すぐに保存します。

**dsh-backup のように、dsh でチャットや設定をバックアップできますか？** はい。**設定 → Composer Plus → バックアップ → 今すぐバックアップ** を使います。同じ形式のアーカイブを同じフォルダー（`~/Desktop/dsh-backups`）に書き込むため、dsh-backup のアーカイブも表示され、復元できます。dsh-backup は削除してかまいません。定期的にバックアップするには、**自動バックアップ** をオンにしてください。

**dsh が起動しなくなりました。バックアップを復元するには？** バックアップフォルダー（`~/Desktop/dsh-backups`）を開き、`Composer Plus Rescue.command` をダブルクリックします（Linux：`composer-plus-rescue.sh`、Windows：`Composer Plus Rescue.cmd`）。`3) Restore a backup` を選び、バックアップを 1 つ選んで `RESTORE` と入力します。dsh がなくても動作します。

**dsh を新しいコンピュータに移すには？** 古いコンピュータで、**バックアップ** → バックアップの横にある **別のコンピュータ用** を使います。そのフォルダーを新しいコンピュータにコピーし、そこに dsh をインストールして終了します。次に、コピーしたフォルダーで `Composer Plus Rescue` を開いて復元します。API キーはもう一度入力してください（API キーは古いコンピュータに残ります）。

**クラッシュの後にチャットが開きません。修復できますか？** **設定 → Composer Plus → セッションログのチェック → セッションログをチェック** を使います。損傷したチャットは、**バックアップから修復** で最新のバックアップから戻ります（そのバックアップ以降のメッセージは失われます）。

**dsh でキュー内のメッセージを並べ替えるには？** キュー内のメッセージの ⠿ ハンドルをドラッグします。または、ハンドルにフォーカスを置いて `↑` / `↓` を押します。

**キュー内のメッセージの入力ミスを直すには？** キュー内のメッセージをダブルクリックし、テキストを変更して `Enter` を押します（`Esc` でキャンセル）。メッセージのキュー内の位置は変わりません。そこで画像やファイルを削除したり、新しく追加したりすることもできます。

**プロジェクトの未読の点を一度にすべて消すには？** サイドバー → プロジェクトの **…** ボタン → **すべて既読にする** を選びます。

**長いチャットの 1 つのメッセージにリンクできますか？** はい。メッセージにポインターを合わせ、**🔗** をクリックします。そのリンクをチャットで送信します。dsh 0.2.1 以降では、リンクをクリックすると、そのメッセージの位置でチャットが開きます。

**間違えてターンをロールバックしました。元に戻せますか？** はい。ロールバックの直後に、入力欄の上の **やり直す** を使います。ロールバックの直前から、同じメッセージで新しいチャットを開始します。**チャットとファイル** でロールバックした場合は、ファイルも戻します。

**どのチャットがこのファイルを変更しましたか？** 右サイドバー → **変更** → ファイルの **…** → **このファイルを変更したチャット**。行をクリックすると、変更した依頼の位置でそのチャットが開きます。

**1 つの長いチャットの中を検索できますか？** はい。チャットで Mac では `Cmd+F`（Windows と Linux では `Ctrl+F`）を押します。**チャット内を検索** はすべての一致をハイライトし、`Enter` と `Shift+Enter` で一致の間を移動します。

**1 つのチャットが変更したファイルだけを見るには？** 右サイドバー → **変更** → **このチャット** を開きます。空白だけの変更を隠すには、**␣** をクリックします。

**1 つのチャットで、自動レビューが同じツールについて何度も確認しないようにするには？** 承認カードの **このチャットで許可** をクリックします。対象は、そのチャットのその特定のツールだけで、既定では 1 時間有効です。許可は、ヘッダーのチップから取り消せます。時間は **設定 → Composer Plus → このチャットで許可** で変更できます。

**iPhone をなくしました。その iPhone が Mac に接続できないようにするには？** サイドバーの左下にある **モバイル接続** をクリックし、その iPhone の横にある **Remove** をクリックします。その iPhone の鍵はすぐに使えなくなります。再び接続するには、Mac で承認する新しいペアリングが必要です。

**Face ID で Tether をロックできますか？** はい。Tether で「Settings → Privacy → Lock with Face ID」をオンにします。すると Tether は、開いたときと、アプリに戻ったときに Face ID（またはパスコード）を求めます。

**dsh のサイドバーに、今日使ったプロジェクトだけを表示するには？** サイドバー → 表示オプション（スライダーのアイコン）→ **過去 2 時間以内にアクティブ** を選びます。もう一度選択すると、すべてのプロジェクトを表示します。

**dsh でプロジェクトのフォルダーパスをコピーするには？** サイドバーでプロジェクトを右クリック → **パスをコピー** を選びます。

**dsh のサイドバーで、すべてのプロジェクトを一度に折りたたむには？** 表示オプション（スライダーのアイコン）の横にある、折りたたみのボタンをクリックします。このボタンは、少なくとも 1 つのプロジェクトが開いているときに表示されます。

**dsh のタスクが完了したときや承認が必要なときに、macOS／Windows の通知を受け取るには？** **バックグラウンド通知** をオン（既定）のままにしてください。そのうえで、OS の設定で DeepSeek Harness の通知を許可します。

**質問をしているチャットを dsh が自動で開くことはできますか？** はい、**操作がないときに待機中のチャットを開く**（既定でオン）を使います。チャットが回答、承認、計画のレビューを待っていて、dsh を 30 秒間操作しないと、dsh がそのチャットを開きます。入力中、スクロール中、マウスを動かしている間は待ちます。

**DeepSeek Harness のインターフェースを、トルコ語、スペイン語、日本語などに切り替えるには？** 設定 → Composer Plus → **アプリケーションの言語** で切り替えます。

**iPhone から dsh を使うには？** `tether/ios` から Tether アプリをビルドし（Xcode）、**設定 → Composer Plus → モバイル接続（iPhone）** をオンにします。左下の **モバイル接続** をクリックし、QR コードを読み取って（iPhone のカメラまたは Tether の **Scan code**）、**Connect** をタップし、**Approve** をクリックします。外出先では、両方のデバイスで Tailscale を使ってください。

**新しいセッションを常に同じプロジェクトで開くには？** 設定 → Composer Plus → **新しいセッションの既定のワークスペース** → **新しいセッションを開く場所** → プロジェクトを選びます。ほかのプロジェクト横の `+` は引き続きそのプロジェクトを開きます。

**1 つのプロジェクトの複数の機能を、それぞれ専用のブランチで同時に進めるには？** **チャットごとのブランチ** を使います。新しいチャットの画面では、ブランチのボタンに既定で **新しいブランチ** が表示されます。最初のメッセージを送信します。各チャットに専用のブランチと worktree フォルダーができ、`.worktreeinclude` に書かれていれば `.env` や `node_modules` もコピーされます。チャットのヘッダーに、今いるブランチが表示されます。

**サイドバーにプロジェクトの各ブランチを表示し、エージェントがブランチを作成したときにチャットを移せますか？** はい、**ワークスペースのツリー内のブランチ**（既定ではオフ）で可能です。設定 → Composer Plus でオンにし、dsh の **表示オプション** → **ワークスペースのツリー** を選びます。`<project>/.worktrees/` に worktree がある各ブランチが、そのプロジェクト内に表示されます。プロジェクトフォルダーのエージェントにブランチを作成してそこで作業するよう頼み、フォルダーに未コミットの変更がなければ、チャットは自動でブランチに移ります。ブランチのフォルダーを削除すると一覧から消え、そのチャットは **グループなし** に移ります。

**iPhone から写真を送れますか？** はい。Tether のチャットで、メッセージ欄の横の **+** → Camera、Photos（最大 4 枚）、または Paste image をタップします。写真はメッセージの添付ファイルとして Mac のチャットに届くため、モデルはそれを見ることができます。

**デスクトップアプリで使えますか？** はい。設定 → プラグイン → **プラグインを追加** → `dsh-composer-plus` でインストールします。dsh 0.2.0-rc.2（デスクトップと Web）と 0.2.1-rc.2（Web）でテストしています。

**新しい機能のルール：** 設定 → Composer Plus の各機能の行には、スクリーンショットを表示します。機能の ID を `client.js` の `SHOT_OF` と `index.js` の `SHOTS` に追加し、`assets/features/<id>.webp` を同梱してください（使い捨てのデモ dsh で英語の UI を使って撮影し、約 60 kB 以下にします）。機能を同じ画像とともに `docs/features.json` に追加し、`npm run build:readme` を実行します。これで `README.md` と翻訳済みの各 `README.<id>.md` の機能表、および `llms.txt` の一覧が書き込まれます。機能にスクリーンショットがないと、`test/shots.test.mjs` が失敗します。`test/browser-settings-shots.mjs` は、実際の設定ページを確認します。変更のたびに確認するチェックリストの全体は、[AGENTS.md](AGENTS.md) にあります。

テストでは、本物の `client.js` を偽の React/DOM に対して実行し、本物の `index.js`（ホスト側）を一時的な git リポジトリに対して実行します。Tether ゲートウェイのテスト（`test/tether-gateway.test.mjs`）は、モックの dsh ホストと本物の TLS ゲートウェイを使います。iPhone アプリは `tether/ios` にあります（[tether/README.md](tether/README.md) と [tether/AGENTS.md](tether/AGENTS.md) を参照）。ホストの各ルート、そのリクエスト、Tether から呼び出せるかどうかは、[docs/ROUTES.md](docs/ROUTES.md) に一覧があります。`node test/browser-history.mjs '<dsh web URL with ?token=…>'` は、専用の `DSH_HOME` を持つ使い捨ての `dsh web` に対して、実際のブラウザーで入力履歴を確認します。

言語パックは、データだけを含む JSON で、`locales/<id>.json` にあります。`npm run build:locales` が、これらを 1 つのクライアントのエントリーに埋め込みます（翻訳サービスや実行時のダウンロードは使いません）。`npm test` は、各パックについて、すべてのキーがそろっていること、プレースホルダーと改行が同じであること、システム言語と上書きの動作を確認します。ローカルにインストールした Playwright を使って、隔離した実際のアプリで確認するには、次のコマンドを実行します：

```sh
PLAYWRIGHT=/path/to/playwright node test/browser-language.mjs /path/to/dsh/lib/bin.js
```
