Komfortfunktionen im Stil von Codex für die Desktop- und Weboberfläche von [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (dsh): ein Änderungsbereich, Funktionsideen als Wischkarten, Suche im Nachrichtentext über die Seitenleiste, Zurücknehmen von Runden samt Wiederherstellung von Dateien, Löschen von Chats in den Papierkorb, der Projektname unter dem Eingabefeld, der Projektstatus in der Seitenleiste, ein Eingabeverlauf, ein Tastenkürzel für den Planmodus, Fortsetzen mit einem Klick, Fortsetzen laufender Chats nach einem Neustart, Drag-and-drop in der Warteschlange, Sitzungslinks, Export von Chats als Markdown, Freigaben der automatischen Prüfung pro Chat, Hintergrundbenachrichtigungen, Zugriff vom iPhone mit der Tether-App und automatische Updates.

**In einer Zeile:** ein einziges Plugin für DeepSeek Harness (npm `dsh-composer-plus`, unter Einstellungen → Plugins als **Composer Plus** angezeigt). Es bringt einen git-Änderungsbereich, Funktionsideen als Karten im Tinder-Stil, eine Seitenleisten-Suche, die auch Wörter in Nachrichten findet, ↶ Runde zurücknehmen (nur Chat oder Chat und Dateien), Chat löschen, den Projektnamen unter dem Eingabefeld, ↑/↓ Eingabeverlauf, einen Shift+Tab-Umschalter für `/plan`, ▶ Fortsetzen mit einem Klick, Nach Neustart fortsetzen, Neuordnen der Warteschlange per Drag-and-drop, Sitzungslink kopieren, Als Markdown exportieren, „Für diesen Chat zulassen“ bei der automatischen Prüfung, Hintergrundbenachrichtigungen, Zugriff vom iPhone (Mobile Verbindung, Tether-App), 11 zusätzliche Oberflächensprachen und automatische Updates.

<p align="center"><img src="docs/images/hero.webp" width="820" alt="DeepSeek Harness mit Composer Plus: Das laufende Projekt zeigt einen Spinner in der Seitenleiste, und der Änderungsbereich zeigt einen git-Diff"></p>

Inoffizielles Community-Plugin. Die Update-Prüfung macht Netzwerkaufrufe (GitHub-Releases und die npm-Registry). Schalte **Automatische Updates** aus, um sie beim Start zu stoppen. **Türkisches Skill-Paket** (standardmäßig an) lädt turkish-anti-ai-skill von GitHub und sucht einmal am Tag nach einer neuen Version, nur solange **App-Sprache** Türkçe ist; schalte es in **Einstellungen → Composer Plus** aus, um diese Aufrufe zu stoppen. **Funktionsideen** ruft das eigene Modell deines Chats nur auf, wenn du auf **Funktionen vorschlagen** klickst. **Vorhersage der nächsten Nachricht** (standardmäßig an) ruft nach jeder beendeten Runde einmal das in den Einstellungen gewählte Modell auf (den dsh-Standard, wenn du kein anderes wählst), ohne Klick. Schalte sie unter **Einstellungen → Composer Plus** aus, um diese Aufrufe zu stoppen. **Beim Tippen vervollständigen** (standardmäßig aus) ruft bei jeder Pause beim Tippen das dafür gewählte Modell auf (standardmäßig das der Vorhersage), nachdem du die Funktion eingeschaltet hast. **Prompt verbessern** ruft ein Modell nur auf, wenn du auf seinen Zauberstab klickst. **Aufgabentafel** ruft für jede Aufgabe, die du auf der Tafel startest, einmal das Modell des neuen Chats für die Schlagwörter auf. Mit der Einstellung **KI-Zusammenfassung** (Standard ist **Schnell (ohne KI)**) ruft sie auch das Modell eines laufenden Chats für eine kurze Fortschrittsnotiz auf, während du den Fortschritt dieser Aufgabe auf der Tafel oder in Tether ansiehst. **Zielprüfung** (standardmäßig an) ruft jedes Mal einmal ein Modell auf, wenn der Agent ein `/goal` in einem automatischen Durchlauf als abgeschlossen markiert. **Mobile Verbindung** (standardmäßig aus) nimmt iPhone-Verbindungen aus deinem lokalen Netz oder Tailnet erst an, wenn du sie einschaltest.

## Installation

**Desktop-App:** Einstellungen → Plugins → **Plugin hinzufügen** → `dsh-composer-plus` eingeben → **Jetzt aktivieren**.
Du kannst statt des npm-Namens auch `https://github.com/furkancak1r/dsh-composer-plus` einfügen.

**Web-/CLI-Profil:**

```sh
dsh plugin --profile web add dsh-composer-plus
```

Starte dsh danach neu. (Die CLI kann nicht in das Desktop-Profil installieren; dieses Profil verwaltet die App.)

> Das pnpm von dsh überspringt Versionen, die jünger als 24 Stunden sind. Gib direkt nach einem Release die Version mit an: `dsh-composer-plus@1.25.0`.

## Einstellungen

Jede Funktion lässt sich einzeln ein- oder ausschalten: dsh **Einstellungen → Composer Plus**. Jede Zeile hat einen kleinen Screenshot: Fahre mit der Maus darüber für eine größere Vorschau, oder klicke darauf, um ihn in voller Größe zu öffnen (`Esc` schließt ihn). Das Feld **Funktionen suchen** oben filtert die Seite nach Name oder Beschreibung (in jeder Sprache, ohne Unterschied bei Groß- und Kleinschreibung oder Akzenten); `Esc` leert es. Daneben zeigen **Alle**, **An** und **Aus** alle Funktionen, nur die eingeschalteten oder nur die ausgeschalteten (schalte **An/Aus-Filter** aus, um sie auszublenden). Jede Zeile hat einen Schalter und eine kurze Beschreibung. Das kleine **?** nach dem Namen einer Zeile öffnet den Teil dieser README, der die Funktion beschreibt, in der README der Oberflächensprache von dsh. Änderungen gelten sofort, ohne Neustart, und bleiben auf diesem Gerät gespeichert. Alles ist standardmäßig an, außer **Mobile Verbindung**, **Nach Neustart fortsetzen** und **Beim Tippen vervollständigen**. Der Host von dsh speichert die Schalter dieser drei Funktionen sowie von **Inhaltssuche**, **Runde zurücknehmen**, **Vorhersage der nächsten Nachricht** und **Zielprüfung**. Deshalb gelten sie für jedes Fenster und bleiben nach einem Neustart erhalten. Der Host speichert auch die Wahl unter **Modell** für **Vorhersage der nächsten Nachricht**, die für **Beim Tippen vervollständigen** (standardmäßig **Wie Vorhersage der nächsten Nachricht**), die für **Prompt verbessern**, die für **Zielprüfung** (beide standardmäßig **Wie das Modell des Chats**) und das **Zeitlimit** von **Für diesen Chat zulassen** (standardmäßig 1 Stunde). **Inhaltssuche** ändert sich erst nach einem Neustart von dsh (dsh liest den Schalter beim Start). Bis dahin steht in ihrer Zeile **Starte dsh neu, damit diese Änderung gilt.**

### App-Sprache

Öffne **Einstellungen → Composer Plus → App-Sprache** und wähle **Systemsprache** oder eine von 13 Sprachen:

English · 中文 · Türkçe · Español · Português (Brasil) · Français · Deutsch · Русский · 日本語 · 한국어 · Bahasa Indonesia · Tiếng Việt · हिन्दी

<p align="center"><img src="docs/images/language-tr.webp" width="720" alt="DeepSeek-Harness-Oberfläche auf Türkçe umgestellt"></p>

Die ganze App wechselt sofort. Die Auswahl ist die eigene gespeicherte `locale.preference` von dsh (dieselbe wie unter Allgemein → Sprache). Deshalb bleibt sie nach Neustarts erhalten. **Systemsprache** löscht diese Auswahl: Die Desktop-App folgt der Sprache des Betriebssystems, die Weboberfläche der Sprache des Browsers. Eine nicht unterstützte Sprache fällt auf Englisch zurück. Die Installation des Plugins überschreibt nie eine Sprache, die du schon gewählt hast.

Jedes Paket hat 3.280 Texte: jeden Oberflächentext von dsh `0.2.0-rc.2` und `0.2.1-rc.2` (Chats, Seitenleiste, Einstellungen, Genehmigungen, Automatisierungsaufgaben, Dateivorschauen, Plugin-Verwaltung, Plugin-Marktplatz), die eigenen Bedienelemente des Plugins und das beliebte Plugin [dsh-rewind](https://github.com/SiriLee/dsh-rewind). Nicht übersetzt werden: deine Nachrichten, die Ausgabe des Modells, Code, Namen von Slash-Befehlen (`/plan`, `/compact`), Bezeichnungen der Anbieter wie die Reasoning-Stufe `High`, Texte anderer Plugins sowie die nativen Menüs und Update-Dialoge der Desktop-App (dsh liefert diese nur auf Englisch und Chinesisch aus). Texte, die eine neuere dsh-Version hinzufügt, erscheinen auf Englisch, bis die Pakete aktualisiert sind. Wenn ein anderes Plugin eine Sprache bereits bereitstellt, behält dieses Plugin die Sprache.

## Datenschutz und Sicherheit

- **Fortsetzen:** Der authentifizierte lokale Endpunkt setzt nur die letzte unterbrochene Runde fort, lehnt veraltete oder doppelte Anfragen ab und behält die vorhandenen Genehmigungs-Hooks bei. Er sendet keine neue Benutzernachricht.
- **Nach Neustart fortsetzen:** aus, bis du es einschaltest. Die Host-Hälfte speichert nur Chat-IDs und Startzeiten in `$DSH_HOME/storages/dsh-composer-plus/resume.json` (Rechte nur für den Besitzer), und nichts verlässt deinen Rechner. Sie setzt einen Chat nur fort, wenn das eigene Protokoll von dsh sagt, dass dsh (nicht du) seine letzte Runde gestoppt hat. Genehmigungen und die automatische Prüfung gelten für die fortgesetzte Runde wie gewohnt.

- **Änderungsbereich:** git läuft nur lesend auf deinem Rechner, im eigenen Ordner des Chats, über den authentifizierten `/api`-Kanal von dsh. Es führt nie Commits, Staging oder Fetches aus und zeigt nur Pfade, die git selbst aufgelistet hat. Der Baum listet bis zu 1000 lokale und entfernte Branches und zeigt die neuesten 300 Commits eines Branches: seine First-Parent-Linie, ein Merge-Commit steht also für die Commits, die er gebracht hat. Er wechselt nie den Branch (Checkout). **Dieser Chat** liest das eigene Protokoll des Chats, um die Dateien zu finden, die seine Datei-Tools geschrieben haben. Er vergleicht sie mit dem Snapshot von Runde zurücknehmen für diesen Chat, in einem temporären Ordner, der sofort gelöscht wird. Er schreibt nichts in dein Repository und nichts in den Snapshot-Speicher.
- **Funktionsideen:** Nichts läuft, bis du auf **Funktionen vorschlagen** klickst. Dann liest die Host-Hälfte nur den eigenen Ordner des Chats (der Browser sendet nie einen Pfad): die Namen der Einträge auf oberster Ebene, die ersten 6 kB von README, AGENTS.md und Manifest (`package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, …), eine Gliederung des restlichen README (Überschriften, Tabellenzeilen, Listenpunkte; höchstens 6 kB) und die Titel der neuesten Commits (`git log --format=%s`, höchstens 6 kB), insgesamt höchstens 28 kB. Sie überspringt `.env*`, Schlüsseldateien und Ordner wie `node_modules`. Sie liest nur reguläre Dateien, die im Ordner bleiben: Ein Symlink, der aus dem Ordner hinauszeigt, ein FIFO oder ein Gerät wird übersprungen. Diese Zusammenfassung geht als eine einzige Anfrage an das Modell, das der Chat nutzt, über die eigenen Anbietereinstellungen von dsh. Sie wird keinem Chat hinzugefügt. Im Projekt wird nichts geschrieben. Eine nach rechts gewischte Idee startet einen neuen Chat im Planmodus, also gelten Genehmigungen und Planprüfung wie gewohnt. **Sofort umsetzen** startet den Chat ohne Planmodus: Das Modell kann sofort Dateien ändern, mit den üblichen Genehmigungen des Chats und der automatischen Prüfung. Für später gemerkte Ideen (Titel, Zusammenfassung, Begründung, Aufwand) werden mit dem Ordnerpfad des Projekts in `storages/dsh-composer-plus/later.json` im dsh-Home gespeichert (Datei nur für den Besitzer). Ins Projekt kommt nichts. Der Verlauf der vorgeschlagenen Ideen (Titel, Zusammenfassung, Begründung, Aufwand, Datum, ob gestartet) wird auf dieselbe Weise in `storages/dsh-composer-plus/idea-history.json` gespeichert, höchstens 200 pro Projekt (die ältesten fallen zuerst weg). Seine Titel gehen beim nächsten **Funktionen vorschlagen** in diesem Projekt an das Modell.
- **Inhaltssuche:** Kein neuer Code durchsucht deine Chats. Das Plugin schaltet nur den eigenen Nachrichtenindex von dsh ein (SQLite FTS5, `dsh-session-query-sqlite`) und gibt ihm eine Datei: `$DSH_HOME/cache/composer-plus/session-search.db` (Datei und Ordner nur für den Besitzer). Die Datei enthält den Text deiner Benutzer- und Assistentennachrichten. Sie ist also so privat wie die Chatprotokolle in `$DSH_HOME/sessions`. Nichts verlässt deinen Rechner. Die Datei ist eine Kopie, die dsh neu erstellen kann: Du kannst sie löschen, während dsh geschlossen ist. Der Schalter liegt in `$DSH_HOME/storages/dsh-composer-plus/content-search.json`.
- **Runde zurücknehmen:** Vor jeder deiner Nachrichten macht der Host einen git-Snapshot des Chat-Ordners in einem eigenen Speicher: `$DSH_HOME/cache/composer-plus/rollback/<chat>.git` (Ordner nur für den Besitzer). Er enthält Kopien der Dateien in diesem Ordner, die git sieht (keine ignorierten Dateien), und ist also so privat wie das Projekt. Er liest die Objekte deines Repositorys (keine Kopie dessen, was git schon hat) und schreibt nie in Index, `HEAD`, Branches, Tags, Stash oder Config deines Repositorys. Die einzige Änderung, die git dort macht, ist ein neuerer Zeitstempel an Objektdateien, die es wiederverwendet (das verzögert ihre Bereinigung durch `git gc`). Ein Zurücknehmen mit Dateien schreibt nur reguläre Dateien im Ordner des Chats. Es überspringt Symlinks, Pipes und alles außerhalb des Ordners. Nichts verlässt deinen Rechner. Du kannst den Speicher löschen, während dsh geschlossen ist (das Zurücknehmen funktioniert dann nur für den Chat, bis neue Nachrichten kommen). **Chat löschen** löscht auch den Speicher eines Chats. Der Schalter liegt in `$DSH_HOME/storages/dsh-composer-plus/rollback.json`. Ein Zurücknehmen mit Dateien behält auch die Dateien, wie sie direkt davor waren (`refs/r/…` im selben Speicher), für **Wiederholen**. Die wiederholten Rücknahmen stehen in `$DSH_HOME/storages/dsh-composer-plus/redone.json` (nur für den Besitzer).
- **GitHub-Issue öffnen** (Funktionsideen → Liste **Später**): läuft nur, wenn du darauf klickst. Die Host-Hälfte führt dein eigenes GitHub CLI (`gh issue create`) im Ordner des Chats aus, mit dem gespeicherten Titel und der Zusammenfassung der Idee (und warum sie wichtig ist). `gh` nutzt seine eigene Anmeldung und das GitHub-Remote des Ordners. Seine Tools lesen die Protokolle deiner anderen Chats auf diesem Mac (Titel, Projekte, Status und mit chat_read ihre neuesten Nachrichten) und geben sie diesem Modell nur, wenn es ein Tool aufruft. Senden, Starten, Stoppen und Archivieren eines Chats warten jeweils auf deine Genehmigung. Die Chat-ID liegt in `$DSH_HOME/storages/dsh-composer-plus/assistant.json` und der Schalter in `assistant-switch.json` (Dateien nur für den Besitzer). Erinnerungen und Automatisierungen sind die eigenen geplanten Aufgaben von dsh. Nichts verlässt diesen Mac außer den Modellanfragen und den Websuchen, die der Chat macht. Die Schalter für den Assistenten als Bot speichern ihren Zustand in `assistant-free.json` und `assistant-notify.json` (Dateien nur für den Besitzer). **Chat-Neuigkeiten im Assistenten** schreibt eine kurze Zeile über einen anderen Chat (Titel, Projekt und höchstens 300 Zeichen seiner letzten Antwort oder seines letzten Fehlers) in den Assistenten-Chat, daher geht dieser Text auch an das Modell des Assistenten; die Neuigkeiten warten nur im Speicher.
- **Geschützte Dateien:** Die Liste und der Schalter liegen in `$DSH_HOME/storages/dsh-composer-plus/protected-files.json` (Datei nur für den Besitzer). Die Prüfung liest nur den Pfad jedes Aufrufs eines Datei-Tools (und seinen echten Pfad), nie die Datei.
- **Blockierte Befehle:** Die Regeln und der Schalter liegen in `$DSH_HOME/storages/dsh-composer-plus/blocked-commands.json` (Datei nur für den Besitzer). Die Prüfung liest nur den Befehlstext jedes Aufrufs von `bash` und `pwsh`; sie führt nichts aus und sendet nichts.
- **Geheime Eingabe:** Der Wert geht von der Karte (oder von Tether über das Gateway, das keine Anfrageinhalte protokolliert) nur in der Antwortanfrage an den Host. Der Host schreibt ihn nach `$DSH_HOME/storages/dsh-composer-plus/secrets/<zufälliger Name>` (Ordner 0700, Datei 0600); nichts geht ins Projekt, ins Chatprotokoll oder ins Tool-Ergebnis. Der Host hält den Wert im Speicher, um ihn in späteren Tool-Ergebnissen dieses Chats durch `[secret]` zu ersetzen. Die Datei und diese Kopie werden am Ende des Durchgangs des Chats und beim Start von dsh gelöscht. Der Schalter liegt daneben in `secrets.json`. Ein Befehl, den der Agent mit der Datei ausführt, kann den Wert dorthin senden, wohin dieser Befehl sendet: Das ist der Zweck.
- **Projektgedächtnis:** aus, bis du es einschaltest. Solange es an ist, schickt der Host-Teil nach jeder abgeschlossenen Runde eines Chats der obersten Ebene die neuen Nachrichten dieses Chats seit der letzten Prüfung (deine Nachrichten und die Textantworten des Agenten; keine Werkzeugausgabe, kein Reasoning, kein verborgener Kontext, keine zurückgenommenen Nachrichten; in einem abgezweigten Chat bleibt die Kopie des Eltern-Chats weg; höchstens etwa 16.000 Zeichen) und die gespeicherten Notizen an das Modell des Chats, als eine Anfrage ohne Werkzeuge. Die Notizen sind Markdown-Dateien unter `$DSH_HOME/storages/dsh-composer-plus/memory/` (nur für den Eigentümer): `projects/<id>/` für jeden Projektordner (`<id>` ist ein Hash des echten Pfads des Ordners; `project.json` nennt den Ordner), `global/`, `journal.jsonl` (jede Änderung mit der Zeile davor und danach) und `reviewed.json` (wie weit jeder Chat gelesen wurde). In den Projektordner wird nichts geschrieben. Notizen, die wie ein Schlüssel, ein Token, ein Passwort oder eine Ausweisnummer aussehen, werden abgelehnt. Die Notizen eines Projekts kommen in den Systemprompt jedes neuen Chats in diesem Ordner und gehen so mit jeder Anfrage dieses Chats an das Modell. Der Schalter liegt in `memory.json` am selben Ort. **Gedächtnis öffnen** schickt nichts, bis du auf **Änderungen ansehen** klickst; dann schickt es die angezeigten Notizen und deinen Text als eine Anfrage ohne Werkzeuge an das Standardmodell von dsh. Die Änderungen werden erst mit **Anwenden** geschrieben, mit `editor` im Journal. Tether liest und ändert die Notizen über dieselbe Route. **Versionsverlauf des Gedächtnisses** (standardmäßig an) behält vor jedem Speichern eine Kopie der Gedächtnisdateien in `memory/history/` daneben (nur für den Besitzer, die neuesten 50 je Gedächtnis); er sendet nichts an ein Modell. **Gedächtnis nach AGENTS.md exportieren** sendet nichts an ein Modell und schreibt nur, wenn du auf **AGENTS.md schreiben** klickst: Es liest und schreibt `AGENTS.md` im Projektordner dieses Gedächtnisses (nur eine normale Datei darin, nie über einen symbolischen Link, der ihn verlässt) und ändert nur seinen markierten Abschnitt. **Veraltete Gedächtnisnotizen finden** sendet nichts an ein Modell und schreibt nichts: Es prüft Pfade im Projektordner mit realpath (keine Datei wird gelesen), liest `package.json` nur als normale Datei im Ordner und führt dort ein `git for-each-ref` aus. **Gedächtnis in diesem Chat nicht nutzen** speichert jeden Chat, den du ausschaltest, in `memory-chats.json` daneben (nur für den Besitzer, die neuesten 500); ein solcher Chat sendet kein Gedächtnis an sein Modell. **Gedächtnisnotizen aus einem Chat vorschlagen** sendet nichts, bis du auf **Für das Gedächtnis vorschlagen** klickst; dann sendet es die gespeicherten Notizen des Projekts des Chats und die globalen Notizen sowie die eigenen Nachrichten und Textantworten des Chats (keine Tool-Ausgabe, keine zurückgesetzten Nachrichten; die Kopie des Eltern-Chats in einem Fork bleibt draußen; höchstens etwa 24.000 Zeichen) als eine Anfrage ohne Tools an das eigene Modell des Chats. Ein Vorschlag wird nur mit **Annehmen** gespeichert.
- **Sicherung:** Nichts verlässt deinen Rechner. Archive landen in `~/Desktop/dsh-backups` (Dateien nur für den Besitzer). Geheimnisse sind nicht im Archiv: Dateien mit Anmeldedaten (`.credentials.yaml`, `.env`), Schlüsseldateien (`.pem`, `.key`, `.p12`, `.pfx`) und die Werte der Einstellungen token, secret, password und API-Schlüssel in den yml-Dateien werden maskiert. Ihre echten Kopien bleiben in `composer-plus-vault/<archive>/` im selben Ordner (nur für den Besitzer), nur auf diesem Computer. **Für einen anderen Computer** kopiert keinen vault: Gib diese Geheimnisse dort neu ein. Deine Chatprotokolle, Einstellungen und der Rest des dsh-Home liegen unverändert im Archiv: Halte den Ordner privat, so wie `$DSH_HOME` selbst. Die Sicherung liest Dateien mit `O_NOFOLLOW | O_NONBLOCK`. Ein Symlink wird als Link gespeichert (nie verfolgt), ein FIFO oder Gerät wird übersprungen. Schalter und Einstellungen der automatischen Sicherung liegen in `$DSH_HOME/storages/dsh-composer-plus/auto-backup.json`, der Schalter der Rettungskonsole in `rescue-console.json`. Solange dsh läuft, nennt `running/host-<pid>.json` jeden dsh-Prozess (die Rettungskonsole liest diese Dateien, um eine Wiederherstellung abzulehnen).
- **Rettungskonsole:** ein Menü im Terminal; sie öffnet keinen Netzwerkport. Eine Wiederherstellung schreibt nur in einen neuen Ordner neben dem dsh-Home (Dateien mit `O_EXCL | O_NOFOLLOW`, Symlinks zuletzt und nie verfolgt). Sie lehnt ein Archiv ab, das einen unsicheren Namen (`..`, einen absoluten Pfad), ein Gerät oder FIFO, mehr als einen obersten Ordner oder einen Eintrag unter einem Link enthält.

## Fehlerbehebung

- **Keine Benachrichtigungen unter macOS:** Systemeinstellungen → Mitteilungen → DeepSeek Harness → erlauben. Wähle Hinweise, damit die Benachrichtigungen auf dem Bildschirm bleiben.
- **▶, Griffe in der Warteschlange, Projektstatus, die Option für aktuelle Projekte, Alle Projekte einklappen, Pfad kopieren, das Suchfeld für Projekte, die Vorhersage der nächsten Nachricht, die Vervollständigung beim Tippen, Für diesen Chat zulassen oder der Rechtsklick fehlen nach einem dsh-Update:** Diese Elemente hängen sich an das aktuelle HTML von dsh, weil dsh noch keinen Platz für sie hat. Wenn dsh dieses Markup ändert, blenden sie sich selbst aus. Sonst geht nichts kaputt. Bitte eröffne ein [Issue](https://github.com/furkancak1r/dsh-composer-plus/issues).
- **„Update fehlgeschlagen“ oder „nicht über npm installiert“:** Eine Kopie, die aus einem lokalen Ordner verlinkt oder umbenannt wurde, kann sich nicht selbst aktualisieren. Installiere `dsh-composer-plus` über Einstellungen → Plugins neu. Sonst zeigt die Meldung die erste Zeile des pnpm-Fehlers; **Nach Updates suchen** versucht es erneut.
- **Mobile Verbindung meldet, dass das Gateway nicht läuft:** „no IPv4 address on en0“ heißt, dass dieser Mac keine WLAN- oder Ethernet-Adresse hat. „EADDRINUSE“ heißt, dass ein anderes dsh (oder eine andere App) Port 19390 oder 19391 nutzt. Nur ein dsh kann Mobile Verbindung gleichzeitig ausführen.
- **Mobile Verbindung, Nach Neustart fortsetzen oder Inhaltssuche meldet „Starte dsh neu“:** Das Plugin wurde aktualisiert, während dsh lief (oder du hast bei der Inhaltssuche den Schalter geändert). Der neue Zustand lädt nach einem Neustart.
- **Die Suche findet nur Titel:** Die Inhaltssuche ist aus, dsh wurde seit dem Einschalten oder seit der Installation des Plugins nicht neu gestartet, oder das Wort steht nur in einer Tool-Ausgabe (siehe Grenzen).
- **Keine ↶-Schaltfläche an meinen Nachrichten:** Runde zurücknehmen ist aus, der Chat ist ein Subagent-Chat, oder dsh-rewind-plugin ist installiert (nutze dessen ↶-Schaltfläche). Starte dsh nach einem Update neu.
- **Chat und Dateien ist ausgegraut:** Das Projekt ist kein git-Repository, es gibt keinen Snapshot von vor dieser Nachricht (die Nachricht ist älter als das Plugin, oder einer der 50 neuesten Snapshots hat ihn ersetzt), oder keine Datei hat sich geändert.
- **Löschen meldet, dass ein anderes dsh diesen Chat geöffnet hat:** Ein zweites dsh mit demselben dsh-Home hält die Sperre des Chats. Schließe dieses Fenster oder dieses dsh und lösche dann erneut. Der Chat bleibt in der Zwischenzeit archiviert.
- **Mein iPhone verbindet sich nicht, seit ich „Tailscale only“ eingeschaltet habe:** Tailscale muss auf dem Mac und auf dem iPhone eingeschaltet sein. Das Panel Mobile Verbindung warnt, wenn es auf dem Mac aus ist. Das Zugriffsprotokoll zeigt jeden abgelehnten Versuch mit seinem Grund.
- **Ein Chat wurde nach einem Neustart nicht fortgesetzt:** Nach Neustart fortsetzen war aus, als dsh beendet wurde, du hast die Runde selbst gestoppt, die Runde war beendet (fertig oder fehlgeschlagen), der Chat war archiviert, oder mehr als 20 Chats liefen (die neuesten 20 werden fortgesetzt).
- **Die Warteschlange ist nach einem Neustart leer:** dsh selbst leert die Warteschlange beim Beenden. Nach Neustart fortsetzen stellt sie nur in einem Chat wieder her, den es fortsetzt; in anderen Chats sende die Nachrichten erneut. Eine Nachricht, die du kurz vor dem Beenden entfernt hast, kann zurückkommen: Entferne sie erneut.
- **GitHub-Issue öffnen meldet „gh could not open the issue“:** Die Meldung ist die erste Zeile von `gh` selbst. Führe `gh auth status` in einem Terminal aus und melde dich mit `gh auth login` an. Der Ordner des Chats muss ein GitHub-Remote haben (`git remote -v`). „not installed or not on the PATH of dsh“ bedeutet, dass dsh `gh` nicht gefunden hat: Installiere es oder starte dsh aus einem Terminal, in dem `gh` funktioniert.
- **Issue melden zeigt „gh could not open the issue“:** Die Meldung ist die erste Zeile von `gh` selbst. Führe `gh auth status` in einem Terminal aus und melde dich mit `gh auth login` an. Oder klicke auf **Stattdessen auf GitHub öffnen**: Die eigene Seite von GitHub für ein neues Issue öffnet sich mit dem ausgefüllten Entwurf, und du sendest es dort ab.
- **Kein Branch-Etikett an einer Chatzeile:** Die Seitenleiste ist nicht in „In einer Liste“ (in „Arbeitsbereich“ und „Arbeitsbereichsbaum“ zeigt keine Chatzeile ein Etikett), der Chat hatte seit der Installation dieser Version keine Runde, sein Ordner ist kein git-Repository, oder **Git-Branch in Chatzeilen** ist aus. Starte dsh nach einem Update neu (die Host-Hälfte zeichnet den Branch auf).
- **Zielprüfung meldet, dass der Test mit Code 127 oder „not found“ beendet wurde:** Ein dsh, das aus dem Finder oder dem Dock gestartet wurde, kann einen kürzeren PATH als dein Terminal haben und findet daher `npm`, `pnpm` oder `cargo` nicht. Starte dsh aus einem Terminal, oder lege unter **Zielprüfung** → **Bearbeiten** deinen eigenen Testbefehl mit dem vollständigen Pfad fest. **Jetzt ausführen** zeigt das Ergebnis sofort.
- **Das Ziel schließt sich nicht und der Agent arbeitet weiter:** **Zielprüfung** hat einen fehlschlagenden Test oder fehlende Arbeit gefunden. Die Zeile unter dem Ziel zeigt den Grund (fahre mit der Maus über das Ergebnis, um die Details zu sehen). Behebe die Ursache oder den Testbefehl, oder schließe das Ziel selbst mit `/goal` oder der Zielleiste ab (das wird nicht geprüft).
- **Die Installation schlägt direkt nach einem Release fehl:** Gib die Version mit an (`dsh-composer-plus@1.25.0`), siehe den Hinweis zur Installation oben.
- **Jetzt sichern meldet „Eine andere Sicherungsaktion läuft“:** Eine Aktion läuft in einem anderen dsh-Fenster oder in der Rettungskonsole (sie teilen sich eine Sperrdatei, `.composer-plus.lock`, im Sicherungsordner). Warte, bis sie fertig ist. Läuft keine Aktion, wird die Sperre eines beendeten Prozesses beim nächsten Klick übernommen.
- **Die Rettungskonsole meldet „dsh is running“:** Beende zuerst dsh. Ist dsh wirklich geschlossen, ist die in der Meldung genannte Datei von einem Absturz übrig: Entferne sie und versuche es erneut.
- **Nach einer Wiederherstellung startet dsh nicht oder ein Plugin fehlt:** Die Plugin-Pakete eines Profils müssen neu installiert werden. Die Rettungskonsole bietet das nach einer Wiederherstellung an; oder führe `pnpm install` in jedem Ordner unter `$DSH_HOME/profiles/` aus, den sie auflistet. Geheimnisse, die nicht im vault waren (anderer Computer), müssen neu eingegeben werden: Die Konsole listet sie auf.

## Grenzen

- Fortsetzen ohne Nachricht beruht auf dem Lebenszyklus `agent/pre-step` → `agent/request` von dsh. Prüfe die Kompatibilität erneut, wenn du dsh aktualisierst.
- **Funktionsideen** behält die Karten für jeden Chat im Speicher, bis dsh oder die Seite neu lädt. Danach fragt **Funktionen vorschlagen** das Modell erneut. Die Karten kommen in der Oberflächensprache, die dsh beim Klicken hat. Nach einem Sprachwechsel behalten Karten, die schon auf dem Stapel liegen, ihre Sprache, und **Weitere Ideen** nutzt die neue Sprache. Das Modell sieht nur die kurze Projektzusammenfassung, nicht den Code. Eine Idee kann also etwas wiederholen, das das Projekt schon hat: Überspringe sie. Der neue Chat läuft nur im Planmodus, wenn das Profil den Befehl `/plan` von dsh hat. Sonst geht die Idee als normale erste Nachricht hinaus. Die Liste **Später** gehört zum Ordnerpfad des Chats: Derselbe Ordner hat über einen Symlink geöffnet eine eigene Liste. Sie hält höchstens 50 Ideen pro Projekt (entferne eine, um weitere hinzuzufügen) und denselben Titel nur einmal. Das Ziehen einer Karte entscheidet nur über links oder rechts; nutze **↓**, um sie zu merken, und **▶**, um sie sofort umzusetzen. Eine Wiederholung wird nur am Titel erkannt: Das Modell kann eine frühere Idee unter einem neuen Namen trotzdem vorschlagen; überspringe sie. Antwortet das Modell nur mit früheren Ideen, erscheint nichts Neues: Klicke erneut. Ein enges Fokusthema macht das wahrscheinlicher; nutze ein breiteres Thema oder leere es. Das Fokusthema bleibt für jeden Chat im Feld, bis dsh oder die Seite neu lädt.
- **Chat als Markdown exportieren** enthält nur deine eigenen Nachrichten und die Textantworten des Assistenten. Werkzeugaufrufe und ihre Ausgabe, Reasoning, Bilder (eine Zeile `[image]` markiert sie), verborgener Kontext und Nachrichten, die Runde zurücknehmen oder dsh-rewind-plugin entfernt hat, fehlen. Die Antworten einer Runde werden zu einem Abschnitt zusammengefasst. Ein Export enthält höchstens etwa 4 Millionen Zeichen; bei einem längeren Chat enthält er den ersten Teil und einen Hinweis.
- **Nach Neustart fortsetzen** setzt die Runde fort; es spielt sie nicht erneut ab. Ein Tool-Aufruf, der beim Beenden lief, endet mit dem Ergebnis „outcome unknown“ von dsh, und das Modell erhält die Anweisung, fertige Arbeit nicht zu wiederholen. Ein Befehl, der nicht sicher zweimal laufen kann, kann aber erneut laufen. Subagents, Genehmigungen und Fragen, die offen waren, werden nicht wiederhergestellt: Ihr übergeordneter Chat macht weiter und fragt erneut. Höchstens 20 Chats werden bei einem Start fortgesetzt.
- **Nach Neustart fortsetzen** und die Warteschlange: dsh leert beim Beenden die Warteschlange eines Chats. Das Plugin stellt deine Nachrichten aus dem Protokoll des Chats wieder her, mit Reihenfolge, Änderungen, Bildern und Dateien; sie laufen nach der fortgesetzten Runde. Nur Chats, die fortgesetzt werden, bekommen ihre Warteschlange zurück (Schalter an, Beenden während die Runde lief). dsh protokolliert dein eigenes Entfernen der letzten Nachrichten in der Warteschlange genauso: Wenn du sie entfernst und dsh beendet wird, bevor der nächste Schritt beginnt, kommen sie zurück.

- **Inhaltssuche** ist die eigene Suche von dsh und hat daher die Grenzen von dsh. Sie durchsucht nur Benutzer- und Assistentennachrichten: keine Tool-Ausgabe (Befehle, Dateiinhalte, Ergebnisse) und kein Reasoning. Sie hat auch keinen Filter für Benutzer-, Assistenten- oder Tool-Nachrichten. Sie findet ganze Wörter, keine Wortteile (`deploy` findet nicht `deployment`). Buchstaben mit Akzent passen auch ohne Akzent (`seker` findet `şeker`). Eine Zeile pro Chat, mit dem Ausschnitt von 240 Zeichen von dsh, höchstens 20 Zeilen.
- Aufwand der **Inhaltssuche**, gemessen an einer Kopie von 247 echten Chatprotokollen (159 MB, dsh 0.2.1-rc.2, Apple Silicon, 32 GB): Die erste Suche nach einem Start baut den Index in etwa 15 s auf. In dieser Zeit antwortet der Host von dsh etwa 7 s lang nicht. Andere Chats streamen in diesem Moment also nicht (die Seite selbst friert nicht ein). Der Speicher des Hosts wächst in der Spitze um etwa 1,1 GB. Eine Minute später liegt er noch etwa 0,5–0,6 GB über dem Startwert, bis dsh beendet wird. Die Indexdatei hat etwa 165 MB. Spätere Suchen dauern etwa 0,5 s. Nach einem Neustart dauert die erste Suche etwa 1 s (nur neue oder geänderte Chats kommen hinzu) und fügt etwa 70 MB hinzu. Schalte die Funktion aus, wenn dein Computer wenig Arbeitsspeicher hat.
- **Inhaltssuche** gilt erst nach einem Neustart von dsh. Alle dsh-Instanzen, die dasselbe dsh-Home nutzen, teilen sich die Indexdatei: Lass immer nur ein solches dsh gleichzeitig laufen (dsh erlaubt einen Besitzer pro Indexdatei).
- **Runde zurücknehmen** setzt Dateien nur in einem git-Repository zurück und nur im Ordner des Chats. Es behält die 50 neuesten Snapshots pro Chat. Ignorierte Dateien (`.gitignore`, `info/exclude`, deine globale Ignore-Datei), leere Ordner, Symlinks und Submodule werden nicht zurückgesetzt. Eine Datei, die beim Snapshot ignoriert war, wird nie gelöscht, auch wenn die Runde die Ignore-Regeln geändert hat. Eine Datei, die git nicht lesen kann, fehlt im Snapshot. Jede deiner Nachrichten führt ein `git add --all` des Chat-Ordners in den privaten Speicher aus. In einem sehr großen Ordner mit vielen nicht verfolgten Dateien kann das einige Sekunden dauern, und der nächste Tool-Aufruf wartet darauf (höchstens 10 s; der Snapshot wird dann im Hintergrund fertig). Wenn `git gc` in deinem Repository ein Objekt entfernt, das ein alter Snapshot braucht, wird diese Datei als nicht zurückgesetzt aufgelistet. Nur der Text der Nachricht kommt ins Eingabefeld zurück: Füge ihre Bilder oder Dateien erneut hinzu. Subagent-Chats haben kein ↶ (die Dateiänderungen eines Subagents zählen als Änderungen des Chats, der ihn gestartet hat). Der exportierte Chat (`/export`) enthält die zurückgenommenen Nachrichten weiterhin. Die Idee einer verborgenen Markierung, die einen Teil eines Chats zurücknimmt, stammt aus [dsh-rewind-plugin](https://github.com/SiriLee/dsh-rewind) von SiriLee (MIT). Composer Plus nutzt keinen Code daraus.
- **Chat löschen** braucht das Archiv von dsh (dsh 0.2.0 und neuer). Ein Chat (oder einer seiner Subagent-Chats), der nicht innerhalb von 15 s stoppt oder den ein anderes dsh hält, bleibt archiviert, und nichts wird verschoben. Auf anderen Systemen als macOS muss der Papierkorb-Ordner auf demselben Laufwerk liegen wie der Chatverlauf. Ein geöffneter Chat, den du löschst, bleibt archiviert und ausgeblendet im Speicher von dsh, bis dsh neu startet. Leere den Papierkorb selbst; dsh tut das nicht.
- Die Warteschlange von dsh hat keine `move`-Aktion. Deshalb verschiebt die Host-Hälfte des Plugins die eingereihte Nachricht selbst in der Warteschlange von dsh (eine Änderung, dieselbe Nachricht). Nachrichten mit Bildern oder Dateien lassen sich ebenfalls verschieben. Nur deine eigenen Nachrichten lassen sich verschieben: Eine Zielrunde oder eine Antwort auf eine Frage in der Warteschlange bleibt an ihrem Platz. Beginnt das Senden einer Nachricht, während du ziehst, wird nichts verschoben, und ein Hinweis meldet das.
- dsh 0.2.1 lädt ein Update sofort, wenn die neue Version keine Einstellungen von dsh ändert. Andernfalls und unter dsh 0.2.0 starte dsh neu, um das Update zu laden. Das Plugin startet dsh nie für dich neu. Web-/CLI-Profile ohne die Plugin-Verwaltung von dsh melden nur eine neue Version.
- **Neu in Composer Plus N** zeigt die Notes in der Sprache von **App-Sprache**. Eine UI-Sprache mit einer anderen Region bekommt die Notes ihrer Grundsprache (`en-GB` die englischen, `zh-TW` die chinesischen von `zh`). Eine Sprache ohne Notes (eine, die ein anderes Sprachpaket hinzufügt, oder `pt-PT`, das nicht `pt-BR` ist) zeigt die englischen Notes. Die Notes kommen mit der neuen Version. Hat die laufende Kopie keine lesbare Notes-Datei (`release-notes.json`), zeigt das Fenster die englischen Notes von GitHub.
- Eine Version, die installiert wird, während dsh läuft (ein Update über Einstellungen → Plugins oder einen kopierten Ordner), lädt erst nach einem Neustart von dsh. Bis dahin zeigt **Composer-Plus-Updates** die laufende Version und bittet um einen Neustart. Ihr Fenster **Neu in Composer Plus N** erscheint einmal beim ersten Start dieser Version. Der erste Start nach der Installation dieses Plugins zeigt kein Fenster; **Neu in dieser Version** öffnet die Notes der laufenden Version.
- Die GitHub-Stern-Zeile unter den Notes kann nicht wissen, ob du dem Repository schon einen Stern gegeben hast: Das Plugin macht dafür keinen Netzwerkaufruf. Jeder Browser (und die Desktop-App) speichert seinen eigenen Stand, daher kann die Zeile in einem anderen noch einmal erscheinen.
- **Mit Notiz ablehnen** sendet die Notiz als Nachricht in die wartende Runde und lehnt dann die Anfrage ab. dsh zeigt die Notiz im Chat als deine Nachricht. Solange das Notizfeld offen ist, zeigt die Karte nur **Abbrechen** und **Ablehnen**, sodass ein Klick die Anfrage nicht aus Versehen zulassen kann. `Esc` oder **Abbrechen** bringt die Schaltflächen von dsh zurück. Eine leere Notiz sendet nichts (nutze die eigene Schaltfläche **Ablehnen** von dsh). Schlägt die Ablehnung fehl, nachdem die Notiz gesendet wurde (zum Beispiel, weil die Anfrage inzwischen an anderer Stelle beantwortet wurde), bleibt die Notiz im Chat, und das Modell liest sie bei seinem nächsten Schritt. Die Schaltfläche kommt in das Markup der Genehmigungskarte von dsh (`data-approval-key`), weil dsh keinen Platz für Aktionen der Karte hat. Ändert ein dsh-Update dieses Markup, erscheint die Schaltfläche nicht, und die eigene Schaltfläche **Ablehnen** von dsh funktioniert wie zuvor. Eine Notiz kann höchstens 4.000 Zeichen haben.
- **Geheime Eingabe** verbirgt nur den genauen Text eines Werts: `[secret]` ersetzt ihn in den späteren Tool-Ergebnissen desselben Chats. Der Agent kann die Datei trotzdem mit einem Shell-Befehl lesen und den Wert in anderer Form ausgeben (base64, ein Teil davon, mit Leerzeichen), und diese Form erreicht das Modell. Die eigenen Datei-Tools des Agenten (read, grep, write, edit) können den Geheimnis-Ordner nicht öffnen. Ist der Wert auch ein häufiges Wort, zeigen andere Ergebnisse dieses Chats ebenfalls `[secret]`. Nur der markierte Text kommt ins Eingabefeld: Ändert sich die Datei später, ändert sich das Zitat nicht.

Ein laufender Schritt des Chats wird in der Kopie geschlossen: Der Nebenchat kennt den Anfang dieses Schritts, aber nicht sein Ergebnis. Der Nebenchat ist ein normaler Chat: Er bleibt in der Seitenleiste und zählt zu deiner Modellnutzung; archiviere ihn dort. Sie findet die Karte über das Markup von dsh (`data-question-key`, `data-question-scroll`); ändert ein dsh-Update dieses Markup, erscheint die Karte so, wie dsh sie zeichnet. Eine Nachricht, die ein Zurücknehmen entfernt hat oder die die Komprimierung aus dem Verlauf entfernt hat, den dsh lädt, kann nicht angezeigt werden: Der Link sagt das dann. Die 🔗-Schaltflächen hängen sich an die Nachrichtenzeilen von dsh. Wenn ein dsh-Update dieses Markup ändert, erscheinen sie nicht.

Wenn dsh dieses Menü ändert, erscheint der Eintrag ebenfalls nicht.

Eine Datei, die du nach dem Zurücknehmen geändert hast, bleibt erhalten, außer du setzt das Häkchen, das sie überschreibt. Wiederholen braucht den Snapshot, den das Zurücknehmen behalten hat (dasselbe Fenster von 50 Einträgen). Ein Zurücknehmen vor dieser Version oder mit **Nur Chat** holt nur die Nachrichten zurück.

Ein gemergter Branch zeigt auf den Branch, dessen Merge-Commit ihn zuerst aufgenommen hat. In **Arbeitsbereichsbaum** bleibt ein übergeordneter Ordner sichtbar, solange ein Projekt darin aktiv ist, und auch die Chatzeilen, die in den letzten 2 Stunden nicht aktiv waren, werden ausgeblendet; in **Arbeitsbereich** werden nur Projektzeilen gefiltert. Der Filter liest die Ansicht, die dsh zeigt, aus der gespeicherten Ansichtseinstellung von dsh (keine öffentliche API); benennt ein dsh-Update sie um, wird **Arbeitsbereichsbaum** wie **Arbeitsbereich** gefiltert. Die Funktion Projektstatus liest dieselbe Einstellung: In **Arbeitsbereichsbaum** zählt die Zeile eines übergeordneten Ordners auch die Chats der Projekte darin; benennt dsh die Einstellung um, zeigt jede Zeile nur ihre eigenen Chats. **Nach Status** hat dieselbe Art von Grenze: dsh hat keinen Platz für eine Sortierung. Deshalb hängen sich der Eintrag und die Zeilenreihenfolge an das Menü- und Listen-Markup von dsh.
- dsh hat auch kein Menü für Projektzeilen und keinen Platz in der Kopfzeile der Arbeitsbereiche. **Pfad kopieren** findet die Projektzeile über das Zeilen-Markup von dsh. **Alle Projekte einklappen** sitzt in der Kopfzeile von dsh und schließt jedes geöffnete Projekt mit demselben Klick wie die Projektzeile. Wenn ein dsh-Update dieses Markup ändert, zeigt ein Rechtsklick das Menü des Browsers, und die Schaltfläche erscheint nicht.
- dsh hat auch im Projektmenü eines neuen Chats keinen Erweiterungspunkt. Deshalb hängen sich das Feld **Projekte durchsuchen** und die A–Z-Reihenfolge an das Menü-Markup von dsh. Wenn ein dsh-Update dieses Markup ändert, erscheint das Menü so, wie dsh es zeichnet: in der gespeicherten Reihenfolge und ohne das Feld. Die A–Z-Reihenfolge ist nur eine Ansicht: Sie ändert die gespeicherte Projektreihenfolge von dsh nicht.
- dsh hat auch keinen Erweiterungspunkt, der wählt, wo **Neue Sitzung** öffnet. **Standard-Arbeitsbereich für Neue Sitzung** umhüllt eine Methode von dsh, die keine öffentliche API ist (`startSession` des Arbeitsbereich-Dienstes von dsh). Wenn ein dsh-Update sie umbenennt, öffnet **Neue Sitzung** dort, wo dsh es wählt (das geöffnete oder das letzte Projekt). Jeder Aufruf ohne Projekt nutzt den Standard: die Schaltfläche in der Seitenleiste, ihr Tastenkürzel, das Logo und auch **Neu** auf der Seite **Automatisierungsaufgaben**. dsh öffnet beim Start weiterhin den letzten Chat. Der allgemeine Ordner wird bei der ersten Nutzung angelegt und zu deinen Projekten hinzugefügt; unter Windows oder Linux mit verschobenem Documents-Ordner kann er ein anderer Ordner als der von dsh sein.
- dsh hat auch für einen Hinweis im Eingabefeld keinen Erweiterungspunkt. Deshalb liegt der Text von **Vorhersage der nächsten Nachricht** über dem eigenen Platzhalter von dsh (`[data-composer-placeholder]`). Wenn ein dsh-Update dieses Markup ändert, erscheint keine Vorhersage. Solange die Funktion an ist, kostet jede beendete Runde einen kurzen Modellaufruf.
- Der Text von **Beim Tippen vervollständigen** erscheint über den eigenen Eingabehinweis von dsh (den Stil `--dsh-composer-hint`, den dsh für den Argumenthinweis eines Slash-Befehls nutzt). Die Funktion läuft nicht bei einem Slash-Befehl, bei einer Nachricht mit einem Datei- oder Symbol-Chip oder wenn der Cursor nicht am Ende der Nachricht steht. Wenn ein dsh-Update diesen Stil ändert, erscheint keine Vervollständigung. Jede Pause beim Tippen kostet einen Modellaufruf.
- **Prompt verbessern** sieht nur eine kurze Projektzusammenfassung, die geänderten Pfade und die Pfade, deren Namen zu deinen Wörtern passen: nicht den Code selbst. Daher kann die Funktion die richtige Datei übersehen, und sie nennt nur Pfade, die sie bekommen hat. Lies den neuen Text, bevor du ihn sendest. Sie läuft nicht bei einem anderen Slash-Befehl als `/goal <Ziel>`, bei einem Steuerwort von `/goal` (`clear`, `pause`, `resume`) oder bei einer Nachricht mit einem Datei- oder Symbol-Chip (der neue Text ist reiner Text, der Chip ginge also verloren), und eine Nachricht kann höchstens 8.000 Zeichen haben. Für ein `/goal`-Ziel schreibt sie Bedingungen nur aus dem Entwurf und dem Kontext. Eine zu strenge Bedingung kann Zieldurchläufe kosten, lies sie also, bevor du sie sendest. Bilder bleiben angehängt: Nur der Text ändert sich. Jeder Klick kostet einen Modellaufruf; ein starkes Modell kann eine Minute brauchen (`Esc` bricht ab).

Der Agent kann die Tests oder die Dateien des Testbefehls selbst ändern; der Prüfer liest den Chat und kann das sehen, kann sich aber in beide Richtungen irren (ein falsches „nicht fertig“ kostet einen Durchlauf mehr; ein falsches „fertig“ schließt das Ziel). Der Prüfer sieht den Chat und `git status`, nicht den Code selbst. Ein Testlauf wird nur wiederverwendet, wenn der neueste Schritt des Agenten, der Dateien ändern kann, sein eigener erfolgreicher `bash`-Lauf genau desselben Befehls im selben Ordner war; ein Befehl mit einer Pipe (`| tail`) oder `&&` wird nicht wiederverwendet. Das Budget wird gemessen, wenn eine Runde endet. Daher kann eine Runde darüber hinausgehen. Das Token-Budget zählt auch die Aufrufe der Subagent-Chats des Chats (gelesen aus ihren gespeicherten Protokollen am Ende jeder Runde, daher dauert die Prüfung eines Chats mit vielen Subagents etwas länger). Die Nachweistabelle kommt aus der eigenen Lektüre des Chats durch den Prüfer: Einen Teil, den er bestätigt nennt, solltest du selbst ansehen, wenn er wichtig ist. `update_goal` wartet, während die Prüfung läuft (der Test höchstens 15 Minuten, der Prüfer höchstens 3 Minuten). Eine Abzweigung bekommt eine neue Chat-ID und startet daher ohne den eigenen Testbefehl und die Limits des übergeordneten Chats. Jeder Abschluss, der den Prüfer erreicht, kostet einen Modellaufruf.
- **Geschützte Dateien** ist eine Leitplanke, keine Sandbox. Die Funktion deckt die eigenen Datei-Tools von dsh ab (`read`, `read_image`, `grep` auf eine Datei, `write`, `edit`, `str_replace_editor`). Ein Shell-Befehl (`cat .env`), ein Skript, das der Agent schreibt, die Shell eines Subagents, ein MCP-Tool, eine `glob`-Liste und ein `grep` über einen ganzen Ordner können eine geschützte Datei trotzdem erreichen. Für eine echte Grenze nutze die Sandbox-Modi von dsh oder halte Geheimnisse aus dem Projektordner heraus. Muster kennen `*`, `**` und `?`, nicht `{a,b}` oder `[ab]`, und sie ignorieren Groß- und Kleinschreibung.
- **Blockierte Befehle** ist eine Leitplanke, keine Sandbox. Die Funktion liest nur den Befehlstext der Tools `bash` und `pwsh` von dsh. Eine Variable oder ein Alias, die den Befehl nennen (`CMD=npm; $CMD publish`), eine Shell-Funktion, eine Skriptdatei, die der Agent schreibt, ein anderes Programm (`python -c`, `node -e`, `make`), ein MCP-Tool und dein eigenes Terminal können ihn trotzdem ausführen. Eine Regel passt auf mehr, als du vielleicht willst: Jedes Wort eines Befehls kann der Befehlsname sein (`echo npm publish` passt auf `npm publish`), und zwischen den Wörtern der Regel können andere Wörter stehen (`git push --force` passt auch auf `git push origin main --force`). Mach eine Regel länger, wenn sie auf zu viel passt. Eine Regel mit **zuerst fragen** braucht einen Chat, der fragen kann: In einem Chat mit der Genehmigungsrichtlinie „never“ (zum Beispiel einem delegierten Subagenten) kann dsh die Karte nicht zeigen, deshalb wird der Aufruf mit dem Grund abgelehnt. Die Genehmigungskarte zeigt den Grund auf Englisch. **Für diesen Chat zulassen** beantwortet keine Karte von **zuerst fragen**.
- **In einem neuen Chat fortsetzen** sendet den Chat (Nachrichten, Werkzeugaufrufe und das Ende jedes Werkzeugergebnisses, höchstens etwa 60.000 Zeichen, den neuesten Teil) an das eigene Modell des Chats. Die Übergabenotiz kann eine Entscheidung oder eine Datei auslassen: Lies sie vor dem Start. Der neue Chat kennt nur die Notiz und den verlinkten Chat (dsh hängt den alten Chat als schreibgeschützten Kontext an). Sein Modellkontext beginnt klein, der alte Chat bleibt, wie er ist. Pro Chat läuft immer nur eine Notiz oder ein Start.
- **Kontextaufschlüsselung** zeigt Schätzungen nach der eigenen Regel von dsh (etwa 4 Zeichen pro Token), derselben Regel wie beim Kontextring von dsh. Die eigene Zählung des Modells kann abweichen. Die Tool-Definitionen sind die der neuesten Anfrage. Die Funktion zeigt den Kontext so, wie das Chatprotokoll ihn enthält. Eine Runde, die gerade läuft, erscheint nach ihrem nächsten Schritt.
- **Geplante Schritte** spart nur dann Tokens, wenn das Modell plant: Solange die Funktion an ist, trägt jede Anfrage das Tool `plan_next_steps` und eine kurze Anweisung (etwa 500 Tokens), auch in Chats, in denen das Modell nie plant. Eine Bedingung beweist nur, was sie sagt (zum Beispiel: der Exit-Code des Builds war 0), nicht, dass die Arbeit stimmt. `ok` liest die eigenen Ergebnismarken von dsh (`[exit code: N]`, Zeitüberschreitungen, Sandbox-Ablehnungen); ein Befehl, der ohne Exit-Code ungleich null fehlschlägt, gilt als bestanden. Schritte laufen einzeln; zwei gleichzeitig bereite Schritte gehen an das Modell zurück. Die Nachricht des Schritts wird als Assistentennachricht des Chat-Modells gespeichert (dsh hat keine Markierung für eine Nachricht, die ein Plugin schreibt), daher sagt ihr Text, dass Composer Plus ihn ausgeführt hat. Nicht in Tether.
- **Türkisches Skill-Paket** installiert einen Skill von Dritten: Seine Regeln kommen aus dem GitHub-Repository des Autors, nicht von Composer Plus, und eine neue Version gilt ab der nächsten täglichen Prüfung, ohne dass wir sie prüfen. Die Prüfung beweist, dass die Dateien die sind, die GitHub für diesen Commit auflistet, nicht dass die Regeln gut sind. Das Modell entscheidet, wann es den Skill lädt (du kannst ihn auch mit Namen aufrufen); die Regeln gelten nur für türkische Texte. Die Host-Hälfte nutzt die Sprache, die ein Browser zuletzt gemeldet hat: Nutzen zwei Browser verschiedene Sprachen, gilt die neueste Meldung. GitHub erlaubt ohne Anmeldung 60 API-Aufrufe pro Stunde; eine abgelehnte Prüfung behält die installierte Kopie und zeigt den Grund in den Einstellungen.
- **Codebasis entwirren** enthält eine feste Kopie des Skills (caldoai/skills, Commit f3cf477): Eine Änderung im Original kommt erst mit einer neuen Composer-Plus-Version. Der Skill führt ein langes Ziel aus, das viele Dateien ändern kann, und seine Subagenten und Prüfungen verbrauchen viele Tokens. Wo das Projekt keine Tests hat, kann er das Verhalten unbemerkt ändern: Starte ihn in einem Branch und lies den Diff vor dem Merge. Ein Skill mit demselben Namen im Projekt, in einem eigenen Skill-Ordner oder in `~/.dsh/skills` ersetzt ihn. Solange der Schalter aus ist, geht `/untangle-codebase` als normaler Text an das Modell.
- **Aufgabentafel** zeigt die Chats, die dsh in diesem Fenster auflistet: Ein Chat außerhalb eines Projekts erscheint nur unter **Alle Projekte**, und der Ordner eines Branches pro Chat (`<project>/.worktrees/<name>`) zählt zu seinem Projekt. Die Spalte einer Karte ist der Live-Zustand des Chats, daher lassen sich Karten nicht ziehen: Ein Chat kommt nach **Fertig**, wenn seine Runde endet, auch nach einem Fehler oder einem Stopp, und zurück nach **In Arbeit**, wenn er wieder läuft. Der grüne Punkt ist der Fertig-Punkt von dsh, den dsh nur in diesem Fenster behält: Nach einem Neuladen erscheinen beendete Chats ohne ihn. **Fertig** zeigt die neuesten 50 Chats (**N ältere anzeigen** zeigt den Rest). **Projekte durchsuchen** findet ein Projekt nur über seinen Namen, nicht über seinen Ordnerpfad. **In den letzten 2 Stunden aktiv** blendet ein Projekt aus, wenn jeder seiner Chats älter als 2 Stunden, inaktiv und gelesen ist; die Tafel zeigt das Projekt, das du gewählt hast, weiterhin. **Neue Aufgabe** merkt sich nur den neuesten neuen Chat dieses Fensters: Wenn du vor der ersten Nachricht einen anderen Chat öffnest, bleibt dieser Chat als **Neue Aufgabe** oben in **In Arbeit**, bis du darin schreibst, aber die Tafel kommt nur für den neuesten von selbst zurück. Nach einem Neuladen steht ein neuer Chat ohne Nachricht nicht auf der Tafel (dsh behält ihn als seine leere Neue Sitzung). Die Schlagwörter kommen aus einem Modellaufruf pro Aufgabe, aus ihrer ersten Nachricht: Sie können falsch sein, und ein Chat, den du nicht auf der Tafel gestartet hast, hat keine. Der Titel ist der Chattitel von dsh (der Titeldienst von dsh, mit dem Modell des Chats); bis er da ist, zeigt die Karte die erste Zeile der ersten Nachricht. **×** und **Alle entfernen** nehmen Karten nur von der Tafel: Kein Chat wird gelöscht. **Rückgängig** erscheint nur 8 Sekunden lang, in diesem Fenster; später holt **Entfernt (N)** → **Zurücklegen** eine Karte zurück, und ein Chat, der wieder läuft, kommt von selbst zurück. **Alle entfernen** fragt zuerst und nimmt die gelesenen fertigen Karten des gezeigten Projekts von der Tafel (bei **Alle Projekte** die aller Projekte), auch die hinter **N ältere anzeigen**; eine ungelesene (grüne) Karte bleibt. dsh behält seinen grünen Punkt nur in diesem Fenster, daher kann Alle entfernen nach einem Neuladen eine Karte nehmen, deren Antwort du nicht gelesen hast. Die Liste liegt auf diesem Mac, für jedes Fenster und für Tether; wenn sie 5.000 Chats hat, kommen die ältesten zurück. **Antworten** beantwortet nur die neueste Anfrage des Chats: Wenn sie an anderer Stelle beantwortet wurde (ein anderes Fenster, Tether, die automatische Prüfung) oder der Chat etwas Neues fragt, sagt das Panel das und sendet nichts. Frühere Versionen hatten eine Aufgabenliste mit Kommentaren und Agenten-Tools; diese gibt es nicht mehr, und die alte `board.json` wird nicht angezeigt. Die Idee und das Aussehen stammen von [Kanzo](https://github.com/emanuele-em/kanzo) von emanuele-em (AGPL-3.0); Composer Plus nutzt keinen Code daraus. `Cmd+Shift+K` ist ein dsh-Tastenkürzel: Im Browser unter Linux hat es keine Standardtaste (lege eine auf der Seite Tastenkürzel von dsh fest), und eine Browser-Erweiterung oder eine andere App kann die Taste vorher belegen. Eine Karte verlässt **Fertig**, wenn der grüne Punkt von dsh verschwindet (du hast den Chat geöffnet), oder, bei einem Chat, der hinter der Tafel als offener Chat fertig wurde, wenn dieser Chat ohne Panel darüber zu sehen ist. Dieser Gelesen-Zustand lebt nur in diesem dsh-Fenster, wie die Punkte von dsh: Nach einem Neuladen oder in einem anderen Fenster zählt jeder beendete Chat als gelesen und steht in **Kürzlich beendet**.
- **Assistent** hat einen Chat für alle Fenster dieses Macs. Er läuft mit dem Berechtigungsmodus workspace-write: Er schreibt Dateien nur in `~/Assistant`, und ein Befehl außerhalb dieses Ordners fragt zuerst. Wenn du den Chat auf einen Modus ohne Genehmigungen (Vollzugriff) umstellst, lehnt dsh jede Genehmigung ab. Dann kann der Assistent keinem Chat eine Nachricht senden und keinen Chat starten, stoppen oder archivieren. Die Genehmigungskarte schützt nur die sechs Tools: Ein Shell-Befehl des Assistenten kann weiterhin das Netzwerk erreichen, wie in jedem Chat mit diesem Modus. Unter dsh 0.2.0 und 0.2.1 sehen die Planungs-Tools von dsh nur die Erinnerungen des Assistenten-Chats selbst, nicht die Automatisierungen anderer Chats; ab dsh 0.2.2 listen und ändern sie jede geplante Aufgabe. chats_list lässt archivierte, leere und Subagent-Chats sowie den Assistenten-Chat selbst weg; „wartet auf dich“ bedeutet eine offene Genehmigung, Frage oder Planprüfung in einem laufenden Chat. chat_read liefert die Nachrichten des Benutzers und die Antworten des Agenten (keine Tool-Ausgabe), höchstens 50 Nachrichten und etwa 24.000 Zeichen. chat_archive lehnt einen Chat ab, der noch läuft oder aktive Erinnerungen hat. Ein Text, den das Modell liest, kann es trotzdem täuschen: Die Genehmigungskarte ist die letzte Prüfung, also lies sie, bevor du auf **Einmal zulassen** klickst. Parallele Themen nutzen das Subagent-Tool von dsh: Ein Profil oder Berechtigungsmodus ohne dieses Tool behält das alte Verhalten (ein Thema nach dem anderen; die nächste Nachricht wartet in der Warteschlange oder steuert die laufende Runde). Das Modell entscheidet, was als lange Aufgabe gilt, daher kann auch eine kurze Frage eine Runde belegen. Der Subagent jedes Themas läuft mit eigenen Tokens; wenn dsh neu startet, stoppt ein laufendes Thema (sein Ergebnis kommt nicht zurück). Ein Ergebnis kommt als neue Runde des Assistenten-Chats zurück, daher wartet es, während du mitten in einer Runde schreibst.
- **Assistent getrennt von Chats** und **Nur Nachrichten im Assistenten** blenden die eigenen Zeilen von dsh mit einer Stilregel aus. Ein Wechsel in einem laufenden Chat ändert seinen System-Prompt einmal, daher kann diese eine Anfrage den Cache des Modellanbieters nicht nutzen. Ein Subagent folgt seinem Wurzel-Chat. Die Prüfung liest die Nachrichten nicht, die ein Chat bekommt, während sein Gedächtnis aus ist, auch nicht, wenn du es später wieder einschaltest. In dsh 0.2.0 hat der Bildschirm Neuer Chat keinen Platz für den Knopf: Er erscheint nach der ersten Nachricht in der Chat-Kopfzeile.
- **Gedächtnisnotizen aus einem Chat vorschlagen** zeigt höchstens 10 Vorschläge und behält sie 30 Minuten und bis zum Neustart von dsh; danach bittet Annehmen dich, neu vorschlagen zu lassen. Ein langer Chat sendet seine neuesten Nachrichten: Die ältesten Antworten des Agenten fallen zuerst weg. Ein Vorschlag kann falsch sein: Lies ihn, bevor du ihn annimmst, und nutze **Gedächtnis öffnen**, um eine Notiz später zu ändern. Ein abgelehnter Vorschlag kann beim nächsten Klick wiederkommen.
- **Sicherung** nutzt einen einzigen festen Ordner, `~/Desktop/dsh-backups` (der Standardordner von dsh-backup, damit dessen Archive nutzbar bleiben); eine Einstellung für einen anderen Ordner gibt es nicht. Ein Archiv ist etwa so groß wie das dsh-Home ohne `cache/` und `dsh-runtimes/` (gemessen: 1,6 GB Dateien ergaben auf Apple Silicon in etwa 30 s ein Archiv von 830 MB; dsh reagierte weiter). Eine Datei, die sich beim Lesen ändert, wird so gespeichert, wie sie war, als die Sicherung sie geöffnet hat. Daher kann das Protokoll eines offenen Chats mit einem abgeschnittenen Datensatz enden, den dsh beim nächsten Schreiben repariert. Die Maskierung findet ein Geheimnis in einer yml-Datei am Namen seines Schlüssels in einer Zeile (`token:`, `apiKey:`, …); ein Geheimnis in einer Flow-Map (`{token: x}`), in einer Liste unter einem solchen Schlüssel, in einer JSON-Datei (zum Beispiel der `apiKey` eines MCP-Servers in einer `.json`-Datei) oder unter einem anderen Namen bleibt im Archiv. Die typisierten Archive von dsh-backup (`dsh-t-…`) werden nicht aufgelistet. **Für einen anderen Computer** kopiert das Archiv (unter APFS ein Klon: kein zusätzlicher Platz); der vault kommt nicht mit. **Jetzt sichern** löscht keine Sicherung. Eine automatische Sicherung behält die neuesten Sicherungen, die Composer Plus erstellt hat (die Einstellung **Behalten** von **Automatische Sicherung**), und löscht die älteren davon; Snapshots vor einem Upgrade werden getrennt gezählt (die neuesten 2 bleiben). Archive von dsh-backup werden nie gelöscht: Entferne sie mit **Löschen**. Solange dsh-backup noch installiert ist, zählt es die Archive von Composer Plus zu seiner eigenen Anzahl behaltener Sicherungen und kann sie löschen.
- **Wiederherstellen** läuft nur in der Rettungskonsole, während dsh geschlossen ist, und ersetzt das ganze dsh-Home. Das alte bleibt daneben als `.dsh.pre-restore-<time>`, bis du es entfernst; die Festplatte braucht also Platz für beide. Chats behalten ihre Projektpfade: Auf einem anderen Computer erscheint ein Projekt unter einem anderen Pfad als fehlend, bis du es neu hinzufügst. Symlinks, die aus dem dsh-Home hinaus zeigen (zum Beispiel Skills, die aus einem anderen Ordner verlinkt sind), kommen als Links zurück; ihre Ziele müssen auf diesem Computer existieren.
- **Sitzungsprotokoll-Prüfung** liest das neueste Protokoll jedes Chats mit den eigenen Regeln von dsh dafür, was aufgeht: Eine Zeile, die kein JSON ist oder nicht in der richtigen Reihenfolge steht, zählt nur dann als Schaden, wenn danach ein Rundenende kommt (sonst öffnet dsh den Chat ohne die Zeilen ab dort, daher wird er nicht aufgelistet). Sie prüft die Ereignisse eines Protokolls nicht gegen die eigenen Ereignisregeln von dsh. Daher kann ein Protokoll, das sie für intakt hält, nach einem dsh-Upgrade trotzdem nicht aufgehen. Eine Reparatur nimmt die Kopie aus einer Sicherung: Die Nachrichten nach dieser Sicherung gehen in diesem Chat verloren (die beschädigte Datei bleibt daneben). Ein Chat, der in diesem dsh offen ist, wird in den Einstellungen nicht repariert: dsh hält ihn.
- **Automatische Sicherung** läuft nur, während dsh läuft: Eine Sicherung, die fällig war, während dsh geschlossen war, läuft etwa 45 s nach dem nächsten Start. Der Snapshot für eine neue Version entsteht nach diesem Start, nicht vor dem Update.
- **Fenstergröße merken** funktioniert nur in der Desktop-App. Bei jedem Start zeigt dsh sein Fenster zuerst in 1280 × 820; das Fenster wechselt zur gespeicherten Größe, sobald das Plugin lädt. Eine Seite hat kein Ereignis für eine Fensterverschiebung, darum liest das Plugin das Fenster einmal pro Sekunde: Eine Änderung in den letzten 2 Sekunden vor dem Beenden von dsh wird nicht gespeichert. Die Größe wird pro Computer im eigenen Speicher der App gehalten.
- **Nutzungszählung:** Gezählt werden Kopien, keine Personen: Jedes dsh-Home ist eine Kopie. Die Zählung der einzelnen Kopien (`installed.txt`) erfasst nur Kopien, die auf die erste Version mit dieser Datei oder eine neuere aktualisieren; eine Kopie, die auf einer älteren Version bleibt, wird nicht gezählt. Eine Kopie, deren Ordner `storages` gelöscht wird, wird noch einmal gezählt. GitHub kann Anfragen von derselben IP-Adresse (zum Beispiel von mehreren Computern hinter einem NAT-Router) innerhalb von etwa 10 Minuten als eine zählen.
- Eingebaute Unterstützung ist upstream angefragt: `move` für die Warteschlange in [#773](https://github.com/deepseek-ai/deepseek-harness/discussions/773), ein Zustand für Fortsetzen in [#9269](https://github.com/deepseek-ai/deepseek-harness/discussions/9269).

## Häufige Fragen

**Wie füge ich DeepSeek Harness einen Bereich für Änderungen / git-Diffs hinzu?** Installiere `dsh-composer-plus` und öffne dann rechte Seitenleiste → `+` → **Änderungen**.

Wische nach rechts, um einen neuen Chat zu starten, der die Funktion plant. Klicke auf **▶ Sofort umsetzen**, um einen Chat zu starten, der sie ohne Plan sofort umsetzt. Wische nach links, um sie zu überspringen.

**Kann die Seitenleisten-Suche von dsh einen Chat über ein Wort in seinen Nachrichten finden, nicht nur über den Titel?** Ja, mit **Inhaltssuche** (standardmäßig an): Starte dsh nach der Installation des Plugins einmal neu und nutze dann die Lupe neben **Arbeitsbereiche**. Passende Chats zeigen den Text um das Wort herum.

**Kann ich eine Runde rückgängig machen und meinen Prompt bearbeiten, wie in OpenCode oder Claude Code?** Ja, mit **Runde zurücknehmen**: Klicke an der Nachricht auf **↶**, wähle **Chat und Dateien**, bearbeite den Text, der ins Eingabefeld zurückkommt, und sende ihn.

**Kann ich einen Chat löschen, statt ihn zu archivieren?** Ja, mit **Chat löschen**: **…** → **Löschen…**. Der Verlauf kommt in den Papierkorb, also lässt sich ein Fehler rückgängig machen.

**Wie sehe ich, zu welchem Projekt ein Chat gehört?** Sieh auf die Zeile unter dem Eingabefeld: Mit **Projektname im Eingabefeld** (standardmäßig an) beginnt sie mit dem Projektnamen. Fahre mit der Maus darüber, um den Ordnerpfad zu sehen.

**Wie bekomme ich einen ↑/↓-Nachrichtenverlauf im Eingabefeld von dsh?** Installiere dieses Plugin. In einem leeren Eingabefeld gehst du mit `↑` / `↓` durch deine gesendeten Nachrichten.

**Wie setze ich eine gestoppte oder fehlgeschlagene Runde in dsh fort, ohne „continue“ zu tippen?** Mit diesem Plugin wird die Senden-Schaltfläche nach einer gestoppten, fehlgeschlagenen oder abgebrochenen Runde zu **▶**. Ein Klick setzt die Runde fort.

**Setzt dsh laufende Chats fort, nachdem ich es beendet und wieder geöffnet habe?** Nicht von selbst: dsh markiert eine solche Runde als unterbrochen und wartet (ein Ziel wartet auch auf `/goal resume`). Schalte **Einstellungen → Composer Plus → Nach Neustart fortsetzen** ein: Die Chats, die beim Beenden von dsh gearbeitet haben, machen dann beim nächsten Start von selbst weiter.

**Welches Modell schreibt die Vorhersage?** Das Modell, das du unter **Einstellungen → Composer Plus → Vorhersage der nächsten Nachricht → Modell** wählst. Die Liste ist die eigene Modellliste von dsh. **dsh-Standard** folgt dem Standardmodell von dsh. Wenn dsh das gewählte Modell nicht mehr listet, nutzt die Vorhersage den Standard. **Beim Tippen vervollständigen** hat ein eigenes Menü **Modell**: **Wie Vorhersage der nächsten Nachricht** (der Standard) folgt dem Modell der Vorhersage. Eine andere Wahl gilt nur für Vervollständigungen. Wenn dsh dieses Modell nicht mehr listet, nutzen Vervollständigungen das Modell der Vorhersage.

**Kann dsh meinen Prompt vor dem Senden verbessern, wie die Schaltfläche Enhance prompt in Roo Code oder Augment?** Ja, mit **Prompt verbessern** (standardmäßig an): Tippe eine grobe Anfrage und klicke auf den Zauberstab neben dem Modellmenü. Die Funktion schreibt den Text mit diesem Chat und dem Projekt als Kontext neu, in deiner Sprache, und sendet ihn nicht. `Cmd/Ctrl+Z` oder **Verbesserung rückgängig machen** holt deinen Text zurück. Wähle ihr Modell unter **Einstellungen → Composer Plus → Prompt verbessern → Modell**.

**Kann der Agent aufhören, seine eigene Arbeit als fertig zu markieren, wie bei den Prüfschleifen im Loop Engineering?** Ja, mit **Zielprüfung** (standardmäßig an): Starte ein Ziel mit `/goal`. Wenn der Agent sagt, dass das Ziel abgeschlossen ist, laufen die Tests des Projekts, und ein unabhängiger Modellaufruf prüft das Ziel anhand des Chats; schlägt eins davon fehl, bleibt das Ziel offen und der Agent liest den Grund. Lege deinen eigenen Testbefehl, ein Zeitlimit oder ein Token-Limit mit **Bearbeiten** in der Zeile **Zielprüfung** unter dem Ziel fest.

**Kann sich der Agent meine Vorlieben über Chats hinweg merken, wie das Gedächtnis von DS Bot?** Ja, mit **Projektgedächtnis** (standardmäßig aus): Schalte es unter **Einstellungen → Composer Plus** ein. Nach jeder Runde werden deine dauerhaften Vorlieben und Entscheidungen als kurze Notizen für das Projekt des Chats gespeichert, und jeder neue Chat in diesem Projekt liest sie. Bitte den Agenten, sich etwas zu merken, dann speichert er es sofort. Um die Notizen zu sehen oder zu ändern, klicke in derselben Zeile auf **Gedächtnis öffnen** und schreibe, was sich ändern soll.

**Ich oder die KI haben das Gedächtnis falsch geändert. Kann ich die alten Notizen zurückholen?** Ja, mit **Versionsverlauf des Gedächtnisses** (standardmäßig an): Wähle in **Gedächtnis öffnen** das Projekt und dann **Verlauf**. Wähle die Version vor der Änderung, um zu sehen, was zurückkommt, dann **Wiederherstellen**.

**Kann ich das Projektgedächtnis mit meinem Team oder einem anderen Agent-Tool teilen?** Ja, mit **Gedächtnis nach AGENTS.md exportieren** (standardmäßig an): Wähle in **Gedächtnis öffnen** das Projekt und dann **Nach AGENTS.md exportieren**. Prüfe den Diff, dann **AGENTS.md schreiben**, und committe die Datei.

**Kann die KI vorschlagen, was aus einem langen Chat behalten werden soll?** Ja, mit **Gedächtnisnotizen aus einem Chat vorschlagen** (standardmäßig an, solange **Projektgedächtnis** an ist): Klicke in der Chat-Kopfzeile auf **Für das Gedächtnis vorschlagen** und dann bei den Notizen, die es wert sind, auf **Annehmen**.

**Kann ich alle meine Chats als Kanban-Tafel sehen und von dort neue starten?** Ja, mit **Aufgabentafel** (standardmäßig an): Öffne sie in der linken Seitenleiste. Jeder Chat ist eine Karte in **In Arbeit**, **In Prüfung** (er wartet auf dich) oder **Fertig**. **Neue Aufgabe** öffnet den neuen Chat von dsh im Projekt, und die Tafel kommt zurück, wenn deine erste Nachricht abgeht; klicke auf einer orangen Karte auf **Antworten**, um zu antworten, ohne den Chat zu öffnen. **Alle entfernen** in **Fertig** fragt zuerst und nimmt die fertigen Karten, die du gelesen hast, von der Tafel; **Rückgängig** und **Entfernt (N)** holen sie zurück, und die Chats bleiben in dsh.

**Kann ich einen persönlichen Assistenten-Chat haben, der mich erinnert und meine anderen Chats verwaltet?** Ja, mit **Assistent** (standardmäßig an): Klicke in der linken Seitenleiste auf **Assistent**. Er legt Erinnerungen mit den geplanten Aufgaben von dsh an, sucht im Web, listet und liest deine Chats und sendet einem Chat eine Nachricht oder startet, stoppt oder archiviert einen Chat erst, nachdem du es genehmigt hast. Speichere dein Profil im Gedächtnis seines Projekts, Thema "profil".

**Kann der Assistent außerhalb meiner Chatliste bleiben und wie ein Bot arbeiten?** Ja. **Assistent getrennt von Chats** nimmt seinen Chat aus der Liste der Seitenleiste und zeigt seinen Zustand in der Zeile **Assistent** (orange, während er auf dich wartet). **Nur Nachrichten im Assistenten** blendet seine Arbeitsschritte aus. **Assistent immer frei** lässt ihn jeden längeren Schritt an einen Subagenten im Hintergrund geben, daher antwortet er sofort. **Chat-Neuigkeiten im Assistenten** (standardmäßig aus, verbraucht Tokens) lässt ihn dir Bescheid sagen, wenn ein anderer Chat fertig ist, fehlschlägt oder auf dich wartet.

**Kann dsh meine Chats und Einstellungen sichern, so wie dsh-backup?** Ja: **Einstellungen → Composer Plus → Sicherung → Jetzt sichern**. Es schreibt dasselbe Archivformat in denselben Ordner (`~/Desktop/dsh-backups`). Daher erscheinen auch die Archive von dsh-backup und lassen sich wiederherstellen, und du kannst dsh-backup entfernen. Schalte **Automatische Sicherung** ein, um nach Zeitplan zu sichern.

**dsh startet nicht mehr. Wie stelle ich eine Sicherung wieder her?** Öffne den Sicherungsordner (`~/Desktop/dsh-backups`) und doppelklicke auf `Composer Plus Rescue.command` (Linux: `composer-plus-rescue.sh`, Windows: `Composer Plus Rescue.cmd`). Wähle `3) Restore a backup`, wähle eine Sicherung aus und tippe `RESTORE`. Das funktioniert ohne dsh.

**Wie ziehe ich dsh auf einen neuen Computer um?** Auf dem alten: **Sicherung** → **Für einen anderen Computer** neben einer Sicherung. Kopiere diesen Ordner auf den neuen Computer, installiere dort dsh, beende es, öffne `Composer Plus Rescue` im kopierten Ordner und stelle wieder her. Gib deine API-Schlüssel neu ein (sie bleiben auf dem alten Computer).

**Ein Chat öffnet sich nach einem Absturz nicht mehr. Kann ich ihn reparieren?** **Einstellungen → Composer Plus → Sitzungsprotokoll-Prüfung → Sitzungsprotokolle prüfen**. Ein beschädigter Chat kommt mit **Aus Sicherungen reparieren** aus der neuesten Sicherung zurück (die Nachrichten nach dieser Sicherung gehen verloren).

**Wie ordne ich eingereihte Nachrichten in dsh neu?** Ziehe den Griff ⠿ an einer eingereihten Nachricht, oder setze den Fokus darauf und drücke `↑` / `↓`.

**Wie korrigiere ich einen Tippfehler in einer eingereihten Nachricht?** Doppelklicke auf die Nachricht in der Warteschlange, ändere den Text und drücke `Enter` (`Esc` bricht ab). Sie behält ihren Platz in der Warteschlange. Dort kannst du auch ihre Bilder und Dateien entfernen oder neue hinzufügen.

**Wie entferne ich alle Ungelesen-Punkte eines Projekts auf einmal?** Seitenleiste → Schaltfläche **…** des Projekts → **Alle als gelesen markieren**.

**Kann ich auf eine einzelne Nachricht in einem langen Chat verlinken?** Ja: Fahre mit der Maus über die Nachricht und klicke auf **🔗**. Sende den Link in einem Chat: Ab dsh 0.2.1 öffnet ein Klick darauf den Chat an dieser Nachricht.

**Ich habe eine Runde aus Versehen zurückgenommen. Bekomme ich sie zurück?** Ja, mit **Wiederholen** über dem Eingabefeld, direkt nach dem Zurücknehmen: Es startet einen neuen Chat ab dem Moment direkt vor dem Zurücknehmen, mit denselben Nachrichten. Mit **Chat und Dateien** holt es auch die Dateien zurück.

**Welcher Chat hat diese Datei geändert?** Rechte Seitenleiste → **Änderungen** → **…** der Datei → **Chats, die diese Datei geändert haben**. Klicke auf eine Zeile, um diesen Chat bei der Anfrage zu öffnen, die die Änderung gemacht hat.

**Kann ich in einem langen Chat suchen?** Ja: Drücke im Chat `Cmd+F` auf einem Mac (`Ctrl+F` unter Windows und Linux). **Im Chat suchen** hebt jeden Treffer hervor und springt mit `Enter` und `Shift+Enter` zwischen ihnen.

**Wie sehe ich nur die Dateien, die ein Chat geändert hat?** Rechte Seitenleiste → **Änderungen** → **Dieser Chat**. Klicke auf **␣**, um Änderungen auszublenden, die nur Leerraum sind.

**Wie verhindere ich, dass der Agent `npm publish` oder `git push --force` ausführt?** **Einstellungen → Composer Plus → Blockierte Befehle**: Gib `npm publish` ein, wähle **blockieren** oder **zuerst fragen** und klicke dann auf **Hinzufügen**. Eine Regel mit **blockieren** lehnt den Befehl ab, und der Agent fragt dich; eine Regel mit **zuerst fragen** zeigt jedes Mal die Genehmigungskarte. „Geschützte Dateien“ deckt die Datei-Tools des Agenten ab, „Blockierte Befehle“ seine Shell-Befehle.

**Kann ich dem Agenten sagen, warum ich einen Tool-Aufruf abgelehnt habe?** Ja, mit **Mit Notiz ablehnen** (standardmäßig an): Klicke auf der Genehmigungskarte auf **Mit Notiz ablehnen…**, schreibe den Grund oder was stattdessen zu tun ist, und klicke auf **Ablehnen**. Der Agent liest die Ablehnung und deine Notiz in derselben Runde.

**Wie gebe ich dem Agenten ein Passwort oder einen Token, ohne es in den Chat zu schreiben?** Mit **Geheime Eingabe** (standardmäßig an): Bitte den Agenten, `request_secret` zu nutzen, oder warte, bis er fragt. Gib den Wert in der Karte in der Zeile des Tools ein und klicke auf **Speichern**. Der Agent bekommt nur den Pfad einer Datei mit dem Wert, und die Datei wird am Ende des Durchgangs gelöscht.

**Wie antworte ich nur auf einen Teil einer langen Antwort?** Markiere diesen Teil und klicke auf **Zitieren** über der Markierung (**In Antwort zitieren**, standardmäßig an). Der Teil kommt als `> …`-Zitat ins Eingabefeld, und du schreibst deine Antwort darunter.

**Wie zeige ich dem Agenten genau die Zeilen einer Datei?** Öffne die Datei in der rechten Seitenleiste (**Dateien im Arbeitsbereich**), markiere die Zeilen und klicke auf **Zitieren** über der Markierung (**Aus Dateivorschau zitieren**, standardmäßig an). Das Eingabefeld bekommt den Pfad und die Zeilennummern (zum Beispiel `src/login.js:2-3`) und die Zeilen als Codeblock; schreibe deine Frage darunter.

**Kann ich etwas fragen, während der Agent arbeitet, ohne ihn anzuhalten?** Schreibe die Frage und klicke im Eingabefeld auf **Im Nebenchat fragen** (**Nebenchat**, standardmäßig an). Eine schreibgeschützte Kopie des Chats beantwortet sie, während der Chat weiterarbeitet. Im Nebenchat legt **Zurückholen** die Antwort in das Eingabefeld des Chats.

**Wie sage ich dem Agenten, was er in seinem Diff ändern soll?** Öffne im **Änderungsbereich** das Diff der Datei, klicke bei einer Zeile auf **+** und schreibe eine Notiz (**Diff-Notizen**, standardmäßig an). Klicke dann auf **In Eingabefeld senden**: Die Notizen kommen mit Datei, Zeilennummern und Zeilen ins Eingabefeld.

**Wie verhindere ich, dass die automatische Prüfung in einem Chat immer wieder nach demselben Tool fragt?** Klicke auf der Genehmigungskarte auf **Für diesen Chat zulassen**. Das gilt nur für genau dieses Tool in diesem Chat, standardmäßig für 1 Stunde. Widerrufe es über den Chip in der Kopfzeile. Ändere die Zeit unter **Einstellungen → Composer Plus → Für diesen Chat zulassen**.

**Kann dsh den Chat, der mir eine Frage stellt, von selbst öffnen?** Ja, mit **Wartenden Chat bei Inaktivität öffnen** (standardmäßig an): Wartet ein Chat auf eine Antwort, eine Genehmigung oder eine Planprüfung und du benutzt dsh 30 Sekunden lang nicht, öffnet dsh ihn. Sie sendet „Option N: …“ als Ihre Nachricht. Drücken Sie auf einer Fragekarte des Agenten 1–9.

Scanne den QR-Code (mit der iPhone-Kamera oder mit **Scan code** in Tether), tippe auf **Connect** und klicke auf **Approve**. Unterwegs nutzt du Tailscale auf beiden Geräten.

**Wie arbeite ich gleichzeitig an mehreren Funktionen eines Projekts, jede auf ihrem eigenen Branch?** Mit **Ein Branch pro Chat**: Im Bildschirm „Neuer Chat“ zeigt die Branch-Schaltfläche standardmäßig **Neuer Branch**: Sende die erste Nachricht. Jeder Chat bekommt einen eigenen Branch und einen eigenen Worktree-Ordner, mit deiner `.env` und deinem `node_modules`, wenn `.worktreeinclude` sie auflistet. Die Kopfzeile des Chats zeigt, auf welchem Branch du bist.

**Kann die Seitenleiste jeden Branch eines Projekts zeigen und meinen Chat verschieben, wenn der Agent einen Branch erstellt?** Ja, mit **Branches im Arbeitsbereichsbaum** (standardmäßig aus): Schalte es in Einstellungen → Composer Plus ein und wähle in dsh **Ansichtsoptionen** → **Arbeitsbereichsbaum**. Jeder Branch mit einem Worktree in `<project>/.worktrees/` erscheint in seinem Projekt. Wenn du den Agenten im Projektordner bittest, einen Branch zu erstellen und dort zu arbeiten, und der Ordner keine nicht committeten Änderungen hat, zieht der Chat von selbst in den Branch um. Lösche den Ordner des Branches, dann verschwindet er aus der Liste; seine Chats kommen nach **Ohne Gruppe**.

**Kann ich ein Foto von meinem iPhone senden?** Ja. Tippe in einem Tether-Chat auf **+** neben dem Nachrichtenfeld → Camera, Photos (bis zu 4) oder Paste image. Die Fotos kommen als Anhänge deiner Nachricht in den Chat auf dem Mac, daher sieht das Modell sie.

**Kann dsh den nächsten Befehl ausführen, ohne das Modell erneut zu fragen?** Ja, mit **Geplante Schritte** (standardmäßig aus): Schalte die Funktion unter Einstellungen → Composer Plus ein. Das Modell kann dann seine nächsten Befehle mit einer Bedingung planen, etwa „führe die Tests aus, wenn der Build gelingt“, und Composer Plus führt einen Schritt ohne neuen Modellaufruf aus, wenn das Ergebnis die Bedingung erfüllt. Freigaben und Sandbox bleiben, wie sie sind.

**Woher kommt der türkische Skill, und kann ich ihn entfernen?** Aus [yucezerey/turkish-anti-ai-skill](https://github.com/yucezerey/turkish-anti-ai-skill) auf GitHub (MIT). Composer Plus installiert ihn nur, solange **App-Sprache** Türkçe ist, behält nur seine Markdown-Dateien und führt keines seiner Skripte aus. Zum Entfernen schalte **Türkisches Skill-Paket** in Einstellungen → Composer Plus aus: Der Skill und die geladene Kopie sind sofort weg.

**Wie melde ich in Composer Plus einen Fehler oder wünsche mir eine Funktion?** Einstellungen → Composer Plus → **Issue melden…** (oder das Menü **…** eines Chats → **Issue zu Composer Plus melden…**). Wähle einen Typ, beschreibe es in deiner eigenen Sprache und klicke auf **Entwurf schreiben**. Prüfe den englischen Entwurf und klicke dann auf **Issue öffnen**.

**Wie kann der Agent eine unordentliche Codebasis aufräumen?** Tippe `/untangle-codebase` in einen Chat (**Codebasis entwirren**, standardmäßig an), auf Wunsch mit einem Bereich, zum Beispiel `/untangle-codebase src/api`. Der Agent listet zuerst Kopien, versteckte Kopplungen, unnötige Wrapper, toten Code und Sonderfälle auf, behebt sie dann als Ziel und prüft mit Subagenten erneut. Starte ihn in einem Chat von **Ein Branch pro Chat**, damit die Arbeit in einem eigenen Branch bleibt.

**Funktioniert es mit der Desktop-App?** Ja: Einstellungen → Plugins → **Plugin hinzufügen** → `dsh-composer-plus`. Getestet mit dsh 0.2.0-rc.2 (Desktop und Web) und 0.2.1-rc.2 (Web).

**Regel für neue Funktionen:** Jede Funktionszeile unter Einstellungen → Composer Plus zeigt einen Screenshot. Füge die ID der Funktion zu `SHOT_OF` in `client.js` und zu `SHOTS` in `index.js` hinzu, und liefere `assets/features/<id>.webp` mit aus (aufgenommen im Wegwerf-Demo-dsh, englische Oberfläche, etwa 60 kB oder weniger). Trage die Funktion mit demselben Bild in `docs/features.json` ein und führe `npm run build:readme` aus: Es schreibt die Funktionstabelle von `README.md` und jeder übersetzten `README.<id>.md` sowie die Liste in `llms.txt`. `test/shots.test.mjs` schlägt fehl, wenn eine Funktion keinen Screenshot hat, und `test/browser-settings-shots.mjs` prüft die echte Einstellungsseite. Die vollständige Checkliste für jede Änderung steht in [AGENTS.md](AGENTS.md).

Die Tests führen das echte `client.js` gegen ein Fake-React/DOM aus und das echte `index.js` (Host-Hälfte) gegen ein temporäres git-Repository. Die Tests des Tether-Gateways (`test/tether-gateway.test.mjs`) nutzen einen Mock-dsh-Host und ein echtes TLS-Gateway. Die iPhone-App liegt in `tether/ios` (siehe [tether/README.md](tether/README.md) und [tether/AGENTS.md](tether/AGENTS.md)). [docs/ROUTES.md](docs/ROUTES.md) listet jede Host-Route, ihre Anfrage und ob Tether sie aufrufen kann. `node test/browser-history.mjs '<dsh web URL with ?token=…>'` prüft den Eingabeverlauf in einem echten Browser gegen ein Wegwerf-`dsh web` mit eigenem `DSH_HOME`.

Sprachpakete sind reine Daten-JSON-Dateien in `locales/<id>.json`. `npm run build:locales` bettet sie in den einzigen Client-Einstiegspunkt ein (kein Übersetzungsdienst, kein Download zur Laufzeit). `npm test` prüft jedes Paket auf vollständige Schlüsselabdeckung, identische Platzhalter und Zeilenumbrüche sowie auf das Verhalten von Systemsprache und manueller Auswahl. Für isolierte Prüfungen in der echten App mit einem lokal installierten Playwright:

```sh
PLAYWRIGHT=/path/to/playwright node test/browser-language.mjs /path/to/dsh/lib/bin.js
```
