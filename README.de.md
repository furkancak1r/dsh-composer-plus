Komfortfunktionen im Stil von Codex für die Desktop- und Weboberfläche von [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (dsh): ein Änderungsbereich, Funktionsideen als Wischkarten, Suche im Nachrichtentext über die Seitenleiste, Zurücknehmen von Runden samt Wiederherstellung von Dateien, Löschen von Chats in den Papierkorb, der Projektname unter dem Eingabefeld, der Projektstatus in der Seitenleiste, ein Eingabeverlauf, ein Tastenkürzel für den Planmodus, Fortsetzen mit einem Klick, Fortsetzen laufender Chats nach einem Neustart, Drag-and-drop in der Warteschlange, Sitzungslinks, Export von Chats als Markdown, Freigaben der automatischen Prüfung pro Chat, Hintergrundbenachrichtigungen, Zugriff vom iPhone mit der Tether-App und automatische Updates.

**In einer Zeile:** ein einziges Plugin für DeepSeek Harness (npm `dsh-composer-plus`, unter Einstellungen → Plugins als **Composer Plus** angezeigt). Es bringt einen git-Änderungsbereich, Funktionsideen als Karten im Tinder-Stil, eine Seitenleisten-Suche, die auch Wörter in Nachrichten findet, ↶ Runde zurücknehmen (nur Chat oder Chat und Dateien), Chat löschen, den Projektnamen unter dem Eingabefeld, ↑/↓ Eingabeverlauf, einen Shift+Tab-Umschalter für `/plan`, ▶ Fortsetzen mit einem Klick, Nach Neustart fortsetzen, Neuordnen der Warteschlange per Drag-and-drop, Sitzungslink kopieren, Als Markdown exportieren, „Für diesen Chat zulassen“ bei der automatischen Prüfung, Hintergrundbenachrichtigungen, Zugriff vom iPhone (Mobile Verbindung, Tether-App), 11 zusätzliche Oberflächensprachen und automatische Updates.

<p align="center"><img src="docs/images/hero.webp" width="820" alt="DeepSeek Harness mit Composer Plus: Das laufende Projekt zeigt einen Spinner in der Seitenleiste, und der Änderungsbereich zeigt einen git-Diff"></p>

Inoffizielles Community-Plugin. Die einzigen Netzwerkaufrufe sind die Update-Prüfung (GitHub-Releases und die npm-Registry). Schalte **Automatische Updates** aus, um sie beim Start zu stoppen. **Funktionsideen** ruft das eigene Modell deines Chats nur auf, wenn du auf **Funktionen vorschlagen** klickst. **Vorhersage der nächsten Nachricht** (standardmäßig an) ruft nach jeder beendeten Runde einmal das in den Einstellungen gewählte Modell auf (den dsh-Standard, wenn du kein anderes wählst), ohne Klick. Schalte sie unter **Einstellungen → Composer Plus** aus, um diese Aufrufe zu stoppen. **Beim Tippen vervollständigen** (standardmäßig aus) ruft bei jeder Pause beim Tippen das dafür gewählte Modell auf (standardmäßig das der Vorhersage), nachdem du die Funktion eingeschaltet hast. **Prompt verbessern** ruft ein Modell nur auf, wenn du auf seinen Zauberstab klickst. **Zielprüfung** (standardmäßig an) ruft jedes Mal einmal ein Modell auf, wenn der Agent ein `/goal` in einem automatischen Durchlauf als abgeschlossen markiert. **Mobile Verbindung** (standardmäßig aus) nimmt iPhone-Verbindungen aus deinem lokalen Netz oder Tailnet erst an, wenn du sie einschaltest.

## Installation

**Desktop-App:** Einstellungen → Plugins → **Plugin hinzufügen** → `dsh-composer-plus` eingeben → **Jetzt aktivieren**.
Du kannst statt des npm-Namens auch `https://github.com/furkancak1r/dsh-composer-plus` einfügen.

**Web-/CLI-Profil:**

```sh
dsh plugin --profile web add dsh-composer-plus
```

Starte dsh danach neu. (Die CLI kann nicht in das Desktop-Profil installieren; dieses Profil verwaltet die App.)

> Das pnpm von dsh überspringt Versionen, die jünger als 24 Stunden sind. Gib direkt nach einem Release die Version mit an: `dsh-composer-plus@1.15.0`.

## Einstellungen

Jede Funktion lässt sich einzeln ein- oder ausschalten: dsh **Einstellungen → Composer Plus**. Jede Zeile hat einen kleinen Screenshot: Fahre mit der Maus darüber für eine größere Vorschau, oder klicke darauf, um ihn in voller Größe zu öffnen (`Esc` schließt ihn). Das Feld **Funktionen suchen** oben filtert die Seite nach Name oder Beschreibung (in jeder Sprache, ohne Unterschied bei Groß- und Kleinschreibung oder Akzenten); `Esc` leert es. Jede Zeile hat einen Schalter und eine kurze Beschreibung. Das kleine **?** nach dem Namen einer Zeile öffnet den Teil dieser README, der die Funktion beschreibt, in der README der Oberflächensprache von dsh. Änderungen gelten sofort, ohne Neustart, und bleiben auf diesem Gerät gespeichert. Alles ist standardmäßig an, außer **Mobile Verbindung**, **Nach Neustart fortsetzen** und **Beim Tippen vervollständigen**. Der Host von dsh speichert die Schalter dieser drei Funktionen sowie von **Inhaltssuche**, **Runde zurücknehmen**, **Vorhersage der nächsten Nachricht** und **Zielprüfung**. Deshalb gelten sie für jedes Fenster und bleiben nach einem Neustart erhalten. Der Host speichert auch die Wahl unter **Modell** für **Vorhersage der nächsten Nachricht**, die für **Beim Tippen vervollständigen** (standardmäßig **Wie Vorhersage der nächsten Nachricht**), die für **Prompt verbessern**, die für **Zielprüfung** (beide standardmäßig **Wie das Modell des Chats**) und das **Zeitlimit** von **Für diesen Chat zulassen** (standardmäßig 1 Stunde). **Inhaltssuche** ändert sich erst nach einem Neustart von dsh (dsh liest den Schalter beim Start). Bis dahin steht in ihrer Zeile **Starte dsh neu, damit diese Änderung gilt.**

Die ganze App wechselt sofort. Die Auswahl ist die eigene gespeicherte `locale.preference` von dsh (dieselbe wie unter Allgemein → Sprache). Deshalb bleibt sie nach Neustarts erhalten. **Systemsprache** löscht diese Auswahl: Die Desktop-App folgt der Sprache des Betriebssystems, die Weboberfläche der Sprache des Browsers. Eine nicht unterstützte Sprache fällt auf Englisch zurück. Die Installation des Plugins überschreibt nie eine Sprache, die du schon gewählt hast.

Jedes Paket hat 3.280 Texte: jeden Oberflächentext von dsh `0.2.0-rc.2` und `0.2.1-rc.2` (Chats, Seitenleiste, Einstellungen, Genehmigungen, Automatisierungsaufgaben, Dateivorschauen, Plugin-Verwaltung, Plugin-Marktplatz), die eigenen Bedienelemente des Plugins und das beliebte Plugin [dsh-rewind](https://github.com/SiriLee/dsh-rewind). Nicht übersetzt werden: deine Nachrichten, die Ausgabe des Modells, Code, Namen von Slash-Befehlen (`/plan`, `/compact`), Bezeichnungen der Anbieter wie die Reasoning-Stufe `High`, Texte anderer Plugins sowie die nativen Menüs und Update-Dialoge der Desktop-App (dsh liefert diese nur auf Englisch und Chinesisch aus). Texte, die eine neuere dsh-Version hinzufügt, erscheinen auf Englisch, bis die Pakete aktualisiert sind. Wenn ein anderes Plugin eine Sprache bereits bereitstellt, behält dieses Plugin die Sprache.

## Datenschutz und Sicherheit

- **Fortsetzen:** Der authentifizierte lokale Endpunkt setzt nur die letzte unterbrochene Runde fort, lehnt veraltete oder doppelte Anfragen ab und behält die vorhandenen Genehmigungs-Hooks bei. Er sendet keine neue Benutzernachricht.
- **Nach Neustart fortsetzen:** aus, bis du es einschaltest. Die Host-Hälfte speichert nur Chat-IDs und Startzeiten in `$DSH_HOME/storages/dsh-composer-plus/resume.json` (Rechte nur für den Besitzer), und nichts verlässt deinen Rechner. Sie setzt einen Chat nur fort, wenn das eigene Protokoll von dsh sagt, dass dsh (nicht du) seine letzte Runde gestoppt hat. Genehmigungen und die automatische Prüfung gelten für die fortgesetzte Runde wie gewohnt.

- **Änderungsbereich:** git läuft nur lesend auf deinem Rechner, im eigenen Ordner des Chats, über den authentifizierten `/api`-Kanal von dsh. Es führt nie Commits, Staging oder Fetches aus und zeigt nur Pfade, die git selbst aufgelistet hat. Der Baum listet bis zu 1000 lokale und entfernte Branches und zeigt die neuesten 300 Commits eines Branches: seine First-Parent-Linie, ein Merge-Commit steht also für die Commits, die er gebracht hat. Er wechselt nie den Branch (Checkout). **Dieser Chat** liest das eigene Protokoll des Chats, um die Dateien zu finden, die seine Datei-Tools geschrieben haben. Er vergleicht sie mit dem Snapshot von Runde zurücknehmen für diesen Chat, in einem temporären Ordner, der sofort gelöscht wird. Er schreibt nichts in dein Repository und nichts in den Snapshot-Speicher.
- **Funktionsideen:** Nichts läuft, bis du auf **Funktionen vorschlagen** klickst. Dann liest die Host-Hälfte nur den eigenen Ordner des Chats (der Browser sendet nie einen Pfad): die Namen der Einträge auf oberster Ebene, die ersten 6 kB von README, AGENTS.md und Manifest (`package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, …), eine Gliederung des restlichen README (Überschriften, Tabellenzeilen, Listenpunkte; höchstens 6 kB) und die Titel der neuesten Commits (`git log --format=%s`, höchstens 6 kB), insgesamt höchstens 28 kB. Sie überspringt `.env*`, Schlüsseldateien und Ordner wie `node_modules`. Sie liest nur reguläre Dateien, die im Ordner bleiben: Ein Symlink, der aus dem Ordner hinauszeigt, ein FIFO oder ein Gerät wird übersprungen. Diese Zusammenfassung geht als eine einzige Anfrage an das Modell, das der Chat nutzt, über die eigenen Anbietereinstellungen von dsh. Sie wird keinem Chat hinzugefügt. Im Projekt wird nichts geschrieben. Eine nach rechts gewischte Idee startet einen neuen Chat im Planmodus, also gelten Genehmigungen und Planprüfung wie gewohnt. **Sofort umsetzen** startet den Chat ohne Planmodus: Das Modell kann sofort Dateien ändern, mit den üblichen Genehmigungen des Chats und der automatischen Prüfung. Für später gemerkte Ideen (Titel, Zusammenfassung, Begründung, Aufwand) werden mit dem Ordnerpfad des Projekts in `storages/dsh-composer-plus/later.json` im dsh-Home gespeichert (Datei nur für den Besitzer). Ins Projekt kommt nichts. Der Verlauf der vorgeschlagenen Ideen (Titel, Zusammenfassung, Begründung, Aufwand, Datum, ob gestartet) wird auf dieselbe Weise in `storages/dsh-composer-plus/idea-history.json` gespeichert, höchstens 200 pro Projekt (die ältesten fallen zuerst weg). Seine Titel gehen beim nächsten **Funktionen vorschlagen** in diesem Projekt an das Modell.
- **Inhaltssuche:** Kein neuer Code durchsucht deine Chats. Das Plugin schaltet nur den eigenen Nachrichtenindex von dsh ein (SQLite FTS5, `dsh-session-query-sqlite`) und gibt ihm eine Datei: `$DSH_HOME/cache/composer-plus/session-search.db` (Datei und Ordner nur für den Besitzer). Die Datei enthält den Text deiner Benutzer- und Assistentennachrichten. Sie ist also so privat wie die Chatprotokolle in `$DSH_HOME/sessions`. Nichts verlässt deinen Rechner. Die Datei ist eine Kopie, die dsh neu erstellen kann: Du kannst sie löschen, während dsh geschlossen ist. Der Schalter liegt in `$DSH_HOME/storages/dsh-composer-plus/content-search.json`.
- **Runde zurücknehmen:** Vor jeder deiner Nachrichten macht der Host einen git-Snapshot des Chat-Ordners in einem eigenen Speicher: `$DSH_HOME/cache/composer-plus/rollback/<chat>.git` (Ordner nur für den Besitzer). Er enthält Kopien der Dateien in diesem Ordner, die git sieht (keine ignorierten Dateien), und ist also so privat wie das Projekt. Er liest die Objekte deines Repositorys (keine Kopie dessen, was git schon hat) und schreibt nie in Index, `HEAD`, Branches, Tags, Stash oder Config deines Repositorys. Die einzige Änderung, die git dort macht, ist ein neuerer Zeitstempel an Objektdateien, die es wiederverwendet (das verzögert ihre Bereinigung durch `git gc`). Ein Zurücknehmen mit Dateien schreibt nur reguläre Dateien im Ordner des Chats. Es überspringt Symlinks, Pipes und alles außerhalb des Ordners. Nichts verlässt deinen Rechner. Du kannst den Speicher löschen, während dsh geschlossen ist (das Zurücknehmen funktioniert dann nur für den Chat, bis neue Nachrichten kommen). **Chat löschen** löscht auch den Speicher eines Chats. Der Schalter liegt in `$DSH_HOME/storages/dsh-composer-plus/rollback.json`. Ein Zurücknehmen mit Dateien behält auch die Dateien, wie sie direkt davor waren (`refs/r/…` im selben Speicher), für **Wiederholen**. Die wiederholten Rücknahmen stehen in `$DSH_HOME/storages/dsh-composer-plus/redone.json` (nur für den Besitzer).
- **GitHub-Issue öffnen** (Funktionsideen → Liste **Später**): läuft nur, wenn du darauf klickst. Die Host-Hälfte führt dein eigenes GitHub CLI (`gh issue create`) im Ordner des Chats aus, mit dem gespeicherten Titel und der Zusammenfassung der Idee (und warum sie wichtig ist). `gh` nutzt seine eigene Anmeldung und das GitHub-Remote des Ordners. Daher landet das Issue mit deinem Konto in diesem Repository, und GitHub zeigt es allen, die dieses Repository sehen können. dsh entfernt Variablen, deren Name wie ein Token aussieht, aus den Befehlen, die es startet. Wenn du `gh` ein Token über `GH_TOKEN` oder `GITHUB_TOKEN` gegeben hast, gibt das Plugin nur diese an `gh` weiter. Der Link zum Issue wird mit der Idee in `later.json` gespeichert.
- **Chats, die diese Datei geändert haben** (Änderungen, das Menü „…“ einer Datei): Die Host-Hälfte liest die Protokolle der Chats, deren Ordner im selben Repository liegt, so wie dsh sie speichert, und liefert den Titel jedes Chats, die Zeit und die erste Zeile der Anfrage. Die Datei selbst öffnet sie nie.
- **Git-Branch in Chatzeilen:** Die Host-Hälfte führt `git branch --show-current` (nur lesend) im Ordner des Chats aus, wenn eine Runde beginnt und wenn sie endet, und speichert nur die Chat-ID, den Branch-Namen und die Zeit in `$DSH_HOME/storages/dsh-composer-plus/session-branches.json` (Datei nur für den Besitzer, die neuesten 2000 Chats). Der Schalter liegt daneben in `branches.json`.
- **Im Chat suchen** läuft nur auf der Seite: Die Funktion liest den Text, den die Seite zeigt, und sendet nichts.
- **Chat als Markdown exportieren:** Die Host-Hälfte liest nur das eigene Protokoll des Chats (dieselben Nachrichten, die dsh zeigt) und gibt sie an die Seite. Sie liest keine Projektdatei und sendet nichts über das Netzwerk. Das Markdown geht nur in deine Zwischenablage oder in die Datei, die du speicherst.
- **Chat löschen:** verschiebt die eigenen Protokollordner des Chats (`$DSH_HOME/sessions/<project>/<chat>`) in den Papierkorb. Den Projektordner fasst es nicht an.
- **Für diesen Chat zulassen:** Freigaben werden mit dem Zeitpunkt, zu dem sie erteilt wurden, in `$DSH_HOME/storages/dsh-composer-plus/chat-grants.json` gespeichert (Rechte nur für den Besitzer). Eine Freigabe gilt für genau ein Tool in einem Chat, bis das Zeitlimit abläuft (standardmäßig 1 Stunde). Wenn dieses Tool schreiben kann, deckt die Freigabe auch jeden Schreibvorgang ab. Widerrufe sie über den Chip in der Kopfzeile.
- Die automatische Prüfung läuft weiterhin bei jedem Aufruf. Fehlgeschlagene Prüfungen werden nie automatisch erlaubt.
- **Mobile Verbindung:** aus, bis du sie einschaltest. Solange sie an ist, betreibt die Host-Hälfte das Tether-Gateway: HTTPS auf Port 19390, das nur dein WLAN-Subnetz und dein Tailnet (100.64.0.0/10) annimmt, und eine Kopplungsseite auf `127.0.0.1:19391` (nur dieser Mac). Ein Telefon braucht einen Einmalcode aus dem QR-Code (5 Minuten gültig) und deine Bestätigung mit **Approve** auf dem Mac. Das Telefon pinnt das Zertifikat des Gateways. Der Mac speichert von jedem Telefon-Token nur einen Hash (30 Tage, wird bei Nutzung verlängert). **Remove** schließt die Verbindungen dieses Telefons sofort. Telefone können nur dsh-Methoden aus einer Positivliste aufrufen (Chats, Prompts, Anhänge, Slash-Befehle, Genehmigungen, Fragen, Modelle, Agenten, Ziele), aber keine Einstellungen, Zugangsdaten, den Dateibrowser oder das Terminal. „Tailscale only“ lehnt jede Verbindung aus dem lokalen Netzwerk ab, auch bereits offene. Das Zugriffsprotokoll speichert die neuesten 200 Verbindungsversuche (Zeit, IP-Adresse, Gerätename, zugelassen oder abgelehnt und warum) in `access.json`. Es enthält nie ein Token oder einen Kopplungscode. Daten: `$DSH_HOME/storages/dsh-composer-plus/mobile/` (Dateien nur für den Besitzer). Details: [tether/README.md](tether/README.md).
- **Updates:** Die Host-Hälfte fragt `api.github.com` nach dem neuesten Release und `registry.npmjs.org` nach genau dieser Version. Über dich oder deine Chats wird nichts gesendet. Die Installation nutzt die Plugin-Verwaltung von dsh (`pnpm add dsh-composer-plus@<version>`; wenn dsh 0.2.1 das für ein installiertes Plugin ablehnt, `pnpm add https://registry.npmjs.org/dsh-composer-plus/-/dsh-composer-plus-<version>.tgz`, und das Profil führt danach diese URL als Quelle des Plugins). Deshalb gelten die eigenen Prüfungen von dsh für Registry, Skripte und Versionskompatibilität. Pre-Release-Tags und ältere Versionen werden nie installiert.
- **Vorhersage der nächsten Nachricht:** standardmäßig an. Schalte sie unter **Einstellungen → Composer Plus** aus, um diese Modellaufrufe zu stoppen. Nach jeder beendeten Runde sendet die Host-Hälfte deine eigenen Nachrichten im Chat und die Textantworten des Agenten (keine Werkzeugausgabe, kein verborgener Kontext, kein Reasoning), höchstens etwa 6.000 Zeichen (den neuesten Teil), an das gewählte Modell (den dsh-Standard, wenn du kein anderes wählst). Das geht als eine einzige Anfrage über die eigenen Anbietereinstellungen von dsh. Im Chat wird nichts gespeichert: Die Vermutung kommt nicht in den Chatverlauf. Der Schalter und die Modellwahl liegen in `$DSH_HOME/storages/dsh-composer-plus/predict.json` (Datei nur für den Besitzer).
- **Beim Tippen vervollständigen:** aus, bis du die Funktion einschaltest. Solange sie an ist, sendet die Host-Hälfte bei jeder Pause beim Tippen den bisher getippten Text sowie deine eigenen Nachrichten im Chat und die Textantworten des Agenten (keine Werkzeugausgabe, kein verborgener Kontext, kein Reasoning), höchstens etwa 3.000 Zeichen aus dem Chat, an das unter **Beim Tippen vervollständigen** gewählte Modell (standardmäßig das Modell von **Vorhersage der nächsten Nachricht**). Eine neuere Pause stoppt die ältere Anfrage. Im Chat wird nichts gespeichert. Der Schalter liegt in `$DSH_HOME/storages/dsh-composer-plus/complete.json` (Datei nur für den Besitzer).
- **Prompt verbessern:** Nichts läuft, bis du auf den Zauberstab klickst. Dann sendet die Host-Hälfte deinen Entwurf, deine eigenen Nachrichten im Chat und die Textantworten des Agenten (keine Werkzeugausgabe, kein verborgener Kontext, kein Reasoning, keine zurückgenommenen Nachrichten; höchstens etwa 6.000 Zeichen, den neuesten Teil), dieselbe Projektzusammenfassung wie **Funktionsideen** (mit denselben Dateiregeln: keine `.env*`- oder Schlüsseldateien, kein Symlink aus dem Ordner hinaus, kein FIFO), die Pfade, die `git status` als geändert listet, und bis zu 30 verfolgte oder unverfolgte (nicht ignorierte) Pfade, deren Namen Wörter mit deinem Entwurf teilen. Das geht als eine einzige Anfrage an das unter **Prompt verbessern** gewählte Modell (standardmäßig das eigene Modell des Chats). Andere Dateiinhalte als diese Zusammenfassung werden nicht gesendet. In den Chat und ins Projekt wird nichts geschrieben: Die Antwort ersetzt nur deinen Entwurf im Eingabefeld, und du entscheidest, ob du ihn sendest. Die Modellwahl liegt in `$DSH_HOME/storages/dsh-composer-plus/improve.json` (Datei nur für den Besitzer).
- **Zielprüfung:** Sie läuft nur, wenn der Agent ein `/goal` in einem automatischen Durchlauf als abgeschlossen markiert (oder wenn du auf **Jetzt ausführen** klickst). Die Host-Hälfte führt den Testbefehl im Ordner des Chats im Sandbox-Modus des Chats aus (wie das eigene `bash`-Werkzeug von dsh: dieselbe Richtlinie für den Dateizugriff; kann diese Sandbox nicht starten, läuft der Test nicht und die Prüfung schlägt fehl). Um den Befehl zu finden, liest sie nur `package.json`, `Makefile`, `Cargo.toml`, `go.mod`, `pyproject.toml` und `pytest.ini`, als reguläre Dateien im Ordner (kein Symlink aus dem Ordner hinaus, kein FIFO). Dann sendet sie das Ziel, den Chat seit dem Start des Ziels (deine Nachrichten, die Antworten des Agenten, Werkzeugaufrufe gekürzt auf 1.000 Zeichen und die letzten 2.000 Zeichen jedes Werkzeugergebnisses; kein Reasoning, keine zurückgenommenen Schritte; höchstens etwa 60.000 Zeichen, den neuesten Teil), `git status --short` und das Ende der Testausgabe als eine einzige Anfrage ohne Werkzeuge an das unter **Zielprüfung** gewählte Modell (standardmäßig das eigene Modell des Chats). Werkzeugausgaben können enthalten, was der Agent gelesen hat. Daher kann diese Anfrage Teile deiner Dateien enthalten, so wie der Chat selbst. In den Chat und ins Projekt wird nichts geschrieben. Dein Testbefehl, die Limits, das letzte Ergebnis (mit dem Ende seiner Ausgabe) und die Modellwahl liegen in `$DSH_HOME/storages/dsh-composer-plus/goal-check.json` (Datei nur für den Besitzer, die neuesten 500 Chats).

## Fehlerbehebung

- **Keine Benachrichtigungen unter macOS:** Systemeinstellungen → Mitteilungen → DeepSeek Harness → erlauben. Wähle Hinweise, damit die Benachrichtigungen auf dem Bildschirm bleiben.
- **▶, Griffe in der Warteschlange, Projektstatus, die Option für aktuelle Projekte, Alle Projekte einklappen, Pfad kopieren, das Suchfeld für Projekte, die Vorhersage der nächsten Nachricht, die Vervollständigung beim Tippen, Für diesen Chat zulassen oder der Rechtsklick fehlen nach einem dsh-Update:** Diese Elemente hängen sich an das aktuelle HTML von dsh, weil dsh noch keinen Platz für sie hat. Wenn dsh dieses Markup ändert, blenden sie sich selbst aus. Sonst geht nichts kaputt. Bitte eröffne ein [Issue](https://github.com/furkancak1r/dsh-composer-plus/issues).
- **„Update fehlgeschlagen“ oder „nicht über npm installiert“:** Eine Kopie, die aus einem lokalen Ordner verlinkt oder umbenannt wurde, kann sich nicht selbst aktualisieren. Installiere `dsh-composer-plus` über Einstellungen → Plugins neu. Sonst zeigt die Meldung die erste Zeile des pnpm-Fehlers; **Nach Updates suchen** versucht es erneut.
- **Mobile Verbindung meldet, dass das Gateway nicht läuft:** „no IPv4 address on en0“ heißt, dass dieser Mac keine WLAN- oder Ethernet-Adresse hat. „EADDRINUSE“ heißt, dass ein anderes dsh (oder eine andere App) Port 19390 oder 19391 nutzt. Nur ein dsh kann Mobile Verbindung gleichzeitig ausführen.
- **Mobile Verbindung, Nach Neustart fortsetzen oder Inhaltssuche meldet „Starte dsh neu“:** Das Plugin wurde aktualisiert, während dsh lief (oder du hast bei der Inhaltssuche den Schalter geändert). Der neue Zustand lädt nach einem Neustart.
- **Die Suche findet nur Titel:** Die Inhaltssuche ist aus, dsh wurde seit dem Einschalten oder seit der Installation des Plugins nicht neu gestartet, oder das Wort steht nur in einer Tool-Ausgabe (siehe Grenzen).
- **Keine ↶-Schaltfläche an meinen Nachrichten:** Runde zurücknehmen ist aus, der Chat ist ein Subagent-Chat, oder dsh-rewind-plugin ist installiert (nutze dessen ↶-Schaltfläche). Starte dsh nach einem Update neu.
- **Chat und Dateien ist ausgegraut:** Das Projekt ist kein git-Repository, es gibt keinen Snapshot von vor dieser Nachricht (die Nachricht ist älter als das Plugin, oder einer der 50 neuesten Snapshots hat ihn ersetzt), oder keine Datei hat sich geändert.
- **Löschen meldet, dass ein anderes dsh diesen Chat geöffnet hat:** Ein zweites dsh mit demselben dsh-Home hält die Sperre des Chats. Schließe dieses Fenster oder dieses dsh und lösche dann erneut. Der Chat bleibt in der Zwischenzeit archiviert.
- **Mein iPhone verbindet sich nicht, seit ich „Tailscale only“ eingeschaltet habe:** Tailscale muss auf dem Mac und auf dem iPhone eingeschaltet sein. Das Panel Mobile Verbindung warnt, wenn es auf dem Mac aus ist. Das Zugriffsprotokoll zeigt jeden abgelehnten Versuch mit seinem Grund.
- **Ein Chat wurde nach einem Neustart nicht fortgesetzt:** Nach Neustart fortsetzen war aus, als dsh beendet wurde, du hast die Runde selbst gestoppt, die Runde war beendet (fertig oder fehlgeschlagen), der Chat war archiviert, oder mehr als 20 Chats liefen (die neuesten 20 werden fortgesetzt).
- **Die Warteschlange ist nach einem Neustart leer:** dsh selbst leert die Warteschlange beim Beenden. Nach Neustart fortsetzen stellt sie nur in einem Chat wieder her, den es fortsetzt; in anderen Chats sende die Nachrichten erneut. Eine Nachricht, die du kurz vor dem Beenden entfernt hast, kann zurückkommen: Entferne sie erneut.
- **GitHub-Issue öffnen meldet „gh could not open the issue“:** Die Meldung ist die erste Zeile von `gh` selbst. Führe `gh auth status` in einem Terminal aus und melde dich mit `gh auth login` an. Der Ordner des Chats muss ein GitHub-Remote haben (`git remote -v`). „not installed or not on the PATH of dsh“ bedeutet, dass dsh `gh` nicht gefunden hat: Installiere es oder starte dsh aus einem Terminal, in dem `gh` funktioniert.
- **Kein Branch-Etikett an einer Chatzeile:** Der Chat hatte seit der Installation dieser Version keine Runde, sein Ordner ist kein git-Repository, oder **Git-Branch in Chatzeilen** ist aus. Starte dsh nach einem Update neu (die Host-Hälfte zeichnet den Branch auf).
- **Zielprüfung meldet, dass der Test mit Code 127 oder „not found“ beendet wurde:** Ein dsh, das aus dem Finder oder dem Dock gestartet wurde, kann einen kürzeren PATH als dein Terminal haben und findet daher `npm`, `pnpm` oder `cargo` nicht. Starte dsh aus einem Terminal, oder lege unter **Zielprüfung** → **Bearbeiten** deinen eigenen Testbefehl mit dem vollständigen Pfad fest. **Jetzt ausführen** zeigt das Ergebnis sofort.
- **Das Ziel schließt sich nicht und der Agent arbeitet weiter:** **Zielprüfung** hat einen fehlschlagenden Test oder fehlende Arbeit gefunden. Die Zeile unter dem Ziel zeigt den Grund (fahre mit der Maus über das Ergebnis, um die Details zu sehen). Behebe die Ursache oder den Testbefehl, oder schließe das Ziel selbst mit `/goal` oder der Zielleiste ab (das wird nicht geprüft).
- **Die Installation schlägt direkt nach einem Release fehl:** Gib die Version mit an (`dsh-composer-plus@1.15.0`), siehe den Hinweis zur Installation oben.

## Grenzen

- Fortsetzen ohne Nachricht beruht auf dem Lebenszyklus `agent/pre-step` → `agent/request` von dsh. Prüfe die Kompatibilität erneut, wenn du dsh aktualisierst.
- **Funktionsideen** behält die Karten für jeden Chat im Speicher, bis dsh oder die Seite neu lädt. Danach fragt **Funktionen vorschlagen** das Modell erneut. Die Karten kommen in der Oberflächensprache, die dsh beim Klicken hat. Nach einem Sprachwechsel behalten Karten, die schon auf dem Stapel liegen, ihre Sprache, und **Weitere Ideen** nutzt die neue Sprache. Das Modell sieht nur die kurze Projektzusammenfassung, nicht den Code. Eine Idee kann also etwas wiederholen, das das Projekt schon hat: Überspringe sie. Der neue Chat läuft nur im Planmodus, wenn das Profil den Befehl `/plan` von dsh hat. Sonst geht die Idee als normale erste Nachricht hinaus. Die Liste **Später** gehört zum Ordnerpfad des Chats: Derselbe Ordner hat über einen Symlink geöffnet eine eigene Liste. Sie hält höchstens 50 Ideen pro Projekt (entferne eine, um weitere hinzuzufügen) und denselben Titel nur einmal. Das Ziehen einer Karte entscheidet nur über links oder rechts; nutze **↓**, um sie zu merken, und **▶**, um sie sofort umzusetzen. Eine Wiederholung wird nur am Titel erkannt: Das Modell kann eine frühere Idee unter einem neuen Namen trotzdem vorschlagen; überspringe sie. Antwortet das Modell nur mit früheren Ideen, erscheint nichts Neues: Klicke erneut. Ein enges Fokusthema macht das wahrscheinlicher; nutze ein breiteres Thema oder leere es. Das Fokusthema bleibt für jeden Chat im Feld, bis dsh oder die Seite neu lädt.
- **Chat als Markdown exportieren** enthält nur deine eigenen Nachrichten und die Textantworten des Assistenten. Werkzeugaufrufe und ihre Ausgabe, Reasoning, Bilder (eine Zeile `[image]` markiert sie), verborgener Kontext und Nachrichten, die Runde zurücknehmen oder dsh-rewind-plugin entfernt hat, fehlen. Die Antworten einer Runde werden zu einem Abschnitt zusammengefasst. Ein Export enthält höchstens etwa 4 Millionen Zeichen; bei einem längeren Chat enthält er den ersten Teil und einen Hinweis.
- **Nach Neustart fortsetzen** setzt die Runde fort; es spielt sie nicht erneut ab. Ein Tool-Aufruf, der beim Beenden lief, endet mit dem Ergebnis „outcome unknown“ von dsh, und das Modell erhält die Anweisung, fertige Arbeit nicht zu wiederholen. Ein Befehl, der nicht sicher zweimal laufen kann, kann aber erneut laufen. Subagents, Genehmigungen und Fragen, die offen waren, werden nicht wiederhergestellt: Ihr übergeordneter Chat macht weiter und fragt erneut. Höchstens 20 Chats werden bei einem Start fortgesetzt.
- **Nach Neustart fortsetzen** und die Warteschlange: dsh leert beim Beenden die Warteschlange eines Chats. Das Plugin stellt deine Nachrichten aus dem Protokoll des Chats wieder her, mit Reihenfolge, Änderungen, Bildern und Dateien; sie laufen nach der fortgesetzten Runde. Nur Chats, die fortgesetzt werden, bekommen ihre Warteschlange zurück (Schalter an, Beenden während die Runde lief). dsh protokolliert dein eigenes Entfernen der letzten Nachrichten in der Warteschlange genauso: Wenn du sie entfernst und dsh beendet wird, bevor der nächste Schritt beginnt, kommen sie zurück.

- **Inhaltssuche** ist die eigene Suche von dsh und hat daher die Grenzen von dsh. Sie durchsucht nur Benutzer- und Assistentennachrichten: keine Tool-Ausgabe (Befehle, Dateiinhalte, Ergebnisse) und kein Reasoning. Sie hat auch keinen Filter für Benutzer-, Assistenten- oder Tool-Nachrichten. Sie findet ganze Wörter, keine Wortteile (`deploy` findet nicht `deployment`). Buchstaben mit Akzent passen auch ohne Akzent (`seker` findet `şeker`). Eine Zeile pro Chat, mit dem Ausschnitt von 240 Zeichen von dsh, höchstens 20 Zeilen.
- Aufwand der **Inhaltssuche**, gemessen an einer Kopie von 247 echten Chatprotokollen (159 MB, dsh 0.2.1-rc.2, Apple Silicon, 32 GB): Die erste Suche nach einem Start baut den Index in etwa 15 s auf. In dieser Zeit antwortet der Host von dsh etwa 7 s lang nicht. Andere Chats streamen in diesem Moment also nicht (die Seite selbst friert nicht ein). Der Speicher des Hosts wächst in der Spitze um etwa 1,1 GB. Eine Minute später liegt er noch etwa 0,5–0,6 GB über dem Startwert, bis dsh beendet wird. Die Indexdatei hat etwa 165 MB. Spätere Suchen dauern etwa 0,5 s. Nach einem Neustart dauert die erste Suche etwa 1 s (nur neue oder geänderte Chats kommen hinzu) und fügt etwa 70 MB hinzu. Schalte die Funktion aus, wenn dein Computer wenig Arbeitsspeicher hat.
- **Inhaltssuche** gilt erst nach einem Neustart von dsh. Alle dsh-Instanzen, die dasselbe dsh-Home nutzen, teilen sich die Indexdatei: Lass immer nur ein solches dsh gleichzeitig laufen (dsh erlaubt einen Besitzer pro Indexdatei).
- **Runde zurücknehmen** setzt Dateien nur in einem git-Repository zurück und nur im Ordner des Chats. Es behält die 50 neuesten Snapshots pro Chat. Ignorierte Dateien (`.gitignore`, `info/exclude`, deine globale Ignore-Datei), leere Ordner, Symlinks und Submodule werden nicht zurückgesetzt. Eine Datei, die beim Snapshot ignoriert war, wird nie gelöscht, auch wenn die Runde die Ignore-Regeln geändert hat. Eine Datei, die git nicht lesen kann, fehlt im Snapshot. Jede deiner Nachrichten führt ein `git add --all` des Chat-Ordners in den privaten Speicher aus. In einem sehr großen Ordner mit vielen nicht verfolgten Dateien kann das einige Sekunden dauern, und der nächste Tool-Aufruf wartet darauf (höchstens 10 s; der Snapshot wird dann im Hintergrund fertig). Wenn `git gc` in deinem Repository ein Objekt entfernt, das ein alter Snapshot braucht, wird diese Datei als nicht zurückgesetzt aufgelistet. Nur der Text der Nachricht kommt ins Eingabefeld zurück: Füge ihre Bilder oder Dateien erneut hinzu. Subagent-Chats haben kein ↶ (die Dateiänderungen eines Subagents zählen als Änderungen des Chats, der ihn gestartet hat). Der exportierte Chat (`/export`) enthält die zurückgenommenen Nachrichten weiterhin. Die Idee einer verborgenen Markierung, die einen Teil eines Chats zurücknimmt, stammt aus [dsh-rewind-plugin](https://github.com/SiriLee/dsh-rewind) von SiriLee (MIT). Composer Plus nutzt keinen Code daraus.

Ein Chat (oder einer seiner Subagent-Chats), der nicht innerhalb von 15 s stoppt oder den ein anderes dsh hält, bleibt archiviert, und nichts wird verschoben. Auf anderen Systemen als macOS muss der Papierkorb-Ordner auf demselben Laufwerk liegen wie der Chatverlauf. Ein geöffneter Chat, den du löschst, bleibt archiviert und ausgeblendet im Speicher von dsh, bis dsh neu startet. Leere den Papierkorb selbst; dsh tut das nicht.

Nachrichten mit Bildern oder Dateien lassen sich ebenfalls verschieben. Nur deine eigenen Nachrichten lassen sich verschieben: Eine Zielrunde oder eine Antwort auf eine Frage in der Warteschlange bleibt an ihrem Platz. Beginnt das Senden einer Nachricht, während du ziehst, wird nichts verschoben, und ein Hinweis meldet das.

Freigaben aus Version 1.12 und älter haben keine Zeit: Nach dem Update fragt der Agent für diese Tools noch einmal.

Tasten, die du in dieser Zeit drückst, gehen verloren. Wenn das `/`-Menü von dsh noch offen ist, wählt `Enter` die markierte Zeile und sendet nicht.
- **Fragekarte an das Fenster anpassen** ändert nur die Fragekarte von dsh, nicht die Karte zur Planprüfung. Sie findet die Karte über das Markup von dsh (`data-question-key`, `data-question-scroll`); ändert ein dsh-Update dieses Markup, erscheint die Karte so, wie dsh sie zeichnet. Die Höhe der Karte folgt dem Fenster, nicht dem Chat: In einem Chat in einem schmalen Seitenbereich kann eine hohe Karte noch über den Chat hinausragen.
- **Mobile Verbindung** funktioniert nur unter macOS (sie nutzt `en0`, `openssl`, `swift` und `dns-sd`). Sie nutzt die festen Ports 19390 und 19391. Daher kann auf jedem Mac nur ein dsh sie gleichzeitig ausführen (jeder Mac ist ein Eintrag in der Mac-Liste des Telefons). Das Telefon bekommt Benachrichtigungen nur, solange Tether offen ist oder gerade in den Hintergrund gewechselt ist (kein Push-Dienst). Die iOS-App ist noch nicht im App Store: Baue sie mit Xcode aus `tether/ios`. „Tailscale only“ braucht trotzdem eine WLAN- oder Ethernet-Adresse auf dem Mac (das Gateway startet nur mit einer solchen Adresse). Das Zugriffsprotokoll gilt pro Mac und speichert nur die neuesten 200 Versuche. Ein wiederholter Versuch innerhalb einer Minute zählt dieselbe Zeile um eins hoch. Die App-Sperre von Tether blendet Mitteilungsvorschauen auf dem Sperrbildschirm des iPhone nicht aus: Schalte sie in den iOS-Einstellungen aus. Die grünen Punkte in Tether folgen dem Mac: Ein Chat, den du in dsh öffnest, verliert seinen Punkt auch auf dem Telefon. Ein Chat, den du in Tether öffnest, verliert seinen Punkt nur auf den Telefonen. Der eigene Punkt von dsh auf dem Mac bleibt, bis du den Chat dort öffnest.
- Ein Sitzungslink funktioniert in Chats; ein Klick darauf öffnet den Chat nicht. Ein mit **Nachrichtenlink kopieren** erstellter Link öffnet seine Nachricht nur ab dsh 0.2.1 und nur aus einer Nachricht in einem Chat (dsh 0.2.0 hat keine Regeln für Benutzertext, dort wird der Link kopiert, erscheint aber als einfacher Text). Eine Nachricht, die ein Zurücknehmen entfernt hat oder die die Komprimierung aus dem Verlauf entfernt hat, den dsh lädt, kann nicht angezeigt werden: Der Link sagt das dann. Die 🔗-Schaltflächen hängen sich an die Nachrichtenzeilen von dsh. Wenn ein dsh-Update dieses Markup ändert, erscheinen sie nicht.
- **Alle als gelesen markieren** ändert die eigenen Ungelesen-Punkte von dsh über einen Teil von dsh, der keine öffentliche API ist (die Liste `completionUnread` im Sitzungsstatus von dsh). Wenn ein dsh-Update sie umbenennt, erscheint der Eintrag nicht. Der Eintrag kommt in das „…“-Menü des Projekts in dsh, das keinen Platz für Plugins hat. Wenn dsh dieses Menü ändert, erscheint der Eintrag ebenfalls nicht.
- **Eingereihte Nachricht direkt bearbeiten** ändert keine Nachricht, deren Senden inzwischen begonnen hat, und überschreibt keine Nachricht, die sich inzwischen geändert hat (zum Beispiel in Tether auf dem iPhone): Ein Hinweis meldet das. Ein neues Bild braucht ein Modell, das Bilder annimmt (die eigenen Bildgrenzen von dsh gelten), und eine neue Datei muss fertig hochgeladen sein, bevor du speichern kannst. Nur deine eigenen eingereihten Nachrichten lassen sich bearbeiten: Eine Zielrunde oder eine Antwort auf eine Frage in der Warteschlange nicht. Nach einem Update des Plugins funktionieren nur Textänderungen sofort: Starte dsh neu, bevor du eine Nachricht mit Bildern oder Dateien speicherst (die Host-Hälfte lädt beim Start).
- **Wiederholen** ändert nie den zurückgenommenen Chat: Es startet einen neuen Chat ab dem Moment direkt vor dem Zurücknehmen (die eigene Abzweigung von dsh, derselbe Kontext des Modells). Der neue Chat hat daher eine neue ID und einen neuen Titel. Nur das neueste Zurücknehmen eines Chats lässt sich wiederholen, einmal, und nur solange danach nichts kam (eine neue Nachricht beendet das Angebot). Eine Datei, die du nach dem Zurücknehmen geändert hast, bleibt erhalten, außer du setzt das Häkchen, das sie überschreibt. Wiederholen braucht den Snapshot, den das Zurücknehmen behalten hat (dasselbe Fenster von 50 Einträgen). Ein Zurücknehmen vor dieser Version oder mit **Nur Chat** holt nur die Nachrichten zurück.
- **Dieser Chat** zählt nur Dateien, die die Datei-Tools von dsh (`write`, `edit`, `str_replace_editor`) geschrieben haben. Dateien, die ein Befehl (`bash`) geändert hat, sind nicht in dieser Ansicht. Sie erscheinen unter **Nicht committet**. Ohne Snapshot von Runde zurücknehmen für den Chat (Runde zurücknehmen aus, dsh-rewind-plugin installiert oder ein Chat, der älter als das Plugin ist) vergleicht die Ansicht mit dem letzten Commit und sagt das. Runde zurücknehmen behält die 50 neuesten Snapshots eines Chats: In einem längeren Chat vergleicht die Ansicht mit dem ältesten behaltenen, nennt die Nachricht und zählt frühere Änderungen nicht. **Leerraum-Änderungen ausblenden** ist `git diff -w`: Auch eine Zeile, die sich nur in Leerzeichen in ihrem Inneren geändert hat, wird ausgeblendet.
- **GitHub-Issue öffnen** braucht das GitHub CLI (`gh`) im PATH von dsh und ein GitHub-Remote im Ordner des Chats. Es läuft höchstens 60 s. Dauert `gh` länger, kann das Issue auf GitHub existieren, ohne dass sein Link in der Liste steht (sieh auf GitHub nach, bevor du erneut klickst: Die Liste liest den Link nur aus einem abgeschlossenen Lauf, ein neuer Klick kann also ein zweites Issue öffnen). Ein Ordner mit mehr als einem GitHub-Remote nutzt den eigenen Standard von `gh` (`gh repo set-default`).
- **Chats, die diese Datei geändert haben** kennt wie **Dieser Chat** nur die Datei-Tools von dsh (`write`, `edit`, `str_replace_editor`): Eine Änderung durch einen Befehl (`bash`) wird nicht aufgeführt. Die Liste liest die neuesten 300 Chats des Repositorys (nach ihrem Erstellungszeitpunkt) und sagt es, wenn es mehr gibt. Sie zeigt höchstens 100 Zeilen. Eine umbenannte Datei steht unter dem Namen, den das Tool geschrieben hat. Ein Chat, dessen Ordner außerhalb des Repositorys liegt (auch über einen anderen Pfad zu denselben Dateien), zählt nicht. Das erste Öffnen nach einem Start von dsh liest alle Chatprotokolle des Repositorys (etwa 4 s für 275 Chats). Spätere Aufrufe lesen nur die Chats, die sich seitdem geändert haben.
- **Git-Branch in Chatzeilen** zeigt den Branch des Chat-Ordners zu Beginn oder am Ende der letzten Runde, nicht den aktuellen Branch: Ein Branch-Wechsel außerhalb einer Runde erscheint erst nach der nächsten Runde. Chats von vor dieser Version zeigen bis zu ihrer nächsten Runde kein Etikett. Das Etikett sitzt im Markup der Chatzeilen von dsh (dsh hat dort keinen Platz dafür). Wenn ein dsh-Update dieses Markup ändert, erscheint kein Etikett. Wenn die Projektzeile über dem Chat denselben Namen wie der Branch hat (zum Beispiel ein Ordner von „Ein Branch pro Chat“), zeigt die Chatzeile kein Etikett, aber „In einer Liste“ zeigt es weiterhin.
- **Ein Branch pro Chat**: Wenn der Branch-Ordner eines Chats (`<project>/.worktrees/<name>`) gelöscht wird, zum Beispiel wenn der eigene Agent des Chats den Worktree entfernt und den Branch löscht, verschiebt der nächste Schritt des Chats den Chat aus diesem Ordner. Das Projekt des Branch-Ordners verschwindet aus der Seitenleiste, und der Chat erscheint unter Ohne Gruppe und bleibt offen. Ab dsh 0.2.1 läuft der Chat im Hauptordner des Projekts weiter, und das Modell bekommt einen Hinweis auf den neuen Ordner. Unter dsh 0.2.0 behält der Chat den gelöschten Ordner: Ein Befehl dort schlägt fehl, bis Sie einen neuen Chat beginnen. Die Verschiebung geschieht erst beim nächsten Schritt des Chats. Daher bleibt das Projekt eines gelöschten Branches, das kein Chat nutzt, in der Seitenleiste: Entfernen Sie es mit dem Projektmenü von dsh. Während ein Chat verschoben wird, antwortet **Neuer Branch** im selben Repository mit „erneut versuchen“. Mit ausgeschaltetem Schalter zeigt dsh wieder seinen eigenen Fehler („working-directory: directory does not exist“).
- **Branches im Arbeitsbereichsbaum** schreibt ohne Klick in git: Wenn es einen Chat verschiebt, setzt es den Projektordner auf seinen vorherigen Branch zurück (`git switch`) und fügt einen Worktree hinzu (`git worktree add`). Es löscht nie einen Branch, einen Worktree oder eine Datei. dsh kann den Ordner eines Chats nicht ändern, daher ist ein verschobener Chat eine Kopie (dshs eigener Fork, mit neuer ID), und der alte Chat wird archiviert. Die Kopie setzt die angehaltene Aufgabe fort; ein Tool-Aufruf, der lief, als der Branch erschien, endet mit einer Ablehnung, und der Agent führt ihn im neuen Ordner erneut aus. Ein Ziel des alten Chats zieht nicht mit. Nur ein Chat, dessen Ordner der Hauptordner des Repositorys ist, wird verschoben, und nur für einen Branch, den er in diesem Durchgang erstellt und ausgecheckt hat (`git switch -c`, `git checkout -b`): Ein nur mit `git branch` erstellter Branch, ein Ordner mit nicht committeten Änderungen, ein verknüpfter Worktree oder ein Unterordner verschieben nichts. Im Baum erscheinen nur Worktrees direkt in `<project>/.worktrees/` mit einem Branch; ein losgelöster (detached) Worktree oder einer an anderer Stelle erscheint nicht. Die Kopie öffnet sich nur von selbst, wenn ihr Chat der geöffnete war (das Plugin liest das aus dshs Zeile in der Seitenleiste); sonst ist sie im Branch-Projekt.
- **Im Chat suchen** durchsucht nur, was die Seite zeigt: die geladenen Nachrichten und Antworten (scrolle nach oben oder klicke auf **Ältere laden** für ältere), nicht geschlossene Tool-Schritte und nicht den eingeklappten Text in der Ausgabe eines Tools. Die Suche zählt höchstens 2.000 Treffer (dann „2000+“). Sie nutzt die Highlight-API des Browsers (Chromium 105 und neuer; die Desktop-App hat sie): In einem älteren Browser funktionieren die Zählung und das Springen ohne die Farbe. `Cmd+F` auf einem Mac (`Ctrl+F` unter Windows und Linux) öffnet sie nur, solange ein Chat auf dem Bildschirm ist. Anderswo funktioniert die eigene Suche des Browsers wie bisher. Auf einem Mac behält `Ctrl+F` in Textfeldern seine macOS-Funktion (der Cursor geht ein Zeichen weiter).
- Eine Benachrichtigung, die vor einem Neustart gesendet wurde, holt dsh beim Klicken nur in den Vordergrund.
- Aktive Projekte werden über die gespeicherte Projektreihenfolge von dsh verschoben. Die neue Reihenfolge bleibt also nach einem Neustart erhalten. Chats außerhalb eines Projekts („Ohne Gruppe“) lassen sich nicht verschieben; dsh listet sie immer zuletzt.
- dsh hat keinen Erweiterungspunkt im Menü der Ansichtsoptionen der Seitenleiste. Deshalb kommt die Option für aktuelle Projekte in das eigene Menü von dsh. Wenn ein dsh-Update dieses Menü ändert, erscheint die Option nicht, und alle Projekte bleiben sichtbar. Der Filter wirkt auf Projektzeilen, daher wird **In einer Liste** nicht gefiltert. Nutze ihn mit **Arbeitsbereich**: In **Arbeitsbereichsbaum** blendet ein ausgeblendeter übergeordneter Ordner auch die aktiven Projekte darin aus. **Nach Status** hat dieselbe Art von Grenze: dsh hat keinen Platz für eine Sortierung. Deshalb hängen sich der Eintrag und die Zeilenreihenfolge an das Menü- und Listen-Markup von dsh.
- dsh hat auch kein Menü für Projektzeilen und keinen Platz in der Kopfzeile der Arbeitsbereiche. **Pfad kopieren** findet die Projektzeile über das Zeilen-Markup von dsh. **Alle Projekte einklappen** sitzt in der Kopfzeile von dsh und schließt jedes geöffnete Projekt mit demselben Klick wie die Projektzeile. Wenn ein dsh-Update dieses Markup ändert, zeigt ein Rechtsklick das Menü des Browsers, und die Schaltfläche erscheint nicht.
- dsh hat auch im Projektmenü eines neuen Chats keinen Erweiterungspunkt. Deshalb hängen sich das Feld **Projekte durchsuchen** und die A–Z-Reihenfolge an das Menü-Markup von dsh. Wenn ein dsh-Update dieses Markup ändert, erscheint das Menü so, wie dsh es zeichnet: in der gespeicherten Reihenfolge und ohne das Feld. Die A–Z-Reihenfolge ist nur eine Ansicht: Sie ändert die gespeicherte Projektreihenfolge von dsh nicht.
- dsh hat auch keinen Erweiterungspunkt, der wählt, wo **Neue Sitzung** öffnet. **Standard-Arbeitsbereich für Neue Sitzung** umhüllt eine Methode von dsh, die keine öffentliche API ist (`startSession` des Arbeitsbereich-Dienstes von dsh). Wenn ein dsh-Update sie umbenennt, öffnet **Neue Sitzung** dort, wo dsh es wählt (das geöffnete oder das letzte Projekt). Jeder Aufruf ohne Projekt nutzt den Standard: die Schaltfläche in der Seitenleiste, ihr Tastenkürzel, das Logo und auch **Neu** auf der Seite **Automatisierungsaufgaben**. dsh öffnet beim Start weiterhin den letzten Chat. Der allgemeine Ordner wird bei der ersten Nutzung angelegt und zu deinen Projekten hinzugefügt; unter Windows oder Linux mit verschobenem Documents-Ordner kann er ein anderer Ordner als der von dsh sein.
- dsh hat auch für einen Hinweis im Eingabefeld keinen Erweiterungspunkt. Deshalb liegt der Text von **Vorhersage der nächsten Nachricht** über dem eigenen Platzhalter von dsh (`[data-composer-placeholder]`). Wenn ein dsh-Update dieses Markup ändert, erscheint keine Vorhersage. Solange die Funktion an ist, kostet jede beendete Runde einen kurzen Modellaufruf.
- Der Text von **Beim Tippen vervollständigen** erscheint über den eigenen Eingabehinweis von dsh (den Stil `--dsh-composer-hint`, den dsh für den Argumenthinweis eines Slash-Befehls nutzt). Die Funktion läuft nicht bei einem Slash-Befehl, bei einer Nachricht mit einem Datei- oder Symbol-Chip oder wenn der Cursor nicht am Ende der Nachricht steht. Wenn ein dsh-Update diesen Stil ändert, erscheint keine Vervollständigung. Jede Pause beim Tippen kostet einen Modellaufruf.
- **Prompt verbessern** sieht nur eine kurze Projektzusammenfassung, die geänderten Pfade und die Pfade, deren Namen zu deinen Wörtern passen: nicht den Code selbst. Daher kann die Funktion die richtige Datei übersehen, und sie nennt nur Pfade, die sie bekommen hat. Lies den neuen Text, bevor du ihn sendest. Sie läuft nicht bei einem Slash-Befehl oder bei einer Nachricht mit einem Datei- oder Symbol-Chip (der neue Text ist reiner Text, der Chip ginge also verloren), und eine Nachricht kann höchstens 8.000 Zeichen haben. Bilder bleiben angehängt: Nur der Text ändert sich. Jeder Klick kostet einen Modellaufruf; ein starkes Modell kann eine Minute brauchen (`Esc` bricht ab).
- **Zielprüfung** prüft nur einen Abschluss, den der Agent in einem automatischen Zieldurchlauf macht: Einen Abschluss, um den du im Chat bittest, `/goal` und die Zielleiste prüft sie nicht. Der Agent kann die Tests oder die Dateien des Testbefehls selbst ändern; der Prüfer liest den Chat und kann das sehen, kann sich aber in beide Richtungen irren (ein falsches „nicht fertig“ kostet einen Durchlauf mehr; ein falsches „fertig“ schließt das Ziel). Der Prüfer sieht den Chat und `git status`, nicht den Code selbst. Ein Testlauf wird nur wiederverwendet, wenn der neueste Schritt des Agenten, der Dateien ändern kann, sein eigener erfolgreicher `bash`-Lauf genau desselben Befehls im selben Ordner war; ein Befehl mit einer Pipe (`| tail`) oder `&&` wird nicht wiederverwendet. Das Budget wird gemessen, wenn eine Runde endet. Daher kann eine Runde darüber hinausgehen. Nur die eigenen Modellaufrufe des Chats zählen (nicht die seiner Subagents). `update_goal` wartet, während die Prüfung läuft (der Test höchstens 15 Minuten, der Prüfer höchstens 3 Minuten). Eine Abzweigung bekommt eine neue Chat-ID und startet daher ohne den eigenen Testbefehl und die Limits des übergeordneten Chats. Jeder Abschluss, der den Prüfer erreicht, kostet einen Modellaufruf.

## Häufige Fragen

**Wie füge ich DeepSeek Harness einen Bereich für Änderungen / git-Diffs hinzu?** Installiere `dsh-composer-plus` und öffne dann rechte Seitenleiste → `+` → **Änderungen**.

**Kann dsh Funktionen für mein Projekt vorschlagen, mit Karten zum Wischen wie bei Tinder?** Ja: rechte Seitenleiste → `+` → **Funktionsideen** → **Funktionen vorschlagen**. Wische nach rechts, um einen neuen Chat zu starten, der die Funktion plant. Klicke auf **▶ Sofort umsetzen**, um einen Chat zu starten, der sie ohne Plan sofort umsetzt. Wische nach links, um sie zu überspringen.

**Kann die Seitenleisten-Suche von dsh einen Chat über ein Wort in seinen Nachrichten finden, nicht nur über den Titel?** Ja, mit **Inhaltssuche** (standardmäßig an): Starte dsh nach der Installation des Plugins einmal neu und nutze dann die Lupe neben **Arbeitsbereiche**. Passende Chats zeigen den Text um das Wort herum.

**Kann ich eine Runde rückgängig machen und meinen Prompt bearbeiten, wie in OpenCode oder Claude Code?** Ja, mit **Runde zurücknehmen**: Klicke an der Nachricht auf **↶**, wähle **Chat und Dateien**, bearbeite den Text, der ins Eingabefeld zurückkommt, und sende ihn.

**Kann ich einen Chat löschen, statt ihn zu archivieren?** Ja, mit **Chat löschen**: **…** → **Löschen…**. Der Verlauf kommt in den Papierkorb, also lässt sich ein Fehler rückgängig machen.

**Wie sehe ich, zu welchem Projekt ein Chat gehört?** Sieh auf die Zeile unter dem Eingabefeld: Mit **Projektname im Eingabefeld** (standardmäßig an) beginnt sie mit dem Projektnamen. Fahre mit der Maus darüber, um den Ordnerpfad zu sehen.

**Wie bekomme ich einen ↑/↓-Nachrichtenverlauf im Eingabefeld von dsh?** Installiere dieses Plugin. In einem leeren Eingabefeld gehst du mit `↑` / `↓` durch deine gesendeten Nachrichten.

**Wie setze ich eine gestoppte oder fehlgeschlagene Runde in dsh fort, ohne „continue“ zu tippen?** Mit diesem Plugin wird die Senden-Schaltfläche nach einer gestoppten, fehlgeschlagenen oder abgebrochenen Runde zu **▶**. Ein Klick setzt die Runde fort.

**Setzt dsh laufende Chats fort, nachdem ich es beendet und wieder geöffnet habe?** Nicht von selbst: dsh markiert eine solche Runde als unterbrochen und wartet (ein Ziel wartet auch auf `/goal resume`). Schalte **Einstellungen → Composer Plus → Nach Neustart fortsetzen** ein: Die Chats, die beim Beenden von dsh gearbeitet haben, machen dann beim nächsten Start von selbst weiter.

**Welches Modell schreibt die Vorhersage?** Das Modell, das du unter **Einstellungen → Composer Plus → Vorhersage der nächsten Nachricht → Modell** wählst. Die Liste ist die eigene Modellliste von dsh. **dsh-Standard** folgt dem Standardmodell von dsh. Wenn dsh das gewählte Modell nicht mehr listet, nutzt die Vorhersage den Standard. **Beim Tippen vervollständigen** hat ein eigenes Menü **Modell**: **Wie Vorhersage der nächsten Nachricht** (der Standard) folgt dem Modell der Vorhersage. Eine andere Wahl gilt nur für Vervollständigungen. Wenn dsh dieses Modell nicht mehr listet, nutzen Vervollständigungen das Modell der Vorhersage.

**Kann dsh meinen Prompt vor dem Senden verbessern, wie die Schaltfläche Enhance prompt in Roo Code oder Augment?** Ja, mit **Prompt verbessern** (standardmäßig an): Tippe eine grobe Anfrage und klicke auf den Zauberstab neben dem Modellmenü. Die Funktion schreibt den Text mit diesem Chat und dem Projekt als Kontext neu, in deiner Sprache, und sendet ihn nicht. `Cmd/Ctrl+Z` oder **Verbesserung rückgängig machen** holt deinen Text zurück. Wähle ihr Modell unter **Einstellungen → Composer Plus → Prompt verbessern → Modell**.

**Kann der Agent aufhören, seine eigene Arbeit als fertig zu markieren, wie bei den Prüfschleifen im Loop Engineering?** Ja, mit **Zielprüfung** (standardmäßig an): Starte ein Ziel mit `/goal`. Wenn der Agent sagt, dass das Ziel abgeschlossen ist, laufen die Tests des Projekts, und ein unabhängiger Modellaufruf prüft das Ziel anhand des Chats; schlägt eins davon fehl, bleibt das Ziel offen und der Agent liest den Grund. Lege deinen eigenen Testbefehl, ein Zeitlimit oder ein Token-Limit mit **Bearbeiten** in der Zeile **Zielprüfung** unter dem Ziel fest.

**Wie ordne ich eingereihte Nachrichten in dsh neu?** Ziehe den Griff ⠿ an einer eingereihten Nachricht, oder setze den Fokus darauf und drücke `↑` / `↓`.

**Wie korrigiere ich einen Tippfehler in einer eingereihten Nachricht?** Doppelklicke auf die Nachricht in der Warteschlange, ändere den Text und drücke `Enter` (`Esc` bricht ab). Sie behält ihren Platz in der Warteschlange. Dort kannst du auch ihre Bilder und Dateien entfernen oder neue hinzufügen.

**Wie entferne ich alle Ungelesen-Punkte eines Projekts auf einmal?** Seitenleiste → Schaltfläche **…** des Projekts → **Alle als gelesen markieren**.

**Kann ich auf eine einzelne Nachricht in einem langen Chat verlinken?** Ja: Fahre mit der Maus über die Nachricht und klicke auf **🔗**. Sende den Link in einem Chat: Ab dsh 0.2.1 öffnet ein Klick darauf den Chat an dieser Nachricht.

**Ich habe eine Runde aus Versehen zurückgenommen. Bekomme ich sie zurück?** Ja, mit **Wiederholen** über dem Eingabefeld, direkt nach dem Zurücknehmen: Es startet einen neuen Chat ab dem Moment direkt vor dem Zurücknehmen, mit denselben Nachrichten. Mit **Chat und Dateien** holt es auch die Dateien zurück.

**Welcher Chat hat diese Datei geändert?** Rechte Seitenleiste → **Änderungen** → **…** der Datei → **Chats, die diese Datei geändert haben**. Klicke auf eine Zeile, um diesen Chat bei der Anfrage zu öffnen, die die Änderung gemacht hat.

**Kann ich in einem langen Chat suchen?** Ja: Drücke im Chat `Cmd+F` auf einem Mac (`Ctrl+F` unter Windows und Linux). **Im Chat suchen** hebt jeden Treffer hervor und springt mit `Enter` und `Shift+Enter` zwischen ihnen.

**Wie sehe ich nur die Dateien, die ein Chat geändert hat?** Rechte Seitenleiste → **Änderungen** → **Dieser Chat**. Klicke auf **␣**, um Änderungen auszublenden, die nur Leerraum sind.

**Wie verhindere ich, dass die automatische Prüfung in einem Chat immer wieder nach demselben Tool fragt?** Klicke auf der Genehmigungskarte auf **Für diesen Chat zulassen**. Das gilt nur für genau dieses Tool in diesem Chat, standardmäßig für 1 Stunde. Widerrufe es über den Chip in der Kopfzeile. Ändere die Zeit unter **Einstellungen → Composer Plus → Für diesen Chat zulassen**.

**Ich habe mein iPhone verloren. Wie verhindere ich, dass es meinen Mac erreicht?** Klicke unten links in der Seitenleiste auf **Mobile Verbindung** und dann neben diesem iPhone auf **Remove**. Sein Schlüssel funktioniert sofort nicht mehr. Es kann nur mit einer neuen Kopplung zurückkommen, die du auf dem Mac bestätigst.

**Kann ich Tether mit Face ID sperren?** Ja: Schalte in Tether „Settings → Privacy → Lock with Face ID“ ein. Tether fragt dann beim Öffnen und bei der Rückkehr zur App nach Face ID (oder dem Code).

**Wie zeige ich in der Seitenleiste von dsh nur die Projekte, die ich heute genutzt habe?** Seitenleiste → Ansichtsoptionen (Schieberegler-Symbol) → **In den letzten 2 Stunden aktiv**. Wähle die Option erneut, um alle Projekte zu zeigen.

**Wie kopiere ich in dsh den Ordnerpfad eines Projekts?** Rechtsklick auf das Projekt in der Seitenleiste → **Pfad kopieren**.

**Wie klappe ich alle Projekte in der Seitenleiste von dsh auf einmal ein?** Klicke auf die Einklapp-Schaltfläche neben den Ansichtsoptionen (Schieberegler-Symbol). Sie erscheint, solange mindestens ein Projekt geöffnet ist.

**Wie bekomme ich Benachrichtigungen unter macOS / Windows, wenn eine dsh-Aufgabe fertig ist oder eine Genehmigung braucht?** Lass **Hintergrundbenachrichtigungen** an (Standard) und erlaube Benachrichtigungen für DeepSeek Harness in den Einstellungen des Betriebssystems.

**Wie stelle ich die Oberfläche von DeepSeek Harness auf Türkisch, Spanisch, Japanisch … um?** Einstellungen → Composer Plus → **App-Sprache**.

**Wie nutze ich dsh von meinem iPhone aus?** Baue die Tether-App aus `tether/ios` (Xcode). Schalte **Einstellungen → Composer Plus → Mobile Verbindung (iPhone)** ein und klicke unten links auf **Mobile Verbindung**. Scanne den QR-Code (mit der iPhone-Kamera oder mit **Scan code** in Tether), tippe auf **Connect** und klicke auf **Approve**. Unterwegs nutzt du Tailscale auf beiden Geräten.

**Wie öffnet sich Neue Sitzung immer im selben Projekt?** Einstellungen → Composer Plus → **Standard-Arbeitsbereich für Neue Sitzung** → **Neue Sitzung öffnen in** → wähle das Projekt. Das `+` neben einem anderen Projekt öffnet weiterhin dieses Projekt.

**Wie arbeite ich gleichzeitig an mehreren Funktionen eines Projekts, jede auf ihrem eigenen Branch?** Mit **Ein Branch pro Chat**: neuer Chat → die Schaltfläche main mit dem Branch-Symbol → **Neuer Branch**, dann sende die erste Nachricht. Jeder Chat bekommt einen eigenen Branch und einen eigenen Worktree-Ordner, mit deiner `.env` und deinem `node_modules`, wenn `.worktreeinclude` sie auflistet. Die Kopfzeile des Chats zeigt, auf welchem Branch du bist.

**Kann die Seitenleiste jeden Branch eines Projekts zeigen und meinen Chat verschieben, wenn der Agent einen Branch erstellt?** Ja, mit **Branches im Arbeitsbereichsbaum** (standardmäßig aus): Schalte es in Einstellungen → Composer Plus ein und wähle in dsh **Ansichtsoptionen** → **Arbeitsbereichsbaum**. Jeder Branch mit einem Worktree in `<project>/.worktrees/` erscheint in seinem Projekt. Wenn du den Agenten im Projektordner bittest, einen Branch zu erstellen und dort zu arbeiten, und der Ordner keine nicht committeten Änderungen hat, zieht der Chat von selbst in den Branch um. Lösche den Ordner des Branches, dann verschwindet er aus der Liste; seine Chats kommen nach **Ohne Gruppe**.

**Kann ich ein Foto von meinem iPhone senden?** Ja. Tippe in einem Tether-Chat auf **+** neben dem Nachrichtenfeld → Camera, Photos (bis zu 4) oder Paste image. Die Fotos kommen als Anhänge deiner Nachricht in den Chat auf dem Mac, daher sieht das Modell sie.

**Funktioniert es mit der Desktop-App?** Ja: Einstellungen → Plugins → **Plugin hinzufügen** → `dsh-composer-plus`. Getestet mit dsh 0.2.0-rc.2 (Desktop und Web) und 0.2.1-rc.2 (Web).

**Regel für neue Funktionen:** Jede Funktionszeile unter Einstellungen → Composer Plus zeigt einen Screenshot. Füge die ID der Funktion zu `SHOT_OF` in `client.js` und zu `SHOTS` in `index.js` hinzu, und liefere `assets/features/<id>.webp` mit aus (aufgenommen im Wegwerf-Demo-dsh, englische Oberfläche, etwa 60 kB oder weniger). Trage die Funktion mit demselben Bild in `docs/features.json` ein und führe `npm run build:readme` aus: Es schreibt die Funktionstabelle von `README.md` und jeder übersetzten `README.<id>.md` sowie die Liste in `llms.txt`. `test/shots.test.mjs` schlägt fehl, wenn eine Funktion keinen Screenshot hat, und `test/browser-settings-shots.mjs` prüft die echte Einstellungsseite. Die vollständige Checkliste für jede Änderung steht in [AGENTS.md](AGENTS.md).

Die Tests führen das echte `client.js` gegen ein Fake-React/DOM aus und das echte `index.js` (Host-Hälfte) gegen ein temporäres git-Repository. Die Tests des Tether-Gateways (`test/tether-gateway.test.mjs`) nutzen einen Mock-dsh-Host und ein echtes TLS-Gateway. Die iPhone-App liegt in `tether/ios` (siehe [tether/README.md](tether/README.md) und [tether/AGENTS.md](tether/AGENTS.md)). [docs/ROUTES.md](docs/ROUTES.md) listet jede Host-Route, ihre Anfrage und ob Tether sie aufrufen kann. `node test/browser-history.mjs '<dsh web URL with ?token=…>'` prüft den Eingabeverlauf in einem echten Browser gegen ein Wegwerf-`dsh web` mit eigenem `DSH_HOME`.

Sprachpakete sind reine Daten-JSON-Dateien in `locales/<id>.json`. `npm run build:locales` bettet sie in den einzigen Client-Einstiegspunkt ein (kein Übersetzungsdienst, kein Download zur Laufzeit). `npm test` prüft jedes Paket auf vollständige Schlüsselabdeckung, identische Platzhalter und Zeilenumbrüche sowie auf das Verhalten von Systemsprache und manueller Auswahl. Für isolierte Prüfungen in der echten App mit einem lokal installierten Playwright:

```sh
PLAYWRIGHT=/path/to/playwright node test/browser-language.mjs /path/to/dsh/lib/bin.js
```
