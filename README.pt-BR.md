Recursos práticos no estilo do Codex para a interface desktop e web do [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (dsh): um painel de alterações, ideias de recursos em cartões para deslizar, pesquisa na barra lateral pelo texto das mensagens, reversão de turnos com restauração de arquivos, exclusão de chats para o Lixo, o nome do projeto abaixo do editor de mensagens, status do projeto na barra lateral, histórico de entrada, um atalho para o modo de plano, Continuar com um clique, retomada dos chats em execução depois de reiniciar, arrastar e soltar na fila, deeplinks de sessão, exportação do chat como Markdown, autorizações da Revisão automática por chat, notificações em segundo plano, acesso pelo iPhone com o app Tether e atualizações automáticas.

**Em uma linha:** um único plugin do DeepSeek Harness (npm `dsh-composer-plus`, exibido como **Composer Plus** em Configurações → Plugins) que adiciona um painel de alterações do git, cartões de ideias de recursos no estilo Tinder, pesquisa na barra lateral que também encontra palavras nas mensagens, ↶ Reverter turno (apenas o chat, ou chat e arquivos), Excluir chat, o nome do projeto abaixo do editor de mensagens, histórico de entrada com ↑/↓, alternância de `/plan` com Shift+Tab, ▶ Continuar com um clique, Retomar após reiniciar, reordenação da fila com arrastar e soltar, Copiar link da sessão, Exportar como Markdown, “Permitir neste chat” na Revisão automática, notificações em segundo plano, acesso pelo iPhone (Conexão móvel, app Tether), 11 idiomas extras na interface e atualizações automáticas.

<p align="center"><img src="docs/images/hero.webp" width="820" alt="DeepSeek Harness com o Composer Plus: o projeto em execução mostra um indicador de carregamento na barra lateral e o painel de alterações mostra um diff do git"></p>

Plugin não oficial da comunidade. A verificação de atualizações faz chamadas de rede (releases do GitHub e registro do npm); desative **Atualizações automáticas** para que elas não aconteçam ao iniciar. **Pacote de skill em turco** (ligado por padrão) baixa o turkish-anti-ai-skill do GitHub e procura uma versão nova uma vez por dia, somente enquanto **Idioma do aplicativo** for Türkçe; desligue-o em **Configurações → Composer Plus** para parar essas chamadas. **Ideias de recursos** chama o próprio modelo do seu chat só quando você clica em **Sugerir recursos**. **Previsão da próxima mensagem** (ativada por padrão) chama o modelo escolhido nas Configurações (o padrão do dsh, a menos que você escolha outro) uma vez após cada turno concluído, sem nenhum clique. Desative-a em **Configurações → Composer Plus** para parar essas chamadas. **Completar ao digitar** (desativado por padrão) chama o modelo escolhido para ele (por padrão, o da previsão) a cada pausa enquanto você digita, depois que você o ativa. **Melhorar prompt** só chama um modelo quando você clica na varinha mágica dele. **Quadro de tarefas** chama o modelo do novo chat uma vez para as etiquetas de cada tarefa que você inicia no quadro. Com a configuração **Resumo com IA** (o padrão é **Rápido (sem IA)**), ele também chama o modelo de um chat em andamento para uma nota curta de progresso enquanto você olha o progresso dessa tarefa no quadro ou no Tether. **Verificação da meta** (ativada por padrão) chama um modelo uma vez cada vez que o agente marca uma `/goal` como concluída em uma rodada automática. **Conexão móvel** (desativada por padrão) só aceita conexões do iPhone vindas da sua rede local ou da sua tailnet depois que você a ativa.

## Instalação

**App desktop:** Configurações → Plugins → **Adicionar plugin** → digite `dsh-composer-plus` → **Ativar agora**.
Você também pode colar `https://github.com/furkancak1r/dsh-composer-plus` em vez do nome do npm.

**Perfil web / CLI:**

```sh
dsh plugin --profile web add dsh-composer-plus
```

Depois, reinicie o dsh. (A CLI não consegue instalar no perfil desktop; quem gerencia esse perfil é o app.)

> O pnpm do dsh ignora versões publicadas há menos de 24 horas. Logo depois de uma nova versão, informe a versão: `dsh-composer-plus@1.27.0`.

Enquanto o chat ainda não tem mensagens, um cartão curto acima do campo de entrada explica o que o assistente faz e mostra três pedidos de exemplo; ele some com a sua primeira mensagem. Peça um lembrete (“me lembre de beber água daqui a 2 minutos”): ele usa as tarefas agendadas do dsh, então o lembrete executa o chat nessa hora, e o Tether envia a notificação "Turn finished" quando a Conexão móvel está ativada. Fale com ele como com um amigo que trabalha em segundo plano: uma tarefa mais demorada (uma pesquisa, várias etapas) vai para um subagente próprio em segundo plano, e o chat diz em uma linha o que iniciou e fica livre na hora. Abra um segundo assunto enquanto o primeiro ainda está em execução: cada assunto ganha o próprio subagente, e cada resultado volta a este chat quando fica pronto. Peça uma pesquisa na web ou pergunte sobre seus outros chats: ele pode listar os chats de todos os projetos (em execução, esperando por você ou ociosos) e ler as mensagens mais recentes de um deles. Só este chat tem essas ferramentas e suas instruções curtas; um texto que ele lê em uma página web ou em outro chat conta como dado, não como ordem. ## Configurações

Cada recurso pode ser ativado ou desativado separadamente em **Configurações → Composer Plus** do dsh. Cada linha tem uma pequena captura de tela: passe o mouse sobre ela para ver uma prévia maior e clique para abri-la em tamanho real (`Esc` fecha). A caixa **Pesquisar recursos** no topo filtra a página por nome ou descrição (em qualquer idioma, sem diferenciar maiúsculas, minúsculas e acentos); `Esc` limpa a caixa. Ao lado, **Todos**, **Ativados** e **Desativados** mostram todos os recursos, só os ativados ou só os desativados (desative **Filtro ativados/desativados** para ocultá-los). Cada linha tem uma chave e uma breve descrição; as alterações valem na hora, sem reiniciar, e ficam salvas naquele dispositivo. O pequeno **?** ao lado do nome de uma linha abre a parte deste README que descreve esse recurso, no README do idioma da interface do dsh. Tudo vem ativado por padrão, exceto **Conexão móvel**, **Retomar após reiniciar** e **Completar ao digitar**. O Host do dsh guarda as chaves desses três recursos e também de **Pesquisa no conteúdo**, **Reverter turno**, **Previsão da próxima mensagem** e **Verificação da meta**, então elas valem para todas as janelas e continuam depois de reiniciar. O Host também guarda o **Modelo** escolhido para a **Previsão da próxima mensagem**, o de **Completar ao digitar** (por padrão **Igual à previsão da próxima mensagem**), o de **Melhorar prompt**, o de **Verificação da meta** (ambos por padrão **Igual ao modelo do chat**) e o **Limite de tempo** de **Permitir neste chat** (1 hora por padrão). **Pesquisa no conteúdo** só muda depois de reiniciar o dsh (o dsh lê essa chave ao iniciar); até lá, a linha dela diz **Reinicie o dsh para aplicar esta alteração.**

A escolha é a própria `locale.preference` salva do dsh (a mesma de Geral → Idioma), então ela continua depois de reiniciar. **Idioma do sistema** limpa essa escolha: o app desktop segue o idioma do sistema operacional, a interface web segue o idioma do navegador, e um idioma sem suporte volta para o inglês. Instalar o plugin nunca substitui um idioma que você já escolheu.

Cada pacote tem 3.280 textos: todos os textos da interface do dsh `0.2.0-rc.2` e `0.2.1-rc.2` (chats, barra lateral, configurações, aprovações, agendamentos, prévias de arquivos, gerenciador de plugins, mercado de plugins), os controles do próprio plugin e o popular plugin [dsh-rewind](https://github.com/SiriLee/dsh-rewind). Não são traduzidos: suas mensagens, a saída do modelo, o código, os nomes dos comandos de barra (`/plan`, `/compact`), rótulos definidos pelo provedor, como o esforço de raciocínio `High`, os textos de outros plugins e os menus nativos e caixas de diálogo de atualização do app desktop (o dsh só os oferece em inglês e chinês). Textos adicionados por uma versão mais nova do dsh aparecem em inglês até que os pacotes sejam atualizados. Se outro plugin já fornece um idioma, esse plugin continua com ele.

## Privacidade e segurança

- **Continuar:** o endpoint local autenticado só retoma o último turno interrompido, rejeita pedidos antigos ou duplicados e mantém os hooks de aprovação existentes. Ele não envia uma nova mensagem do usuário.
- **Retomar após reiniciar:** fica desativado até você ativar. A parte Host guarda só os IDs dos chats e os horários de início em `$DSH_HOME/storages/dsh-composer-plus/resume.json` (acesso só para o dono), e nada sai do seu computador. Ela só continua um chat quando o próprio log do dsh indica que foi o dsh (e não você) que interrompeu o último turno. As aprovações e a Revisão automática valem para o turno retomado, como de costume.

- **Painel de alterações:** o git roda somente leitura no seu computador, na própria pasta do chat, pelo canal `/api` autenticado do dsh. Ele nunca faz commit, stage ou fetch, e só mostra caminhos que o próprio git listou. A árvore lista até 1000 branches locais e remotos e mostra os 300 commits mais recentes de um branch: a linha do primeiro pai, então um commit de merge representa os commits que ele trouxe. Ela nunca troca de branch (checkout). **Este chat** lê o log do próprio chat para achar os arquivos que as ferramentas de arquivo dele gravaram e os compara com o snapshot de Reverter turno do chat em uma pasta temporária que é excluída na hora; ele não grava nada no seu repositório nem no armazenamento de snapshots.
- **Ideias de recursos:** nada é executado até você clicar em **Sugerir recursos**. Então a parte Host lê só a própria pasta do chat (o navegador nunca envia um caminho): os nomes das entradas do nível superior, os primeiros 6 kB do README, do AGENTS.md e do manifesto (`package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, …), um esboço do resto do README (títulos, linhas de tabela, itens de lista; no máximo 6 kB) e os títulos dos commits mais recentes (`git log --format=%s`, no máximo 6 kB), no máximo 28 kB no total. Ela ignora `.env*`, arquivos de chave e pastas como `node_modules`, e só lê arquivos comuns que ficam dentro da pasta: um symlink que aponta para fora da pasta, um FIFO ou um dispositivo é ignorado. Esse resumo vai para o modelo que o chat usa, pelas próprias configurações de provedor do dsh, como uma única solicitação; ele não é adicionado a nenhum chat. Nada no projeto é gravado. Uma ideia deslizada para a direita inicia um novo chat no modo de plano, então as aprovações e a revisão do plano valem como de costume. **Criar agora** inicia o chat sem o modo de plano: o modelo pode alterar arquivos na hora, com as aprovações de costume do chat e a Revisão automática. As ideias salvas para depois (título, resumo, motivo, esforço) ficam guardadas com o caminho da pasta do projeto em `storages/dsh-composer-plus/later.json`, dentro da pasta home do dsh (arquivo só para o dono); nada vai para o projeto. O histórico de ideias sugeridas (título, resumo, motivo, esforço, data, se foi iniciada) fica guardado da mesma forma em `storages/dsh-composer-plus/idea-history.json`, no máximo 200 por projeto (as mais antigas saem primeiro); os títulos dele vão para o modelo no próximo **Sugerir recursos** desse projeto.
- **Pesquisa no conteúdo:** nenhum código novo pesquisa seus chats: o plugin só ativa o índice de mensagens do próprio dsh (SQLite FTS5, `dsh-session-query-sqlite`) e dá a ele um arquivo, `$DSH_HOME/cache/composer-plus/session-search.db` (arquivo e pasta só para o dono). O arquivo guarda o texto das suas mensagens e das mensagens do assistente, então é tão privado quanto os logs de chat em `$DSH_HOME/sessions`. Nada sai do seu computador. Ele é uma cópia que o dsh consegue refazer: você pode excluí-lo enquanto o dsh estiver fechado. A chave fica em `$DSH_HOME/storages/dsh-composer-plus/content-search.json`.
- **Reverter turno:** antes de cada mensagem sua, o Host tira um snapshot git da pasta do chat em um armazenamento próprio, `$DSH_HOME/cache/composer-plus/rollback/<chat>.git` (pasta só para o dono). Ele guarda cópias dos arquivos dessa pasta que o git enxerga (não os arquivos ignorados), então é tão privado quanto o projeto. Ele lê os objetos do seu repositório (sem copiar o que o git já tem) e nunca grava no index, no `HEAD`, nos branches, nas tags, no stash ou na configuração do seu repositório; a única mudança que o git faz ali é atualizar a data e hora dos arquivos de objeto que ele reaproveita (isso adia a limpeza deles pelo `git gc`). Uma reversão com arquivos só grava arquivos comuns dentro da pasta do chat; ela ignora symlinks, pipes e qualquer coisa fora da pasta. Nada sai do seu computador. Você pode excluir o armazenamento enquanto o dsh estiver fechado (aí a reversão só funciona para o chat, até haver novas mensagens). **Excluir chat** também exclui o armazenamento de um chat. A chave fica em `$DSH_HOME/storages/dsh-composer-plus/rollback.json`. Uma reversão com arquivos também guarda os arquivos como estavam logo antes dela (`refs/r/…` no mesmo armazenamento), para **Refazer**; as reversões refeitas ficam listadas em `$DSH_HOME/storages/dsh-composer-plus/redone.json` (acesso só para o dono).
- **Abrir issue no GitHub** (Ideias de recursos → lista **Depois**): só é executado quando você clica. A parte Host executa o seu próprio GitHub CLI (`gh issue create`) na pasta do chat, com o título e o resumo salvos da ideia (e por que ela importa); o `gh` usa o próprio login e o remoto do GitHub da pasta, então a issue vai para esse repositório com a sua conta, e o GitHub a mostra para todos que podem ver esse repositório. O dsh remove dos comandos que inicia as variáveis com nome de token; se você deu um token ao `gh` por `GH_TOKEN` ou `GITHUB_TOKEN`, o plugin passa só essas variáveis ao `gh`. O link da issue fica guardado com a ideia em `later.json`.
- **Relatar uma issue** (Configurações → Composer Plus → **Relatar uma issue…**, ou o menu **…** de um chat → **Relatar uma issue do Composer Plus…**): nada é executado até você clicar. **Escrever rascunho** envia só o tipo e o texto que você digitou (não o chat, não o projeto) para o modelo padrão do dsh, como uma única solicitação. A parte Host adiciona uma linha com as versões do Composer Plus, do dsh e do sistema operacional e troca o caminho da sua pasta home por `~`. **Abrir issue** executa o seu próprio GitHub CLI (`gh issue create --repo furkancak1r/dsh-composer-plus`) com o seu login do `gh`, então a issue é pública e mostra a sua conta do GitHub. Um texto que parece uma chave, um token ou uma senha é recusado e não sai do seu Mac.
- **Chats que alteraram este arquivo** (Alterações, menu "…" de um arquivo): a parte Host lê os registros dos chats cuja pasta está no mesmo repositório, do jeito que o dsh os guarda, e responde com o título de cada chat, o horário e a primeira linha do pedido; ela nunca abre o arquivo em si.
- **Branch do Git nas linhas de chat:** a parte Host executa `git branch --show-current` (somente leitura) na pasta do chat quando um turno começa e quando termina, e guarda só o ID do chat, o nome do branch e o horário em `$DSH_HOME/storages/dsh-composer-plus/session-branches.json` (arquivo só para o dono, os 2000 chats mais recentes). A chave fica em `branches.json`, ao lado dele.
- **Buscar no chat** roda só na página: ele lê o texto que a página mostra e não envia nada.
- **Exportar chat como Markdown:** a parte Host lê só o próprio log do chat (as mesmas mensagens que o dsh mostra) e as entrega à página; ela não lê nenhum arquivo do projeto e não envia nada pela rede. O Markdown vai só para a sua área de transferência ou para o arquivo que você salva.
- **Excluir chat:** move as pastas de log do próprio chat (`$DSH_HOME/sessions/<project>/<chat>`) para o Lixo. A pasta do projeto não é tocada.
- **Permitir neste chat:** as autorizações ficam guardadas, com o horário em que foram dadas, em `$DSH_HOME/storages/dsh-composer-plus/chat-grants.json` (acesso só para o dono). Uma autorização cobre uma ferramenta exata em um chat, até o fim do limite de tempo (1 hora por padrão). Se essa ferramenta pode gravar, a autorização também cobre qualquer gravação. Revogue-a pelo chip no cabeçalho.
- A Revisão automática continua sendo executada em toda chamada; falhas de revisão nunca são permitidas automaticamente.
- **Conexão móvel:** fica desativada até você ativar. Enquanto está ativada, a parte Host executa o gateway do Tether: HTTPS na porta 19390, que só aceita a sua sub-rede Wi-Fi e a sua tailnet (100.64.0.0/10), e uma página de pareamento em `127.0.0.1:19391` (só neste Mac). Um celular precisa de um código de uso único do código QR (válido por 5 minutos) e de você clicar em **Approve** no Mac. O celular fixa o certificado do gateway. O Mac guarda só um hash do token de cada celular (30 dias, renovado enquanto estiver em uso); **Remove** fecha na hora as conexões daquele celular. Os celulares só podem chamar uma lista permitida de métodos do dsh (chats, prompts, anexos, comandos de barra, aprovações, perguntas, modelos, agentes, metas), não configurações, credenciais, o navegador de arquivos ou o terminal. "Tailscale only" recusa toda conexão vinda da rede local, inclusive as que já estão abertas. O registro de acesso guarda as 200 tentativas de conexão mais recentes (horário, endereço IP, nome do aparelho, permitida ou recusada, e o motivo) em `access.json`; ele nunca guarda um token nem um código de pareamento. Dados: `$DSH_HOME/storages/dsh-composer-plus/mobile/` (arquivos só para o dono). Detalhes: [tether/README.md](tether/README.md).
- **Computadores remotos:** o recurso fica desativado até você ativá-lo em cada Mac. **Permitir que outros computadores abram este Mac** abre uma segunda porta HTTPS (19392) só no endereço do Tailscale deste Mac (não no Wi-Fi, e sem anúncio pelo Bonjour). Outro Mac precisa de um link de pareamento de uso único (válido por 5 minutos), do certificado correspondente (fixado) e de você clicar em **Aprovar**. Este Mac guarda só um hash do token dele. Um computador pareado ganha controle total do dsh neste Mac, como se você o usasse aqui: chats, modelos, ferramentas, arquivos e terminal. Remova-o no painel de Configurações, e as conexões dele fecham na hora. O Mac que abre outro guarda o token desse computador em `$DSH_HOME/storages/dsh-composer-plus/computers.json` (só para o dono). Ele abre um relay em `127.0.0.1` para cada computador que você escolhe. A página recebe um link de uso único (válido por 60 segundos), e o relay só aceita a própria página (o endereço dela, nenhum outro site). A página do outro Mac nesta janela pode ler os nomes e os estados dos computadores deste Mac (sem endereço e sem token) e pode trocar esta janela entre eles. Ela não pode adicionar, renomear nem remover um computador, nem mudar as configurações deste Mac.
- **Atualizações:** a parte Host pede a `api.github.com` a versão mais recente e a `registry.npmjs.org` exatamente essa versão; nada sobre você ou seus chats é enviado. A instalação usa o gerenciador de plugins do dsh (`pnpm add dsh-composer-plus@<version>`; quando o dsh 0.2.1 recusa isso para um plugin já instalado, `pnpm add https://registry.npmjs.org/dsh-composer-plus/-/dsh-composer-plus-<version>.tgz`, e o perfil passa a listar essa URL como a origem do plugin), então valem as verificações de registro, de scripts e de compatibilidade de versão do próprio dsh. Tags de pré-lançamento e versões mais antigas nunca são instaladas.
- **Pacote de skill em turco:** ligado por padrão, e só funciona enquanto o idioma do app for Türkçe: o navegador informa à parte Host o idioma da interface do dsh. Então, no máximo uma vez por dia, a parte Host pede a `api.github.com` o commit mais recente de `yucezerey/turkish-anti-ai-skill` e sua lista de arquivos, e baixa de `raw.githubusercontent.com` os arquivos Markdown que mudaram. O GitHub vê seu endereço IP, como em cada verificação de atualizações; nada sobre você ou suas conversas é enviado. Só os arquivos `.md` comuns da pasta `skills/turkish-anti-ai-skill/` ficam (no máximo 20 arquivos e 1 MB), e cada arquivo deve bater com seu id na lista de arquivos do GitHub. A cópia fica em `$DSH_HOME/cache/composer-plus/turkish-skill/<commit>` (só o dono acessa) e entra na lista de skills do dsh; nenhum script do pacote é executado. A chave e o último idioma informado ficam em `$DSH_HOME/storages/dsh-composer-plus/turkish-skill.json`. Desligar remove o skill e apaga a cópia.
- **Contagem de uso:** a parte Host pede ao GitHub dois pequenos arquivos da versão publicada que você tem instalada (`github.com/furkancak1r/dsh-composer-plus/releases/download/v<version>/<file>`): `active.txt` uma vez por dia e `installed.txt` só uma vez para cada dsh home. O GitHub conta esses pedidos por arquivo, então o autor só vê quantas cópias de cada versão pediram `active.txt` naquele dia e quantas cópias pediram `installed.txt` no total (o número de cópias). O pedido não tem id, cookie nem dados sobre você ou seus chats; o GitHub vê seu endereço IP, como em cada verificação de atualização. O dia do último pedido de `active.txt` fica em `$DSH_HOME/storages/dsh-composer-plus/active.json`, e a marca de que `installed.txt` já foi contado fica em `$DSH_HOME/storages/dsh-composer-plus/installed.json`. Uma cópia git deste repositório e uma cópia renomeada não enviam nada. Não há chave para isso.
- **Previsão da próxima mensagem:** vem ativada por padrão; desative-a em **Configurações → Composer Plus** para parar essas chamadas ao modelo. Após cada turno concluído, a parte Host envia as suas próprias mensagens do chat e as respostas em texto do agente (sem saída de ferramentas, sem contexto oculto e sem raciocínio), no máximo cerca de 6.000 caracteres (a parte mais recente), para o modelo escolhido (o padrão do dsh, a menos que você escolha outro). O envio usa as próprias configurações de provedor do dsh, como uma única solicitação. Nada é salvo no chat: o palpite não entra no histórico do chat. A chave e o modelo escolhido ficam em `$DSH_HOME/storages/dsh-composer-plus/predict.json` (arquivo só para o dono).
- **Completar ao digitar:** fica desativado até você ativar. Enquanto está ativado, a cada pausa enquanto você digita, a parte Host envia o texto que você digitou até ali e as suas próprias mensagens do chat e as respostas em texto do agente (sem saída de ferramentas, sem contexto oculto e sem raciocínio), no máximo cerca de 3.000 caracteres do chat, para o modelo escolhido em **Completar ao digitar** (por padrão, o modelo da **Previsão da próxima mensagem**). Uma pausa mais nova interrompe a solicitação anterior. Nada é salvo no chat. A chave fica em `$DSH_HOME/storages/dsh-composer-plus/complete.json` (arquivo só para o dono).
- **Melhorar prompt:** nada é executado até você clicar na varinha mágica. Então a parte Host envia o seu rascunho, as suas próprias mensagens do chat e as respostas em texto do agente (sem saída de ferramentas, sem contexto oculto, sem raciocínio e sem mensagens revertidas; no máximo cerca de 6.000 caracteres, a parte mais recente), o mesmo resumo do projeto usado em **Ideias de recursos** (com as mesmas regras de arquivos: sem `.env*` nem arquivos de chave, sem symlink para fora da pasta, sem FIFO), os caminhos que o `git status` lista como alterados e até 30 caminhos rastreados ou não rastreados (não ignorados) cujos nomes têm palavras em comum com o seu rascunho, para o modelo escolhido em **Melhorar prompt** (por padrão, o próprio modelo do chat), como uma única solicitação. Nenhum outro conteúdo de arquivo além desse resumo é enviado. Nada é gravado no chat nem no projeto: a resposta só substitui o seu rascunho no editor de mensagens, e você decide se vai enviá-lo. O modelo escolhido fica em `$DSH_HOME/storages/dsh-composer-plus/improve.json` (arquivo só para o dono).
- **Verificação da meta:** só é executada quando o agente marca uma `/goal` como concluída em uma rodada automática (ou quando você clica em **Executar agora**). A parte Host executa o comando de teste na pasta do chat, no modo sandbox do chat (como a própria ferramenta `bash` do dsh: a mesma política de acesso a arquivos; quando esse sandbox não consegue iniciar, o teste não é executado e a verificação falha). Para encontrar o comando, ela lê só `package.json`, `Makefile`, `Cargo.toml`, `go.mod`, `pyproject.toml` e `pytest.ini`, como arquivos comuns dentro da pasta (sem symlink para fora dela, sem FIFO). Depois envia a meta, o chat desde o início da meta (as suas mensagens, as respostas do agente, as chamadas de ferramentas cortadas em 1.000 caracteres e os últimos 2.000 caracteres de cada resultado de ferramenta; sem raciocínio e sem passos revertidos; no máximo cerca de 60.000 caracteres, a parte mais recente), o `git status --short` e o fim da saída do teste para o modelo escolhido em **Verificação da meta** (por padrão, o próprio modelo do chat), como uma única solicitação sem ferramentas. A saída das ferramentas pode conter o que o agente leu, então essa solicitação pode ter partes dos seus arquivos, como o próprio chat. Nada é gravado no chat nem no projeto. O seu comando de teste, os limites, o último resultado (com o fim da saída) e o modelo escolhido ficam em `$DSH_HOME/storages/dsh-composer-plus/goal-check.json` (arquivo só para o dono, os 500 chats mais recentes).
- **Continuar em um novo chat:** nada é executado até você clicar. Então a parte Host envia o chat (como a Verificação da meta o lê: sem raciocínio e sem passos revertidos) para o próprio modelo do chat e mostra a nota de passagem; só **Iniciar novo chat** cria um novo chat. Nada é gravado no projeto.
- **Detalhamento do contexto:** a parte Host lê só o log do chat; nenhuma chamada ao modelo, nenhum arquivo do projeto.
- **Quadro de tarefas:** o quadro mostra os próprios chats do dsh, a partir das próprias listas do dsh nesta janela; ele não adiciona dados de chat próprios. **Nova tarefa** abre o próprio novo chat do dsh, e você escreve a primeira mensagem no editor de mensagens do dsh, então as aprovações, o sandbox e o modelo do chat valem como de costume. A parte Host guarda a primeira mensagem desse chat como o prompt do cartão e a envia (os primeiros 4.000 caracteres dela, nada mais) ao modelo desse chat em mais uma solicitação, sem ferramentas, para obter até 3 etiquetas. O prompt, as etiquetas e a hora de início de cada tarefa ficam em `$DSH_HOME/storages/dsh-composer-plus/board-chats.json` (arquivo só para o dono, as 2.000 mais recentes), junto com os IDs dos chats que você tirou do quadro com **×** ou **Limpar tudo** (os 5.000 mais recentes); a chave fica em `board-switch.json`, ao lado. Nada é gravado em uma pasta de projeto. **Responder** envia a sua resposta para a solicitação pendente do próprio dsh, do mesmo jeito que o cartão do próprio chat. A lista de tarefas antiga das versões anteriores (`board.json`) fica no disco como estava e não é lida. **Progresso ao passar o cursor** lê o registro do chat neste Mac. Com **Rápido (sem IA)** (o padrão), nada é enviado. Com **Resumo com IA**, enquanto a caixa de progresso de um cartão em andamento aparece (ou enquanto o quadro do Tether está aberto, para até 8 cartões em andamento), a parte Host envia a parte mais recente desse chat (no máximo cerca de 6.000 caracteres: suas mensagens, as respostas em texto do agente, as chamadas de ferramentas e o fim dos resultados delas; sem raciocínio e sem mensagens revertidas) ao modelo do chat, em uma única solicitação sem ferramentas. Ela só envia de novo depois que o chat avançou, no máximo uma vez a cada 20 segundos por chat. A nota fica só na memória; a configuração fica em `$DSH_HOME/storages/dsh-composer-plus/board-progress.json` (arquivo só para o dono).
- **Assistente:** o chat do assistente é um chat comum do dsh em `~/Assistant`; as chamadas de modelo dele vão para o modelo padrão do dsh, como em qualquer chat. As ferramentas dele leem os registros dos seus outros chats neste Mac (títulos, projetos, status e, com chat_read, as mensagens mais recentes) e os passam a esse modelo só quando ele chama uma ferramenta. Enviar, iniciar, parar e arquivar um chat esperam, cada um, a sua aprovação. O ID do chat fica em `$DSH_HOME/storages/dsh-composer-plus/assistant.json` e a chave em `assistant-switch.json` (arquivos só para o dono). Lembretes e automações são as próprias tarefas agendadas do dsh. Nada sai deste Mac, exceto as solicitações ao modelo e as pesquisas na web que o chat faz. As chaves do assistente como bot guardam o estado em `assistant-free.json` e `assistant-notify.json` (arquivos só para o dono). **Avisos de chats no Assistente** coloca no chat do assistente uma linha curta sobre outro chat (o título, o projeto e no máximo 300 caracteres da última resposta ou do último erro dele), então esse texto também vai para o modelo do assistente; os avisos esperam só na memória.
- **Arquivos protegidos:** a lista e a chave ficam em `$DSH_HOME/storages/dsh-composer-plus/protected-files.json` (arquivo só para o dono). A verificação lê só o caminho de cada chamada de ferramenta de arquivo (e o caminho real dele), nunca o arquivo.
- **Comandos bloqueados:** as regras e a chave ficam em `$DSH_HOME/storages/dsh-composer-plus/blocked-commands.json` (arquivo só para o dono). A verificação lê só o texto do comando de cada chamada de `bash` e `pwsh`; não executa nada e não envia nada.
- **Entrada secreta:** o valor vai do cartão (ou do Tether, pelo gateway, que não registra o corpo das solicitações) para o Host só na solicitação de resposta. O Host o grava em `$DSH_HOME/storages/dsh-composer-plus/secrets/<nome aleatório>` (pasta 0700, arquivo 0600); nada vai para o projeto, o registro do chat ou o resultado da ferramenta. O Host mantém o valor na memória para substituí-lo por `[secret]` nos resultados de ferramenta posteriores desse chat. O arquivo e essa cópia são apagados quando o turno do chat termina e quando o dsh inicia. A chave fica em `secrets.json`, ao lado. Um comando que o agente executa com o arquivo pode enviar o valor para onde esse comando envia: esse é o propósito.
- **Memória do projeto:** desativada até você ativar. Enquanto está ativada, depois de cada turno concluído de um chat de nível superior, a parte Host envia as mensagens novas do próprio chat desde a última revisão (suas mensagens e as respostas de texto do agente; sem saída de ferramentas, sem raciocínio, sem contexto oculto, sem mensagens revertidas; a cópia do chat pai num chat ramificado fica de fora; no máximo cerca de 16.000 caracteres) e as notas salvas para o modelo do próprio chat, como uma única solicitação sem ferramentas. As notas são arquivos Markdown em `$DSH_HOME/storages/dsh-composer-plus/memory/` (arquivos só do proprietário): `projects/<id>/` para cada pasta de projeto (`<id>` é um hash do caminho real da pasta; `project.json` nomeia a pasta), `global/`, `journal.jsonl` (cada mudança com a linha antes e depois) e `reviewed.json` (até onde cada chat foi lido). Nada é escrito na pasta do projeto. Notas que parecem uma chave, um token, uma senha ou um número de documento são recusadas. As notas de um projeto entram no prompt de sistema de cada chat novo nessa pasta, então chegam ao modelo com cada solicitação desse chat. A chave fica em `memory.json`, na mesma pasta. **Abrir memória** não envia nada até você tocar em **Ver prévia das mudanças**; então envia as notas que mostra e o seu texto ao modelo padrão do dsh, em uma única solicitação sem ferramentas. As mudanças só são gravadas em **Aplicar**, com `editor` no registro. O Tether lê e muda as notas pela mesma rota. **Histórico de versões da memória** (ativado por padrão) guarda uma cópia dos arquivos da memória antes de cada gravação em `memory/history/`, ao lado deles (arquivos só do dono, as 50 mais recentes por memória); não envia nada a nenhum modelo. **Exportar a memória para AGENTS.md** não envia nada a nenhum modelo e só grava quando você clica em **Gravar AGENTS.md**: lê e grava `AGENTS.md` na pasta do projeto dessa memória (só um arquivo comum dentro dela, nunca por um link simbólico que saia dela) e só muda a seção marcada. **Encontrar notas de memória desatualizadas** não envia nada a nenhum modelo e não grava nada: verifica os caminhos dentro da pasta do projeto com realpath (nenhum arquivo é lido), lê `package.json` só como arquivo comum dentro da pasta e roda ali um `git for-each-ref`. **Não usar a memória neste chat** guarda cada chat que você desativa em `memory-chats.json`, ao lado dos outros arquivos (só do dono, os 500 mais recentes); esse chat não envia nenhuma memória ao modelo. **Sugerir notas de memória a partir de um chat** não envia nada até você clicar em **Sugerir para a memória**; então envia as notas salvas do projeto do chat e as notas globais, e as mensagens e respostas de texto do próprio chat (sem saída de ferramentas nem mensagens revertidas; a cópia do pai num fork fica de fora; no máximo cerca de 24.000 caracteres), ao próprio modelo do chat, como um pedido sem ferramentas. Uma sugestão só é salva com **Aceitar**.
- **Backup:** nada sai do seu computador. Os arquivos compactados vão para `~/Desktop/dsh-backups` (arquivos só para o dono). Os segredos não ficam no arquivo compactado: arquivos de credenciais (`.credentials.yaml`, `.env`), arquivos de chave (`.pem`, `.key`, `.p12`, `.pfx`) e os valores das configurações token, secret, password e API key nos arquivos yml são mascarados; as cópias reais ficam em `composer-plus-vault/<archive>/`, na mesma pasta (só para o dono), só neste computador. **Para outro computador** não copia nenhum vault: informe esses segredos de novo lá. Os seus logs de chat, as suas configurações e o resto do dsh home ficam no arquivo compactado como estão: mantenha a pasta privada, como o próprio `$DSH_HOME`. O backup lê os arquivos com `O_NOFOLLOW | O_NONBLOCK`; um symlink é guardado como link (nunca é seguido) e um FIFO ou dispositivo é ignorado. A chave e as opções do backup automático ficam em `$DSH_HOME/storages/dsh-composer-plus/auto-backup.json`, a chave do console de resgate em `rescue-console.json` e, enquanto o dsh está em execução, `running/host-<pid>.json` identifica cada processo do dsh (o console de resgate os lê para recusar uma restauração).
- **Console de resgate:** um menu de terminal; ele não abre nenhuma porta de rede. Uma restauração grava só em uma pasta nova ao lado do dsh home (arquivos com `O_EXCL | O_NOFOLLOW`, symlinks por último e nunca seguidos) e recusa um arquivo compactado com um nome inseguro (`..`, um caminho absoluto), um dispositivo ou FIFO, mais de uma pasta de nível superior ou uma entrada abaixo de um link.

## Solução de problemas

- **Sem notificações no macOS:** Ajustes do Sistema → Notificações → DeepSeek Harness → permita. Escolha Alertas para que elas fiquem na tela.
- **▶, as alças da fila, o status do projeto, a opção de projetos recentes, Recolher todos os projetos, Copiar caminho, a caixa de busca de projetos, a previsão da próxima mensagem, o complemento ao digitar, Permitir neste chat ou o clique com o botão direito sumiram depois de uma atualização do dsh:** esses recursos se prendem ao HTML atual do dsh, porque o dsh ainda não tem um espaço para eles. Se o dsh mudar essa marcação, eles se escondem sozinhos; nada mais quebra. Abra uma [issue](https://github.com/furkancak1r/dsh-composer-plus/issues).
- **"Falha na atualização" ou "não foi instalada pelo npm":** uma cópia vinculada a partir de uma pasta local ou renomeada não consegue se atualizar sozinha; reinstale `dsh-composer-plus` em Configurações → Plugins. Nos outros casos, a mensagem mostra a primeira linha do erro do pnpm; **Verificar atualizações** tenta de novo.
- **A Conexão móvel diz que o gateway não está em execução:** "no IPv4 address on en0" significa que este Mac não tem endereço de Wi-Fi/Ethernet; "EADDRINUSE" significa que outro dsh (ou outro app) usa a porta 19390 ou 19391. Só um dsh pode executar a Conexão móvel por vez.
- **Conexão móvel, Retomar após reiniciar ou Pesquisa no conteúdo diz "Reinicie o dsh":** o plugin foi atualizado enquanto o dsh estava em execução (ou, no caso da Pesquisa no conteúdo, você mudou a chave); o novo estado é carregado depois de reiniciar.
- **A pesquisa só encontra títulos:** a Pesquisa no conteúdo está desativada, o dsh não foi reiniciado desde que você a ativou ou instalou o plugin, ou a palavra só aparece na saída de uma ferramenta (veja Limites).
- **Não há botão ↶ nas minhas mensagens:** Reverter turno está desativado, o chat é um chat de subagente, ou o dsh-rewind-plugin está instalado (use o botão ↶ dele). Depois de uma atualização, reinicie o dsh.
- **Chat e arquivos está acinzentado:** o projeto não é um repositório git, não há snapshot de antes daquela mensagem (a mensagem é mais antiga que o plugin, ou um dos 50 snapshots mais novos a substituiu), ou nenhum arquivo mudou.
- **Excluir diz que outro dsh está com este chat aberto:** um segundo dsh no mesmo dsh home está com o bloqueio do chat. Feche essa janela ou esse dsh e exclua de novo. Enquanto isso, o chat continua arquivado.
- **Meu iPhone não consegue se conectar depois que ativei "Tailscale only":** o Tailscale precisa estar ativado no Mac e no iPhone. O painel da Conexão móvel avisa quando ele está desativado no Mac. O registro de acesso mostra cada tentativa recusada com o motivo.
- **Um chat não continuou depois de reiniciar:** Retomar após reiniciar estava desativado quando o dsh fechou, você mesmo interrompeu aquele turno, o turno já tinha terminado (concluído ou com falha), o chat foi arquivado, ou mais de 20 chats estavam em execução (os 20 mais novos continuam).
- **A fila está vazia depois de reiniciar:** o próprio dsh esvazia a fila quando fecha. Retomar após reiniciar só a devolve em um chat que continua; nos outros chats, envie as mensagens de novo. Uma mensagem que você removeu logo antes do fechamento pode voltar: remova-a de novo.
- **Abrir issue no GitHub diz "gh could not open the issue":** a mensagem é a primeira linha do próprio `gh`. Execute `gh auth status` em um terminal e faça login com `gh auth login`; a pasta do chat precisa ter um remoto do GitHub (`git remote -v`). "not installed or not on the PATH of dsh" significa que o dsh não encontrou o `gh`: instale-o ou inicie o dsh a partir de um terminal em que o `gh` funcione.
- **Relatar uma issue diz "gh could not open the issue":** a mensagem é a primeira linha do próprio `gh`. Execute `gh auth status` em um terminal e faça login com `gh auth login`. Ou clique em **Abrir no GitHub em vez disso**: a própria página de nova issue do GitHub abre com o rascunho preenchido, e você a envia lá.
- **Nenhuma etiqueta de branch em uma linha de chat:** a barra lateral não está em “Em uma única lista” (em “Workspace” e “Árvore de workspaces”, nenhuma linha de chat mostra uma etiqueta), o chat não teve nenhum turno desde que você instalou esta versão, a pasta dele não é um repositório git, ou **Branch do Git nas linhas de chat** está desativado. Depois de uma atualização, reinicie o dsh (a parte Host registra o branch).
- **Verificação da meta diz que o teste saiu com o código 127 ou "not found":** o dsh iniciado pelo Finder ou pelo Dock pode ter um PATH mais curto que o do seu terminal, então ele não encontra `npm`, `pnpm` ou `cargo`. Inicie o dsh a partir de um terminal ou defina o seu próprio comando de teste com o caminho completo em **Verificação da meta** → **Editar**. **Executar agora** mostra o resultado na hora.
- **A meta não fecha e o agente continua trabalhando:** **Verificação da meta** encontrou um teste com falha ou trabalho faltando; a linha abaixo da meta mostra o motivo (passe o mouse sobre o resultado para ver os detalhes). Corrija a causa ou o comando de teste, ou conclua a meta você mesmo com `/goal` ou com a barra da meta (isso não é verificado).
- **A instalação falha logo depois de uma nova versão:** informe a versão (`dsh-composer-plus@1.27.0`); veja a nota de instalação acima.
- **Fazer backup agora diz "Outra ação de backup está em andamento":** uma ação está em execução em outra janela do dsh ou no console de resgate (eles compartilham um arquivo de bloqueio, `.composer-plus.lock`, na pasta de backups). Aguarde até ela terminar. Se nenhuma ação estiver em execução, o próximo clique assume o bloqueio de um processo encerrado.
- **O console de resgate diz "dsh is running":** feche o dsh primeiro. Se o dsh estiver mesmo fechado, o arquivo citado na mensagem sobrou de uma falha: remova-o e tente de novo.
- **Depois de uma restauração, o dsh não inicia ou falta um plugin:** os pacotes de plugin de um perfil precisam ser instalados de novo. O console de resgate oferece isso depois de uma restauração; ou execute `pnpm install` em cada pasta de `$DSH_HOME/profiles/` que ele listar. Os segredos que não estavam no vault (outro computador) precisam ser informados de novo: o console os lista.

## Limites

- O Continuar sem mensagem depende do ciclo de vida `agent/pre-step` → `agent/request` do dsh. Verifique de novo a compatibilidade ao atualizar o dsh.
- **Ideias de recursos** guarda os cartões na memória para cada chat até o dsh ou a página recarregar; depois disso, **Sugerir recursos** pergunta ao modelo de novo. Os cartões vêm no idioma que a interface do dsh tem quando você clica; depois que você muda o idioma, os cartões que já estão na pilha mantêm o idioma deles e **Mais ideias** usa o novo. O modelo vê só o breve resumo do projeto, não o código, então uma ideia pode repetir algo que o projeto já tem: pule essa ideia. O novo chat só roda no modo de plano quando o perfil tem o comando `/plan` do dsh; caso contrário, a ideia vai como uma primeira mensagem comum. A lista **Depois** pertence ao caminho da pasta do chat: a mesma pasta aberta por um symlink tem sua própria lista. Ela guarda no máximo 50 ideias por projeto (remova uma para adicionar mais) e cada título só uma vez. Arrastar um cartão só decide entre esquerda e direita; use **↓** para salvá-lo e **▶** para criá-lo agora. Uma repetição é reconhecida só pelo título: o modelo ainda pode sugerir uma ideia anterior com outro nome; pule essa ideia. Quando o modelo responde só com ideias anteriores, nada novo aparece: clique de novo. Um tema de foco estreito torna isso mais provável; use um tema mais amplo ou limpe o tema. O tema de foco fica no campo para cada chat até o dsh ou a página recarregar.
- **Exportar chat como Markdown** tem só as suas próprias mensagens e as respostas em texto do assistente: chamadas de ferramentas e a saída delas, raciocínio, imagens (uma linha `[image]` as marca), contexto oculto e mensagens que o Reverter turno ou o dsh-rewind-plugin removeu ficam de fora. As respostas de um turno se juntam em uma única seção. No máximo cerca de 4 milhões de caracteres entram em uma exportação; um chat mais longo recebe a primeira parte e uma nota.
- **Retomar após reiniciar** continua o turno; ele não o repete. Uma chamada de ferramenta que estava em execução no momento do fechamento termina com o resultado “desfecho desconhecido” do dsh, e o modelo é instruído a não repetir trabalho já feito, mas um comando que não é seguro executar duas vezes pode ser executado de novo. Subagentes, aprovações e perguntas que estavam abertos não são restaurados: o chat pai continua e pergunta de novo. No máximo 20 chats continuam em uma inicialização.
- **Retomar após reiniciar** e a fila: o dsh esvazia a fila de um chat quando fecha. O plugin devolve suas mensagens da fila a partir do registro do chat, com a ordem, as edições, as imagens e os arquivos; elas rodam depois do turno retomado. Só os chats que continuam recebem a fila de volta (chave ligada e fechamento durante o turno). O dsh registra do mesmo jeito quando você mesmo remove as últimas mensagens da fila: se você as remover e o dsh fechar antes de o próximo passo começar, elas voltam.

- **Pesquisa no conteúdo** é a pesquisa do próprio dsh, então tem os limites do dsh. Ela só pesquisa mensagens do usuário e do assistente: não a saída das ferramentas (comandos, conteúdo de arquivos, resultados), não o raciocínio, e não tem filtro para mensagens do usuário, do assistente ou de ferramentas. Ela encontra palavras inteiras, não partes de uma palavra (`deploy` não encontra `deployment`); letras com acento correspondem às mesmas letras sem acento (`seker` encontra `şeker`). Uma linha por chat, com o trecho de 240 caracteres do dsh, no máximo 20 linhas.
- Custo da **Pesquisa no conteúdo**, medido em uma cópia de 247 logs de chat reais (159 MB, dsh 0.2.1-rc.2, Apple Silicon, 32 GB): a primeira pesquisa depois de iniciar cria o índice em cerca de 15 s. Durante esse tempo, o Host do dsh não responde a nada por cerca de 7 s, então os outros chats param de transmitir nesse momento (a página em si não trava). A memória do Host cresce cerca de 1,1 GB no pico; um minuto depois, ela ainda fica cerca de 0,5–0,6 GB acima do início, até o dsh fechar. O arquivo de índice tem cerca de 165 MB. As pesquisas seguintes levam cerca de 0,5 s. Depois de reiniciar, a primeira pesquisa leva cerca de 1 s (só os chats novos ou alterados são adicionados) e adiciona cerca de 70 MB. Desative o recurso se o seu computador tiver pouca memória.
- **Pesquisa no conteúdo** só vale depois de reiniciar o dsh, e o arquivo de índice é compartilhado por todo dsh que usa o mesmo dsh home: execute só um desses dsh por vez (o dsh permite um único dono por arquivo de índice).
- **Reverter turno** só restaura arquivos em um repositório git, e só na pasta do chat. Ele guarda os 50 snapshots mais novos por chat. Arquivos ignorados (`.gitignore`, `info/exclude`, seu arquivo global de ignore), pastas vazias, symlinks e submódulos não são restaurados; um arquivo que estava ignorado quando o snapshot foi feito nunca é excluído, mesmo quando o turno mudou as regras de ignore. Um arquivo que o git não consegue ler fica fora do snapshot. Cada mensagem sua executa um `git add --all` da pasta do chat no armazenamento privado: em uma pasta muito grande, com muitos arquivos não rastreados, isso pode levar alguns segundos, e a próxima chamada de ferramenta espera por ele (no máximo 10 s; depois disso, o snapshot termina em segundo plano). Se o `git gc` do seu repositório remover um objeto de que um snapshot antigo precisa, esse arquivo aparece na lista como não restaurado. Só o texto da mensagem volta para o editor de mensagens: adicione de novo as imagens ou os arquivos dela. Chats de subagente não têm ↶ (as alterações de arquivos de um subagente contam como alterações do chat que o iniciou). O chat exportado (`/export`) ainda contém as mensagens removidas. A ideia de um marcador oculto que remove parte de um chat vem do [dsh-rewind-plugin](https://github.com/SiriLee/dsh-rewind), de SiriLee (MIT); o Composer Plus não usa nenhum código dele.
- **Excluir chat** precisa do arquivamento do dsh (dsh 0.2.0 ou mais recente). Um chat (ou um dos chats de subagente dele) que não para em 15 s, ou que outro dsh está usando, continua arquivado, e nada é movido. Em sistemas que não são o macOS, a pasta de lixo precisa estar no mesmo disco que o histórico de chats. Um chat aberto que você exclui fica na memória do dsh, arquivado e oculto, até o dsh reiniciar. Esvazie o Lixo você mesmo; o dsh não faz isso.
- A fila do dsh não tem uma ação `move`, então a parte Host do plugin move a própria mensagem na fila do dsh (uma única alteração, a mesma mensagem). Mensagens com imagens ou arquivos também são movidas. Só as suas próprias mensagens são movidas: uma rodada de meta ou uma resposta a uma pergunta na fila fica onde está. Se uma mensagem começar a ser enviada enquanto você arrasta, nada é movido e um aviso informa isso.
- O dsh 0.2.1 carrega uma atualização imediatamente quando a nova versão não muda nenhuma configuração do dsh; caso contrário, e no dsh 0.2.0, reinicie o dsh para carregá-la. O plugin nunca reinicia o dsh por você. Perfis web/CLI sem o gerenciador de plugins do dsh só avisam que há uma nova versão.
- **Novidades do Composer Plus N** mostra as notas no idioma de **Idioma do aplicativo**. Um idioma da interface com outra região recebe as notas do seu idioma base (`en-GB` recebe as notas em inglês, e `zh-TW`, as notas em chinês de `zh`). Um idioma sem notas (um que outro pacote de idioma adiciona, ou `pt-PT`, que não é `pt-BR`) mostra as notas em inglês. As notas vêm com a nova versão. Se a cópia em execução não tiver um arquivo de notas legível (`release-notes.json`), a janela mostra as notas em inglês do GitHub.
- Uma versão instalada enquanto o dsh está em execução (uma atualização por Configurações → Plugins ou por uma pasta copiada) só carrega depois de reiniciar o dsh: até lá, **Atualizações do Composer Plus** mostra a versão em execução e pede para reiniciar. A janela **Novidades do Composer Plus N** dessa versão aparece uma vez na primeira inicialização dela. A primeira inicialização depois de instalar este plugin não mostra janela; **Novidades desta versão** abre as notas da versão em execução.
- A linha da estrela do GitHub abaixo das notas não sabe se você já deu uma estrela ao repositório: o plugin não faz nenhuma chamada de rede para isso. Cada navegador (e o app para desktop) guarda seu próprio registro, então a linha pode aparecer mais uma vez em outro.
- **Rejeitar com nota** envia a nota como uma mensagem no turno que espera e depois rejeita a solicitação; o dsh mostra a nota no chat como uma mensagem sua. Enquanto o campo da nota está aberto, o cartão mostra só **Cancelar** e **Rejeitar**, então um clique não pode permitir a solicitação por engano; `Esc` ou **Cancelar** traz de volta os botões do dsh. Uma nota vazia não envia nada (use o próprio **Rejeitar** do dsh). Se a rejeição falhar depois que a nota foi enviada (por exemplo, a solicitação foi respondida em outro lugar nesse meio-tempo), a nota fica no chat e o modelo a lê no próximo passo dele. O botão fica na marcação do cartão de aprovação do dsh (`data-approval-key`), porque o dsh não tem um espaço para ações do cartão; se uma atualização do dsh mudar essa marcação, o botão não aparece e o próprio **Rejeitar** do dsh funciona como antes. Uma nota pode ter no máximo 4.000 caracteres.
- **Entrada secreta** esconde só o texto exato de um valor: `[secret]` o substitui nos resultados de ferramenta posteriores do mesmo chat. O agente ainda pode ler o arquivo com um comando de shell e imprimir o valor de outra forma (base64, uma parte, com espaços), e essa forma chega ao modelo. As ferramentas de arquivo do próprio agente (read, grep, write, edit) não conseguem abrir a pasta de segredos. Se o valor também for uma palavra comum, outros resultados desse chat também mostram `[secret]`. O arquivo fica até o turno terminar; se o dsh fechar durante o turno, a próxima inicialização o apaga. Um chat pode ter um só pedido aberto por vez. A ferramenta adiciona cerca de 870 caracteres (cerca de 220 tokens, estimado) a cada solicitação ao modelo: desative-a quando não a usar.
- **Citar na resposta** cita o texto como a página o mostra: um bloco de código, uma tabela ou uma lista vêm como linhas simples, sem as marcas de Markdown. Uma seleção que começa em uma resposta e termina em outra, ou que toca o raciocínio, uma linha de ferramenta ou sua própria mensagem, não mostra o botão: selecione dentro de uma só resposta. O botão encontra a resposta pela estrutura do chat do dsh, porque o dsh não tem um slot para seleção de texto; se uma atualização do dsh mudar essa estrutura, o botão não aparece. Quando a citação fica no fim do campo, mais uma linha vazia entra depois dela para que a próxima linha digitada comece abaixo; o dsh remove as linhas vazias do fim ao enviar.
- **Citar da prévia do arquivo** lê a própria prévia de arquivos do dsh: os números de linha vêm das linhas da prévia, então estão certos para arquivos de código e de texto. Um arquivo Markdown aparece como uma página formatada, então a citação dele tem o texto sem as marcas de Markdown e sem números de linha; uma citação de PDF tem a página, não uma linha. Uma seleção no cabeçalho do caminho, em outro visualizador (uma planilha, um arquivo do Office, uma imagem) ou sobre dois arquivos abertos não mostra o botão, e a barra lateral direita em tela cheia também não (nesse caso o campo de texto não está na tela). O botão encontra a prévia pela estrutura da página do dsh, porque o dsh não tem um slot para uma seleção ali; se uma atualização do dsh mudar essa estrutura, o botão não aparece. Só o texto selecionado vai para o campo de texto: se o arquivo mudar depois, a citação não muda.
- **Chat paralelo** é somente leitura pelo próprio modo somente leitura do dsh: as ferramentas de arquivo não podem escrever e os comandos de shell rodam no sandbox do dsh sem escrita (ou não rodam quando o sandbox não consegue iniciar). O agente ainda pode pedir mais acesso com o cartão de aprovação do dsh, e uma chamada de rede (por exemplo, uma requisição a uma API) ainda pode mudar algo fora do computador. A cópia é feita no momento mais recente em que nenhuma mensagem esperava na fila, então uma pergunta feita enquanto há mensagens na fila não vê o que aconteceu depois delas. Uma etapa do chat em andamento é fechada na cópia, então o chat paralelo conhece o início dessa etapa, mas não o resultado. O chat paralelo é um chat comum: fica na barra lateral e conta no seu uso do modelo; arquive-o lá. Trazer de volta pega só as mensagens do próprio chat paralelo (no máximo 12.000 caracteres) e só a última resposta de cada pergunta; as notas do agente entre as chamadas de ferramenta ficam de fora. O dsh não oferece aos plugins um espaço para um chat dentro da barra lateral direita, então o chat paralelo abre na visão principal.
- **Notas no diff** funciona só no painel de alterações, não na visão Último turno do dsh. Um intervalo deve ficar em um só bloco do diff (uma parte `@@`). As notas ficam no armazenamento deste navegador, então outro navegador ou o dsh em outro computador não as vê; o Tether guarda as próprias notas na memória. Uma nota guarda as linhas como estavam no clique: se o agente mudar o arquivo depois, a nota ainda mostra as linhas e os números antigos. No máximo 50 notas por chat, 2.000 caracteres por nota e 40 linhas por nota (depois uma linha `…`).
- **Permitir neste chat** conta o limite de tempo a partir do momento da autorização. Um novo limite de tempo vale na hora para as autorizações em vigor, então um limite menor pode encerrá-las na hora. As autorizações da versão 1.12 e anteriores não têm horário: depois da atualização, o agente pergunta mais uma vez sobre essas ferramentas.
- **Manter o foco no editor** só devolve o foco depois de um comando `/` ou de uma skill. Enquanto o dsh resolve o comando, o editor de mensagens fica somente leitura por alguns milissegundos, então as teclas pressionadas nesse tempo se perdem. Se o menu `/` do dsh ainda estiver aberto, `Enter` escolhe a linha destacada e não envia.
- **Ajustar o cartão de pergunta à janela** muda só o cartão de pergunta do dsh, não o cartão de revisão do plano. Ele encontra o cartão pela marcação do dsh (`data-question-key`, `data-question-scroll`); se uma atualização do dsh mudar essa marcação, o cartão aparece como o dsh o desenha. A altura do cartão segue a janela, não o chat: em um chat dentro de um painel lateral estreito, um cartão alto ainda pode passar do topo do chat.
- **Ajustar o cabeçalho do chat à janela** encontra o cabeçalho do chat do dsh pelos nomes de classe gerados (`_titleRow`, `_titleCluster`, `_crumbs`, `_headerActions`, `_headerUtilities`), porque o dsh não oferece um ponto de extensão para o layout dele. Se uma atualização do dsh mudar esses nomes, o cabeçalho aparece como o dsh o desenha. Em uma coluna de chat muito estreita o cabeçalho pode ocupar duas ou três linhas, então sobra menos espaço acima das mensagens.
- **Subagentes em execução no cabeçalho do chat** só muda o texto do próprio contador do dsh. Ele conta os subagentes diretos do chat (a mesma contagem do dsh), não os subagentes de um subagente. O dsh desenha a lista aberta sem um lugar para plugins, então a linha do total fica acima da estrutura da lista do dsh (`role="tree"`). Se uma atualização do dsh mudar essa estrutura, a lista não terá a linha do total e o cabeçalho continuará mostrando os que estão em execução.
- **Conexão móvel** só funciona no macOS (ela usa `en0`, `openssl`, `swift` e `dns-sd`). Ela usa as portas fixas 19390 e 19391, então só um dsh em cada Mac pode executá-la por vez (cada Mac é uma entrada na lista de Macs do celular). Com uma chave APNs em `apns.json` (veja `tether/README.md`), o Mac envia as notificações pelo serviço de push da Apple, então elas chegam também com o Tether fechado; o Mac precisa estar ativo e com o dsh aberto. Sem a chave, o celular só as recebe enquanto o Tether está aberto ou acabou de ir para segundo plano. O Tether só as envia depois que você ativa "Settings → Notifications → Send notifications" no Tether. O Tether guarda essa opção e o horário dela separadamente para cada Mac pareado. Ela vem desativada por padrão em cada Mac, e o iOS pede a permissão quando você a ativa. O app iOS ainda não está na App Store: compile-o a partir de `tether/ios` com o Xcode. "Tailscale only" ainda precisa de um endereço de Wi-Fi ou Ethernet no Mac (o gateway só inicia com um). O registro de acesso é de cada Mac e guarda só as 200 tentativas mais recentes; uma tentativa repetida em até um minuto soma um na mesma linha. Cada notificação mostra o Mac e o projeto do chat (`Studio Mac · recipe-box`), o título do chat e o texto: Turn finished mostra a última resposta do agente. Com a chave do APNs, esse texto passa pelo serviço de push da Apple. O bloqueio do app Tether não oculta as prévias das notificações na Tela Bloqueada do iPhone: desative-as nos Ajustes do iOS. Os pontos verdes do Tether seguem o Mac: um chat que você abre no dsh também perde o ponto no celular. Um chat que você abre no Tether também perde o ponto no dsh, em cerca de 3 segundos enquanto uma janela do dsh estiver aberta, então o celular e o dsh mostram o mesmo número. Para isso, a janela do dsh muda a lista de não lidos do dsh pela mesma parte do dsh que **Marcar tudo como lido** usa (não é uma API pública). Um chat arquivado não tem ponto no celular, como no dsh. Um Mac cujo Composer Plus não tem essa lista (uma versão mais antiga) não mostra pontos verdes no Tether.
- **Computadores remotos** precisa do Tailscale nos dois Macs, e do Composer Plus com este recurso ativado no Mac que você abre. Esse Mac não pode estar em repouso, e o dsh precisa estar em execução nele. O seletor só aparece quando a barra lateral esquerda está aberta (não quando ela mostra só ícones). Se a página do outro Mac não tiver um seletor próprio (Composer Plus anterior à 1.23.0 nele), o seletor deste Mac aparece sobre essa página, no mesmo lugar. Com a 1.23.0 ou posterior nele, a página desse Mac mostra o seletor da própria versão do Composer Plus dele (uma versão anterior mostra um só botão, não as duas partes). Cada computador que você abriu mantém a página dele na memória até você desativar o recurso ou reiniciar o dsh. Se o computador não respondeu (estava em repouso ou o Tailscale estava desligado), a página dele não é mantida: escolha-o de novo e ela carrega outra vez. No app para desktop, a página do outro Mac é uma página incorporada: os atalhos de teclado do próprio dsh (por exemplo, um novo chat) não funcionam nela, e downloads de arquivos, microfone e notificações também não funcionam ali. No macOS, essa página ocupa a janela inteira e desenha a própria linha de barra de título, como a página deste Mac; para mover a janela, arraste a área ao lado dos botões de semáforo. Ele usa a porta 19392 (só um dsh em cada Mac pode deixar outros computadores entrarem). Na página de outro Mac, o seletor só troca entre os computadores deste Mac: você não pode abrir um terceiro Mac por meio do outro Mac. As duas partes contam só os computadores pareados e acessíveis (um computador que precisa ser pareado de novo não conta); com um só computador assim, **Adicionar um computador…** fica no menu do clique com o botão direito (em tela sensível ao toque: toque e segure) ou em **Configurações → Composer Plus → Computadores remotos**.
- Um link de sessão funciona dentro dos chats; clicar nele não abre o chat. Um link criado com **Copiar link da mensagem** só abre a mensagem no dsh 0.2.1 ou mais recente, e só a partir de uma mensagem em um chat (o dsh 0.2.0 não tem regras de texto do usuário, então ali o link é copiado, mas aparece como texto simples). Uma mensagem que uma reversão removeu, ou que a compactação tirou do histórico que o dsh carrega, não pode ser mostrada: o link avisa isso. Os botões 🔗 se prendem às linhas de mensagem do dsh; se uma atualização do dsh mudar essa marcação, eles não aparecem.
- **Marcar tudo como lido** muda os pontos de não lido do próprio dsh por uma parte do dsh que não é uma API pública (a lista `completionUnread` do status de sessão do dsh). Se uma atualização do dsh mudar esse nome, o item não aparece. O item fica no menu "…" do projeto no dsh, que não tem espaço para plugins; se o dsh mudar esse menu, o item também não aparece.
- **Editar mensagem na fila no lugar** não altera uma mensagem que começou a ser enviada nesse meio-tempo nem sobrescreve uma mensagem que mudou nesse meio-tempo (por exemplo, no Tether do iPhone): um aviso informa isso. Uma imagem nova precisa de um modelo que aceite imagens (valem os limites de imagem do próprio dsh), e um arquivo novo precisa terminar o upload antes que você possa salvar. Só as suas próprias mensagens na fila podem ser editadas: uma rodada de meta ou uma resposta a uma pergunta na fila, não. Depois de uma atualização do plugin, só as edições de texto funcionam na hora: reinicie o dsh antes de salvar uma mensagem com imagens ou arquivos (a parte Host carrega na inicialização).
- **Refazer** nunca altera o chat revertido: ele inicia um novo chat a partir de logo antes da reversão (a bifurcação do próprio dsh, o mesmo contexto do modelo), então o novo chat tem outro id e outro título. Só a reversão mais recente de um chat pode ser refeita, uma vez, e só enquanto nada veio depois dela (uma nova mensagem encerra a oferta). Um arquivo que você alterou depois da reversão é mantido, a menos que você marque a caixa que o sobrescreve. Refazer precisa do snapshot que a reversão guardou (a mesma janela de 50 entradas); uma reversão feita antes desta versão, ou com **Apenas o chat**, só traz de volta as mensagens.
- O mapa de branches de **Árvore** adivinha para onde vai cada seta, porque o git não guarda em qual branch um branch é mesclado. Um branch mesclado aponta para o branch cujo commit de mesclagem o recebeu primeiro. Um branch que aguarda aponta para o branch mais próximo de onde ele partiu (o branch principal primeiro); quando dois branches partiram do mesmo commit, o mapa pode escolher o errado. Um branch que avançou com um fast-forward não tem commit de mesclagem, então o rótulo **Mesclado** dele não abre nada. O branch principal é o branch padrão de `origin`; se não houver, `main` ou `master`; se também não houver, o branch aberto. O mapa lê os 20.000 commits mais recentes e mostra no máximo 60 branches; em um histórico mais longo, ele avisa que algumas setas podem estar erradas. Um branch mesclado com squash ou rebase (por exemplo, no GitHub) aparece como **Aguardando**: o git não guarda nenhum vínculo com os commits dele.
- **Este chat** conta só os arquivos que as ferramentas de arquivo do dsh (`write`, `edit`, `str_replace_editor`) gravaram. Arquivos que um comando (`bash`) alterou não estão nesta visão; eles aparecem em **Não confirmadas**. Sem um snapshot de Reverter turno do chat (Reverter turno desativado, dsh-rewind-plugin instalado ou um chat mais antigo que o plugin), a visão compara com o último commit e avisa isso. Reverter turno guarda os 50 snapshots mais recentes de um chat: num chat mais longo, a visão compara com o mais antigo guardado, informa a partir de qual mensagem e não conta as alterações anteriores. **Ocultar alterações de espaço em branco** é `git diff -w`: uma linha que mudou só nos espaços dentro dela também fica oculta.
- **Abrir issue no GitHub** precisa do GitHub CLI (`gh`) no PATH do dsh e de um remoto do GitHub na pasta do chat. Ele roda no máximo 60 s; se o `gh` demorar mais, a issue pode existir no GitHub sem o link dela na lista (antes de clicar de novo, olhe no GitHub: a lista só lê o link de uma execução concluída, então um novo clique pode abrir uma segunda issue). Uma pasta com mais de um remoto do GitHub usa o padrão do próprio `gh` (`gh repo set-default`).
- **Relatar uma issue** abre issues só no repositório do Composer Plus (`furkancak1r/dsh-composer-plus`), não no seu projeto (para isso, use **Abrir issue no GitHub** na lista **Depois** de Ideias de recursos). Precisa de um modelo padrão no dsh para o rascunho e do GitHub CLI (`gh`) com login para abrir a issue. O rascunho é sempre em inglês. O modelo pode errar um detalhe: leia o rascunho antes de clicar em **Abrir issue**. Abrir a issue leva no máximo 60 s; o mesmo título e o mesmo texto de novo dentro de uma hora mostram a issue anterior em vez de uma cópia. **Abrir no GitHub em vez disso** corta uma descrição muito longa para manter o link curto.
- **Chats que alteraram este arquivo** só conhece as ferramentas de arquivo do dsh (`write`, `edit`, `str_replace_editor`), como **Este chat**: uma alteração feita por um comando (`bash`) não aparece na lista. Ele lê os 300 chats mais recentes do repositório (pela data de criação) e avisa quando há mais; mostra no máximo 100 linhas. Um arquivo renomeado aparece com o nome que a ferramenta escreveu. Um chat cuja pasta fica fora do repositório (também por outro caminho para os mesmos arquivos) não é contado. A primeira abertura depois de iniciar o dsh lê todos os registros de chat do repositório (cerca de 4 s para 275 chats); as aberturas seguintes leem só os chats que mudaram desde então.
- **Branch do Git nas linhas de chat** mostra o branch da pasta do chat quando o último turno dele começou ou terminou, não o branch atual: uma troca de branch fora de um turno aparece depois do próximo turno. Chats de antes desta versão não mostram etiqueta até o próximo turno. A etiqueta fica na marcação das linhas de chat do dsh (o dsh não tem um espaço ali); se uma atualização do dsh mudar essa marcação, nenhuma etiqueta aparece. A etiqueta só aparece em “Em uma única lista”.
- **Um branch por chat** no modo de plano: o dsh envia `/plan <mensagem>` como comando, não como mensagem, então o Composer Plus intercepta o envio do comando no editor de mensagens do dsh (não é uma API pública). Se uma atualização do dsh mudar isso, `/plan <mensagem>` com **Novo branch** escolhido roda no Novo chat aberto como comando do próprio dsh. Quando o Host não consegue ativar o modo de plano no novo chat, a pasta do branch fica e a mensagem não é enviada, então o novo chat não altera arquivos no modo padrão.
- **Um branch por chat**: quando a pasta do branch de um chat (`<project>/.worktrees/<name>`) é excluída, por exemplo quando o próprio agente do chat remove o worktree e exclui o branch, o próximo passo do chat tira o chat dessa pasta. O projeto da pasta do branch sai da barra lateral, e o chat aparece em Sem grupo e continua aberto. No dsh 0.2.1 e posteriores, o chat continua na pasta principal do projeto, e o modelo recebe uma nota sobre a nova pasta. No dsh 0.2.0, o chat mantém a pasta excluída: um comando nela falha até você começar um novo chat. O projeto de um branch excluído que nenhum chat usa também sai da barra lateral: o Composer Plus verifica as pastas de branch ao iniciar e a cada 30 segundos, também sem filtro da barra lateral. Enquanto um chat é movido, **Novo branch** no mesmo repositório responde "tente de novo". Com a chave desligada, o erro do próprio dsh volta a aparecer ("working-directory: directory does not exist").
- **Branches na árvore de workspaces** escreve no git sem um clique: quando move um chat, volta a pasta do projeto para o branch anterior (`git switch`) e adiciona um worktree (`git worktree add`). Nunca apaga um branch, um worktree ou um arquivo. O dsh não pode mudar a pasta de um chat, então um chat movido é uma cópia (o fork do próprio dsh, com um id novo) e o chat antigo é arquivado. A cópia continua a tarefa parada; uma chamada de ferramenta que rodava quando o branch apareceu termina com uma recusa, e o agente a roda de novo na pasta nova. Um objetivo do chat antigo não vai junto. Só se move um chat cuja pasta é a pasta principal do repositório, e só por um branch que ele criou e para o qual mudou naquele turno (`git switch -c`, `git checkout -b`): um branch feito só com `git branch`, uma pasta com alterações não commitadas, um worktree vinculado ou uma subpasta não movem nada. Na árvore só aparecem worktrees diretamente em `<project>/.worktrees/` com um branch; um worktree desanexado (detached) ou em outro lugar não aparece. A cópia abre sozinha só quando o chat dela era o aberto (o plugin lê isso da linha da barra lateral do dsh); senão, ela está no projeto do branch.
- **Buscar no chat** busca só no que a página mostra: as mensagens e respostas carregadas (role para cima ou clique em **Carregar anteriores** para ver as mais antigas), não as etapas de ferramenta fechadas nem o texto recolhido dentro da saída de uma ferramenta. Ele conta no máximo 2.000 ocorrências (depois, "2000+"). Ele usa a API de destaque do navegador (Chromium 105 ou mais recente; o app para desktop tem): em um navegador mais antigo, a contagem e os saltos funcionam sem a cor. `Cmd+F` no Mac (`Ctrl+F` no Windows e no Linux) só o abre enquanto há um chat na tela; em outros lugares, a busca do próprio navegador funciona como antes. No Mac, `Ctrl+F` mantém seu uso do macOS nos campos de texto (o cursor avança um caractere).
- **Abrir o chat em espera quando ocioso** conhece só o que a janela do dsh vê: o trabalho em outro app não conta, então, com o dsh em segundo plano, ele pode abrir um chat em espera após 30 segundos. Ele não traz o dsh para a frente. Ler sem tocar em uma tecla, clicar ou mover o mouse conta como ocioso. Ele olha só os chats com o ponto laranja do dsh (uma pergunta, uma aprovação ou uma revisão do plano) ou com o ponto verde (um turno concluído que você ainda não abriu); o pedido de um subagente aparece no chat principal dele. Os chats laranja abrem primeiro. Abrir um chat verde remove o ponto dele, então os 30 segundos do próximo chat verde só começam depois da sua próxima tecla, clique, movimento do mouse, roda de rolagem ou toque: quando você volta, os outros pontos verdes continuam lá. Enquanto um chat em espera está na tela, nenhum outro abre; um chat que você deixou sem responder pode abrir de novo depois dos próximos 30 segundos sem uso. Os 30 segundos não podem ser alterados.
- **Próximo chat em espera** conta os mesmos chats que **Abrir o chat em espera quando ocioso**: o ponto laranja do dsh (uma pergunta, uma aprovação ou uma revisão do plano que você pode responder aqui) e o ponto verde (um turno concluído que você ainda não abriu); o pedido de um subagente aparece no chat principal dele. O dsh não registra quando um chat começou a esperar, então a ordem conta a partir do momento em que esta janela o viu: depois de recarregar, os chats que já esperavam mantêm a ordem do dsh. A tecla é um atalho do dsh: em um navegador no Linux ela não tem tecla até você definir uma na página de atalhos de teclado do dsh, e uma extensão do navegador ou outro app pode pegar `Cmd+Shift+E` antes. O dsh não tem um espaço para extensões no cabeçalho da barra lateral, então o botão entra na estrutura desse cabeçalho; se uma atualização do dsh mudar essa estrutura, o botão não aparece e a tecla continua funcionando. O botão não fica na barra lateral estreita.
- **Botões de opções** só lê as respostas que terminam com uma lista de opções: uma lista numerada de 1 a 9 itens, numerada a partir de 1, como última parte da resposta, logo abaixo de um título ou de uma linha em negrito "Opções" ou "Próximos passos" (ou as palavras em inglês "Options", "Choices" e "Next steps", e as mesmas palavras nos outros idiomas do aplicativo). Uma lista no meio de uma resposta, em um bloco de código ou sob outro título não recebe botões. O Composer Plus não pede ao agente que escreva essa lista. Os botões só aparecem abaixo da resposta mais recente, enquanto o chat está ocioso e a caixa de mensagem está vazia, e só depois que o Composer Plus sabe quais respostas uma reversão retirou. No cartão de pergunta do dsh, as teclas 1–9 não fazem nada nos primeiros 0,8 segundo depois que uma pergunta aparece, para que uma tecla que você queria usar para outra coisa não escolha uma opção que você não leu. O dsh não tem uma API de teclas para o cartão de pergunta, então as teclas encontram os botões do cartão na marcação do dsh; se uma atualização do dsh mudar essa marcação, as teclas não fazem nada.
- **Botão Aprovar** funciona só quando o modelo segue a regra e escreve a frase em um bloco `onay`; se não, copie e cole a frase como antes. A verificação de destinos ao vivo é uma lista de palavras (palavras em turco e inglês; partes de palavras também contam), não uma barreira de segurança: um botão oculto é seguro, por isso ele também some com palavras inofensivas como "product" ou "share". A Revisão automática continua verificando cada chamada de ferramenta; o botão só poupa digitação. Só a resposta mais recente tem botões, então uma frase de aprovação antiga não aprova uma etapa posterior. Uma frase com letras fora dos alfabetos inglês e turco não tem botão, nem uma grafia parecida de uma palavra ao vivo ("dep1oy", "pr0d").
- Uma notificação enviada antes de reiniciar só traz o dsh para a frente quando você clica nela.
- Os projetos ativos são movidos com a ordem de projetos salva do dsh, então a nova ordem continua depois de reiniciar. Chats fora de qualquer projeto ("Sem grupo") não podem ser movidos; o dsh sempre os lista por último.
- O dsh não tem um ponto de extensão no menu de opções de exibição da barra lateral, então a opção de projetos recentes é adicionada ao próprio menu do dsh. Se uma atualização do dsh mudar esse menu, a opção não aparece e todos os projetos continuam visíveis. O filtro funciona nas linhas de projeto, então **Em uma única lista** não é filtrada. Em **Árvore de workspaces**, uma pasta pai continua visível enquanto um projeto dentro dela está ativo, e as linhas de chat que não estiveram ativas nas últimas 2 horas também ficam ocultas; em **Workspace**, só as linhas de projeto são filtradas. O filtro lê qual visualização o dsh mostra a partir da configuração de visualização que o dsh salva (não é uma API pública); se uma atualização do dsh mudar esse nome, **Árvore de workspaces** é filtrada como **Workspace**. O recurso Status do projeto lê a mesma configuração: em **Árvore de workspaces**, a linha de uma pasta pai também conta os chats dos projetos dentro dela; se o dsh mudar o nome da configuração, cada linha mostra só os próprios chats. **Por status** tem o mesmo tipo de limite: o dsh não tem um espaço para ordenação, então o item e a ordem das linhas se prendem à marcação do menu e da lista do dsh.
- O dsh também não tem um menu de linha de projeto nem um espaço no cabeçalho de Workspaces. **Copiar caminho** encontra a linha do projeto pela marcação de linha do dsh, e **Recolher todos os projetos** entra no cabeçalho do dsh e fecha cada projeto aberto com o mesmo clique da linha do projeto. Se uma atualização do dsh mudar essa marcação, o clique com o botão direito mostra o menu do navegador e o botão não aparece.
- O dsh também não tem um ponto de extensão no menu de projetos de um novo chat, então a caixa **Buscar projetos** e a ordem A–Z se prendem à marcação do menu do dsh. Se uma atualização do dsh mudar essa marcação, o menu aparece como o dsh o desenha: na ordem salva e sem a caixa. A ordem A–Z é só uma visualização: ela não muda a ordem de projetos salva do dsh.
- O dsh também não tem um ponto de extensão que escolha onde **Nova sessão** abre. **Espaço de trabalho padrão para Nova sessão** envolve um método do dsh que não é uma API pública (`startSession` do serviço de espaços de trabalho do dsh). Se uma atualização do dsh renomeá-lo, **Nova sessão** abre onde o dsh escolher (o projeto aberto ou o mais recente). Toda chamada que não indica um projeto usa o padrão: o botão da barra lateral, seu atalho, o logotipo e também **Nova** na página **Tarefas de automação**. O dsh ainda abre o último chat ao iniciar. A pasta geral é criada e adicionada aos seus projetos no primeiro uso; no Windows ou Linux com a pasta Documents movida, ela pode ser diferente da pasta do próprio dsh.
- O dsh também não tem um ponto de extensão para uma dica no editor de mensagens, então o texto da **Previsão da próxima mensagem** fica sobre o texto de exemplo do próprio dsh (`[data-composer-placeholder]`). Se uma atualização do dsh mudar essa marcação, nenhuma previsão aparece. Enquanto ela está ativada, cada turno concluído custa uma chamada curta ao modelo.
- **Completar ao digitar** mostra o texto pela própria dica do editor de mensagens do dsh (o estilo `--dsh-composer-hint` que o dsh usa para a dica de argumento de um comando de barra). Ele não é executado em um comando de barra, em uma mensagem com um chip de arquivo ou de símbolo nem quando o cursor não está no final da mensagem. Se uma atualização do dsh mudar esse estilo, nenhum complemento aparece. Cada pausa enquanto você digita custa uma chamada ao modelo.
- **Melhorar prompt** vê só um resumo curto do projeto, os caminhos alterados e os caminhos cujos nomes combinam com as suas palavras: não o código em si. Por isso, pode não encontrar o arquivo certo, e só cita caminhos que recebeu. Leia o novo texto antes de enviá-lo. Ele não é executado em um comando de barra que não seja `/goal <meta>`, em uma palavra de controle do `/goal` (`clear`, `pause`, `resume`) nem em uma mensagem com um chip de arquivo ou de símbolo (o novo texto é texto simples, então o chip se perderia), e uma mensagem pode ter no máximo 8.000 caracteres. Para uma meta do `/goal`, ele escreve condições só a partir do rascunho e do contexto; uma condição rígida demais pode custar rodadas da meta, então leia-a antes de enviar. As imagens continuam anexadas: só o texto muda. Cada clique custa uma chamada ao modelo; um modelo forte pode levar um minuto (`Esc` cancela).
- **Verificação da meta** verifica só uma conclusão que o agente faz em uma rodada automática da meta: uma conclusão que você pede no chat, `/goal` e a barra da meta não são verificados. O agente pode alterar os testes ou os arquivos do comando de teste por conta própria; o verificador lê o chat e pode ver isso, mas pode errar nos dois sentidos (um "não concluída" errado custa mais uma rodada; um "concluída" errado fecha a meta). O verificador vê o chat e o `git status`, não o código em si. Uma execução de teste só é reaproveitada quando o passo mais recente do agente que pode alterar arquivos foi a sua própria execução bem-sucedida de `bash` com exatamente o mesmo comando na mesma pasta; um comando com pipe (`| tail`) ou `&&` não é reaproveitado. O orçamento é medido quando um turno termina, então um turno pode ultrapassá-lo. O orçamento de tokens também conta as chamadas dos chats de subagentes do chat (lidas dos logs salvos deles ao fim de cada turno, então um chat com muitos subagentes leva um pouco mais para ser verificado). A tabela de evidências vem da própria leitura do chat feita pelo verificador: uma parte que ele chama de verificada ainda precisa que você mesmo olhe quando isso importa. `update_goal` espera enquanto a verificação é executada (o teste no máximo 15 minutos, o verificador no máximo 3 minutos). Uma bifurcação recebe um novo id de chat, então começa sem o comando de teste e os limites próprios do chat original. Cada conclusão que chega ao verificador custa uma chamada ao modelo.
- **Arquivos protegidos** é uma barreira de proteção, não um sandbox. Cobre as ferramentas de arquivo do próprio dsh (`read`, `read_image`, `grep` em um arquivo, `write`, `edit`, `str_replace_editor`). Um comando de shell (`cat .env`), um script que o agente escreve, o shell de um subagente, uma ferramenta MCP, uma listagem de `glob` e um `grep` em uma pasta inteira ainda podem acessar um arquivo protegido. Para um limite real, use os modos sandbox do dsh ou mantenha segredos fora da pasta do projeto. Os padrões conhecem `*`, `**` e `?`, não `{a,b}` nem `[ab]`, e ignoram maiúsculas e minúsculas.
- **Comandos bloqueados** é uma barreira de proteção, não um sandbox. Lê só o texto do comando das ferramentas `bash` e `pwsh` do dsh. Uma variável ou um alias que nomeia o comando (`CMD=npm; $CMD publish`), uma função de shell, um arquivo de script que o agente escreve, outro programa (`python -c`, `node -e`, `make`), uma ferramenta MCP e o seu próprio terminal ainda podem executá-lo. Uma regra pode corresponder a mais do que você quer: qualquer palavra de um comando pode ser o nome do comando (`echo npm publish` corresponde a `npm publish`), e outras palavras podem vir entre as palavras da regra (`git push --force` também corresponde a `git push origin main --force`). Deixe a regra mais longa quando ela corresponder a coisas demais. **perguntar antes** precisa de um chat que possa perguntar: em um chat cuja política de aprovação é never (por exemplo, um subagente delegado), o dsh não consegue mostrar o cartão, então a chamada é recusada com o motivo. O cartão de aprovação mostra o motivo em inglês. **Permitir neste chat** não responde a um cartão de **perguntar antes**.
- **Continuar em um novo chat** envia o chat (mensagens, chamadas de ferramentas e o fim de cada resultado de ferramenta, no máximo cerca de 60.000 caracteres, a parte mais recente) para o próprio modelo do chat. A nota de passagem pode deixar de fora uma decisão ou um arquivo: leia-a antes de iniciar. O novo chat conhece só a nota e o chat vinculado (o dsh anexa o chat antigo como contexto somente leitura); o contexto do modelo dele começa pequeno, e o chat antigo fica como está. Só uma nota ou um início por chat de cada vez.
- **Detalhamento do contexto** mostra estimativas com a regra do próprio dsh (cerca de 4 caracteres por token), a mesma regra do anel de contexto do dsh; a contagem do próprio modelo pode ser diferente. As definições de ferramentas são as da solicitação mais recente. Ele mostra o contexto como o log do chat o tem; um turno em execução aparece depois do próximo passo dele.
- **Etapas planejadas** economiza tokens só quando o modelo planeja: enquanto está ativado, cada requisição leva a ferramenta `plan_next_steps` e uma instrução curta (cerca de 500 tokens), também em chats em que o modelo nunca planeja. Uma condição prova só o que diz (por exemplo: o código de saída do build foi 0), não que o trabalho está certo. `ok` lê as marcas de resultado do próprio dsh (`[exit code: N]`, tempo esgotado, recusas do sandbox); um comando que falha sem um código de saída diferente de zero passa. As etapas rodam uma de cada vez; duas etapas prontas ao mesmo tempo voltam para o modelo. A mensagem da etapa fica salva como mensagem de assistente do modelo do chat (o dsh não tem uma marca para mensagem escrita por plugin), por isso o texto diz que o Composer Plus a executou. Não está no Tether.
- **Pacote de skill em turco** instala um skill de terceiros: as regras vêm do repositório do autor no GitHub, não do Composer Plus, e uma versão nova é usada a partir da próxima verificação diária sem uma revisão nossa. A verificação prova que os arquivos são os que o GitHub lista para aquele commit, não que as regras sejam boas. O modelo decide quando carregar o skill (você também pode chamá-lo pelo nome); as regras valem só para textos em turco. A parte Host usa o idioma que um navegador informou por último: quando dois navegadores usam idiomas diferentes, vale o mais recente. O GitHub permite 60 chamadas de API por hora sem login; uma verificação recusada mantém a cópia instalada e mostra o motivo nas Configurações.
- **Desembaraçar o código** traz uma cópia fixa da skill (caldoai/skills, commit f3cf477): uma mudança no original só chega com uma nova versão do Composer Plus. A skill executa uma meta longa que pode alterar muitos arquivos, e seus subagentes e verificações gastam muitos tokens. Onde o projeto não tem testes, ela pode mudar o comportamento sem aviso: inicie-a em um branch e leia o diff antes de fazer o merge. Uma skill com o mesmo nome no projeto, em uma pasta de skills personalizada ou em `~/.dsh/skills` a substitui. Com o interruptor desligado, `/untangle-codebase` vai para o modelo como texto comum.
- **Quadro de tarefas** mostra os chats que o dsh lista nesta janela: um chat fora de um projeto aparece só em **Todos os projetos**, e uma pasta de “Um branch por chat” (`<project>/.worktrees/<name>`) conta como o projeto dela. A coluna de um cartão é o estado ao vivo do chat, então os cartões não podem ser arrastados: um chat vai para **Concluído** quando o turno dele termina, também depois de um erro ou de uma parada, e volta para **Fazendo** quando é executado de novo. O ponto verde é o próprio ponto de concluído do dsh, que o dsh mantém só nesta janela: depois de recarregar, os chats concluídos aparecem sem ele. **Concluído** mostra os 50 chats mais recentes (**Mostrar N mais antigas** mostra o resto). **Buscar projetos** encontra um projeto só pelo nome, não pelo caminho da pasta. **Ativos nas últimas 2 horas** oculta um projeto quando todos os chats dele têm mais de 2 horas, estão ociosos e lidos; o quadro continua mostrando o projeto que você escolheu. **Nova tarefa** lembra só o novo chat mais recente desta janela: quando você abre outro chat antes da primeira mensagem, esse chat fica no topo de **Fazendo** como **Nova tarefa** até você escrever nele, mas o quadro volta sozinho só para o mais recente. Depois de recarregar, um novo chat sem mensagem não aparece no quadro (o dsh o mantém como a Nova sessão vazia dele). As etiquetas vêm de uma chamada ao modelo por tarefa, a partir da primeira mensagem dela: elas podem estar erradas, e um chat que você não iniciou no quadro não tem nenhuma. O título é o próprio título do chat no dsh (o serviço de títulos do dsh, com o modelo do chat); até ele chegar, o cartão mostra a primeira linha da primeira mensagem. **×** e **Limpar tudo** só tiram cartões do quadro: nenhum chat é apagado. **Desfazer** aparece só por 8 segundos, nesta janela; depois, **Retirados (N)** → **Devolver** traz um cartão de volta, e um chat que é executado de novo volta sozinho. **Limpar tudo** pergunta antes e tira os cartões concluídos e lidos do projeto mostrado (de todos os projetos com **Todos os projetos**), também os que estão atrás de **Mostrar N mais antigas**; um cartão não lido (verde) fica. O dsh mantém o ponto verde só nesta janela, então, depois de recarregar, o Limpar tudo pode tirar um cartão cuja resposta você não leu. A lista fica neste Mac para todas as janelas e para o Tether; quando ela chega a 5.000 chats, os mais antigos voltam. **Responder** responde só à solicitação mais recente do chat: quando o chat a respondeu em outro lugar (outra janela, Tether, Revisão automática) ou pergunta algo novo, o painel avisa e não envia nada. As versões anteriores tinham uma lista de tarefas com comentários e ferramentas para agentes; elas não existem mais, e o `board.json` antigo não é mostrado. A ideia e a aparência vêm do [Kanzo](https://github.com/emanuele-em/kanzo), de emanuele-em (AGPL-3.0); o Composer Plus não usa código dele. `Cmd+Shift+K` é um atalho do dsh: em um navegador no Linux, ele não tem tecla padrão (defina uma na página de atalhos de teclado do dsh), e uma extensão do navegador ou outro aplicativo pode usá-la antes. Um cartão sai de **Concluído** quando o ponto verde do dsh some (você abriu o chat) ou, para um chat que terminou atrás do quadro enquanto era o chat aberto, quando esse chat aparece sem um painel por cima. Esse estado de lido fica só nesta janela do dsh, como os pontos do dsh: depois de recarregar ou em outra janela, todo chat concluído conta como lido, então fica em **Concluídos recentemente**.
- **Assistente** tem um só chat para todas as janelas deste Mac. Ele roda com o modo de permissão workspace-write: grava arquivos só em `~/Assistant`, e um comando fora dessa pasta pergunta primeiro. Quando você muda o chat para um modo sem aprovações (Acesso total), o dsh recusa cada aprovação, então o assistente não consegue enviar, iniciar, parar nem arquivar um chat. O cartão de aprovação protege só as seis ferramentas: um comando de shell do assistente ainda pode acessar a rede, como em qualquer chat com esse modo. No dsh 0.2.0 e 0.2.1, as ferramentas de agendamento do dsh veem só os lembretes do próprio chat do assistente, não as automações de outros chats; a partir do dsh 0.2.2, elas listam e mudam todas as tarefas agendadas. chats_list deixa de fora chats arquivados, vazios e de subagentes, e o próprio chat do assistente; “esperando por você” significa uma aprovação, pergunta ou revisão de plano em aberto em um chat em execução. chat_read dá as mensagens do usuário e as respostas do agente (sem saída de ferramentas), no máximo 50 mensagens e cerca de 24.000 caracteres. chat_archive recusa um chat que ainda está em execução ou que tem lembretes ativos. Um texto que o modelo lê ainda pode enganá-lo: o cartão de aprovação é a última verificação, então leia-o antes de clicar em **Permitir uma vez**. No modo de permissão Auto do dsh, a última verificação é a Revisão automática, não o cartão: quem decide é um modelo revisor, não você. Os assuntos em paralelo usam a ferramenta de subagentes do dsh: um perfil ou modo de permissão sem ela mantém o comportamento antigo (um assunto por vez; a próxima mensagem espera na fila ou direciona o turno em execução). O modelo decide o que conta como tarefa longa, então uma pergunta curta ainda pode ocupar um turno. O subagente de cada assunto roda com os próprios tokens; quando o dsh reinicia, um assunto em execução para (o resultado dele não volta). Um resultado volta como um novo turno do chat do assistente, então ele espera enquanto você digita no meio de um turno.
- **Assistente separado dos chats** e **Só mensagens no Assistente** ocultam as próprias linhas do dsh com uma regra de estilo, que as encontra pela marcação da barra lateral e do chat do dsh (`data-row-key`, `data-chat-flow-kind`): quando uma atualização do dsh muda essa marcação, o chat do assistente volta a aparecer na lista, ou as etapas de trabalho dele voltam a aparecer. As linhas ficam ocultas, não removidas: a navegação por teclado do dsh na barra lateral ainda pode chegar a uma linha oculta. **Assistente sempre livre** recusa cada chamada de ferramenta do chat do assistente que não seja uma das ferramentas curtas dele; então o modelo passa a etapa a um subagente, mas pode tentar primeiro a chamada recusada, o que custa uma etapa do modelo. Enquanto um cartão de aprovação espera por você, o chat do assistente ainda conta como ocupado. Quando a solicitação mais recente dele não tem a ferramenta de subagentes (um modo de permissão ou perfil sem ela), a regra não faz nada. Com **Assistente sempre livre**, uma mensagem que você envia enquanto ele trabalha entra no turno na próxima etapa, então a fila abaixo do campo de entrada a mostra só por um momento; enquanto um cartão de pergunta espera, o mesmo texto responde a cada pergunta desse cartão. O aviso de "concluído" de um subagente não inicia um segundo turno só no dsh 0.2.2 ou posterior (um dsh anterior não marca que o subagente já enviou o resultado). **Avisos de chats no Assistente** inicia um turno do modelo no chat do assistente para cada lote de avisos, então usa tokens; com **Conexão móvel (iPhone)** ativada, seu celular pode receber duas notificações por um chat concluído (a do próprio chat e a do assistente). Os avisos que estão esperando se perdem quando o dsh reinicia. O recurso vê só os chats deste Mac.
- **Painel de status do Assistente** mostra o painel dentro do corpo do chat do dsh, que encontra pela marcação do dsh (`data-conversation-content`): se uma atualização do dsh mudar essa marca, o painel não aparece (a lista e as ferramentas do agente continuam funcionando). Em uma janela com menos de 1000 px, o painel cobre a borda direita do chat: clique no título para recolhê-lo. O painel lê a lista de novo a cada 5 segundos enquanto o assistente trabalha, ao fim de cada turno e depois do seu clique, então um item que o assistente adiciona aparece com um pequeno atraso. Quando o idioma da interface do dsh não é o inglês, a linha de resultado de cada tarefa de subagente aparece nesse idioma: o modelo padrão do dsh traduz cada linha nova uma vez (uma chamada para as linhas novas de uma leitura, sem ferramentas), e a mesma linha não é enviada de novo enquanto o dsh roda. Até a tradução chegar, e quando a chamada falha, a tarefa não mostra linha de resultado. Os subagentes continuam escrevendo e lendo em inglês.
- **Prioridade à mensagem enviada após Parar** só age depois que você interrompe o chat (ou depois de um turno que falhou, ou ao abrir um chat que ainda tem fila): uma mensagem enviada enquanto um turno é executado continua esperando no fim da fila. Ela só passa à frente das suas próprias mensagens na fila: se uma rodada de meta ou uma resposta a uma pergunta espera na fila, a ordem do dsh fica. Ela lê uma parte do dsh que não é uma API pública (se o turno interrompido ainda está terminando); se uma atualização do dsh mudar esse nome, a mensagem só passa à frente depois que esse turno terminar. Chats de subagentes mantêm a ordem do dsh.
- **Memória do projeto** pertence à primeira pasta do chat (a pasta de projeto do dsh): um chat que muda de pasta com `cd` continua com a memória do primeiro projeto, e a mesma pasta aberta por outro caminho para os mesmos arquivos a compartilha. Um chat congela sua seção de memória quando começa, então uma nota salva depois aparece a partir do chat seguinte (`memory_recall` a encontra na hora). A revisão guarda só o que o modelo decide guardar: pode deixar passar um fato ou guardar um errado; confira em **Abrir memória** e mude lá, ou edite os arquivos à mão com o dsh fechado. **Abrir memória** envia as notas do projeto selecionado e as notas globais (todos os projetos quando você seleciona Todas as notas; no máximo cerca de 60.000 caracteres, o resto só é contado e não pode mudar nesse pedido) e o seu texto ao modelo padrão do dsh, não ao modelo do chat. Uma prévia fica no Mac por 30 minutos e até o dsh reiniciar; se uma revisão ou o agente mudar as notas nesse meio-tempo, **Aplicar** recusa e você pede a prévia de novo. **Aplicar** grava todas as mudanças de uma prévia ou nenhuma: se uma mudança não puder ser gravada (por exemplo, a nota que ela muda não existe mais), as notas ficam como estavam e o motivo aparece. Cada turno concluído com uma mensagem sua custa uma chamada ao modelo; uma chamada com falha lê as mesmas mensagens de novo depois do turno seguinte. Chats de subagentes não são revisados, mas recebem as notas como contexto. Um subagente usa a memória da pasta em que trabalha (a pasta da sua tarefa), não a da pasta do chat que o iniciou. A revisão também lê suas respostas nos cartões de perguntas. Uma revisão com falha ou uma nota que ela não consegue salvar deixa uma linha com `"actor":"review-error"` em `journal.jsonl`. A ideia e o formato de arquivo vêm do [DS Bot](https://github.com/Fei2411/DS-Bot) (Apache-2.0); o Composer Plus não usa o código dele e nunca lê nem escreve a memória do próprio DS Bot.
- **Pasta da memória** vale a partir do próximo início do dsh. O primeiro início com uma pasta sem `Genel` nem `Projeler` copia todas as notas para lá uma vez, tudo ou nada; as notas antigas na pasta do dsh ficam, e as mudanças seguintes vão só para a pasta. Se a cópia falhar, Memória do projeto fica desligada até o próximo início (nenhuma nota vai para o lugar errado) e o motivo fica no log do dsh. As notas não têm limite de tamanho nem de tópicos; o prompt de cada chat recebe as notas mais novas de cada MEMORY.md, até 8.000 caracteres, e o agente encontra as outras com `memory_recall`. Uma nota escrita à mão deve ser uma linha `- ` fora de `## Index`, e o nome de um arquivo de tópico deve estar em minúsculas com `-` no lugar de espaços (`health-records.md`); outros arquivos da pasta não são lidos. Um link simbólico no lugar da pasta, de `Genel` ou de `Projeler` é recusado, e um arquivo de nota que é link simbólico é lido como vazio. Tudo que sincroniza ou faz backup dessa pasta (iCloud, Git, Obsidian Sync) também recebe as notas.
- **Histórico de versões da memória** guarda as 50 versões mais recentes de cada memória (cada projeto e a memória global); as mais antigas são apagadas. Uma versão guarda toda a memória daquele projeto, não uma nota. **Restaurar** devolve todos os arquivos daquela versão (tópicos incluídos) e recusa quando a memória mudou depois que você abriu a versão; a memória de antes da restauração vira uma nova versão, então você pode desfazê-la. Com a chave desativada, nenhuma versão nova é guardada e **Restaurar** recusa; as versões guardadas ficam. Não há versões de antes deste recurso: o histórico começa com a primeira gravação depois de instalá-lo.
- **Exportar a memória para AGENTS.md** grava só as notas da memória de um projeto; notas globais, fontes e datas ficam de fora. A próxima exportação substitui toda a seção marcada, então uma mudança feita à mão dentro dela se perde (o diff mostra antes); o texto fora das marcas fica. Se as marcas estiverem quebradas (falta uma ou aparecem duas vezes), a exportação recusa até você corrigi-las. Um AGENTS.md com mais de 512 kB, um link simbólico que sai da pasta do projeto e tudo que não for arquivo comum são recusados. Se o AGENTS.md ou as notas mudarem depois da prévia, **Gravar AGENTS.md** recusa e você exporta de novo.
- **Link de origem das notas da memória** funciona para notas salvas depois que você instalar esta versão: uma nota mais antiga indica só o chat (ou nada), então **Origem** só abre o chat ou não aparece. Quando a mensagem não existe mais (uma reversão a retirou ou o chat foi apagado), o chat abre e um aviso diz que a mensagem não está lá.
- **Copiar a memória para outro projeto** copia no máximo 100 notas por vez e só para um projeto que o dsh lista (lê a lista de projetos do próprio dsh; nenhum caminho vem da janela). Cada cópia é independente: uma mudança posterior numa nota de um projeto não muda a cópia. Se uma nota marcada não puder ser copiada (não está mais na origem, ou um arquivo não pode ser gravado), nada é copiado. Uma nota cujo texto e tópico já estão no destino é ignorada, e a contagem diz quantas.
- **Encontrar notas de memória desatualizadas** só encontra o que uma nota escreve numa forma que conhece: um caminho num trecho de código (`src/cart.ts`), um script npm depois de `npm run` (ou `npm test`, `pnpm lint`), um nome de branch num trecho de código perto da palavra "branch". Um caminho que sai da pasta do projeto não é informado; um script só é verificado se o projeto tem `package.json`, um branch só num repositório git. Verifica no máximo 200 itens por vez. Um aviso significa "não encontrado agora", não "errado": um arquivo que uma build cria depois também é informado.
- **Não usar a memória neste chat** vale a partir do próximo pedido ao modelo desse chat: um pedido já em andamento mantém o que tem. Mudar num chat em andamento muda o prompt de sistema uma vez, então esse pedido não pode usar o cache do provedor do modelo. Um subagente segue o chat raiz. A revisão não lê as mensagens que um chat recebe enquanto a memória dele está desativada, nem se você ativar de novo depois. No dsh 0.2.0 a tela de novo chat não tem lugar para o botão: ele aparece no cabeçalho do chat depois da primeira mensagem.
- **Sugerir notas de memória a partir de um chat** mostra no máximo 10 sugestões e as guarda por 30 minutos e até o dsh reiniciar; depois disso, ao aceitar você é pedido para sugerir de novo. Um chat longo envia as mensagens mais recentes: as respostas mais antigas do agente saem primeiro. Uma sugestão pode estar errada: leia antes de aceitar e use **Abrir memória** para mudar uma nota depois. Uma sugestão rejeitada pode voltar no próximo clique.
- **Backup** usa uma única pasta fixa, `~/Desktop/dsh-backups` (o padrão do dsh-backup, para que os arquivos compactados dele continuem utilizáveis); não há opção para outra pasta. Um arquivo compactado tem mais ou menos o tamanho do dsh home sem `cache/` e `dsh-runtimes/` (medido: 1,6 GB de arquivos geraram um arquivo compactado de 830 MB em cerca de 30 s no Apple Silicon; o dsh continuou respondendo). Um arquivo que muda enquanto é lido é guardado como estava quando o backup o abriu, então o log de um chat aberto pode terminar em um registro cortado, que o dsh repara na próxima gravação. O mascaramento encontra um segredo em um arquivo yml pelo nome da chave em uma linha (`token:`, `apiKey:`, …); um segredo em um mapa de fluxo (`{token: x}`), em uma lista sob uma dessas chaves, em um arquivo JSON (por exemplo, a `apiKey` de um servidor MCP em um arquivo `.json`) ou com outro nome fica no arquivo compactado. Os arquivos compactados por tipo do dsh-backup (`dsh-t-…`) não aparecem na lista. **Para outro computador** copia o arquivo compactado (um clone no APFS: sem espaço extra); o vault não vai junto. **Fazer backup agora** não exclui nenhum backup. Um backup automático mantém os backups mais recentes feitos pelo Composer Plus (a opção **Manter** do **Backup automático**) e exclui os backups mais antigos que ele fez; os snapshots de antes de uma atualização são contados à parte (os 2 mais recentes ficam). Os arquivos compactados do dsh-backup nunca são excluídos: remova-os com **Excluir**. Enquanto o dsh-backup ainda estiver instalado, ele conta os arquivos compactados do Composer Plus no próprio limite de cópias mantidas e pode excluí-los.
- **Restaurar** só funciona no console de resgate, com o dsh fechado: substitui todo o dsh home. O antigo fica ao lado como `.dsh.pre-restore-<time>` até você removê-lo, então o disco precisa de espaço para os dois. Os chats mantêm os caminhos dos projetos: em outro computador, um projeto em outro caminho aparece como ausente até você adicioná-lo de novo. Symlinks que apontam para fora do dsh home (por exemplo, skills vinculadas de outra pasta) voltam como links; os destinos deles precisam existir nesse computador.
- **Verificação de logs de sessão** lê o log mais recente de cada chat com as próprias regras do dsh sobre o que abre: uma linha que não é JSON ou que está fora de ordem só conta como dano quando um fim de turno vem depois dela (senão o dsh abre o chat sem as linhas a partir dali, então ele não aparece na lista). Ela não confere os eventos de um log com as regras de eventos do próprio dsh, então um log que ela considera íntegro ainda pode não abrir depois de uma atualização do dsh. Um reparo pega a cópia de um backup: as mensagens depois desse backup se perdem nesse chat (o arquivo danificado fica ao lado). Um chat aberto neste dsh não é reparado em Configurações: o dsh o mantém em uso.
- **Backup automático** só é executado enquanto o dsh está em execução: um backup que venceu com o dsh fechado é executado cerca de 45 s depois da próxima inicialização. O snapshot de uma nova versão é feito depois dessa inicialização, não antes da atualização.
- **Lembrar o tamanho da janela** funciona só no app para desktop. A cada início, o dsh mostra primeiro a janela em 1280 × 820; a janela passa ao tamanho salvo quando o plugin carrega. Uma página não tem evento para o movimento da janela, então o plugin lê a janela uma vez por segundo: uma mudança nos últimos 2 segundos antes de o dsh fechar não é salva. O tamanho fica salvo por computador, no armazenamento do próprio app.
- **Contagem de uso:** conta cópias, não pessoas: cada dsh home é uma cópia. A contagem de cópias únicas (`installed.txt`) só inclui cópias que atualizam para a primeira versão com esse arquivo ou para uma mais nova; uma cópia que fica numa versão mais antiga não é contada. Uma cópia cuja pasta `storages` é apagada é contada de novo. O GitHub pode contar como um só os pedidos que vêm do mesmo endereço IP (por exemplo, vários computadores atrás do mesmo roteador NAT) em cerca de 10 minutos.
- O suporte nativo foi pedido no projeto original: `move` na fila em [#773](https://github.com/deepseek-ai/deepseek-harness/discussions/773), um estado de Continuar em [#9269](https://github.com/deepseek-ai/deepseek-harness/discussions/9269).

## Perguntas frequentes

**Como adiciono um painel de alterações / git diff ao DeepSeek Harness?** Instale `dsh-composer-plus` e depois use barra lateral direita → `+` → **Alterações**.

**O dsh pode sugerir recursos para o meu projeto, como ao deslizar cartões no Tinder?** Sim: barra lateral direita → `+` → **Ideias de recursos** → **Sugerir recursos**. Deslize para a direita para iniciar um novo chat que planeja o recurso; clique em **▶ Criar agora** para iniciar um chat que o cria na hora, sem plano; deslize para a esquerda para pular.

**A pesquisa da barra lateral do dsh consegue encontrar um chat por uma palavra das mensagens, e não só pelo título?** Sim, com **Pesquisa no conteúdo** (ativada por padrão): reinicie o dsh uma vez depois de instalar o plugin e use a lupa ao lado de **Workspaces**. Os chats encontrados mostram o texto ao redor da palavra.

**Posso desfazer um turno e editar meu prompt, como no OpenCode ou no Claude Code?** Sim, com **Reverter turno**: clique em **↶** na mensagem, escolha **Chat e arquivos**, edite o texto que volta para o editor de mensagens e envie.

**Posso excluir um chat em vez de arquivá-lo?** Sim, com **Excluir chat**: **…** → **Excluir…**. O histórico vai para o Lixo, então um erro pode ser desfeito.

**Como vejo a qual projeto um chat pertence?** Olhe a linha abaixo do editor de mensagens: com **Nome do projeto no compositor** (ativado por padrão), ela começa com o nome do projeto. Passe o mouse sobre ele para ver o caminho da pasta.

**Como tenho histórico de mensagens com ↑/↓ no editor de mensagens do dsh?** Instale este plugin; com o editor de mensagens vazio, `↑` / `↓` percorrem as mensagens que você enviou.

**Como continuo um turno interrompido ou com falha no dsh sem digitar "continue"?** Com este plugin, o botão de enviar vira **▶** depois de um turno interrompido, com falha ou cortado; um clique retoma o turno.

**O dsh continua os chats em execução depois que eu fecho e abro o app de novo?** Não por conta própria: o dsh marca esse turno como interrompido e espera (uma meta também espera por `/goal resume`). Ative **Configurações → Composer Plus → Retomar após reiniciar**: assim, os chats que estavam trabalhando quando o dsh fechou continuam sozinhos na próxima inicialização.

**Qual modelo escreve a previsão?** O modelo que você escolhe em **Configurações → Composer Plus → Previsão da próxima mensagem → Modelo**. A lista é a própria lista de modelos do dsh. **Padrão do dsh** segue o modelo padrão do dsh. Se o dsh não listar mais o modelo escolhido, a previsão usa o padrão. **Completar ao digitar** tem o próprio menu **Modelo**: **Igual à previsão da próxima mensagem** (o padrão) segue o modelo da previsão; outra escolha é usada só para os complementos. Se o dsh não listar mais esse modelo, os complementos usam o modelo da previsão.

**O dsh pode melhorar meu prompt antes de eu enviá-lo, como o botão Enhance prompt do Roo Code ou do Augment?** Sim, com **Melhorar prompt** (ativado por padrão): digite um pedido aproximado e clique na varinha mágica ao lado do menu de modelos. Ele reescreve o texto com este chat e o projeto como contexto, no seu idioma, e não o envia. `Cmd/Ctrl+Z` ou **Desfazer melhoria** traz o seu texto de volta. Escolha o modelo dele em **Configurações → Composer Plus → Melhorar prompt → Modelo**.

**O agente pode parar de marcar o próprio trabalho como concluído, como nos loops de verificação da loop engineering?** Sim, com **Verificação da meta** (ativada por padrão): comece uma meta com `/goal`. Quando o agente diz que a meta foi concluída, os testes do projeto são executados e uma chamada independente ao modelo confere a meta com o chat; se algum dos dois falhar, a meta continua aberta e o agente lê o motivo. Defina o seu próprio comando de teste, um limite de tempo ou um limite de tokens com **Editar** na linha **Verificação da meta** abaixo da meta.

**O agente pode lembrar minhas preferências entre chats, como a memória do DS Bot?** Sim, com **Memória do projeto** (desativada por padrão): ative em **Configurações → Composer Plus**. Depois de cada turno, suas preferências e decisões duradouras são guardadas como notas curtas para o projeto do chat, e cada chat novo desse projeto as lê. Peça ao agente para lembrar algo e ele salva na hora. Para ver ou mudar as notas, clique em **Abrir memória** na mesma linha e escreva o que mudar.

**Eu ou a IA fizemos uma mudança errada na memória. Posso recuperar as notas antigas?** Sim, com **Histórico de versões da memória** (ativado por padrão): em **Abrir memória**, selecione o projeto e depois **Histórico**. Selecione a versão de antes da mudança para ver o que volta e depois **Restaurar**.

**Posso compartilhar a memória do projeto com minha equipe ou outra ferramenta de agentes?** Sim, com **Exportar a memória para AGENTS.md** (ativado por padrão): em **Abrir memória**, selecione o projeto e depois **Exportar para AGENTS.md**. Confira o diff, depois **Gravar AGENTS.md**, e faça commit do arquivo.

**A IA pode sugerir o que guardar de um chat longo?** Sim, com **Sugerir notas de memória a partir de um chat** (ativado por padrão enquanto **Memória do projeto** está ativada): clique em **Sugerir para a memória** no cabeçalho do chat e depois em **Aceitar** nas notas que vale a pena guardar.

**Posso ver todos os meus chats como um quadro kanban e iniciar novos chats a partir dele?** Sim, com **Quadro de tarefas** (ativado por padrão): abra-o na barra lateral esquerda. Cada chat é um cartão em **Fazendo**, **Em revisão** (ele espera por você) ou **Concluído**. **Nova tarefa** abre o novo chat do dsh no projeto, e o quadro volta quando a sua primeira mensagem é enviada; clique em **Responder** em um cartão laranja para responder sem abrir o chat. **Limpar tudo**, em **Concluído**, pergunta antes e tira do quadro os cartões concluídos que você leu; **Desfazer** e **Retirados (N)** os trazem de volta, e os chats continuam no dsh.

**Posso ter um chat de assistente pessoal que me lembra de coisas e gerencia meus outros chats?** Sim, com **Assistente** (ativado por padrão): clique em **Assistente** na barra lateral esquerda. Ele cria lembretes com as tarefas agendadas do dsh, pesquisa na web, lista e lê seus chats, e envia uma mensagem a um chat ou inicia, para ou arquiva um só depois que você aprova. Guarde seu perfil na memória do projeto dele, tema "profil".

**O assistente pode ficar fora da minha lista de chats e funcionar como um bot?** Sim. **Assistente separado dos chats** tira o chat dele da lista da barra lateral e mostra o estado na linha **Assistente** (laranja enquanto espera por você). **Só mensagens no Assistente** oculta as etapas de trabalho dele. **Assistente sempre livre** faz com que ele passe cada etapa mais longa a um subagente em segundo plano, então ele responde na hora. **Avisos de chats no Assistente** (desativado por padrão, usa tokens) faz com que ele avise você quando outro chat termina, falha ou espera por você. Por padrão (**Só automações**), ele avisa só dos turnos que uma tarefa agendada iniciou (também em um chat que você iniciou), depois de cada um desses turnos, como um subagente informa; escolha **Todos os chats** em **Avisar sobre** para saber de todos os chats.

**O dsh consegue fazer backup dos meus chats e configurações, como o dsh-backup?** Sim: **Configurações → Composer Plus → Backup → Fazer backup agora**. Ele grava o mesmo formato de arquivo compactado na mesma pasta (`~/Desktop/dsh-backups`), então os arquivos compactados do dsh-backup também aparecem e podem ser restaurados, e você pode remover o dsh-backup. Ative **Backup automático** para ter backups agendados.

**O dsh não inicia mais. Como restauro um backup?** Abra a pasta de backups (`~/Desktop/dsh-backups`) e clique duas vezes em `Composer Plus Rescue.command` (Linux: `composer-plus-rescue.sh`, Windows: `Composer Plus Rescue.cmd`). Escolha `3) Restore a backup`, selecione um e digite `RESTORE`. Funciona sem o dsh.

**Como levo o dsh para um computador novo?** No antigo: **Backup** → **Para outro computador** ao lado de um backup. Copie essa pasta para o computador novo, instale o dsh lá, feche-o, abra `Composer Plus Rescue` na pasta copiada e restaure. Informe as suas chaves de API de novo (elas ficam no computador antigo).

**Um chat não abre depois de uma falha. Posso repará-lo?** **Configurações → Composer Plus → Verificação de logs de sessão → Verificar logs de sessão**. Um chat danificado volta do backup mais recente com **Reparar a partir dos backups** (as mensagens depois desse backup se perdem).

**Como reordeno as mensagens na fila do dsh?** Arraste a alça ⠿ de uma mensagem na fila, ou coloque o foco nela e pressione `↑` / `↓`.

**Como corrijo um erro de digitação em uma mensagem na fila?** Dê um clique duplo na mensagem na fila, altere o texto e pressione `Enter` (`Esc` cancela). Ela mantém o lugar na fila. Ali você também pode remover as imagens e os arquivos dela, ou adicionar novos.

**Como limpo de uma vez todos os pontos de não lido de um projeto?** Barra lateral → botão **…** do projeto → **Marcar tudo como lido**.

**Posso criar um link para uma única mensagem em um chat longo?** Sim: passe o mouse sobre a mensagem e clique em **🔗**. Envie o link em um chat: no dsh 0.2.1 ou mais recente, um clique nele abre o chat naquela mensagem.

**Reverti um turno por engano. Posso recuperá-lo?** Sim, com **Refazer** acima do editor de mensagens, logo depois da reversão: ele inicia um novo chat a partir de logo antes da reversão com as mesmas mensagens, e com **Chat e arquivos** também traz os arquivos de volta.

**Qual chat alterou este arquivo?** Barra lateral direita → **Alterações** → **…** do arquivo → **Chats que alteraram este arquivo**. Clique em uma linha para abrir esse chat no pedido que fez a alteração.

**Posso buscar dentro de um chat longo?** Sim: pressione `Cmd+F` no Mac (`Ctrl+F` no Windows e no Linux) no chat. **Buscar no chat** destaca todas as ocorrências e passa de uma para outra com `Enter` e `Shift+Enter`.

**Como vejo só os arquivos que um chat alterou?** Barra lateral direita → **Alterações** → **Este chat**. Clique em **␣** para ocultar alterações que são só espaço em branco.

**Como impeço o agente de executar `npm publish` ou `git push --force`?** **Configurações → Composer Plus → Comandos bloqueados**: digite `npm publish`, escolha **bloquear** ou **perguntar antes** e depois clique em **Adicionar**. **bloquear** recusa o comando e o agente pergunta a você; **perguntar antes** mostra o cartão de aprovação toda vez. Arquivos protegidos cobre as ferramentas de arquivo do agente; Comandos bloqueados cobre os comandos de shell dele.

**Posso dizer ao agente por que rejeitei uma chamada de ferramenta?** Sim, com **Rejeitar com nota** (ativado por padrão): clique em **Rejeitar com nota…** no cartão de aprovação, escreva o motivo ou o que fazer no lugar e clique em **Rejeitar**. O agente lê a rejeição e a sua nota no mesmo turno.

**Como dou ao agente uma senha ou um token sem escrever no chat?** Com **Entrada secreta** (ativada por padrão): peça ao agente que use `request_secret`, ou espere que ele peça. Digite o valor no cartão da linha da ferramenta e clique em **Salvar**. O agente recebe só o caminho de um arquivo que contém o valor, e o arquivo é apagado quando o turno termina.

**Como respondo só a uma parte de uma resposta longa?** Selecione essa parte e clique em **Citar** acima da seleção (**Citar na resposta**, ativado por padrão). A parte vai para o campo de texto como citação `> …`, e você escreve sua resposta abaixo.

**Como mostro ao agente as linhas exatas de um arquivo?** Abra o arquivo na barra lateral direita (**Arquivos do workspace**), selecione as linhas e clique em **Citar** acima da seleção (**Citar da prévia do arquivo**, ativado por padrão). O campo de texto recebe o caminho e os números de linha (por exemplo `src/login.js:2-3`) e as linhas como bloco de código; escreva sua pergunta abaixo delas.

**Posso perguntar algo enquanto o agente trabalha, sem pará-lo?** Digite a pergunta e clique em **Perguntar em um chat paralelo** no campo de texto (**Chat paralelo**, ativado por padrão). Uma cópia somente leitura do chat responde enquanto o chat continua. No chat paralelo, **Trazer de volta** coloca a resposta no campo de texto do chat.

**Como digo ao agente o que mudar no diff dele?** No **Painel de alterações**, abra o diff do arquivo, clique em **+** em uma linha e escreva uma nota (**Notas no diff**, ativado por padrão). Depois clique em **Enviar ao campo de texto**: as notas vão para o campo de texto com o arquivo, os números de linha e as linhas.

**Como faço a Revisão automática parar de perguntar sobre a mesma ferramenta em um chat?** Clique em **Permitir neste chat** no cartão de aprovação. Isso cobre só aquela ferramenta exata naquele chat, por 1 hora por padrão; revogue pelo chip no cabeçalho. Mude o tempo em **Configurações → Composer Plus → Permitir neste chat**.

**Perdi meu iPhone. Como impeço que ele acesse meu Mac?** Clique em **Conexão móvel** no canto inferior esquerdo da barra lateral e clique em **Remove** ao lado desse iPhone. A chave dele para de funcionar na hora; ele só volta com um novo pareamento que você aprove no Mac.

**Como continuo um chat do meu outro Mac a partir deste?** No outro Mac, ative **Configurações → Composer Plus → Computadores remotos** e **Permitir que outros computadores abram este Mac**, clique em **Criar link de pareamento** e copie o link (envie o link para você mesmo, por exemplo pelo AirDrop ou pelo Notas). Neste Mac, ative também **Computadores remotos**, escolha **Adicionar um computador…** no seletor da barra lateral esquerda (abaixo do nome da marca, acima de **Nova sessão**), cole o link, digite um **Nome** e clique em **Conectar**. Depois, clique em **Aprovar** no outro Mac. A partir daí, clique no nome desse computador no seletor: ele ocupa esta janela. Clique em **Este Mac** no mesmo lugar para voltar. Enquanto isso, os chats deste Mac continuam em execução.

**Posso bloquear o Tether com o Face ID?** Sim: no Tether, ative "Settings → Privacy → Lock with Face ID". Depois disso, o Tether pede o Face ID (ou o código) quando abre e quando você volta para ele.

**Como mostro na barra lateral do dsh só os projetos que usei hoje?** Barra lateral → opções de exibição (ícone de controles deslizantes) → **Ativos nas últimas 2 horas**. Selecione de novo para mostrar todos os projetos.

**Como copio o caminho da pasta de um projeto no dsh?** Clique com o botão direito no projeto na barra lateral → **Copiar caminho**.

**Como recolho todos os projetos da barra lateral do dsh de uma vez?** Clique no botão de recolher ao lado das opções de exibição (ícone de controles deslizantes). Ele aparece enquanto pelo menos um projeto estiver aberto.

**Como recebo notificações do macOS / Windows quando uma tarefa do dsh termina ou precisa de aprovação?** Mantenha **Notificações em segundo plano** ativado (padrão) e permita notificações para o DeepSeek Harness nas configurações do sistema operacional.

**O dsh pode abrir sozinho o chat que me faz uma pergunta?** Sim, com **Abrir o chat em espera quando ocioso** (ativado por padrão): quando um chat aguarda uma resposta, uma aprovação ou uma revisão do plano e você não usa o dsh por 30 segundos, o dsh o abre. Um chat que concluiu um turno que você ainda não leu (o ponto verde) abre do mesmo jeito, depois dos laranja. Enquanto você digita, rola a tela ou move o mouse, ele espera.

**Posso ir direto para o próximo chat que está esperando por mim?** Sim, com **Próximo chat em espera** (ativado por padrão): pressione `Cmd+Shift+E` (`Ctrl+Shift+E` no Windows e no Linux) ou clique no botão com o número no cabeçalho da barra lateral. Primeiro vêm os chats que fazem uma pergunta ou aguardam uma aprovação, depois os que terminaram um turno que você ainda não leu.

**Posso responder às opções de um agente com um clique?** Sim, com **Botões de opções** (ativado por padrão): quando uma resposta termina com uma lista "Opções", clique em um botão abaixo dela. Ele envia "Option N: …" como sua mensagem. Em um cartão de pergunta do agente, pressione 1–9.

**Posso enviar a frase de aprovação do agente sem digitá-la?** Sim, com **Botão Aprovar** (ativado por padrão): quando o agente precisa de uma aprovação escrita, ele escreve a frase em um bloco `onay`. Clique em **Aprovar** abaixo da resposta: a frase exata vai como sua mensagem, e a Revisão automática a vê como sua. Uma frase que cita um destino ao vivo ou público não tem botão: digite-a você.

**Como mudo a interface do DeepSeek Harness para turco, espanhol, japonês…?** Configurações → Composer Plus → **Idioma do aplicativo**.

**Como uso o dsh no meu iPhone?** Compile o app Tether a partir de `tether/ios` (Xcode), ative **Configurações → Composer Plus → Conexão móvel (iPhone)**, clique em **Conexão móvel** no canto inferior esquerdo, leia o código QR (com a Câmera do iPhone ou com **Scan code** no Tether), toque em **Connect** e clique em **Approve**. Longe de casa, use o Tailscale nos dois aparelhos.

**Como faço Nova sessão abrir sempre no mesmo projeto?** Configurações → Composer Plus → **Espaço de trabalho padrão para Nova sessão** → **Abrir Nova sessão em** → escolha o projeto. O `+` ao lado de outro projeto continua abrindo esse projeto.

**Como trabalho em vários recursos de um projeto ao mesmo tempo, cada um no seu próprio branch?** Com **Um branch por chat**: na tela de novo chat, o botão de branch mostra **Novo branch** por padrão: envie a primeira mensagem. Cada chat ganha o próprio branch e a própria pasta de worktree, com o seu `.env` e o seu `node_modules` quando o `.worktreeinclude` os lista. O cabeçalho do chat mostra em qual branch você está.

**A barra lateral pode mostrar cada branch de um projeto e mover meu chat quando o agente cria um branch?** Sim, com **Branches na árvore de workspaces** (desligado por padrão): ligue em Configurações → Composer Plus e escolha **Opções de exibição** → **Árvore de workspaces** do dsh. Cada branch com um worktree em `<project>/.worktrees/` aparece dentro do seu projeto. Quando você pede ao agente da pasta do projeto que crie um branch e trabalhe nele, e a pasta não tem alterações não commitadas, o chat vai sozinho para o branch. Apague a pasta do branch e ele sai da lista; os chats dele vão para **Sem grupo**.

**Posso enviar uma foto do meu iPhone?** Sim. Em um chat do Tether, toque em **+** ao lado do campo de mensagem → Camera, Photos (até 4) ou Paste image. As fotos vão para o chat no Mac como anexos da sua mensagem, então o modelo as vê.

**O dsh pode rodar o próximo comando sem perguntar de novo ao modelo?** Sim, com **Etapas planejadas** (desativado por padrão): ative em Configurações → Composer Plus. O modelo pode então planejar os próximos comandos com uma condição, por exemplo “rode os testes quando o build passar”, e o Composer Plus executa uma etapa sem nova chamada ao modelo quando o resultado atende à condição. Aprovações e sandbox continuam iguais.

**De onde vem o skill em turco e posso removê-lo?** De [yucezerey/turkish-anti-ai-skill](https://github.com/yucezerey/turkish-anti-ai-skill) no GitHub (MIT). O Composer Plus o instala só enquanto **Idioma do aplicativo** for Türkçe, guarda só os arquivos Markdown e não executa nenhum script dele. Para removê-lo, desligue **Pacote de skill em turco** em Configurações → Composer Plus: o skill e a cópia baixada são apagados na hora.

**Como relato um bug ou peço um recurso no Composer Plus?** Configurações → Composer Plus → **Relatar uma issue…** (ou o menu **…** de um chat → **Relatar uma issue do Composer Plus…**). Escolha um tipo, descreva-o no seu idioma e clique em **Escrever rascunho**. Confira o rascunho em inglês e depois clique em **Abrir issue**.

**Como o agente pode organizar um código bagunçado?** Digite `/untangle-codebase` em um chat (**Desembaraçar o código**, ativado por padrão), se quiser com uma área, por exemplo `/untangle-codebase src/api`. Primeiro o agente lista as cópias, os vínculos ocultos, os wrappers desnecessários, o código morto e os casos especiais; depois corrige tudo como uma meta e verifica de novo com subagentes. Inicie-a em um chat de **Um branch por chat** para que o trabalho fique no próprio branch.

**Funciona com o app desktop?** Sim: Configurações → Plugins → **Adicionar plugin** → `dsh-composer-plus`. Testado no dsh 0.2.0-rc.2 (desktop e web) e 0.2.1-rc.2 (web).

**Regra para novos recursos:** toda linha de recurso em Configurações → Composer Plus mostra uma captura de tela. Adicione o id do recurso a `SHOT_OF` em `client.js` e a `SHOTS` em `index.js`, e inclua `assets/features/<id>.webp` (feita no dsh de demonstração descartável, com a interface em inglês, com cerca de 60 kB ou menos). Adicione o recurso, com a mesma imagem, ao `docs/features.json` e execute `npm run build:readme`: ele escreve a tabela de recursos do `README.md` e de cada `README.<id>.md` traduzido, e a lista do `llms.txt`. `test/shots.test.mjs` falha quando um recurso não tem captura de tela, e `test/browser-settings-shots.mjs` verifica a página real de Configurações. A lista de verificação completa para cada alteração está em [AGENTS.md](AGENTS.md).

Os testes executam o `client.js` real contra um React/DOM falso e o `index.js` real (parte Host) contra um repositório git temporário. Os testes do gateway do Tether (`test/tether-gateway.test.mjs`) usam um host dsh simulado e um gateway TLS real. O app para iPhone está em `tether/ios` (veja [tether/README.md](tether/README.md) e [tether/AGENTS.md](tether/AGENTS.md)). O [docs/ROUTES.md](docs/ROUTES.md) lista cada rota do Host, a requisição dela e se o Tether pode chamá-la. `node test/browser-history.mjs '<dsh web URL with ?token=…>'` verifica o histórico de entrada em um navegador real, contra um `dsh web` descartável com seu próprio `DSH_HOME`.

Os pacotes de idioma são arquivos JSON só com dados em `locales/<id>.json`, embutidos na entrada única do cliente por `npm run build:locales` (sem serviço de tradução nem download em tempo de execução). `npm test` verifica em cada pacote a cobertura completa das chaves, os placeholders e as quebras de linha idênticos, e o comportamento de idioma do sistema/substituição. Para verificações isoladas no app real com um Playwright instalado localmente:

```sh
PLAYWRIGHT=/path/to/playwright node test/browser-language.mjs /path/to/dsh/lib/bin.js
```
