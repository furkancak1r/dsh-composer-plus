Mejoras de comodidad al estilo de Codex para la interfaz de escritorio y web de [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (dsh): un panel de cambios, ideas de funciones en tarjetas que se deslizan, búsqueda en el texto de los mensajes desde la barra lateral, revertir turnos con restauración de archivos, eliminar chats a la Papelera, el nombre del proyecto debajo del editor, el estado del proyecto en la barra lateral, historial de entrada, un atajo para el modo plan, Continuar con un clic, reanudar los chats en ejecución tras un reinicio, arrastrar y soltar en la cola, enlaces directos a sesiones, exportar el chat como Markdown, permisos de la revisión automática por chat, notificaciones en segundo plano, acceso desde el iPhone con la app Tether y actualizaciones automáticas.

**En una línea:** un único plugin de DeepSeek Harness (npm `dsh-composer-plus`, que aparece como **Composer Plus** en Configuración → Plugins) que añade un panel de cambios de git, tarjetas de ideas de funciones al estilo de Tinder, una búsqueda en la barra lateral que también encuentra palabras dentro de los mensajes, la reversión de turnos con ↶ (solo el chat, o el chat y los archivos), Eliminar chat, el nombre del proyecto debajo del editor, el historial de entrada con ↑/↓, un interruptor de `/plan` con Shift+Tab, ▶ Continuar con un clic, Reanudar tras reiniciar, reordenar la cola arrastrando y soltando, Copiar enlace de sesión, Exportar como Markdown, “Permitir en este chat” para la revisión automática, notificaciones en segundo plano, acceso desde el iPhone (Conexión móvil, app Tether), 11 idiomas adicionales para la interfaz y actualizaciones automáticas.

Plugin comunitario no oficial. La comprobación de actualizaciones hace llamadas de red (las versiones publicadas en GitHub y el registro de npm). Desactiva **Actualizaciones automáticas** para que no se hagan al iniciar. **Paquete de skill en turco** (activado por defecto) descarga turkish-anti-ai-skill de GitHub y busca una versión nueva una vez al día, solo mientras **Idioma de la aplicación** es Türkçe; desactívalo en **Configuración → Composer Plus** para detener estas llamadas. **Ideas de funciones** llama al modelo de tu propio chat solo cuando haces clic en **Sugerir funciones**. **Predicción del siguiente mensaje** (activada de forma predeterminada) llama al modelo elegido en Configuración (el predeterminado de dsh, salvo que elijas otro) una vez después de cada turno terminado, sin ningún clic. Desactívala en **Configuración → Composer Plus** para detener estas llamadas. **Completar al escribir** (desactivado de forma predeterminada) llama al modelo elegido para esta función (de forma predeterminada, el de la predicción) en cada pausa mientras escribes, después de que lo actives. **Mejorar prompt** solo llama a un modelo cuando haces clic en su varita mágica. **Tablero de tareas** llama una vez al modelo del chat nuevo para las etiquetas de cada tarea que inicias en el tablero. Con su ajuste **Resumen con IA** (el predeterminado es **Rápido (sin IA)**), también llama al modelo de un chat en curso para una breve nota de progreso mientras miras el progreso de esa tarea en el tablero o en Tether. **Comprobación del objetivo** (activada de forma predeterminada) llama a un modelo una vez cada vez que el agente marca un `/goal` como completado en una ronda automática. **Conexión móvil** (desactivada de forma predeterminada) acepta conexiones del iPhone desde tu red local o tu tailnet solo después de que la actives.

## Instalación

**App de escritorio:** Configuración → Plugins → **Añadir plugin** → escribe `dsh-composer-plus` → **Activar ahora**.
También puedes pegar `https://github.com/furkancak1r/dsh-composer-plus` en lugar del nombre de npm.

**Perfil web / CLI:**

```sh
dsh plugin --profile web add dsh-composer-plus
```

Después, reinicia dsh. (La CLI no puede instalar en el perfil de escritorio: de eso se encarga la app).

> El pnpm de dsh omite las versiones publicadas hace menos de 24 horas. Justo después de una versión nueva, añade la versión: `dsh-composer-plus@1.25.0`.

Entonces el modelo solo sugiere funciones sobre ese tema; un campo vacío significa cualquier función. ## Configuración

Cada función se puede activar o desactivar por separado en **Configuración → Composer Plus** de dsh. Cada fila tiene una captura pequeña: pasa el puntero por encima para ver una vista previa más grande, o haz clic para abrirla a tamaño completo (`Esc` la cierra). El cuadro **Buscar funciones** de la parte superior filtra la página por nombre o descripción (en cualquier idioma, sin distinguir mayúsculas ni acentos); `Esc` lo vacía. A su lado, **Todas**, **Activadas** y **Desactivadas** muestran todas las funciones, solo las activadas o solo las desactivadas (desactiva **Filtro activadas/desactivadas** para ocultarlos). Cada fila tiene un interruptor y una breve descripción. El pequeño **?** junto al nombre de una fila abre la parte de este README que describe esa función, en el README del idioma de la interfaz de dsh. Los cambios se aplican de inmediato, sin reiniciar, y se recuerdan en ese dispositivo. Todo está activado de forma predeterminada, salvo **Conexión móvil**, **Reanudar tras reiniciar** y **Completar al escribir**. El Host de dsh guarda los interruptores de estas tres funciones y los de **Búsqueda en el contenido**, **Revertir turno**, **Predicción del siguiente mensaje** y **Comprobación del objetivo**, así que se aplican a todas las ventanas y se mantienen tras un reinicio. El Host también guarda el **Modelo** elegido para **Predicción del siguiente mensaje**, el de **Completar al escribir** (por defecto **Igual que la predicción del siguiente mensaje**), el de **Mejorar prompt**, el de **Comprobación del objetivo** (ambos por defecto **Igual que el modelo del chat**) y el **Límite de tiempo** de **Permitir en este chat** (1 hora por defecto). **Búsqueda en el contenido** solo cambia después de reiniciar dsh (dsh la lee al iniciar); hasta entonces, su fila dice **Reinicia dsh para aplicar este cambio.**

## Privacidad y seguridad

- **Continuar:** el endpoint local autenticado solo reanuda el último turno interrumpido, rechaza las peticiones obsoletas o duplicadas y mantiene los hooks de aprobación existentes. No envía un nuevo mensaje del usuario.
- **Reanudar tras reiniciar:** desactivada hasta que la actives. La parte Host solo guarda los ids de los chats y sus horas de inicio en `$DSH_HOME/storages/dsh-composer-plus/resume.json` (permisos solo para el propietario), y nada sale de tu equipo. Solo continúa un chat cuando el propio registro de dsh indica que fue dsh (no tú) quien detuvo su último turno. Las aprobaciones y la revisión automática se aplican al turno continuado como siempre.

- **Panel de cambios:** git se ejecuta en modo de solo lectura en tu equipo, en la carpeta del propio chat, a través del canal `/api` autenticado de dsh. Nunca hace commits, nunca prepara archivos ni ejecuta fetch, y solo muestra las rutas que el propio git listó. El árbol lista hasta 1000 ramas locales y remotas y muestra los 300 commits más recientes de una rama: su línea de primer padre, así que un commit de merge representa los commits que trajo. Nunca cambia de rama (checkout). **Este chat** lee el registro propio del chat para saber qué archivos escribieron sus herramientas de archivos, y los compara con la instantánea de Revertir turno del chat en una carpeta temporal que se elimina al momento; no escribe nada en tu repositorio ni en el almacén de instantáneas.
- **Ideas de funciones:** no se ejecuta nada hasta que haces clic en **Sugerir funciones**. Entonces la parte Host lee solo la carpeta del propio chat (el navegador nunca envía una ruta): los nombres de las entradas del nivel superior, los primeros 6 kB del README, de AGENTS.md y del manifiesto (`package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, …), un esquema del resto del README (títulos, filas de tablas, elementos de listas; 6 kB como máximo) y los títulos de los commits más recientes (`git log --format=%s`, 6 kB como máximo), con un máximo de 28 kB en total. Tether lee y cambia las notas por la misma ruta. **Historial de versiones de la memoria** (activado por defecto) guarda una copia de los archivos de la memoria antes de cada guardado en `memory/history/`, junto a ellos (archivos solo del propietario, las 50 más recientes por memoria); no envía nada a ningún modelo. **Exportar la memoria a AGENTS.md** no envía nada a ningún modelo y solo escribe cuando haces clic en **Escribir AGENTS.md**: lee y escribe `AGENTS.md` en la carpeta del proyecto de esa memoria (solo un archivo normal dentro de ella, nunca a través de un enlace simbólico que salga de ella) y solo cambia su sección marcada. **Buscar notas de memoria obsoletas** no envía nada a ningún modelo y no escribe nada: comprueba las rutas dentro de la carpeta del proyecto con realpath (no lee ningún archivo), lee `package.json` solo como archivo normal dentro de la carpeta y ejecuta allí un `git for-each-ref`. **No usar la memoria en este chat** guarda cada chat que desactivas en `memory-chats.json`, junto a los demás archivos (solo del propietario, los 500 más recientes); ese chat no envía ninguna memoria a su modelo. **Sugerir notas de memoria desde un chat** no envía nada hasta que haces clic en **Sugerir para la memoria**; entonces envía las notas guardadas del proyecto del chat y las notas globales, y los mensajes y respuestas de texto del propio chat (sin salida de herramientas ni mensajes revertidos; la copia del padre en una bifurcación se omite; como máximo unos 24.000 caracteres), al propio modelo del chat, como una petición sin herramientas. Una sugerencia solo se guarda con **Aceptar**.
- **Copia de seguridad:** nada sale de tu equipo. Los archivos comprimidos van a `~/Desktop/dsh-backups` (archivos solo para el propietario). Los secretos no están en un archivo comprimido: los archivos de credenciales (`.credentials.yaml`, `.env`), los archivos de claves (`.pem`, `.key`, `.p12`, `.pfx`) y los valores de los ajustes token, secret, password y API key de los archivos yml se ocultan; sus copias reales se quedan en `composer-plus-vault/<archive>/`, en la misma carpeta (solo para el propietario), solo en este equipo. **Para otro equipo** no copia ningún vault: vuelve a introducir esos secretos allí. Tus registros de chat, tus ajustes y el resto del directorio home de dsh están tal cual en el archivo comprimido: mantén la carpeta privada, igual que el propio `$DSH_HOME`. La copia de seguridad lee los archivos con `O_NOFOLLOW | O_NONBLOCK`; un enlace simbólico se guarda como enlace (nunca se sigue) y un FIFO o un dispositivo se omite. El interruptor y los ajustes de la copia de seguridad automática están en `$DSH_HOME/storages/dsh-composer-plus/auto-backup.json`, el interruptor de la consola de rescate en `rescue-console.json` y, mientras dsh se ejecuta, `running/host-<pid>.json` nombra cada proceso de dsh (la consola de rescate los lee para rechazar una restauración).
- **Consola de rescate:** un menú de terminal; no abre ningún puerto de red. Una restauración solo escribe en una carpeta nueva junto al directorio home de dsh (archivos con `O_EXCL | O_NOFOLLOW`, enlaces simbólicos al final y nunca seguidos) y rechaza un archivo comprimido con un nombre inseguro (`..`, una ruta absoluta), un dispositivo o FIFO, más de una carpeta superior o una entrada bajo un enlace.

## Solución de problemas

- **No hay notificaciones en macOS:** Ajustes del Sistema → Notificaciones → DeepSeek Harness → permitir. Elige Alertas para que se queden en pantalla.
- **Faltan ▶, las asas de la cola, el estado del proyecto, la opción de proyectos recientes, Contraer todos los proyectos, Copiar ruta, el cuadro de búsqueda de proyectos, la predicción del siguiente mensaje, la compleción al escribir, Permitir en este chat o el clic derecho después de actualizar dsh:** estos elementos se enganchan al HTML actual de dsh, porque dsh aún no tiene un espacio para ellos. Si dsh cambia ese marcado, se ocultan solos; nada más se rompe. Por favor, abre una [incidencia](https://github.com/furkancak1r/dsh-composer-plus/issues).
- **«Error al actualizar» o «no se instaló desde npm»:** una copia enlazada desde una carpeta local o renombrada no puede actualizarse sola; reinstala `dsh-composer-plus` desde Configuración → Plugins. En los demás casos, el mensaje muestra la primera línea del error de pnpm; **Buscar actualizaciones** lo vuelve a intentar.
- **Conexión móvil dice que la pasarela no está en ejecución:** "no IPv4 address on en0" significa que este Mac no tiene dirección Wi-Fi ni Ethernet; "EADDRINUSE" significa que otro dsh (u otra app) usa el puerto 19390 o 19391. Solo un dsh a la vez puede ejecutar Conexión móvil.
- **Conexión móvil, Reanudar tras reiniciar o Búsqueda en el contenido dicen «Reinicia dsh»:** el plugin se actualizó mientras dsh estaba en ejecución (o, en el caso de Búsqueda en el contenido, cambiaste el interruptor); el nuevo estado se carga tras reiniciar.
- **La búsqueda solo encuentra títulos:** Búsqueda en el contenido está desactivada, dsh no se ha reiniciado desde que la activaste o instalaste el plugin, o la palabra solo está en la salida de una herramienta (consulta Límites).
- **No hay botón ↶ en mis mensajes:** Revertir turno está desactivado, el chat es un chat de subagente, o dsh-rewind-plugin está instalado (usa su botón ↶). Después de una actualización, reinicia dsh.
- **Chat y archivos aparece en gris:** el proyecto no es un repositorio git, no hay ninguna instantánea de antes de ese mensaje (el mensaje es anterior al plugin, o una de las 50 instantáneas más recientes la sustituyó), o no cambió ningún archivo.
- **Eliminar dice que otro dsh tiene abierto este chat:** un segundo dsh que usa el mismo directorio home de dsh tiene el bloqueo del chat. Cierra esa ventana o ese dsh y vuelve a eliminarlo. Mientras tanto, el chat sigue archivado.
- **Mi iPhone no puede conectarse después de activar «Tailscale only»:** Tailscale debe estar activado en el Mac y en el iPhone. El panel Conexión móvil avisa cuando está desactivado en el Mac. El registro de accesos muestra cada intento rechazado con su motivo.
- **Un chat no continuó tras un reinicio:** Reanudar tras reiniciar estaba desactivado cuando dsh se cerró, detuviste tú mismo ese turno, el turno ya había terminado (completado o fallido), el chat estaba archivado, o había más de 20 chats en ejecución (continúan los 20 más recientes).
- **La cola está vacía tras un reinicio:** el propio dsh vacía la cola al cerrarse. Reanudar tras reiniciar solo la devuelve en un chat que continúa; en los demás chats, envía los mensajes de nuevo. Un mensaje que quitaste justo antes del cierre puede volver: quítalo de nuevo.
- **Abrir issue en GitHub dice «gh could not open the issue»:** el mensaje es la primera línea del propio `gh`. Ejecuta `gh auth status` en una terminal e inicia sesión con `gh auth login`; la carpeta del chat debe tener un remoto de GitHub (`git remote -v`). «not installed or not on the PATH of dsh» significa que dsh no encontró `gh`: instálalo o inicia dsh desde una terminal donde `gh` funcione.
- **Informar de un problema dice «gh could not open the issue»:** el mensaje es la primera línea del propio `gh`. Ejecuta `gh auth status` en una terminal e inicia sesión con `gh auth login`. O haz clic en **Abrir en GitHub en su lugar**: se abre la propia página de nueva issue de GitHub con el borrador ya rellenado, y la envías allí.
- **No hay etiqueta de rama en una fila de chat:** la barra lateral no está en «En una sola lista» (en «Espacio de trabajo» y «Árbol de espacios de trabajo», ninguna fila de chat muestra una etiqueta), el chat no tuvo ningún turno desde que instalaste esta versión, su carpeta no es un repositorio git o **Rama de Git en las filas de chat** está desactivada. Después de una actualización, reinicia dsh (la parte Host registra la rama).
- **Comprobación del objetivo dice que la prueba terminó con el código 127 o «not found»:** dsh iniciado desde el Finder o el Dock puede tener un PATH más corto que tu terminal, así que no encuentra `npm`, `pnpm` ni `cargo`. Inicia dsh desde una terminal, o define tu propio comando de prueba con la ruta completa en **Comprobación del objetivo** → **Editar**. **Ejecutar ahora** muestra el resultado al momento.
- **El objetivo no se cierra y el agente sigue trabajando:** **Comprobación del objetivo** encontró una prueba fallida o trabajo pendiente; la fila bajo el objetivo muestra el motivo (pasa el puntero por el resultado para ver los detalles). Corrige la causa o el comando de prueba, o completa el objetivo tú mismo con `/goal` o con la barra del objetivo (eso no se comprueba).
- **La instalación falla justo después de una versión nueva:** añade la versión (`dsh-composer-plus@1.25.0`); consulta la nota de instalación de más arriba.
- **Hacer copia ahora dice «Ya hay otra acción de copia de seguridad en curso»:** hay una acción en marcha en otra ventana de dsh o en la consola de rescate (comparten un archivo de bloqueo, `.composer-plus.lock`, en la carpeta de copias de seguridad). Espera a que termine. Si no hay ninguna acción en marcha, el siguiente clic toma el bloqueo de un proceso cerrado.
- **La consola de rescate dice «dsh is running»:** primero sal de dsh. Si dsh está realmente cerrado, el archivo que nombra el mensaje quedó de un cierre inesperado: elimínalo y vuelve a intentarlo.
- **Después de una restauración, dsh no se inicia o falta un plugin:** hay que volver a instalar los paquetes de plugins de un perfil. La consola de rescate lo ofrece después de una restauración; o ejecuta `pnpm install` en cada carpeta de `$DSH_HOME/profiles/` que indique. Los secretos que no estaban en el vault (otro equipo) hay que introducirlos de nuevo: la consola los enumera.

## Límites

- Continuar sin mensaje depende del ciclo de vida `agent/pre-step` → `agent/request` de dsh. Vuelve a comprobar la compatibilidad cuando actualices dsh.
- **Ideas de funciones** guarda las tarjetas en memoria para cada chat hasta que dsh o la página se recargan; después, **Sugerir funciones** vuelve a preguntar al modelo. Las tarjetas llegan en el idioma de la interfaz que tiene dsh cuando haces clic; si cambias el idioma, las tarjetas que ya están en el montón conservan el suyo y **Más ideas** usa el nuevo. El modelo solo ve el breve resumen del proyecto, no el código, así que una idea puede repetir algo que el proyecto ya tiene: omítela. El nuevo chat solo se ejecuta en modo plan cuando el perfil tiene el comando `/plan` de dsh; si no, la idea se envía como un primer mensaje normal. La lista **Después** pertenece a la ruta de la carpeta del chat: la misma carpeta abierta a través de un enlace simbólico tiene su propia lista. Guarda como máximo 50 ideas por proyecto (quita una para añadir más) y cada título solo una vez. Arrastrar una tarjeta solo decide entre izquierda y derecha; usa **↓** para guardarla y **▶** para crearla ahora. Una repetición se detecta solo por su título: el modelo aún puede sugerir una idea anterior con otro nombre; omítela. Cuando el modelo responde solo con ideas anteriores, no aparece nada nuevo: vuelve a hacer clic. Un tema de enfoque muy concreto hace que esto pase más a menudo; usa un tema más amplio o quítalo. El tema de enfoque se queda en el campo de cada chat hasta que dsh o la página se recargan.
- **Exportar chat como Markdown** incluye solo tus propios mensajes y las respuestas de texto del asistente: se quedan fuera las llamadas a herramientas y su salida, el razonamiento, las imágenes (una línea `[image]` las marca), el contexto oculto y los mensajes que Revertir turno o dsh-rewind-plugin quitaron. Las respuestas de un mismo turno se unen en una sola sección. Una exportación incluye como máximo unos 4 millones de caracteres; de un chat más largo se exporta su primera parte y una nota.
- **Reanudar tras reiniciar** continúa el turno; no lo repite. Una llamada a herramienta que estaba en ejecución al cerrar termina con el resultado “outcome unknown” de dsh, y se le indica al modelo que no repita el trabajo terminado, pero un comando que no es seguro ejecutar dos veces puede volver a ejecutarse. Los subagentes, las aprobaciones y las preguntas que estaban abiertos no se restauran: su chat padre continúa y vuelve a preguntar. Como máximo continúan 20 chats en cada inicio.
- **Reanudar tras reiniciar** y la cola: dsh vacía la cola de un chat al cerrarse. El plugin devuelve tus mensajes en cola a partir del registro del chat, con su orden, sus ediciones, imágenes y archivos; se ejecutan después del turno reanudado. Solo los chats que continúan recuperan su cola (interruptor activado y cierre durante el turno). dsh registra igual que quites tú los últimos mensajes de la cola: si los quitas y dsh se cierra antes de que empiece el paso siguiente, vuelven.

- **Búsqueda en el contenido** es la búsqueda propia de dsh, así que tiene los límites de dsh. Solo busca en los mensajes del usuario y del asistente: no busca en la salida de las herramientas (comandos, contenido de archivos, resultados) ni en el razonamiento, y no tiene ningún filtro por mensajes del usuario, del asistente o de herramientas. Coincide con palabras completas, no con partes de una palabra (`deploy` no encuentra `deployment`); las letras con acento coinciden sin él (`seker` encuentra `şeker`). Muestra una fila por chat, con el fragmento de 240 caracteres de dsh, y como máximo 20 filas.
- **Búsqueda en el contenido**: coste medido en una copia de 247 registros de chat reales (159 MB, dsh 0.2.1-rc.2, Apple Silicon, 32 GB). La primera búsqueda tras un inicio crea el índice en unos 15 s. Durante ese tiempo, el Host de dsh no responde a nada durante unos 7 s, así que los demás chats dejan de transmitir en ese momento (la página en sí no se congela). La memoria del Host crece en torno a 1,1 GB en el pico; un minuto después sigue unos 0,5–0,6 GB por encima del inicio, hasta que dsh se cierra. El archivo de índice ocupa unos 165 MB. Las búsquedas posteriores tardan unos 0,5 s. Tras un reinicio, la primera búsqueda tarda aproximadamente 1 s (solo se añaden los chats nuevos o cambiados) y añade unos 70 MB. Desactívala si tu equipo tiene poca memoria.
- **Búsqueda en el contenido** solo se aplica después de reiniciar dsh, y todos los dsh que usan el mismo directorio home de dsh comparten el archivo de índice: ejecuta solo uno de esos dsh a la vez (dsh permite un único propietario por archivo de índice).
- **Revertir turno** solo restaura archivos en un repositorio git, y solo en la carpeta del chat. Conserva las 50 instantáneas más recientes de cada chat. Los archivos ignorados (`.gitignore`, `info/exclude`, tu archivo global de ignorados), las carpetas vacías, los enlaces simbólicos y los submódulos no se restauran; un archivo que estaba ignorado cuando se tomó la instantánea nunca se elimina, aunque el turno haya cambiado las reglas de ignorado. Un archivo que git no puede leer queda fuera de la instantánea. Cada uno de tus mensajes ejecuta un `git add --all` de la carpeta del chat en el almacén privado: en una carpeta muy grande con muchos archivos sin seguimiento, esto puede tardar unos segundos, y la siguiente llamada a herramienta lo espera (como máximo 10 s; después, la instantánea termina en segundo plano). Si el `git gc` de tu repositorio elimina un objeto que necesita una instantánea antigua, ese archivo aparece como no restaurado. Solo vuelve al editor el texto del mensaje: añade otra vez sus imágenes o archivos. Los chats de subagentes no tienen ↶ (los cambios de archivos de un subagente cuentan como cambios del chat que lo inició). El chat exportado (`/export`) sigue teniendo los mensajes retirados. La idea de un marcador oculto que retira parte de un chat viene de [dsh-rewind-plugin](https://github.com/SiriLee/dsh-rewind) de SiriLee (MIT); Composer Plus no usa nada de su código.
- **Eliminar chat** necesita el archivado de dsh (dsh 0.2.0 y posteriores). Un chat (o uno de los chats de sus subagentes) que no se detiene en 15 s, o que tiene abierto otro dsh, sigue archivado y no se mueve nada. En sistemas distintos de macOS, la carpeta de la papelera tiene que estar en el mismo disco que el historial de chats. Un chat abierto que eliminas se queda en la memoria de dsh, archivado y oculto, hasta que dsh se reinicia. Vacía tú la Papelera; dsh no lo hace.
- La cola de dsh no tiene una acción `move`, así que la parte Host del plugin mueve el propio mensaje dentro de la cola de dsh (un solo cambio, el mismo mensaje). Los mensajes con imágenes o archivos también se mueven. Solo se mueven tus propios mensajes: una ronda de un objetivo o una respuesta a una pregunta en la cola se queda donde está. Si un mensaje empieza a enviarse mientras arrastras, no se mueve nada y un aviso lo indica.
- dsh 0.2.1 carga una actualización de inmediato cuando la nueva versión no cambia ningún ajuste de dsh; en caso contrario, y en dsh 0.2.0, reinicia dsh para cargarla. El plugin nunca reinicia dsh por ti. Los perfiles web/CLI sin el gestor de plugins de dsh solo avisan de que hay una versión nueva.
- **Novedades de Composer Plus N** muestra las notas en el idioma de **Idioma de la aplicación**. Un idioma de interfaz con otra región recibe las notas de su idioma base (`en-GB` recibe las notas en inglés y `zh-TW`, las notas en chino de `zh`). Un idioma sin notas (uno que añade otro paquete de idioma, o `pt-PT`, que no es `pt-BR`) muestra las notas en inglés. Las notas llegan con la nueva versión. Si la copia en ejecución no tiene un archivo de notas legible (`release-notes.json`), la ventana muestra las notas en inglés de GitHub.
- Una versión que se instala mientras dsh se ejecuta (una actualización desde Configuración → Plugins o una carpeta copiada) se carga solo tras reiniciar dsh: hasta entonces, **Actualizaciones de Composer Plus** muestra la versión en ejecución y pide reiniciar. Su ventana **Novedades de Composer Plus N** aparece una vez en el primer inicio de esa versión. El primer inicio después de instalar este plugin no muestra ninguna ventana; **Novedades de esta versión** abre las notas de la versión en ejecución.
- La línea de la estrella de GitHub bajo las notas no puede saber si ya diste una estrella al repositorio: el plugin no hace ninguna llamada de red para eso. Cada navegador (y la app de escritorio) guarda su propio registro, así que la línea puede aparecer una vez más en otro.
- **Rechazar con nota** envía la nota como un mensaje dentro del turno que espera y después rechaza la solicitud; dsh muestra la nota en el chat como un mensaje tuyo. Mientras el campo de la nota está abierto, la tarjeta muestra solo **Cancelar** y **Rechazar**, así que un clic no puede permitir la solicitud por error; `Esc` o **Cancelar** devuelve los botones de dsh. Una nota vacía no envía nada (usa el propio **Rechazar** de dsh). Si el rechazo falla después de enviar la nota (por ejemplo, porque mientras tanto la solicitud se respondió en otro lugar), la nota se queda en el chat y el modelo la lee en su siguiente paso. El botón va en el marcado de la tarjeta de aprobación de dsh (`data-approval-key`), porque dsh no tiene un espacio para acciones de la tarjeta; si una actualización de dsh cambia ese marcado, el botón no aparece y el propio **Rechazar** de dsh funciona como antes. Una nota puede tener como máximo 4.000 caracteres.
- **Entrada secreta** oculta solo el texto exacto de un valor: `[secret]` lo reemplaza en los resultados de herramienta posteriores del mismo chat. El agente aún puede leer el archivo con un comando de shell e imprimir el valor de otra forma (base64, una parte, con espacios), y esa forma llega al modelo. Las herramientas de archivos del propio agente (read, grep, write, edit) no pueden abrir la carpeta de secretos. Si el valor también es una palabra común, otros resultados de ese chat también muestran `[secret]`. El archivo se mantiene hasta que termina el turno; si dsh se cierra durante el turno, el siguiente inicio lo borra. Un chat puede tener una sola solicitud abierta a la vez. La herramienta añade unos 870 caracteres (unos 220 tokens, estimado) a cada solicitud al modelo: desactívala si no la usas.
- **Citar en la respuesta** cita el texto tal como lo muestra la página: un bloque de código, una tabla o una lista llegan como líneas simples, sin sus marcas de Markdown. Una selección que empieza en una respuesta y termina en otra, o que toca el razonamiento, una fila de herramienta o tu propio mensaje, no muestra el botón: selecciona dentro de una sola respuesta. El botón encuentra la respuesta por la estructura del chat de dsh, porque dsh no tiene un slot para la selección de texto; si una actualización de dsh cambia esa estructura, el botón no aparece. Cuando la cita queda al final del campo, se añade una línea vacía más para que la siguiente línea que escribas empiece debajo; dsh quita las líneas vacías del final al enviar.
- **Citar desde la vista previa del archivo** lee la propia vista previa de archivos de dsh: los números de línea vienen de sus filas, así que son correctos para archivos de código y de texto. Un archivo Markdown se muestra como una página con formato, así que su cita tiene el texto sin sus marcas de Markdown y sin números de línea; la cita de un PDF tiene la página, no una línea. Una selección en el encabezado de la ruta, en otro visor (una hoja de cálculo, un archivo de Office, una imagen) o sobre dos archivos abiertos no muestra el botón, y tampoco lo muestra la barra lateral derecha en pantalla completa (entonces el campo de texto no está en pantalla). El botón encuentra la vista previa por la estructura de la página de dsh, porque dsh no tiene un slot para una selección ahí; si una actualización de dsh cambia esa estructura, el botón no aparece. Solo el texto seleccionado va al campo de texto: si el archivo cambia después, la cita no cambia.
- **Chat lateral** es de solo lectura gracias al modo de solo lectura de dsh: las herramientas de archivos no pueden escribir y los comandos de shell se ejecutan en el sandbox de dsh sin escritura (o no se ejecutan cuando el sandbox no puede iniciar). El agente aún puede pedir más acceso con la tarjeta de aprobación de dsh, y una llamada de red (por ejemplo, una solicitud a una API) aún puede cambiar algo fuera del equipo. La copia se hace en el momento más reciente en que no esperaba ningún mensaje en la cola, así que una pregunta hecha mientras esperan mensajes en la cola no ve lo que pasó después de ellos. Un paso del chat en curso se cierra en la copia, así que el chat lateral conoce el inicio de ese paso pero no su resultado. El chat lateral es un chat normal: queda en la barra lateral y cuenta para tu uso del modelo; archívalo allí. Traer de vuelta toma solo los mensajes propios del chat lateral (máximo 12.000 caracteres) y solo la última respuesta de cada pregunta; las notas del agente entre sus llamadas a herramientas quedan fuera. dsh no ofrece a los plugins un espacio para un chat dentro de la barra lateral derecha, así que el chat lateral se abre en la vista principal.
- **Notas del diff** funciona solo en el panel de cambios, no en la vista Último turno de dsh. Un rango debe quedar en un solo bloque del diff (una parte `@@`). Las notas se guardan en el almacenamiento de este navegador, así que otro navegador o dsh en otro equipo no las ve; Tether guarda sus propias notas en memoria. Una nota guarda las líneas como estaban al hacer clic: si el agente cambia el archivo después, la nota sigue mostrando las líneas y los números anteriores. Como máximo 50 notas por chat, 2.000 caracteres por nota y 40 líneas por nota (luego una línea `…`).
- **Permitir en este chat** cuenta el límite de tiempo desde el momento en que se concede el permiso. Un nuevo límite de tiempo se aplica al instante a los permisos vigentes, así que uno más corto puede terminarlos al instante. Los permisos de la versión 1.12 y anteriores no tienen hora: después de la actualización, el agente vuelve a preguntar una vez por esas herramientas.
- **Mantener el foco en el editor** solo devuelve el foco después de un comando `/` o una skill. Mientras dsh resuelve el comando, el editor queda en solo lectura unos milisegundos, así que las teclas que pulses en ese tiempo se pierden. Si el menú `/` de dsh sigue abierto, `Enter` elige la fila resaltada y no envía.
- **Ajustar la tarjeta de pregunta a la ventana** cambia solo la tarjeta de pregunta de dsh, no la tarjeta de revisión del plan. Una variable o un alias que nombra el comando (`CMD=npm; $CMD publish`), una función de shell, un archivo de script que escribe el agente, otro programa (`python -c`, `node -e`, `make`), una herramienta MCP y tu propia terminal aún pueden ejecutarlo. Una regla puede coincidir con más de lo que quieres: cualquier palabra de un comando puede ser el nombre del comando (`echo npm publish` coincide con `npm publish`), y puede haber otras palabras entre las palabras de la regla (`git push --force` también coincide con `git push origin main --force`). Alarga una regla cuando coincida con demasiado. **preguntar antes** necesita un chat que pueda preguntar: en un chat cuya política de aprobación es never (por ejemplo, un subagente delegado), dsh no puede mostrar la tarjeta, así que la llamada se rechaza con el motivo. La tarjeta de aprobación muestra el motivo en inglés. **Permitir en este chat** no responde a una tarjeta de **preguntar antes**.
- **Continuar en un chat nuevo** envía el chat (mensajes, llamadas a herramientas y el final de cada resultado de herramienta, como máximo unos 60.000 caracteres, la parte más reciente) al modelo del propio chat. La nota de traspaso puede omitir una decisión o un archivo: léela antes de empezar. El chat nuevo solo conoce la nota y el chat enlazado (dsh adjunta el chat anterior como contexto de solo lectura); su contexto del modelo empieza pequeño y el chat anterior se queda como está. Solo una nota o un inicio por chat a la vez.
- **Desglose del contexto** muestra estimaciones con la regla propia de dsh (unos 4 caracteres por token), la misma regla que usa el anillo de contexto de dsh; el recuento propio del modelo puede ser distinto. Las definiciones de herramientas son las de la petición más reciente. Muestra el contexto tal como lo tiene el registro del chat; un turno que se está ejecutando aparece después de su siguiente paso.
- **Pasos planificados** ahorra tokens solo cuando el modelo planifica: mientras está activada, cada solicitud lleva la herramienta `plan_next_steps` y una instrucción breve (unos 500 tokens), también en los chats donde el modelo nunca planifica. Una condición prueba solo lo que dice (por ejemplo: el código de salida de la compilación fue 0), no que el trabajo sea correcto. `ok` lee las marcas de resultado propias de dsh (`[exit code: N]`, tiempos de espera, rechazos del sandbox); un comando que falla sin un código de salida distinto de cero pasa. Los pasos se ejecutan de uno en uno; dos pasos listos a la vez vuelven al modelo. El mensaje del paso se guarda como un mensaje del asistente del modelo del chat (dsh no tiene una marca para un mensaje escrito por un plugin), por eso su texto dice que Composer Plus lo ejecutó. No está en Tether.
- **Paquete de skill en turco** instala un skill de terceros: sus reglas vienen del repositorio de GitHub de su autor, no de Composer Plus, y una versión nueva se usa desde la siguiente comprobación diaria sin que la revisemos. La comprobación demuestra que los archivos son los que GitHub lista para ese commit, no que las reglas sean buenas. El modelo decide cuándo cargar el skill (también puedes llamarlo por su nombre); las reglas solo se aplican a textos en turco. La parte Host usa el idioma que un navegador informó por última vez: si dos navegadores usan idiomas distintos, gana el más reciente. GitHub permite 60 llamadas a la API por hora sin iniciar sesión; una comprobación rechazada conserva la copia instalada y muestra el motivo en la configuración.
- **Desenredar el código** incluye una copia fija de la skill (caldoai/skills, commit f3cf477): un cambio en el original solo llega con una nueva versión de Composer Plus. La skill ejecuta un objetivo largo que puede cambiar muchos archivos, y sus subagentes y comprobaciones gastan muchos tokens. Donde el proyecto no tiene pruebas, puede cambiar el comportamiento sin avisar: iníciala en una rama y lee el diff antes de fusionar. Una skill con el mismo nombre en el proyecto, en una carpeta de skills personalizada o en `~/.dsh/skills` la sustituye. Mientras el interruptor está apagado, `/untangle-codebase` llega al modelo como texto normal.
- **Tablero de tareas** muestra los chats que dsh lista en esta ventana: un chat fuera de un proyecto solo aparece en **Todos los proyectos**, y una carpeta de «Una rama por chat» (`<project>/.worktrees/<name>`) cuenta como su proyecto. La columna de una tarjeta es el estado en vivo del chat, así que las tarjetas no se pueden arrastrar: un chat pasa a **Hecho** cuando termina su turno, también después de un error o una detención, y vuelve a **En curso** cuando se ejecuta de nuevo. El punto verde es el propio punto de terminado de dsh, que dsh solo guarda en esta ventana: después de recargar, los chats terminados aparecen sin él. **Hecho** muestra los 50 chats más recientes (**Mostrar N más antiguas** muestra el resto). **Buscar proyectos** encuentra un proyecto solo por su nombre, no por la ruta de su carpeta. **Activos en las últimas 2 horas** oculta un proyecto cuando todos sus chats tienen más de 2 horas, están inactivos y leídos; el tablero sigue mostrando el proyecto que elegiste. **Nueva tarea** solo recuerda el chat nuevo más reciente de esta ventana: cuando abres otro chat antes del primer mensaje, ese chat se queda en la parte superior de **En curso** como **Nueva tarea** hasta que escribas en él, pero el tablero vuelve por sí solo únicamente para el más reciente. Después de recargar, un chat nuevo sin mensajes no está en el tablero (dsh lo guarda como su Nueva sesión vacía). Las etiquetas vienen de una llamada al modelo por cada tarea, a partir de su primer mensaje: pueden ser incorrectas, y un chat que no iniciaste en el tablero no tiene ninguna. El título es el propio título del chat en dsh (el servicio de títulos de dsh, con el modelo del chat); hasta que llega, la tarjeta muestra la primera línea del primer mensaje. **×** y **Limpiar todo** solo quitan tarjetas del tablero: no se borra ningún chat. **Deshacer** solo aparece durante 8 segundos, en esta ventana; después, **Quitadas (N)** → **Volver a poner** devuelve una tarjeta, y un chat que vuelve a ejecutarse regresa por sí solo. **Limpiar todo** pregunta primero y quita las tarjetas terminadas y leídas del proyecto que se muestra (de todos los proyectos con **Todos los proyectos**), también las que están detrás de **Mostrar N más antiguas**; una tarjeta sin leer (verde) se queda. dsh guarda su punto verde solo en esta ventana, así que después de recargar, Limpiar todo puede quitar una tarjeta cuya respuesta no leíste. La lista se guarda en este Mac para todas las ventanas y para Tether; cuando llega a 5.000 chats, los más antiguos vuelven. **Responder** solo responde la solicitud más reciente del chat: cuando el chat la respondió en otro lugar (otra ventana, Tether, la revisión automática) o pregunta algo nuevo, el panel lo indica y no envía nada. Las versiones anteriores tenían una lista de tareas con comentarios y herramientas para agentes; ya no existen, y el antiguo `board.json` no se muestra. La idea y el aspecto vienen de [Kanzo](https://github.com/emanuele-em/kanzo), de emanuele-em (AGPL-3.0); Composer Plus no usa su código. `Cmd+Shift+K` es un atajo de dsh: en un navegador en Linux no tiene tecla predeterminada (asígnala en la página de atajos de teclado de dsh), y una extensión del navegador u otra aplicación puede tomarla antes. Una tarjeta sale de **Hecho** cuando desaparece el punto verde de dsh (abriste el chat) o, para un chat que terminó detrás del tablero mientras era el chat abierto, cuando ese chat se muestra sin un panel encima. Este estado de leído vive solo en esta ventana de dsh, como los puntos de dsh: tras recargar o en otra ventana, cada chat terminado cuenta como leído, así que está en **Terminados hace poco**.
- **Asistente** tiene un solo chat para todas las ventanas de este Mac. Se ejecuta con el modo de permisos workspace-write: solo escribe archivos en `~/Assistant`, y un comando fuera de esa carpeta pregunta primero. Cuando cambias el chat a un modo sin aprobaciones (Acceso completo), dsh rechaza cada aprobación, así que el asistente no puede enviar, iniciar, detener ni archivar un chat. La tarjeta de aprobación solo protege las seis herramientas: un comando de shell del asistente aún puede llegar a la red, como en cualquier chat con ese modo. En dsh 0.2.0 y 0.2.1, las herramientas de programación de dsh solo ven los recordatorios del propio chat del asistente, no las automatizaciones de otros chats; desde dsh 0.2.2, listan y cambian todas las tareas programadas. chats_list deja fuera los chats archivados, vacíos y de subagentes, y el propio chat del asistente; «esperándote» significa una aprobación, una pregunta o una revisión de plan abierta en un chat en ejecución. chat_read da los mensajes del usuario y las respuestas del agente (sin la salida de las herramientas), como máximo 50 mensajes y unos 24.000 caracteres. chat_archive rechaza un chat que aún se ejecuta o que tiene recordatorios activos. Un texto que el modelo lee aún puede engañarlo: la tarjeta de aprobación es la última comprobación, así que léela antes de hacer clic en **Permitir una vez**. Los temas en paralelo usan la herramienta de subagentes de dsh: un perfil o un modo de permisos sin ella mantiene el comportamiento anterior (un tema a la vez; el siguiente mensaje espera en la cola o guía el turno en ejecución). El modelo decide qué cuenta como una tarea larga, así que una pregunta corta aún puede ocupar un turno. El subagente de cada tema se ejecuta con sus propios tokens; cuando dsh se reinicia, un tema en ejecución se detiene (su resultado no vuelve). Un resultado vuelve como un nuevo turno del chat del asistente, así que espera mientras escribes en medio de un turno.
- **Asistente separado de los chats** y **Solo mensajes en el Asistente** ocultan las filas propias de dsh con una regla de estilo, que las encuentra por el marcado de la barra lateral y del chat de dsh (`data-row-key`, `data-chat-flow-kind`): cuando una actualización de dsh cambia ese marcado, el chat del asistente vuelve a aparecer en la lista, o sus pasos de trabajo vuelven a aparecer. Las filas se ocultan, no se eliminan: la navegación con el teclado de dsh en la barra lateral aún puede llegar a una fila oculta. **Asistente siempre libre** rechaza cada llamada a herramienta del chat del asistente que no sea una de sus herramientas cortas; entonces el modelo da el paso a un subagente, pero puede intentar primero la llamada rechazada, lo que cuesta un paso del modelo. Mientras una tarjeta de aprobación te espera, el chat del asistente sigue contando como ocupado. Cuando su solicitud más reciente no tiene la herramienta de subagentes (un modo de permisos o un perfil sin ella), la regla no hace nada. **Avisos de chats en el Asistente** inicia un turno del modelo en el chat del asistente por cada grupo de avisos, así que usa tokens; con **Conexión móvil (iPhone)** activada, tu teléfono puede recibir dos notificaciones por un chat terminado (la del propio chat y la del asistente). Los avisos que esperan se pierden cuando dsh se reinicia. Solo ve los chats de este Mac.
- **Prioridad al mensaje enviado tras Detener** solo actúa después de que detienes el chat (o tras un turno que falló, o al abrir un chat que aún tiene cola): un mensaje que envías mientras un turno se ejecuta sigue esperando al final de la cola. Solo pasa por delante de tus propios mensajes en cola: si en la cola espera una ronda de un objetivo o una respuesta a una pregunta, se mantiene el orden de dsh. Lee una parte de dsh que no es una API pública (si el turno detenido aún está terminando); si una actualización de dsh le cambia el nombre, el mensaje pasa delante solo cuando ese turno ha terminado. Los chats de subagentes mantienen el orden de dsh.
- **Memoria del proyecto** pertenece a la primera carpeta del chat (la carpeta de proyecto de dsh): un chat que cambia de carpeta con `cd` conserva la memoria de su primer proyecto, y la misma carpeta abierta por otra ruta a los mismos archivos la comparte. Un chat congela su sección de memoria al empezar, así que una nota guardada después aparece desde el chat siguiente (`memory_recall` la encuentra al momento). La revisión solo guarda lo que el modelo decide guardar: puede pasar por alto un dato o guardar uno erróneo; revísalas en **Abrir memoria** y cámbialas allí, o edita los archivos a mano con dsh cerrado. **Abrir memoria** envía las notas del proyecto seleccionado y las notas globales (todos los proyectos si seleccionas Todas las notas; como mucho unos 60.000 caracteres, el resto solo se cuenta y no puede cambiar en esa solicitud) y tu texto al modelo predeterminado de dsh, no al modelo del chat. Una vista previa se guarda en el Mac 30 minutos y hasta que dsh se reinicia; si una revisión o el agente cambian las notas mientras tanto, **Aplicar** se niega y vuelves a pedir la vista previa. **Aplicar** guarda todos los cambios de una vista previa o ninguno: si un cambio no se puede guardar (por ejemplo, MEMORY.md está lleno), las notas quedan como estaban y se muestra el motivo. Cada turno terminado con un mensaje tuyo cuesta una llamada al modelo; una llamada fallida vuelve a leer los mismos mensajes después del turno siguiente. Los chats de subagentes no se revisan. La idea y el formato de archivo vienen de [DS Bot](https://github.com/Fei2411/DS-Bot) (Apache-2.0); Composer Plus no usa su código y nunca lee ni escribe la memoria propia de DS Bot.
- **Historial de versiones de la memoria** conserva las 50 versiones más recientes de cada memoria (cada proyecto y la memoria global); las más antiguas se borran. Una versión guarda toda la memoria de ese proyecto, no una nota. **Restaurar** devuelve todos los archivos de esa versión (temas incluidos) y se niega si la memoria cambió después de abrir la versión; la memoria anterior a la restauración pasa a ser una versión nueva, así que puedes deshacerla. Con el interruptor desactivado no se guardan versiones nuevas y **Restaurar** se niega; las versiones guardadas se quedan. No hay versiones de antes de esta función: el historial empieza con el primer guardado tras instalarla.
- **Exportar la memoria a AGENTS.md** escribe solo las notas de la memoria de un proyecto; las notas globales, las fuentes y las fechas no se incluyen. La siguiente exportación sustituye toda la sección marcada, así que un cambio que hagas a mano dentro de ella se pierde (el diff lo muestra antes); el texto fuera de las marcas se queda. Si las marcas están rotas (falta una o están dos veces), la exportación se niega hasta que las corrijas. Se rechazan un AGENTS.md de más de 512 kB, un enlace simbólico que sale de la carpeta del proyecto y todo lo que no sea un archivo normal. Si AGENTS.md o las notas cambian tras la vista previa, **Escribir AGENTS.md** se niega y vuelves a exportar.
- **Enlace de origen de las notas de memoria** funciona con las notas guardadas después de instalar esta versión: una nota más antigua solo indica su chat (o nada), así que **Origen** solo abre el chat o no aparece. Si el mensaje ya no está (una reversión lo retiró o se borró el chat), el chat se abre y un aviso dice que el mensaje no está.
- **Copiar la memoria a otro proyecto** copia como máximo 100 notas a la vez y solo a un proyecto que dsh lista (lee la propia lista de proyectos de dsh; ninguna ruta viene de la ventana). Cada copia es independiente: un cambio posterior en una nota de un proyecto no cambia la copia. Si una nota marcada no cabe (el MEMORY.md o el tema de destino está lleno, o ya tiene 40 temas), no se copia nada. Una nota cuyo texto y tema ya están en el destino se omite, y el recuento dice cuántas.
- **Buscar notas de memoria obsoletas** solo encuentra lo que una nota escribe de una forma que conoce: una ruta en un fragmento de código (`src/cart.ts`), un script de npm tras `npm run` (o `npm test`, `pnpm lint`), un nombre de rama en un fragmento de código junto a la palabra "rama". Una ruta que sale de la carpeta del proyecto no se informa; un script solo se comprueba si el proyecto tiene `package.json`, una rama solo en un repositorio git. Comprueba como máximo 200 cosas a la vez. Un aviso significa "no se encuentra ahora", no "incorrecto": también se informa de un archivo que una compilación crea después.
- **No usar la memoria en este chat** actúa desde la siguiente petición al modelo de ese chat: una petición que ya está en curso conserva lo que tiene. Cambiarlo en un chat en marcha cambia su prompt de sistema una vez, así que esa petición no puede usar la caché del proveedor del modelo. Un subagente sigue a su chat raíz. La revisión no lee los mensajes que un chat recibe mientras su memoria está desactivada, tampoco si la vuelves a activar después. En dsh 0.2.0 la pantalla de chat nuevo no tiene sitio para el botón: aparece en la cabecera del chat tras el primer mensaje.
- **Sugerir notas de memoria desde un chat** muestra como máximo 10 sugerencias y las guarda 30 minutos y hasta que dsh se reinicia; después, al aceptar se te pide volver a sugerir. Un chat largo envía sus mensajes más recientes: las respuestas más antiguas del agente salen primero. Una sugerencia puede ser errónea: léela antes de aceptarla y usa **Abrir memoria** para cambiar una nota después. Una sugerencia rechazada puede volver en el siguiente clic.
- **Copia de seguridad** usa una sola carpeta fija, `~/Desktop/dsh-backups` (la predeterminada de dsh-backup, para que sus archivos comprimidos sigan sirviendo); no hay ningún ajuste para otra carpeta. Un archivo comprimido ocupa más o menos lo mismo que el directorio home de dsh sin `cache/` ni `dsh-runtimes/` (medido: 1,6 GB de archivos dieron un archivo comprimido de 830 MB en unos 30 s en Apple Silicon; dsh siguió respondiendo). El ocultamiento encuentra un secreto en un archivo yml por el nombre de su clave en una línea (`token:`, `apiKey:`, …); un secreto en un mapa de flujo (`{token: x}`), en una lista bajo una de esas claves, en un archivo JSON (por ejemplo, la `apiKey` de un servidor MCP en un archivo `.json`) o con otro nombre se queda en el archivo comprimido. Los archivos comprimidos de dsh-backup nunca se eliminan: quítalos con **Eliminar**. Mientras dsh-backup siga instalado, cuenta los archivos comprimidos de Composer Plus en su propio número de copias que conserva y puede eliminarlos.

El anterior se queda a su lado como `.dsh.pre-restore-<time>` hasta que lo elimines, así que el disco necesita espacio para los dos. Los chats conservan las rutas de sus proyectos: en otro equipo, un proyecto en otra ruta aparece como ausente hasta que vuelvas a añadirlo. Los enlaces simbólicos que apuntan fuera del directorio home de dsh (por ejemplo, skills enlazadas desde otra carpeta) vuelven como enlaces; sus destinos deben existir en ese equipo.
- **Comprobación de registros de sesión** lee el registro más reciente de cada chat con las propias reglas de dsh sobre lo que se abre: una línea que no es JSON o que está fuera de orden solo cuenta como daño cuando después viene un final de turno (si no, dsh abre el chat sin las líneas desde ese punto, así que no aparece en la lista). No comprueba los eventos de un registro con las reglas de eventos del propio dsh, así que un registro que considera sano puede no abrirse después de una actualización de dsh. Una reparación toma la copia de una copia de seguridad: los mensajes posteriores a esa copia de seguridad se pierden en ese chat (el archivo dañado se queda a su lado). Un chat abierto en este dsh no se repara en Configuración: dsh lo tiene retenido.

- **Recordar el tamaño de la ventana** funciona solo en la app de escritorio. ## Preguntas frecuentes

**¿Cómo añado un panel de cambios / diff de git a DeepSeek Harness?** Instala `dsh-composer-plus` y luego ve a barra lateral derecha → `+` → **Cambios**.

**¿Puede dsh sugerir funciones para mi proyecto, deslizando tarjetas como en Tinder?** Sí: barra lateral derecha → `+` → **Ideas de funciones** → **Sugerir funciones**. Desliza a la derecha para iniciar un nuevo chat que planifique la función, haz clic en **▶ Crear ahora** para iniciar un chat que la cree enseguida sin plan, o desliza a la izquierda para omitirla.

**¿Puede la búsqueda de la barra lateral de dsh encontrar un chat por una palabra de sus mensajes, no solo por su título?** Sí, con **Búsqueda en el contenido** (activada de forma predeterminada): reinicia dsh una vez después de instalar el plugin y usa la lupa junto a **Espacios de trabajo**. Los chats que coinciden muestran el texto alrededor de la palabra.

**¿Puedo deshacer un turno y editar mi prompt, como en OpenCode o Claude Code?** Sí, con **Revertir turno**: haz clic en **↶** en el mensaje, elige **Chat y archivos**, edita el texto que vuelve al editor y envíalo.

**¿Puedo eliminar un chat en lugar de archivarlo?** Sí, con **Eliminar chat**: **…** → **Eliminar…**. El historial va a la Papelera, así que un error se puede deshacer.

**¿Cómo veo a qué proyecto pertenece un chat?** Mira la fila que hay debajo del editor: con **Nombre del proyecto en el compositor** (activada de forma predeterminada) empieza con el nombre del proyecto. Pasa el puntero por encima para ver la ruta de la carpeta.

**¿Cómo tengo historial de mensajes con ↑/↓ en el editor de dsh?** Instala este plugin; con el editor vacío, `↑` / `↓` recorren los mensajes que enviaste.

**¿Cómo continúo un turno de dsh detenido o fallido sin escribir «continúa»?** Con este plugin, el botón de enviar se convierte en **▶** después de un turno detenido, fallido o cortado; un clic lo reanuda.

**¿dsh sigue con los chats en ejecución después de cerrarlo y volver a abrirlo?** No por sí solo: dsh marca ese turno como interrumpido y espera (un objetivo también espera a `/goal resume`). Activa **Configuración → Composer Plus → Reanudar tras reiniciar**: los chats que estaban trabajando cuando dsh se cerró continúan solos en el siguiente inicio.

**¿Qué modelo escribe la predicción?** El modelo que eliges en **Configuración → Composer Plus → Predicción del siguiente mensaje → Modelo**. La lista es la propia lista de modelos de dsh. **Predeterminado de dsh** sigue el modelo predeterminado de dsh. Si dsh ya no muestra el modelo elegido, la predicción usa el predeterminado. **Completar al escribir** tiene su propio menú **Modelo**: **Igual que la predicción del siguiente mensaje** (la opción predeterminada) sigue el modelo de la predicción; otra opción se usa solo para las compleciones. Si dsh ya no muestra ese modelo, las compleciones usan el modelo de la predicción.

**¿Puede dsh mejorar mi prompt antes de enviarlo, como el botón Enhance prompt de Roo Code o Augment?** Sí, con **Mejorar prompt** (activado de forma predeterminada): escribe una petición aproximada y haz clic en la varita mágica junto al menú de modelos. Reescribe el texto con este chat y el proyecto como contexto, en tu idioma, y no lo envía. `Cmd/Ctrl+Z` o **Deshacer mejora** recuperan tu texto. Elige su modelo en **Configuración → Composer Plus → Mejorar prompt → Modelo**.

**¿Puede el agente dejar de dar por terminado su propio trabajo, como en los bucles de verificación de la loop engineering?** Sí, con **Comprobación del objetivo** (activada de forma predeterminada): empieza un objetivo con `/goal`. Cuando el agente dice que el objetivo está completado, se ejecutan las pruebas del proyecto y una llamada independiente al modelo comprueba el objetivo frente al chat; si alguna falla, el objetivo sigue abierto y el agente lee el motivo. Define tu propio comando de prueba, un límite de tiempo o un límite de tokens con **Editar** en la fila **Comprobación del objetivo** bajo el objetivo.

**¿Puede el agente recordar mis preferencias entre chats, como la memoria de DS Bot?** Sí, con **Memoria del proyecto** (desactivada de forma predeterminada): actívala en **Configuración → Composer Plus**. Después de cada turno, tus preferencias y decisiones duraderas se guardan como notas breves para el proyecto del chat, y cada chat nuevo de ese proyecto las lee. Pide al agente que recuerde algo y lo guarda al momento. Para ver o cambiar las notas, pulsa **Abrir memoria** en la misma fila y escribe qué cambiar.

**Yo o la IA hicimos un cambio incorrecto en la memoria. ¿Puedo recuperar las notas anteriores?** Sí, con **Historial de versiones de la memoria** (activado por defecto): en **Abrir memoria**, selecciona el proyecto y luego **Historial**. Selecciona la versión anterior al cambio para ver qué vuelve y luego **Restaurar**.

**¿Puedo compartir la memoria del proyecto con mi equipo u otra herramienta de agentes?** Sí, con **Exportar la memoria a AGENTS.md** (activado por defecto): en **Abrir memoria**, selecciona el proyecto y luego **Exportar a AGENTS.md**. Revisa el diff, luego **Escribir AGENTS.md**, y confirma el archivo en git.

**¿Puede la IA sugerir qué guardar de un chat largo?** Sí, con **Sugerir notas de memoria desde un chat** (activado por defecto mientras **Memoria del proyecto** está activada): haz clic en **Sugerir para la memoria** en la cabecera del chat y luego **Aceptar** en las notas que valga la pena guardar.

**¿Puedo ver todos mis chats como un tablero kanban e iniciar chats nuevos desde él?** Sí, con **Tablero de tareas** (activado de forma predeterminada): ábrelo en la barra lateral izquierda. Cada chat es una tarjeta en **En curso**, **En revisión** (te espera) o **Hecho**. **Nueva tarea** abre el chat nuevo de dsh en el proyecto, y el tablero vuelve cuando se envía tu primer mensaje; haz clic en **Responder** en una tarjeta naranja para responderla sin abrir el chat. **Limpiar todo**, en **Hecho**, pregunta primero y quita del tablero las tarjetas terminadas que ya leíste; **Deshacer** y **Quitadas (N)** las devuelven, y los chats siguen en dsh.

**¿Puedo tener un chat de asistente personal que me haga recordatorios y gestione mis otros chats?** Sí, con **Asistente** (activado de forma predeterminada): haz clic en **Asistente** en la barra lateral izquierda. Crea recordatorios con las tareas programadas de dsh, busca en la web, lista y lee tus chats, y envía un mensaje a un chat o inicia, detiene o archiva uno solo después de que lo apruebes. Guarda tu perfil en la memoria de su proyecto, tema "profil".

**¿Puede el asistente quedar fuera de mi lista de chats y funcionar como un bot?** Sí. **Asistente separado de los chats** saca su chat de la lista de la barra lateral y muestra su estado en la fila **Asistente** (naranja mientras te espera). **Solo mensajes en el Asistente** oculta sus pasos de trabajo. **Asistente siempre libre** hace que dé cada paso más largo a un subagente en segundo plano, así que responde al instante. **Avisos de chats en el Asistente** (desactivado de forma predeterminada, usa tokens) hace que te avise cuando otro chat termina, falla o te espera.

**¿Puede dsh hacer copias de seguridad de mis chats y ajustes, como dsh-backup?** Sí: **Configuración → Composer Plus → Copia de seguridad → Hacer copia ahora**. Escribe el mismo formato de archivo comprimido en la misma carpeta (`~/Desktop/dsh-backups`), así que los archivos comprimidos de dsh-backup también aparecen y se pueden restaurar, y puedes desinstalar dsh-backup. Activa **Copia de seguridad automática** para hacer copias según un horario.

**dsh ya no se inicia. ¿Cómo restauro una copia de seguridad?** Abre la carpeta de copias de seguridad (`~/Desktop/dsh-backups`) y haz doble clic en `Composer Plus Rescue.command` (Linux: `composer-plus-rescue.sh`, Windows: `Composer Plus Rescue.cmd`). Elige `3) Restore a backup`, selecciona una y escribe `RESTORE`. Funciona sin dsh.

**¿Cómo muevo dsh a un equipo nuevo?** En el antiguo: **Copia de seguridad** → **Para otro equipo** junto a una copia de seguridad. Copia esa carpeta al equipo nuevo, instala dsh allí, ciérralo, abre `Composer Plus Rescue` en la carpeta copiada y restaura. Vuelve a introducir tus claves de API (se quedan en el equipo antiguo).

**Un chat no se abre después de un cierre inesperado. ¿Puedo repararlo?** **Configuración → Composer Plus → Comprobación de registros de sesión → Comprobar registros de sesión**. Un chat dañado vuelve desde la copia de seguridad más reciente con **Reparar desde copias de seguridad** (se pierden los mensajes posteriores a esa copia de seguridad).

**¿Cómo reordeno los mensajes en cola en dsh?** Arrastra el asa ⠿ de un mensaje en cola, o pon el foco en ella y pulsa `↑` / `↓`.

**¿Cómo corrijo una errata en un mensaje en cola?** Haz doble clic en el mensaje en la cola, cambia el texto y pulsa `Enter` (`Esc` cancela). El mensaje mantiene su lugar en la cola. Ahí también puedes quitar sus imágenes y archivos, o añadir otros nuevos.

**¿Cómo quito a la vez todos los puntos de no leído de un proyecto?** Barra lateral → botón **…** del proyecto → **Marcar todo como leído**.

**¿Puedo enlazar a un solo mensaje de un chat largo?** Sí: pasa el puntero por encima del mensaje y haz clic en **🔗**. Envía el enlace en un chat: en dsh 0.2.1 y posteriores, un clic en él abre el chat en ese mensaje.

**Revertí un turno por error. ¿Puedo recuperarlo?** Sí, con **Rehacer** encima del editor, justo después de revertir: inicia un chat nuevo desde justo antes de la reversión con los mismos mensajes, y con **Chat y archivos** también devuelve los archivos.

**¿Qué chat cambió este archivo?** Barra lateral derecha → **Cambios** → **…** del archivo → **Chats que cambiaron este archivo**. Haz clic en una fila para abrir ese chat en la petición que hizo el cambio.

**¿Puedo buscar dentro de un chat largo?** Sí: pulsa `Cmd+F` en un Mac (`Ctrl+F` en Windows y Linux) en el chat. **Buscar en el chat** resalta todas las coincidencias y salta entre ellas con `Enter` y `Shift+Enter`.

**¿Cómo veo solo los archivos que cambió un chat?** Barra lateral derecha → **Cambios** → **Este chat**. Haz clic en **␣** para ocultar los cambios que solo son espacios en blanco.

**¿Cómo evito que el agente ejecute `npm publish` o `git push --force`?** **Configuración → Composer Plus → Comandos bloqueados**: escribe `npm publish`, elige **bloquear** o **preguntar antes** y luego haz clic en **Añadir**. **bloquear** rechaza el comando y el agente te pregunta; **preguntar antes** muestra la tarjeta de aprobación cada vez. Archivos protegidos cubre las herramientas de archivos del agente; Comandos bloqueados cubre sus comandos de shell.

**¿Puedo decirle al agente por qué rechacé una llamada a herramienta?** Sí, con **Rechazar con nota** (activado de forma predeterminada): haz clic en **Rechazar con nota…** en la tarjeta de aprobación, escribe el motivo o qué hacer en su lugar y haz clic en **Rechazar**. El agente lee el rechazo y tu nota en el mismo turno.

**¿Cómo le doy al agente una contraseña o un token sin escribirlo en el chat?** Con **Entrada secreta** (activada de forma predeterminada): pide al agente que use `request_secret`, o espera a que lo pida. Escribe el valor en la tarjeta de la fila de la herramienta y haz clic en **Guardar**. El agente recibe solo la ruta de un archivo que contiene el valor, y el archivo se borra al terminar el turno.

**¿Cómo respondo solo a una parte de una respuesta larga?** Selecciona esa parte y haz clic en **Citar** sobre la selección (**Citar en la respuesta**, activada de forma predeterminada). La parte va al campo de texto como cita `> …` y escribes tu respuesta debajo.

**¿Cómo le muestro al agente las líneas exactas de un archivo?** Abre el archivo en la barra lateral derecha (**Archivos del espacio de trabajo**), selecciona las líneas y haz clic en **Citar** sobre la selección (**Citar desde la vista previa del archivo**, activada de forma predeterminada). El campo de texto recibe la ruta y los números de línea (por ejemplo `src/login.js:2-3`) y las líneas como bloque de código; escribe tu pregunta debajo.

**¿Puedo preguntar algo mientras el agente trabaja, sin detenerlo?** Escribe la pregunta y haz clic en **Preguntar en un chat lateral** en el campo de texto (**Chat lateral**, activado de forma predeterminada). Una copia de solo lectura del chat la responde mientras el chat sigue. En el chat lateral, **Traer de vuelta** pone la respuesta en el campo de texto del chat.

**¿Cómo le digo al agente qué cambiar en su diff?** En **Panel de cambios**, abre el diff del archivo, haz clic en **+** en una línea y escribe una nota (**Notas del diff**, activado de forma predeterminada). Luego haz clic en **Enviar al campo de texto**: las notas van al campo de texto con el archivo, los números de línea y las líneas.

**¿Cómo evito que la revisión automática pregunte por la misma herramienta en un chat?** Haz clic en **Permitir en este chat** en la tarjeta de aprobación. Solo cubre esa herramienta exacta en ese chat, durante 1 hora por defecto; revoca el permiso desde el chip de la cabecera. Cambia el tiempo en **Configuración → Composer Plus → Permitir en este chat**.

**Perdí mi iPhone. ¿Cómo evito que llegue a mi Mac?** Haz clic en **Conexión móvil**, abajo a la izquierda de la barra lateral, y haz clic en **Remove** junto a ese iPhone. Su clave deja de funcionar al instante; solo puede volver con un nuevo emparejamiento que apruebes en el Mac.

**¿Cómo continúo un chat de mi otro Mac desde este?** En el otro Mac, activa **Configuración → Composer Plus → Equipos remotos** y **Permitir que otros equipos abran este Mac**, haz clic en **Crear enlace de emparejamiento** y copia el enlace (envíatelo, por ejemplo con AirDrop o Notas). En este Mac, activa también **Equipos remotos**, elige **Añadir un equipo…** en el selector de la barra lateral izquierda (a la derecha del nombre de la marca, encima de **Nueva sesión**), pega el enlace, escribe un **Nombre** y haz clic en **Conectar**. Después haz clic en **Aprobar** en el otro Mac. Desde entonces, elige ese equipo en el mismo menú: ocupa esta ventana. Haz clic en **Volver a este Mac** en el mismo lugar para volver. Mientras tanto, los chats de este Mac siguen funcionando.

**¿Puedo bloquear Tether con Face ID?** Sí: en Tether, activa «Settings → Privacy → Lock with Face ID». Después, Tether pide Face ID (o el código) al abrirse y cuando vuelves a la app.

**¿Cómo muestro en la barra lateral de dsh solo los proyectos que usé hoy?** Barra lateral → opciones de vista (icono de controles deslizantes) → **Activos en las últimas 2 horas**. Selecciónalo otra vez para mostrar todos los proyectos.

**¿Cómo copio la ruta de la carpeta de un proyecto en dsh?** Haz clic derecho en el proyecto en la barra lateral → **Copiar ruta**.

**¿Cómo contraigo a la vez todos los proyectos de la barra lateral de dsh?** Haz clic en el botón de contraer, junto a las opciones de vista (icono de controles deslizantes). Aparece mientras hay al menos un proyecto abierto.

**¿Cómo recibo notificaciones de macOS / Windows cuando una tarea de dsh termina o necesita aprobación?** Deja activada **Notificaciones en segundo plano** (lo está de forma predeterminada) y permite las notificaciones de DeepSeek Harness en los ajustes del sistema operativo.

**¿Puede dsh abrir por sí solo el chat que me hace una pregunta?** Sí, con **Abrir el chat en espera si estás inactivo** (activado por defecto): cuando un chat espera una respuesta, una aprobación o una revisión del plan y no usas dsh durante 30 segundos, dsh lo abre. Un chat que terminó un turno que aún no has leído (el punto verde) se abre de la misma forma, después de los naranjas. Mientras escribes, te desplazas o mueves el ratón, espera.

**¿Puedo ir directamente al siguiente chat que me espera?** Sí, con **Siguiente chat en espera** (activado por defecto): pulsa `Cmd+Shift+E` (`Ctrl+Shift+E` en Windows y Linux) o haz clic en el botón con el número en la cabecera de la barra lateral. Primero van los chats que hacen una pregunta o esperan una aprobación, después los que terminaron un turno que aún no has leído.

**¿Puedo responder a las opciones de un agente con un clic?** Sí, con **Botones de opciones** (activado por defecto): cuando una respuesta termina con una lista "Opciones", haz clic en un botón debajo de ella. Envía "Option N: …" como tu mensaje. En una tarjeta de pregunta del agente, pulsa 1–9.

**¿Cómo cambio la interfaz de DeepSeek Harness a turco, español, japonés…?** Configuración → Composer Plus → **Idioma de la aplicación**.

**¿Cómo uso dsh desde mi iPhone?** Compila la app Tether desde `tether/ios` (Xcode), activa **Configuración → Composer Plus → Conexión móvil (iPhone)**, haz clic en **Conexión móvil** abajo a la izquierda, escanea el código QR (con la Cámara del iPhone o con **Scan code** en Tether), toca **Connect** y haz clic en **Approve**. Fuera de casa, usa Tailscale en los dos dispositivos.

**¿Cómo hago que Nueva sesión se abra siempre en el mismo proyecto?** Configuración → Composer Plus → **Espacio de trabajo predeterminado para Nueva sesión** → **Abrir Nueva sesión en** → elige el proyecto. El `+` junto a otro proyecto sigue abriendo ese proyecto.

**¿Cómo trabajo en varias funciones de un proyecto a la vez, cada una en su propia rama?** Con **Una rama por chat**: en la pantalla de chat nuevo, el botón de rama muestra **Nueva rama** de forma predeterminada: envía el primer mensaje. Cada chat tiene su propia rama y su carpeta de worktree, con tu `.env` y tu `node_modules` cuando `.worktreeinclude` los lista. La cabecera del chat muestra en qué rama estás.

**¿Puede la barra lateral mostrar cada rama de un proyecto y mover mi chat cuando el agente crea una rama?** Sí, con **Ramas en el árbol de espacios de trabajo** (desactivado por defecto): actívalo en Configuración → Composer Plus y elige **Opciones de vista** → **Árbol de espacios de trabajo** de dsh. Cada rama con un worktree en `<project>/.worktrees/` aparece dentro de su proyecto. Cuando pides al agente de la carpeta del proyecto que cree una rama y trabaje allí, y la carpeta no tiene cambios sin confirmar, el chat se mueve solo a la rama. Si borras la carpeta de la rama, sale de la lista; sus chats pasan a **Sin agrupar**.

**¿Puedo enviar una foto desde mi iPhone?** Sí. En un chat de Tether, toca **+** junto al campo de mensaje → Camera, Photos (hasta 4) o Paste image. Las fotos llegan al chat del Mac como adjuntos de tu mensaje, así que el modelo las ve.

**¿Puede dsh ejecutar el siguiente comando sin volver a preguntar al modelo?** Sí, con **Pasos planificados** (desactivada de forma predeterminada): actívala en Configuración → Composer Plus. El modelo puede entonces planificar sus próximos comandos con una condición, por ejemplo «ejecuta las pruebas cuando la compilación pase», y Composer Plus ejecuta un paso sin una nueva llamada al modelo cuando el resultado cumple la condición. Las aprobaciones y el sandbox siguen igual.

**¿De dónde viene el skill en turco y puedo quitarlo?** De [yucezerey/turkish-anti-ai-skill](https://github.com/yucezerey/turkish-anti-ai-skill) en GitHub (MIT). Composer Plus lo instala solo mientras **Idioma de la aplicación** es Türkçe, guarda solo sus archivos Markdown y no ejecuta ninguno de sus scripts. Para quitarlo, desactiva **Paquete de skill en turco** en Configuración → Composer Plus: el skill y la copia descargada se borran al momento.

**¿Cómo informo de un error o pido una función en Composer Plus?** Configuración → Composer Plus → **Informar de un problema…** (o menú **…** de un chat → **Informar de un problema de Composer Plus…**). Elige un tipo, descríbelo en tu propio idioma y haz clic en **Escribir borrador**. Revisa el borrador en inglés y luego haz clic en **Abrir issue**.

**¿Cómo puede el agente ordenar un código desordenado?** Escribe `/untangle-codebase` en un chat (**Desenredar el código**, activada de forma predeterminada), si quieres con un área, por ejemplo `/untangle-codebase src/api`. Primero el agente enumera las copias, los vínculos ocultos, los envoltorios innecesarios, el código muerto y los casos especiales; luego los corrige como un objetivo y vuelve a comprobar con subagentes. Iníciala en un chat de **Una rama por chat** para que el trabajo quede en su propia rama.

**¿Funciona con la app de escritorio?** Sí: Configuración → Plugins → **Añadir plugin** → `dsh-composer-plus`. Probado en dsh 0.2.0-rc.2 (escritorio y web) y 0.2.1-rc.2 (web).

**Regla para las funciones nuevas:** cada fila de función en Configuración → Composer Plus muestra una captura. Añade el id de la función a `SHOT_OF` en `client.js` y a `SHOTS` en `index.js`, e incluye `assets/features/<id>.webp` (tomada del dsh de demostración desechable, con la interfaz en inglés, de unos 60 kB o menos). Añade la función, con la misma imagen, a `docs/features.json` y ejecuta `npm run build:readme`: escribe la tabla de funciones de `README.md` y de cada `README.<id>.md` traducido, y la lista de `llms.txt`. `test/shots.test.mjs` falla cuando una función no tiene captura, y `test/browser-settings-shots.mjs` comprueba la página de Configuración real. La lista completa de comprobaciones para cada cambio está en [AGENTS.md](AGENTS.md).

Las pruebas ejecutan el `client.js` real contra un React/DOM falso, y el `index.js` real (la parte Host) contra un repositorio git temporal. Las pruebas de la pasarela de Tether (`test/tether-gateway.test.mjs`) usan un host de dsh simulado y una pasarela TLS real. La app de iPhone está en `tether/ios` (consulta [tether/README.md](tether/README.md) y [tether/AGENTS.md](tether/AGENTS.md)). El archivo [docs/ROUTES.md](docs/ROUTES.md) muestra cada ruta del Host, su petición y si Tether puede llamarla. `node test/browser-history.mjs '<dsh web URL with ?token=…>'` comprueba el historial de entrada en un navegador real contra un `dsh web` desechable con su propio `DSH_HOME`.

Los paquetes de idioma son archivos JSON solo de datos en `locales/<id>.json`, que `npm run build:locales` incrusta en la única entrada del cliente (sin servicio de traducción ni descarga en tiempo de ejecución). `npm test` comprueba en cada paquete que estén todas las claves, que los marcadores de posición y los saltos de línea sean idénticos, y el comportamiento del idioma del sistema y de la elección manual. Para comprobaciones aisladas en la app real con un Playwright instalado localmente:

```sh
PLAYWRIGHT=/path/to/playwright node test/browser-language.mjs /path/to/dsh/lib/bin.js
```
