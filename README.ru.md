Удобные функции в стиле Codex для настольного и веб-интерфейса [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (dsh): панель изменений, идеи функций в виде карточек, которые можно смахивать, поиск по тексту сообщений на боковой панели, откат хода с восстановлением файлов, удаление чата в Корзину, название проекта под полем ввода, статус проекта на боковой панели, история ввода, быстрое переключение режима плана, продолжение в один клик, продолжение работающих чатов после перезапуска, перетаскивание в очереди, ссылки на сеансы, экспорт чата в Markdown, разрешения автопроверки для отдельного чата, фоновые уведомления, доступ с iPhone через приложение Tether и автоматические обновления.

**Коротко:** это один плагин для DeepSeek Harness (npm `dsh-composer-plus`, в разделе Настройки → Плагины он называется **Composer Plus**). Он добавляет панель изменений git, карточки идей функций в стиле Tinder, поиск на боковой панели, который находит и слова в сообщениях, откат хода ↶ (только чат или чат и файлы), удаление чата, название проекта под полем ввода, историю ввода по ↑/↓, переключатель `/plan` по Shift+Tab, кнопку ▶ «Продолжить» в один клик, продолжение после перезапуска, изменение порядка очереди перетаскиванием, копирование ссылки на сеанс, экспорт в Markdown, «Разрешить для этого чата» для автопроверки, фоновые уведомления, доступ с iPhone (мобильное подключение, приложение Tether), 11 дополнительных языков интерфейса и автоматические обновления.

Неофициальный плагин сообщества. Проверка обновлений делает сетевые запросы (выпуски GitHub и реестр npm). Чтобы при запуске их не было, выключите **Автоматические обновления**. **Пакет навыка для турецкого** (включён по умолчанию) загружает turkish-anti-ai-skill с GitHub и раз в день проверяет новую версию, только пока **Язык приложения** — Türkçe; выключите его в **Настройки → Composer Plus**, чтобы остановить эти запросы. **Идеи функций** обращается к модели вашего чата, только когда вы нажимаете **Предложить функции**. **Предсказание следующего сообщения** (по умолчанию включено) обращается к модели, выбранной в настройках (по умолчанию это модель dsh, если вы не выберете другую), один раз после каждого завершённого хода, без нажатия. Чтобы остановить эти запросы, выключите его в **Настройки → Composer Plus**. **Дополнение при вводе** (по умолчанию выключено) после включения обращается к выбранной для него модели (по умолчанию это модель предсказания) при каждой паузе в наборе. **Улучшить промпт** обращается к модели, только когда вы нажимаете волшебную палочку. **Доска задач** обращается к модели нового чата один раз для тегов каждой задачи, которую вы начинаете на доске. В режиме **Сводка ИИ** (по умолчанию **Быстро (без ИИ)**) она также обращается к модели работающего чата за короткой заметкой о ходе работы, пока вы смотрите ход этой задачи на доске или в Tether. **Проверка цели** (по умолчанию включена) обращается к модели один раз каждый раз, когда агент в автоматическом раунде отмечает `/goal` как выполненную. **Мобильное подключение** (по умолчанию выключено) принимает подключения iPhone из вашей локальной сети или tailnet только после того, как вы его включите.

## Установка

**Настольное приложение:** Настройки → Плагины → **Добавить плагин** → введите `dsh-composer-plus` → **Включить сейчас**.
Вместо имени npm-пакета можно вставить `https://github.com/furkancak1r/dsh-composer-plus`.

**Профиль Web / CLI:**

```sh
dsh plugin --profile web add dsh-composer-plus
```

Затем перезапустите dsh. (CLI не может устанавливать плагины в профиль настольного приложения: им управляет само приложение.)

> pnpm в dsh пропускает версии, которые вышли меньше 24 часов назад. Сразу после выпуска укажите версию: `dsh-composer-plus@1.27.1`.

| **Панель изменений** | <a id="feature-changespanel"></a>Правая боковая панель → `+` → **Изменения**. Страница открывается в режиме **Дерево**: это карта веток репозитория чата. | **Идеи функций** | <a id="feature-featureideas"></a>Правая боковая панель → `+` → **Идеи функций** → **Предложить функции**. Модель чата читает краткую сводку проекта этого чата (файлы верхнего уровня, начало README и манифеста, структуру остальной части README, заголовки последних коммитов) и предлагает до 8 функций. Они появляются стопкой карточек на языке интерфейса dsh. Смахните карточку вправо (или нажмите **✓**, или клавишу `→`; в любом случае карточка улетает в свою сторону), чтобы начать новый чат в том же проекте. Чат начинается в режиме плана, а идея становится запросом, поэтому до одобрения плана ничего не меняется. Чтобы обойтись без плана, нажмите **▶ Создать сразу** (или клавишу `↑`; карточка улетает вверх): новый чат сразу начинается с идеей как обычным запросом, и модель вносит изменение и запускает свои проверки (одобрения действуют как обычно). Смахните влево (или **✕**, или `←`), чтобы пропустить карточку. **Отменить** (или `Z`) возвращает пропущенную карточку. Нажмите **↓** (или клавишу `↓`), чтобы отложить хорошую идею: она попадает в список проекта **На потом**. Этот список виден в каждом чате из той же папки проекта (и после перезапуска). **На потом (N)** открывает список. **Спланировать** начинает для идеи такой же чат в режиме плана, а **Создать сразу** — чат без плана; обе кнопки убирают её из списка. **Спланировать все (N)** начинает один чат в режиме плана для всех идей из списка, поэтому общие части планируются один раз. **Убрать из списка** удаляет её. **Копировать как чек-лист** копирует весь список в буфер обмена как чек-лист Markdown (`- [ ] Title — Summary`, по одной строке на идею) для трекера задач или файла TODO; сетевых запросов при этом нет. **Открыть issue на GitHub** у идеи открывает issue с её названием и кратким описанием (и тем, почему она важна) в репозитории проекта на GitHub через ваш собственный вход в GitHub CLI (`gh`); затем рядом с идеей появляется ссылка **Issue #N**, которая открывает issue. **Ещё идеи** добавляет карточки. Чтобы получить идеи только по одной области, введите короткую тему в поле **Тема** рядом с **Предложить функции** (не более 80 символов; `Enter` тоже запускает предложение) или нажмите одну из готовых тем под ним: **Производительность**, **Доступность**, **Тесты**, **Безопасность**, **Удобство** или **Документация** (повторное нажатие очищает тему). Тогда модель предлагает только функции по этой теме; пустое поле означает любые функции. В одном проекте идея не предлагается дважды: каждая предложенная идея (пропущенная, отложенная или начатая) попадает в список проекта **История**, модель получает указание больше не предлагать эти идеи, а идея с повторным заголовком отбрасывается. **История** показывает их с пометкой **Начата** или **Предложена**; **Забыть** (или **Забыть все**) позволяет идее появиться снова; идея, которая ещё есть в списке **На потом**, не попадает в предложения, пока вы не уберёте её оттуда. Модель запускается, только когда вы нажимаете кнопку. | <a href="assets/features/featureIdeas.webp"><img src="assets/features/featureIdeas.webp" width="160" alt="Снимок экрана: Идеи функций"></a> |

## Настройки

Каждую функцию можно включить или выключить отдельно: dsh **Настройки → Composer Plus**. В каждой строке есть маленький снимок экрана: наведите на него указатель, чтобы увидеть его крупнее, или нажмите, чтобы открыть в полном размере (`Esc` закрывает). Поле **Поиск функций** вверху фильтрует страницу по названию или описанию (на любом языке, без учёта регистра и диакритических знаков); `Esc` очищает его. Рядом кнопки **Все**, **Включённые** и **Выключенные** показывают все функции, только включённые или только выключенные (чтобы скрыть их, выключите **Фильтр «вкл./выкл.»**). В каждой строке есть переключатель и короткое описание. Маленький **?** после названия строки открывает часть README с описанием этой функции, в README на языке интерфейса dsh. Изменения применяются сразу, без перезапуска, и запоминаются на этом устройстве. По умолчанию включено всё, кроме **Мобильное подключение**, **Продолжать после перезапуска** и **Дополнение при вводе**. Переключатели этих трёх функций, а также **Поиск по содержимому**, **Откат хода**, **Предсказание следующего сообщения** и **Проверка цели** хранит Host dsh, поэтому они действуют во всех окнах и сохраняются после перезапуска. Выбор в меню **Модель** для **Предсказание следующего сообщения**, для **Дополнение при вводе** (по умолчанию **Как у предсказания следующего сообщения**), для **Улучшить промпт** и для **Проверка цели** (у обоих по умолчанию **Как модель чата**), а также **Лимит времени** для **Разрешить для этого чата** (по умолчанию 1 час) тоже хранит Host. **Поиск по содержимому** меняется только после перезапуска dsh (dsh читает эту настройку при запуске). До этого в его строке написано **Перезапустите dsh, чтобы применить это изменение.**

## Конфиденциальность и безопасность

- **Продолжить:** аутентифицированная локальная конечная точка возобновляет только последний прерванный ход, отклоняет устаревшие и повторные запросы и сохраняет существующие хуки одобрения. Новое сообщение пользователя она не отправляет.
- **Продолжать после перезапуска:** выключено, пока вы его не включите. Host-часть хранит только ID чатов и время их запуска в `$DSH_HOME/storages/dsh-composer-plus/resume.json` (доступ только для владельца), и ничего не покидает ваш компьютер. Чат продолжается, только если собственный журнал dsh показывает, что последний ход остановил dsh, а не вы. Одобрения и автопроверка действуют для продолженного хода как обычно.

- **Панель изменений:** git работает только на чтение на вашем компьютере, в папке самого чата, через аутентифицированный канал dsh `/api`. Он никогда не выполняет commit, stage или fetch и показывает только пути, которые перечислил сам git. Дерево показывает до 1000 локальных и удалённых веток и последние 300 коммитов одной ветки: только линию первого родителя, поэтому коммит слияния заменяет коммиты, которые он принёс. Оно никогда не переключает ветку (checkout). **Этот чат** читает собственный журнал чата, чтобы найти файлы, которые записали его файловые инструменты, и сравнивает их со снимком отката хода этого чата во временной папке, которая сразу удаляется; он ничего не записывает ни в ваш репозиторий, ни в хранилище снимков.
- **Идеи функций:** ничего не запускается, пока вы не нажмёте **Предложить функции**. Затем Host-часть читает только папку самого чата (браузер никогда не отправляет путь): имена записей верхнего уровня, первые 6 КБ файлов README, AGENTS.md и манифеста (`package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, …), структуру остальной части README (заголовки, строки таблиц, пункты списков; не более 6 КБ) и заголовки последних коммитов (`git log --format=%s`, не более 6 КБ), всего не более 28 КБ. Она пропускает `.env*`, файлы ключей и папки вроде `node_modules` и читает только обычные файлы внутри папки: символическая ссылка за пределы папки, FIFO или устройство пропускаются. Эта сводка уходит одним запросом к модели, которую использует чат, через настройки провайдера самого dsh. Она не добавляется ни в один чат. В проекте ничего не записывается. Идея, смахнутая вправо, начинает новый чат в режиме плана, поэтому одобрения и проверка плана действуют как обычно. **Создать сразу** начинает чат без режима плана: модель может сразу менять файлы, с обычными одобрениями чата и автопроверкой. Идеи, отложенные на потом (заголовок, описание, обоснование, объём работы), хранятся вместе с путём к папке проекта в `storages/dsh-composer-plus/later.json` в домашней папке dsh (файл доступен только владельцу); в проект ничего не попадает. История предложенных идей (заголовок, описание, обоснование, объём работы, дата, начата ли идея) хранится так же, в `storages/dsh-composer-plus/idea-history.json`, не более 200 на проект (первыми удаляются самые старые); её заголовки уходят модели при следующем нажатии **Предложить функции** в этом проекте.
- **Поиск по содержимому:** никакой новый код не ищет по вашим чатам. Плагин только включает встроенный индекс сообщений dsh (SQLite FTS5, `dsh-session-query-sqlite`) и даёт ему файл `$DSH_HOME/cache/composer-plus/session-search.db` (файл и папка доступны только владельцу). В файле хранится текст ваших сообщений и сообщений ассистента, поэтому он так же конфиденциален, как журналы чатов в `$DSH_HOME/sessions`. Ничего не покидает ваш компьютер. Это копия, которую dsh может создать заново: её можно удалить, пока dsh закрыт. Переключатель хранится в `$DSH_HOME/storages/dsh-composer-plus/content-search.json`.
- **Откат хода:** перед каждым вашим сообщением Host делает git-снимок папки чата в собственном хранилище `$DSH_HOME/cache/composer-plus/rollback/<chat>.git` (папка доступна только владельцу). В нём хранятся копии тех файлов этой папки, которые видит git (кроме игнорируемых), поэтому оно так же конфиденциально, как сам проект. Хранилище читает объекты вашего репозитория (то, что уже есть в git, не копируется) и никогда не записывает индекс, `HEAD`, ветки, теги, stash или конфигурацию вашего репозитория. Единственное, что git там меняет, — более новая отметка времени у файлов объектов, которые он использует повторно (из-за этого `git gc` удаляет их позже). Откат с файлами записывает только обычные файлы внутри папки чата; символические ссылки, каналы (pipes) и всё за пределами папки он пропускает. Ничего не покидает ваш компьютер. Хранилище можно удалить, пока dsh закрыт (тогда откат работает только для чата, пока не появятся новые сообщения). **Удалить чат** удаляет и хранилище чата. Переключатель хранится в `$DSH_HOME/storages/dsh-composer-plus/rollback.json`. Откат с файлами также сохраняет файлы в том виде, в каком они были непосредственно перед ним (`refs/r/…` в том же хранилище), для кнопки **Повторить**; повторённые откаты перечислены в `$DSH_HOME/storages/dsh-composer-plus/redone.json` (доступ только для владельца).
- **Открыть issue на GitHub** (Идеи функций → список **На потом**): запускается, только когда вы нажимаете эту кнопку. Host-часть запускает ваш собственный GitHub CLI (`gh issue create`) в папке чата с сохранёнными названием и кратким описанием идеи (и тем, почему она важна); `gh` использует свой вход и удалённый репозиторий GitHub этой папки, поэтому issue создаётся в этом репозитории от вашей учётной записи, и GitHub показывает её всем, кто видит этот репозиторий. dsh удаляет из запускаемых им команд переменные с именами, похожими на токен; если вы передали `gh` токен через `GH_TOKEN` или `GITHUB_TOKEN`, плагин передаёт `gh` только эти переменные. Ссылка на issue хранится вместе с идеей в `later.json`.
- **Сообщить о проблеме** (Настройки → Composer Plus → **Сообщить о проблеме…** или меню **…** чата → **Сообщить о проблеме с Composer Plus…**): ничего не запускается, пока вы не нажмёте кнопку. **Написать черновик** одним запросом отправляет модели dsh по умолчанию только тип и текст, который вы ввели (не чат и не проект). Host-часть добавляет одну строку с версиями Composer Plus, dsh и операционной системы и заменяет путь к вашей домашней папке на `~`. **Открыть issue** запускает ваш собственный GitHub CLI (`gh issue create --repo furkancak1r/dsh-composer-plus`) с вашим входом в `gh`, поэтому issue публичная и показывает вашу учётную запись GitHub. Текст, похожий на ключ, токен или пароль, отклоняется и не покидает ваш Mac.
- **Чаты, которые изменили этот файл** (Изменения, меню «…» файла): Host-часть читает журналы чатов, папка которых находится в том же репозитории, в том виде, в каком их хранит dsh, и возвращает название каждого чата, время и первую строку запроса; сам файл она никогда не открывает.
- **Ветка Git в строках чатов:** Host-часть запускает `git branch --show-current` (только чтение) в папке чата, когда ход начинается и когда заканчивается, и хранит только ID чата, имя ветки и время в `$DSH_HOME/storages/dsh-composer-plus/session-branches.json` (файл доступен только владельцу, 2000 самых новых чатов). Переключатель хранится рядом, в `branches.json`.
- **Поиск в чате** работает только на странице: он читает текст, который показывает страница, и ничего не отправляет.
- **Экспорт чата в Markdown:** Host-часть читает только журнал самого чата (те же сообщения, которые показывает dsh) и передаёт их странице; она не читает файлы проекта и ничего не отправляет по сети. Markdown попадает только в ваш буфер обмена или в файл, который вы сохраняете.
- **Удалить чат:** перемещает в Корзину только папки журнала самого чата (`$DSH_HOME/sessions/<project>/<chat>`). Папку проекта функция не трогает.
- **Разрешить для этого чата:** разрешения хранятся вместе со временем выдачи в `$DSH_HOME/storages/dsh-composer-plus/chat-grants.json` (доступ только для владельца). Разрешение действует для одного конкретного инструмента в одном чате, пока не истечёт лимит времени (по умолчанию 1 час). Если этот инструмент может выполнять запись, разрешение покрывает и любую запись. Отозвать его можно через значок в заголовке.
- Автопроверка по-прежнему выполняется при каждом вызове. Если проверка завершилась сбоем, вызов никогда не разрешается автоматически.
- **Мобильное подключение:** выключено, пока вы его не включите. Когда оно включено, Host-часть запускает шлюз Tether: HTTPS на порту 19390, который принимает подключения только из вашей подсети Wi-Fi и вашего tailnet (100.64.0.0/10), и страницу сопряжения на `127.0.0.1:19391` (только для этого Mac). Телефону нужен одноразовый код из QR-кода (действует 5 минут) и ваше подтверждение **Approve** на Mac. Телефон закрепляет сертификат шлюза. Mac хранит только хеш токена каждого телефона (30 дней, срок продлевается при использовании); **Remove** сразу закрывает подключения этого телефона. Телефоны могут вызывать только разрешённый список методов dsh (чаты, запросы, вложения, слеш-команды, одобрения, вопросы, модели, агенты, цели), но не настройки, учётные данные, обозреватель файлов или терминал. «Tailscale only» отклоняет любое подключение из локальной сети, в том числе уже открытые. Журнал доступа хранит 200 самых новых попыток подключения (время, IP-адрес, имя устройства, разрешено или отклонено и причина) в `access.json`; токенов и кодов сопряжения в нём никогда нет. Данные: `$DSH_HOME/storages/dsh-composer-plus/mobile/` (файлы доступны только владельцу). Подробности: [tether/README.md](tether/README.md).
- **Удалённые компьютеры:** функция выключена, пока вы не включите её на каждом Mac. **Разрешить другим компьютерам открывать этот Mac** открывает второй порт HTTPS (19392) только на адресе Tailscale этого Mac (не в сети Wi-Fi и без объявления через Bonjour). Другому Mac нужна одноразовая ссылка для сопряжения (действует 5 минут), соответствующий сертификат (закреплённый) и ваше подтверждение **Одобрить**. Этот Mac хранит только хеш его токена. Сопряжённый компьютер получает полный контроль над dsh на этом Mac, как если бы вы работали здесь: чаты, модели, инструменты, файлы и терминал. Удалите его на панели настроек, и его подключения сразу закроются. Mac, который открывает другой Mac, хранит токен этого компьютера в `$DSH_HOME/storages/dsh-composer-plus/computers.json` (файл доступен только владельцу). Для каждого выбранного компьютера он открывает ретранслятор (relay) на `127.0.0.1`. Страница получает одноразовую ссылку (действует 60 секунд), а ретранслятор принимает только свою страницу (свой адрес, никакой другой сайт). Страница другого Mac в этом окне может читать имена и состояния компьютеров этого Mac (без адресов и токенов) и может переключать это окно между ними. Она не может добавлять, переименовывать или удалять компьютеры и не может менять настройки этого Mac.
- **Обновления:** Host-часть запрашивает у `api.github.com` последний выпуск, а у `registry.npmjs.org` — именно эту версию. Никакие данные о вас или ваших чатах не отправляются. Установка идёт через менеджер плагинов dsh (`pnpm add dsh-composer-plus@<version>`; если dsh 0.2.1 отклоняет её для уже установленного плагина, то `pnpm add https://registry.npmjs.org/dsh-composer-plus/-/dsh-composer-plus-<version>.tgz`, и тогда профиль указывает этот URL как источник плагина), поэтому действуют встроенные проверки dsh: реестр, скрипты и совместимость версий. Предварительные выпуски и более старые версии никогда не устанавливаются.
- **Пакет навыка для турецкого:** включён по умолчанию и работает, только пока язык приложения — Türkçe: браузер сообщает Host-части язык интерфейса dsh. Затем не чаще раза в день Host-часть запрашивает у `api.github.com` последний коммит `yucezerey/turkish-anti-ai-skill` и его список файлов и загружает изменившиеся файлы Markdown с `raw.githubusercontent.com`. GitHub видит ваш IP-адрес, как при каждой проверке обновлений; ничего о вас или ваших чатах не отправляется. Сохраняются только обычные файлы `.md` из папки `skills/turkish-anti-ai-skill/` (не больше 20 файлов и 1 МБ), и каждый файл должен совпадать со своим идентификатором в списке файлов GitHub. Копия лежит в `$DSH_HOME/cache/composer-plus/turkish-skill/<commit>` (доступ только у владельца) и попадает в список навыков dsh; ни один скрипт пакета не запускается. Переключатель и последний сообщённый язык хранятся в `$DSH_HOME/storages/dsh-composer-plus/turkish-skill.json`. Выключение удаляет навык и копию.
- **Подсчёт использования:** Host-часть запрашивает у GitHub два маленьких файла из выпуска установленной версии (`github.com/furkancak1r/dsh-composer-plus/releases/download/v<version>/<file>`): `active.txt` раз в день, а `installed.txt` только один раз для каждой домашней папки dsh. GitHub считает эти запросы для каждого файла, поэтому автор видит только, сколько копий каждой версии запросили `active.txt` в этот день и сколько копий всего запросили `installed.txt` (число копий). В запросе нет идентификатора, cookie и данных о вас или ваших чатах; GitHub видит ваш IP-адрес, как и при каждой проверке обновлений. День последнего запроса `active.txt` хранится в `$DSH_HOME/storages/dsh-composer-plus/active.json`, а отметка о том, что `installed.txt` уже засчитан, — в `$DSH_HOME/storages/dsh-composer-plus/installed.json`. Git-клон этого репозитория и переименованная копия ничего не отправляют. Переключателя для этого нет.
- **Предсказание следующего сообщения:** по умолчанию включено. Чтобы остановить эти вызовы модели, выключите его в **Настройки → Composer Plus**. После каждого завершённого хода Host-часть отправляет ваши собственные сообщения в чате и текстовые ответы агента (без вывода инструментов, скрытого контекста и рассуждений), не более примерно 6 000 символов (самую новую часть), выбранной модели (по умолчанию это модель dsh, если вы не выберете другую). Это один запрос через настройки провайдера самого dsh. В чате ничего не сохраняется: предположение не попадает в историю чата. Переключатель и выбранная модель хранятся в `$DSH_HOME/storages/dsh-composer-plus/predict.json` (файл доступен только владельцу).
- **Дополнение при вводе:** выключено, пока вы его не включите. Когда оно включено, при каждой паузе в наборе Host-часть отправляет уже набранный текст, а также ваши собственные сообщения в чате и текстовые ответы агента (без вывода инструментов, скрытого контекста и рассуждений), не более примерно 3 000 символов чата, модели, выбранной для **Дополнение при вводе** (по умолчанию это модель **Предсказание следующего сообщения**). Новая пауза останавливает предыдущий запрос. В чате ничего не сохраняется. Переключатель хранится в `$DSH_HOME/storages/dsh-composer-plus/complete.json` (файл доступен только владельцу).
- **Улучшить промпт:** ничего не запускается, пока вы не нажмёте волшебную палочку. Затем Host-часть одним запросом отправляет модели, выбранной для **Улучшить промпт** (по умолчанию это модель самого чата), ваш черновик, ваши собственные сообщения в чате и текстовые ответы агента (без вывода инструментов, скрытого контекста, рассуждений и сообщений, убранных откатом; не более примерно 6 000 символов, самую новую часть), ту же сводку проекта, что и **Идеи функций** (с теми же правилами для файлов: без `.env*` и файлов ключей, без символических ссылок за пределы папки, без FIFO), пути, которые `git status` показывает как изменённые, и до 30 отслеживаемых или неотслеживаемых (не игнорируемых) путей, в именах которых есть слова из вашего черновика. Другое содержимое файлов, кроме этой сводки, не отправляется. В чат и в проект ничего не записывается: ответ только заменяет ваш черновик в поле ввода, а отправлять ли его, решаете вы. Выбранная модель хранится в `$DSH_HOME/storages/dsh-composer-plus/improve.json` (файл доступен только владельцу).
- **Проверка цели:** запускается, только когда агент в автоматическом раунде отмечает `/goal` как выполненную (или когда вы нажимаете **Запустить сейчас**). Host-часть запускает тестовую команду в папке чата в режиме песочницы этого чата (как собственный инструмент `bash` в dsh: та же политика доступа к файлам; если эта песочница не может запуститься, тест не запускается и проверка не пройдена). Чтобы найти команду, она читает только `package.json`, `Makefile`, `Cargo.toml`, `go.mod`, `pyproject.toml` и `pytest.ini`, как обычные файлы внутри папки (без символических ссылок за пределы папки, без FIFO). Затем она одним запросом без инструментов отправляет модели, выбранной для **Проверка цели** (по умолчанию это модель самого чата), цель, чат с момента начала цели (ваши сообщения, ответы агента, вызовы инструментов, обрезанные до 1 000 символов, и последние 2 000 символов каждого результата инструмента; без рассуждений и шагов, убранных откатом; не более примерно 60 000 символов, самую новую часть), `git status --short` и конец вывода теста. Вывод инструментов может содержать то, что прочитал агент, поэтому в этом запросе могут быть части ваших файлов, как и в самом чате. В чат и в проект ничего не записывается. Ваша тестовая команда, лимиты, последний результат (с концом его вывода) и выбранная модель хранятся в `$DSH_HOME/storages/dsh-composer-plus/goal-check.json` (файл доступен только владельцу, последние 500 чатов).
- **Продолжить в новом чате:** ничего не запускается, пока вы не нажмёте этот пункт. Затем Host-часть отправляет чат (так, как его читает Проверка цели: без рассуждений и шагов, убранных откатом) собственной модели чата и показывает заметку для передачи; новый чат создаёт только **Начать новый чат**. В проект ничего не записывается.
- **Состав контекста:** Host-часть читает только журнал чата; без вызова модели и без файлов проекта.
- **Доска задач:** доска показывает чаты dsh из собственных списков dsh в этом окне; своих данных о чатах она не добавляет. **Новая задача** открывает собственный новый чат dsh, и вы пишете первое сообщение в поле ввода dsh, поэтому подтверждения, песочница и модель чата действуют как обычно. Host-часть сохраняет первое сообщение этого чата как промпт карточки и отправляет его (первые 4 000 символов, больше ничего) модели этого чата ещё одним запросом, без инструментов, чтобы получить до 3 тегов. Промпт, теги и время запуска каждой задачи хранятся в `$DSH_HOME/storages/dsh-composer-plus/board-chats.json` (файл доступен только владельцу, последние 2 000), а также идентификаторы чатов, которые вы убрали с доски кнопкой **×** или **Очистить всё** (последние 5 000); переключатель хранится рядом, в `board-switch.json`. В папку проекта ничего не записывается. **Ответить** отправляет ваш ответ в ожидающий запрос dsh так же, как это делает карточка в самом чате. Старый список задач прежних версий (`board.json`) остаётся на диске без изменений и не читается. **Ход работы при наведении** читает журнал чата на этом Mac. В режиме **Быстро (без ИИ)** (по умолчанию) ничего не отправляется. В режиме **Сводка ИИ**, пока видно окно хода работы у работающей карточки (или пока доска в Tether открыта, не более чем для 8 работающих карточек), часть Host отправляет самую новую часть этого чата (не более примерно 6 000 символов: ваши сообщения, текстовые ответы агента, его вызовы инструментов и конец их результатов; без рассуждений и сообщений, убранных откатом) модели чата одним запросом без инструментов. Снова она отправляет только после того, как чат продвинулся, и не чаще одного раза в 20 секунд для каждого чата. Заметка хранится только в памяти; настройка хранится в `$DSH_HOME/storages/dsh-composer-plus/board-progress.json` (файл доступен только владельцу).
- **Ассистент:** чат ассистента — это обычный чат dsh в `~/Assistant`; его вызовы модели идут к модели dsh по умолчанию, как в любом чате. Его инструменты читают журналы ваших других чатов на этом Mac (названия, проекты, состояние, а с chat_read — их последние сообщения) и передают их этой модели, только когда она вызывает инструмент. Отправка, запуск, остановка и архивирование чата каждый раз ждут вашего подтверждения. Идентификатор чата хранится в `$DSH_HOME/storages/dsh-composer-plus/assistant.json`, а переключатель — в `assistant-switch.json` (файлы доступны только владельцу). Напоминания и автоматизации — это собственные запланированные задачи dsh. Ничто не покидает этот Mac, кроме запросов к модели и веб-поиска, который делает чат. Переключатели ассистента в роли бота хранят своё состояние в `assistant-free.json` и `assistant-notify.json` (файлы доступны только владельцу). **Новости чатов от ассистента** добавляет в чат ассистента короткую строку о другом чате (его название, проект и не более 300 символов его последнего ответа или ошибки), поэтому этот текст тоже уходит к модели ассистента; новости ждут только в памяти.
- **Защищённые файлы:** список и переключатель хранятся в `$DSH_HOME/storages/dsh-composer-plus/protected-files.json` (файл доступен только владельцу). Проверка читает только путь каждого вызова файлового инструмента (и его реальный путь), но никогда не сам файл.
- **Заблокированные команды:** правила и переключатель хранятся в `$DSH_HOME/storages/dsh-composer-plus/blocked-commands.json` (файл доступен только владельцу). Проверка читает только текст команды каждого вызова `bash` и `pwsh`; она ничего не запускает и ничего не отправляет.
- **Ввод секрета:** значение уходит из карточки (или из Tether через шлюз, который не записывает содержимое запросов) на Host только в запросе ответа. Host записывает его в `$DSH_HOME/storages/dsh-composer-plus/secrets/<случайное имя>` (папка 0700, файл 0600); ничего не попадает в проект, журнал чата или результат инструмента. Host хранит значение в памяти, чтобы заменять его на `[secret]` в следующих результатах инструментов этого чата. Файл и эта копия удаляются в конце хода чата и при запуске dsh. Переключатель находится рядом, в `secrets.json`. Команда, которую агент запускает с этим файлом, может отправить значение туда, куда отправляет эта команда: в этом и состоит цель.
- **Память проекта:** выключена, пока вы её не включите. Когда она включена, после каждого завершённого хода чата верхнего уровня часть Host отправляет новые сообщения этого чата с момента последнего разбора (ваши сообщения и текстовые ответы агента; без вывода инструментов, рассуждений, скрытого контекста и сообщений, убранных откатом; в ответвлённом чате копия родительского чата не учитывается; не больше примерно 16 000 символов) и сохранённые заметки модели этого чата, одним запросом без инструментов. Заметки — это файлы Markdown в `$DSH_HOME/storages/dsh-composer-plus/memory/` (доступны только владельцу): `projects/<id>/` для каждой папки проекта (`<id>` — хеш реального пути папки; `project.json` указывает папку), `global/`, `journal.jsonl` (каждое изменение со строкой до и после) и `reviewed.json` (до какого места прочитан каждый чат). В папку проекта ничего не записывается. Заметки, похожие на ключ, токен, пароль или номер документа, отклоняются. Заметки проекта попадают в системный промпт каждого нового чата в этой папке, поэтому уходят модели с каждым запросом этого чата. Переключатель хранится в `memory.json` там же. **Открыть память** ничего не отправляет, пока вы не нажмёте **Предпросмотр изменений**; тогда она отправляет показанные заметки и ваш текст модели dsh по умолчанию одним запросом без инструментов. Изменения записываются только по **Применить**, в журнале с `editor`. Tether читает и изменяет заметки через тот же маршрут. **История версий памяти** (включена по умолчанию) перед каждым сохранением кладёт копию файлов памяти в `memory/history/` рядом с ними (файлы только для владельца, 50 последних для каждой памяти); она ничего не отправляет модели. **Экспорт памяти в AGENTS.md** ничего не отправляет модели и пишет только после нажатия **Записать AGENTS.md**: он читает и пишет `AGENTS.md` в папке проекта этой памяти (только обычный файл внутри неё, никогда через символьную ссылку, ведущую наружу) и меняет только отмеченный раздел. **Поиск устаревших заметок памяти** ничего не отправляет модели и ничего не записывает: он проверяет пути внутри папки проекта через realpath (файлы не читаются), читает `package.json` только как обычный файл внутри папки и запускает там один `git for-each-ref`. **Не использовать память в этом чате** хранит каждый выключенный вами чат в `memory-chats.json` рядом (файл только для владельца, 500 последних); такой чат не отправляет модели никакой памяти. **Предложить заметки памяти из чата** ничего не отправляет, пока вы не нажмёте **Предложить для памяти**; затем он отправляет сохранённые заметки проекта чата и глобальные заметки, а также собственные сообщения и текстовые ответы чата (без вывода инструментов и откаченных сообщений; копия родителя в форке не отправляется; не больше примерно 24 000 символов) собственной модели чата одним запросом без инструментов. Предложение сохраняется только по **Принять**.
- **Резервное копирование:** ничего не покидает ваш компьютер. Архивы сохраняются в `~/Desktop/dsh-backups` (файлы доступны только владельцу). Секретов в архиве нет: файлы учётных данных (`.credentials.yaml`, `.env`), файлы ключей (`.pem`, `.key`, `.p12`, `.pfx`) и значения настроек token, secret, password и API-ключей в файлах yml скрыты; их настоящие копии остаются в `composer-plus-vault/<archive>/` в той же папке (доступно только владельцу) и только на этом компьютере. **Для другого компьютера** не копирует vault: введите эти секреты там заново. Ваши журналы чатов, настройки и остальное содержимое домашней папки dsh лежат в архиве как есть: держите папку закрытой, как и сам `$DSH_HOME`. Резервное копирование читает файлы с `O_NOFOLLOW | O_NONBLOCK`; символическая ссылка сохраняется как ссылка (переход по ней не выполняется), а FIFO или устройство пропускается. Переключатель и настройки автоматического резервного копирования хранятся в `$DSH_HOME/storages/dsh-composer-plus/auto-backup.json`, переключатель аварийной консоли — в `rescue-console.json`, а пока dsh работает, `running/host-<pid>.json` указывает каждый процесс dsh (аварийная консоль читает эти файлы, чтобы отказать в восстановлении).
- **Аварийная консоль:** меню в терминале; она не открывает сетевой порт. Восстановление пишет только в новую папку рядом с домашней папкой dsh (файлы — с `O_EXCL | O_NOFOLLOW`, символические ссылки — в последнюю очередь и без перехода по ним) и отклоняет архив с небезопасным именем (`..`, абсолютный путь), устройством или FIFO, более чем одной папкой верхнего уровня или записью внутри ссылки.

## Устранение неполадок

- **Нет уведомлений в macOS:** Системные настройки → Уведомления → DeepSeek Harness → разрешить. Выберите Предупреждения, чтобы уведомления оставались на экране.
- **После обновления dsh пропали ▶, маркеры очереди, статус проекта, фильтр недавних проектов, «Свернуть все проекты», «Копировать путь», поле поиска проектов, предсказание следующего сообщения, дополнение при вводе, «Разрешить для этого чата» или меню правого щелчка:** эти элементы привязаны к текущей HTML-разметке dsh, потому что в dsh пока нет для них отдельного места. Если dsh меняет эту разметку, они скрываются сами; больше ничего не ломается. Пожалуйста, откройте [issue](https://github.com/furkancak1r/dsh-composer-plus/issues).
- **«Не удалось обновить» или «установлена не из npm»:** копия, подключённая из локальной папки или переименованная, не может обновиться сама. Переустановите `dsh-composer-plus` в разделе Настройки → Плагины. В остальных случаях сообщение показывает первую строку ошибки pnpm; **Проверить обновления** повторяет попытку.
- **Мобильное подключение сообщает, что шлюз не запущен:** «no IPv4 address on en0» означает, что у этого Mac нет адреса Wi-Fi/Ethernet. «EADDRINUSE» означает, что порт 19390 или 19391 занят другим dsh (или приложением). Мобильное подключение может работать одновременно только в одном dsh.
- **Мобильное подключение, «Продолжать после перезапуска» или «Поиск по содержимому» просит «Перезапустите dsh»:** плагин обновился, пока dsh работал (или, для поиска по содержимому, вы изменили переключатель). Новое состояние загрузится после перезапуска.
- **Поиск находит только названия:** поиск по содержимому выключен, dsh не перезапускался после того, как вы включили функцию или установили плагин, или слово есть только в выводе инструмента (см. «Ограничения»).
- **На моих сообщениях нет кнопки ↶:** откат хода выключен, это чат субагента, или установлен dsh-rewind-plugin (пользуйтесь его кнопкой ↶). После обновления перезапустите dsh.
- **Пункт «Чат и файлы» недоступен (серый):** проект не является репозиторием git, нет снимка до этого сообщения (сообщение старше плагина, или его снимок вытеснили 50 более новых), или ни один файл не изменился.
- **При удалении появляется сообщение, что этот чат открыт в другом dsh:** второй dsh с той же домашней папкой dsh удерживает блокировку чата. Закройте это окно или dsh и удалите чат снова. До этого чат остаётся в архиве.
- **iPhone не подключается после включения «Tailscale only»:** Tailscale должен быть включён и на Mac, и на iPhone. Панель «Мобильное подключение» предупреждает, если на Mac он выключен. Журнал доступа показывает каждую отклонённую попытку и её причину.
- **Чат не продолжился после перезапуска:** функция «Продолжать после перезапуска» была выключена, когда dsh завершил работу; вы сами остановили этот ход; ход уже закончился (готово или сбой); чат был в архиве; или работало больше 20 чатов (продолжаются 20 самых новых).
- **После перезапуска очередь пуста:** очередь очищает сам dsh при завершении. Функция «Продолжать после перезапуска» возвращает её только в чате, который продолжается; в других чатах отправьте сообщения снова. Сообщение, удалённое прямо перед выходом, может вернуться: удалите его снова.
- **Открыть issue на GitHub сообщает «gh could not open the issue»:** это первая строка вывода самого `gh`. Выполните `gh auth status` в терминале и войдите с помощью `gh auth login`; у папки чата должен быть удалённый репозиторий GitHub (`git remote -v`). «not installed or not on the PATH of dsh» означает, что dsh не нашёл `gh`: установите его или запустите dsh из терминала, в котором `gh` работает.
- **«Сообщить о проблеме» сообщает «gh could not open the issue»:** это первая строка вывода самого `gh`. Выполните `gh auth status` в терминале и войдите с помощью `gh auth login`. Или нажмите **Открыть на сайте GitHub**: откроется собственная страница новой issue на GitHub с заполненным черновиком, и вы отправите её там.
- **На строке чата нет метки ветки:** боковая панель не в режиме «Одним списком» (в режимах «По рабочей области» и «Дерево рабочих областей» ни одна строка чата не показывает метку), у чата не было хода с момента установки этой версии, его папка не является репозиторием git, или функция **Ветка Git в строках чатов** выключена. После обновления перезапустите dsh (ветку записывает Host-часть).
- **Проверка цели сообщает, что тест завершился с кодом 127 или «not found»:** у dsh, запущенного из Finder или Dock, PATH может быть короче, чем в вашем терминале, поэтому он не находит `npm`, `pnpm` или `cargo`. Запустите dsh из терминала или задайте свою тестовую команду с полным путём в **Проверка цели** → **Изменить**. **Запустить сейчас** сразу показывает результат.
- **Цель не закрывается, и агент продолжает работать:** **Проверка цели** нашла непройденный тест или недоделанную работу; строка под целью показывает причину (наведите указатель на результат, чтобы увидеть подробности). Исправьте причину или тестовую команду либо завершите цель сами командой `/goal` или через панель цели (это не проверяется).
- **Установка не удаётся сразу после выпуска:** укажите версию (`dsh-composer-plus@1.27.1`), см. примечание об установке выше.
- **Кнопка «Создать копию сейчас» сообщает «Уже выполняется другое действие с резервными копиями»:** действие выполняется в другом окне dsh или в аварийной консоли (они используют общий файл блокировки `.composer-plus.lock` в папке резервных копий). Дождитесь его окончания. Если никакое действие не выполняется, блокировку закрытого процесса перехватит следующее нажатие.
- **Аварийная консоль сообщает «dsh is running»:** сначала выйдите из dsh. Если dsh действительно закрыт, файл, названный в сообщении, остался после сбоя: удалите его и повторите попытку.
- **После восстановления dsh не запускается или не хватает плагина:** пакеты плагинов профиля нужно установить заново. Аварийная консоль предлагает это после восстановления; или выполните `pnpm install` в каждой папке внутри `$DSH_HOME/profiles/`, которую она перечисляет. Секреты, которых не было в vault (другой компьютер), нужно ввести заново: консоль перечисляет их.

## Ограничения

- Продолжение без сообщения опирается на жизненный цикл dsh `agent/pre-step` → `agent/request`. Проверяйте совместимость при обновлении dsh.
- **Идеи функций** хранит карточки в памяти для каждого чата, пока не перезагрузится dsh или страница. После этого **Предложить функции** снова обращается к модели. Карточки приходят на том языке интерфейса dsh, который выбран в момент нажатия. Если вы смените язык, карточки, которые уже лежат в стопке, сохранят свой язык, а **Ещё идеи** использует новый. Модель видит только краткую сводку проекта, а не код, поэтому идея может повторять то, что в проекте уже есть: просто пропустите её. Новый чат запускается в режиме плана, только если в профиле есть команда dsh `/plan`; иначе идея уходит как обычное первое сообщение. Список **На потом** привязан к пути папки чата: та же папка, открытая через символическую ссылку, получает свой список. В нём хранится не более 50 идей на проект (удалите одну, чтобы добавить новые), и каждый заголовок только один раз. Перетаскивание карточки решает только «влево» или «вправо»; чтобы отложить её, используйте **↓**, а чтобы создать её сразу — **▶**. Повтор определяется только по заголовку: модель всё равно может предложить прежнюю идею под новым названием; пропустите её. Если модель отвечает только прежними идеями, ничего нового не появляется: нажмите ещё раз. Узкая тема делает это более вероятным: выберите тему шире или очистите её. Тема остаётся в поле для каждого чата, пока не перезагрузится dsh или страница.
- **Экспорт чата в Markdown** включает только ваши сообщения и текстовые ответы ассистента. Вызовы инструментов и их вывод, рассуждения, изображения (их отмечает строка `[image]`), скрытый контекст и сообщения, которые убрал откат хода или dsh-rewind-plugin, в экспорт не попадают. Ответы одного хода объединяются в один раздел. В один экспорт входит не более примерно 4 миллионов символов; для более длинного чата экспорт содержит его первую часть и примечание.
- **Продолжать после перезапуска** продолжает ход, а не повторяет его. Вызов инструмента, который выполнялся в момент выхода, завершается результатом dsh «outcome unknown» (результат неизвестен). Модели сообщается, что не нужно повторять сделанную работу, но команда, которую небезопасно запускать дважды, может выполниться снова. Субагенты, одобрения и вопросы, которые были открыты, не восстанавливаются: их родительский чат продолжает работу и спрашивает снова. За один запуск продолжается не более 20 чатов.
- **Продолжать после перезапуска** и очередь: при завершении dsh очищает очередь чата. Плагин возвращает ваши сообщения из очереди по журналу чата, с их порядком, правками, изображениями и файлами; они выполняются после продолженного хода. Очередь возвращается только в чатах, которые продолжаются (переключатель включён, выход во время хода). Ваше собственное удаление последних сообщений из очереди dsh записывает так же: если вы удалили их и dsh завершил работу до начала следующего шага, они вернутся.

- **Поиск по содержимому** — это встроенный поиск dsh, поэтому у него те же ограничения. Он ищет только в сообщениях пользователя и ассистента: не в выводе инструментов (команды, содержимое файлов, результаты) и не в рассуждениях. Фильтра по сообщениям пользователя, ассистента или инструментов нет. Он находит целые слова, а не части слов (`deploy` не находит `deployment`); буквы с диакритикой совпадают с буквами без неё (`seker` находит `şeker`). На каждый чат одна строка с фрагментом dsh длиной 240 символов, всего не более 20 строк.
- **Поиск по содержимому**: затраты измерены на копии 247 реальных журналов чатов (159 МБ, dsh 0.2.1-rc.2, Apple Silicon, 32 ГБ). Первый поиск после запуска строит индекс примерно за 15 с. В это время Host dsh около 7 с ничего не отвечает, поэтому другие чаты на этот момент перестают выводить ответ (сама страница не зависает). Память Host на пике вырастает примерно на 1,1 ГБ; через минуту она всё ещё примерно на 0,5–0,6 ГБ выше начальной и остаётся такой до выхода из dsh. Файл индекса занимает около 165 МБ. Следующие поиски занимают около 0,5 с. После перезапуска первый поиск занимает около 1 с (добавляются только новые или изменённые чаты) и добавляет около 70 МБ. Если на компьютере мало памяти, выключите эту функцию.
- **Поиск по содержимому** начинает действовать только после перезапуска dsh. Файл индекса общий для всех dsh, которые используют одну домашнюю папку dsh: запускайте одновременно только один такой dsh (dsh допускает одного владельца на файл индекса).
- **Откат хода** возвращает файлы только в репозитории git и только в папке чата. Он хранит 50 самых новых снимков на чат. Игнорируемые файлы (`.gitignore`, `info/exclude`, ваш глобальный файл игнорирования), пустые папки, символические ссылки и подмодули не возвращаются. Файл, который был игнорируемым в момент снимка, никогда не удаляется, даже если ход изменил правила игнорирования. Файл, который git не может прочитать, не попадает в снимок. Каждое ваше сообщение запускает один `git add --all` папки чата в закрытое хранилище. В очень большой папке с множеством неотслеживаемых файлов это может занять несколько секунд, и следующий вызов инструмента ждёт завершения (не более 10 с; затем снимок заканчивается в фоне). Если `git gc` вашего репозитория удалит объект, который нужен старому снимку, этот файл будет показан как не возвращённый. В поле ввода возвращается только текст сообщения: добавьте его изображения или файлы снова. У чатов субагентов нет ↶ (изменения файлов субагентом считаются изменениями чата, который его запустил). Экспортированный чат (`/export`) по-прежнему содержит отозванные сообщения. Идея одной скрытой метки, которая отзывает часть чата, взята из [dsh-rewind-plugin](https://github.com/SiriLee/dsh-rewind) от SiriLee (MIT); Composer Plus не использует его код.
- **Удалить чат** требует архивации dsh (dsh 0.2.0 и новее). Если чат (или один из чатов его субагентов) не останавливается за 15 с или его удерживает другой dsh, он остаётся в архиве, и ничего не перемещается. В системах, отличных от macOS, папка корзины должна быть на том же диске, что и история чатов. Открытый чат, который вы удалили, остаётся в памяти dsh (в архиве и скрытым) до перезапуска dsh. Очищайте Корзину сами: dsh этого не делает.
- В очереди dsh нет действия `move`, поэтому Host-часть плагина перемещает само сообщение в очереди dsh (одно изменение, то же самое сообщение). Сообщения с изображениями или файлами тоже перемещаются. Перемещаются только ваши собственные сообщения: раунд цели или ответ на вопрос в очереди остаётся на своём месте. Если сообщение начинает отправляться, пока вы перетаскиваете, ничего не перемещается, и об этом сообщает уведомление.
- dsh 0.2.1 загружает обновление сразу, если новая версия не меняет никаких настроек dsh; в остальных случаях, а также в dsh 0.2.0, перезапустите dsh, чтобы загрузить его. Плагин никогда не перезапускает dsh за вас. Профили Web/CLI без менеджера плагинов dsh только сообщают о новой версии.
- **Что нового в Composer Plus N** показывает примечания на языке из **Язык приложения**. Язык интерфейса с другим регионом получает примечания своего основного языка (`en-GB` — английские, `zh-TW` — китайские примечания `zh`). Для языка без примечаний (его добавляет другой языковой пакет, или это `pt-PT`, а не `pt-BR`) показываются английские примечания. Примечания приходят вместе с новой версией. Если у запущенной копии нет читаемого файла примечаний (`release-notes.json`), окно показывает английские примечания с GitHub.
- Версия, установленная во время работы dsh (обновление через Настройки → Плагины или скопированную папку), загружается только после перезапуска dsh: до этого **Обновления Composer Plus** показывает запущенную версию и просит перезапустить dsh. Её окно **Что нового в Composer Plus N** показывается один раз при первом запуске этой версии. Первый запуск после установки плагина не показывает окно; **Что нового в этой версии** открывает примечания запущенной версии.
- Строка со звездой GitHub под примечаниями не может знать, поставили ли вы звезду репозиторию: плагин не делает для этого сетевых запросов. Каждый браузер (и настольное приложение) хранит свою запись, поэтому в другом браузере строка может показаться ещё раз.
- **Отклонить с примечанием** отправляет примечание как сообщение в ожидающий ход, а затем отклоняет запрос; dsh показывает примечание в чате как ваше сообщение. Пока поле примечания открыто, карточка показывает только **Отмена** и **Отклонить**, поэтому щелчок не может по ошибке разрешить запрос; `Esc` или **Отмена** возвращает кнопки dsh. Пустое примечание ничего не отправляет (используйте собственную кнопку **Отклонить** в dsh). Если отклонить запрос не удалось уже после отправки примечания (например, на запрос тем временем ответили в другом месте), примечание остаётся в чате, и модель прочитает его на своём следующем шаге. Кнопка встраивается в разметку карточки одобрения dsh (`data-approval-key`), потому что в dsh нет места для действий карточки; если обновление dsh изменит эту разметку, кнопка не появится, а собственная кнопка **Отклонить** в dsh работает как раньше. Примечание может содержать не более 4 000 символов.
- **Ввод секрета** скрывает только точный текст значения: в следующих результатах инструментов того же чата его заменяет `[secret]`. Агент всё равно может прочитать файл командой shell и вывести значение в другой форме (base64, часть значения, с пробелами), и эта форма дойдёт до модели. Собственные файловые инструменты агента (read, grep, write, edit) не могут открыть папку секретов. Если значение — ещё и частое слово, другие результаты этого чата тоже покажут `[secret]`. Файл хранится до конца хода; если dsh закроется во время хода, следующий запуск удалит его. В чате может быть только один открытый запрос одновременно. Инструмент добавляет к каждому запросу к модели около 870 символов (примерно 220 токенов, оценка): выключите его, если не пользуетесь.
- **Цитата в ответе** цитирует текст так, как его показывает страница: блок кода, таблица или список приходят простыми строками, без разметки Markdown. Если выделение начинается в одном ответе и заканчивается в другом или задевает рассуждения, строку инструмента или ваше собственное сообщение, кнопка не появится: выделяйте внутри одного ответа. Кнопка находит ответ по структуре чата dsh, потому что в dsh нет слота для выделения текста; если обновление dsh изменит эту структуру, кнопка не появится. Если цитата стоит в конце поля, после неё добавляется ещё одна пустая строка, чтобы следующая строка начиналась ниже; при отправке dsh удаляет пустые строки в конце.
- **Цитата из предпросмотра файла** читает собственный предпросмотр файлов dsh: номера строк берутся из его строк, поэтому для файлов кода и текстовых файлов они верные. Файл Markdown показывается как оформленная страница, поэтому его цитата содержит текст без разметки Markdown и без номеров строк; цитата из PDF содержит страницу, а не строку. Если выделение находится в заголовке с путём, в другом средстве просмотра (таблица, файл Office, изображение) или захватывает два открытых файла, кнопка не появится; не появится она и тогда, когда правая боковая панель развёрнута на весь экран (поля ввода тогда нет на экране). Кнопка находит предпросмотр по разметке dsh, потому что в dsh там нет слота для выделения; если обновление dsh изменит эту разметку, кнопка не появится. В поле ввода попадает только выделенный текст: если файл потом изменится, цитата не изменится.
- **Побочный чат** работает только на чтение благодаря собственному режиму только чтения dsh: файловые инструменты не могут писать, а команды оболочки выполняются в песочнице dsh без записи (или не выполняются, если песочница не может запуститься). Агент всё же может запросить больше доступа через карточку подтверждения dsh, а сетевой вызов (например, запрос к API) всё же может изменить что-то за пределами компьютера. Копия делается на самый новый момент, когда в очереди не ждало ни одного сообщения, поэтому вопрос, заданный, пока сообщения ждут в очереди, не видит того, что было после них. Выполняемый шаг чата в копии закрывается, поэтому побочный чат знает начало этого шага, но не его результат. Побочный чат — обычный чат: он остаётся на боковой панели и учитывается в использовании модели; архивируйте его там. «Вернуть» берёт только собственные сообщения побочного чата (не более 12 000 символов) и только последний ответ на каждый вопрос; заметки агента между вызовами инструментов не попадают. dsh не даёт плагинам места для чата на правой боковой панели, поэтому побочный чат открывается в основном виде.
- **Заметки к diff** работают только на панели изменений, а не в представлении «Последний ход» dsh. Диапазон должен оставаться в одном блоке diff (в одной части `@@`). Заметки хранятся в хранилище этого браузера, поэтому другой браузер или dsh на другом компьютере их не видит; Tether хранит свои заметки в памяти. Заметка сохраняет строки такими, какими они были в момент щелчка: если агент потом изменит файл, заметка покажет старые строки и номера. Не более 50 заметок на чат, 2 000 символов и 40 строк на заметку (дальше строка `…`).
- **Разрешить для этого чата** отсчитывает лимит времени с момента выдачи разрешения. Новый лимит времени сразу применяется к действующим разрешениям, поэтому более короткий лимит может сразу их завершить. У разрешений из версии 1.12 и более ранних нет времени: после обновления агент ещё раз спросит об этих инструментах.
- **Сохранять фокус в поле ввода** возвращает фокус только после команды `/` или навыка. Пока dsh обрабатывает команду, поле ввода несколько миллисекунд доступно только для чтения, поэтому клавиши, нажатые в это время, теряются. Если меню `/` в dsh ещё открыто, `Enter` выбирает выделенную строку и ничего не отправляет.
- **Подгонять карточку вопроса под окно** меняет только карточку вопроса dsh, а не карточку проверки плана. Она находит карточку по разметке dsh (`data-question-key`, `data-question-scroll`); если обновление dsh изменит эту разметку, карточка будет выглядеть так, как её рисует dsh. Высота карточки следует за окном, а не за чатом: в чате в узкой боковой панели высокая карточка всё ещё может выходить выше чата.
- **Подогнать заголовок чата под окно** находит заголовок чата dsh по его сгенерированным именам классов (`_titleRow`, `_titleCluster`, `_crumbs`, `_headerActions`, `_headerUtilities`), потому что dsh не даёт точки подключения для его раскладки. Если обновление dsh переименует их, заголовок показывается так, как его рисует dsh. В очень узкой колонке чата заголовок может занять две или три строки, и места над сообщениями становится меньше.
- **Работающие субагенты в заголовке чата** меняет только текст собственного счётчика dsh. Он считает прямых субагентов чата (то же число, что и dsh), а не субагентов субагента. dsh рисует открытый список без места для плагинов, поэтому строка с общим числом ставится над структурой списка dsh (`role="tree"`). Если обновление dsh изменит эту структуру, в списке не будет строки с общим числом, а заголовок по-прежнему покажет работающих субагентов.
- **Мобильное подключение** работает только в macOS (оно использует `en0`, `openssl`, `swift` и `dns-sd`). Оно использует фиксированные порты 19390 и 19391, поэтому на каждом Mac его может одновременно запускать только один dsh (каждый Mac — одна запись в списке Mac на телефоне). С ключом APNs в `apns.json` (см. `tether/README.md`) Mac отправляет уведомления через push-сервис Apple, поэтому они приходят и при закрытом Tether; Mac должен быть активен, а dsh открыт. Без ключа телефон получает уведомления, только пока Tether открыт или только что ушёл в фон. Tether отправляет их только после того, как вы включите в Tether «Settings → Notifications → Send notifications». Tether хранит этот переключатель и его часы отдельно для каждого сопряжённого Mac. По умолчанию он выключен на каждом Mac, а разрешение iOS запрашивает в момент включения. Приложения для iOS пока нет в App Store: соберите его из `tether/ios` в Xcode. «Tailscale only» всё равно требует адрес Wi-Fi или Ethernet на Mac (шлюз запускается только при таком адресе). Журнал доступа у каждого Mac свой и хранит только 200 самых новых попыток; повторная попытка в течение минуты увеличивает счётчик той же строки на один. Каждое уведомление показывает Mac и проект чата (`Studio Mac · recipe-box`), название чата и текст: Turn finished показывает последний ответ агента. С ключом APNs этот текст проходит через push-сервис Apple. Блокировка приложения Tether не скрывает превью уведомлений на экране блокировки iPhone: выключите их в настройках iOS. Зелёные точки в Tether следуют за Mac: у чата, который вы открыли в dsh, точка пропадает и на телефоне. У чата, который вы открыли в Tether, точка пропадает и в dsh, примерно за 3 секунды, пока открыто окно dsh. Поэтому телефон и dsh показывают одно и то же число. Для этого окно dsh меняет список непрочитанных dsh через ту же часть dsh, что и **Отметить все как прочитанные** (это не публичный API). У архивного чата нет точки на телефоне, как и в dsh. Mac, в Composer Plus которого нет этого списка (более старая версия), не показывает зелёных точек в Tether.
- **Удалённые компьютеры** требуют Tailscale на обоих Mac и Composer Plus с включённой функцией на Mac, который вы открываете. Этот Mac не должен быть в режиме сна, и на нём должен работать dsh. Меню выбора компьютера видно, только когда левая боковая панель открыта (а не свёрнута до значков). Если на странице другого Mac нет своего меню выбора (там Composer Plus версии ниже 1.23.0), меню выбора этого Mac появляется в том же месте поверх этой страницы. Если там версия 1.23.0 или новее, страница того Mac показывает меню выбора своей версии Composer Plus (старая версия показывает одну кнопку, а не две части). Каждый открытый вами компьютер держит свою страницу в памяти, пока вы не выключите функцию или не перезапустите dsh. Если компьютер не ответил (он спал или Tailscale был выключен), его страница не сохраняется: выберите его снова, и она загрузится заново. В настольном приложении страница другого Mac — встроенная страница: собственные сочетания клавиш dsh (например, новый чат) в ней не работают, и загрузка файлов, микрофон и уведомления там тоже не работают. В macOS эта страница занимает всё окно и рисует собственную строку заголовка, как страница этого Mac; чтобы переместить окно, перетащите область рядом с кнопками-светофором. Функция использует порт 19392 (на каждом Mac пускать другие компьютеры может только один dsh). Со страницы другого Mac меню выбора переключает только между компьютерами этого Mac: открыть третий Mac через другой Mac нельзя. Две части учитывают только сопряжённые и доступные компьютеры (компьютер, который нужно сопрячь заново, не учитывается); если такой компьютер один, пункт **Добавить компьютер…** доступен через правый клик (на сенсорном экране — долгое нажатие) или в **Настройки → Composer Plus → Удалённые компьютеры**.
- Ссылка на сеанс работает внутри чатов; щелчок по ней не открывает чат. Ссылка, созданная через **Копировать ссылку на сообщение**, открывает своё сообщение только в dsh 0.2.1 и новее и только из сообщения в чате (в dsh 0.2.0 нет правил для пользовательского текста, поэтому там ссылка копируется, но показывается как обычный текст). Сообщение, которое убрал откат или которое сжатие удалило из истории, загружаемой dsh, показать нельзя: ссылка тогда сообщает об этом. Кнопки 🔗 привязаны к строкам сообщений dsh; если обновление dsh изменит эту разметку, они не появятся.
- **Отметить все как прочитанные** меняет собственные точки непрочитанного dsh через часть dsh, которая не является публичным API (список `completionUnread` в состоянии сеансов dsh). Если обновление dsh переименует его, пункт не появится. Пункт добавляется в меню «…» проекта в dsh, где нет места для плагинов; если dsh изменит это меню, пункт тоже не появится.
- **Правка сообщения в очереди на месте** не меняет сообщение, которое тем временем начало отправляться, и не перезаписывает сообщение, которое тем временем изменилось (например, в Tether на iPhone): об этом сообщает уведомление. Для нового изображения нужна модель, которая принимает изображения (действуют собственные ограничения dsh на изображения), а новый файл должен загрузиться до того, как вы сможете сохранить. Изменять можно только свои сообщения в очереди: раунд цели или ответ на вопрос в очереди изменить нельзя. После обновления плагина сразу работает только правка текста: перезапустите dsh, прежде чем сохранять сообщение с изображениями или файлами (Host-часть загружается при запуске).
- **Повторить** никогда не меняет откаченный чат: кнопка начинает новый чат с момента непосредственно перед откатом (встроенное ответвление dsh, тот же контекст модели), поэтому у нового чата новый id и новое название. Повторить можно только самый новый откат чата, один раз и только пока после него ничего не было (новое сообщение убирает эту возможность). Файл, который вы изменили после отката, сохраняется, если вы не отметите флажок, который его перезаписывает. Для повтора нужен снимок, который сохранил откат (то же окно из 50 записей); откат, сделанный до этой версии или с вариантом **Только чат**, возвращает только сообщения.
- Карта веток в режиме **Дерево** угадывает, куда идёт каждая стрелка, потому что git не сохраняет, в какую ветку слита ветка. Слитая ветка указывает на ветку, коммит слияния которой первым принял её. Ожидающая ветка указывает на ближайшую ветку, от которой она началась (в первую очередь на основную ветку); если две ветки начались от одного коммита, карта может выбрать не ту. У ветки, которая продвинулась перемоткой вперёд (fast-forward), нет коммита слияния, поэтому её метка **Слито** ничего не открывает. Основная ветка — это ветка по умолчанию у `origin`, иначе `main` или `master`, иначе открытая ветка. Карта читает последние 20 000 коммитов и показывает не больше 60 веток; если история длиннее, она сообщает, что некоторые стрелки могут быть неверными. Ветка, слитая через squash или rebase (например, на GitHub), показывается как **Ожидает**: git не хранит связи с её коммитами.
- **Этот чат** учитывает только файлы, которые записали файловые инструменты dsh (`write`, `edit`, `str_replace_editor`). Файлов, которые изменила команда (`bash`), в этом представлении нет; они показаны в разделе **Незафиксированные**. Без снимка отката хода для чата (откат хода выключен, установлен dsh-rewind-plugin или чат старше плагина) представление сравнивает с последним коммитом и сообщает об этом. Откат хода хранит 50 последних снимков чата: в более длинном чате представление сравнивает с самым старым сохранённым снимком, сообщает, с какого сообщения, и не учитывает более ранние изменения. **Скрыть изменения пробелов** — это `git diff -w`: строка, в которой изменились только пробелы внутри неё, тоже скрывается.
- **Открыть issue на GitHub** требует GitHub CLI (`gh`) в PATH dsh и удалённый репозиторий GitHub в папке чата. Команда работает не дольше 60 с; если `gh` работает дольше, issue может уже существовать на GitHub без ссылки в списке (прежде чем нажать ещё раз, проверьте GitHub: список читает ссылку только из завершённого запуска, поэтому новое нажатие может открыть вторую issue). Папка с несколькими удалёнными репозиториями GitHub использует значение по умолчанию самого `gh` (`gh repo set-default`).
- **Сообщить о проблеме** открывает issue только в репозитории Composer Plus (`furkancak1r/dsh-composer-plus`), а не в вашем проекте (для проекта используйте **Открыть issue на GitHub** в списке **На потом** функции «Идеи функций»). Для черновика нужна модель по умолчанию в dsh, а чтобы открыть issue — GitHub CLI (`gh`) с выполненным входом. Черновик всегда на английском. Модель может ошибиться в деталях: прочитайте черновик, прежде чем нажать **Открыть issue**. Открытие длится не более 60 с; если в течение часа снова отправить тот же заголовок и текст, вместо копии показывается прежняя issue. **Открыть на сайте GitHub** обрезает очень длинное описание, чтобы ссылка оставалась короткой.
- **Чаты, которые изменили этот файл**, как и **Этот чат**, знают только файловые инструменты dsh (`write`, `edit`, `str_replace_editor`): изменение, сделанное командой (`bash`), в списке не появляется. Список читает 300 самых новых чатов репозитория (по времени создания) и сообщает, если их больше; он показывает не более 100 строк. Переименованный файл показан под тем именем, которое записал инструмент. Чат, папка которого находится вне репозитория (в том числе через другой путь к тем же файлам), не учитывается. Первое открытие после запуска dsh читает все журналы чатов репозитория (около 4 с для 275 чатов); последующие открытия читают только чаты, изменившиеся с тех пор.
- **Ветка Git в строках чатов** показывает ветку папки чата на момент начала или конца его последнего хода, а не текущую ветку: переключение ветки вне хода появится после следующего хода. У чатов, созданных до этой версии, метки нет до их следующего хода. Метка встроена в разметку строк чатов dsh (в dsh нет для неё отдельного места); если обновление dsh изменит эту разметку, метка не появится. Метка видна только в режиме «Одним списком».
- **Ветка для каждого чата** в режиме плана: dsh отправляет `/plan <сообщение>` как команду, а не как сообщение, поэтому Composer Plus перехватывает отправку команды в поле ввода dsh (это не публичный API). Если обновление dsh это изменит, `/plan <сообщение>` при выбранном пункте **Новая ветка** выполнится на открытом экране нового чата как собственная команда dsh. Если Host не может включить режим плана в новом чате, папка ветки остаётся, а сообщение не отправляется, поэтому новый чат не меняет файлы в режиме по умолчанию.
- **Ветка для каждого чата**: когда папка ветки чата (`<project>/.worktrees/<name>`) удалена, например когда агент самого чата удаляет worktree и ветку, следующий шаг чата выводит чат из этой папки. Проект папки ветки исчезает с боковой панели, а чат появляется в разделе «Без группы» и остаётся открытым. В dsh 0.2.1 и новее чат продолжается в основной папке проекта, и модель получает заметку о новой папке. В dsh 0.2.0 чат остаётся в удалённой папке: команда там завершается с ошибкой, пока вы не начнёте новый чат. Проект удалённой ветки, который не использует ни один чат, тоже исчезает с боковой панели: Composer Plus проверяет папки веток при запуске и каждые 30 секунд, также без фильтра боковой панели. Пока чат переносится, **Новая ветка** в том же репозитории отвечает «попробуйте ещё раз». Если переключатель выключен, снова показывается собственная ошибка dsh («working-directory: directory does not exist»).
- **Ветки в дереве рабочих областей** пишет в git без клика: при переносе чата он возвращает папку проекта на прежнюю ветку (`git switch`) и добавляет worktree (`git worktree add`). Он никогда не удаляет ветку, worktree или файл. dsh не может сменить папку чата, поэтому перенесённый чат — это копия (собственный форк dsh с новым id), а старый чат архивируется. Копия продолжает остановленную задачу; вызов инструмента, который шёл в момент появления ветки, завершается отказом, и агент запускает его снова в новой папке. Цель старого чата не переносится. Переносится только чат, чья папка — главная папка репозитория, и только ради ветки, которую он создал и на которую переключился в этом ходе (`git switch -c`, `git checkout -b`): ветка, созданная только через `git branch`, папка с незакоммиченными изменениями, связанный worktree или подпапка ничего не переносят. В дереве показываются только worktree прямо в `<project>/.worktrees/` с веткой; отсоединённый (detached) worktree или worktree в другом месте не показывается. Копия открывается сама, только если её чат был открытым (плагин читает это из строки боковой панели dsh); иначе она находится в проекте ветки.
- **Поиск в чате** ищет только в том, что показывает страница: в загруженных сообщениях и ответах (для более старых прокрутите вверх или нажмите **Загрузить более ранние**), но не в закрытых шагах инструментов и не в свёрнутом тексте вывода инструмента. Он считает не более 2 000 совпадений (дальше — «2000+»). Он использует API подсветки браузера (Chromium 105 и новее; в настольном приложении он есть): в более старом браузере счётчик и переходы работают без цвета. `Cmd+F` на Mac (`Ctrl+F` в Windows и Linux) открывает его, только пока на экране есть чат; в других местах встроенный поиск браузера работает как раньше. На Mac `Ctrl+F` сохраняет своё действие macOS в текстовых полях (курсор сдвигается на один символ вперёд).
- **Открывать ожидающий чат при бездействии** знает только то, что видит окно dsh: работа в другом приложении не считается, поэтому, когда dsh в фоне, функция может открыть ожидающий чат через 30 секунд. Окно dsh при этом не выходит на передний план. Чтение без нажатия клавиш, щелчков и движений мыши считается бездействием. Функция смотрит только на чаты с оранжевой точкой dsh (вопрос, одобрение или проверка плана) или с зелёной точкой (завершённый ход, который вы ещё не открыли); запрос субагента показывается в его родительском чате. Оранжевые чаты открываются первыми. Открытие зелёного чата убирает его точку, поэтому 30 секунд следующего зелёного чата начинаются только после вашего следующего нажатия клавиши, щелчка, движения мыши, прокрутки колесом или касания: когда вы вернётесь, остальные зелёные точки останутся на месте. Пока ожидающий чат на экране, другой не открывается; чат, из которого вы ушли без ответа, может открыться снова после следующих 30 секунд бездействия. 30 секунд изменить нельзя.
- **Следующий ожидающий чат** считает те же чаты, что и **Открывать ожидающий чат при бездействии**: оранжевую точку dsh (вопрос, одобрение или проверка плана, на которые можно ответить здесь) и зелёную точку (завершённый ход, который вы ещё не открывали); запрос субагента показывается в его родительском чате. dsh не сохраняет, когда чат начал ждать, поэтому порядок считается с момента, когда это окно его увидело: после перезагрузки уже ожидавшие чаты сохраняют порядок dsh. Клавиша — это сочетание клавиш dsh: в браузере в Linux у неё нет клавиши, пока вы не зададите её на странице сочетаний клавиш dsh, а расширение браузера или другое приложение может перехватить `Cmd+Shift+E` раньше. В заголовке боковой панели dsh нет места для расширений, поэтому кнопка встраивается в разметку этого заголовка. Если обновление dsh её изменит, кнопка не появится, а клавиша продолжит работать. В узкой боковой панели кнопки нет.
- **Кнопки вариантов** читает только ответы, которые заканчиваются списком вариантов: нумерованным списком из 1–9 пунктов, с нумерацией от 1, в самом конце ответа, сразу под заголовком или жирной строкой «Варианты» или «Следующие шаги» (или английскими словами «Options», «Choices» и «Next steps» и теми же словами на других языках приложения). Список в середине ответа, в блоке кода или под другим заголовком кнопок не получает. Composer Plus не просит агента писать такой список. Кнопки появляются только под самым новым ответом, пока чат простаивает и поле сообщения пусто, и только когда Composer Plus знает, какие ответы отозвал откат. На карточке вопроса dsh клавиши 1–9 ничего не делают первые 0,8 секунды после появления вопроса, чтобы клавиша, нажатая для другого действия, не выбрала вариант, который вы не прочитали. У карточки вопроса dsh нет API для клавиш, поэтому клавиши находят кнопки карточки в разметке dsh. Если обновление dsh изменит эту разметку, клавиши ничего не делают.
- **Кнопка «Одобрить»** работает, только если модель следует правилу и пишет фразу в блоке `onay`; иначе копируйте и вставляйте фразу, как раньше. Автопроверка по-прежнему проверяет каждый вызов инструмента; кнопка только избавляет от набора текста. Кнопки есть только у последнего ответа, поэтому старая фраза одобрения не может одобрить более поздний шаг. Для фразы с буквами не из английского и турецкого алфавитов кнопки нет.
- Уведомление, отправленное до перезапуска, при щелчке только выводит dsh на передний план.
- Активные проекты перемещаются через сохранённый порядок проектов dsh, поэтому новый порядок сохраняется после перезапуска. Чаты вне проектов («Без группы») перемещать нельзя; dsh всегда показывает их последними.
- В меню параметров просмотра на боковой панели у dsh нет точки расширения, поэтому пункт фильтра недавних проектов добавляется во встроенное меню dsh. Если обновление dsh изменит это меню, пункт не появится, и все проекты останутся видны. Фильтр работает со строками проектов, поэтому режим **Одним списком** не фильтруется. В режиме **Дерево рабочих областей** родительская папка остаётся видна, пока активен проект внутри неё, а строки чатов, которые не были активны за последние 2 часа, тоже скрываются; в режиме **По рабочей области** фильтруются только строки проектов. Фильтр узнаёт текущий вид dsh из сохранённой настройки вида dsh (это не публичный API); если обновление dsh её переименует, **Дерево рабочих областей** фильтруется как **По рабочей области**. Функция «Статус проекта» читает ту же настройку: в режиме **Дерево рабочих областей** строка родительской папки учитывает и чаты проектов внутри неё; если dsh переименует настройку, каждая строка показывает только свои чаты. У **По состоянию** ограничение того же рода: в dsh нет места для своего порядка сортировки, поэтому пункт и порядок строк привязаны к разметке меню и списка dsh.
- В dsh нет ни меню строки проекта, ни места в заголовке «Рабочие области». **Копировать путь** находит строку проекта по разметке строк dsh, а **Свернуть все проекты** встраивается в заголовок dsh и закрывает каждый открытый проект тем же щелчком, что и строка проекта. Если обновление dsh изменит эту разметку, правый щелчок покажет меню браузера, а кнопка не появится.
- В меню проектов нового чата у dsh тоже нет точки расширения, поэтому поле **Поиск проектов** и порядок A–Z привязаны к разметке меню dsh. Если обновление dsh изменит эту разметку, меню будет выглядеть так, как его рисует dsh: в сохранённом порядке и без поля поиска. Порядок A–Z — только способ показа: он не меняет сохранённый порядок проектов dsh.
- В dsh также нет точки расширения, которая выбирает, где открывается **Новый сеанс**. **Рабочая область по умолчанию для нового сеанса** оборачивает метод dsh, который не является публичным API (`startSession` службы рабочих областей dsh). Если обновление dsh его переименует, **Новый сеанс** откроется там, где выберет dsh (открытый или последний проект). Каждый вызов без проекта использует значение по умолчанию: кнопка на боковой панели, её сочетание клавиш, логотип, а также **Создать** на странице **Задачи автоматизации**. При запуске dsh по-прежнему открывает последний чат. Общая папка создаётся и добавляется в ваши проекты при первом использовании; в Windows или Linux с перемещённой папкой Documents она может отличаться от папки самого dsh.
- Для подсказки в поле ввода у dsh тоже нет точки расширения, поэтому текст **Предсказание следующего сообщения** накладывается на собственный текст-заполнитель dsh (`[data-composer-placeholder]`). Если обновление dsh изменит эту разметку, предсказание не появится. Пока функция включена, каждый завершённый ход стоит один короткий вызов модели.
- **Дополнение при вводе** показывает свой текст через собственную подсказку поля ввода dsh (стиль `--dsh-composer-hint`, который dsh использует для подсказки аргумента слеш-команды). Функция не работает для слеш-команды, для сообщения со значком файла или символа и когда курсор стоит не в конце сообщения. Если обновление dsh изменит этот стиль, дополнение не появится. Каждая пауза в наборе стоит один вызов модели.
- **Улучшить промпт** видит только краткую сводку проекта, изменённые пути и пути, имена которых совпадают с вашими словами, но не сам код. Поэтому функция может пропустить нужный файл и называет только те пути, которые получила. Прочитайте новый текст перед отправкой. Она не работает для слеш-команды, кроме `/goal <цель>`, для управляющего слова `/goal` (`clear`, `pause`, `resume`) и для сообщения со значком файла или символа (новый текст — обычный текст, поэтому значок бы потерялся), а в сообщении может быть не более 8 000 символов. Для цели `/goal` функция пишет условия только из черновика и контекста; слишком строгое условие может стоить лишних раундов цели, поэтому прочитайте его перед отправкой. Изображения остаются прикреплёнными: меняется только текст. Каждое нажатие стоит один вызов модели; сильной модели может понадобиться минута (`Esc` отменяет).
- **Проверка цели** проверяет только выполнение, которое агент отмечает в автоматическом раунде цели: выполнение, о котором вы просите в чате, `/goal` и панель цели не проверяются. Агент может сам изменить тесты или файлы тестовой команды; верификатор читает чат и может это увидеть, но может ошибиться в обе стороны (ошибочное «не выполнено» стоит ещё одного раунда; ошибочное «выполнено» закрывает цель). Верификатор видит чат и `git status`, но не сам код. Запуск тестов используется повторно, только если последним шагом агента, который может менять файлы, был его собственный успешный запуск `bash` точно той же команды в той же папке; команда с конвейером (`| tail`) или `&&` повторно не используется. Бюджет измеряется, когда заканчивается ход, поэтому один ход может его превысить. Бюджет токенов учитывает и вызовы чатов субагентов этого чата (они читаются из их сохранённых журналов в конце каждого хода, поэтому проверка чата с большим числом субагентов идёт немного дольше). Таблица доказательств основана на том, как верификатор сам прочитал чат: часть, которую он называет подтверждённой, всё равно стоит проверить самому, если она важна. `update_goal` ждёт, пока идёт проверка (тест не более 15 минут, верификатор не более 3 минут). Ответвление получает новый id чата, поэтому начинает без собственной тестовой команды и лимитов родительского чата. Каждое выполнение, которое доходит до верификатора, стоит одного вызова модели.
- **Защищённые файлы** — это ограждение, а не песочница. Функция охватывает собственные файловые инструменты dsh (`read`, `read_image`, `grep` по файлу, `write`, `edit`, `str_replace_editor`). Команда оболочки (`cat .env`), скрипт, который пишет агент, оболочка субагента, инструмент MCP, список `glob` и `grep` по всей папке всё равно могут добраться до защищённого файла. Для настоящего ограничения используйте режимы песочницы dsh или храните секреты вне папки проекта. Шаблоны понимают `*`, `**` и `?`, но не `{a,b}` и не `[ab]`, и не учитывают регистр букв.
- **Заблокированные команды** — это ограждение, а не песочница. Функция читает только текст команд инструментов dsh `bash` и `pwsh`. Переменная или псевдоним, который называет команду (`CMD=npm; $CMD publish`), функция оболочки, файл скрипта, который пишет агент, другая программа (`python -c`, `node -e`, `make`), инструмент MCP и ваш собственный терминал всё равно могут её запустить. Правило может подходить к большему, чем вы хотите: любое слово команды может быть именем команды (`echo npm publish` подходит к `npm publish`), а между словами правила могут стоять другие слова (`git push --force` подходит и к `git push origin main --force`). Если правило подходит к слишком многому, сделайте его длиннее. Для правила **сначала спросить** нужен чат, который может спросить: в чате с политикой одобрения never (например, у делегированного субагента) dsh не может показать карточку, поэтому вызов отклоняется с причиной. Карточка одобрения показывает причину на английском. **Разрешить для этого чата** не отвечает на карточку **сначала спросить**.
- **Продолжить в новом чате** отправляет чат (сообщения, вызовы инструментов и конец каждого результата инструмента, не более примерно 60 000 символов, самую новую часть) собственной модели чата. Заметка для передачи может пропустить решение или файл: прочитайте её перед запуском. Новый чат знает только заметку и связанный чат (dsh прикрепляет старый чат как контекст только для чтения); его контекст модели начинается с малого, а старый чат остаётся как есть. Для одного чата одновременно идёт только одна заметка или один запуск.
- **Состав контекста** показывает оценки по собственному правилу dsh (около 4 символов на токен), тому же правилу, что и у кольца контекста dsh; собственный подсчёт модели может отличаться. Определения инструментов взяты из самого нового запроса. Функция показывает контекст так, как он записан в журнале чата; ход, который идёт сейчас, появляется после своего следующего шага.
- **Запланированные шаги** экономят токены, только когда модель действительно планирует: пока функция включена, каждый запрос несёт инструмент `plan_next_steps` и короткую инструкцию (около 500 токенов), даже в чатах, где модель никогда не планирует. Условие доказывает только то, что в нём сказано (например: код выхода сборки был 0), а не то, что работа сделана верно. `ok` читает собственные отметки результата dsh (`[exit code: N]`, тайм-ауты, отказы песочницы); команда, которая завершилась неудачей без ненулевого кода выхода, считается успешной. Шаги выполняются по одному; два шага, готовые одновременно, возвращаются модели. Сообщение шага сохраняется как сообщение ассистента модели чата (в dsh нет отметки для сообщения, написанного плагином), поэтому его текст говорит, что шаг запустил Composer Plus. В Tether нет.
- **Пакет навыка для турецкого** устанавливает сторонний навык: его правила приходят из репозитория автора на GitHub, а не из Composer Plus, и новая версия используется со следующей ежедневной проверки без нашего просмотра. Проверка доказывает, что файлы — те, которые GitHub перечисляет для этого коммита, но не то, что правила хороши. Когда загружать навык, решает модель (вы также можете вызвать его по имени); правила относятся только к турецким текстам. Host-часть использует язык, о котором браузер сообщил последним: если два браузера используют разные языки, действует более новый. Без входа GitHub разрешает 60 запросов к API в час; при отказе проверка сохраняет установленную копию и показывает причину в настройках.
- **Распутать кодовую базу** содержит фиксированную копию навыка (caldoai/skills, коммит f3cf477): изменение в оригинале приходит только с новой версией Composer Plus. Навык выполняет долгую цель, которая может изменить много файлов, а его субагенты и проверки тратят много токенов. Там, где у проекта нет тестов, он может незаметно изменить поведение: запускайте его в отдельной ветке и читайте diff перед слиянием. Навык с тем же именем в проекте, в своей папке навыков или в `~/.dsh/skills` заменяет его. Пока переключатель выключен, `/untangle-codebase` уходит модели как обычный текст.
- **Доска задач** показывает чаты, которые dsh перечисляет в этом окне: чат вне проекта виден только в **Все проекты**, а папка ветки для каждого чата (`<project>/.worktrees/<name>`) считается частью своего проекта. Колонка карточки — это живое состояние чата, поэтому карточки нельзя перетаскивать: чат переходит в **Готово**, когда его ход заканчивается, в том числе после ошибки или остановки, и возвращается в **В работе**, когда снова запускается. Зелёная точка — это собственная точка завершения dsh, которую dsh хранит только в этом окне: после перезагрузки завершённые чаты показываются без неё. **Готово** показывает 50 последних чатов (**Показать более старые: N** показывает остальные). **Поиск проектов** находит проект только по названию, а не по пути к его папке. **Активные за последние 2 часа** скрывает проект, если каждый его чат старше 2 часов, неактивен и прочитан; доска всё равно показывает выбранный вами проект. **Новая задача** помнит только последний новый чат этого окна: если вы открываете другой чат до первого сообщения, тот чат остаётся в самом верху колонки **В работе** как **Новая задача**, пока вы в нём не напишете, но доска возвращается сама только для последнего. После перезагрузки новый чат без сообщения не показывается на доске (dsh хранит его как свой пустой «Новый сеанс»). Теги берутся из одного вызова модели на каждую задачу, по её первому сообщению: они могут быть ошибочными, а у чата, который вы начали не на доске, их нет. Название — это собственное название чата в dsh (служба названий dsh, с моделью чата); пока его нет, карточка показывает первую строку первого сообщения. **×** и **Очистить всё** только убирают карточки с доски: ни один чат не удаляется. Кнопка **Отменить** видна только 8 секунд и только в этом окне; позже карточку возвращает **Убранные (N)** → **Вернуть на доску**, а чат, который снова запускается, возвращается сам. **Очистить всё** сначала спрашивает и убирает прочитанные завершённые карточки показанного проекта (при **Все проекты** — всех проектов), в том числе те, что скрыты за **Показать более старые: N**; непрочитанная (зелёная) карточка остаётся. dsh хранит свою зелёную точку только в этом окне, поэтому после перезагрузки «Очистить всё» может убрать карточку, ответ в которой вы не прочитали. Список хранится на этом Mac и действует для всех окон и для Tether; когда в нём 5 000 чатов, самые старые возвращаются. **Ответить** отвечает только на последний запрос чата: если на него уже ответили в другом месте (другое окно, Tether, автопроверка) или чат спрашивает что-то новое, панель сообщает об этом и ничего не отправляет. В прежних версиях был список задач с комментариями и инструментами для агентов; их больше нет, а старый `board.json` не показывается. Идея и внешний вид взяты из [Kanzo](https://github.com/emanuele-em/kanzo) от emanuele-em (AGPL-3.0); Composer Plus не использует его код. `Cmd+Shift+K` — сочетание клавиш dsh: в браузере на Linux у него нет клавиши по умолчанию (задайте её на странице сочетаний клавиш dsh), а расширение браузера или другое приложение может перехватить её раньше. Карточка уходит из **Готово**, когда исчезает зелёная точка dsh (вы открыли чат), а для чата, который завершился за доской, будучи открытым чатом, — когда этот чат показан без панели поверх него. Это состояние «прочитано» хранится только в этом окне dsh, как и точки dsh: после перезагрузки или в другом окне каждый завершённый чат считается прочитанным и находится в **Недавно завершённые**.
- **Ассистент** — один чат для всех окон этого Mac. Он работает в режиме разрешений workspace-write: записывает файлы только в `~/Assistant`, а команда за пределами этой папки сначала спрашивает. Если переключить чат в режим без подтверждений (Полный доступ), dsh отклоняет каждое подтверждение, поэтому ассистент не может отправить сообщение в чат, начать, остановить или архивировать чат. Карточка подтверждения защищает только шесть инструментов: команда оболочки ассистента всё равно может обращаться к сети, как в любом чате с этим режимом. В dsh 0.2.0 и 0.2.1 инструменты расписания dsh видят только напоминания самого чата ассистента, а не автоматизации других чатов; начиная с dsh 0.2.2 они показывают и изменяют все запланированные задачи. chats_list не показывает архивированные и пустые чаты, чаты субагентов и сам чат ассистента; «ждёт вас» означает открытый запрос подтверждения, вопрос или проверку плана в выполняющемся чате. chat_read отдаёт сообщения пользователя и ответы агента (без вывода инструментов), не более 50 сообщений и примерно 24 000 символов. chat_archive отказывается архивировать чат, который ещё выполняется или у которого есть активные напоминания. Текст, который читает модель, всё же может ввести её в заблуждение: карточка подтверждения — последняя проверка, поэтому прочитайте её, прежде чем нажать **Разрешить один раз**. В режиме разрешений Auto в dsh последней проверкой служит автопроверка, а не карточка: решает модель-проверщик, а не вы. Параллельные темы используют инструмент субагентов dsh: в профиле или режиме разрешений без него остаётся старое поведение (одна тема за раз; следующее сообщение ждёт в очереди или направляет выполняющийся ход). Что считать долгой задачей, решает модель, поэтому и короткий вопрос может занять ход. Субагент каждой темы работает со своими токенами; при перезапуске dsh выполняющаяся тема останавливается (её результат не приходит). Результат приходит как новый ход чата ассистента, поэтому он ждёт, пока вы пишете посреди хода.
- **Ассистент отдельно от чатов** и **Только сообщения в чате ассистента** скрывают собственные строки dsh правилом стиля, которое находит их по разметке боковой панели и чата dsh (`data-row-key`, `data-chat-flow-kind`): если обновление dsh изменит эту разметку, чат ассистента снова появится в списке или снова появятся его рабочие шаги. Строки скрыты, а не удалены: навигация с клавиатуры по боковой панели dsh всё ещё может попасть на скрытую строку. **Ассистент всегда свободен** отклоняет каждый вызов инструмента в чате ассистента, если это не один из его коротких инструментов; тогда модель передаёт шаг субагенту, но сначала может попробовать отклонённый вызов, а это стоит одного шага модели. Пока карточка подтверждения ждёт вас, чат ассистента всё ещё считается занятым. Если в его последнем запросе нет инструмента субагентов (режим разрешений или профиль без него), правило ничего не делает. С **Ассистент всегда свободен** сообщение, отправленное во время его работы, попадает в текущий ход на следующем шаге, поэтому очередь под полем ввода показывает его лишь на мгновение; пока ждёт карточка вопроса, тот же текст отвечает на каждый вопрос этой карточки. Уведомление субагента «завершён» не начинает второй ход только в dsh 0.2.2 и новее (старый dsh не отмечает, что субагент уже прислал вам результат). **Новости чатов от ассистента** запускает ход модели в чате ассистента для каждой пачки новостей, поэтому расходует токены; если включено **Мобильное подключение (iPhone)**, телефон может получить два уведомления об одном завершённом чате (от самого чата и от ассистента). Ожидающие новости теряются при перезапуске dsh. Функция видит только чаты на этом Mac.
- **Панель статуса ассистента** показывает свою панель в теле чата dsh и находит его по разметке dsh (`data-conversation-content`): если обновление dsh изменит эту метку, панель не появится (список и инструменты агента продолжат работать). В окне уже 1000 px панель закрывает правый край чата: нажмите на заголовок, чтобы свернуть её. Панель перечитывает список каждые 5 секунд, пока ассистент работает, в конце каждого хода и после вашего нажатия, поэтому пункт, который добавил ассистент, появляется с небольшой задержкой. Если язык интерфейса dsh не английский, строка результата каждой задачи субагента показывается на этом языке: модель dsh по умолчанию переводит каждую новую строку один раз (один вызов для новых строк одного чтения, без инструментов), и пока dsh работает, та же строка повторно не отправляется. Пока перевод не пришёл, и если вызов не удался, у задачи нет строки результата. Субагенты по-прежнему пишут и читают на английском.
- **Приоритет сообщения после остановки** работает только после того, как вы остановили чат (или после хода с ошибкой, или когда вы открываете чат, у которого ещё есть очередь): сообщение, отправленное во время хода, по-прежнему ждёт в конце очереди. Оно обгоняет только ваши собственные сообщения в очереди: если в очереди ждёт раунд цели или ответ на вопрос, остаётся порядок dsh. Функция читает часть dsh, которая не является публичным API (завершается ли ещё остановленный ход); если обновление dsh её переименует, сообщение встанет первым только после завершения этого хода. Чаты субагентов сохраняют порядок dsh.
- **Память проекта** принадлежит первой папке чата (папке проекта dsh): чат, который меняет папку командой `cd`, сохраняет память своего первого проекта, а та же папка, открытая по другому пути к тем же файлам, использует ту же память. Чат замораживает свой раздел памяти при запуске, поэтому заметка, сохранённая позже, появляется со следующего чата (`memory_recall` находит её сразу). Разбор сохраняет только то, что решила сохранить модель: он может пропустить факт или сохранить неверный; проверьте их в **Открыть память** и измените там, или правьте файлы вручную, когда dsh закрыт. **Открыть память** отправляет заметки выбранного проекта и глобальные заметки (все проекты, если выбрано «Все заметки»; не больше примерно 60 000 символов, остальные только считаются и не могут измениться в этом запросе) и ваш текст модели dsh по умолчанию, а не модели чата. Предпросмотр хранится на Mac 30 минут и до перезапуска dsh; если за это время разбор или агент изменят заметки, **Применить** откажет, и нужно запросить предпросмотр снова. **Применить** сохраняет все изменения предпросмотра или ни одного: если одно изменение нельзя сохранить (например, заметки, которую оно меняет, уже нет), заметки остаются как были, и показывается причина. Каждый завершённый ход с вашим сообщением стоит одного вызова модели; неудачный вызов перечитывает те же сообщения после следующего хода. Чаты субагентов не разбираются, но получают заметки как контекст. Субагент использует память папки, в которой он работает (папки своей задачи), а не папки чата, который его запустил. Разбор также читает ваши ответы на карточках вопросов. Неудачный разбор или заметка, которую он не может сохранить, оставляет в `journal.jsonl` строку с `"actor":"review-error"`. Идея и формат файлов взяты из [DS Bot](https://github.com/Fei2411/DS-Bot) (Apache-2.0); Composer Plus не использует его код и никогда не читает и не записывает собственную память DS Bot.
- **Папка памяти** начинает работать при следующем запуске dsh. Первый запуск с папкой без `Genel` и `Projeler` один раз копирует туда все заметки, всё или ничего; старые заметки в папке dsh остаются, а дальнейшие изменения идут только в папку. Если копирование не удалось, Память проекта остаётся выключенной до следующего запуска (ни одна заметка не попадёт не туда), а причина записана в журнал dsh. У заметок нет ограничения размера и числа тем; промпт каждого чата получает самые новые записи каждого MEMORY.md, до 8 000 символов, а остальные агент находит через `memory_recall`. Заметка, написанная вручную, должна быть строкой `- ` вне `## Index`, а имя файла темы — строчными буквами, с `-` вместо пробелов (`health-records.md`); другие файлы в папке не читаются. Символическая ссылка вместо папки, `Genel` или `Projeler` отклоняется, а файл заметки, который является символической ссылкой, читается как пустой. Всё, что синхронизирует или копирует эту папку (iCloud, Git, Obsidian Sync), тоже получает заметки.
- **История версий памяти** хранит 50 последних версий каждой памяти (каждого проекта и глобальной памяти); более старые удаляются. Версия хранит всю память проекта, а не одну заметку. **Восстановить** возвращает все файлы этой версии (включая темы) и отказывает, если память изменилась после открытия версии; память до восстановления становится новой версией, поэтому восстановление можно отменить. Пока переключатель выключен, новые версии не сохраняются и **Восстановить** отказывает; сохранённые версии остаются. Версий до появления этой функции нет: история начинается с первого сохранения после установки.
- **Экспорт памяти в AGENTS.md** записывает только заметки памяти одного проекта; глобальные заметки, источники и даты не записываются. Следующий экспорт заменяет весь отмеченный раздел, поэтому ручная правка внутри него теряется (diff сначала её покажет); текст вне меток остаётся. Если метки повреждены (одной нет или они повторяются), экспорт отказывает, пока вы их не исправите. AGENTS.md больше 512 кБ, символьная ссылка за пределы папки проекта и всё, что не является обычным файлом, отклоняются. Если AGENTS.md или заметки изменились после предпросмотра, **Записать AGENTS.md** отказывает, и вы экспортируете снова.
- **Ссылка на источник заметки памяти** работает для заметок, сохранённых после установки этой версии: более старая заметка указывает только чат (или ничего), поэтому **Источник** открывает только чат или не показывается. Если сообщения больше нет (его отозвал откат или чат удалён), чат откроется и уведомление скажет, что сообщения там нет.
- **Копировать память в другой проект** копирует не больше 100 заметок за раз и только в проект из списка dsh (читается собственный список проектов dsh; путь из окна не передаётся). Каждая копия независима: позднее изменение заметки в одном проекте не меняет копию. Если одну отмеченную заметку нельзя скопировать (её уже нет в источнике или файл нельзя записать), ничего не копируется. Заметка, чей текст и тема уже есть в целевом проекте, пропускается, и показывается их число.
- **Поиск устаревших заметок памяти** находит только то, что заметка пишет в известном ему виде: путь во фрагменте кода (`src/cart.ts`), скрипт npm после `npm run` (или `npm test`, `pnpm lint`), имя ветки во фрагменте кода рядом со словом «ветка». Путь за пределы папки проекта не сообщается; скрипт проверяется, только если в проекте есть `package.json`, ветка — только в репозитории git. За раз проверяется не больше 200 пунктов. Предупреждение значит «сейчас не найдено», а не «ошибка»: файл, который позже создаст сборка, тоже будет отмечен.
- **Не использовать память в этом чате** действует со следующего запроса этого чата к модели: уже идущий запрос сохраняет то, что у него есть. Переключение в идущем чате один раз меняет его системный промпт, поэтому этот один запрос не может использовать кэш поставщика модели. Субагент следует своему корневому чату. Проверка не читает сообщения, которые чат получает, пока его память выключена, даже если позже вы её снова включите. В dsh 0.2.0 на экране нового чата нет места для кнопки: она появляется в заголовке чата после первого сообщения.
- **Предложить заметки памяти из чата** показывает не больше 10 предложений и хранит их 30 минут и до перезапуска dsh; после этого при принятии вас попросят запросить предложения снова. Длинный чат отправляет свои последние сообщения: первыми отбрасываются самые старые ответы агента. Предложение может быть неверным: прочитайте его перед принятием и используйте **Открыть память**, чтобы позже изменить заметку. Отклонённое предложение может появиться снова при следующем щелчке.
- **Резервное копирование** использует одну постоянную папку, `~/Desktop/dsh-backups` (папку dsh-backup по умолчанию, поэтому его архивы остаются пригодными); настройки для другой папки нет. Архив примерно такого же размера, как домашняя папка dsh без `cache/` и `dsh-runtimes/` (измерено: из 1,6 ГБ файлов получился архив 830 МБ примерно за 30 с на Apple Silicon; dsh при этом отвечал). Файл, который меняется во время чтения, сохраняется в том виде, в каком он был, когда резервное копирование его открыло, поэтому журнал открытого чата может заканчиваться обрезанной записью, которую dsh исправляет при следующей записи. Скрытие находит секрет в файле yml по имени ключа в одной строке (`token:`, `apiKey:`, …); секрет в потоковом словаре (`{token: x}`), в списке под таким ключом, в файле JSON (например, `apiKey` сервера MCP в файле `.json`) или под другим именем остаётся в архиве. Архивы dsh-backup по типам (`dsh-t-…`) не показываются в списке. **Для другого компьютера** копирует архив (в APFS — клон, без дополнительного места); vault с ним не копируется. **Создать копию сейчас** не удаляет ни одной резервной копии. Автоматическое резервное копирование хранит самые новые резервные копии, которые создал Composer Plus (настройка **Хранить** функции **Автоматическое резервное копирование**), и удаляет более старые из них; снимки перед обновлением считаются отдельно (остаются 2 самых новых). Архивы dsh-backup не удаляются никогда: уберите их кнопкой **Удалить**. Пока dsh-backup ещё установлен, он учитывает архивы Composer Plus в своём лимите хранимых копий и может их удалить.
- **Восстановить** можно только в аварийной консоли, пока dsh закрыт: восстановление заменяет всю домашнюю папку dsh. Старая остаётся рядом как `.dsh.pre-restore-<time>`, пока вы её не удалите, поэтому на диске нужно место для обеих. Чаты сохраняют пути своих проектов: на другом компьютере проект по другому пути показывается как отсутствующий, пока вы не добавите его снова. Символические ссылки, которые указывают за пределы домашней папки dsh (например, навыки, подключённые ссылкой из другой папки), возвращаются как ссылки; их цели должны существовать на том компьютере.
- **Проверка журналов сеансов** читает самый новый журнал каждого чата по собственным правилам dsh о том, что открывается: строка, которая не является JSON или стоит не по порядку, считается повреждением, только когда после неё идёт конец хода (иначе dsh открывает чат без строк начиная с этой, поэтому чат не попадает в список). Она не сверяет события журнала с собственными правилами событий dsh, поэтому журнал, который она считает исправным, всё равно может не открыться после обновления dsh. Исправление берёт копию из резервной копии: сообщения после этой резервной копии из чата пропадают (повреждённый файл остаётся рядом). Чат, открытый в этом dsh, в Настройках не исправляется: его удерживает dsh.
- **Автоматическое резервное копирование** работает, только пока работает dsh: копия, срок которой наступил, пока dsh был закрыт, создаётся примерно через 45 с после следующего запуска. Снимок для новой версии создаётся после этого запуска, а не перед обновлением.
- **Запоминать размер окна** работает только в настольном приложении. При каждом запуске dsh сначала показывает окно размером 1280 × 820; окно переходит к сохранённому размеру, когда загружается плагин. У страницы нет события для перемещения окна, поэтому плагин читает окно раз в секунду: изменение за последние 2 секунды перед закрытием dsh не сохраняется. Размер хранится для каждого компьютера в собственном хранилище приложения.
- **Подсчёт использования:** считает копии, а не людей: каждая домашняя папка dsh — это одна копия. Подсчёт уникальных копий (`installed.txt`) учитывает только копии, которые обновились до первой версии с этим файлом или до более новой; копия, которая осталась на более старой версии, не учитывается. Копия, у которой удалили папку `storages`, засчитывается снова. GitHub может засчитать как один запросы с одного IP-адреса (например, с нескольких компьютеров за одним NAT-маршрутизатором), пришедшие примерно за 10 минут.
- Встроенную поддержку запросили у разработчиков dsh: `move` для очереди в [#773](https://github.com/deepseek-ai/deepseek-harness/discussions/773), состояние «Продолжить» в [#9269](https://github.com/deepseek-ai/deepseek-harness/discussions/9269).

## Частые вопросы

**Как добавить в DeepSeek Harness панель изменений / git diff?** Установите `dsh-composer-plus`, затем: правая боковая панель → `+` → **Изменения**.

**Может ли dsh предлагать функции для моего проекта, как карточки в Tinder?** Да: правая боковая панель → `+` → **Идеи функций** → **Предложить функции**. Смахните вправо, чтобы начать новый чат, который спланирует функцию; нажмите **▶ Создать сразу**, чтобы начать чат, который сразу создаст её без плана; смахните влево, чтобы пропустить её.

**Может ли поиск на боковой панели dsh найти чат по слову из сообщений, а не только по названию?** Да, с функцией **Поиск по содержимому** (включена по умолчанию): после установки плагина один раз перезапустите dsh, затем нажмите лупу рядом с **Рабочие области**. Под найденными чатами показывается текст вокруг слова.

**Можно ли отменить ход и изменить запрос, как в OpenCode или Claude Code?** Да, с функцией **Откат хода**: нажмите **↶** на сообщении, выберите **Чат и файлы**, измените текст, который вернулся в поле ввода, и отправьте его.

**Можно ли удалить чат, а не архивировать его?** Да, с функцией **Удалить чат**: **…** → **Удалить…**. История попадает в Корзину, поэтому ошибку можно исправить.

**Как узнать, к какому проекту относится чат?** Посмотрите на строку под полем ввода: с функцией **Название проекта в поле ввода** (включена по умолчанию) она начинается с названия проекта. Наведите на него указатель, чтобы увидеть путь к папке.

**Как получить историю сообщений по ↑/↓ в поле ввода dsh?** Установите этот плагин: в пустом поле ввода `↑` / `↓` листают отправленные сообщения.

**Как продолжить остановленный или завершившийся сбоем ход dsh, не печатая «continue»?** С этим плагином кнопка отправки превращается в **▶** после остановленного, завершившегося сбоем или оборванного хода. Один щелчок продолжает его.

**Продолжает ли dsh работающие чаты после выхода и повторного запуска?** Сам по себе нет: dsh помечает такой ход как прерванный и ждёт (цель тоже ждёт команды `/goal resume`). Включите **Настройки → Composer Plus → Продолжать после перезапуска**: тогда чаты, которые работали в момент выхода из dsh, сами продолжат работу при следующем запуске.

**Какая модель пишет предсказание?** Модель, которую вы выбираете в **Настройки → Composer Plus → Предсказание следующего сообщения → Модель**. Это собственный список моделей dsh. **По умолчанию в dsh** следует модели dsh по умолчанию. Если dsh больше не показывает выбранную модель, предсказание использует модель по умолчанию. У **Дополнение при вводе** есть своё меню **Модель**: **Как у предсказания следующего сообщения** (по умолчанию) следует модели предсказания, а другой выбор действует только для дополнений. Если dsh больше не показывает эту модель, дополнения используют модель предсказания.

**Может ли dsh улучшить мой промпт перед отправкой, как кнопка Enhance prompt в Roo Code или Augment?** Да, с функцией **Улучшить промпт** (включена по умолчанию): напишите черновой запрос и нажмите волшебную палочку рядом с меню моделей. Функция переписывает текст с этим чатом и проектом в качестве контекста, на вашем языке, и не отправляет его. `Cmd/Ctrl+Z` или **Отменить улучшение** возвращает ваш текст. Модель для неё выбирается в **Настройки → Composer Plus → Улучшить промпт → Модель**.

**Можно ли сделать так, чтобы агент сам не отмечал свою работу как выполненную, как в циклах с верификатором из loop engineering?** Да, с функцией **Проверка цели** (включена по умолчанию): начните цель командой `/goal`. Когда агент говорит, что цель выполнена, запускаются тесты проекта, а независимый вызов модели сверяет цель с чатом; если что-то не пройдено, цель остаётся открытой, а агент читает причину. Свою тестовую команду, лимит времени или лимит токенов задайте кнопкой **Изменить** в строке **Проверка цели** под целью.

**Может ли агент помнить мои предпочтения между чатами, как память DS Bot?** Да, с функцией **Память проекта** (по умолчанию выключена): включите её в **Настройки → Composer Plus**. После каждого хода ваши постоянные предпочтения и решения сохраняются короткими заметками для проекта чата, и каждый новый чат этого проекта их читает. Попросите агента что-то запомнить, и он сразу сохранит это. Чтобы посмотреть или изменить заметки, нажмите **Открыть память** в той же строке и напишите, что изменить.

**Я или ИИ неправильно изменили память. Можно вернуть старые заметки?** Да, с **История версий памяти** (включена по умолчанию): в **Открыть память** выберите проект, затем **История**. Выберите версию до изменения, чтобы увидеть, что вернётся, затем **Восстановить**.

**Можно поделиться памятью проекта с командой или другим инструментом агентов?** Да, с **Экспорт памяти в AGENTS.md** (включён по умолчанию): в **Открыть память** выберите проект, затем **Экспорт в AGENTS.md**. Проверьте diff, затем **Записать AGENTS.md**, и закоммитьте файл.

**Может ли ИИ предложить, что сохранить из длинного чата?** Да, с **Предложить заметки памяти из чата** (включено по умолчанию, пока включена **Память проекта**): нажмите **Предложить для памяти** в заголовке чата, затем **Принять** для заметок, которые стоит сохранить.

**Можно ли видеть все мои чаты в виде канбан-доски и начинать с неё новые?** Да, с функцией **Доска задач** (по умолчанию включена): откройте её на левой боковой панели. Каждый чат — это карточка в **В работе**, **На проверке** (он ждёт вас) или **Готово**. **Новая задача** открывает новый чат dsh в проекте, а доска возвращается, когда ваше первое сообщение отправлено; нажмите **Ответить** на оранжевой карточке, чтобы ответить, не открывая чат. **Очистить всё** в **Готово** сначала спрашивает и убирает с доски завершённые карточки, которые вы прочитали; **Отменить** и **Убранные (N)** возвращают их, а чаты остаются в dsh.

**Можно ли завести личный чат-ассистент, который напоминает мне о делах и управляет моими другими чатами?** Да, с функцией **Ассистент** (по умолчанию включена): нажмите Damon на левой боковой панели. Он создаёт напоминания с помощью запланированных задач dsh, ищет в интернете, показывает и читает ваши чаты, а отправляет сообщение в чат, начинает, останавливает или архивирует чат только после вашего подтверждения. Храните свой профиль в памяти его проекта, в теме "profil".

**Может ли ассистент не попадать в мой список чатов и работать как бот?** Да. **Ассистент отдельно от чатов** убирает его чат из списка на боковой панели и показывает его состояние в строке Damon (оранжевая точка, пока он ждёт вас). **Только сообщения в чате ассистента** скрывает его рабочие шаги. **Ассистент всегда свободен** заставляет его отдавать каждый долгий шаг фоновому субагенту, поэтому он отвечает сразу. **Новости чатов от ассистента** (по умолчанию выключено, расходует токены): ассистент сообщает вам, когда другой чат заканчивает работу, завершается с ошибкой или ждёт вас. По умолчанию (**Только автоматизации**) он сообщает только о ходах, которые запустила запланированная задача (и в чате, который начали вы), после каждого такого хода, как отчитывается субагент; выберите **Все чаты** в **Сообщать о**, чтобы узнавать обо всех чатах.

**Может ли dsh создавать резервные копии моих чатов и настроек, как dsh-backup?** Да: **Настройки → Composer Plus → Резервное копирование → Создать копию сейчас**. Он записывает архив того же формата в ту же папку (`~/Desktop/dsh-backups`), поэтому архивы dsh-backup тоже показываются и восстанавливаются, а dsh-backup можно удалить. Чтобы копии создавались по расписанию, включите **Автоматическое резервное копирование**.

**dsh больше не запускается. Как восстановить резервную копию?** Откройте папку резервных копий (`~/Desktop/dsh-backups`) и дважды щёлкните `Composer Plus Rescue.command` (Linux: `composer-plus-rescue.sh`, Windows: `Composer Plus Rescue.cmd`). Выберите `3) Restore a backup`, выберите копию и введите `RESTORE`. Это работает без dsh.

**Как перенести dsh на новый компьютер?** На старом: **Резервное копирование** → **Для другого компьютера** рядом с резервной копией. Скопируйте эту папку на новый компьютер, установите там dsh, выйдите из него, откройте `Composer Plus Rescue` в скопированной папке и выполните восстановление. Введите свои API-ключи заново (они остаются на старом компьютере).

**Чат не открывается после сбоя. Можно ли его исправить?** **Настройки → Composer Plus → Проверка журналов сеансов → Проверить журналы сеансов**. Повреждённый чат возвращается из самой новой резервной копии кнопкой **Исправить из резервных копий** (сообщения после этой резервной копии теряются).

**Как изменить порядок сообщений в очереди dsh?** Перетащите маркер ⠿ на сообщении в очереди или переведите на него фокус и нажмите `↑` / `↓`.

**Как исправить опечатку в сообщении в очереди?** Дважды щёлкните сообщение в очереди, измените текст и нажмите `Enter` (`Esc` отменяет). Сообщение остаётся на своём месте в очереди. Там же можно удалить его изображения и файлы или добавить новые.

**Как сразу убрать все точки непрочитанного в проекте?** Боковая панель → кнопка **…** проекта → **Отметить все как прочитанные**.

**Можно ли дать ссылку на одно сообщение в длинном чате?** Да: наведите указатель на сообщение и нажмите **🔗**. Отправьте ссылку в чате: в dsh 0.2.1 и новее щелчок по ней открывает чат на этом сообщении.

**Я откатил ход по ошибке. Можно его вернуть?** Да, кнопкой **Повторить** над полем ввода сразу после отката: она начинает новый чат с момента непосредственно перед откатом с теми же сообщениями, а после отката с вариантом **Чат и файлы** возвращает и файлы.

**Какой чат изменил этот файл?** Правая боковая панель → **Изменения** → **…** файла → **Чаты, которые изменили этот файл**. Нажмите на строку, чтобы открыть этот чат на запросе, который сделал изменение.

**Можно ли искать внутри одного длинного чата?** Да: нажмите `Cmd+F` на Mac (`Ctrl+F` в Windows и Linux) в чате. **Поиск в чате** подсвечивает каждое совпадение и переходит между ними по `Enter` и `Shift+Enter`.

**Как увидеть только файлы, которые изменил один чат?** Правая боковая панель → **Изменения** → **Этот чат**. Нажмите **␣**, чтобы скрыть изменения, которые состоят только из пробелов.

**Как запретить агенту запускать `npm publish` или `git push --force`?** **Настройки → Composer Plus → Заблокированные команды**: введите `npm publish`, выберите **блокировать** или **сначала спросить** и нажмите **Добавить**. Правило **блокировать** отклоняет команду, и агент спрашивает вас; правило **сначала спросить** каждый раз показывает карточку одобрения. «Защищённые файлы» охватывают файловые инструменты агента, а «Заблокированные команды» — его команды оболочки.

**Можно ли объяснить агенту, почему я отклонил вызов инструмента?** Да, с функцией **Отклонить с примечанием** (включена по умолчанию): нажмите **Отклонить с примечанием…** на карточке одобрения, напишите причину или что сделать вместо этого и нажмите **Отклонить**. Агент прочитает отказ и ваше примечание в том же ходе.

**Как передать агенту пароль или токен, не вводя его в чат?** С помощью функции **Ввод секрета** (включена по умолчанию): попросите агента использовать `request_secret` или дождитесь, когда он сам попросит. Введите значение в карточке в строке инструмента и нажмите **Сохранить**. Агент получает только путь к файлу со значением, а файл удаляется в конце хода.

**Как ответить только на часть длинного ответа?** Выделите эту часть и нажмите **Цитировать** над выделением (**Цитата в ответе**, включена по умолчанию). Часть попадёт в поле ввода как цитата `> …`, а ниже вы напишете ответ.

**Как показать агенту точные строки файла?** Откройте файл на правой боковой панели (**Файлы рабочей области**), выделите строки и нажмите **Цитировать** над выделением (**Цитата из предпросмотра файла**, включена по умолчанию). В поле ввода попадут путь и номера строк (например, `src/login.js:2-3`) и сами строки как блок кода; напишите свой вопрос ниже.

**Можно ли спросить что-то, пока агент работает, не останавливая его?** Напишите вопрос и нажмите **Спросить в побочном чате** в поле ввода (**Побочный чат**, включено по умолчанию). Копия чата только для чтения ответит, а чат продолжит работу. В побочном чате **Вернуть** помещает ответ в поле ввода чата.

**Как сказать агенту, что изменить в его diff?** В разделе **Панель изменений** откройте diff файла, нажмите **+** у строки и напишите заметку (**Заметки к diff**, включено по умолчанию). Затем нажмите **Отправить в поле ввода**: заметки попадут в поле ввода вместе с файлом, номерами строк и самими строками.

**Как сделать, чтобы автопроверка не спрашивала об одном и том же инструменте в одном чате?** Нажмите **Разрешить для этого чата** на карточке одобрения. Разрешение действует только для этого инструмента в этом чате, по умолчанию 1 час; отозвать его можно через значок в заголовке. Изменить время можно в **Настройки → Composer Plus → Разрешить для этого чата**.

**Я потерял iPhone. Как не дать ему подключаться к моему Mac?** Нажмите **Мобильное подключение** внизу слева на боковой панели и нажмите **Remove** рядом с этим iPhone. Его ключ сразу перестаёт работать; вернуться он сможет только после нового сопряжения, которое вы подтвердите на Mac.

**Как продолжить на этом Mac чат с другого моего Mac?** На другом Mac включите **Настройки → Composer Plus → Удалённые компьютеры** и **Разрешить другим компьютерам открывать этот Mac**, нажмите **Создать ссылку для сопряжения** и скопируйте ссылку (отправьте её себе, например через AirDrop или «Заметки»). На этом Mac тоже включите **Удалённые компьютеры**, выберите **Добавить компьютер…** в меню выбора на левой боковой панели (под названием приложения, над **Новый сеанс**), вставьте ссылку, введите **Имя** и нажмите **Подключить**. Затем нажмите **Одобрить** на другом Mac. После этого нажимайте на имя этого компьютера в меню выбора: он займёт это окно. Чтобы вернуться, нажмите **Этот Mac** в том же месте. Тем временем чаты этого Mac продолжают работать.

**Можно ли заблокировать Tether с помощью Face ID?** Да: в Tether включите «Settings → Privacy → Lock with Face ID». После этого Tether запрашивает Face ID (или код-пароль) при открытии и при возврате в приложение.

**Как показать на боковой панели dsh только проекты, с которыми я работал сегодня?** Боковая панель → параметры просмотра (значок с ползунками) → **Активные за последние 2 часа**. Выберите пункт ещё раз, чтобы показать все проекты.

**Как скопировать путь к папке проекта в dsh?** Правый щелчок по проекту на боковой панели → **Копировать путь**.

**Как свернуть сразу все проекты на боковой панели dsh?** Нажмите кнопку сворачивания рядом с параметрами просмотра (значок с ползунками). Она видна, пока открыт хотя бы один проект.

**Как получать уведомления macOS / Windows, когда задача dsh завершилась или ждёт одобрения?** Оставьте включёнными **Фоновые уведомления** (по умолчанию) и разрешите уведомления для DeepSeek Harness в настройках ОС.

**Может ли dsh сам открыть чат, который задаёт мне вопрос?** Да, с функцией **Открывать ожидающий чат при бездействии** (включена по умолчанию): когда чат ждёт ответа, одобрения или проверки плана, а вы не пользуетесь dsh 30 секунд, dsh открывает его. Чат, который завершил ход, который вы ещё не прочитали (зелёная точка), открывается так же, после оранжевых. Пока вы печатаете, прокручиваете или двигаете мышь, функция ждёт.

**Можно ли сразу перейти к следующему чату, который ждёт меня?** Да, с **Следующий ожидающий чат** (включено по умолчанию): нажмите `Cmd+Shift+E` (`Ctrl+Shift+E` в Windows и Linux) или кнопку с числом в заголовке боковой панели. Сначала идут чаты, которые задают вопрос или ждут одобрения, затем чаты, завершившие ход, который вы ещё не прочитали.

**Можно ли ответить на варианты агента одним нажатием?** Да, с **Кнопки вариантов** (включено по умолчанию): когда ответ заканчивается списком «Варианты», нажмите кнопку под ним. Она отправляет «Option N: …» как ваше сообщение. На карточке вопроса агента нажмите 1–9.

**Можно ли отправить фразу одобрения агента, не набирая её?** Да, с **Кнопка «Одобрить»** (включено по умолчанию): когда агенту нужно письменное одобрение, он пишет фразу в блоке `onay`. Нажмите **Одобрить** под ответом: точная фраза уходит как ваше сообщение, и автопроверка видит её от вас.

**Как переключить интерфейс DeepSeek Harness на турецкий, испанский, японский…?** Настройки → Composer Plus → **Язык приложения**.

**Как пользоваться dsh с iPhone?** Соберите приложение Tether из `tether/ios` (Xcode), включите **Настройки → Composer Plus → Мобильное подключение (iPhone)**, нажмите **Мобильное подключение** внизу слева, отсканируйте QR-код (камерой iPhone или кнопкой **Scan code** в Tether), коснитесь **Connect** и нажмите **Approve**. Вне дома используйте Tailscale на обоих устройствах.

**Как сделать, чтобы Новый сеанс всегда открывался в одном проекте?** Настройки → Composer Plus → **Рабочая область по умолчанию для нового сеанса** → **Открывать «Новый сеанс» в** → выберите проект. «`+`» рядом с другим проектом по-прежнему открывает этот проект.

**Как работать над несколькими функциями одного проекта одновременно, каждой в своей ветке?** С функцией **Ветка для каждого чата**: на экране нового чата кнопка ветки по умолчанию показывает **Новая ветка**: отправьте первое сообщение. Каждый чат получает свою ветку и папку worktree, а также ваши `.env` и `node_modules`, если они перечислены в `.worktreeinclude`. Заголовок чата показывает, в какой ветке вы находитесь.

**Может ли боковая панель показывать каждую ветку проекта и переносить мой чат, когда агент создаёт ветку?** Да, с помощью **Ветки в дереве рабочих областей** (по умолчанию выключено): включите его в Настройки → Composer Plus, затем выберите в dsh **Параметры просмотра** → **Дерево рабочих областей**. Каждая ветка с worktree в `<project>/.worktrees/` показывается внутри своего проекта. Если вы попросите агента в папке проекта создать ветку и работать в ней, а в папке нет незакоммиченных изменений, чат сам перейдёт в эту ветку. Удалите папку ветки — и она уйдёт из списка; её чаты окажутся в **Без группы**.

**Можно ли отправить фото с iPhone?** Да. В чате Tether коснитесь **+** рядом с полем сообщения → Camera, Photos (до 4) или Paste image. Фотографии попадают в чат на Mac как вложения вашего сообщения, поэтому модель их видит.

**Может ли dsh выполнить следующую команду, не спрашивая модель снова?** Да, с помощью **Запланированные шаги** (по умолчанию выключено): включите функцию в Настройки → Composer Plus. Тогда модель может планировать следующие команды с условием, например «запусти тесты, если сборка прошла», и Composer Plus выполняет шаг без нового вызова модели, когда результат выполняет условие. Подтверждения и песочница остаются как есть.

**Откуда берётся турецкий навык и можно ли его удалить?** Из [yucezerey/turkish-anti-ai-skill](https://github.com/yucezerey/turkish-anti-ai-skill) на GitHub (MIT). Composer Plus устанавливает его, только пока **Язык приложения** — Türkçe, хранит только его файлы Markdown и не запускает ни одного его скрипта. Чтобы удалить его, выключите **Пакет навыка для турецкого** в Настройки → Composer Plus: навык и загруженная копия сразу удаляются.

**Как сообщить об ошибке в Composer Plus или попросить новую функцию?** Настройки → Composer Plus → **Сообщить о проблеме…** (или меню **…** чата → **Сообщить о проблеме с Composer Plus…**). Выберите тип, напишите описание на своём языке и нажмите **Написать черновик**. Проверьте черновик на английском, затем нажмите **Открыть issue**.

**Как агенту навести порядок в запутанном коде?** Введите `/untangle-codebase` в чате (**Распутать кодовую базу**, включено по умолчанию), при желании с областью, например `/untangle-codebase src/api`. Сначала агент перечисляет копии, скрытые связи, лишние обёртки, мёртвый код и особые случаи, затем исправляет их как цель и снова проверяет с помощью субагентов. Запускайте его в чате функции **Ветка для каждого чата**, чтобы работа осталась в отдельной ветке.

**Работает ли плагин с настольным приложением?** Да: Настройки → Плагины → **Добавить плагин** → `dsh-composer-plus`. Проверено на dsh 0.2.0-rc.2 (настольное приложение и веб) и 0.2.1-rc.2 (веб).

**Правило для новых функций:** каждая строка функции в Настройки → Composer Plus показывает снимок экрана. Добавьте id функции в `SHOT_OF` в `client.js` и в `SHOTS` в `index.js` и включите в пакет `assets/features/<id>.webp` (снимок из одноразового демо-dsh с английским интерфейсом, около 60 КБ или меньше). Добавьте функцию с тем же изображением в `docs/features.json` и запустите `npm run build:readme`: он записывает таблицу функций в `README.md` и в каждый переведённый `README.<id>.md`, а также список в `llms.txt`. `test/shots.test.mjs` завершается ошибкой, если у функции нет снимка экрана, а `test/browser-settings-shots.mjs` проверяет настоящую страницу настроек. Полный список проверок для каждого изменения находится в [AGENTS.md](AGENTS.md).

Тесты запускают настоящий `client.js` с фальшивым React/DOM и настоящий `index.js` (Host-часть) с временным репозиторием git. Тесты шлюза Tether (`test/tether-gateway.test.mjs`) используют имитацию хоста dsh и настоящий TLS-шлюз. Приложение для iPhone находится в `tether/ios` (см. [tether/README.md](tether/README.md) и [tether/AGENTS.md](tether/AGENTS.md)). Каждый маршрут Host, его запрос и то, может ли Tether его вызвать, перечислены в [docs/ROUTES.md](docs/ROUTES.md). `node test/browser-history.mjs '<dsh web URL with ?token=…>'` проверяет историю ввода в настоящем браузере с одноразовым `dsh web`, у которого свой `DSH_HOME`.

Языковые пакеты — это JSON-файлы только с данными в `locales/<id>.json`. `npm run build:locales` встраивает их в единственную клиентскую точку входа (без сервиса перевода и без загрузки во время работы). `npm test` проверяет, что каждый пакет покрывает все ключи и сохраняет те же подстановки и переносы строк, а также проверяет работу системного языка и ручного выбора. Для изолированных проверок в настоящем приложении с локально установленным Playwright:

```sh
PLAYWRIGHT=/path/to/playwright node test/browser-language.mjs /path/to/dsh/lib/bin.js
```
