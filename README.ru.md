Удобные функции в стиле Codex для настольного и веб-интерфейса [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (dsh): панель изменений, идеи функций в виде карточек, которые можно смахивать, поиск по тексту сообщений на боковой панели, откат хода с восстановлением файлов, удаление чата в Корзину, название проекта под полем ввода, статус проекта на боковой панели, история ввода, быстрое переключение режима плана, продолжение в один клик, продолжение работающих чатов после перезапуска, перетаскивание в очереди, ссылки на сеансы, экспорт чата в Markdown, разрешения автопроверки для отдельного чата, фоновые уведомления, доступ с iPhone через приложение Tether и автоматические обновления.

**Коротко:** это один плагин для DeepSeek Harness (npm `dsh-composer-plus`, в разделе Настройки → Плагины он называется **Composer Plus**). Он добавляет панель изменений git, карточки идей функций в стиле Tinder, поиск на боковой панели, который находит и слова в сообщениях, откат хода ↶ (только чат или чат и файлы), удаление чата, название проекта под полем ввода, историю ввода по ↑/↓, переключатель `/plan` по Shift+Tab, кнопку ▶ «Продолжить» в один клик, продолжение после перезапуска, изменение порядка очереди перетаскиванием, копирование ссылки на сеанс, экспорт в Markdown, «Разрешить для этого чата» для автопроверки, фоновые уведомления, доступ с iPhone (мобильное подключение, приложение Tether), 11 дополнительных языков интерфейса и автоматические обновления.

<p align="center"><img src="docs/images/hero.webp" width="820" alt="DeepSeek Harness с Composer Plus: у работающего проекта на боковой панели крутится индикатор, а панель изменений показывает git diff"></p>

Неофициальный плагин сообщества. Сетевые запросы плагин делает только для проверки обновлений (выпуски GitHub и реестр npm). Чтобы при запуске их не было, выключите **Автоматические обновления**. **Идеи функций** обращается к модели вашего чата, только когда вы нажимаете **Предложить функции**. **Предсказание следующего сообщения** (по умолчанию включено) обращается к модели, выбранной в настройках (по умолчанию это модель dsh, если вы не выберете другую), один раз после каждого завершённого хода, без нажатия. Чтобы остановить эти запросы, выключите его в **Настройки → Composer Plus**. **Дополнение при вводе** (по умолчанию выключено) после включения обращается к выбранной для него модели (по умолчанию это модель предсказания) при каждой паузе в наборе. **Улучшить промпт** обращается к модели, только когда вы нажимаете волшебную палочку. **Проверка цели** (по умолчанию включена) обращается к модели один раз каждый раз, когда агент в автоматическом раунде отмечает `/goal` как выполненную. **Мобильное подключение** (по умолчанию выключено) принимает подключения iPhone из вашей локальной сети или tailnet только после того, как вы его включите.

## Установка

**Настольное приложение:** Настройки → Плагины → **Добавить плагин** → введите `dsh-composer-plus` → **Включить сейчас**.
Вместо имени npm-пакета можно вставить `https://github.com/furkancak1r/dsh-composer-plus`.

**Профиль Web / CLI:**

```sh
dsh plugin --profile web add dsh-composer-plus
```

Затем перезапустите dsh. (CLI не может устанавливать плагины в профиль настольного приложения: им управляет само приложение.)

> pnpm в dsh пропускает версии, которые вышли меньше 24 часов назад. Сразу после выпуска укажите версию: `dsh-composer-plus@1.15.0`.

Модель чата читает краткую сводку проекта этого чата (файлы верхнего уровня, начало README и манифеста, структуру остальной части README, заголовки последних коммитов) и предлагает до 8 функций. Смахните карточку вправо (или нажмите **✓**, или клавишу `→`; в любом случае карточка улетает в свою сторону), чтобы начать новый чат в том же проекте. Чтобы получить идеи только по одной области, введите короткую тему в поле **Тема** рядом с **Предложить функции** (не более 80 символов; `Enter` тоже запускает предложение) или нажмите одну из готовых тем под ним: **Производительность**, **Доступность**, **Тесты**, **Безопасность**, **Удобство** или **Документация** (повторное нажатие очищает тему). Тогда модель предлагает только функции по этой теме; пустое поле означает любые функции. В одном проекте идея не предлагается дважды: каждая предложенная идея (пропущенная, отложенная или начатая) попадает в список проекта **История**, модель получает указание больше не предлагать эти идеи, а идея с повторным заголовком отбрасывается. **История** показывает их с пометкой **Начата** или **Предложена**; **Забыть** (или **Забыть все**) позволяет идее появиться снова; идея, которая ещё есть в списке **На потом**, не попадает в предложения, пока вы не уберёте её оттуда. ## Настройки

Каждую функцию можно включить или выключить отдельно: dsh **Настройки → Composer Plus**. В каждой строке есть маленький снимок экрана: наведите на него указатель, чтобы увидеть его крупнее, или нажмите, чтобы открыть в полном размере (`Esc` закрывает). Поле **Поиск функций** вверху фильтрует страницу по названию или описанию (на любом языке, без учёта регистра и диакритических знаков); `Esc` очищает его. В каждой строке есть переключатель и короткое описание. Маленький **?** после названия строки открывает часть README с описанием этой функции, в README на языке интерфейса dsh. Изменения применяются сразу, без перезапуска, и запоминаются на этом устройстве. По умолчанию включено всё, кроме **Мобильное подключение**, **Продолжать после перезапуска** и **Дополнение при вводе**. Переключатели этих трёх функций, а также **Поиск по содержимому**, **Откат хода**, **Предсказание следующего сообщения** и **Проверка цели** хранит Host dsh, поэтому они действуют во всех окнах и сохраняются после перезапуска. Выбор в меню **Модель** для **Предсказание следующего сообщения**, для **Дополнение при вводе** (по умолчанию **Как у предсказания следующего сообщения**), для **Улучшить промпт** и для **Проверка цели** (у обоих по умолчанию **Как модель чата**), а также **Лимит времени** для **Разрешить для этого чата** (по умолчанию 1 час) тоже хранит Host. **Поиск по содержимому** меняется только после перезапуска dsh (dsh читает эту настройку при запуске). До этого в его строке написано **Перезапустите dsh, чтобы применить это изменение.**

Проверено на dsh `0.2.0-rc.2` (настольное приложение и веб) и `0.2.1-rc.2` (веб). CI запускает тесты при каждом push.

## Конфиденциальность и безопасность

- **Продолжить:** аутентифицированная локальная конечная точка возобновляет только последний прерванный ход, отклоняет устаревшие и повторные запросы и сохраняет существующие хуки одобрения. Новое сообщение пользователя она не отправляет.
- **Продолжать после перезапуска:** выключено, пока вы его не включите. Host-часть хранит только ID чатов и время их запуска в `$DSH_HOME/storages/dsh-composer-plus/resume.json` (доступ только для владельца), и ничего не покидает ваш компьютер. Чат продолжается, только если собственный журнал dsh показывает, что последний ход остановил dsh, а не вы. Одобрения и автопроверка действуют для продолженного хода как обычно.

- **Панель изменений:** git работает только на чтение на вашем компьютере, в папке самого чата, через аутентифицированный канал dsh `/api`. Он никогда не выполняет commit, stage или fetch и показывает только пути, которые перечислил сам git. Дерево показывает до 1000 локальных и удалённых веток и последние 300 коммитов одной ветки: только линию первого родителя, поэтому коммит слияния заменяет коммиты, которые он принёс. Оно никогда не переключает ветку (checkout). **Этот чат** читает собственный журнал чата, чтобы найти файлы, которые записали его файловые инструменты, и сравнивает их со снимком отката хода этого чата во временной папке, которая сразу удаляется; он ничего не записывает ни в ваш репозиторий, ни в хранилище снимков.
- **Идеи функций:** ничего не запускается, пока вы не нажмёте **Предложить функции**. Затем Host-часть читает только папку самого чата (браузер никогда не отправляет путь): имена записей верхнего уровня, первые 6 КБ файлов README, AGENTS.md и манифеста (`package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, …), структуру остальной части README (заголовки, строки таблиц, пункты списков; не более 6 КБ) и заголовки последних коммитов (`git log --format=%s`, не более 6 КБ), всего не более 28 КБ. Она пропускает `.env*`, файлы ключей и папки вроде `node_modules` и читает только обычные файлы внутри папки: символическая ссылка за пределы папки, FIFO или устройство пропускаются. Эта сводка уходит одним запросом к модели, которую использует чат, через настройки провайдера самого dsh. Она не добавляется ни в один чат. В проекте ничего не записывается. Идея, смахнутая вправо, начинает новый чат в режиме плана, поэтому одобрения и проверка плана действуют как обычно. **Создать сразу** начинает чат без режима плана: модель может сразу менять файлы, с обычными одобрениями чата и автопроверкой. Идеи, отложенные на потом (заголовок, описание, обоснование, объём работы), хранятся вместе с путём к папке проекта в `storages/dsh-composer-plus/later.json` в домашней папке dsh (файл доступен только владельцу); в проект ничего не попадает. История предложенных идей (заголовок, описание, обоснование, объём работы, дата, начата ли идея) хранится так же, в `storages/dsh-composer-plus/idea-history.json`, не более 200 на проект (первыми удаляются самые старые); её заголовки уходят модели при следующем нажатии **Предложить функции** в этом проекте.
- **Поиск по содержимому:** никакой новый код не ищет по вашим чатам. Плагин только включает встроенный индекс сообщений dsh (SQLite FTS5, `dsh-session-query-sqlite`) и даёт ему файл `$DSH_HOME/cache/composer-plus/session-search.db` (файл и папка доступны только владельцу). В файле хранится текст ваших сообщений и сообщений ассистента, поэтому он так же конфиденциален, как журналы чатов в `$DSH_HOME/sessions`. Ничего не покидает ваш компьютер. Это копия, которую dsh может создать заново: её можно удалить, пока dsh закрыт. Переключатель хранится в `$DSH_HOME/storages/dsh-composer-plus/content-search.json`.
- **Откат хода:** перед каждым вашим сообщением Host делает git-снимок папки чата в собственном хранилище `$DSH_HOME/cache/composer-plus/rollback/<chat>.git` (папка доступна только владельцу). В нём хранятся копии тех файлов этой папки, которые видит git (кроме игнорируемых), поэтому оно так же конфиденциально, как сам проект. Хранилище читает объекты вашего репозитория (то, что уже есть в git, не копируется) и никогда не записывает индекс, `HEAD`, ветки, теги, stash или конфигурацию вашего репозитория. Единственное, что git там меняет, — более новая отметка времени у файлов объектов, которые он использует повторно (из-за этого `git gc` удаляет их позже). Откат с файлами записывает только обычные файлы внутри папки чата; символические ссылки, каналы (pipes) и всё за пределами папки он пропускает. Ничего не покидает ваш компьютер. Хранилище можно удалить, пока dsh закрыт (тогда откат работает только для чата, пока не появятся новые сообщения). **Удалить чат** удаляет и хранилище чата. Переключатель хранится в `$DSH_HOME/storages/dsh-composer-plus/rollback.json`. Откат с файлами также сохраняет файлы в том виде, в каком они были непосредственно перед ним (`refs/r/…` в том же хранилище), для кнопки **Повторить**; повторённые откаты перечислены в `$DSH_HOME/storages/dsh-composer-plus/redone.json` (доступ только для владельца).
- **Открыть issue на GitHub** (Идеи функций → список **На потом**): запускается, только когда вы нажимаете эту кнопку. Host-часть запускает ваш собственный GitHub CLI (`gh issue create`) в папке чата с сохранёнными названием и кратким описанием идеи (и тем, почему она важна); `gh` использует свой вход и удалённый репозиторий GitHub этой папки, поэтому issue создаётся в этом репозитории от вашей учётной записи, и GitHub показывает её всем, кто видит этот репозиторий. dsh удаляет из запускаемых им команд переменные с именами, похожими на токен; если вы передали `gh` токен через `GH_TOKEN` или `GITHUB_TOKEN`, плагин передаёт `gh` только эти переменные. Ссылка на issue хранится вместе с идеей в `later.json`.
- **Чаты, которые изменили этот файл** (Изменения, меню «…» файла): Host-часть читает журналы чатов, папка которых находится в том же репозитории, в том виде, в каком их хранит dsh, и возвращает название каждого чата, время и первую строку запроса; сам файл она никогда не открывает.
- **Ветка Git в строках чатов:** Host-часть запускает `git branch --show-current` (только чтение) в папке чата, когда ход начинается и когда заканчивается, и хранит только ID чата, имя ветки и время в `$DSH_HOME/storages/dsh-composer-plus/session-branches.json` (файл доступен только владельцу, 2000 самых новых чатов). Переключатель хранится рядом, в `branches.json`.
- **Поиск в чате** работает только на странице: он читает текст, который показывает страница, и ничего не отправляет.
- **Экспорт чата в Markdown:** Host-часть читает только журнал самого чата (те же сообщения, которые показывает dsh) и передаёт их странице; она не читает файлы проекта и ничего не отправляет по сети. Markdown попадает только в ваш буфер обмена или в файл, который вы сохраняете.
- **Удалить чат:** перемещает в Корзину только папки журнала самого чата (`$DSH_HOME/sessions/<project>/<chat>`). Папку проекта функция не трогает.
- **Разрешить для этого чата:** разрешения хранятся вместе со временем выдачи в `$DSH_HOME/storages/dsh-composer-plus/chat-grants.json` (доступ только для владельца). Разрешение действует для одного конкретного инструмента в одном чате, пока не истечёт лимит времени (по умолчанию 1 час). Если этот инструмент может выполнять запись, разрешение покрывает и любую запись. Отозвать его можно через значок в заголовке.
- Автопроверка по-прежнему выполняется при каждом вызове. Если проверка завершилась сбоем, вызов никогда не разрешается автоматически.
- **Мобильное подключение:** выключено, пока вы его не включите. Когда оно включено, Host-часть запускает шлюз Tether: HTTPS на порту 19390, который принимает подключения только из вашей подсети Wi-Fi и вашего tailnet (100.64.0.0/10), и страницу сопряжения на `127.0.0.1:19391` (только для этого Mac). Телефону нужен одноразовый код из QR-кода (действует 5 минут) и ваше подтверждение **Approve** на Mac. Телефон закрепляет сертификат шлюза. Mac хранит только хеш токена каждого телефона (30 дней, срок продлевается при использовании); **Remove** сразу закрывает подключения этого телефона. Телефоны могут вызывать только разрешённый список методов dsh (чаты, запросы, вложения, слеш-команды, одобрения, вопросы, модели, агенты, цели), но не настройки, учётные данные, обозреватель файлов или терминал. «Tailscale only» отклоняет любое подключение из локальной сети, в том числе уже открытые. Журнал доступа хранит 200 самых новых попыток подключения (время, IP-адрес, имя устройства, разрешено или отклонено и причина) в `access.json`; токенов и кодов сопряжения в нём никогда нет. Данные: `$DSH_HOME/storages/dsh-composer-plus/mobile/` (файлы доступны только владельцу). Подробности: [tether/README.md](tether/README.md).
- **Обновления:** Host-часть запрашивает у `api.github.com` последний выпуск, а у `registry.npmjs.org` — именно эту версию. Никакие данные о вас или ваших чатах не отправляются. Установка идёт через менеджер плагинов dsh (`pnpm add dsh-composer-plus@<version>`; если dsh 0.2.1 отклоняет её для уже установленного плагина, то `pnpm add https://registry.npmjs.org/dsh-composer-plus/-/dsh-composer-plus-<version>.tgz`, и тогда профиль указывает этот URL как источник плагина), поэтому действуют встроенные проверки dsh: реестр, скрипты и совместимость версий. Предварительные выпуски и более старые версии никогда не устанавливаются.
- **Предсказание следующего сообщения:** по умолчанию включено. Чтобы остановить эти вызовы модели, выключите его в **Настройки → Composer Plus**. После каждого завершённого хода Host-часть отправляет ваши собственные сообщения в чате и текстовые ответы агента (без вывода инструментов, скрытого контекста и рассуждений), не более примерно 6 000 символов (самую новую часть), выбранной модели (по умолчанию это модель dsh, если вы не выберете другую). Это один запрос через настройки провайдера самого dsh. В чате ничего не сохраняется: предположение не попадает в историю чата. Переключатель и выбранная модель хранятся в `$DSH_HOME/storages/dsh-composer-plus/predict.json` (файл доступен только владельцу).
- **Дополнение при вводе:** выключено, пока вы его не включите. Когда оно включено, при каждой паузе в наборе Host-часть отправляет уже набранный текст, а также ваши собственные сообщения в чате и текстовые ответы агента (без вывода инструментов, скрытого контекста и рассуждений), не более примерно 3 000 символов чата, модели, выбранной для **Дополнение при вводе** (по умолчанию это модель **Предсказание следующего сообщения**). Новая пауза останавливает предыдущий запрос. В чате ничего не сохраняется. Переключатель хранится в `$DSH_HOME/storages/dsh-composer-plus/complete.json` (файл доступен только владельцу).
- **Улучшить промпт:** ничего не запускается, пока вы не нажмёте волшебную палочку. Затем Host-часть одним запросом отправляет модели, выбранной для **Улучшить промпт** (по умолчанию это модель самого чата), ваш черновик, ваши собственные сообщения в чате и текстовые ответы агента (без вывода инструментов, скрытого контекста, рассуждений и сообщений, убранных откатом; не более примерно 6 000 символов, самую новую часть), ту же сводку проекта, что и **Идеи функций** (с теми же правилами для файлов: без `.env*` и файлов ключей, без символических ссылок за пределы папки, без FIFO), пути, которые `git status` показывает как изменённые, и до 30 отслеживаемых или неотслеживаемых (не игнорируемых) путей, в именах которых есть слова из вашего черновика. Другое содержимое файлов, кроме этой сводки, не отправляется. В чат и в проект ничего не записывается: ответ только заменяет ваш черновик в поле ввода, а отправлять ли его, решаете вы. Выбранная модель хранится в `$DSH_HOME/storages/dsh-composer-plus/improve.json` (файл доступен только владельцу).
- **Проверка цели:** запускается, только когда агент в автоматическом раунде отмечает `/goal` как выполненную (или когда вы нажимаете **Запустить сейчас**). Host-часть запускает тестовую команду в папке чата в режиме песочницы этого чата (как собственный инструмент `bash` в dsh: та же политика доступа к файлам; если эта песочница не может запуститься, тест не запускается и проверка не пройдена). Чтобы найти команду, она читает только `package.json`, `Makefile`, `Cargo.toml`, `go.mod`, `pyproject.toml` и `pytest.ini`, как обычные файлы внутри папки (без символических ссылок за пределы папки, без FIFO). Затем она одним запросом без инструментов отправляет модели, выбранной для **Проверка цели** (по умолчанию это модель самого чата), цель, чат с момента начала цели (ваши сообщения, ответы агента, вызовы инструментов, обрезанные до 1 000 символов, и последние 2 000 символов каждого результата инструмента; без рассуждений и шагов, убранных откатом; не более примерно 60 000 символов, самую новую часть), `git status --short` и конец вывода теста. Вывод инструментов может содержать то, что прочитал агент, поэтому в этом запросе могут быть части ваших файлов, как и в самом чате. В чат и в проект ничего не записывается. Ваша тестовая команда, лимиты, последний результат (с концом его вывода) и выбранная модель хранятся в `$DSH_HOME/storages/dsh-composer-plus/goal-check.json` (файл доступен только владельцу, последние 500 чатов).

## Устранение неполадок

- **Нет уведомлений в macOS:** Системные настройки → Уведомления → DeepSeek Harness → разрешить. Выберите Предупреждения, чтобы уведомления оставались на экране.
- **После обновления dsh пропали ▶, маркеры очереди, статус проекта, фильтр недавних проектов, «Свернуть все проекты», «Копировать путь», поле поиска проектов, предсказание следующего сообщения, дополнение при вводе, «Разрешить для этого чата» или меню правого щелчка:** эти элементы привязаны к текущей HTML-разметке dsh, потому что в dsh пока нет для них отдельного места. Если dsh меняет эту разметку, они скрываются сами; больше ничего не ломается. Пожалуйста, откройте [issue](https://github.com/furkancak1r/dsh-composer-plus/issues).
- **«Не удалось обновить» или «установлена не из npm»:** копия, подключённая из локальной папки или переименованная, не может обновиться сама. Переустановите `dsh-composer-plus` в разделе Настройки → Плагины. В остальных случаях сообщение показывает первую строку ошибки pnpm; **Проверить обновления** повторяет попытку.
- **Мобильное подключение сообщает, что шлюз не запущен:** «no IPv4 address on en0» означает, что у этого Mac нет адреса Wi-Fi/Ethernet. «EADDRINUSE» означает, что порт 19390 или 19391 занят другим dsh (или приложением). Мобильное подключение может работать одновременно только в одном dsh.
- **Мобильное подключение, «Продолжать после перезапуска» или «Поиск по содержимому» просит «Перезапустите dsh»:** плагин обновился, пока dsh работал (или, для поиска по содержимому, вы изменили переключатель). Новое состояние загрузится после перезапуска.
- **Поиск находит только названия:** поиск по содержимому выключен, dsh не перезапускался после того, как вы включили функцию или установили плагин, или слово есть только в выводе инструмента (см. «Ограничения»).
- **На моих сообщениях нет кнопки ↶:** откат хода выключен, это чат субагента, или установлен dsh-rewind-plugin (пользуйтесь его кнопкой ↶). После обновления перезапустите dsh.
- **Пункт «Чат и файлы» недоступен (серый):** проект не является репозиторием git, нет снимка до этого сообщения (сообщение старше плагина, или его снимок вытеснили 50 более новых), или ни один файл не изменился.
- **При удалении появляется сообщение, что этот чат открыт в другом dsh:** второй dsh с той же домашней папкой dsh удерживает блокировку чата. Закройте это окно или dsh и удалите чат снова. До этого чат остаётся в архиве.
- **iPhone не подключается после включения «Tailscale only»:** Tailscale должен быть включён и на Mac, и на iPhone. Панель «Мобильное подключение» предупреждает, если на Mac он выключен. Журнал доступа показывает каждую отклонённую попытку и её причину.
- **Чат не продолжился после перезапуска:** функция «Продолжать после перезапуска» была выключена, когда dsh завершил работу; вы сами остановили этот ход; ход уже закончился (готово или сбой); чат был в архиве; или работало больше 20 чатов (продолжаются 20 самых новых).
- **После перезапуска очередь пуста:** очередь очищает сам dsh при завершении. Функция «Продолжать после перезапуска» возвращает её только в чате, который продолжается; в других чатах отправьте сообщения снова. Сообщение, удалённое прямо перед выходом, может вернуться: удалите его снова.
- **Открыть issue на GitHub сообщает «gh could not open the issue»:** это первая строка вывода самого `gh`. Выполните `gh auth status` в терминале и войдите с помощью `gh auth login`; у папки чата должен быть удалённый репозиторий GitHub (`git remote -v`). «not installed or not on the PATH of dsh» означает, что dsh не нашёл `gh`: установите его или запустите dsh из терминала, в котором `gh` работает.
- **На строке чата нет метки ветки:** у чата не было хода с момента установки этой версии, его папка не является репозиторием git, или функция **Ветка Git в строках чатов** выключена. После обновления перезапустите dsh (ветку записывает Host-часть).
- **Проверка цели сообщает, что тест завершился с кодом 127 или «not found»:** у dsh, запущенного из Finder или Dock, PATH может быть короче, чем в вашем терминале, поэтому он не находит `npm`, `pnpm` или `cargo`. Запустите dsh из терминала или задайте свою тестовую команду с полным путём в **Проверка цели** → **Изменить**. **Запустить сейчас** сразу показывает результат.
- **Цель не закрывается, и агент продолжает работать:** **Проверка цели** нашла непройденный тест или недоделанную работу; строка под целью показывает причину (наведите указатель на результат, чтобы увидеть подробности). Исправьте причину или тестовую команду либо завершите цель сами командой `/goal` или через панель цели (это не проверяется).
- **Установка не удаётся сразу после выпуска:** укажите версию (`dsh-composer-plus@1.15.0`), см. примечание об установке выше.

## Ограничения

- Продолжение без сообщения опирается на жизненный цикл dsh `agent/pre-step` → `agent/request`. Проверяйте совместимость при обновлении dsh.
- **Идеи функций** хранит карточки в памяти для каждого чата, пока не перезагрузится dsh или страница. После этого **Предложить функции** снова обращается к модели. Карточки приходят на том языке интерфейса dsh, который выбран в момент нажатия. Если вы смените язык, карточки, которые уже лежат в стопке, сохранят свой язык, а **Ещё идеи** использует новый. Модель видит только краткую сводку проекта, а не код, поэтому идея может повторять то, что в проекте уже есть: просто пропустите её. Новый чат запускается в режиме плана, только если в профиле есть команда dsh `/plan`; иначе идея уходит как обычное первое сообщение. Список **На потом** привязан к пути папки чата: та же папка, открытая через символическую ссылку, получает свой список. В нём хранится не более 50 идей на проект (удалите одну, чтобы добавить новые), и каждый заголовок только один раз. Перетаскивание карточки решает только «влево» или «вправо»; чтобы отложить её, используйте **↓**, а чтобы создать её сразу — **▶**. Повтор определяется только по заголовку: модель всё равно может предложить прежнюю идею под новым названием; пропустите её. Если модель отвечает только прежними идеями, ничего нового не появляется: нажмите ещё раз. Узкая тема делает это более вероятным: выберите тему шире или очистите её. Тема остаётся в поле для каждого чата, пока не перезагрузится dsh или страница.
- **Экспорт чата в Markdown** включает только ваши сообщения и текстовые ответы ассистента. Вызовы инструментов и их вывод, рассуждения, изображения (их отмечает строка `[image]`), скрытый контекст и сообщения, которые убрал откат хода или dsh-rewind-plugin, в экспорт не попадают. Ответы одного хода объединяются в один раздел. В один экспорт входит не более примерно 4 миллионов символов; для более длинного чата экспорт содержит его первую часть и примечание.
- **Продолжать после перезапуска** продолжает ход, а не повторяет его. Вызов инструмента, который выполнялся в момент выхода, завершается результатом dsh «outcome unknown» (результат неизвестен). Модели сообщается, что не нужно повторять сделанную работу, но команда, которую небезопасно запускать дважды, может выполниться снова. Субагенты, одобрения и вопросы, которые были открыты, не восстанавливаются: их родительский чат продолжает работу и спрашивает снова. За один запуск продолжается не более 20 чатов.
- **Продолжать после перезапуска** и очередь: при завершении dsh очищает очередь чата. Плагин возвращает ваши сообщения из очереди по журналу чата, с их порядком, правками, изображениями и файлами; они выполняются после продолженного хода. Очередь возвращается только в чатах, которые продолжаются (переключатель включён, выход во время хода). Ваше собственное удаление последних сообщений из очереди dsh записывает так же: если вы удалили их и dsh завершил работу до начала следующего шага, они вернутся.

- **Поиск по содержимому** — это встроенный поиск dsh, поэтому у него те же ограничения. Он ищет только в сообщениях пользователя и ассистента: не в выводе инструментов (команды, содержимое файлов, результаты) и не в рассуждениях. Фильтра по сообщениям пользователя, ассистента или инструментов нет. Он находит целые слова, а не части слов (`deploy` не находит `deployment`); буквы с диакритикой совпадают с буквами без неё (`seker` находит `şeker`). На каждый чат одна строка с фрагментом dsh длиной 240 символов, всего не более 20 строк.
- **Поиск по содержимому**: затраты измерены на копии 247 реальных журналов чатов (159 МБ, dsh 0.2.1-rc.2, Apple Silicon, 32 ГБ). Первый поиск после запуска строит индекс примерно за 15 с. В это время Host dsh около 7 с ничего не отвечает, поэтому другие чаты на этот момент перестают выводить ответ (сама страница не зависает). Память Host на пике вырастает примерно на 1,1 ГБ; через минуту она всё ещё примерно на 0,5–0,6 ГБ выше начальной и остаётся такой до выхода из dsh. Файл индекса занимает около 165 МБ. Следующие поиски занимают около 0,5 с. После перезапуска первый поиск занимает около 1 с (добавляются только новые или изменённые чаты) и добавляет около 70 МБ. Если на компьютере мало памяти, выключите эту функцию.
- **Поиск по содержимому** начинает действовать только после перезапуска dsh. Файл индекса общий для всех dsh, которые используют одну домашнюю папку dsh: запускайте одновременно только один такой dsh (dsh допускает одного владельца на файл индекса).
- **Откат хода** возвращает файлы только в репозитории git и только в папке чата. Он хранит 50 самых новых снимков на чат. Игнорируемые файлы (`.gitignore`, `info/exclude`, ваш глобальный файл игнорирования), пустые папки, символические ссылки и подмодули не возвращаются. Файл, который был игнорируемым в момент снимка, никогда не удаляется, даже если ход изменил правила игнорирования. Файл, который git не может прочитать, не попадает в снимок. Каждое ваше сообщение запускает один `git add --all` папки чата в закрытое хранилище. В очень большой папке с множеством неотслеживаемых файлов это может занять несколько секунд, и следующий вызов инструмента ждёт завершения (не более 10 с; затем снимок заканчивается в фоне). Если `git gc` вашего репозитория удалит объект, который нужен старому снимку, этот файл будет показан как не возвращённый. В поле ввода возвращается только текст сообщения: добавьте его изображения или файлы снова. У чатов субагентов нет ↶ (изменения файлов субагентом считаются изменениями чата, который его запустил). Экспортированный чат (`/export`) по-прежнему содержит отозванные сообщения. Идея одной скрытой метки, которая отзывает часть чата, взята из [dsh-rewind-plugin](https://github.com/SiriLee/dsh-rewind) от SiriLee (MIT); Composer Plus не использует его код.
- **Удалить чат** требует архивации dsh (dsh 0.2.0 и новее). Если чат (или один из чатов его субагентов) не останавливается за 15 с или его удерживает другой dsh, он остаётся в архиве, и ничего не перемещается. В системах, отличных от macOS, папка корзины должна быть на том же диске, что и история чатов. Открытый чат, который вы удалили, остаётся в памяти dsh (в архиве и скрытым) до перезапуска dsh. Очищайте Корзину сами: dsh этого не делает.
- В очереди dsh нет действия `move`, поэтому Host-часть плагина перемещает само сообщение в очереди dsh (одно изменение, то же самое сообщение). Сообщения с изображениями или файлами тоже перемещаются. Перемещаются только ваши собственные сообщения: раунд цели или ответ на вопрос в очереди остаётся на своём месте. Если сообщение начинает отправляться, пока вы перетаскиваете, ничего не перемещается, и об этом сообщает уведомление.
- dsh 0.2.1 загружает обновление сразу, если новая версия не меняет никаких настроек dsh; в остальных случаях, а также в dsh 0.2.0, перезапустите dsh, чтобы загрузить его. Плагин никогда не перезапускает dsh за вас. Профили Web/CLI без менеджера плагинов dsh только сообщают о новой версии.
- **Разрешить для этого чата** отсчитывает лимит времени с момента выдачи разрешения. Новый лимит времени сразу применяется к действующим разрешениям, поэтому более короткий лимит может сразу их завершить. У разрешений из версии 1.12 и более ранних нет времени: после обновления агент ещё раз спросит об этих инструментах.
- **Сохранять фокус в поле ввода** возвращает фокус только после команды `/` или навыка. Пока dsh обрабатывает команду, поле ввода несколько миллисекунд доступно только для чтения, поэтому клавиши, нажатые в это время, теряются. Если меню `/` в dsh ещё открыто, `Enter` выбирает выделенную строку и ничего не отправляет.
- **Подгонять карточку вопроса под окно** меняет только карточку вопроса dsh, а не карточку проверки плана. Она находит карточку по разметке dsh (`data-question-key`, `data-question-scroll`); если обновление dsh изменит эту разметку, карточка будет выглядеть так, как её рисует dsh. Высота карточки следует за окном, а не за чатом: в чате в узкой боковой панели высокая карточка всё ещё может выходить выше чата.
- **Мобильное подключение** работает только в macOS (оно использует `en0`, `openssl`, `swift` и `dns-sd`). Оно использует фиксированные порты 19390 и 19391, поэтому на каждом Mac его может одновременно запускать только один dsh (каждый Mac — одна запись в списке Mac на телефоне). Телефон получает уведомления, только пока Tether открыт или только что ушёл в фон (сервиса push-уведомлений нет). Приложения для iOS пока нет в App Store: соберите его из `tether/ios` в Xcode. «Tailscale only» всё равно требует адрес Wi-Fi или Ethernet на Mac (шлюз запускается только при таком адресе). Журнал доступа у каждого Mac свой и хранит только 200 самых новых попыток; повторная попытка в течение минуты увеличивает счётчик той же строки на один. Блокировка приложения Tether не скрывает превью уведомлений на экране блокировки iPhone: выключите их в настройках iOS. Зелёные точки в Tether следуют за Mac: у чата, который вы открыли в dsh, точка пропадает и на телефоне. У чата, который вы открыли в Tether, точка пропадает только на телефонах. Собственная точка dsh на Mac остаётся, пока вы не откроете чат на Mac.
- Ссылка на сеанс работает внутри чатов; щелчок по ней не открывает чат. Ссылка, созданная через **Копировать ссылку на сообщение**, открывает своё сообщение только в dsh 0.2.1 и новее и только из сообщения в чате (в dsh 0.2.0 нет правил для пользовательского текста, поэтому там ссылка копируется, но показывается как обычный текст). Сообщение, которое убрал откат или которое сжатие удалило из истории, загружаемой dsh, показать нельзя: ссылка тогда сообщает об этом. Кнопки 🔗 привязаны к строкам сообщений dsh; если обновление dsh изменит эту разметку, они не появятся.
- **Отметить все как прочитанные** меняет собственные точки непрочитанного dsh через часть dsh, которая не является публичным API (список `completionUnread` в состоянии сеансов dsh). Если обновление dsh переименует его, пункт не появится. Пункт добавляется в меню «…» проекта в dsh, где нет места для плагинов; если dsh изменит это меню, пункт тоже не появится.
- **Правка сообщения в очереди на месте** не меняет сообщение, которое тем временем начало отправляться, и не перезаписывает сообщение, которое тем временем изменилось (например, в Tether на iPhone): об этом сообщает уведомление. Для нового изображения нужна модель, которая принимает изображения (действуют собственные ограничения dsh на изображения), а новый файл должен загрузиться до того, как вы сможете сохранить. Изменять можно только свои сообщения в очереди: раунд цели или ответ на вопрос в очереди изменить нельзя. После обновления плагина сразу работает только правка текста: перезапустите dsh, прежде чем сохранять сообщение с изображениями или файлами (Host-часть загружается при запуске).
- **Повторить** никогда не меняет откаченный чат: кнопка начинает новый чат с момента непосредственно перед откатом (встроенное ответвление dsh, тот же контекст модели), поэтому у нового чата новый id и новое название. Повторить можно только самый новый откат чата, один раз и только пока после него ничего не было (новое сообщение убирает эту возможность). Файл, который вы изменили после отката, сохраняется, если вы не отметите флажок, который его перезаписывает. Для повтора нужен снимок, который сохранил откат (то же окно из 50 записей); откат, сделанный до этой версии или с вариантом **Только чат**, возвращает только сообщения.
- **Этот чат** учитывает только файлы, которые записали файловые инструменты dsh (`write`, `edit`, `str_replace_editor`). Файлов, которые изменила команда (`bash`), в этом представлении нет; они показаны в разделе **Незафиксированные**. Без снимка отката хода для чата (откат хода выключен, установлен dsh-rewind-plugin или чат старше плагина) представление сравнивает с последним коммитом и сообщает об этом. Откат хода хранит 50 последних снимков чата: в более длинном чате представление сравнивает с самым старым сохранённым снимком, сообщает, с какого сообщения, и не учитывает более ранние изменения. **Скрыть изменения пробелов** — это `git diff -w`: строка, в которой изменились только пробелы внутри неё, тоже скрывается.
- **Открыть issue на GitHub** требует GitHub CLI (`gh`) в PATH dsh и удалённый репозиторий GitHub в папке чата. Команда работает не дольше 60 с; если `gh` работает дольше, issue может уже существовать на GitHub без ссылки в списке (прежде чем нажать ещё раз, проверьте GitHub: список читает ссылку только из завершённого запуска, поэтому новое нажатие может открыть вторую issue). Папка с несколькими удалёнными репозиториями GitHub использует значение по умолчанию самого `gh` (`gh repo set-default`).
- **Чаты, которые изменили этот файл**, как и **Этот чат**, знают только файловые инструменты dsh (`write`, `edit`, `str_replace_editor`): изменение, сделанное командой (`bash`), в списке не появляется. Список читает 300 самых новых чатов репозитория (по времени создания) и сообщает, если их больше; он показывает не более 100 строк. Переименованный файл показан под тем именем, которое записал инструмент. Чат, папка которого находится вне репозитория (в том числе через другой путь к тем же файлам), не учитывается. Первое открытие после запуска dsh читает все журналы чатов репозитория (около 4 с для 275 чатов); последующие открытия читают только чаты, изменившиеся с тех пор.
- **Ветка Git в строках чатов** показывает ветку папки чата на момент начала или конца его последнего хода, а не текущую ветку: переключение ветки вне хода появится после следующего хода. У чатов, созданных до этой версии, метки нет до их следующего хода. Метка встроена в разметку строк чатов dsh (в dsh нет для неё отдельного места); если обновление dsh изменит эту разметку, метка не появится. Если строка проекта над чатом называется так же, как ветка (например, папка «Ветка для каждого чата»), строка чата не показывает метку, но в режиме «Одним списком» метка по-прежнему видна.
- **Поиск в чате** ищет только в том, что показывает страница: в загруженных сообщениях и ответах (для более старых прокрутите вверх или нажмите **Загрузить более ранние**), но не в закрытых шагах инструментов и не в свёрнутом тексте вывода инструмента. Он считает не более 2 000 совпадений (дальше — «2000+»). Он использует API подсветки браузера (Chromium 105 и новее; в настольном приложении он есть): в более старом браузере счётчик и переходы работают без цвета. `Cmd+F` на Mac (`Ctrl+F` в Windows и Linux) открывает его, только пока на экране есть чат; в других местах встроенный поиск браузера работает как раньше. На Mac `Ctrl+F` сохраняет своё действие macOS в текстовых полях (курсор сдвигается на один символ вперёд).
- Уведомление, отправленное до перезапуска, при щелчке только выводит dsh на передний план.
- Активные проекты перемещаются через сохранённый порядок проектов dsh, поэтому новый порядок сохраняется после перезапуска. Чаты вне проектов («Без группы») перемещать нельзя; dsh всегда показывает их последними.
- В меню параметров просмотра на боковой панели у dsh нет точки расширения, поэтому пункт фильтра недавних проектов добавляется во встроенное меню dsh. Если обновление dsh изменит это меню, пункт не появится, и все проекты останутся видны. Фильтр работает со строками проектов, поэтому режим **Одним списком** не фильтруется. Используйте фильтр с **По рабочей области**: в режиме **Дерево рабочих областей** скрытая родительская папка скрывает и активные проекты внутри неё. У **По состоянию** ограничение того же рода: в dsh нет места для своего порядка сортировки, поэтому пункт и порядок строк привязаны к разметке меню и списка dsh.
- В dsh нет ни меню строки проекта, ни места в заголовке «Рабочие области». **Копировать путь** находит строку проекта по разметке строк dsh, а **Свернуть все проекты** встраивается в заголовок dsh и закрывает каждый открытый проект тем же щелчком, что и строка проекта. Если обновление dsh изменит эту разметку, правый щелчок покажет меню браузера, а кнопка не появится.
- В меню проектов нового чата у dsh тоже нет точки расширения, поэтому поле **Поиск проектов** и порядок A–Z привязаны к разметке меню dsh. Если обновление dsh изменит эту разметку, меню будет выглядеть так, как его рисует dsh: в сохранённом порядке и без поля поиска. Порядок A–Z — только способ показа: он не меняет сохранённый порядок проектов dsh.
- В dsh также нет точки расширения, которая выбирает, где открывается **Новый сеанс**. **Рабочая область по умолчанию для нового сеанса** оборачивает метод dsh, который не является публичным API (`startSession` службы рабочих областей dsh). Если обновление dsh его переименует, **Новый сеанс** откроется там, где выберет dsh (открытый или последний проект). Каждый вызов без проекта использует значение по умолчанию: кнопка на боковой панели, её сочетание клавиш, логотип, а также **Создать** на странице **Задачи автоматизации**. При запуске dsh по-прежнему открывает последний чат. Общая папка создаётся и добавляется в ваши проекты при первом использовании; в Windows или Linux с перемещённой папкой Documents она может отличаться от папки самого dsh.
- Для подсказки в поле ввода у dsh тоже нет точки расширения, поэтому текст **Предсказание следующего сообщения** накладывается на собственный текст-заполнитель dsh (`[data-composer-placeholder]`). Если обновление dsh изменит эту разметку, предсказание не появится. Пока функция включена, каждый завершённый ход стоит один короткий вызов модели.
- **Дополнение при вводе** показывает свой текст через собственную подсказку поля ввода dsh (стиль `--dsh-composer-hint`, который dsh использует для подсказки аргумента слеш-команды). Функция не работает для слеш-команды, для сообщения со значком файла или символа и когда курсор стоит не в конце сообщения. Если обновление dsh изменит этот стиль, дополнение не появится. Каждая пауза в наборе стоит один вызов модели.
- **Улучшить промпт** видит только краткую сводку проекта, изменённые пути и пути, имена которых совпадают с вашими словами, но не сам код. Поэтому функция может пропустить нужный файл и называет только те пути, которые получила. Прочитайте новый текст перед отправкой. Она не работает для слеш-команды и для сообщения со значком файла или символа (новый текст — обычный текст, поэтому значок бы потерялся), а в сообщении может быть не более 8 000 символов. Изображения остаются прикреплёнными: меняется только текст. Каждое нажатие стоит один вызов модели; сильной модели может понадобиться минута (`Esc` отменяет).
- **Проверка цели** проверяет только выполнение, которое агент отмечает в автоматическом раунде цели: выполнение, о котором вы просите в чате, `/goal` и панель цели не проверяются. Агент может сам изменить тесты или файлы тестовой команды; верификатор читает чат и может это увидеть, но может ошибиться в обе стороны (ошибочное «не выполнено» стоит ещё одного раунда; ошибочное «выполнено» закрывает цель). Верификатор видит чат и `git status`, но не сам код. Запуск тестов используется повторно, только если последним шагом агента, который может менять файлы, был его собственный успешный запуск `bash` точно той же команды в той же папке; команда с конвейером (`| tail`) или `&&` повторно не используется. Бюджет измеряется, когда заканчивается ход, поэтому один ход может его превысить. Учитываются только вызовы модели самого чата (не его субагентов). `update_goal` ждёт, пока идёт проверка (тест не более 15 минут, верификатор не более 3 минут). Ответвление получает новый id чата, поэтому начинает без собственной тестовой команды и лимитов родительского чата. Каждое выполнение, которое доходит до верификатора, стоит одного вызова модели.
- Встроенную поддержку запросили у разработчиков dsh: `move` для очереди в [#773](https://github.com/deepseek-ai/deepseek-harness/discussions/773), состояние «Продолжить» в [#9269](https://github.com/deepseek-ai/deepseek-harness/discussions/9269).

## Частые вопросы

**Как добавить в DeepSeek Harness панель изменений / git diff?** Установите `dsh-composer-plus`, затем: правая боковая панель → `+` → **Изменения**.

**Может ли dsh предлагать функции для моего проекта, как карточки в Tinder?** Да: правая боковая панель → `+` → **Идеи функций** → **Предложить функции**. Смахните вправо, чтобы начать новый чат, который спланирует функцию; нажмите **▶ Создать сразу**, чтобы начать чат, который сразу создаст её без плана; смахните влево, чтобы пропустить её.

**Может ли поиск на боковой панели dsh найти чат по слову из сообщений, а не только по названию?** Да, с функцией **Поиск по содержимому** (включена по умолчанию): после установки плагина один раз перезапустите dsh, затем нажмите лупу рядом с **Рабочие области**. Под найденными чатами показывается текст вокруг слова.

**Можно ли отменить ход и изменить запрос, как в OpenCode или Claude Code?** Да, с функцией **Откат хода**: нажмите **↶** на сообщении, выберите **Чат и файлы**, измените текст, который вернулся в поле ввода, и отправьте его.

**Можно ли удалить чат, а не архивировать его?** Да, с функцией **Удалить чат**: **…** → **Удалить…**. История попадает в Корзину, поэтому ошибку можно исправить.

**Как узнать, к какому проекту относится чат?** Посмотрите на строку под полем ввода: с функцией **Название проекта в поле ввода** (включена по умолчанию) она начинается с названия проекта. Наведите на него указатель, чтобы увидеть путь к папке.

**Как получить историю сообщений по ↑/↓ в поле ввода dsh?** Установите этот плагин: в пустом поле ввода `↑` / `↓` листают отправленные сообщения.

**Как продолжить остановленный или завершившийся сбоем ход dsh, не печатая «continue»?** С этим плагином кнопка отправки превращается в **▶** после остановленного, завершившегося сбоем или оборванного хода. Один щелчок продолжает его.

**Продолжает ли dsh работающие чаты после выхода и повторного запуска?** Сам по себе нет: dsh помечает такой ход как прерванный и ждёт (цель тоже ждёт команды `/goal resume`). Включите **Настройки → Composer Plus → Продолжать после перезапуска**: тогда чаты, которые работали в момент выхода из dsh, сами продолжат работу при следующем запуске.

**Какая модель пишет предсказание?** Модель, которую вы выбираете в **Настройки → Composer Plus → Предсказание следующего сообщения → Модель**. Это собственный список моделей dsh. **По умолчанию в dsh** следует модели dsh по умолчанию. Если dsh больше не показывает выбранную модель, предсказание использует модель по умолчанию. У **Дополнение при вводе** есть своё меню **Модель**: **Как у предсказания следующего сообщения** (по умолчанию) следует модели предсказания, а другой выбор действует только для дополнений. Если dsh больше не показывает эту модель, дополнения используют модель предсказания.

**Может ли dsh улучшить мой промпт перед отправкой, как кнопка Enhance prompt в Roo Code или Augment?** Да, с функцией **Улучшить промпт** (включена по умолчанию): напишите черновой запрос и нажмите волшебную палочку рядом с меню моделей. Функция переписывает текст с этим чатом и проектом в качестве контекста, на вашем языке, и не отправляет его. `Cmd/Ctrl+Z` или **Отменить улучшение** возвращает ваш текст. Модель для неё выбирается в **Настройки → Composer Plus → Улучшить промпт → Модель**.

**Можно ли сделать так, чтобы агент сам не отмечал свою работу как выполненную, как в циклах с верификатором из loop engineering?** Да, с функцией **Проверка цели** (включена по умолчанию): начните цель командой `/goal`. Когда агент говорит, что цель выполнена, запускаются тесты проекта, а независимый вызов модели сверяет цель с чатом; если что-то не пройдено, цель остаётся открытой, а агент читает причину. Свою тестовую команду, лимит времени или лимит токенов задайте кнопкой **Изменить** в строке **Проверка цели** под целью.

**Как изменить порядок сообщений в очереди dsh?** Перетащите маркер ⠿ на сообщении в очереди или переведите на него фокус и нажмите `↑` / `↓`.

**Как исправить опечатку в сообщении в очереди?** Дважды щёлкните сообщение в очереди, измените текст и нажмите `Enter` (`Esc` отменяет). Сообщение остаётся на своём месте в очереди. Там же можно удалить его изображения и файлы или добавить новые.

**Как сразу убрать все точки непрочитанного в проекте?** Боковая панель → кнопка **…** проекта → **Отметить все как прочитанные**.

**Можно ли дать ссылку на одно сообщение в длинном чате?** Да: наведите указатель на сообщение и нажмите **🔗**. Отправьте ссылку в чате: в dsh 0.2.1 и новее щелчок по ней открывает чат на этом сообщении.

**Я откатил ход по ошибке. Можно его вернуть?** Да, кнопкой **Повторить** над полем ввода сразу после отката: она начинает новый чат с момента непосредственно перед откатом с теми же сообщениями, а после отката с вариантом **Чат и файлы** возвращает и файлы.

**Какой чат изменил этот файл?** Правая боковая панель → **Изменения** → **…** файла → **Чаты, которые изменили этот файл**. Нажмите на строку, чтобы открыть этот чат на запросе, который сделал изменение.

**Можно ли искать внутри одного длинного чата?** Да: нажмите `Cmd+F` на Mac (`Ctrl+F` в Windows и Linux) в чате. **Поиск в чате** подсвечивает каждое совпадение и переходит между ними по `Enter` и `Shift+Enter`.

**Как увидеть только файлы, которые изменил один чат?** Правая боковая панель → **Изменения** → **Этот чат**. Нажмите **␣**, чтобы скрыть изменения, которые состоят только из пробелов.

**Как сделать, чтобы автопроверка не спрашивала об одном и том же инструменте в одном чате?** Нажмите **Разрешить для этого чата** на карточке одобрения. Разрешение действует только для этого инструмента в этом чате, по умолчанию 1 час; отозвать его можно через значок в заголовке. Изменить время можно в **Настройки → Composer Plus → Разрешить для этого чата**.

**Я потерял iPhone. Как не дать ему подключаться к моему Mac?** Нажмите **Мобильное подключение** внизу слева на боковой панели и нажмите **Remove** рядом с этим iPhone. Его ключ сразу перестаёт работать; вернуться он сможет только после нового сопряжения, которое вы подтвердите на Mac.

**Можно ли заблокировать Tether с помощью Face ID?** Да: в Tether включите «Settings → Privacy → Lock with Face ID». После этого Tether запрашивает Face ID (или код-пароль) при открытии и при возврате в приложение.

**Как показать на боковой панели dsh только проекты, с которыми я работал сегодня?** Боковая панель → параметры просмотра (значок с ползунками) → **Активные за последние 2 часа**. Выберите пункт ещё раз, чтобы показать все проекты.

**Как скопировать путь к папке проекта в dsh?** Правый щелчок по проекту на боковой панели → **Копировать путь**.

**Как свернуть сразу все проекты на боковой панели dsh?** Нажмите кнопку сворачивания рядом с параметрами просмотра (значок с ползунками). Она видна, пока открыт хотя бы один проект.

**Как получать уведомления macOS / Windows, когда задача dsh завершилась или ждёт одобрения?** Оставьте включёнными **Фоновые уведомления** (по умолчанию) и разрешите уведомления для DeepSeek Harness в настройках ОС.

**Как переключить интерфейс DeepSeek Harness на турецкий, испанский, японский…?** Настройки → Composer Plus → **Язык приложения**.

**Как пользоваться dsh с iPhone?** Соберите приложение Tether из `tether/ios` (Xcode), включите **Настройки → Composer Plus → Мобильное подключение (iPhone)**, нажмите **Мобильное подключение** внизу слева, отсканируйте QR-код (камерой iPhone или кнопкой **Scan code** в Tether), коснитесь **Connect** и нажмите **Approve**. Вне дома используйте Tailscale на обоих устройствах.

**Как сделать, чтобы Новый сеанс всегда открывался в одном проекте?** Настройки → Composer Plus → **Рабочая область по умолчанию для нового сеанса** → **Открывать «Новый сеанс» в** → выберите проект. «`+`» рядом с другим проектом по-прежнему открывает этот проект.

**Как работать над несколькими функциями одного проекта одновременно, каждой в своей ветке?** С функцией **Ветка для каждого чата**: новый чат → кнопка main со значком ветки → **Новая ветка**, затем отправьте первое сообщение. Каждый чат получает свою ветку и папку worktree, а также ваши `.env` и `node_modules`, если они перечислены в `.worktreeinclude`. Заголовок чата показывает, в какой ветке вы находитесь.

**Можно ли отправить фото с iPhone?** Да. В чате Tether коснитесь **+** рядом с полем сообщения → Camera, Photos (до 4) или Paste image. Фотографии попадают в чат на Mac как вложения вашего сообщения, поэтому модель их видит.

**Работает ли плагин с настольным приложением?** Да: Настройки → Плагины → **Добавить плагин** → `dsh-composer-plus`. Проверено на dsh 0.2.0-rc.2 (настольное приложение и веб) и 0.2.1-rc.2 (веб).

**Правило для новых функций:** каждая строка функции в Настройки → Composer Plus показывает снимок экрана. Добавьте id функции в `SHOT_OF` в `client.js` и в `SHOTS` в `index.js` и включите в пакет `assets/features/<id>.webp` (снимок из одноразового демо-dsh с английским интерфейсом, около 60 КБ или меньше). Добавьте функцию с тем же изображением в `docs/features.json` и запустите `npm run build:readme`: он записывает таблицу функций в `README.md` и в каждый переведённый `README.<id>.md`, а также список в `llms.txt`. `test/shots.test.mjs` завершается ошибкой, если у функции нет снимка экрана, а `test/browser-settings-shots.mjs` проверяет настоящую страницу настроек. Полный список проверок для каждого изменения находится в [AGENTS.md](AGENTS.md).

Тесты запускают настоящий `client.js` с фальшивым React/DOM и настоящий `index.js` (Host-часть) с временным репозиторием git. Тесты шлюза Tether (`test/tether-gateway.test.mjs`) используют имитацию хоста dsh и настоящий TLS-шлюз. Приложение для iPhone находится в `tether/ios` (см. [tether/README.md](tether/README.md) и [tether/AGENTS.md](tether/AGENTS.md)). Каждый маршрут Host, его запрос и то, может ли Tether его вызвать, перечислены в [docs/ROUTES.md](docs/ROUTES.md). `node test/browser-history.mjs '<dsh web URL with ?token=…>'` проверяет историю ввода в настоящем браузере с одноразовым `dsh web`, у которого свой `DSH_HOME`.

Языковые пакеты — это JSON-файлы только с данными в `locales/<id>.json`. `npm run build:locales` встраивает их в единственную клиентскую точку входа (без сервиса перевода и без загрузки во время работы). `npm test` проверяет, что каждый пакет покрывает все ключи и сохраняет те же подстановки и переносы строк, а также проверяет работу системного языка и ручного выбора. Для изолированных проверок в настоящем приложении с локально установленным Playwright:

```sh
PLAYWRIGHT=/path/to/playwright node test/browser-language.mjs /path/to/dsh/lib/bin.js
```
