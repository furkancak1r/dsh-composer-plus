# dsh-composer-plus — next release (0.6.0)

## Objective
1. Codex-style **Changes** panel in dsh's right sidebar: Uncommitted / Unstaged / Staged / Branch (vs upstream) / Last turn, with per-file diffs.
2. Publish to **npm** so the Plugins page installs it by name.
3. **dsh 0.2.1** compatibility check + GitHub Actions CI running `npm test` on every push.
4. **Richer notifications**: approval names the tool, question shows its first line, finish shows a short reply preview; Dock unread badge.
5. **Persist Auto Review "Allow for this chat" grants** across restarts (opt-in per grant, revocable).

Out of scope (user decision): Interrupt-and-send, edit-last-message.

## Invariants
- Client-only features stay client-only; the Host half adds git/grant endpoints and authenticated, message-free Continue.
- No shell interpolation: git runs through dsh's `subprocess` capability with argv arrays, a scrubbed env, a timeout and bounded output (same as dsh-workspace-changes). Read-only git commands only.
- Endpoints are registered through `ctx.connection.fetch.register` (auth + host fence are applied by dsh).
- Never edit live dsh files mid-turn; back up before install; never restart dsh.
- Public repo: no local paths, emails, tokens or real DB names.

## Message-free Continue (2026-10-13)

Objective: resume a stopped/failed turn without editing the draft or adding a user message.

Invariants: use public agent/pre-step, agent/request and steer APIs; never bypass approval hooks;
reject busy, completed, stale, unknown and child sessions; do not lose other queued input;
prevent duplicate clicks; keep localized errors and existing visibility/feature toggles.
No added dependency, private driver methods or transcript deletion.

Scope: client.js, index.js, Continue tests, host route fixtures, package test script, README.
Live files: back up first, install only after DSH_IDLE, do not restart the desktop app.

Phases:
1. [done] Authenticated resume endpoint and client; unit checks for visibility,
   no prompt/draft writes, errors, duplicate requests and other pre-step messages.
2. [done] Isolated dsh 0.2.0-rc.2 and 0.2.1-alpha.2 stop/error -> resume -> complete;
   assert model is called again without a new user message; run npm test.
3. [done] Inspect diff, back up and install live while idle; document desktop reload need.

Decision: send an empty, plugin-owned wake marker through the public agent inbox;
retain the final message batch from the outermost agent/pre-step listener, then
remove only that marker at agent/request, before it reaches history or the model.
An empty first step is skipped by dsh, so removal must follow step entry.
Use steer while idle so queued user messages remain in their original order
and no extra empty turn is appended after them.
Preserve downstream rejection and every other message. Resume requests carry the
latest turn event seq so a delayed/repeated click cannot reopen a completed turn.

Last checkpoint: npm test passes. Isolated 0.2.0-rc.2 and 0.2.1-alpha.2 both
passed stop -> resume and HTTP 400 -> resume -> complete. Each resume made a
second model request with identical history, unchanged draft, no Continue
bubble and no browser exceptions. Native completed state hides the button.
Live installation is waiting for the currently running desktop turn to finish.

## Keep composer focus (2026-10-15)
Problem: macOS Hammerspoon hotkeys (F5 → `/gt`, F6, F7, F8, F11) type a skill command and press Enter. The command runs, but the next keys go nowhere: the cursor is not in the composer.
Root cause (dsh 0.2.0-rc.2 … 0.2.1-alpha.3, read in `dsh-client-ui-conversation`): Enter on a `/` line moves the input machine to `adjudicating`; InputBar sets `editable = !machineBusy`, so Lexical writes `contenteditable="false"` on the focused root and the browser moves the focus to `<body>`. dsh calls `focusDraftEditor` only when `locked`, `sessionId` or `editor` changes, so the focus never comes back. Evidence (real dsh, switch off): `focusout composer -> none | phase=adjudicating`, then `editable=true phase=plain` and no `focusin`.
Fix: feature `keepFocus` (own switch, `conversation.input.right` slot, no DOM markup dependency). When the phase leaves `adjudicating`/`submitting`, one frame later it calls dsh's public `conversation.input.for(actx).focus()` (Lexical restores the last caret), only if the focus is on `<body>`/none and no `[aria-modal="true"]`/`dialog[open]` is open. A new command or unmount cancels the frame.
Limits: keys pressed during the few milliseconds of adjudication are lost; an open `/` menu takes the first Enter (dsh picks the row).
Checks: `test/keep-focus.test.mjs` (phases, focused field, dialog, cancel, unmount, closed session); `npm test` (19 files, 16 shots); `test/browser-keep-focus.mjs` on dsh 0.2.0-rc.2 and 0.2.1-alpha.2 (switch off: focus on body after `/release-notes`; switch on: typing goes on in the composer in a blank and an open chat; `/permission` popup keeps its search field focused); `test/browser-settings-shots.mjs` (16 rows); Semgrep p/javascript + p/secrets: 0 findings. An isolated run also proved that dsh's client-hmr loads a rewritten `client.js` into an open page without a reload.
Live desktop copy installed (client, host, keepFocus shot; module id `@local/dsh-composer-history`). Backup: `~/Documents/testdeepseekharness/backup-before-keepfocus-20261015-115529`. dsh not restarted. Not released or published yet.

## Resume after restart → 1.6.0 (2026-10-16)
Request (user): "Is there a dsh setting that continues running work after I quit dsh and open it again? If not, add it to the plugin."
Evidence that dsh has no such setting (0.2.0-rc.2, 0.2.1-alpha.2, 0.2.1-alpha.4):
- `dsh-session-persistence` README, Known limitations: "Synthetic closers are the only crash story … there is no partial-turn resume that continues an interrupted turn instead of closing it." On quit, `agent-loop` disposal cancels the running turn with `{ kind: 'disposed' }` (`turn/end { aborted, reason: disposed }`); after a crash, the next resume appends `turn/end { interrupted }`.
- `dsh-goal`: goal activation is process-local; every `agent/created` disarms it. `dsh-goal-round-driver`: "the driver never revives work on its own".
- No setting or config key with resume/restart semantics in any package (grep of both installs and alpha.4).
Design (feature `resumeAfterRestart`, Host half only does the work):
- Off by default (`OFF_BY_DEFAULT`): it starts model turns without a click. The switch lives in the Host (`$DSH_HOME/storages/dsh-composer-plus/resume.json`, `{ on, sessions: [] }`, 0600, atomic rename), like Mobile connect.
- Tracking (`resumeTracker`): Host listens to `agent/status` and `session/event` (`turn/start`, `turn/end`). A top-level chat (`ctx.agents.roots()`, header origin not `subagent`) that becomes `running` is saved at once (so a crash keeps it). When it becomes idle it leaves the list, except when its turn end was caused by dsh (`stoppedByDsh`: `aborted` + cause `disposed`/`parent`, or `interrupted`) or no turn end arrived for an open turn (the shutdown could not write it). Plugin unload stops all writes.
- Wake (`wakeSession`): after `ctx.appReady.onReady` (both versions; a 3 s timer without it), once per start, newest first, at most 20: forget the list, then for each chat `sessionController.resolveAgent` (dsh closes a crashed turn as `interrupted` here), skip archived/busy/unavailable chats, read the newest `turn/start|turn/end` through `sessionQuery.observeSession`, continue only when `stoppedByDsh`. A stopped goal round re-arms its goal with `ctx.goals.resume` (dsh's goal driver starts the next round, so the model can still complete the goal); any other turn gets the One-click Continue marker through `agent.steer` (the existing `agent/pre-step` hook swaps it for the hidden note). A goal is never armed for an ordinary turn (dsh does not keep whether it was armed).
- Never: a chat the user stopped (`aborted/user`), a completed or failed turn, archived chats, subagents, a chat that runs again before the wake. No age limit: the user wants a quit-and-open to continue, also after a long break.
Limits: a quit while a tool runs ends that tool call ("outcome unknown" result); the model is told to continue and not to repeat work, but a non-idempotent command may run again. Only Host shutdowns are seen: if the computer loses power, the list still holds the running chats (saved on every change), and their turns end as `interrupted`, so they continue too.

## Issues found in Feature ideas (d014428, 2026-10-19) — fixed in 1.7.0
Found by review of d014428 (not released; no tag contains it). Each was reproduced on an extracted copy of `HEAD` = `origin/main` = d014428 with synthetic files under `$TMPDIR`.
- **F-01 (P1) Project brief follows symlinks out of the project — fixed in 1.7.0.** `head()` in `index.js` opens `README.md`, `package.json`, … with `open(path, 'r')`, which follows symlinks; `BRIEF_SKIP` checks only top-level names. The 90 s timeout starts after `projectBrief()`, so it does not cover this; the request never answers and the Host keeps the pending call. Each blocked `open()` also holds one libuv threadpool thread, and dsh does not set `UV_THREADPOOL_SIZE` (default 4). - **F-03 (P2) "More ideas" and a swipe right overlap and break the deck state — fixed in 1.7.0.** `suggestIdeas()` in `client.js` always writes `status: 'ready'` and `history: []`. When the load ends during the start, `starting` is lost (a second swipe right sends a second start in parallel) and Undo history is cleared. A symlink inside the folder is still read.
- F-03, `client.js`: one `deckBusy(deck)` (`loading` or `starting`) guards `suggestIdeas()`, `decideIdea()`, the pointer-drag start and the `busy` flag; `suggestIdeas()` no longer resets `history`.

## Turn rollback + Delete chat — GitHub issue #2 (2026-10-19)
Request (issue #2, user decisions): (1) roll back a turn: take a user message and everything after it out of the model context and the view, put its text back in the composer, and optionally put the project files back as they were before that message; (2) delete a chat from the sidebar chat menu, not only archive it. User decisions: files come back from a git snapshot of the work tree (bash changes too); a deleted chat goes to the macOS Trash (elsewhere: a trash folder under `$DSH_HOME`); stop before the GitHub release and give the owner the `gh release` command; write no issue comment, give a draft.
Reference: `dsh-rewind-plugin` 0.17.0 (MIT, SiriLee), installed in the owner's desktop profile. It rolls back with one appended `user/message` marker (`surfaceOp: replace` + `sourceEventSeqs`, the same mechanism as `/compact`) and backs up only files that its write/edit tools touch. No code is copied; the marker idea and the "(empty message)" text are reused (README credits it).
Evidence (dsh 0.2.0-rc.2 and 0.2.1-rc.2 source):
- `Session.append(type, data, { surfaceOp: { op: 'replace', startSeq, endSeq }, sourceEventSeqs })` validates that `sourceEventSeqs` holds every shadowed surface node; `session.surface.nodes` and `snapshotEvents()` exist on both. dsh's chat view does not draw a replacement `user/message` (`messageDefinition` matches append events only), but it still draws the shadowed rows: the client must hide them.
- Agent: `cancel(cause, { keepInbox })`, `whenIdle()`, `inbox.nextStep` + `inbox.remove(id)` on both. Composer: `ctx.sessions.scope(id)` → `conversation.input.for(scope).setDraft(text)` on both.
- Chat rows: `[data-chat-flow-kind="user"][data-chat-anchor-key]`; the key maps to a node with `anchorSeq` in `uiConversation.binding(id).target('chat').getSnapshot()` (to be proven on 0.2.0-rc.2 in phase 0).
- Git snapshot without touching the user's repository: dsh's own `dsh-workspace-changes` copies the index to a private `GIT_INDEX_FILE`, sets `GIT_OBJECT_DIRECTORY` to a private store and the repository's objects as `GIT_ALTERNATE_OBJECT_DIRECTORIES`, then `git add --all` + `write-tree`. Its trees live in a temp folder that goes away with the session, so they cannot serve a later rollback.
- dsh has no delete: `workspaceRegistry.archiveSession(id, { stopActivity: true })` stops the turn, jobs, subagents and schedules, blocks later steps (archived gate) and hides the chat. A live agent cannot be unloaded from outside (its owner is the controller fiber). The log folder is `<sessions root>/<project key>/<encoded id>/` with `session.v4.jsonl[.zstd]` + `session.lock` (same code on both). `sessionPersistence.locate(header)` gives the log path; `open(id, 'write')` takes the cross-process flock (`SessionAlreadyOwnedError` when another dsh holds it).
Design — feature `turnRollback` (Host keeps the switch; on by default):
- Host snapshots: at every human `user/message` (source `user`) of a top-level chat whose folder is in a git work tree, queue one snapshot (as above) into `$DSH_HOME/cache/composer-plus/rollback/<encoded id>.git` (a bare store; its `objects/info/alternates` names the repository's objects) and keep it as ref `refs/s/<seq>` → tree. `tools/pre-execute` waits for the queue, so no tool runs before its snapshot. Keep the newest 50 per chat; drop older refs, then `git prune` in the store only. Skip all of this while the switch is off or `dsh-rewind-plugin` is loaded (its command `rewind-plugin` is registered).
- `POST /api/composer-plus.rollback {sessionId, seq, files, preview?}`: preview → `{git, files: [{path, action}]}` (diff of the snapshot tree and a fresh tree of the work tree, limited to the chat's folder). Do → one rollback at a time per chat (409 otherwise): cancel a running turn (keep the inbox, wait ≤ 15 s), drop unread steering, append the marker, then (files) restore. `GET ?sessionId` → the hidden ranges `[start, markerSeq]` of this chat's markers.
- Restore writes only regular files inside the chat folder: `git read-tree` into a temp index + `git checkout-index --prefix=<temp>/ -z --stdin` puts the old bytes into a private temp folder; each target is checked with `realpath` (inside the folder's real path) and opened with `O_NOFOLLOW | O_NONBLOCK`, `fstat` must say regular file; then truncate + write + mode. A file that the snapshot did not have is deleted only when `lstat` says regular file. Symlinks, FIFOs, folders outside and failures are listed as skipped; the user's index, HEAD, refs, stash and config are never written.
- Client: a ↶ button in each human message's action row (hidden while `dsh-rewind-plugin`'s style tag is in the page); a small popover: "Chat only" / "Chat and files" (preview list first; "not a git repository" note); the text goes back to an empty composer; withdrawn rows are hidden. One action per chat at a time in every entry point.
- Default ON: no port, no server, no model call; the snapshots are private objects in dsh's cache. Cost: one `git add --all` per user message (dsh's Changes recorder does the same per turn). README states the size limit and the 50-snapshot window.
Design — feature `deleteChat` (client item, Host route; on by default):

The id stays archived: putting the folder back and restarting dsh shows it under Archived again.

Out of scope: rolling back subagent chats, folders outside the chat folder, ignored files, emptying the trash, restoring directories left empty.

## Worktree chats: start a chat on its own branch, see the branch (2026-10-27, branch `feat/session-worktree`)
Request (owner, chat 2026-10-27): 5–10 parallel developments per project without confusion and without Worktrunk (`wt`). (1) The New chat screen shows the branch and offers "start on the current branch", "start on a new branch" and the open worktrees; (2) the AI names the new branch from the first message; (3) the open chat's header shows its branch, changes and push state; (4) Tether shows the same; (5) the branch folders show inside their project in the sidebar, as a tree ("BOM tree"), not as separate projects; (6) shared ignored files (`.env`, `node_modules`) come into each worktree; (7) after this works, Promes moves from `wt` to Composer Plus and `wt` is removed.
Work happens in the worktree `../dsh-composer-plus-session-worktree` (branch `feat/session-worktree`, from e1cd30c). The main checkout has another chat's uncommitted five-features work (same files); merge after both are committed (conflicts expected in `FEATURES`, the test script, locales, `docs/features.json`, generated README tables, `tether/FEATURES.md`; reuse its `branchOf` then).
Evidence (read before planning, dsh 0.2.0-rc.2 / 0.2.1-rc.2 packages):
- `conversation.hero.options` (list, session scope) renders next to the project chip only on 0.2.1+, only with a session. 0.2.0-rc.2 has no hero slot: there only the header part works.
- Sidebar membership is `header.cwd` with exact realpath equality (`dsh-workspace` `attachSession`/`indexHeader`); a chat never moves to another project. So a branch chat must be a new session created in the worktree's own workspace, not a moved chat (`workingDirectory.set` would leave it under the main project).
- dsh's own "Workspace tree" view (`groupBy: 'workspace-tree'`, `owningParentFolder`) nests a registered workspace under the nearest registered parent folder. A worktree at `<repo>/.worktrees/<name>` therefore shows inside its project. The view is a dsh setting (localStorage `dsh.workspace.view.v5`, read once at start); a plugin cannot switch it live.
- `WorkspaceRegistry.create(path, title)` (Host, `workspaceRegistry`) is idempotent per real path and prepends new workspaces; `sessionController.create({ workspaceId, agentPreset? })`, `prompt`, `selectModel` exist on both versions.
- The composer send goes through `SessionInputShell.deps.defaultSink(text, attachmentIds, mode, signal)` (both versions; `conversation.input.for(actx)` returns the shell); `{kind:'error', text}` restores the draft and shows the text. Slash commands use `claim.submit`, not the sink.
- `git ls-files --others --ignored --exclude-standard --directory` lists ignored entries (folders collapsed). `--exclude-from=<include>` with `--directory` also lists parent folders, so a plain intersection could copy a whole ignored folder for one included file: matching must test each ignored entry against the include patterns.
- Copy speed: Promes frontend `node_modules` (16 861 entries) with `fs.promises.cp(..., { mode: COPYFILE_FICLONE, verbatimSymlinks: true })` 4.7 s, `cp -c -R` 2.85 s (APFS clones, no extra disk).
Decisions:
- One feature `worktreeChats` (browser switch, on by default: no port, the only model call is the branch name after the user sends with "New branch" chosen). It covers the New chat chip, the send hook and the header status.
- Worktree path `<main repo>/.worktrees/<branch with / → ->` (the Promes layout). When `.worktrees/` is not ignored, add it to `.git/info/exclude` (local, not committed).
- Copy = `.worktreeinclude` ∩ ignored entries, from the chat's repository top folder; no include file → nothing (the `--require-include` behavior). An entry is copied only when the entry itself matches (a folder is never copied for a file inside it: under-copy, never over-copy). Symlinks are copied as links (their target is never read); a FIFO/device is skipped; a source or target parent outside its tree is skipped; nothing is overwritten.
- Branch name: one model call (dsh default model, lowest effort, 10 s) for `<type>/<topic>` (`feat|fix|refactor|docs|chore|test`, lowercase ASCII words with `-`), validated with a regex and `git check-ref-format --branch`; fallback: a slug of the message (Turkish letters folded) `feat/<words>`, else `feat/chat-<time>`; a taken name gets `-2`, `-3`.
- New chat: workspace title = branch name, `sessionController.create({ workspaceId, agentPreset })` with the source chat's preset and model, then `prompt` (text only; a message with attachments is refused with a notice: send text first).
- Header status: `⑂ <branch> · N changes · ↑a ↓b` (upstream) and "not pushed" without upstream; refreshed on open, when the chat stops running and on window focus; a click opens Changes (when that feature is on).
- Tree look: the chip menu shows a one-line hint to choose dsh's View options → Workspace tree while another grouping is active (no hidden write to dsh's store).
- Invariant change: Composer Plus git was read-only (plus Turn rollback's own store and file restore). This feature writes: `git worktree add -b`, `.git/info/exclude`, copied ignored files, a workspace registration. It never removes, pushes, merges or deletes a branch or worktree.
