为 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（dsh）桌面版和网页版界面带来 Codex 风格的实用功能：改动面板、滑动卡片式的功能创意、能搜索消息文字的侧边栏搜索、可同时恢复文件的回合回退、把对话删除到废纸篓、输入框下方的项目名称、侧边栏中的项目状态、输入历史、计划模式快捷键、一键继续、重启后继续运行中的对话、队列拖拽排序、会话深层链接、以 Markdown 格式导出对话、按对话授予的 Auto Review 许可、后台通知、通过 Tether 应用在 iPhone 上访问，以及自动更新。

**一句话概括：** 这是一个 DeepSeek Harness 插件（npm 包 `dsh-composer-plus`，在 设置 → 插件 中显示为 **Composer Plus**）。它添加了 git 改动面板、Tinder 式的功能创意卡片、也能查找消息中词语的侧边栏搜索、↶ 回合回退（仅对话，或对话和文件）、删除对话、输入框下方的项目名称、↑/↓ 输入历史、Shift+Tab `/plan` 切换、一键 ▶ 继续、重启后继续、拖拽调整队列顺序、复制会话链接、导出为 Markdown、Auto Review “本对话内允许”、后台通知、iPhone 访问（手机连接，Tether 应用）、11 种额外界面语言和自动更新。

<p align="center"><img src="docs/images/hero.webp" width="820" alt="装有 Composer Plus 的 DeepSeek Harness：正在运行的项目在侧边栏中显示加载图标，改动面板显示 git diff"></p>

这是非官方的社区插件。插件只在检查更新时访问网络（GitHub releases 和 npm registry）；关闭 **自动更新** 后，启动时就不再发出这些请求。只有在你点击 **推荐功能** 时，**功能创意** 才会调用对话自己的模型。**下一条消息预测**（默认开启）每完成一个回合都会调用一次在设置中选择的模型（除非你另选，否则为 dsh 的默认模型），不需要点击；在 **设置 → Composer Plus** 中关闭它，即可停止这些调用。**输入时补全**（默认关闭）在你开启后，会在你每次输入停顿时调用为它选择的模型（默认使用预测的模型）。只有在你点击魔法棒时，**优化提示词** 才会调用模型。**目标检查**（默认开启）在智能体每次于自动轮次中把 `/goal` 标记为完成时调用一次模型。**手机连接**（默认关闭）只有在你开启后，才会接受来自本地网络或 tailnet 的 iPhone 连接。

## 安装

**桌面应用：** 设置 → 插件 → **添加插件** → 输入 `dsh-composer-plus` → **立即启用**。
也可以粘贴 `https://github.com/furkancak1r/dsh-composer-plus` 来代替 npm 包名。

**网页版 / CLI profile：**

```sh
dsh plugin --profile web add dsh-composer-plus
```

然后重启 dsh。（CLI 无法安装到桌面版 profile 中；桌面版 profile 由应用自己管理。）

> dsh 使用的 pnpm 会跳过发布不到 24 小时的版本。刚发布新版本时，请加上版本号：`dsh-composer-plus@1.15.0`。

| **功能创意** | <a id="feature-featureideas"></a>右侧边栏 → `+` → **功能创意** → **推荐功能**。对话自己的模型会读取对话所属项目的简短概要（顶层文件、README 和清单文件的开头部分、README 其余部分的大纲、最近提交的标题），并推荐最多 8 个功能。这些功能以一叠卡片的形式显示，语言与 dsh 的界面语言一致。向右滑动卡片（或点击 **✓**，或按 `→`；无论哪种方式，卡片都会飞向对应的一侧），即可在同一项目中新建对话：新对话以计划模式启动，并把该创意作为请求，因此在你批准计划之前不会有任何改动。要跳过计划，请点击 **▶ 直接实现**（或按 `↑`；卡片会向上飞出）：新对话会立即启动，并把该创意作为普通请求，模型会做出改动并运行检查（审批照常适用）。向左滑动（或点击 **✕**，或按 `←`）可跳过；**撤销**（或按 `Z`）可找回跳过的卡片。点击 **↓**（或按 `↓`）可把好的创意留到以后：它会进入项目的 **稍后** 列表，同一项目文件夹中的每个对话都会显示这个列表（重启后也一样）。**稍后（N）** 会打开这个列表；**规划** 会为该创意启动同样的计划模式对话，**直接实现** 则启动不做规划的对话，两者都会把它从列表中移除；**全部合并规划（N）** 会为列表中的所有创意启动一个计划模式对话，因此共同的部分只需规划一次；**从列表中移除** 会删除它。**复制为清单** 会把整个列表以 Markdown 清单的形式复制到剪贴板（`- [ ] Title — Summary`，每个创意一行），可用于问题跟踪器或 TODO 文件；它不会发起任何网络请求。在某个创意上点击 **创建 GitHub issue**，会用你自己的 GitHub CLI（`gh`）登录，在项目的 GitHub 仓库中以该创意的标题和概要（以及理由）创建 issue；之后创意旁会显示 **Issue #N** 链接，点击即可打开该 issue。**更多创意** 会添加更多卡片。如果只想获得某一方面的创意，请在 **推荐功能** 旁边的输入框中输入一个简短的 **关注主题**（最多 80 个字符；按 `Enter` 也会开始推荐），或点击输入框下方的某个固定主题：**性能**、**无障碍**、**测试**、**安全**、**易用性** 或 **文档**（再次点击可清除）。之后，模型只会推荐与该主题相关的功能；输入框为空表示不限主题。同一项目中不会重复推荐同一个创意：每个推荐过的创意（跳过的、留到以后的或已开始的）都会进入项目的 **历史**，模型会被告知不要再推荐这些创意，标题重复的创意会被丢弃。**历史** 会列出这些创意，并标为 **已开始** 或 **已建议**；**忘记**（或 **全部忘记**）可让某个创意再次出现；仍在 **稍后** 列表中的创意不会被推荐，直到你从该列表中移除它。只有在你点击时才会调用模型。 | <a href="assets/features/featureIdeas.webp"><img src="assets/features/featureIdeas.webp" width="160" alt="截图：功能创意"></a> |

## 设置

每项功能都可以单独开启或关闭：dsh **设置 → Composer Plus**。每一行都有一张小截图：将鼠标悬停在上面可查看放大的预览，点击可按原尺寸打开（按 `Esc` 关闭）。顶部的 **搜索功能** 框会按名称或描述筛选页面（支持任何语言，不区分大小写和重音符号）；按 `Esc` 可清空。每一行都有一个开关和一段简短说明；更改会立即生效，不需要重启，并会保存在该设备上。行名后面的小 **?** 会打开 README 中介绍该功能的部分，使用与 dsh 界面语言相同的 README。除 **手机连接**、**重启后继续** 和 **输入时补全** 外，所有功能默认开启。这三项以及 **内容搜索**、**回合回退**、**下一条消息预测** 和 **目标检查** 的开关由 dsh 的 Host 保存，因此它们对每个窗口都有效，并在重启后保留。**下一条消息预测**、**输入时补全**、**优化提示词** 和 **目标检查** 的 **模型** 选择也由 Host 保存（**输入时补全** 默认 **与“下一条消息预测”相同**，**优化提示词** 和 **目标检查** 默认 **与对话的模型相同**）；**本对话内允许** 的 **时限**（默认 1 小时）也由 Host 保存。**内容搜索** 只有在重启 dsh 后才会改变（dsh 在启动时读取它）；在此之前，它所在的行会显示 **重启 dsh 后此更改生效。**

### 应用语言

打开 **设置 → Composer Plus → 应用语言**，然后选择 **系统语言** 或 13 种语言之一：

English · 中文 · Türkçe · Español · Português (Brasil) · Français · Deutsch · Русский · 日本語 · 한국어 · Bahasa Indonesia · Tiếng Việt · हिन्दी

<p align="center"><img src="docs/images/language-tr.webp" width="720" alt="已切换为 Türkçe 的 DeepSeek Harness 界面"></p>

整个应用会立即切换语言。这个选择保存在 dsh 自己的 `locale.preference` 中（与 通用设置 → 语言 是同一个设置），因此重启后依然有效。**系统语言** 会清除这个选择：桌面应用跟随操作系统语言，网页版跟随浏览器语言，不支持的语言会回退为英语。安装插件绝不会覆盖你已经选择的语言。

每个语言包有 3,280 条文本：dsh `0.2.0-rc.2` 和 `0.2.1-rc.2` 的全部界面文本（对话、侧边栏、设置、审批、自动化任务、文件预览、插件管理器、插件市场）、插件自己的控件，以及常用的 [dsh-rewind](https://github.com/SiriLee/dsh-rewind) 插件。以下内容不会翻译：你的消息、模型输出、代码、斜杠命令名称（`/plan`、`/compact`）、由提供商定义的标签（例如推理强度 `High`）、其他插件的文本，以及桌面应用的原生菜单和更新对话框（dsh 只提供这些内容的英文和中文版本）。较新版本的 dsh 新增的字符串，在语言包更新之前会以英文显示。如果其他插件已经提供了某种语言，该语言仍由那个插件提供。

## 隐私与安全

- **继续：** 经过身份验证的本地接口只会恢复最后一个被中断的回合，会拒绝过期或重复的请求，并保留现有的审批钩子。它不会发送新的用户消息。
- **重启后继续：** 在你开启之前一直关闭。Host 端只在 `$DSH_HOME/storages/dsh-composer-plus/resume.json`（仅所有者可访问）中保存对话 ID 和开始时间，任何数据都不会离开你的电脑。只有当 dsh 自己的日志表明是 dsh（而不是你）停止了最后一个回合时，它才会继续该对话。审批和 Auto Review 照常适用于继续的回合。

- **改动面板：** git 在你的电脑上、在对话自己的文件夹中以只读方式运行，并通过 dsh 经过身份验证的 `/api` 通道调用。它从不提交、暂存或拉取，只显示 git 自己列出的路径。树最多列出 1000 个本地和远程分支，每个分支最多显示最新的 300 个提交：只沿第一父提交，合并提交代表它带入的提交。它从不切换（checkout）分支。**本对话** 会读取对话自己的日志，找出它的文件工具写入的文件，并在一个会立即删除的临时文件夹中，把它们与该对话的回合回退快照进行比较；它不会向你的仓库或快照存储写入任何内容。
- **功能创意：** 在你点击 **推荐功能** 之前，什么都不会运行。点击后，Host 端只读取对话自己的文件夹（浏览器从不发送路径）：顶层条目的名称，README、AGENTS.md 和清单文件（`package.json`、`pyproject.toml`、`Cargo.toml`、`go.mod` 等）的前 6 kB，README 其余部分的大纲（标题、表格行、列表项，最多 6 kB），以及最近提交的标题（`git log --format=%s`，最多 6 kB），总计最多 28 kB。它会跳过 `.env*`、密钥文件和 `node_modules` 等文件夹，并且只读取位于该文件夹内的普通文件：指向文件夹外部的符号链接、FIFO 或设备文件都会被跳过。这份概要会通过 dsh 自己的提供商设置，以一次请求的形式发送给对话所用的模型；它不会被添加到任何对话中。项目中的任何内容都不会被写入。向右滑动的创意会以计划模式新建对话，因此审批和计划审阅照常适用。**直接实现** 不使用计划模式启动对话：模型可以立即修改文件，对话平常的审批和 Auto Review 照常适用。留到以后的创意（标题、概要、理由、工作量）会与项目的文件夹路径一起，保存在 dsh home 下的 `storages/dsh-composer-plus/later.json` 中（仅所有者可访问的文件）；不会向项目写入任何内容。推荐过的创意的历史（标题、概要、理由、工作量、日期、是否已启动）也以同样方式保存在 `storages/dsh-composer-plus/idea-history.json` 中，每个项目最多 200 条（最早的先被移除）；该项目下次 **推荐功能** 时，这些标题会发送给模型。
- **内容搜索：** 没有新的代码来搜索你的对话：插件只是开启 dsh 自带的消息索引（SQLite FTS5，`dsh-session-query-sqlite`），并为它提供一个文件 `$DSH_HOME/cache/composer-plus/session-search.db`（文件和文件夹仅所有者可访问）。这个文件包含你的用户消息和助手消息的文本，因此它的私密程度与 `$DSH_HOME/sessions` 中的对话日志相同。任何数据都不会离开你的电脑。它是 dsh 可以重新生成的副本：你可以在 dsh 关闭时删除它。开关保存在 `$DSH_HOME/storages/dsh-composer-plus/content-search.json` 中。
- **回合回退：** 在你发送每条消息之前，Host 会在它自己的存储 `$DSH_HOME/cache/composer-plus/rollback/<chat>.git`（仅所有者可访问的文件夹）中，为对话的文件夹创建一个 git 快照。快照保存该文件夹中 git 能看到的文件（不包括被忽略的文件）的副本，因此它的私密程度与项目相同。它会读取你仓库中的对象（不会再复制一份 git 已有的内容），并且从不写入你仓库的索引、`HEAD`、分支、标签、stash 或配置；git 在你的仓库中做出的唯一更改，是更新它复用的对象文件的时间戳（这会推迟 `git gc` 对这些文件的清理）。带文件的回退只会写入对话文件夹内的普通文件；它会跳过符号链接、管道以及文件夹外的任何内容。任何数据都不会离开你的电脑。你可以在 dsh 关闭时删除这个存储（此后在发送新消息之前，回退只能用于对话本身）。**删除对话** 也会删除对话的存储。开关保存在 `$DSH_HOME/storages/dsh-composer-plus/rollback.json` 中。带文件的回退还会保留回退之前那一刻的文件（同一存储中的 `refs/r/…`），供 **重新应用** 使用；已重新应用的回退记录在 `$DSH_HOME/storages/dsh-composer-plus/redone.json` 中（仅所有者可访问）。
- **创建 GitHub issue**（功能创意 → **稍后** 列表）：只在你点击时运行。Host 端会在对话的文件夹中运行你自己的 GitHub CLI（`gh issue create`），使用该创意保存的标题和概要（以及理由）；`gh` 使用它自己的登录和该文件夹的 GitHub 远程仓库，因此 issue 会以你的账号创建在那个仓库中，能看到那个仓库的所有人都能看到它。dsh 会从它启动的命令中移除名称像令牌（token）的变量；如果你通过 `GH_TOKEN` 或 `GITHUB_TOKEN` 给 `gh` 提供了令牌，插件只把这两个变量传给 `gh`。issue 链接会与该创意一起保存在 `later.json` 中。
- **改动此文件的对话**（改动面板，文件的“…”菜单）：Host 端按 dsh 保存的样子，读取文件夹位于同一仓库中的对话的日志，并返回每个对话的标题、时间和请求的第一行；它从不打开该文件本身。
- **对话行显示 Git 分支：** Host 端会在每轮开始和结束时，在对话的文件夹中运行 `git branch --show-current`（只读），并只把对话 id、分支名和时间保存在 `$DSH_HOME/storages/dsh-composer-plus/session-branches.json` 中（仅所有者可访问的文件，最多保留最新的 2000 个对话）。开关保存在它旁边的 `branches.json` 中。
- **在对话中查找** 只在页面中运行：它读取页面显示的文本，不发送任何内容。
- **将对话导出为 Markdown：** Host 端只读取对话自己的日志（即 dsh 显示的那些消息），并把它们交给页面；它不读取任何项目文件，也不通过网络发送任何内容。Markdown 只会进入你的剪贴板或你保存的文件。
- **删除对话：** 把对话自己的日志文件夹（`$DSH_HOME/sessions/<project>/<chat>`）移到废纸篓。它不会触碰项目文件夹。
- **本对话内允许：** 授权连同授予时间一起保存在 `$DSH_HOME/storages/dsh-composer-plus/chat-grants.json` 中（仅所有者可访问）。一项授权只覆盖一个对话中的一个确切工具，直到时限结束（默认 1 小时）。如果该工具可以写入，授权也覆盖任何写入操作。可以在标题栏的标签中撤销授权。
- Auto Review 仍会检查每一次调用；审查失败的调用永远不会被自动允许。
- **手机连接：** 在你开启之前一直关闭。开启后，Host 端会运行 Tether 网关：端口 19390 上的 HTTPS 服务只接受你的 Wi-Fi 子网和你的 tailnet（100.64.0.0/10）；另有一个位于 `127.0.0.1:19391` 的配对页面（仅限这台 Mac）。手机需要二维码中的一次性代码（5 分钟内有效），还需要你在 Mac 上点击 **Approve**。手机会固定（pin）网关的证书。Mac 只保存每部手机令牌的哈希值（有效期 30 天，使用期间会续期）；**Remove** 会立即关闭该手机的连接。手机只能调用允许列表中的 dsh 方法（对话、提示词、附件、斜杠命令、审批、问题、模型、智能体、目标），不能访问设置、凭据、文件浏览器或终端。“Tailscale only”会拒绝来自本地网络的所有连接，包括已经打开的连接。访问日志在 `access.json` 中保存最新的 200 次连接尝试（时间、IP 地址、设备名称、允许或拒绝，以及原因）；其中从不包含令牌或配对代码。数据：`$DSH_HOME/storages/dsh-composer-plus/mobile/`（仅所有者可访问的文件）。详情：[tether/README.md](tether/README.md)。
- **更新：** Host 端会向 `api.github.com` 查询最新版本，并向 `registry.npmjs.org` 查询这个确切的版本；不会发送任何关于你或你的对话的信息。安装使用 dsh 的插件管理器（`pnpm add dsh-composer-plus@<version>`；如果 dsh 0.2.1 对已安装的插件拒绝这样做，则使用 `pnpm add https://registry.npmjs.org/dsh-composer-plus/-/dsh-composer-plus-<version>.tgz`，之后 profile 会把这个 URL 列为插件的来源），因此 dsh 自己的 registry、脚本和版本兼容性检查都会生效。预发布标签和旧版本永远不会被安装。
- **下一条消息预测：** 默认开启；在 **设置 → Composer Plus** 中关闭它，即可停止这些模型调用。每完成一个回合，Host 端会把该对话中你自己的消息和智能体的文字回复（不含工具输出、隐藏上下文和推理内容），最多约 6,000 个字符（最新的部分），发送给所选的模型（除非你另选，否则为 dsh 的默认模型）。它通过 dsh 自己的提供商设置，以一次请求的形式发送。对话中不会保存任何内容：猜测不会被添加到对话历史中。开关和模型选择保存在 `$DSH_HOME/storages/dsh-composer-plus/predict.json` 中（仅所有者可访问的文件）。
- **输入时补全：** 在你开启之前一直关闭。开启后，你每次输入停顿时，Host 端会把你目前已输入的文字，以及该对话中你自己的消息和智能体的文字回复（不含工具输出、隐藏上下文和推理内容；对话部分最多约 3,000 个字符），发送给在 **输入时补全** 下选择的模型（默认为 **下一条消息预测** 的模型）。新的停顿会停止较早的请求。对话中不会保存任何内容。开关保存在 `$DSH_HOME/storages/dsh-composer-plus/complete.json` 中（仅所有者可访问的文件）。
- **优化提示词：** 在你点击魔法棒之前，什么都不会运行。点击后，Host 端会以一次请求的形式，把以下内容发送给在 **优化提示词** 下选择的模型（默认为对话自己的模型）：你的草稿；该对话中你自己的消息和智能体的文字回复（不含工具输出、隐藏上下文、推理内容和已回退的消息；最多约 6,000 个字符，最新的部分）；与 **功能创意** 相同的项目概要（文件规则也相同：不读取 `.env*` 或密钥文件，跳过指向文件夹外部的符号链接和 FIFO）；`git status` 列为已更改的路径；以及最多 30 个名称与你的草稿有相同词语的已跟踪或未跟踪（未被忽略）路径。除这份概要外，不会发送任何文件内容。对话和项目中都不会写入任何内容：回答只会替换输入框中的草稿，是否发送由你决定。模型选择保存在 `$DSH_HOME/storages/dsh-composer-plus/improve.json` 中（仅所有者可访问的文件）。
- **目标检查：** 只有当智能体在自动轮次中把 `/goal` 标记为完成时（或者你点击 **立即运行** 时）才会运行。Host 端在对话的文件夹中、按对话的沙箱模式运行测试命令（与 dsh 自己的 `bash` 工具相同：同样的文件访问策略；沙箱无法启动时，测试不会运行，检查判为失败）。为了找到命令，它只读取 `package.json`、`Makefile`、`Cargo.toml`、`go.mod`、`pyproject.toml` 和 `pytest.ini`，并且只读取文件夹内的普通文件（不跟随指向文件夹外部的符号链接，不读取 FIFO）。然后，它以一次不带工具的请求，把以下内容发送给在 **目标检查** 下选择的模型（默认为对话自己的模型）：目标；从目标开始以来的对话（你的消息、智能体的回复、截断到 1,000 个字符的工具调用以及每个工具结果的最后 2,000 个字符；不含推理内容和已回退的步骤；最多约 60,000 个字符，最新的部分）；`git status --short`；以及测试输出的末尾。工具输出可能包含智能体读取过的内容，因此这次请求可能包含你文件的一部分，与对话本身相同。对话和项目中都不会写入任何内容。你的测试命令、上限、上次结果（含其输出的末尾）和模型选择保存在 `$DSH_HOME/storages/dsh-composer-plus/goal-check.json` 中（仅所有者可访问的文件，最新的 500 个对话）。

## 故障排除

- **macOS 上没有通知：** 系统设置 → 通知 → DeepSeek Harness → 允许通知。选择“提醒”可以让通知一直留在屏幕上。
- **dsh 更新后，▶、队列把手、项目状态、近期项目选项、折叠全部项目、复制路径、项目搜索框、下一条消息预测、输入时补全、本对话内允许或右键菜单不见了：** 这些功能挂接在 dsh 当前的 HTML 上，因为 dsh 还没有为它们提供插槽。如果 dsh 修改了这部分标记，它们会自动隐藏；其他功能不受影响。请提交一个 [issue](https://github.com/furkancak1r/dsh-composer-plus/issues)。
- **“更新失败”或“不是从 npm 安装的”：** 从本地文件夹链接的副本或被重命名的副本无法自行更新；请在 设置 → 插件 中重新安装 `dsh-composer-plus`。在其他情况下，消息会显示 pnpm 错误的第一行；点击 **检查更新** 可重试。
- **手机连接提示网关未运行：** “no IPv4 address on en0”表示这台 Mac 没有 Wi-Fi/以太网地址；“EADDRINUSE”表示另一个 dsh（或其他应用）正在使用端口 19390 或 19391。同一时间只能有一个 dsh 运行手机连接。
- **手机连接、重启后继续或内容搜索提示“重启 dsh”：** 插件在 dsh 运行期间被更新了（对于内容搜索，也可能是你更改了开关）；新状态会在重启后加载。
- **搜索只能找到标题：** 内容搜索已关闭；或者你开启它或安装插件后还没有重启 dsh；或者这个词只出现在工具输出中（见“限制”）。
- **我的消息上没有 ↶ 按钮：** 回合回退已关闭；或者该对话是子代理对话；或者已安装 dsh-rewind-plugin（请使用它的 ↶ 按钮）。更新后，请重启 dsh。
- **“对话和文件”显示为灰色：** 项目不是 git 仓库；或者没有这条消息之前的快照（这条消息比插件更早，或者它的快照已被最新的 50 个快照替换）；或者没有文件发生变化。
- **删除时提示另一个 dsh 已打开此对话：** 使用同一 dsh home 的另一个 dsh 持有该对话的锁。关闭那个窗口或那个 dsh，然后再次删除。在此期间，对话会保持归档状态。
- **开启“Tailscale only”后 iPhone 无法连接：** Mac 和 iPhone 上都必须开启 Tailscale。Mac 上的 Tailscale 关闭时，手机连接面板会发出警告。访问日志会显示每次被拒绝的尝试及其原因。
- **重启后对话没有继续：** dsh 退出时“重启后继续”处于关闭状态；或者你自己停止了那个回合；或者回合已经结束（完成或失败）；或者对话已被归档；或者当时有超过 20 个对话正在运行（只有最新的 20 个会继续）。
- **创建 GitHub issue 提示“gh could not open the issue”：** 这条消息是 `gh` 自己输出的第一行。请在终端中运行 `gh auth status`，并用 `gh auth login` 登录；对话的文件夹必须有 GitHub 远程仓库（`git remote -v`）。“not installed or not on the PATH of dsh”表示 dsh 没有找到 `gh`：请安装它，或从一个能运行 `gh` 的终端启动 dsh。
- **对话行上没有分支标签：** 安装此版本后，该对话还没有新的一轮；或者它的文件夹不是 git 仓库；或者 **对话行显示 Git 分支** 已关闭。更新后，请重启 dsh（分支由 Host 端记录）。
- **目标检查显示测试以代码 127 或 “not found” 退出：** 从 Finder 或程序坞启动的 dsh 的 PATH 可能比终端里的短，因此找不到 `npm`、`pnpm` 或 `cargo`。请从终端启动 dsh，或者在 **目标检查** → **编辑** 中用完整路径设置你自己的测试命令。**立即运行** 会马上显示结果。
- **目标没有关闭，智能体一直在工作：** **目标检查** 发现了失败的测试或缺少的工作；目标下方的一行会显示原因（将鼠标悬停在结果上可查看详情）。请修正原因或测试命令，或者用 `/goal` 或目标栏自己完成目标（这不会被检查）。
- **刚发布新版本时安装失败：** 请加上版本号（`dsh-composer-plus@1.15.0`），见上文的安装说明。

## 限制

- 不发送消息的“继续”依赖 dsh 的 `agent/pre-step` → `agent/request` 生命周期。升级 dsh 时，请重新检查兼容性。
- **功能创意** 会在内存中为每个对话保留卡片，直到 dsh 或页面重新加载；之后，**推荐功能** 会再次询问模型。卡片使用你点击时 dsh 的界面语言；更改语言后，已在卡片堆中的卡片保持原来的语言，**更多创意** 则使用新语言。模型只能看到简短的项目概要，看不到代码，因此某个创意可能与项目已有的功能重复：跳过它即可。只有当 profile 中有 dsh 的 `/plan` 命令时，新对话才会以计划模式运行；否则，创意会作为普通的第一条消息发送。**稍后** 列表属于对话的文件夹路径：通过符号链接打开的同一个文件夹有它自己的列表。每个项目最多保留 50 个创意（移除一个后才能再添加），相同的标题只保留一次。拖动卡片只能决定向左或向右；要保存卡片，请使用 **↓**；要直接实现，请使用 **▶**。重复只按标题判断：模型仍可能以新名称推荐以前的创意，跳过它即可。如果模型只返回以前的创意，就不会显示新的创意：请再点击一次。关注主题越窄，越容易出现这种情况；请换一个更宽的主题，或清除主题。在 dsh 或页面重新加载之前，每个对话的关注主题都会保留在输入框中。
- **将对话导出为 Markdown** 只包含你自己的消息和助手的文字回复：工具调用及其输出、推理内容、图片（用一行 `[image]` 标记）、隐藏上下文以及被回合回退或 dsh-rewind-plugin 移除的消息都不包含在内。同一回合的回复会合并为一个部分。一次导出最多包含约 400 万个字符；更长的对话只导出前面的部分，并附上一条说明。
- **重启后继续** 是继续回合，而不是重放回合。退出时正在运行的工具调用会以 dsh 的“结果未知”结果结束，模型会被告知不要重复已完成的工作，但不能安全运行两次的命令仍可能再次运行。当时打开的子代理、审批和问题不会恢复：它们的父对话会继续，并再次询问。每次启动最多继续 20 个对话。

- **内容搜索** 是 dsh 自带的搜索，因此也有 dsh 的限制。它只搜索用户消息和助手消息：不搜索工具输出（命令、文件内容、结果），也不搜索推理内容，并且不能按用户、助手或工具消息筛选。它匹配完整的词，而不是词的一部分（`deploy` 找不到 `deployment`）；不带重音的字母也能匹配带重音的字母（`seker` 能找到 `şeker`）。每个对话只显示一行，带有 dsh 的 240 字符摘录，最多显示 20 行。
- **内容搜索** 的开销（在 247 个真实对话日志的副本上测得：159 MB，dsh 0.2.1-rc.2，Apple Silicon，32 GB）：每次启动后的第一次搜索会构建索引，约需 15 秒。在此期间，dsh 的 Host 约有 7 秒不响应任何请求，因此其他对话会在这段时间内暂停流式输出（页面本身不会卡住）。Host 的内存在峰值时约增加 1.1 GB；一分钟后仍比启动时高约 0.5–0.6 GB，直到 dsh 退出。索引文件约 165 MB。之后的搜索约需 0.5 秒。重启后，第一次搜索约需 1 秒（只添加新的或有改动的对话），内存约增加 70 MB。如果你的电脑内存较少，请关闭此功能。
- **内容搜索** 只有在重启 dsh 后才会生效，并且索引文件由所有使用同一 dsh home 的 dsh 共享：同一时间只运行一个这样的 dsh（dsh 规定每个索引文件只能有一个所有者）。
- **回合回退** 只在 git 仓库中、并且只在对话的文件夹中恢复文件。每个对话保留最新的 50 个快照。被忽略的文件（`.gitignore`、`info/exclude`、你的全局忽略文件）、空文件夹、符号链接和子模块不会被恢复；创建快照时被忽略的文件永远不会被删除，即使该回合更改了忽略规则也一样。git 无法读取的文件不会进入快照。你每发送一条消息，就会对对话的文件夹执行一次 `git add --all`，写入私有存储：在包含大量未跟踪文件的超大文件夹中，这可能需要几秒钟，下一次工具调用会等待它完成（最多 10 秒；之后快照会在后台完成）。如果你仓库的 `git gc` 删除了旧快照需要的对象，该文件会被列为未恢复。只有消息的文字会回到输入框中：请重新添加它的图片或文件。子代理对话没有 ↶（子代理的文件更改算作启动它的对话的更改）。导出的对话（`/export`）中仍包含被撤回的消息。用一个隐藏标记撤回对话的一部分，这个思路来自 SiriLee 的 [dsh-rewind-plugin](https://github.com/SiriLee/dsh-rewind)（MIT）；Composer Plus 没有使用其中的任何代码。
- **删除对话** 需要 dsh 的归档功能（dsh 0.2.0 及更高版本）。如果对话（或它的某个子代理对话）在 15 秒内没有停止，或被另一个 dsh 持有，它会保持归档状态，不会移动任何内容。在 macOS 以外的系统上，废纸篓文件夹必须与对话历史位于同一磁盘。你删除的已打开对话会以归档和隐藏的状态留在 dsh 的内存中，直到 dsh 重启。请自行清倒废纸篓；dsh 不会替你清倒。
- dsh 的队列没有 `move` 操作，所以由插件的 Host 端在 dsh 的队列中直接移动排队的消息本身（一次改动，还是同一条消息）。带有图片或文件的消息也能移动。只有你自己的消息可以移动：队列中的目标轮次或对问题的回答会留在原处。如果在你拖动时有消息开始发送，则不会移动任何消息，并会显示一条提示说明这一点。
- 如果新版本不改动任何 dsh 设置，dsh 0.2.1 会立即加载更新；否则（以及在 dsh 0.2.0 上），请重启 dsh 来加载更新。插件从不替你重启 dsh。没有 dsh 插件管理器的网页版/CLI profile 只会提示有新版本。
- **本对话内允许** 从授权的那一刻开始计算时限。新的时限会立即应用于仍在生效的授权，因此更短的时限可能会让它们立即结束。1.12 及更早版本的授权没有时间信息：更新后，代理会就这些工具再询问一次。
- **保持输入框焦点** 只在发送 `/` 命令或技能后才会把焦点还给输入框。dsh 解析命令时，输入框会有几毫秒处于只读状态，因此这段时间内按下的键会丢失。如果 dsh 的 `/` 菜单仍然打开，`Enter` 会选择高亮的行，而不会发送。
- **手机连接** 只适用于 macOS（它使用 `en0`、`openssl`、`swift` 和 `dns-sd`）。它使用固定端口 19390 和 19391，因此每台 Mac 上同一时间只能有一个 dsh 运行它（每台 Mac 是手机 Mac 列表中的一项）。只有在 Tether 打开或刚转入后台时，手机才能收到通知（没有推送服务）。在 Tether 中打开“Settings → Notifications → Send notifications”之前，Tether 不会发送通知。此开关默认关闭，打开时 iOS 会请求通知权限。iOS 应用尚未上架 App Store：请用 Xcode 从 `tether/ios` 构建它。“Tailscale only”仍然需要 Mac 有 Wi-Fi 或以太网地址（只有在有这样的地址时，网关才会启动）。访问日志按 Mac 分别保存，只保留最新的 200 次尝试；一分钟内重复的尝试不会新增一行，而是把同一行的次数加一。Tether 的应用锁不会隐藏 iPhone 锁定屏幕上的通知预览：请在 iOS 设置中关闭它们。Tether 的绿点跟随 Mac：在 dsh 中打开的对话，手机上的绿点也会消失。在 Tether 中打开的对话，只在手机上消失；Mac 上 dsh 自己的绿点会一直保留，直到你在 Mac 上打开该对话。
- 会话链接在对话中有效；点击它不会打开对应的对话。用 **复制消息链接** 复制的链接，只在 dsh 0.2.1 及更高版本中、并且只从对话中的消息里才能打开对应的消息（dsh 0.2.0 没有用户文本规则，所以链接仍会被复制，但只显示为普通文本）。被回退移除的消息，或被压缩从 dsh 加载的历史中移除的消息，无法显示：此时链接会给出提示。🔗 按钮依附在 dsh 的消息行上；如果 dsh 更新改变了这部分标记，按钮就不会显示。
- **全部标为已读** 通过 dsh 中一个不是公开 API 的部分（dsh 会话状态中的 `completionUnread` 列表）来更改 dsh 自己的未读圆点。如果 dsh 更新重命名了它，该菜单项就不会显示。该菜单项放在 dsh 项目的“…”菜单中，而这个菜单没有给插件的插槽；如果 dsh 修改了这个菜单，该菜单项也不会显示。
- **原地编辑排队消息** 打开的是 dsh 自带的队列编辑器，因此也有它的限制：带图片或文件的消息不能编辑；在此期间已经开始发送的消息不会被修改（dsh 会显示它自己的错误）。
- **重新应用** 从不更改被回退的对话：它会从回退之前开始一个新对话（dsh 自带的分叉，模型上下文相同），因此新对话有新的 id 和标题。只有对话中最新的一次回退可以重新应用，只能一次，并且只在它之后没有新内容时可用（发送新消息后该选项消失）。回退之后你更改过的文件会被保留，除非你勾选覆盖它的选项。重新应用需要回退时保留的快照（同样是最新 50 个快照的范围）；在此版本之前做的回退，或用 **仅对话** 做的回退，只会恢复消息。
- **本对话** 只统计 dsh 的文件工具（`write`、`edit`、`str_replace_editor`）写入的文件。命令（`bash`）更改的文件不在这个视图中；它们显示在 **未提交** 下。如果没有该对话的回合回退快照（回合回退已关闭、安装了 dsh-rewind-plugin，或对话比插件更早），视图会与最后一次提交比较，并给出提示。回合回退为每个对话保留最新的 50 个快照：在更长的对话中，视图与保留的最早快照比较，说明从哪条消息开始，并且不计入更早的改动。**隐藏空白改动** 就是 `git diff -w`：只在行内空格上有变化的行也会被隐藏。
- **创建 GitHub issue** 需要 dsh 的 PATH 中有 GitHub CLI（`gh`），并且对话的文件夹中有 GitHub 远程仓库。它最多运行 60 秒；如果 `gh` 用时更长，issue 可能已经在 GitHub 上创建，但列表中没有它的链接（再次点击之前，请先到 GitHub 上查看：列表只从已完成的运行中读取链接，所以再次点击可能会创建第二个 issue）。有多个 GitHub 远程仓库的文件夹使用 `gh` 自己的默认仓库（`gh repo set-default`）。
- **改动此文件的对话** 与 **本对话** 一样，只识别 dsh 的文件工具（`write`、`edit`、`str_replace_editor`）：命令（`bash`）做出的改动不会列出。它读取该仓库最新的 300 个对话（按创建时间），对话更多时会给出提示；它最多显示 100 行。重命名的文件按工具写入时的名称列出。文件夹在仓库之外的对话（包括通过另一条路径指向相同文件的情况）不计入。dsh 启动后第一次打开时，会读取该仓库的所有对话日志（275 个对话约需 4 秒）；之后再打开时，只读取此后有变化的对话。
- **对话行显示 Git 分支** 显示的是对话最后一轮开始或结束时其文件夹所在的分支，而不是当前的分支：在回合之外切换分支，要到下一轮之后才会显示。此版本之前的对话，在下一轮之前不显示标签。标签放在 dsh 的对话行标记中（dsh 在那里没有插槽）；如果 dsh 更新改变了这部分标记，就不会显示标签。当对话上方的项目行与分支同名时（例如“每个对话一个分支”的文件夹），该对话行不显示分支标签，但“列表视图”中仍会显示。
- **在对话中查找** 只搜索页面显示的内容：已加载的消息和回复（向上滚动或点击 **加载更早** 可查看更早的内容），不搜索已收起的工具步骤，也不搜索工具输出中被折叠的文本。它最多统计 2,000 个匹配项（之后显示“2000+”）。它使用浏览器的高亮 API（Chromium 105 及更高版本；桌面应用支持）：在较旧的浏览器中，计数和跳转仍然可用，只是没有颜色。`Cmd+F`（Mac）或 `Ctrl+F`（Windows 和 Linux）只在屏幕上有对话时打开它；在其他地方，浏览器自带的查找照常工作。在 Mac 上，`Ctrl+F` 在文本框中仍保持 macOS 的用法（光标向前移动一个字符）。
- 重启前发出的通知，点击后只会把 dsh 带到前台。
- 活跃项目通过 dsh 保存的项目顺序来移动，因此新顺序在重启后依然保留。不属于任何项目的对话（“未分组”）无法移动；dsh 总是把它们列在最后。
- dsh 在侧边栏的视图选项菜单中没有扩展点，所以近期项目选项被添加到 dsh 自己的菜单中。如果 dsh 更新修改了这个菜单，该选项将不会显示，所有项目都保持可见。筛选作用于项目行，因此 **单列表** 不会被筛选。请与 **按工作区** 一起使用：在 **按工作区树** 中，被隐藏的父文件夹也会隐藏其中的活跃项目。**按状态** 也有同类限制：dsh 没有排序插槽，因此该菜单项和行顺序依赖 dsh 的菜单和列表标记。
- dsh 也没有项目行菜单或“工作区”标题栏插槽。**复制路径** 通过 dsh 的行标记找到项目行；**折叠全部项目** 放在 dsh 的标题栏中，并用与点击项目行相同的方式折叠每个展开的项目。如果 dsh 更新修改了这些标记，右键点击会显示浏览器自己的菜单，按钮也不会显示。
- dsh 在新对话的项目菜单中也没有扩展点，所以 **搜索项目** 框和 A–Z 顺序依赖 dsh 的菜单标记。如果 dsh 更新修改了这些标记，菜单会按 dsh 自己的样子显示：使用保存的顺序，没有搜索框。A–Z 顺序只是一种视图，不会改变 dsh 保存的项目顺序。
- dsh 也没有决定 **新会话** 在何处打开的扩展点。**新会话的默认工作区** 包装了 dsh 的一个非公开 API 方法（dsh 工作区服务的 `startSession`）。如果 dsh 更新改了它的名字，**新会话** 会在 dsh 自己选择的位置打开（当前或最近的项目）。所有不指定项目的调用都使用默认值：侧边栏按钮、它的快捷键、徽标，以及 **自动化任务** 页面上的 **新建**。dsh 启动时仍会打开上一个对话。通用文件夹在首次使用时创建并加入你的项目；在 Windows 或 Linux 上，如果 Documents 文件夹被移动过，它可能与 dsh 自己的文件夹不同。
- dsh 也没有输入框提示的扩展点，所以 **下一条消息预测** 的文字覆盖在 dsh 自己的占位文字（`[data-composer-placeholder]`）上。如果 dsh 更新修改了这部分标记，就不会显示预测。开启期间，每完成一个回合都会进行一次简短的模型调用。
- **输入时补全** 通过 dsh 自己的输入框提示显示文字（即 dsh 用于斜杠命令参数提示的 `--dsh-composer-hint` 样式）。输入斜杠命令、消息中带有文件或符号标签，或光标不在消息末尾时，它不会运行。如果 dsh 更新修改了这个样式，就不会显示补全。你每次输入停顿都会进行一次模型调用。
- **优化提示词** 只能看到简短的项目概要、已更改的路径以及名称与你的用词匹配的路径，看不到代码本身。因此它可能漏掉正确的文件，并且只会提到提供给它的路径。发送前请先阅读新文本。输入斜杠命令或消息中带有文件或符号标签时，它不会运行（新文本是纯文本，标签会丢失）；一条消息最多 8,000 个字符。图片仍保留在附件中：只有文字会改变。每次点击都会进行一次模型调用；较强的模型可能需要一分钟（按 `Esc` 取消）。
- **目标检查** 只检查智能体在自动目标轮次中做出的完成：你在对话中要求的完成、`/goal` 和目标栏都不会被检查。智能体可以自己修改测试或测试命令用到的文件；审核模型会阅读对话，可以看到这一点，但它在两个方向上都可能出错（错误的“尚未完成”会多花一轮；错误的“已完成”会关闭目标）。审核模型看到的是对话和 `git status`，而不是代码本身。只有当智能体最新的一步能更改文件的操作就是它自己在同一文件夹中成功运行完全相同命令的 `bash` 时，才会复用这次测试；带管道（`| tail`）或 `&&` 的命令不会被复用。预算在回合结束时计算，因此一个回合可能会超出预算。只计算对话自己的模型调用（不含其子智能体的调用）。检查运行期间 `update_goal` 会等待（测试最多 15 分钟，审核最多 3 分钟）。分支对话会得到新的对话 id，因此它开始时没有父对话自己的测试命令和上限。每次进入审核的完成都会花费一次模型调用。
- 已向上游请求内置支持：队列 `move` 见 [#773](https://github.com/deepseek-ai/deepseek-harness/discussions/773)，“继续”状态见 [#9269](https://github.com/deepseek-ai/deepseek-harness/discussions/9269)。

## 常见问题

**如何为 DeepSeek Harness 添加改动 / git diff 面板？** 安装 `dsh-composer-plus`，然后打开右侧边栏 → `+` → **改动**。

**dsh 能像滑 Tinder 卡片一样为我的项目推荐功能吗？** 可以：右侧边栏 → `+` → **功能创意** → **推荐功能**。向右滑动会新建一个对话来规划该功能，点击 **▶ 直接实现** 会新建一个不做规划、立即实现该功能的对话，向左滑动则跳过。

**dsh 侧边栏搜索能按消息中的词语查找对话，而不只是按标题吗？** 可以，使用 **内容搜索**（默认开启）：安装插件后重启一次 dsh，然后使用 **工作区** 旁边的放大镜。匹配的对话会显示该词周围的文字。

**能像在 OpenCode 或 Claude Code 中那样撤销一个回合并编辑我的提示词吗？** 可以，使用 **回合回退**：点击消息上的 **↶**，选择 **对话和文件**，编辑回到输入框中的文字，然后发送。

**可以删除对话，而不是归档它吗？** 可以，使用 **删除对话**：**…** → **删除…**。历史记录会移到废纸篓，因此误删后可以恢复。

**如何查看对话属于哪个项目？** 看输入框下方那一行：开启 **输入框中的项目名称**（默认开启）后，这一行会以项目名称开头。将鼠标悬停在上面可查看文件夹路径。

**如何在 dsh 输入框中使用 ↑/↓ 消息历史？** 安装本插件；在空输入框中按 `↑` / `↓` 即可浏览你发送过的消息。

**如何不输入“继续”就让被停止或失败的 dsh 回合继续？** 使用本插件后，回合被停止、失败或中断时，发送按钮会变成 **▶**；点击一次即可继续。

**我退出并重新打开 dsh 后，正在运行的对话会继续吗？** dsh 本身不会：dsh 会把这样的回合标记为已中断并等待（目标也会等待 `/goal resume`）。开启 **设置 → Composer Plus → 重启后继续** 后，dsh 退出时正在运行的对话会在下次启动时自动继续。

**预测由哪个模型生成？** 由你在 **设置 → Composer Plus → 下一条消息预测 → 模型** 中选择的模型生成。这个列表就是 dsh 自己的模型列表。**dsh 默认** 跟随 dsh 的默认模型。如果 dsh 不再列出所选的模型，预测会改用默认模型。**输入时补全** 有自己的 **模型** 菜单：**与“下一条消息预测”相同**（默认）跟随预测的模型；选择其他模型时，该模型只用于补全。如果 dsh 不再列出这个模型，补全会改用预测的模型。

**dsh 能在发送前优化我的提示词吗，就像 Roo Code 或 Augment 中的 Enhance prompt 按钮那样？** 可以，使用 **优化提示词**（默认开启）：输入一个粗略的请求，然后点击模型菜单旁边的魔法棒。它会以此对话和项目为上下文，用你的语言改写文字，但不会发送。`Cmd/Ctrl+Z` 或 **撤销优化** 可恢复你的原文。在 **设置 → Composer Plus → 优化提示词 → 模型** 中选择它的模型。

**能否让智能体不再自己宣布工作已完成，就像 loop engineering 中的审核循环那样？** 可以，使用 **目标检查**（默认开启）：用 `/goal` 开始一个目标。当智能体说目标已完成时，会运行项目的测试，并由一次独立的模型调用对照对话检查目标；任一项失败时，目标保持进行中，智能体会看到原因。在目标下方的 **目标检查** 行中用 **编辑** 设置你自己的测试命令、时间上限或 token 上限。

**如何在 dsh 中调整排队消息的顺序？** 拖动排队消息上的 ⠿ 把手，或者让它获得焦点后按 `↑` / `↓`。

**如何修改排队消息中的错字？** 在队列中双击这条消息，修改文字后按 `Enter`（按 `Esc` 取消）。它在队列中的位置不变。

**如何一次清除一个项目的所有未读圆点？** 侧边栏 → 项目的 **…** 按钮 → **全部标为已读**。

**可以链接到长对话中的某一条消息吗？** 可以：将鼠标悬停在这条消息上，点击 **🔗**。在对话中发送这个链接：在 dsh 0.2.1 及更高版本中，点击它会打开那个对话并定位到这条消息。

**我误回退了一个回合。可以找回来吗？** 可以：回退之后，立即使用输入框上方的 **重新应用**。它会从回退之前开始一个新对话，消息相同；如果回退时选择了 **对话和文件**，它还会把文件恢复回来。

**哪个对话改动了这个文件？** 右侧边栏 → **改动** → 文件的 **…** → **改动此文件的对话**。点击某一行，即可打开该对话并定位到做出改动的那条请求。

**可以在一个很长的对话中搜索吗？** 可以：在对话中按 `Cmd+F`（Mac）或 `Ctrl+F`（Windows 和 Linux）。**在对话中查找** 会高亮每个匹配项，并用 `Enter` 和 `Shift+Enter` 在它们之间跳转。

**如何只查看一个对话更改过的文件？** 右侧边栏 → **改动** → **本对话**。点击 **␣** 可隐藏只有空白的改动。

**如何让 Auto Review 在同一个对话中不再反复询问同一个工具？** 点击审批卡片上的 **本对话内允许**。它只覆盖该对话中的这个确切工具，默认有效 1 小时；可以在标题栏的标签中撤销它。在 **设置 → Composer Plus → 本对话内允许** 中更改时间。

**我的 iPhone 丢了。如何阻止它访问我的 Mac？** 点击侧边栏左下角的 **手机连接**，然后点击该 iPhone 旁边的 **Remove**。它的密钥会立即失效；只有通过你在 Mac 上批准的新配对，它才能重新连接。

**可以用 Face ID 锁定 Tether 吗？** 可以：在 Tether 中打开“Settings → Privacy → Lock with Face ID”。之后，Tether 在打开时以及你回到它时，都会要求 Face ID（或密码）。

**如何在 dsh 侧边栏中只显示我今天用过的项目？** 侧边栏 → 视图选项（滑块图标）→ **最近 2 小时内活跃**。再次选择该项即可显示所有项目。

**如何在 dsh 中复制项目的文件夹路径？** 在侧边栏中右键点击项目 → **复制路径**。

**如何一次折叠 dsh 侧边栏中的所有项目？** 点击视图选项（滑块图标）旁边的折叠按钮。至少有一个项目展开时，这个按钮才会显示。

**dsh 任务完成或需要审批时，如何收到 macOS / Windows 通知？** 保持 **后台通知** 开启（默认开启），并在操作系统设置中允许 DeepSeek Harness 发送通知。

**如何把 DeepSeek Harness 界面切换为土耳其语、西班牙语、日语……？** 设置 → Composer Plus → **应用语言**。

**如何在 iPhone 上使用 dsh？** 用 Xcode 从 `tether/ios` 构建 Tether 应用，开启 **设置 → Composer Plus → 手机连接（iPhone）**，点击左下角的 **手机连接**，扫描二维码（用 iPhone 相机或 Tether 中的 **Scan code**），轻点 **Connect**，然后点击 **Approve**。不在家时，请在两台设备上都使用 Tailscale。

**如何让新会话总在同一个项目中打开？** 设置 → Composer Plus → **新会话的默认工作区** → **新会话打开于** → 选择项目。其他项目旁的 `+` 仍会打开那个项目。

**如何在同一个项目中同时开发多个功能，并让每个功能在自己的分支上？** 使用 **每个对话一个分支**：新对话 → 带分支图标的 main 按钮 → **新分支**，然后发送第一条消息。每个对话都有自己的分支和 worktree 文件夹；如果 `.worktreeinclude` 列出了你的 `.env` 和 `node_modules`，它们也会一起复制过去。对话标题栏会显示你当前所在的分支。

**可以从 iPhone 发送照片吗？** 可以。在 Tether 的对话中，轻点消息输入框旁边的 **+** → Camera、Photos（最多 4 张）或 Paste image。照片会作为你消息的附件发送到 Mac 上的对话，因此模型能看到它们。

**它支持桌面应用吗？** 支持：设置 → 插件 → **添加插件** → `dsh-composer-plus`。已在 dsh 0.2.0-rc.2（桌面版和网页版）和 0.2.1-rc.2（网页版）上测试。

**新功能规则：** 设置 → Composer Plus 中的每个功能行都会显示一张截图。把功能 id 添加到 `client.js` 的 `SHOT_OF` 和 `index.js` 的 `SHOTS` 中，并发布 `assets/features/<id>.webp`（从临时演示 dsh 中截取，使用英文界面，大小约 60 kB 或更小）。把该功能（使用同一张图片）添加到 `docs/features.json`，然后运行 `npm run build:readme`：它会写入 `README.md` 和每个翻译版 `README.<id>.md` 的功能表格，以及 `llms.txt` 中的列表。功能没有截图时，`test/shots.test.mjs` 会失败；`test/browser-settings-shots.mjs` 会检查真实的设置页面。每次更改的完整检查清单见 [AGENTS.md](AGENTS.md)。

测试会在假的 React/DOM 上运行真实的 `client.js`，并在临时 git 仓库上运行真实的 `index.js`（Host 端）。Tether 网关测试（`test/tether-gateway.test.mjs`）使用模拟的 dsh host 和真实的 TLS 网关。iPhone 应用位于 `tether/ios` 中（见 [tether/README.md](tether/README.md) 和 [tether/AGENTS.md](tether/AGENTS.md)）。每个 Host 路由、它的请求以及 Tether 能否调用它，都列在 [docs/ROUTES.md](docs/ROUTES.md) 中。`node test/browser-history.mjs '<dsh web URL with ?token=…>'` 会在真实浏览器中，针对一个使用独立 `DSH_HOME` 的临时 `dsh web` 检查输入历史。

语言包是 `locales/<id>.json` 中的纯数据 JSON，由 `npm run build:locales` 嵌入到唯一的客户端入口中（不使用翻译服务，也不在运行时下载）。`npm test` 会检查每个语言包是否覆盖全部键、占位符和换行是否一致，以及跟随系统语言和手动覆盖时的行为。如需在本地安装的 Playwright 中进行隔离的真实应用检查：

```sh
PLAYWRIGHT=/path/to/playwright node test/browser-language.mjs /path/to/dsh/lib/bin.js
```
