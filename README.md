Codex-style quality-of-life features for the [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (dsh) desktop and web UI: a Changes panel, swipe-card feature ideas, sidebar search in message text, turn rollback with file restore, chat deletion to the Trash, the project name under the composer, project status in the sidebar, input history, a plan-mode shortcut, one-click Continue, resume running chats after a restart, queue drag-and-drop, session deeplinks, chat export as Markdown, per-chat Auto Review grants, background notifications, iPhone access with the Tether app and automatic updates.

**In one line:** a single DeepSeek Harness plugin (npm `dsh-composer-plus`, shown as **Composer Plus** in Settings → Plugins) that adds a git Changes panel, Tinder-style feature idea cards, sidebar search that also finds words in messages, ↶ turn rollback (chat only, or chat and files), Delete chat, the project name under the composer, ↑/↓ input history, a Shift+Tab `/plan` toggle, one-click ▶ Continue, Resume after restart, drag-and-drop queue reordering, Copy session link, Export as Markdown, Auto Review “Allow for this chat”, background notifications, iPhone access (Mobile connect, Tether app), 11 extra interface languages and automatic updates.

Unofficial community plugin. The update check (GitHub releases and the npm registry) makes network calls; switch off **Automatic updates** to stop them at startup. **Turkish skill pack** (on by default) downloads the turkish-anti-ai-skill from GitHub and checks it for a newer version once a day, only while **Application language** is Türkçe; switch it off in **Settings → Composer Plus** to stop these calls. **Feature ideas** calls your chat's own model only when you click **Suggest features**. **Next message prediction** (on by default) calls the model chosen in Settings (dsh's default unless you pick another) once after each finished turn, without a click. Switch it off in **Settings → Composer Plus** to stop these calls. **Complete while typing** (off by default) calls its chosen model (by default the prediction's) at each pause while you type, after you switch it on. **Improve prompt** calls a model only when you click its magic wand. **Task board** calls the new chat's model once for the tags of each task that you start on the board. With its **AI summary** setting (the default is **Fast (no AI)**), it also calls a running chat's model for a short progress note while you look at that task's progress on the board or in Tether. **Goal check** (on by default) calls a model once each time the agent marks a `/goal` complete in an automatic round. **Mobile connect** (off by default) accepts iPhone connections from your local network or tailnet only after you switch it on.

## Install

**Desktop app:** Settings → Plugins → **Add plugin** → enter `dsh-composer-plus` → **Enable now**.
You can also paste `https://github.com/furkancak1r/dsh-composer-plus` instead of the npm name.

**Web / CLI profile:**

```sh
dsh plugin --profile web add dsh-composer-plus
```

Then restart dsh. (The CLI can't install into the desktop profile; the app manages it.)

> dsh's pnpm skips versions younger than 24 hours. Right after a release, add the version: `dsh-composer-plus@1.26.0`.

| **Goal check** | <a id="feature-goalcheck"></a>Start a goal with `/goal`. When the agent marks the goal complete in an automatic round, the goal closes only after two checks. ## Settings

Every feature can be switched on or off on its own: dsh **Settings → Composer Plus**. Each row has a small screenshot: hover it for a larger preview, click it to open it full size (`Esc` closes). The **Search features** box at the top filters the page by name or description (any language, case- and accent-insensitive); `Esc` clears it. Next to it, **All**, **On** and **Off** show every feature, only the features that are on, or only the ones that are off (switch off **On/off filter** to hide them). Each row has a switch and a short description; changes apply immediately, without a restart, and are remembered on that device. The small **?** after a row's name opens the part of this README that describes that feature, in the README of dsh's interface language. Everything is on by default, except **Mobile connect**, **Resume after restart** and **Complete while typing**. dsh's Host keeps the switches of these three and of **Content search**, **Turn rollback**, **Next message prediction** and **Goal check**, so they apply to every window and survive a restart. The Host also keeps the **Model** choice of **Next message prediction**, the one of **Complete while typing** (by default **Same as Next message prediction**), the one of **Improve prompt** and the one of **Goal check** (both by default **Same as the chat's model**), and the **Time limit** of **Allow for this chat** (1 hour by default). **Content search** changes only after a dsh restart (dsh reads it at start); until then its row says **Restart dsh to apply this change.**

## Privacy and security

- **Continue:** the authenticated local endpoint resumes only the last interrupted turn, rejects stale or duplicate requests, and preserves the existing approval hooks. It does not send a new user message.
- **Resume after restart:** off until you switch it on. The Host half keeps only chat ids and start times in `$DSH_HOME/storages/dsh-composer-plus/resume.json` (owner-only permissions), and nothing leaves your machine. It continues a chat only when dsh's own log says that dsh (not you) stopped its last turn. Approvals and Auto Review apply to the continued turn as usual.

- **Changes panel:** git runs read-only on your machine, in the chat's own folder, through dsh's authenticated `/api` channel. It never commits, stages or fetches, and only shows paths git itself listed. Tree lists up to 1000 local and remote branches and shows the newest 300 commits of one branch: its first-parent line, so a merge commit stands for the commits that it brought in. It never checks out a branch. **This chat** reads the chat's own log for the files that its file tools wrote and compares them with the chat's Turn rollback snapshot in a temporary folder that is deleted at once; it writes nothing to your repository or to the snapshot store.
- **Feature ideas:** nothing runs until you click **Suggest features**. Then the Host half reads only the chat's own folder (the browser never sends a path): the names of the top-level entries, the first 6 kB of the README, AGENTS.md and the manifest (`package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, …), an outline of the rest of the README (headings, table rows, list items; at most 6 kB) and the titles of the newest commits (`git log --format=%s`, at most 6 kB), at most 28 kB in total. It skips `.env*`, key files and folders such as `node_modules`, and it reads only regular files that stay inside the folder: a symlink that points out of the folder, a FIFO or a device is skipped. This summary goes to the model that the chat uses, through dsh's own provider settings, as one request; it is not added to any chat. Nothing in the project is written. A swiped-right idea starts a new chat in plan mode, so approvals and plan review apply as usual. **Build now** starts the chat without plan mode: the model can change files at once, with the chat's usual approvals and Auto Review. Ideas saved for later (title, summary, why, effort) are kept with the project's folder path in `storages/dsh-composer-plus/later.json` under the dsh home (owner-only file); nothing goes into the project. The history of suggested ideas (title, summary, why, effort, date, started) is kept the same way in `storages/dsh-composer-plus/idea-history.json`, at most 200 per project (the oldest leave first); its titles go to the model with the next **Suggest features** of that project.
- **Content search:** no new code searches your chats: the plugin only switches on dsh's own message index (SQLite FTS5, `dsh-session-query-sqlite`) and gives it a file, `$DSH_HOME/cache/composer-plus/session-search.db` (owner-only file and folder). The file holds the text of your user and assistant messages, so it is as private as the chat logs in `$DSH_HOME/sessions`. Nothing leaves your machine. It is a copy that dsh can make again: you can delete it while dsh is closed. The switch is in `$DSH_HOME/storages/dsh-composer-plus/content-search.json`.
- **Turn rollback:** before each of your messages, the Host takes a git snapshot of the chat's folder in its own store, `$DSH_HOME/cache/composer-plus/rollback/<chat>.git` (owner-only folder). It holds copies of the files in that folder that git sees (not ignored files), so it is as private as the project. It reads your repository's objects (no copy of what git already has) and never writes your repository's index, `HEAD`, branches, tags, stash or config; the only change git makes there is a newer time stamp on object files it reuses (this delays their cleanup by `git gc`). A rollback with files writes only regular files inside the chat's folder; it skips symlinks, pipes and anything outside the folder. Nothing leaves your machine. You can delete the store while dsh is closed (rollback then works for the chat only, until new messages). **Delete chat** deletes a chat's store too. The switch is in `$DSH_HOME/storages/dsh-composer-plus/rollback.json`. A rollback with files also keeps the files as they were just before it (`refs/r/…` in the same store), for **Redo**; the rollbacks that were redone are listed in `$DSH_HOME/storages/dsh-composer-plus/redone.json` (owner-only).
- **Open GitHub issue** (Feature ideas → **Later** list): runs only when you click it. The Host half runs your own GitHub CLI (`gh issue create`) in the chat's folder, with the idea's saved title and summary (and why it matters); `gh` uses its own login and the folder's GitHub remote, so the issue goes to that repository with your account, and GitHub shows it to everyone who can see that repository. dsh removes variables named like a token from the commands it starts; when you gave `gh` a token through `GH_TOKEN` or `GITHUB_TOKEN`, the plugin passes only these to `gh`. The issue link is kept with the idea in `later.json`.
- **Report an issue** (Settings → Composer Plus → **Report an issue…**, or a chat's **…** menu → **Report a Composer Plus issue…**): nothing runs until you click. **Write draft** sends only the type and the text that you typed (not the chat, not the project) to dsh's default model, in one call. The Host adds one line with the Composer Plus, dsh and operating system versions and replaces your home folder path with `~`. **Open issue** runs your own GitHub CLI (`gh issue create --repo furkancak1r/dsh-composer-plus`) with your `gh` login, so the issue is public and shows your GitHub account. Text that looks like a key, a token or a password is refused and does not leave your Mac.
- **Chats that changed this file** (Changes, a file's "…" menu): the Host half reads the logs of the chats whose folder is in the same repository, as dsh keeps them, and answers each chat's title, the time and the first line of the request; it never opens the file itself.
- **Git branch on chat rows:** the Host half runs `git branch --show-current` (read-only) in the chat's folder when a turn starts and when it ends, and keeps only the chat id, the branch name and the time in `$DSH_HOME/storages/dsh-composer-plus/session-branches.json` (owner-only file, newest 2000 chats). The switch is in `branches.json` next to it.
- **Find in chat** runs only in the page: it reads the text that the page shows and sends nothing.
- **Export chat as Markdown:** the Host half reads only the chat's own log (the same messages that dsh shows) and gives them to the page; it reads no project file and sends nothing over the network. The Markdown goes only to your clipboard or to the file that you save.
- **Delete chat:** moves the chat's own log folders (`$DSH_HOME/sessions/<project>/<chat>`) to the Trash. It does not touch the project folder.
- **Allow for this chat:** grants are stored with the time they were given in `$DSH_HOME/storages/dsh-composer-plus/chat-grants.json` (owner-only permissions). A grant covers one exact tool in one chat, until the time limit ends (1 hour by default). If that tool can write, the grant covers any write too. Revoke it from the header chip.
- Auto Review still runs on every call; review failures are never auto-allowed.
- **Mobile connect:** off until you switch it on. While it is on, the Host half runs the Tether gateway: HTTPS on port 19390 that accepts only your Wi-Fi subnet and your tailnet (100.64.0.0/10), and a pairing page on `127.0.0.1:19391` (this Mac only). A phone needs a one-time code from the QR code (5 minutes) and your **Approve** on the Mac. The phone pins the gateway's certificate. The Mac keeps only a hash of each phone's token (30 days, renewed while used); **Remove** closes that phone's connections at once. Phones can call only an allowlist of dsh methods (chats, prompts, attachments, slash commands, approvals, questions, models, agents, goals), not settings, credentials, the file browser or the terminal. **Tailscale only** refuses every connection from the local network, also open ones. The access log keeps the newest 200 connection attempts (time, IP address, device name, allowed or refused, and why) in `access.json`; it never holds a token or a pairing code. Data: `$DSH_HOME/storages/dsh-composer-plus/mobile/` (owner-only files). Details: [tether/README.md](tether/README.md).
- **Remote computers:** off until you switch it on, on each Mac. **Let other computers open this Mac** opens a second HTTPS port (19392) on this Mac's Tailscale address only (not on the Wi-Fi, not announced with Bonjour). Another Mac needs a one-time pairing link (5 minutes), the matching certificate (pinned) and your **Approve**; this Mac keeps only a hash of its token. A paired computer gets full control of dsh on this Mac, as if you used it here: its chats, models, tools, files and terminal. Remove it in the Settings panel and its connections close at once. The Mac that opens another one keeps that computer's token in `$DSH_HOME/storages/dsh-composer-plus/computers.json` (owner-only). It opens a relay on `127.0.0.1` for each computer that you pick: the page gets a one-time link (60 seconds), and the relay accepts only its own page (its address, no other site). The other Mac's page in this window can read the names and states of this Mac's computers (no address, no token) and can switch this window between them; it cannot add, rename or remove a computer or change this Mac's settings.
- **Updates:** the Host half asks `api.github.com` for the latest release and `registry.npmjs.org` for that exact version; nothing about you or your chats is sent. Installation uses dsh's plugin manager (`pnpm add dsh-composer-plus@<version>`; when dsh 0.2.1 refuses that for an installed plugin, `pnpm add https://registry.npmjs.org/dsh-composer-plus/-/dsh-composer-plus-<version>.tgz`, and the profile then lists that URL as the plugin's source), so dsh's own registry, script and version-compatibility checks apply. Pre-release tags and older versions are never installed.
- **Turkish skill pack:** on by default, and it works only while the app language is Türkçe: the browser tells the Host dsh's UI language. Then, at most once a day, the Host asks `api.github.com` for the newest commit of `yucezerey/turkish-anti-ai-skill` and its file list, and downloads the changed Markdown files from `raw.githubusercontent.com`. GitHub sees your IP address, as with each update check; nothing about you or your chats is sent. Only regular `.md` files of the `skills/turkish-anti-ai-skill/` folder are kept (at most 20 files and 1 MB), and each file must match its id in GitHub's file list. The copy is in `$DSH_HOME/cache/composer-plus/turkish-skill/<commit>` (owner-only) and goes into dsh's skill list; no script of the pack runs. The switch and the last reported language are in `$DSH_HOME/storages/dsh-composer-plus/turkish-skill.json`. Switching it off removes the skill and deletes the copy.
- **Usage count:** the Host half asks GitHub for two small files of the release of the installed version (`github.com/furkancak1r/dsh-composer-plus/releases/download/v<version>/<file>`): `active.txt` once a day, and `installed.txt` only once for each dsh home. GitHub counts these requests per file, so the owner sees only how many copies of each version asked for `active.txt` that day, and how many copies asked for `installed.txt` in total (the number of copies). The request has no id, cookie or data about you or your chats; GitHub sees your IP address, as with each update check. The day of the last `active.txt` request is kept in `$DSH_HOME/storages/dsh-composer-plus/active.json`, and the mark that `installed.txt` was counted in `$DSH_HOME/storages/dsh-composer-plus/installed.json`. A git checkout of this repository and a renamed copy send nothing. There is no switch for it.
- **Next message prediction:** on by default; switch it off in **Settings → Composer Plus** to stop these model calls. After each finished turn, the Host half sends the chat's own user messages and the agent's text replies (no tool output, no hidden context, no reasoning), at most about 6,000 characters (the newest part), to the chosen model (dsh's default unless you pick another). It goes through dsh's own provider settings, as one request. Nothing is saved in the chat: the guess is not added to the chat history. The switch and the model choice are in `$DSH_HOME/storages/dsh-composer-plus/predict.json` (owner-only file).
- **Complete while typing:** off until you switch it on. While it is on, at each pause while you type, the Host half sends the text that you typed so far and the chat's own user messages and agent text replies (no tool output, no hidden context, no reasoning), at most about 3,000 characters of chat, to the model chosen under **Complete while typing** (by default the model of **Next message prediction**). A newer pause stops the older request. Nothing is saved in the chat. The switch is in `$DSH_HOME/storages/dsh-composer-plus/complete.json` (owner-only file).
- **Improve prompt:** nothing runs until you click the magic wand. Then the Host half sends your draft, the chat's own user messages and agent text replies (no tool output, no hidden context, no reasoning, no rolled-back messages; at most about 6,000 characters, the newest part), the same project summary as **Feature ideas** (with the same file rules: no `.env*` or key files, no symlink out of the folder, no FIFO), the paths that `git status` lists as changed and up to 30 tracked or untracked (not ignored) paths whose names share words with your draft, to the model chosen under **Improve prompt** (by default the chat's own model), as one request. File contents other than that summary are not sent. Nothing is written to the chat or the project: the answer only replaces your draft in the composer, and you decide whether to send it. The model choice is in `$DSH_HOME/storages/dsh-composer-plus/improve.json` (owner-only file).
- **Goal check:** it runs only when the agent marks a `/goal` complete in an automatic round (or when you click **Run now**). The Host half runs the test command in the chat's folder with the chat's sandbox mode (as dsh's own `bash` tool: the same file-access policy; when that sandbox cannot start, the test does not run and the check fails). It reads only `package.json`, `Makefile`, `Cargo.toml`, `go.mod`, `pyproject.toml` and `pytest.ini` to find the command, as regular files inside the folder (no symlink out of it, no FIFO). Then it sends the goal, the chat since the goal started (your messages, the agent's replies, tool calls cut to 1,000 characters and the last 2,000 characters of each tool result; no reasoning, no rolled-back steps; at most about 60,000 characters, the newest part), `git status --short` and the end of the test output to the model chosen under **Goal check** (by default the chat's own model), as one request with no tools. Tool output can contain what the agent read, so this request can hold parts of your files, as the chat itself does. Nothing is written to the chat or the project. Your test command, the limits, the last result (with the end of its output) and the model choice are in `$DSH_HOME/storages/dsh-composer-plus/goal-check.json` (owner-only file, newest 500 chats).
- **Continue in a new chat:** nothing runs until you click it. Then the Host half sends the chat (as Goal check reads it: no reasoning, no rolled-back steps) to the chat's own model and shows the note; only **Start new chat** makes a new chat. Nothing is written to the project.
- **Context breakdown:** reads only the chat log on the Host; no model call, no project file.
- **Task board:** the board shows dsh's own chats from dsh's own lists in this window; it adds no chat data of its own. **New task** opens dsh's own new chat, and you write the first message in dsh's composer, so approvals, the sandbox and the chat's model apply as usual. The Host half keeps that chat's first message as the card's prompt and sends it (its first 4,000 characters, nothing else) to that chat's model in one more request, with no tools, for up to 3 tags. The prompt, the tags and the start time of each task are kept in `$DSH_HOME/storages/dsh-composer-plus/board-chats.json` (owner-only file, the newest 2,000), with the ids of the chats that you took off the board with **×** or **Clear all** (the newest 5,000); the switch is in `board-switch.json` next to it. Nothing is written to a project folder. **Answer** sends your answer to dsh's own pending request, the same way the chat's own card does. The old task list of earlier versions (`board.json`) stays on disk as it was and is not read. **Progress on hover** reads the chat's log on this Mac. With **Fast (no AI)** (the default), nothing is sent. With **AI summary**, while a running card's progress box shows (or while Tether's board is open, for up to 8 running cards), the Host half sends that chat's newest part (at most about 6,000 characters: your messages, the agent's text replies, its tool calls and the end of their results; no reasoning, no rolled-back messages) to the chat's model, as one request with no tools. It sends again only after the chat moved on, at most once every 20 seconds per chat. The note is kept only in memory; the setting is in `$DSH_HOME/storages/dsh-composer-plus/board-progress.json` (owner-only file).
- **Assistant:** the assistant chat is an ordinary dsh chat in `~/Assistant`; its model calls go to dsh's default model as in any chat. Its tools read your other chats' logs on this Mac (titles, projects, status, and with chat_read their newest messages) and give them to that model only when it calls a tool. Sending, starting, stopping and archiving a chat each wait for your approval. The chat id is kept in `$DSH_HOME/storages/dsh-composer-plus/assistant.json` and the switch in `assistant-switch.json` (owner-only files). Reminders and automations are dsh's own scheduled tasks. Nothing leaves this Mac except the model requests and the web searches that the chat makes. The assistant-as-a-bot switches keep their state in `assistant-free.json` and `assistant-notify.json` (owner-only files). **Assistant news from chats** puts a short line about another chat (its title, project and at most 300 characters of its last reply or error) into the assistant chat, so that text goes to the assistant's model too; the news waits in memory only.
- **Protected files:** the list and the switch are in `$DSH_HOME/storages/dsh-composer-plus/protected-files.json` (owner-only file). The check reads only the path of each file tool call (and its real path), never the file.
- **Blocked commands:** the rules and the switch are in `$DSH_HOME/storages/dsh-composer-plus/blocked-commands.json` (owner-only file). The check reads only the command text of each `bash` and `pwsh` call; it runs nothing and sends nothing.
- **Secret input:** the value goes from the card (or from Tether, through the gateway, which does not log request bodies) to the Host only in the answer request. The Host writes it to `$DSH_HOME/storages/dsh-composer-plus/secrets/<random name>` (folder 0700, file 0600); nothing goes into the project, the chat log or the tool result. The Host keeps the value in memory to replace it with `[secret]` in later tool results of that chat. The file and that copy go when the chat's turn ends and at dsh start. The switch is in `secrets.json` next to it. A command that the agent runs with the file can send the value where that command sends it: that is the purpose.
- **Project memory:** off until you switch it on. While it is on, after each finished turn of a top-level chat, the Host half sends the chat's own new messages since the last review (your messages and the agent's text replies; no tool output, no reasoning, no hidden context, no rolled-back messages; a fork's copy of its parent is left out; at most about 16,000 characters) and the saved notes to the chat's own model, as one request with no tools. The notes are Markdown files under `$DSH_HOME/storages/dsh-composer-plus/memory/` (owner-only files): `projects/<id>/` for each project folder (`<id>` is a hash of the folder's real path; `project.json` names the folder), `global/`, `journal.jsonl` (every change with the line before and after) and `reviewed.json` (how far each chat was read). Nothing is written to the project folder. With a **Memory folder** (`memory-folder.json` next to it), the notes are only in that folder (`Genel/`, `Projeler/<project>/` with `project.json`), and anything that syncs or backs up that folder (iCloud, Git, Obsidian Sync) gets them too; `journal.jsonl`, `reviewed.json` and the history stay under the dsh home. Notes that look like a key, a token, a password or an ID number (also an 11-digit Turkish ID number with right check digits) are refused. The notes of a project go into the system prompt of each new chat in that folder, so they reach the model with every request of that chat. The switch is in `memory.json` next to it. **Open memory** sends nothing until you click **Preview changes**; then it sends the notes it shows and your text to dsh's default model, as one request with no tools. Its changes are written only on **Apply**, with `editor` in the journal. Tether reads and changes the notes through the same route. **Memory version history** (on by default) keeps a copy of the memory files before each save in `memory/history/` next to them (owner-only files, the newest 50 per memory); it sends nothing to a model. **Export memory to AGENTS.md** sends nothing to a model and writes only when you click **Write AGENTS.md**: it reads and writes `AGENTS.md` in the memory's own project folder (only a regular file inside it, never through a symlink that leaves it), and changes only its marked section. **Find stale memory notes** sends nothing to a model and writes nothing: it checks paths inside the project folder with realpath (no file is read), reads `package.json` only as a regular file inside the folder, and runs one `git for-each-ref` there. **Do not use memory in this chat** keeps each chat that you switch off in `memory-chats.json` next to it (owner-only, the newest 500); such a chat sends no memory to its model. **Suggest memory notes from a chat** sends nothing until you click **Suggest for memory**; then it sends the saved notes of the chat's project and the global notes, and the chat's own messages and text replies (no tool output, no rolled-back messages; a fork's copy of its parent is left out; at most about 24,000 characters), to the chat's own model, as one request with no tools. A suggestion is saved only on **Accept**.
- **Backup:** nothing leaves your machine. Archives go to `~/Desktop/dsh-backups` (owner-only files). Secrets are not in an archive: credential files (`.credentials.yaml`, `.env`), key files (`.pem`, `.key`, `.p12`, `.pfx`) and the values of token, secret, password and API key settings in the yml files are masked; their real copies stay in `composer-plus-vault/<archive>/` in the same folder (owner-only), on this computer only. **For another computer** copies no vault: enter those secrets again there. Your chat logs, settings and the rest of the dsh home are in the archive as they are: keep the folder private, as `$DSH_HOME` itself. The backup reads files with `O_NOFOLLOW | O_NONBLOCK`; a symbolic link is stored as a link (never followed) and a FIFO or device is skipped. The automatic backup switch and settings are in `$DSH_HOME/storages/dsh-composer-plus/auto-backup.json`, the rescue console switch in `rescue-console.json`, and while dsh runs, `running/host-<pid>.json` names each dsh process (the rescue console reads them to refuse a restore).
- **Rescue console:** a terminal menu; it opens no network port. A restore writes only into a new folder next to the dsh home (files with `O_EXCL | O_NOFOLLOW`, symbolic links last and never followed) and refuses an archive with an unsafe name (`..`, an absolute path), a device or FIFO, more than one top folder or an entry below a link.

## Troubleshooting

- **No notifications on macOS:** System Settings → Notifications → DeepSeek Harness → allow. Choose Alerts to keep them on screen.
- **▶, queue grips, project status, the recent projects option, Collapse all projects, Copy path, the project search box, the next message prediction, the completion while typing, Allow for this chat or right-click missing after a dsh update:** these attach to dsh's current HTML because dsh has no slot for them yet. If dsh changes that markup they hide themselves; nothing else breaks. Please open an [issue](https://github.com/furkancak1r/dsh-composer-plus/issues).
- **"Update failed" or "not installed from npm":** a copy linked from a local folder or renamed can't update itself; reinstall `dsh-composer-plus` from Settings → Plugins. Otherwise the message shows the first line of pnpm's error; **Check for updates** retries.
- **Mobile connect says the gateway is not running:** "no IPv4 address on en0" means this Mac has no Wi-Fi/Ethernet address; "EADDRINUSE" means another dsh (or app) uses port 19390 or 19391. Only one dsh can run Mobile connect at a time.
- **Mobile connect, Resume after restart or Content search says "Restart dsh":** the plugin was updated while dsh was running (or, for Content search, you changed the switch); the new state loads after a restart.
- **The search finds only titles:** Content search is off, dsh has not restarted since you switched it on or installed the plugin, or the word is only in a tool output (see Limits).
- **No ↶ button on my messages:** Turn rollback is off, the chat is a subagent chat, or dsh-rewind-plugin is installed (use its ↶ button). After an update, restart dsh.
- **Chat and files is greyed out:** the project is not a git repository, there is no snapshot from before that message (the message is older than the plugin, or one of the 50 newest snapshots replaced it), or no file changed.
- **Delete says another dsh has this chat open:** a second dsh on the same dsh home holds the chat's lock. Close that window or dsh, then delete again. The chat stays archived meanwhile.
- **My iPhone cannot connect after I switched on Tailscale only:** Tailscale must be on in both the Mac and the iPhone. The Mobile connect panel warns when it is off on the Mac. The access log shows each refused attempt with its reason.
- **A chat did not continue after a restart:** Resume after restart was off when dsh quit, you stopped that turn yourself, the turn had ended (done or failed), the chat was archived, or more than 20 chats were running (the newest 20 continue).
- **The queue is empty after a restart:** dsh itself empties the queue when it quits. Resume after restart puts it back only in a chat that it continues; in other chats, send the messages again. A message that you removed just before the quit can come back: remove it again.
- **Open GitHub issue says "gh could not open the issue":** the message is `gh`'s own first line. Run `gh auth status` in a terminal and log in with `gh auth login`; the chat's folder must have a GitHub remote (`git remote -v`). "not installed or not on the PATH of dsh" means dsh did not find `gh`: install it, or start dsh from a terminal where `gh` works.
- **Report an issue says "gh could not open the issue":** the message is `gh`'s own first line. Run `gh auth status` in a terminal and log in with `gh auth login`. Or click **Open on GitHub instead**: GitHub's own new issue page opens with the draft filled in, and you submit it there.
- **No branch pill on a chat row:** the sidebar is not in “In one list” (in “WorkSpace” and “Workspace Tree”, no chat row shows a pill), the chat had no turn since you installed this version, its folder is not a git repository, or **Git branch on chat rows** is off. After an update, restart dsh (the Host half records the branch).
- **Goal check says the test exited with code 127 or "not found":** dsh started from the Finder or the Dock can have a shorter PATH than your terminal, so it does not find `npm`, `pnpm` or `cargo`. Start dsh from a terminal, or set your own test command with the full path under **Goal check** → **Edit**. **Run now** shows the result at once.
- **The goal does not close and the agent keeps working:** **Goal check** found a failing test or missing work; the row under the goal shows why (hover the result for the details). Fix the cause or the test command, or complete the goal yourself with `/goal` or the goal bar (that is not checked).
- **Install fails right after a release:** add the version (`dsh-composer-plus@1.26.0`), see the install note above.
- **Back up now says "another backup action is running":** an action runs in another dsh window or in the rescue console (they share a lock file, `.composer-plus.lock`, in the backup folder). Wait for it. If no action runs, the lock of a closed process is taken over at the next click.
- **The rescue console says "dsh is running":** quit dsh first. If dsh is really closed, the file named in the message is left from a crash: remove it and try again.
- **After a restore, dsh does not start or a plugin is missing:** the plugin packages of a profile must be installed again. The rescue console offers it after a restore; or run `pnpm install` in each folder under `$DSH_HOME/profiles/` that it lists. Secrets that were not in the vault (another computer) must be entered again: the console lists them.

## Limits

- Message-free Continue relies on dsh’s `agent/pre-step` → `agent/request` lifecycle. Recheck compatibility when upgrading dsh.
- **Feature ideas** keeps the cards in memory for each chat until dsh or the page reloads; then **Suggest features** asks the model again. The cards come in the UI language that dsh has when you click; after you change the language, cards already on the stack keep theirs and **More ideas** uses the new one. The model sees only the short project summary, not the code, so an idea can repeat something the project already has: skip it. The new chat runs in plan mode only when the profile has dsh's `/plan` command; otherwise the idea goes as an ordinary first message. The **Later** list belongs to the chat's folder path: the same folder opened through a symlink has its own list. It keeps at most 50 ideas per project (remove one to add more) and the same title only once. Dragging a card decides left or right only; use **↓** to save it and **▶** to build it now. A repeat is found by its title only: the model can still suggest an earlier idea under a new name; skip it. When the model answers only earlier ideas, nothing new shows: click again. A narrow focus topic makes that more likely; use a wider topic or clear it. The focus topic stays in the field for each chat until dsh or the page reloads.
- **Export chat as Markdown** has only your own messages and the assistant's text replies: tool calls and their output, thinking, images (a `[image]` line marks them), hidden context and messages that Turn rollback or dsh-rewind-plugin took out are left out. Replies of one turn join into one section. At most about 4 million characters go into one export; a longer chat gets its first part and a note.
- **Resume after restart** continues the turn; it does not replay it. A tool call that was running at the quit ends with dsh's “outcome unknown” result, and the model is told not to repeat finished work, but a command that is not safe to run twice can run again. Subagents, approvals and questions that were open are not restored: their parent chat continues and asks again. At most 20 chats continue at one start.
- **Resume after restart** and the queue: dsh empties a chat's queue when it quits. The plugin puts your queued messages back from the chat's log, with their order, edits, images and files; they run after the continued turn. Only chats that continue get their queue back (switch on, a quit while the turn ran). dsh logs your own removal of the last queued messages the same way: if you remove them and dsh quits before the next step starts, they come back.

- **Content search** is dsh's own search, so it has dsh's limits. It searches only user and assistant messages: not tool output (commands, file contents, results), not reasoning, and it has no filter for user, assistant or tool messages. It matches whole words, not parts of a word (`deploy` does not find `deployment`); letters with accents match without them (`seker` finds `şeker`). One row per chat, with dsh's 240-character snippet, at most 20 rows.
- **Content search** cost, measured on a copy of 247 real chat logs (159 MB, dsh 0.2.1-rc.2, Apple Silicon, 32 GB): the first search after a start builds the index in about 15 s. During that time dsh's Host answers nothing for about 7 s, so other chats stop streaming for that moment (the page itself does not freeze). The Host's memory grows by about 1.1 GB at the peak; one minute later it is still about 0.5–0.6 GB above the start, until dsh quits. The index file is about 165 MB. Later searches take about 0.5 s. After a restart, the first search takes about 1 s (only new or changed chats are added) and adds about 70 MB. Switch it off if your computer has little memory.
- **Content search** applies only after a dsh restart, and the index file is shared by every dsh that uses the same dsh home: run only one such dsh at a time (dsh allows one owner per index file).
- **Turn rollback** puts files back only in a git repository, and only in the chat's folder. It keeps the 50 newest snapshots per chat. - **Continue in a new chat** sends the chat (messages, tool calls and the end of each tool result, at most about 60,000 characters, the newest part) to the chat's own model. The note can miss a decision or a file: read it before you start. The new chat knows only the note and the linked chat (dsh attaches the old chat as read-only context); its model context starts small, the old chat stays as it is. One note or start per chat at a time.
- **Context breakdown** shows estimates with dsh's own rule (about 4 characters per token), the same rule as dsh's context ring; the model's own count can differ. Tool definitions are the ones of the newest request. It shows the context as the chat log has it; a turn that runs now appears after its next step.
- **Planned steps** saves tokens only when the model plans: while it is on, each request carries the `plan_next_steps` tool and a short instruction (about 500 tokens), also in chats where the model never plans. A condition proves only what it says (for example: the build exit code was 0), not that the work is right. `ok` reads dsh's own result marks (`[exit code: N]`, timeouts, sandbox denials); a command that fails without a non-zero exit code passes. Steps run one at a time; two steps that are ready at the same time go back to the model. The step's message is stored as an assistant message of the chat's model (dsh has no mark for a message that a plugin wrote), so its text says that Composer Plus ran it. Not in Tether.
- **Turkish skill pack** installs a third-party skill: its rules come from the author's GitHub repository, not from Composer Plus, and a new version is used from the next daily check without a review by us. The check proves that the files are the ones GitHub lists for that commit, not that the rules are good. The model decides when to load the skill (the user can also call it by name); the rules apply to Turkish texts only. The Host uses the language that a browser reported last: when two browsers use different languages, the newest one wins. GitHub allows 60 API calls per hour without a login; a refused check keeps the installed copy and shows the reason in Settings.
- **Untangle codebase** ships a fixed copy of the skill (caldoai/skills, commit f3cf477): a change upstream comes only with a new Composer Plus version. The skill runs a long goal that can change many files, and its subagents and checks use many tokens. Where the project has no tests, it can change behavior without notice: start it on a branch and read the diff before you merge. A skill with the same name in the project, in a custom skill folder or in `~/.dsh/skills` replaces it. While the switch is off, `/untangle-codebase` goes to the model as plain text.
- **Task board** shows the chats that dsh lists in this window: a chat outside a project shows only in **All projects**, and a Branch per chat folder (`<project>/.worktrees/<name>`) counts as its project. A card's column is the chat's live state, so cards cannot be dragged: a chat goes to **Done** when its turn ends, also after an error or a stop, and back to **Doing** when it runs again. The green dot is dsh's own done dot, which dsh keeps only in this window: after a reload, finished chats show without it. **Done** shows the newest 50 chats (**Show N older** shows the rest). **Search projects** finds a project by its name only, not by its folder path. **Active in the last 2 hours** hides a project when each of its chats is older than 2 hours, idle and read; the board still shows the project that you picked. **New task** remembers only the newest new chat of this window: when you open another chat before the first message, that chat stays at the top of **Doing** as **New task** until you write in it, but the board comes back by itself only for the newest one. After a reload, a new chat without a message is not on the board (dsh keeps it as its empty New session). The tags come from one model call per task, from its first message: they can be wrong, and a chat that you did not start on the board has none. The title is dsh's own chat title (dsh's title service, with the chat's model); until it comes, the card shows the first line of the first message. **×** and **Clear all** take cards off the board only: no chat is deleted. **Undo** shows for 8 seconds only, in this window; later, **Removed (N)** → **Put back** brings a card back, and a chat that runs again comes back by itself. **Clear all** asks first and takes the read finished cards of the shown project (all projects with **All projects**), also the ones behind **Show N older**; an unread (green) card stays. dsh keeps its green dot only in this window, so after a reload Clear all can take a card whose answer you did not read. The list is kept on this Mac for every window and for Tether; when it has 5,000 chats, the oldest come back. **Answer** answers only the newest request of the chat: when the chat answered it elsewhere (another window, Tether, Auto Review) or asks something new, the panel says so and sends nothing. Earlier versions had a task list with comments and agent tools; they are gone, and the old `board.json` is not shown. The idea and the look come from [Kanzo](https://github.com/emanuele-em/kanzo) by emanuele-em (AGPL-3.0); Composer Plus uses no code from it. `Cmd+Shift+K` is a dsh shortcut: in a browser on Linux it has no default key (set one on dsh's Keyboard shortcuts page), and a browser extension or another app can take it first. A card leaves **Done** when dsh's own green dot goes (you opened the chat) or, for a chat that finished behind the board while it was the open chat, when that chat shows with no panel over it. This read state lives only in this dsh window, as dsh's own dots: after a reload or in another window every finished chat is read, so it is in **Recently finished**.
- **Assistant** has one chat for all windows of this Mac. It runs with the workspace-write permission mode: it writes files only in `~/Assistant`, and a command outside it asks first. When you switch the chat to a mode without approvals (Full access), dsh rejects each approval, so the assistant cannot send, start, stop or archive a chat. The approval card guards the six tools only: a shell command of the assistant can still reach the network, as in any chat with that mode. On dsh 0.2.0 and 0.2.1, dsh's schedule tools see only the reminders of the assistant chat itself, not the automations of other chats; from dsh 0.2.2, they list and change every scheduled task. chats_list leaves out archived, blank and subagent chats, and the assistant chat itself; "waiting for you" means an open approval, question or plan review in a running chat. chat_read gives the user's messages and the agent's replies (no tool output), at most 50 messages and about 24,000 characters. chat_archive refuses a chat that still runs or has active reminders. A model can still be misled by text that it reads: the approval card is the last check, so read it before you click **Allow once**. Parallel topics use dsh's subagent tool: a profile or permission mode without it keeps the old way (one topic at a time, the next message waits in the queue or steers the running turn). The model decides what counts as a long task, so a short question can still take a turn. Each topic's subagent runs with its own tokens; when dsh restarts, a running topic stops (its result does not come back). A result comes back as a new turn of the assistant chat, so it waits while you type in the middle of a turn.
- **Assistant apart from chats** and **Assistant messages only** hide dsh's own rows with a style rule, found by dsh's sidebar and chat markup (`data-row-key`, `data-chat-flow-kind`): when a dsh update changes that markup, the assistant chat shows in the list again, or its work steps show again. The rows are hidden, not removed: dsh's keyboard navigation in the sidebar can still reach a hidden row. **Assistant always free** refuses each tool call of the assistant chat that is not one of its short tools; the model then gives the step to a subagent, but it can try the refused call first, which costs one model step. While an approval card waits for you, the assistant chat still counts as busy. When its newest request has no subagent tool (a permission mode or profile without it), the rule does nothing. A message that you send while it works goes into its turn at the next step, so the queue under the input shows it only for a moment; while a question card waits, the same text answers every question of that card. A subagent's "finished" notice starts no second turn only on dsh 0.2.2 or later (older dsh does not mark that the subagent sent you its result). **Assistant news from chats** starts a model turn of the assistant chat for each batch of news, so it uses tokens; with **Mobile connect (iPhone)** on, your phone can get two notifications for one finished chat (the chat's own and the assistant's). News that waits is lost when dsh restarts. It sees only chats on this Mac.
- **Assistant status panel** shows its panel inside dsh's chat body, found by dsh's chat markup (`data-conversation-content`): when a dsh update changes that mark, the panel does not show (the list and the agent tools still work). In a window narrower than 1000 px, the panel covers the right edge of the chat: click its title to fold it. The panel reads the list again every 5 seconds while the assistant works, at the end of each turn and after your click, so an item that the assistant adds shows after a short delay.
- **Send after Stop goes first** works only after you stop the chat (or after a turn that failed, or when you open a chat that still has a queue): a message that you send while a turn runs still waits at the end of the queue. It moves only past your own queued messages: when a goal round or a question reply waits in the queue, dsh's own order stays. It reads a part of dsh that is not a public API (whether the stopped turn still ends); if a dsh update renames it, the message moves only after that turn has ended. Subagent chats keep dsh's own order.
- **Project memory** belongs to the chat's first folder (dsh's project folder): a chat that changes its folder with `cd` keeps its first project's memory, and the same folder opened through another path to the same files shares it. A chat freezes its memory section when it starts, so a note saved later shows from the next chat (`memory_recall` finds it at once). The review keeps only what the model decides to keep: it can miss a fact or keep a wrong one; check them in **Open memory** and change them there, or edit the files by hand while dsh is closed. **Open memory** sends the notes of the selected project and the global notes (all projects when you select All notes; at most about 60,000 characters, the rest is counted and cannot change in that request) and your text to dsh's default model, not to the chat's model. A preview is kept on the Mac for 30 minutes and until dsh restarts; when a review or the agent changes the notes in between, **Apply** refuses and you preview again. **Apply** saves all the changes of a preview or none: when one change cannot be saved (for example, the note that it changes is gone), the notes stay as they were and the reason shows. Each finished turn with a message from you costs one model call; a failed call reads the same messages again after the next turn. Subagent chats are not reviewed, but they get the notes as context. The review also reads your answers on question cards. A failed review or a note that it cannot save leaves a line with `"actor":"review-error"` in `journal.jsonl`. The idea and the file format come from [DS Bot](https://github.com/Fei2411/DS-Bot) (Apache-2.0); Composer Plus uses no code from it, and it never reads or writes DS Bot's own memory.
- **Memory folder** takes effect at the next dsh start. The first start with a folder that has no `Genel` or `Projeler` copies every note there once, all or none; the old notes under the dsh home stay, and later changes go only to the folder. When that copy fails, Project memory stays off until the next start (so no note goes to the wrong place), and the reason is in dsh's log. A note has no size limit and a memory has no topic limit; each chat's prompt gets the newest entries of each MEMORY.md, up to 8,000 characters, and the agent finds the others with `memory_recall`. A note that you write by hand must be a `- ` line outside `## Index`, and a topic file name must be lower case with `-` instead of spaces (`health-records.md`); other files in the folder are not read. A symlink in place of the folder, `Genel` or `Projeler` is refused, and a symlinked note file reads as empty.
- **Memory version history** keeps the newest 50 versions of each memory (each project and the global memory); older ones go. A version holds the whole memory of that project, not one note. **Restore** puts back every file of that version (topics included) and refuses when the memory changed after you opened the version; the memory before the restore becomes a new version, so you can undo it. While the switch is off, no new version is kept and **Restore** refuses; the kept versions stay. A version from before this feature does not exist: the history starts with the first save after you install it.
- **Export memory to AGENTS.md** writes only the notes of one project memory; global notes, sources and dates stay out. The next export replaces the whole marked section, so a change that you make by hand inside it is lost (the diff shows it first); text outside the markers stays. When the markers are broken (one is missing or they are there twice), the export refuses until you fix them. AGENTS.md larger than 512 kB, a symlink that leaves the project folder, and anything but a regular file are refused. When AGENTS.md or the notes change after the preview, **Write AGENTS.md** refuses and you export again.
- **Memory note source link** works for notes saved after you install this version: an older note names only its chat (or nothing), so **Source** opens only the chat or does not show. When the message is gone (a rollback withdrew it, or the chat was deleted), the chat opens and a notice says that the message is not there.
- **Copy memory to another project** copies at most 100 notes at a time, only into a project that dsh lists (it reads dsh's own project list; no path comes from the window). Each copy is independent: a later change to a note in one project does not change the copy. When one ticked note cannot be copied (it is gone from the source, or a file cannot be written), nothing is copied. A note whose text and topic are already in the target is skipped, and the count says how many.
- **Find stale memory notes** finds only what a note writes in a form it knows: a path in a code span (`src/cart.ts`), an npm script after `npm run` (or `npm test`, `pnpm lint`), a branch name in a code span next to the word "branch". A path that leaves the project folder is not reported; a script is checked only when the project has a `package.json`, a branch only in a git repository. It checks at most 200 things at a time. A warning means "not found now", not "wrong": a file that a build makes later is reported too.
- **Do not use memory in this chat** acts from the chat's next model request: a request that already runs keeps what it has. Switching it in a running chat changes its system prompt once, so the model provider's cache cannot be used for that one request. A subagent follows its root chat. The review does not read the messages that a chat gets while its memory is off, also when you switch it on again later. On dsh 0.2.0 the New chat screen has no place for the button: it shows in the chat header after the first message.
- **Suggest memory notes from a chat** shows at most 10 suggestions and keeps them for 30 minutes and until dsh restarts; after that, accept asks you to suggest again. A long chat sends its newest messages: the oldest agent replies go first. A suggestion can be wrong: read it before you accept it, and use **Open memory** to change a note later. A rejected suggestion can come again at the next click.
- **Backup** keeps one fixed folder, `~/Desktop/dsh-backups` (dsh-backup's default, so its archives stay usable); there is no setting for another folder. An archive is about as large as the dsh home without `cache/` and `dsh-runtimes/` (measured: 1.6 GB of files gave an 830 MB archive in about 30 s on Apple Silicon; dsh stayed responsive). A file that changes while it is read is stored as it was when the backup opened it, so an open chat's log can end in a cut-off record, which dsh repairs at its next write. Masking finds a secret in a yml file by its key name on one line (`token:`, `apiKey:`, …); a secret in a flow map (`{token: x}`), in a list under such a key, in a JSON file (for example an MCP server's `apiKey` in a `.json` file) or under another name stays in the archive. dsh-backup's typed archives (`dsh-t-…`) are not listed. **For another computer** copies the archive (a clone on APFS: no extra space); the vault does not go with it. **Back up now** deletes no backup. An automatic backup keeps the newest backups that Composer Plus made (the **Keep** setting of **Automatic backup**) and deletes its older ones; snapshots before an upgrade are counted apart (the newest 2 stay). Archives of dsh-backup are never deleted: remove them with **Delete**. While dsh-backup is still installed, it counts the Composer Plus archives in its own keep count and can delete them.
- **Restore** runs only in the rescue console, while dsh is closed: it replaces the whole dsh home. The old one stays next to it as `.dsh.pre-restore-<time>` until you remove it, so the disk needs room for both. Chats keep their project paths: on another computer, a project at another path shows as missing until you add it again. Symbolic links that point outside the dsh home (for example skills linked from another folder) come back as links; their targets must exist on that computer.
- **Session log check** reads the newest log of each chat with dsh's own rules for what opens: a row that is not JSON or is out of order counts as damage only when a turn end comes after it (else dsh opens the chat without the rows from there, so it is not listed). It does not check a log's events against dsh's own event rules, so a log that it calls healthy can still fail to open after a dsh upgrade. A repair takes the copy from a backup: the messages after that backup are lost from that chat (the damaged file stays next to it). A chat that is open in this dsh is not repaired in Settings: dsh holds it.
- **Automatic backup** runs only while dsh runs: a backup that was due while dsh was closed runs about 45 s after the next start. The snapshot for a new version is taken after that start, not before the update.
- **Remember window size** works only in the desktop app. At each start, dsh shows its window at 1280 × 820 first; the window moves to the saved size when the plugin loads. A page has no event for a window move, so the plugin reads the window once a second: a change in the last 2 seconds before dsh quits is not saved. The size is kept per computer, in the app's own storage.
- **Usage count:** it counts copies, not people: each dsh home is one copy. The unique count (`installed.txt`) counts only copies that update to the first version with this file or a later one; a copy that stays on an older version is not counted. A copy whose `storages` folder is deleted is counted again. GitHub can count the requests from one IP address (for example, many computers behind one NAT router) in about 10 minutes as one.
- Built-in support is requested upstream: queue `move` in [#773](https://github.com/deepseek-ai/deepseek-harness/discussions/773), a Continue state in [#9269](https://github.com/deepseek-ai/deepseek-harness/discussions/9269).

## FAQ

**How do I add a Changes / git diff panel to DeepSeek Harness?** Install `dsh-composer-plus`, then right sidebar → `+` → **Changes**.

**Can dsh suggest features for my project, like swiping Tinder cards?** Yes: right sidebar → `+` → **Feature ideas** → **Suggest features**. Swipe right to start a new chat that plans the feature, click **▶ Build now** to start a chat that builds it at once without a plan, swipe left to skip.

**Can the dsh sidebar search find a chat by a word in its messages, not only its title?** Yes, with **Content search** (on by default): restart dsh once after you install the plugin, then use the magnifier next to **Workspaces**. Matching chats show the text around the word.

**Can I undo a turn and edit my prompt, like in OpenCode or Claude Code?** Yes, with **Turn rollback**: click **↶** on the message, choose **Chat and files**, edit the text that comes back in the composer and send it.

**Can I delete a chat instead of archiving it?** Yes, with **Delete chat**: **…** → **Delete…**. The history goes to the Trash, so a mistake can be undone.

**How do I see which project a chat belongs to?** Look at the row under the composer: with **Project name in the composer** (on by default) it starts with the project name. Hover it for the folder path.

**How do I get ↑/↓ message history in the dsh composer?** Install this plugin; in an empty composer `↑` / `↓` walk through messages you sent.

**How do I continue a stopped or failed dsh turn without typing "continue"?** With this plugin the Send button becomes **▶** after a stopped, failed or cut-off turn; one click resumes it.

**Does dsh continue running chats after I quit and open it again?** Not by itself: dsh marks such a turn as interrupted and waits (a goal also waits for `/goal resume`). Switch on **Settings → Composer Plus → Resume after restart**: the chats that were working when dsh quit then continue by themselves at the next start.

**Which model writes the prediction?** The model that you choose in **Settings → Composer Plus → Next message prediction → Model**. The list is dsh's own model list. **dsh default** follows dsh's default model. When dsh no longer lists the chosen model, the prediction uses the default. **Complete while typing** has its own **Model** menu: **Same as Next message prediction** (the default) follows the prediction's model; another choice is used for completions only. When dsh no longer lists that model, completions use the prediction's model.

**Can dsh improve my prompt before I send it, like the Enhance prompt button in Roo Code or Augment?** Yes, with **Improve prompt** (on by default): type a rough request and click the magic wand next to the model menu. It rewrites the text with this chat and the project as context, in your language, and does not send it. `Cmd/Ctrl+Z` or **Undo improvement** brings your text back. Choose its model in **Settings → Composer Plus → Improve prompt → Model**.

**Can the agent stop marking its own work as done, like the verifier loops in loop engineering?** Yes, with **Goal check** (on by default): start a goal with `/goal`. When the agent says the goal is complete, the project's tests run and an independent model call checks the goal against the chat; if either fails, the goal stays open and the agent reads why. Set your own test command, a time limit or a token limit with **Edit** in the **Goal check** row under the goal.

**Can the agent remember my preferences across chats, like DS Bot's memory?** Yes, with **Project memory** (off by default): switch it on in **Settings → Composer Plus**. After each turn, your lasting preferences and decisions are kept as short notes for the chat's project, and each new chat in that project reads them. Ask the agent to remember something and it saves it at once. To see or change the notes, click **Open memory** in the same row and write what to change.

**I or the AI made a wrong change to the memory. Can I get the old notes back?** Yes, with **Memory version history** (on by default): in **Open memory**, select the project, then **History**. Select the version before the change to see what comes back, then **Restore**.

**Can I share the project memory with my team or another agent tool?** Yes, with **Export memory to AGENTS.md** (on by default): in **Open memory**, select the project, then **Export to AGENTS.md**. Check the diff, then **Write AGENTS.md**, and commit the file.

**Can the AI suggest what to keep from a long chat?** Yes, with **Suggest memory notes from a chat** (on by default, while **Project memory** is on): click **Suggest for memory** in the chat header, then **Accept** the notes worth keeping.

**Can I see all my chats as a kanban board and start new ones from it?** Yes, with **Task board** (on by default): open it in the left sidebar. Each chat is a card in **Doing**, **Review** (it waits for you) or **Done**. **New task** opens dsh's new chat in the project, and the board comes back when your first message goes; click **Answer** on an orange card to answer it without opening the chat. **Clear all** in **Done** asks first and takes the finished cards that you read off the board; **Undo** and **Removed (N)** bring them back, and the chats stay in dsh.

**Can I have a personal assistant chat that reminds me and manages my other chats?** Yes, with **Assistant** (on by default): click **Assistant** in the left sidebar. It sets reminders with dsh's scheduled tasks, searches the web, lists and reads your chats, and sends a message to a chat or starts, stops or archives one only after you approve it. Keep your profile in its project memory, topic "profil".

**Can the assistant stay out of my chat list and work like a bot?** Yes. **Assistant apart from chats** takes its chat out of the sidebar list and shows its state on the **Assistant** row (orange while it waits for you). **Assistant messages only** hides its work steps. **Assistant always free** makes it give every longer step to a background subagent, so it answers at once. **Assistant news from chats** (off by default, it uses tokens) makes it tell you when another chat finishes, fails or waits for you. By default (**Automations only**) it tells you only about the turns that a scheduled task started (also in a chat that you started), after each of these turns, as a subagent reports; choose **All chats** under **Tell me about** to hear about every chat.

**Can dsh back up my chats and settings, like dsh-backup?** Yes: **Settings → Composer Plus → Backup → Back up now**. It writes the same archive format into the same folder (`~/Desktop/dsh-backups`), so dsh-backup's archives show and restore too, and you can remove dsh-backup. Switch on **Automatic backup** for a schedule.

**dsh does not start any more. How do I restore a backup?** Open the backup folder (`~/Desktop/dsh-backups`) and double-click `Composer Plus Rescue.command` (Linux: `composer-plus-rescue.sh`, Windows: `Composer Plus Rescue.cmd`). Choose **3) Restore a backup**, pick one and type `RESTORE`. It works without dsh.

**How do I move dsh to a new computer?** On the old one: **Backup** → **For another computer** next to a backup. Copy that folder to the new computer, install dsh there, quit it, open `Composer Plus Rescue` in the copied folder and restore. Enter your API keys again (they stay on the old computer).

**A chat does not open after a crash. Can I repair it?** **Settings → Composer Plus → Session log check → Check session logs**. A damaged chat comes back from the newest backup with **Repair from backups** (the messages after that backup are lost).

**How do I reorder queued messages in dsh?** Drag the ⠿ grip on a queued message, or focus it and press `↑` / `↓`.

**How do I fix a typo in a queued message?** Double-click the message in the queue, change the text and press `Enter` (`Esc` cancels). It keeps its place in the queue. You can also remove its images and files there, or add new ones.

**How do I clear all unread dots of a project at once?** Sidebar → the project's **…** button → **Mark all as read**.

**Can I link to one message in a long chat?** Yes: hover the message and click **🔗**. Send the link in a chat: on dsh 0.2.1 and later a click on it opens the chat at that message.

**I rolled back a turn by mistake. Can I get it back?** Yes, with **Redo** above the composer, right after the rollback: it starts a new chat from just before the rollback with the same messages, and **Chat and files** also puts the files back.

**Which chat changed this file?** Right sidebar → **Changes** → the file's **…** → **Chats that changed this file**. Click a row to open that chat at the request that made the change.

**Can I search inside one long chat?** Yes: press `Cmd+F` on a Mac (`Ctrl+F` on Windows and Linux) in the chat. **Find in chat** highlights every match and moves between them with `Enter` and `Shift+Enter`.

**How do I see only the files that one chat changed?** Right sidebar → **Changes** → **This chat**. Click **␣** to hide changes that are only whitespace.

**How do I stop the agent from running `npm publish` or `git push --force`?** **Settings → Composer Plus → Blocked commands**: type `npm publish`, choose **block** or **ask first**, then click **Add**. **block** refuses the command and the agent asks you; **ask first** shows the approval card each time. Protected files covers the agent's file tools; Blocked commands covers its shell commands.

**Can I tell the agent why I rejected a tool call?** Yes, with **Reject with note** (on by default): click **Reject with note…** on the approval card, write why or what to do instead, and click **Reject**. The agent reads the rejection and your note in the same turn.

**How do I give the agent a password or a token without writing it in the chat?** With **Secret input** (on by default): ask the agent to use `request_secret`, or wait until it asks. Type the value in the card on the tool's row and click **Save**. The agent gets only the path of a file that holds the value, and the file is deleted when the turn ends.

**How do I answer one part of a long answer?** Select that part and click **Quote** above the selection (**Quote in reply**, on by default). The part goes into the composer as a `> …` quote, and you write your reply below it.

**How do I show the agent the exact lines of a file?** Open the file in the right sidebar (**Workspace files**), select the lines and click **Quote** above the selection (**Quote from file preview**, on by default). The composer gets the path and the line numbers (for example `src/login.js:2-3`) and the lines as a code block; write your question below them.

**Can I ask something while the agent works, without stopping it?** Type the question and click **Ask in a side chat** in the composer (**Side chat**, on by default). A read-only copy of the chat answers it while the chat goes on. In the side chat, **Bring back** puts the answer into the chat's composer.

**How do I tell the agent what to change in its diff?** In **Changes panel**, open the file's diff, click **+** at a line and write a note (**Diff notes**, on by default). Then click **Send to composer**: the notes go into the composer with the file, the line numbers and the lines.

**How do I stop Auto Review asking about the same tool in one chat?** Click **Allow for this chat** on the approval card. It covers that exact tool in that chat only, for 1 hour by default; revoke it from the header chip. Change the time in **Settings → Composer Plus → Allow for this chat**.

**I lost my iPhone. How do I stop it from reaching my Mac?** Click **Mobile connect** at the bottom left of the sidebar and click **Remove** next to that iPhone. Its key stops working at once; it can come back only with a new pairing that you approve on the Mac.

**How do I continue a chat of my other Mac from this one?** On the other Mac, switch on **Settings → Composer Plus → Remote computers** and **Let other computers open this Mac**, click **Create pairing link** and copy the link (send it to yourself, for example with AirDrop or Notes). On this Mac, switch on **Remote computers** too, pick **Add a computer…** in the picker of the left sidebar (under the brand, above **New session**), paste the link, type a **Name** and click **Connect**, then click **Approve** on the other Mac. From then on, click the name of that computer in the picker: it fills this window. To come back, click **This Mac** in the same place; this Mac's chats keep running meanwhile.

**Can I lock Tether with Face ID?** Yes: in Tether, **Settings → Privacy → Lock with Face ID**. Tether then asks for Face ID (or the passcode) when it opens and when you come back to it.

**How do I show only the projects I used today in the dsh sidebar?** Sidebar → view options (sliders icon) → **Active in the last 2 hours**. Select it again to show all projects.

**How do I copy a project's folder path in dsh?** Right-click the project in the sidebar → **Copy path**.

**How do I collapse all projects in the dsh sidebar at once?** Click the collapse button next to the view options (sliders icon). It shows while at least one project is open.

**How do I get macOS / Windows notifications when a dsh task finishes or needs approval?** Keep **Background notifications** on (default) and allow notifications for DeepSeek Harness in the OS settings.

**Can dsh open the chat that asks me a question by itself?** Yes, with **Open waiting chat when idle** (on by default): when a chat waits for an answer, an approval or a plan review and you do not use dsh for 30 seconds, dsh opens it. A chat that finished a turn that you have not read (the green dot) opens the same way, after the orange ones. While you type, scroll or move the mouse, it waits.

**Can I jump to the next chat that waits for me?** Yes, with **Next waiting chat** (on by default): press `Cmd+Shift+E` (`Ctrl+Shift+E` on Windows and Linux) or click the button with the count in the sidebar header. Chats that ask a question or wait for an approval come first, then chats that finished a turn that you have not read.

**Can I answer an agent's options with one click?** Yes, with **Option buttons** (on by default): when an answer ends with an "Options" list, click a button under it. It sends "Option N: …" as your message. On a question card of the agent, press 1–9.

**Can I send the agent's approval sentence without typing it?** Yes, with **Approve button** (on by default): when the agent needs a written approval, it writes the sentence in an `onay` block. Click **Approve** under the answer: the exact sentence goes as your message, so Auto review sees it from you. A sentence that names a live or public target has no button: type it yourself.

**How do I switch the DeepSeek Harness interface to Turkish, Spanish, Japanese…?** Settings → Composer Plus → **Application language**.

**How do I use dsh from my iPhone?** Build the Tether app from `tether/ios` (Xcode), switch on **Settings → Composer Plus → Mobile connect (iPhone)**, click **Mobile connect** at the bottom left, scan the QR code (iPhone Camera or **Scan code** in Tether), tap **Connect** and click **Approve**. Away from home, use Tailscale on both devices.

**How do I make New session always open in the same project?** Settings → Composer Plus → **Default workspace for New session** → **Open New session in** → choose the project. The `+` next to another project still opens that project.

**How do I run several features of one project at the same time, each on its own branch?** With **Branch per chat**: on the New chat screen, the branch button shows **New branch** by default: send the first message. Each chat gets its own branch and worktree folder, with your `.env` and `node_modules` when `.worktreeinclude` lists them. The chat header shows which branch you are on.

**Can the sidebar show each branch of a project, and move my chat when the agent creates a branch?** Yes, with **Branches in the workspace tree** (off by default): switch it on in Settings → Composer Plus, then choose dsh's **View options** → **Workspace Tree**. Each branch with a worktree in `<project>/.worktrees/` shows inside its project. When you ask the agent in the project folder to create a branch and work there, and the folder has no uncommitted changes, the chat moves into the branch by itself. Delete the branch's folder and it leaves the list; its chats go to **Ungrouped**.

**Can I send a photo from my iPhone?** Yes. In a Tether chat, tap **+** next to the message field → Camera, Photos (up to 4) or Paste image. The photos go to the chat on the Mac as attachments of your message, so the model sees them.

**Can dsh run the next command without asking the model again?** Yes, with **Planned steps** (off by default): switch it on in Settings → Composer Plus. The model can then plan its next commands with a condition, for example "run the tests when the build passes", and Composer Plus runs a step without a new model call when the result meets the condition. Approvals and the sandbox stay as they are.

**Where does the Turkish skill come from, and can I remove it?** From [yucezerey/turkish-anti-ai-skill](https://github.com/yucezerey/turkish-anti-ai-skill) on GitHub (MIT). Composer Plus installs it only while **Application language** is Türkçe, keeps only its Markdown files and runs none of its scripts. To remove it, switch off **Turkish skill pack** in Settings → Composer Plus: the skill and the downloaded copy go at once.

**How do I report a bug or ask for a feature in Composer Plus?** Settings → Composer Plus → **Report an issue…** (or a chat's **…** menu → **Report a Composer Plus issue…**). Pick a type, describe it in your own language and click **Write draft**. Check the English draft, then click **Open issue**.

**How can the agent clean up a messy codebase?** Type `/untangle-codebase` in a chat (**Untangle codebase**, on by default), optionally with an area, for example `/untangle-codebase src/api`. The agent first lists the copies, hidden links, needless wrappers, dead code and special cases, then fixes them as a goal and checks again with subagents. Start it in a chat of **Branch per chat**, so the work stays on its own branch.

**Does it work with the desktop app?** Yes: Settings → Plugins → **Add plugin** → `dsh-composer-plus`. Tested on dsh 0.2.0-rc.2 (desktop and web) and 0.2.1-rc.2 (web).

**Rule for new features:** every feature row in Settings → Composer Plus shows a screenshot. Add the feature id to `SHOT_OF` in `client.js` and to `SHOTS` in `index.js`, and ship `assets/features/<id>.webp` (taken from the throwaway demo dsh, English UI, about 60 kB or less). Add the feature, with the same image, to `docs/features.json` and run `npm run build:readme`: it writes the feature table of `README.md` and of each translated `README.<id>.md`, and the list in `llms.txt`. `test/shots.test.mjs` fails when a feature has no screenshot, and `test/browser-settings-shots.mjs` checks the real Settings page. The full checklist for every change is in [AGENTS.md](AGENTS.md).

The tests run the real `client.js` against a fake React/DOM and the real `index.js` (Host half) against a temporary git repository. The Tether gateway tests (`test/tether-gateway.test.mjs`) use a mock dsh host and a real TLS gateway. The iPhone app is in `tether/ios` (see [tether/README.md](tether/README.md) and [tether/AGENTS.md](tether/AGENTS.md)). Each Host route, its request and whether Tether can call it is listed in [docs/ROUTES.md](docs/ROUTES.md). `node test/browser-history.mjs '<dsh web URL with ?token=…>'` checks input history in a real browser against a throwaway `dsh web` with its own `DSH_HOME`.

Language packs are data-only JSON in `locales/<id>.json`, embedded into the single client entry by `npm run build:locales` (no translation service or runtime download). `npm test` checks every pack for full key coverage, identical placeholders and line breaks, and the system/override behaviour. For isolated real-app checks with a locally installed Playwright:

```sh
PLAYWRIGHT=/path/to/playwright node test/browser-language.mjs /path/to/dsh/lib/bin.js
```
