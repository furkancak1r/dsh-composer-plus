[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)(dsh) 데스크톱 앱과 웹 UI를 위한 Codex 스타일 편의 기능 모음입니다. 변경 사항 패널, 스와이프 카드로 보는 기능 아이디어, 메시지 본문까지 찾는 사이드바 검색, 파일 복원을 포함한 턴 되돌리기, 휴지통으로 보내는 채팅 삭제, 입력란 아래의 프로젝트 이름, 사이드바의 프로젝트 상태, 입력 기록, 계획 모드 단축키, 원클릭 계속, 재시작 후 실행 중이던 채팅 이어서 실행, 대기열 끌어서 놓기, 세션 딥링크, Markdown으로 채팅 내보내기, 채팅별 자동 검토 허용, 백그라운드 알림, Tether 앱을 통한 iPhone 접속, 자동 업데이트를 제공합니다.

**한 줄 요약:** DeepSeek Harness 플러그인 하나(npm `dsh-composer-plus`, 설정 → 플러그인에서 **Composer Plus**로 표시)로 다음 기능을 추가합니다. git 변경 사항 패널, Tinder 스타일 기능 아이디어 카드, 메시지 속 단어도 찾는 사이드바 검색, ↶ 턴 되돌리기(채팅만 또는 채팅과 파일), 채팅 삭제, 입력란 아래의 프로젝트 이름, ↑/↓ 입력 기록, Shift+Tab `/plan` 전환, 원클릭 ▶ 계속, 재시작 후 이어서 실행, 끌어서 놓는 대기열 순서 변경, 세션 링크 복사, Markdown으로 내보내기, 자동 검토의 “이 채팅에서 허용”, 백그라운드 알림, iPhone 접속(모바일 연결, Tether 앱), 11개 추가 인터페이스 언어, 자동 업데이트.

비공식 커뮤니티 플러그인입니다. 네트워크 호출은 업데이트 확인(GitHub 릴리스와 npm 레지스트리)뿐입니다. 시작할 때 이 호출을 막으려면 **자동 업데이트**를 끄세요. **기능 아이디어**는 **기능 제안**을 클릭할 때만 채팅 자체의 모델을 호출합니다. **다음 메시지 예측**(기본값: 켜짐)은 턴이 끝날 때마다 설정에서 고른 모델(다른 모델을 고르지 않으면 dsh의 기본 모델)을 클릭 없이 한 번 호출합니다. 이 호출을 막으려면 **설정 → Composer Plus**에서 끄세요. **입력 중 자동 완성**(기본값: 꺼짐)은 사용자가 켠 뒤에 입력을 멈출 때마다 이 기능에서 고른 모델(기본값: 예측의 모델)을 호출합니다. **프롬프트 개선**은 요술봉을 클릭할 때만 모델을 호출합니다. **모바일 연결**(기본값: 꺼짐)은 사용자가 켠 뒤에만 로컬 네트워크나 tailnet에서 오는 iPhone 연결을 받습니다.

## 설치

**데스크톱 앱:** 설정 → 플러그인 → **플러그인 추가** → `dsh-composer-plus` 입력 → **지금 활성화**.
npm 이름 대신 `https://github.com/furkancak1r/dsh-composer-plus`를 붙여 넣어도 됩니다.

**웹 / CLI 프로필:**

```sh
dsh plugin --profile web add dsh-composer-plus
```

그런 다음 dsh를 다시 시작하세요. (CLI는 데스크톱 프로필에 설치할 수 없습니다. 데스크톱 프로필은 앱이 관리합니다.)

> dsh의 pnpm은 게시된 지 24시간이 지나지 않은 버전을 건너뜁니다. 릴리스 직후에는 버전을 붙여서 설치하세요: `dsh-composer-plus@1.13.0`.

모든 기능은 dsh **설정 → Composer Plus**에서 하나씩 켜거나 끌 수 있습니다. 각 행에는 작은 스크린샷이 있습니다. 포인터를 올리면 크게 미리 보고, 클릭하면 원래 크기로 엽니다(`Esc`로 닫기). 맨 위의 **기능 검색** 상자는 이름이나 설명으로 페이지를 걸러 냅니다(모든 언어, 대소문자와 악센트 구분 없음). `Esc`를 누르면 검색어가 지워집니다. 각 행에는 스위치와 짧은 설명이 있습니다. 행 이름 뒤의 작은 **?**는 그 기능을 설명하는 README 부분을 dsh 인터페이스 언어의 README에서 엽니다. 변경 사항은 재시작 없이 바로 적용되고 그 기기에 저장됩니다. **모바일 연결**, **재시작 후 이어서 실행**, **입력 중 자동 완성**을 빼고 모든 기능이 기본적으로 켜져 있습니다. 이 세 기능과 **내용 검색**, **턴 되돌리기**, **다음 메시지 예측**의 스위치는 dsh의 Host가 보관합니다. 그래서 모든 창에 적용되고 재시작 후에도 유지됩니다. **다음 메시지 예측**에서 고른 **모델**, **입력 중 자동 완성**에서 고른 모델(기본값 **다음 메시지 예측과 같음**), **프롬프트 개선**에서 고른 모델(기본값 **채팅의 모델과 같음**), **이 채팅에서 허용**의 **시간 제한**(기본값 1시간)도 Host가 보관합니다. **내용 검색**은 dsh를 다시 시작한 뒤에만 바뀝니다(dsh가 시작할 때 이 값을 읽기 때문입니다). 그 전까지 해당 행에 **이 변경 사항을 적용하려면 dsh를 다시 시작하세요.**가 표시됩니다.

### 애플리케이션 언어

**설정 → Composer Plus → 애플리케이션 언어**를 열고 **시스템 언어** 또는 13개 언어 중 하나를 선택하세요.

English · 中文 · Türkçe · Español · Português (Brasil) · Français · Deutsch · Русский · 日本語 · 한국어 · Bahasa Indonesia · Tiếng Việt · हिन्दी

<p align="center"><img src="docs/images/language-tr.webp" width="720" alt="Türkçe(터키어)로 바뀐 DeepSeek Harness 인터페이스"></p>

앱 전체가 바로 바뀝니다. 이 선택은 dsh 자체에 저장되는 `locale.preference`(일반 → 언어와 같은 설정)이므로 재시작 후에도 유지됩니다. **시스템 언어**는 이 선택을 지웁니다. 그러면 데스크톱 앱은 OS 언어를, 웹 UI는 브라우저 언어를 따릅니다. 지원하지 않는 언어이면 영어로 표시됩니다. 플러그인을 설치해도 이미 고른 언어는 절대 바뀌지 않습니다.

각 언어 팩에는 텍스트 3,280개가 있습니다. dsh `0.2.0-rc.2`와 `0.2.1-rc.2`의 모든 UI 텍스트(채팅, 사이드바, 설정, 승인, 예약, 파일 미리 보기, 플러그인 관리자, 플러그인 마켓), 플러그인 자체의 컨트롤, 인기 있는 [dsh-rewind](https://github.com/SiriLee/dsh-rewind) 플러그인의 텍스트가 포함됩니다. 번역하지 않는 것: 내 메시지, 모델 출력, 코드, 슬래시 명령 이름(`/plan`, `/compact`), `High` 추론 강도처럼 제공자가 정한 레이블, 다른 플러그인의 텍스트, 데스크톱 앱의 네이티브 메뉴와 업데이트 대화 상자(dsh가 영어/중국어로만 제공). 더 새로운 dsh가 추가한 문자열은 팩이 업데이트될 때까지 영어로 표시됩니다. 다른 플러그인이 이미 어떤 언어를 제공하면, 그 언어는 해당 플러그인의 것이 유지됩니다.

## 개인정보 보호와 보안

- **계속:** 인증된 로컬 엔드포인트는 마지막으로 중단된 턴만 재개합니다. 오래되었거나 중복된 요청은 거부하고, 기존 승인 훅은 그대로 유지합니다. 새 사용자 메시지는 보내지 않습니다.
- **재시작 후 이어서 실행:** 켜기 전까지 꺼져 있습니다. Host 쪽은 채팅 ID와 시작 시각만 `$DSH_HOME/storages/dsh-composer-plus/resume.json`(소유자 전용 권한)에 보관합니다. 아무것도 컴퓨터 밖으로 나가지 않습니다. 마지막 턴을 사용자가 아니라 dsh가 멈췄다고 dsh 자체 로그에 기록된 경우에만 채팅을 이어 갑니다. 이어지는 턴에도 승인과 자동 검토가 평소대로 적용됩니다.

- **변경 사항 패널:** git은 dsh의 인증된 `/api` 채널을 거쳐, 내 컴퓨터의 채팅 폴더 안에서 읽기 전용으로 실행됩니다. 커밋, 스테이징, fetch는 절대 하지 않으며, git 자체가 나열한 경로만 보여 줍니다. 트리는 로컬 및 원격 브랜치를 최대 1000개까지 나열하고, 한 브랜치의 최신 커밋 300개를 보여 줍니다. 첫 번째 부모 줄기만 따라가므로 병합 커밋이 그 커밋이 가져온 커밋들을 대신합니다. 브랜치를 전환(checkout)하지 않습니다. **이 채팅**은 채팅 자체의 로그에서 파일 도구가 쓴 파일을 찾고, 곧바로 삭제되는 임시 폴더에서 그 파일을 채팅의 턴 되돌리기 스냅샷과 비교합니다. 내 저장소나 스냅샷 저장소에는 아무것도 쓰지 않습니다.
- **기능 아이디어:** **기능 제안**을 클릭하기 전에는 아무것도 실행되지 않습니다. 클릭하면 Host 쪽이 채팅 자체의 폴더만 읽습니다(브라우저는 경로를 보내지 않습니다). 읽는 내용은 최상위 항목 이름, README·AGENTS.md·매니페스트(`package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, …)의 처음 6 kB, README 나머지 부분의 개요(제목, 표의 행, 목록 항목, 최대 6 kB), 최근 커밋 제목(`git log --format=%s`, 최대 6 kB)이며, 합계 최대 28 kB입니다. `.env*`, 키 파일, `node_modules` 같은 폴더는 건너뜁니다. 폴더 안에 있는 일반 파일만 읽으며, 폴더 밖을 가리키는 심볼릭 링크, FIFO, 장치는 건너뜁니다. 이 요약은 dsh 자체 제공자 설정을 거쳐 채팅이 쓰는 모델에 요청 한 번으로 전달됩니다. 어떤 채팅에도 추가되지 않습니다. 프로젝트에는 아무것도 쓰지 않습니다. 오른쪽으로 스와이프한 아이디어는 계획 모드로 새 채팅을 시작하므로, 승인과 계획 검토가 평소대로 적용됩니다. **바로 구현**은 계획 모드 없이 채팅을 시작합니다. 모델이 바로 파일을 바꿀 수 있으며, 채팅의 평소 승인과 자동 검토가 적용됩니다. 나중을 위해 저장한 아이디어(제목, 요약, 이유, 작업량)는 프로젝트 폴더 경로와 함께 dsh 홈 아래 `storages/dsh-composer-plus/later.json`(소유자 전용 파일)에 보관됩니다. 프로젝트에는 아무것도 들어가지 않습니다. 제안된 아이디어의 기록(제목, 요약, 이유, 작업량, 날짜, 시작 여부)도 같은 방식으로 `storages/dsh-composer-plus/idea-history.json`에 보관되며, 프로젝트당 최대 200개입니다(가장 오래된 것부터 지워집니다). 그 제목들은 그 프로젝트에서 다음에 **기능 제안**을 누를 때 모델에 전달됩니다.
- **내용 검색:** 채팅을 검색하는 새 코드는 없습니다. 플러그인은 dsh 자체 메시지 색인(SQLite FTS5, `dsh-session-query-sqlite`)을 켜고, 그 색인에 `$DSH_HOME/cache/composer-plus/session-search.db` 파일(소유자 전용 파일과 폴더)을 지정할 뿐입니다. 이 파일에는 사용자와 어시스턴트 메시지의 텍스트가 들어 있으므로, `$DSH_HOME/sessions`의 채팅 로그만큼 민감합니다. 아무것도 컴퓨터 밖으로 나가지 않습니다. 이 파일은 dsh가 다시 만들 수 있는 사본이므로, dsh가 닫혀 있을 때 삭제해도 됩니다. 스위치 값은 `$DSH_HOME/storages/dsh-composer-plus/content-search.json`에 있습니다.
- **턴 되돌리기:** 내 메시지마다, 보내기 전에 Host가 채팅 폴더의 git 스냅샷을 자체 저장소 `$DSH_HOME/cache/composer-plus/rollback/<chat>.git`(소유자 전용 폴더)에 만듭니다. 이 저장소에는 그 폴더에서 git이 보는 파일(무시된 파일 제외)의 사본이 있으므로, 프로젝트만큼 민감합니다. 내 저장소의 객체를 읽기만 하고(git에 이미 있는 것은 복사하지 않음), 내 저장소의 인덱스, `HEAD`, 브랜치, 태그, stash, 설정에는 절대 쓰지 않습니다. git이 그곳에서 바꾸는 것은 재사용한 객체 파일의 타임스탬프를 새로 고치는 것뿐입니다(그래서 `git gc`의 정리가 늦어집니다). 파일까지 되돌릴 때는 채팅 폴더 안의 일반 파일에만 씁니다. 심볼릭 링크, 파이프, 폴더 밖의 모든 것은 건너뜁니다. 아무것도 컴퓨터 밖으로 나가지 않습니다. dsh가 닫혀 있을 때 이 저장소를 삭제해도 됩니다(그러면 새 메시지를 보낼 때까지 채팅만 되돌릴 수 있습니다). **채팅 삭제**는 채팅의 저장소도 함께 삭제합니다. 스위치 값은 `$DSH_HOME/storages/dsh-composer-plus/rollback.json`에 있습니다. 파일까지 되돌릴 때는 **다시 실행**을 위해 되돌리기 직전의 파일도 보관합니다(같은 저장소의 `refs/r/…`). 다시 실행한 되돌리기 목록은 `$DSH_HOME/storages/dsh-composer-plus/redone.json`(소유자 전용)에 있습니다.
- **GitHub 이슈 열기**(기능 아이디어 → **나중에** 목록): 클릭할 때만 실행됩니다. Host 쪽은 채팅 폴더에서 사용자의 GitHub CLI(`gh issue create`)를 아이디어의 저장된 제목과 요약(그리고 중요한 이유)으로 실행합니다. `gh`는 자체 로그인과 폴더의 GitHub 원격 저장소를 쓰므로, 이슈는 사용자 계정으로 그 저장소에 만들어지고, GitHub는 그 저장소를 볼 수 있는 모든 사람에게 이슈를 보여 줍니다. dsh는 자신이 시작하는 명령에서 토큰처럼 보이는 이름의 변수를 제거합니다. `GH_TOKEN` 또는 `GITHUB_TOKEN`으로 `gh`에 토큰을 주었다면, 플러그인은 이 두 변수만 `gh`에 전달합니다. 이슈 링크는 아이디어와 함께 `later.json`에 보관됩니다.
- **이 파일을 변경한 채팅**(변경 사항, 파일의 "…" 메뉴): Host 쪽은 폴더가 같은 저장소에 있는 채팅의 로그를 dsh가 보관한 그대로 읽고, 각 채팅의 제목, 시간, 요청의 첫 줄을 응답합니다. 파일 자체는 절대 열지 않습니다.
- **채팅 행의 Git 브랜치:** Host 쪽은 턴이 시작될 때와 끝날 때 채팅 폴더에서 `git branch --show-current`(읽기 전용)를 실행하고, 채팅 ID, 브랜치 이름, 시간만 `$DSH_HOME/storages/dsh-composer-plus/session-branches.json`(소유자 전용 파일, 최신 채팅 2000개)에 보관합니다. 스위치 값은 그 옆의 `branches.json`에 있습니다.
- **채팅에서 찾기**는 페이지 안에서만 실행됩니다. 페이지가 보여 주는 텍스트를 읽고, 아무것도 보내지 않습니다.
- **채팅을 Markdown으로 내보내기:** 호스트 쪽은 채팅 자체의 로그(dsh가 보여 주는 것과 같은 메시지)만 읽어 페이지에 넘깁니다. 프로젝트 파일은 읽지 않고, 네트워크로 아무것도 보내지 않습니다. Markdown은 클립보드나 사용자가 저장하는 파일로만 갑니다.
- **채팅 삭제:** 채팅 자체의 로그 폴더(`$DSH_HOME/sessions/<project>/<chat>`)를 휴지통으로 옮깁니다. 프로젝트 폴더는 건드리지 않습니다.
- **이 채팅에서 허용:** 허용 항목은 허용한 시각과 함께 `$DSH_HOME/storages/dsh-composer-plus/chat-grants.json`(소유자 전용 권한)에 저장됩니다. 허용 하나는 한 채팅의 정확히 한 도구에만 적용되며, 시간 제한이 끝날 때까지 유효합니다(기본값 1시간). 그 도구가 쓰기를 할 수 있다면, 허용은 모든 쓰기에도 적용됩니다. 헤더 칩에서 취소하세요.
- 자동 검토는 여전히 모든 호출에서 실행됩니다. 검토가 실패한 호출은 절대 자동으로 허용되지 않습니다.
- **모바일 연결:** 켜기 전까지 꺼져 있습니다. 켜져 있는 동안 Host 쪽이 Tether 게이트웨이를 실행합니다. 게이트웨이는 두 부분입니다. 포트 19390의 HTTPS는 Wi-Fi 서브넷과 tailnet(100.64.0.0/10)의 연결만 받고, `127.0.0.1:19391`의 페어링 페이지는 이 Mac에서만 열립니다. 휴대폰을 연결하려면 QR 코드의 일회용 코드(5분 유효)와 Mac에서의 **Approve**가 필요합니다. 휴대폰은 게이트웨이 인증서를 고정(pinning)합니다. Mac은 각 휴대폰 토큰의 해시만 보관합니다(30일, 사용하는 동안 갱신). **Remove**를 누르면 그 휴대폰의 연결이 즉시 끊깁니다. 휴대폰은 허용 목록에 있는 dsh 메서드(채팅, 프롬프트, 첨부 파일, 슬래시 명령, 승인, 질문, 모델, 에이전트, 목표)만 호출할 수 있습니다. 설정, 자격 증명, 파일 브라우저, 터미널은 호출할 수 없습니다. "Tailscale only"는 로컬 네트워크에서 오는 모든 연결을 거부하며, 이미 열린 연결도 끊습니다. 액세스 로그는 가장 최근의 연결 시도 200개(시각, IP 주소, 기기 이름, 허용 또는 거부, 그 이유)를 `access.json`에 보관합니다. 토큰이나 페어링 코드는 절대 보관하지 않습니다. 데이터: `$DSH_HOME/storages/dsh-composer-plus/mobile/`(소유자 전용 파일). 자세한 내용: [tether/README.md](tether/README.md).
- **업데이트:** Host 쪽은 `api.github.com`에 최신 릴리스를 묻고, `registry.npmjs.org`에 그 정확한 버전을 묻습니다. 사용자나 채팅에 관한 정보는 보내지 않습니다. 설치는 dsh의 플러그인 관리자(`pnpm add dsh-composer-plus@<version>`. 이미 설치된 플러그인에 대해 dsh 0.2.1이 이를 거부하면 `pnpm add https://registry.npmjs.org/dsh-composer-plus/-/dsh-composer-plus-<version>.tgz`를 쓰며, 그 후 프로필에는 그 URL이 플러그인의 소스로 표시됩니다)를 쓰므로, dsh 자체의 레지스트리, 스크립트, 버전 호환성 검사가 적용됩니다. 사전 릴리스 태그와 더 오래된 버전은 절대 설치하지 않습니다.
- **다음 메시지 예측:** 기본적으로 켜져 있습니다. 이 모델 호출을 막으려면 **설정 → Composer Plus**에서 끄세요. 턴이 끝날 때마다 Host 쪽은 그 채팅에서 사용자가 직접 보낸 메시지와 에이전트의 텍스트 답변(도구 출력, 숨은 컨텍스트, 추론 제외)을 최대 약 6,000자(가장 최근 부분)까지 고른 모델(다른 모델을 고르지 않으면 dsh의 기본 모델)에 보냅니다. dsh 자체 제공자 설정을 거쳐 요청 한 번으로 전달됩니다. 채팅에는 아무것도 저장되지 않으며, 예측은 채팅 기록에 추가되지 않습니다. 스위치와 고른 모델은 `$DSH_HOME/storages/dsh-composer-plus/predict.json`(소유자 전용 파일)에 보관됩니다.
- **입력 중 자동 완성:** 켜기 전까지 꺼져 있습니다. 켜져 있는 동안 입력을 멈출 때마다 Host 쪽은 지금까지 입력한 텍스트와, 그 채팅에서 사용자가 직접 보낸 메시지와 에이전트의 텍스트 답변(도구 출력, 숨은 컨텍스트, 추론 제외)을 채팅 기준 최대 약 3,000자까지 **입력 중 자동 완성**에서 고른 모델(기본값: **다음 메시지 예측**의 모델)에 보냅니다. 입력을 다시 멈추면 이전 요청은 중지됩니다. 채팅에는 아무것도 저장되지 않습니다. 스위치는 `$DSH_HOME/storages/dsh-composer-plus/complete.json`(소유자 전용 파일)에 보관됩니다.
- **프롬프트 개선:** 요술봉을 클릭하기 전에는 아무것도 실행되지 않습니다. 클릭하면 Host 쪽은 초안, 그 채팅에서 사용자가 직접 보낸 메시지와 에이전트의 텍스트 답변(도구 출력, 숨은 컨텍스트, 추론, 되돌린 메시지 제외. 최대 약 6,000자, 가장 최근 부분), **기능 아이디어**와 같은 프로젝트 요약(파일 규칙도 같음: `.env*`나 키 파일 없음, 폴더 밖을 가리키는 심볼릭 링크 없음, FIFO 없음), `git status`가 변경됨으로 표시하는 경로, 이름에 초안과 같은 단어가 들어 있는 추적되거나 추적되지 않는(무시되지 않은) 경로 최대 30개를 **프롬프트 개선**에서 고른 모델(기본값: 채팅 자체의 모델)에 요청 한 번으로 보냅니다. 이 요약 외의 파일 내용은 보내지 않습니다. 채팅과 프로젝트에는 아무것도 쓰지 않습니다. 답변은 입력란의 초안을 바꿀 뿐이며, 보낼지는 사용자가 정합니다. 고른 모델은 `$DSH_HOME/storages/dsh-composer-plus/improve.json`(소유자 전용 파일)에 보관됩니다.

## 문제 해결

- **macOS에서 알림이 오지 않음:** 시스템 설정 → 알림 → DeepSeek Harness → 알림을 허용하세요. 알림을 화면에 계속 두려면 알림 스타일에서 알림을 선택하세요.
- **dsh 업데이트 후 ▶, 대기열 핸들, 프로젝트 상태, 최근 프로젝트 옵션, 모든 프로젝트 접기, 경로 복사, 프로젝트 검색 상자, 다음 메시지 예측, 입력 중 자동 완성, 이 채팅에서 허용 또는 오른쪽 클릭 메뉴가 보이지 않음:** 이 요소들은 dsh에 아직 전용 슬롯이 없어서 dsh의 현재 HTML에 붙습니다. dsh가 그 마크업을 바꾸면 이 요소들은 스스로 숨겨지며, 다른 기능은 망가지지 않습니다. [issue](https://github.com/furkancak1r/dsh-composer-plus/issues)를 열어 주세요.
- **"업데이트 실패" 또는 "npm에서 설치되지 않았으므로" 메시지:** 로컬 폴더에서 링크했거나 이름을 바꾼 사본은 스스로 업데이트할 수 없습니다. 설정 → 플러그인에서 `dsh-composer-plus`를 다시 설치하세요. 그 밖의 경우에는 메시지에 pnpm 오류의 첫 줄이 표시됩니다. **업데이트 확인**을 누르면 다시 시도합니다.
- **모바일 연결에 게이트웨이가 실행되고 있지 않다고 표시됨:** "no IPv4 address on en0"은 이 Mac에 Wi-Fi/이더넷 주소가 없다는 뜻입니다. "EADDRINUSE"는 다른 dsh(또는 앱)가 포트 19390 또는 19391을 쓰고 있다는 뜻입니다. 모바일 연결은 한 번에 dsh 하나에서만 실행할 수 있습니다.
- **모바일 연결, 재시작 후 이어서 실행, 내용 검색에 "dsh를 다시 시작하세요"가 표시됨:** dsh가 실행 중일 때 플러그인이 업데이트되었습니다(내용 검색은 스위치를 바꾼 경우에도 표시됩니다). 새 상태는 재시작 후 로드됩니다.
- **검색이 제목만 찾음:** 내용 검색이 꺼져 있거나, 켜거나 플러그인을 설치한 뒤 dsh를 다시 시작하지 않았거나, 그 단어가 도구 출력에만 있습니다(제한 사항 참고).
- **내 메시지에 ↶ 버튼이 없음:** 턴 되돌리기가 꺼져 있거나, 하위 에이전트 채팅이거나, dsh-rewind-plugin이 설치되어 있습니다(그 플러그인의 ↶ 버튼을 쓰세요). 업데이트한 뒤에는 dsh를 다시 시작하세요.
- **채팅과 파일이 회색으로 비활성화됨:** 프로젝트가 git 저장소가 아니거나, 그 메시지 이전 스냅샷이 없거나(메시지가 플러그인보다 오래되었거나, 최신 스냅샷 50개가 그 스냅샷을 대체함), 바뀐 파일이 없습니다.
- **삭제할 때 다른 dsh가 이 채팅을 열고 있다고 표시됨:** 같은 dsh 홈을 쓰는 두 번째 dsh가 채팅 잠금을 잡고 있습니다. 그 창이나 dsh를 닫은 뒤 다시 삭제하세요. 그동안 채팅은 보관된 상태로 남습니다.
- **"Tailscale only"를 켠 뒤 iPhone이 연결되지 않음:** Mac과 iPhone 모두에서 Tailscale이 켜져 있어야 합니다. Mac에서 꺼져 있으면 모바일 연결 패널에 경고가 표시됩니다. 액세스 로그에서 거부된 각 시도와 그 이유를 볼 수 있습니다.
- **재시작 후 채팅이 이어지지 않음:** dsh를 종료할 때 재시작 후 이어서 실행이 꺼져 있었거나, 그 턴을 직접 중지했거나, 턴이 이미 끝났거나(완료 또는 실패), 채팅이 보관되었거나, 실행 중인 채팅이 20개보다 많았습니다(가장 최근 채팅 20개만 이어짐).
- **GitHub 이슈 열기에 "gh could not open the issue"가 표시됨:** 이 메시지는 `gh` 자체 출력의 첫 줄입니다. 터미널에서 `gh auth status`를 실행하고 `gh auth login`으로 로그인하세요. 채팅 폴더에 GitHub 원격 저장소가 있어야 합니다(`git remote -v`). "not installed or not on the PATH of dsh"는 dsh가 `gh`를 찾지 못했다는 뜻입니다. 설치하거나, `gh`가 작동하는 터미널에서 dsh를 시작하세요.
- **채팅 행에 브랜치 배지가 없음:** 이 버전을 설치한 뒤 그 채팅에 턴이 없었거나, 폴더가 git 저장소가 아니거나, **채팅 행의 Git 브랜치**가 꺼져 있습니다. 업데이트한 뒤에는 dsh를 다시 시작하세요(브랜치는 Host 쪽이 기록합니다).
- **릴리스 직후 설치 실패:** 버전을 붙여서 설치하세요(`dsh-composer-plus@1.13.0`). 위의 설치 안내를 참고하세요.

## 제한 사항

- 메시지 없는 계속은 dsh의 `agent/pre-step` → `agent/request` 수명 주기에 의존합니다. dsh를 업그레이드할 때 호환성을 다시 확인하세요.
- **기능 아이디어**는 dsh나 페이지를 다시 로드할 때까지 채팅마다 카드를 메모리에 둡니다. 그 뒤 **기능 제안**은 모델에 다시 묻습니다. 카드는 클릭한 시점의 dsh UI 언어로 나옵니다. 언어를 바꿔도 이미 쌓인 카드는 원래 언어를 유지하고, **아이디어 더 받기**는 새 언어를 씁니다. 모델은 코드가 아니라 짧은 프로젝트 요약만 봅니다. 그래서 프로젝트에 이미 있는 기능을 제안할 수도 있습니다. 그럴 때는 건너뛰세요. 새 채팅은 프로필에 dsh의 `/plan` 명령이 있을 때만 계획 모드로 실행됩니다. 없으면 아이디어가 일반 첫 메시지로 전달됩니다. **나중에** 목록은 채팅의 폴더 경로에 속합니다. 같은 폴더를 심볼릭 링크로 열면 별도 목록이 생깁니다. 프로젝트당 최대 50개 아이디어를 보관하며(더 추가하려면 하나를 제거하세요), 같은 제목은 한 번만 보관합니다. 카드를 끌면 왼쪽 또는 오른쪽만 결정됩니다. 저장하려면 **↓**를, 바로 구현하려면 **▶**를 쓰세요. 반복은 제목으로만 찾습니다. 그래서 모델이 이전 아이디어를 새 이름으로 다시 제안할 수 있습니다. 그럴 때는 건너뛰세요. 모델이 이전 아이디어만 답하면 새로 보이는 것이 없습니다. 다시 클릭하세요. 집중 주제가 좁으면 이런 일이 더 자주 생깁니다. 더 넓은 주제를 쓰거나 주제를 지우세요. 집중 주제는 dsh나 페이지를 다시 로드할 때까지 채팅마다 입력란에 남아 있습니다.
- **채팅을 Markdown으로 내보내기**에는 사용자 자신의 메시지와 어시스턴트의 텍스트 답변만 들어갑니다. 도구 호출과 그 출력, 생각, 이미지(`[image]` 줄로 표시됩니다), 숨겨진 컨텍스트, 턴 되돌리기나 dsh-rewind-plugin로 뺀 메시지는 빠집니다. 한 턴의 답변은 섹션 하나로 합쳐집니다. 내보내기 한 번에는 최대 약 400만 자가 들어갑니다. 더 긴 채팅은 앞부분과 안내 문구만 내보냅니다.
- **재시작 후 이어서 실행**은 턴을 이어 갈 뿐, 처음부터 다시 실행하지 않습니다. 종료 시점에 실행 중이던 도구 호출은 dsh의 “결과 알 수 없음” 결과로 끝납니다. 모델에게는 끝난 작업을 반복하지 말라고 알리지만, 두 번 실행하면 안전하지 않은 명령이 다시 실행될 수 있습니다. 열려 있던 하위 에이전트, 승인, 질문은 복원되지 않습니다. 대신 부모 채팅이 이어지면서 다시 묻습니다. 한 번 시작할 때 최대 20개 채팅만 이어집니다.

- **내용 검색**은 dsh 자체 검색이므로 dsh의 제한을 그대로 가집니다. 사용자와 어시스턴트 메시지만 검색합니다. 도구 출력(명령, 파일 내용, 결과)과 추론은 검색하지 않으며, 사용자, 어시스턴트, 도구 메시지를 고르는 필터도 없습니다. 단어 일부가 아니라 단어 전체가 일치해야 합니다(`deploy`로는 `deployment`를 찾을 수 없음). 악센트가 있는 글자는 악센트 없이도 일치합니다(`seker`로 `şeker`를 찾음). 채팅마다 한 행에 dsh의 240자 발췌가 표시되며, 최대 20행입니다.
- **내용 검색**의 비용은 실제 채팅 로그 247개의 사본으로 측정했습니다(159 MB, dsh 0.2.1-rc.2, Apple Silicon, 32 GB). 시작 후 첫 검색에서 약 15초 동안 색인을 만듭니다. 그중 약 7초 동안 dsh의 Host가 아무 응답도 하지 않으므로, 다른 채팅의 스트리밍이 그 순간 멈춥니다(페이지 자체는 멈추지 않습니다). Host의 메모리는 최고 약 1.1 GB 늘어납니다. 1분 뒤에도 시작 때보다 약 0.5–0.6 GB 많은 상태가 dsh를 종료할 때까지 유지됩니다. 색인 파일은 약 165 MB입니다. 이후 검색은 약 0.5초 걸립니다. 재시작 후 첫 검색은 약 1초 걸리고(새 채팅이나 바뀐 채팅만 추가) 메모리가 약 70 MB 늘어납니다. 컴퓨터 메모리가 적다면 이 기능을 끄세요.
- **내용 검색**은 dsh를 다시 시작한 뒤에만 적용됩니다. 같은 dsh 홈을 쓰는 모든 dsh가 색인 파일을 함께 쓰므로, 이런 dsh는 한 번에 하나만 실행하세요(dsh는 색인 파일 하나에 소유자 하나만 허용합니다).
- **턴 되돌리기**는 git 저장소에서만, 그리고 채팅 폴더 안에서만 파일을 되돌립니다. 채팅마다 최신 스냅샷 50개를 보관합니다. 무시된 파일(`.gitignore`, `info/exclude`, 전역 ignore 파일), 빈 폴더, 심볼릭 링크, 서브모듈은 되돌리지 않습니다. 스냅샷을 만들 때 무시되던 파일은 턴이 ignore 규칙을 바꾸었더라도 절대 삭제하지 않습니다. git이 읽을 수 없는 파일은 스냅샷에서 빠집니다. 메시지를 보낼 때마다 채팅 폴더에 `git add --all`을 한 번 실행해 비공개 저장소에 넣습니다. 추적되지 않는 파일이 많은 아주 큰 폴더에서는 몇 초 걸릴 수 있고, 다음 도구 호출이 이를 기다립니다(최대 10초. 그 뒤 스냅샷은 백그라운드에서 마무리됩니다). 내 저장소의 `git gc`가 오래된 스냅샷에 필요한 객체를 지우면, 그 파일은 되돌리지 못한 파일로 표시됩니다. 입력란에는 메시지의 텍스트만 돌아옵니다. 이미지나 파일은 다시 추가하세요. 하위 에이전트 채팅에는 ↶가 없습니다(하위 에이전트의 파일 변경은 그 하위 에이전트를 시작한 채팅의 변경으로 칩니다). 내보낸 채팅(`/export`)에는 철회한 메시지가 그대로 남아 있습니다. 숨겨진 표시 하나로 채팅 일부를 철회하는 아이디어는 SiriLee의 [dsh-rewind-plugin](https://github.com/SiriLee/dsh-rewind)(MIT)에서 가져왔습니다. Composer Plus는 그 코드를 전혀 쓰지 않습니다.
- **채팅 삭제**에는 dsh의 보관 기능(dsh 0.2.0 이상)이 필요합니다. 15초 안에 멈추지 않거나 다른 dsh가 잡고 있는 채팅(또는 그 하위 에이전트 채팅 중 하나)은 보관된 상태로 남고, 아무것도 이동하지 않습니다. macOS가 아닌 시스템에서는 휴지통 폴더가 채팅 기록과 같은 디스크에 있어야 합니다. 열려 있는 채팅을 삭제하면, 그 채팅은 dsh를 다시 시작할 때까지 dsh 메모리에 보관되고 숨겨진 상태로 남습니다. 휴지통은 직접 비우세요. dsh는 휴지통을 비우지 않습니다.
- dsh의 대기열에는 `move` 동작이 없습니다. 그래서 플러그인의 Host 쪽이 dsh의 대기열 안에서 대기 중인 메시지 자체를 옮깁니다(한 번의 변경, 같은 메시지). 이미지나 파일이 있는 메시지도 이동할 수 있습니다. 내 메시지만 이동할 수 있습니다. 대기열에 있는 목표 라운드나 질문에 대한 답변은 제자리에 남습니다. 끄는 중에 메시지 전송이 시작되면 아무것도 이동하지 않고, 알림으로 이를 알려 줍니다.
- 새 버전이 dsh 설정을 하나도 바꾸지 않으면 dsh 0.2.1은 업데이트를 바로 로드합니다. 그 밖의 경우와 dsh 0.2.0에서는 업데이트를 로드하려면 dsh를 다시 시작하세요. 플러그인은 dsh를 대신 재시작하지 않습니다. dsh 플러그인 관리자가 없는 웹/CLI 프로필은 새 버전을 알리기만 합니다.
- **이 채팅에서 허용**은 허용한 순간부터 시간 제한을 셉니다. 새 시간 제한은 유효한 허용에 즉시 적용되므로, 더 짧은 시간 제한은 허용을 즉시 끝낼 수 있습니다. 버전 1.12 이하의 허용에는 시간 정보가 없습니다. 업데이트 후 에이전트가 그 도구들에 대해 한 번 더 묻습니다.
- **입력란 포커스 유지**는 `/` 명령이나 스킬을 보낸 뒤에만 포커스를 돌려줍니다. dsh가 명령을 처리하는 몇 밀리초 동안 입력란이 읽기 전용이므로, 그동안 누른 키는 사라집니다. dsh의 `/` 메뉴가 아직 열려 있으면 `Enter`는 강조된 행을 선택하고 메시지를 보내지 않습니다.
- **모바일 연결**은 macOS에서만 작동합니다(`en0`, `openssl`, `swift`, `dns-sd` 사용). 고정 포트 19390과 19391을 쓰므로, Mac마다 한 번에 dsh 하나에서만 실행할 수 있습니다(각 Mac은 휴대폰의 Mac 목록에서 항목 하나입니다). 휴대폰은 Tether가 열려 있거나 막 백그라운드로 간 동안에만 알림을 받습니다(푸시 서비스 없음). iOS 앱은 아직 App Store에 없습니다. Xcode로 `tether/ios`에서 빌드하세요. "Tailscale only"를 켜도 Mac에 Wi-Fi 또는 이더넷 주소가 있어야 합니다(게이트웨이는 그런 주소가 있을 때만 시작됩니다). 액세스 로그는 Mac마다 따로 있으며, 가장 최근의 시도 200개만 보관합니다. 1분 안에 반복된 시도는 새 행을 만들지 않고 같은 행의 횟수를 하나 늘립니다. Tether의 앱 잠금은 iPhone 잠금 화면의 알림 미리보기를 숨기지 않습니다. iOS 설정에서 끄세요. Tether의 초록 점은 Mac을 따릅니다. dsh에서 연 채팅은 휴대폰에서도 점이 사라집니다. Tether에서 연 채팅은 휴대폰에서만 점이 사라집니다. Mac에 있는 dsh 자체의 점은 Mac에서 그 채팅을 열 때까지 남습니다.
- 세션 링크는 채팅 안에서 작동하지만, 클릭해도 채팅이 열리지는 않습니다. **메시지 링크 복사**로 만든 링크는 dsh 0.2.1 이상에서만, 그리고 채팅 안의 메시지에서만 그 메시지를 엽니다(dsh 0.2.0에는 사용자 텍스트 규칙이 없으므로, 링크는 복사되지만 일반 텍스트로 보입니다). 되돌리기로 빠진 메시지나, 압축으로 dsh가 불러오는 기록에서 빠진 메시지는 보여 줄 수 없습니다. 이때 링크가 그렇다고 알려 줍니다. 🔗 버튼은 dsh의 메시지 행에 붙습니다. dsh 업데이트로 그 마크업이 바뀌면 버튼이 표시되지 않습니다.
- **모두 읽음으로 표시**는 공개 API가 아닌 dsh의 일부(dsh 세션 상태의 `completionUnread` 목록)를 통해 dsh 자체의 읽지 않음 점을 바꿉니다. dsh 업데이트로 이 이름이 바뀌면 항목이 표시되지 않습니다. 이 항목은 dsh의 프로젝트 "…" 메뉴에 들어가는데, 이 메뉴에는 플러그인용 슬롯이 없습니다. dsh가 이 메뉴를 바꾸면 이 항목도 표시되지 않습니다.
- **대기 중인 메시지 제자리 편집**은 dsh 자체의 대기열 편집기를 열므로 그 제한도 따릅니다. 이미지나 파일이 있는 메시지는 편집할 수 없고, 그사이 전송이 시작된 메시지는 바뀌지 않습니다(dsh가 자체 오류를 표시합니다).
- **다시 실행**은 되돌린 채팅을 절대 바꾸지 않습니다. 되돌리기 직전 시점부터 새 채팅을 시작하므로(dsh 자체 포크, 같은 모델 컨텍스트), 새 채팅은 새 ID와 제목을 가집니다. 채팅의 가장 최근 되돌리기만, 한 번만, 그리고 그 뒤에 아무것도 없을 때만 다시 실행할 수 있습니다(새 메시지를 보내면 이 선택지가 사라집니다). 되돌린 뒤 내가 바꾼 파일은 덮어쓰기 상자를 체크하지 않는 한 유지됩니다. 다시 실행에는 되돌리기가 보관한 스냅샷이 필요합니다(같은 50개 범위). 이 버전 이전에 한 되돌리기나 **채팅만**으로 한 되돌리기는 메시지만 다시 가져옵니다.
- **이 채팅**은 dsh의 파일 도구(`write`, `edit`, `str_replace_editor`)가 쓴 파일만 셉니다. 명령(`bash`)이 바꾼 파일은 이 보기에 없고, **커밋 안 됨**에 표시됩니다. 채팅의 턴 되돌리기 스냅샷이 없으면(턴 되돌리기 꺼짐, dsh-rewind-plugin 설치됨, 또는 플러그인보다 오래된 채팅) 보기는 마지막 커밋과 비교하고 그렇다고 알려 줍니다. 턴 되돌리기는 채팅마다 최신 스냅샷 50개를 보관합니다. 더 긴 채팅에서는 보기가 보관된 가장 오래된 스냅샷과 비교하고, 어느 메시지부터인지 알려 주며, 그 이전의 변경은 세지 않습니다. **공백 변경 숨기기**는 `git diff -w`입니다. 줄 안의 공백만 바뀐 줄도 숨겨집니다.
- **GitHub 이슈 열기**에는 dsh의 PATH에 있는 GitHub CLI(`gh`)와 채팅 폴더의 GitHub 원격 저장소가 필요합니다. 최대 60초 동안 실행됩니다. `gh`가 더 오래 걸리면, 이슈가 GitHub에는 만들어졌지만 목록에는 링크가 없을 수 있습니다(다시 클릭하기 전에 GitHub를 확인하세요. 목록은 끝난 실행에서만 링크를 읽으므로, 다시 클릭하면 두 번째 이슈가 열릴 수 있습니다). GitHub 원격 저장소가 둘 이상인 폴더는 `gh` 자체의 기본값(`gh repo set-default`)을 씁니다.
- **이 파일을 변경한 채팅**은 **이 채팅**처럼 dsh의 파일 도구(`write`, `edit`, `str_replace_editor`)만 압니다. 명령(`bash`)으로 만든 변경은 목록에 나오지 않습니다. 저장소의 최신 채팅 300개(만든 시점 기준)를 읽고, 더 있으면 그렇다고 알려 줍니다. 최대 100행을 보여 줍니다. 이름이 바뀐 파일은 도구가 쓴 이름으로 표시됩니다. 폴더가 저장소 밖에 있는 채팅(같은 파일로 가는 다른 경로를 통한 경우도 포함)은 세지 않습니다. dsh를 시작한 뒤 처음 열 때는 저장소의 모든 채팅 로그를 읽습니다(채팅 275개에 약 4초). 그 뒤로 열 때는 그 이후에 바뀐 채팅만 읽습니다.
- **채팅 행의 Git 브랜치**는 현재 브랜치가 아니라, 마지막 턴이 시작되거나 끝날 때 채팅 폴더가 있던 브랜치를 보여 줍니다. 턴 밖에서 브랜치를 바꾸면 다음 턴 뒤에 표시됩니다. 이 버전 이전의 채팅에는 다음 턴까지 배지가 표시되지 않습니다. 배지는 dsh의 채팅 행 마크업 안에 들어갑니다(dsh에는 그곳에 슬롯이 없습니다). dsh 업데이트로 그 마크업이 바뀌면 배지가 표시되지 않습니다.
- **채팅에서 찾기**는 페이지가 보여 주는 것만 검색합니다. 불러온 메시지와 답변이 대상이며(이전 것은 위로 스크롤하거나 **이전 기록 로드**를 클릭하세요), 닫힌 도구 단계와 도구 출력 안의 접힌 텍스트는 검색하지 않습니다. 일치 항목은 최대 2,000개까지 셉니다(그 뒤에는 "2000+"). 브라우저의 하이라이트 API를 씁니다(Chromium 105 이상, 데스크톱 앱에는 있습니다). 더 오래된 브라우저에서는 개수와 이동은 작동하지만 색은 표시되지 않습니다. Mac에서는 `Cmd+F`(Windows와 Linux에서는 `Ctrl+F`)가 화면에 채팅이 있을 때만 이것을 엽니다. 다른 곳에서는 브라우저 자체의 찾기가 전처럼 작동합니다. Mac에서 `Ctrl+F`는 텍스트 필드에서 macOS 기능(커서를 한 글자 앞으로 이동)을 그대로 유지합니다.
- 재시작 전에 보낸 알림을 클릭하면 dsh를 앞으로 가져오기만 합니다.
- 활성 프로젝트는 dsh에 저장되는 프로젝트 순서로 이동하므로, 새 순서는 재시작 후에도 유지됩니다. 어느 프로젝트에도 속하지 않은 채팅("그룹 없음")은 이동할 수 없습니다. dsh는 이 채팅을 항상 맨 마지막에 나열합니다.
- dsh의 사이드바 보기 옵션 메뉴에는 확장 지점이 없습니다. 그래서 최근 프로젝트 옵션은 dsh 자체 메뉴에 추가됩니다. dsh 업데이트로 이 메뉴가 바뀌면 옵션이 표시되지 않고 모든 프로젝트가 계속 보입니다. 필터는 프로젝트 행에 적용되므로 **하나의 목록**은 걸러지지 않습니다. **작업 공간**과 함께 쓰세요. **작업 공간 트리**에서는 숨겨진 상위 폴더가 그 안의 활성 프로젝트도 숨깁니다. **상태별**에도 같은 종류의 제한이 있습니다. dsh에는 정렬 슬롯이 없으므로, 항목과 행 순서가 dsh의 메뉴와 목록 마크업에 붙습니다.
- dsh에는 프로젝트 행 메뉴나 작업 공간 헤더 슬롯도 없습니다. **경로 복사**는 dsh의 행 마크업으로 프로젝트 행을 찾습니다. **모든 프로젝트 접기**는 dsh 헤더에 들어가서, 프로젝트 행을 클릭하는 것과 같은 방식으로 열린 프로젝트를 하나씩 닫습니다. dsh 업데이트로 이 마크업이 바뀌면 오른쪽 클릭 시 브라우저 메뉴가 나오고 버튼은 표시되지 않습니다.
- dsh에는 새 채팅의 프로젝트 메뉴에도 확장 지점이 없습니다. 그래서 **프로젝트 검색** 상자와 A–Z 순서는 dsh의 메뉴 마크업에 붙습니다. dsh 업데이트로 이 마크업이 바뀌면 메뉴는 dsh가 그리는 그대로 표시됩니다. 즉, 저장된 순서로 표시되고 검색 상자는 없습니다. A–Z 순서는 보기일 뿐이며, dsh에 저장된 프로젝트 순서를 바꾸지 않습니다.
- dsh에는 **새 세션**를 열 위치를 고르는 확장 지점도 없습니다. **새 세션의 기본 작업 공간**은 공개 API가 아닌 dsh 메서드(dsh 작업 공간 서비스의 `startSession`)를 감쌉니다. dsh 업데이트로 이 이름이 바뀌면 **새 세션**는 dsh가 고른 위치(열린 프로젝트 또는 최근 프로젝트)에서 열립니다. 프로젝트를 지정하지 않는 모든 호출이 기본값을 사용합니다: 사이드바 버튼, 그 단축키, 로고, 그리고 **자동화 작업** 페이지의 **새로 만들기**도 마찬가지입니다. dsh는 시작할 때 여전히 마지막 채팅을 엽니다. 일반 폴더는 처음 사용할 때 만들어지고 프로젝트에 추가됩니다. Windows나 Linux에서 Documents 폴더를 옮겼다면 dsh 자체 폴더와 다른 폴더일 수 있습니다.
- dsh에는 입력란 힌트를 위한 확장 지점도 없습니다. 그래서 **다음 메시지 예측** 텍스트는 dsh 자체의 플레이스홀더(`[data-composer-placeholder]`) 위에 겹쳐 표시됩니다. dsh 업데이트로 이 마크업이 바뀌면 예측이 표시되지 않습니다. 켜져 있는 동안에는 턴이 끝날 때마다 짧은 모델 호출이 한 번 일어납니다.
- **입력 중 자동 완성**은 dsh 자체의 입력란 힌트(dsh가 슬래시 명령의 인수 힌트에 쓰는 `--dsh-composer-hint` 스타일)로 텍스트를 표시합니다. 슬래시 명령, 파일 칩이나 기호 칩이 있는 메시지, 커서가 메시지 끝에 있지 않을 때는 실행되지 않습니다. dsh 업데이트로 이 스타일이 바뀌면 완성 텍스트가 표시되지 않습니다. 입력을 멈출 때마다 모델 호출이 한 번 일어납니다.
- **프롬프트 개선**은 짧은 프로젝트 요약, 변경된 경로, 이름이 입력한 단어와 일치하는 경로만 보며, 코드 자체는 보지 않습니다. 그래서 맞는 파일을 놓칠 수 있고, 전달받은 경로만 언급합니다. 보내기 전에 새 텍스트를 읽어 보세요. 슬래시 명령이나 파일 칩이나 기호 칩이 있는 메시지에서는 실행되지 않습니다(새 텍스트는 일반 텍스트라서 칩이 사라지기 때문입니다). 메시지는 최대 8,000자까지 가능합니다. 이미지는 그대로 첨부되어 있고, 텍스트만 바뀝니다. 클릭할 때마다 모델 호출이 한 번 일어나며, 성능이 높은 모델은 1분쯤 걸릴 수 있습니다(`Esc`로 취소).
- 기본 지원은 업스트림에 요청해 두었습니다: 대기열 `move`는 [#773](https://github.com/deepseek-ai/deepseek-harness/discussions/773), 계속 상태는 [#9269](https://github.com/deepseek-ai/deepseek-harness/discussions/9269).

## 자주 묻는 질문

**DeepSeek Harness에 변경 사항 / git diff 패널을 추가하려면 어떻게 하나요?** `dsh-composer-plus`를 설치한 뒤 오른쪽 사이드바 → `+` → **변경 사항**을 여세요.

**dsh가 Tinder 카드를 넘기듯 내 프로젝트에 맞는 기능을 제안할 수 있나요?** 네. 오른쪽 사이드바 → `+` → **기능 아이디어** → **기능 제안**. 오른쪽으로 스와이프하면 그 기능을 계획하는 새 채팅이 시작되고, **▶ 바로 구현**을 클릭하면 계획 없이 그 기능을 바로 구현하는 채팅이 시작되며, 왼쪽으로 스와이프하면 건너뜁니다.

**dsh 사이드바 검색이 제목뿐 아니라 메시지 속 단어로도 채팅을 찾을 수 있나요?** 네, **내용 검색**(기본적으로 켜짐)으로 가능합니다. 플러그인을 설치한 뒤 dsh를 한 번 다시 시작하고, **작업 공간** 옆의 돋보기를 쓰세요. 일치하는 채팅에는 그 단어 주변의 텍스트가 표시됩니다.

**OpenCode나 Claude Code처럼 턴을 되돌리고 프롬프트를 고칠 수 있나요?** 네, **턴 되돌리기**로 가능합니다. 메시지의 **↶** 버튼을 클릭하고 **채팅과 파일**을 선택하세요. 그다음 입력란에 돌아온 텍스트를 고쳐서 보내세요.

**채팅을 보관하는 대신 삭제할 수 있나요?** 네, **채팅 삭제**로 가능합니다: **…** → **삭제…**. 기록은 휴지통으로 가므로 실수해도 되돌릴 수 있습니다.

**채팅이 어느 프로젝트에 속하는지 어떻게 알 수 있나요?** 입력란 아래 줄을 보세요. **입력창에 프로젝트 이름**(기본적으로 켜짐)이 켜져 있으면 그 줄이 프로젝트 이름으로 시작합니다. 포인터를 올리면 폴더 경로가 보입니다.

**dsh 입력란에서 ↑/↓ 메시지 기록을 쓰려면 어떻게 하나요?** 이 플러그인을 설치하세요. 빈 입력란에서 `↑` / `↓`로 보낸 메시지를 차례로 불러옵니다.

**"continue"를 입력하지 않고 중지되거나 실패한 dsh 턴을 이어 가려면 어떻게 하나요?** 이 플러그인을 쓰면 턴이 중지되거나, 실패하거나, 중간에 끊긴 뒤 보내기 버튼이 **▶**로 바뀝니다. 한 번 클릭하면 턴이 이어집니다.

**dsh를 종료했다가 다시 열면 실행 중이던 채팅이 이어지나요?** 저절로 이어지지는 않습니다. dsh는 이런 턴을 중단됨으로 표시하고 기다립니다(목표도 `/goal resume`을 기다립니다). **설정 → Composer Plus → 재시작 후 이어서 실행**을 켜세요. 그러면 dsh를 종료할 때 작업 중이던 채팅이 다음 시작 때 자동으로 이어집니다.

**예측은 어떤 모델이 쓰나요?** **설정 → Composer Plus → 다음 메시지 예측 → 모델**에서 고른 모델입니다. 이 목록은 dsh 자체의 모델 목록입니다. **dsh 기본값**은 dsh의 기본 모델을 따릅니다. dsh 목록에서 고른 모델이 사라지면 예측은 기본 모델을 씁니다. **입력 중 자동 완성**에는 전용 **모델** 메뉴가 있습니다. **다음 메시지 예측과 같음**(기본값)은 예측의 모델을 따르고, 다른 모델을 고르면 그 모델은 자동 완성에만 사용됩니다. dsh 목록에서 그 모델이 사라지면 자동 완성은 예측의 모델을 씁니다.

**Roo Code나 Augment의 Enhance prompt 버튼처럼, 보내기 전에 dsh가 프롬프트를 개선할 수 있나요?** 네, **프롬프트 개선**(기본적으로 켜짐)으로 가능합니다. 대략적인 요청을 입력하고 모델 메뉴 옆의 요술봉을 클릭하세요. 이 채팅과 프로젝트를 컨텍스트로 삼아 사용 언어 그대로 텍스트를 다시 쓰며, 보내지는 않습니다. `Cmd/Ctrl+Z` 또는 **개선 실행 취소**로 원래 텍스트를 되돌립니다. 모델은 **설정 → Composer Plus → 프롬프트 개선 → 모델**에서 고르세요.

**dsh에서 대기 중인 메시지의 순서를 바꾸려면 어떻게 하나요?** 대기 중인 메시지의 ⠿ 핸들을 끌거나, 핸들에 포커스를 두고 `↑` / `↓`를 누르세요.

**대기 중인 메시지의 오타를 고치려면 어떻게 하나요?** 대기열에서 메시지를 두 번 클릭하고, 텍스트를 고친 뒤 `Enter`를 누르세요(`Esc`는 취소). 메시지는 대기열에서 제자리를 유지합니다.

**프로젝트의 읽지 않음 점을 한 번에 모두 지우려면 어떻게 하나요?** 사이드바 → 프로젝트의 **…** 버튼 → **모두 읽음으로 표시**.

**긴 채팅의 메시지 하나에 링크할 수 있나요?** 네. 메시지 위에 포인터를 올리고 **🔗**를 클릭하세요. 그 링크를 채팅에서 보내세요. dsh 0.2.1 이상에서는 링크를 클릭하면 그 메시지 위치에서 채팅이 열립니다.

**실수로 턴을 되돌렸습니다. 다시 살릴 수 있나요?** 네. 되돌린 직후 입력란 위의 **다시 실행**을 쓰세요. 되돌리기 직전 시점부터 같은 메시지로 새 채팅을 시작하고, **채팅과 파일**로 되돌렸다면 파일도 다시 돌려놓습니다.

**어떤 채팅이 이 파일을 변경했나요?** 오른쪽 사이드바 → **변경 사항** → 파일의 **…** → **이 파일을 변경한 채팅**. 행을 클릭하면 변경을 만든 요청 위치에서 그 채팅이 열립니다.

**긴 채팅 하나 안에서 검색할 수 있나요?** 네. 채팅에서 Mac에서는 `Cmd+F`(Windows와 Linux에서는 `Ctrl+F`)를 누르세요. **채팅에서 찾기**가 모든 일치 항목을 강조 표시하고, `Enter`와 `Shift+Enter`로 그 사이를 이동합니다.

**한 채팅이 바꾼 파일만 보려면 어떻게 하나요?** 오른쪽 사이드바 → **변경 사항** → **이 채팅**. 공백만 바뀐 변경을 숨기려면 **␣**를 클릭하세요.

**한 채팅에서 자동 검토가 같은 도구를 계속 묻지 않게 하려면 어떻게 하나요?** 승인 카드에서 **이 채팅에서 허용**을 클릭하세요. 이 허용은 그 채팅의 그 도구에만 적용되며, 기본값은 1시간입니다. 헤더 칩에서 취소할 수 있습니다. 시간은 **설정 → Composer Plus → 이 채팅에서 허용**에서 바꿉니다.

**iPhone을 잃어버렸습니다. 그 iPhone이 Mac에 접속하지 못하게 하려면 어떻게 하나요?** 사이드바 왼쪽 아래의 **모바일 연결**을 클릭하고, 그 iPhone 옆의 **Remove**를 클릭하세요. 그 iPhone의 키는 즉시 작동을 멈춥니다. 다시 연결하려면 Mac에서 승인하는 새 페어링이 필요합니다.

**Face ID로 Tether를 잠글 수 있나요?** 네. Tether에서 "Settings → Privacy → Lock with Face ID"를 켜세요. 그러면 Tether를 열 때와 Tether로 돌아올 때 Face ID(또는 암호)를 요구합니다.

**dsh 사이드바에 오늘 사용한 프로젝트만 표시하려면 어떻게 하나요?** 사이드바 → 보기 옵션(슬라이더 아이콘) → **최근 2시간 내 활성**. 모든 프로젝트를 다시 보려면 이 옵션을 다시 선택하세요.

**dsh에서 프로젝트 폴더 경로를 복사하려면 어떻게 하나요?** 사이드바에서 프로젝트를 마우스 오른쪽 버튼으로 클릭 → **경로 복사**.

**dsh 사이드바의 모든 프로젝트를 한 번에 접으려면 어떻게 하나요?** 보기 옵션(슬라이더 아이콘) 옆의 접기 버튼을 클릭하세요. 이 버튼은 열린 프로젝트가 하나 이상 있을 때 표시됩니다.

**dsh 작업이 끝나거나 승인이 필요할 때 macOS / Windows 알림을 받으려면 어떻게 하나요?** **백그라운드 알림**을 켜 두세요(기본값). 그리고 OS 설정에서 DeepSeek Harness의 알림을 허용하세요.

**DeepSeek Harness 인터페이스를 터키어, 스페인어, 일본어 등으로 바꾸려면 어떻게 하나요?** 설정 → Composer Plus → **애플리케이션 언어**.

**iPhone에서 dsh를 쓰려면 어떻게 하나요?** `tether/ios`에서 Tether 앱을 빌드하세요(Xcode). **설정 → Composer Plus → 모바일 연결(iPhone)**을 켜고, 왼쪽 아래의 **모바일 연결**을 클릭하세요. QR 코드를 스캔하고(iPhone 카메라 또는 Tether의 **Scan code**), **Connect**를 탭한 뒤 **Approve**를 클릭하세요. 집 밖에서는 두 기기 모두에서 Tailscale을 쓰세요.

**새 세션를 항상 같은 프로젝트에서 열려면 어떻게 하나요?** 설정 → Composer Plus → **새 세션의 기본 작업 공간** → **새 세션을 열 위치** → 프로젝트를 선택합니다. 다른 프로젝트 옆의 `+`는 계속 그 프로젝트를 엽니다.

**한 프로젝트의 여러 기능을 각각 자기 브랜치에서 동시에 진행하려면 어떻게 하나요?** **채팅별 브랜치**를 쓰세요. 새 채팅 → ⑂ main 버튼 → **새 브랜치**를 고른 뒤 첫 메시지를 보내세요. 채팅마다 자체 브랜치와 worktree 폴더가 생기고, `.worktreeinclude`에 나열되어 있으면 `.env`와 `node_modules`도 함께 복사됩니다. 채팅 헤더에 현재 브랜치가 표시됩니다.

**iPhone에서 사진을 보낼 수 있나요?** 네. Tether 채팅에서 메시지 입력란 옆의 **+** → Camera, Photos(최대 4장) 또는 Paste image를 탭하세요. 사진은 메시지의 첨부 파일로 Mac의 채팅에 전달되므로 모델이 볼 수 있습니다.

**데스크톱 앱에서도 작동하나요?** 네. 설정 → 플러그인 → **플러그인 추가** → `dsh-composer-plus`. dsh 0.2.0-rc.2(데스크톱과 웹)와 0.2.1-rc.2(웹)에서 테스트했습니다.

## 개발

스크린샷은 가짜 모델과 지어낸 데모 프로젝트(`acme-web`, `weather-cli`, `docs-site`)를 쓰는 일회용 dsh에서 다시 만듭니다. 그래서 실제 데이터가 들어 있지 않습니다. 기능 썸네일은 `assets/features/`에 둡니다(패키지에 포함되며 설정에 표시됨). README에서만 쓰는 그림은 `docs/images/`에 둡니다(npm 패키지에 포함되지 않음):

**새 기능 규칙:** 설정 → Composer Plus의 모든 기능 행에는 스크린샷이 표시됩니다. 기능 ID를 `client.js`의 `SHOT_OF`와 `index.js`의 `SHOTS`에 추가하세요. 그리고 `assets/features/<id>.webp`를 함께 배포하세요(일회용 데모 dsh에서 영어 UI로 찍은 약 60 kB 이하 이미지). 같은 이미지로 기능을 `docs/features.json`에 추가하고 `npm run build:readme`를 실행하세요. 이 명령이 `README.md`와 번역된 각 `README.<id>.md`의 기능 표, 그리고 `llms.txt`의 목록을 씁니다. 기능에 스크린샷이 없으면 `test/shots.test.mjs`가 실패합니다. `test/browser-settings-shots.mjs`는 실제 설정 페이지를 확인합니다. 모든 변경에 대한 전체 체크리스트는 [AGENTS.md](AGENTS.md)에 있습니다.

테스트는 실제 `client.js`를 가짜 React/DOM에서, 실제 `index.js`(Host 쪽)를 임시 git 저장소에서 실행합니다. Tether 게이트웨이 테스트(`test/tether-gateway.test.mjs`)는 모의 dsh 호스트와 실제 TLS 게이트웨이를 사용합니다. iPhone 앱은 `tether/ios`에 있습니다([tether/README.md](tether/README.md)와 [tether/AGENTS.md](tether/AGENTS.md) 참고). 각 Host 경로와 그 요청, Tether가 그 경로를 호출할 수 있는지는 [docs/ROUTES.md](docs/ROUTES.md)에 정리되어 있습니다. `node test/browser-history.mjs '<dsh web URL with ?token=…>'`는 실제 브라우저에서 입력 기록을 확인합니다. 이 확인은 자체 `DSH_HOME`을 쓰는 일회용 `dsh web`을 대상으로 실행됩니다.

언어 팩은 `locales/<id>.json`에 있는 데이터 전용 JSON입니다. `npm run build:locales`가 이 파일들을 단일 클라이언트 엔트리에 포함합니다(번역 서비스나 런타임 다운로드 없음). `npm test`는 모든 팩에서 전체 키 포함 여부, 자리 표시자와 줄바꿈 일치, 시스템 언어/직접 선택 동작을 확인합니다. 로컬에 설치한 Playwright로 격리된 실제 앱을 확인하려면:

```sh
PLAYWRIGHT=/path/to/playwright node test/browser-language.mjs /path/to/dsh/lib/bin.js
```
